## 目标

canon 告诉主 agent 现在可以派哪些活、还能派几个、为什么现在不该派；共用的重资源统一排队，派多个 worker 时不互相拖垮。

## 范围

议程里的可派建议（把正在跑的整组测试算进容量）；整组测试按机器排队；两个会话同时派同一个变更时的冲突。

## 不做

不自动派活、不选模型：主 agent 决定（D-152）。

## 成功标准

- S1 机器有空时，议程列出可派的变更（设计已在 main、依赖满足、没人认领），按负责人的待办顺序，并写还能派几个；每一组正在跑的整组测试占一个 worker 名额，并把负载上限降到 0.9 倍（BR-2581）。（已满足：C-632）
- S2 同一台机器上同时只跑一组整组测试，其余排队，排队的命令说明前面还有几组。（已满足：C-637, C-639）
- S3 两个会话同时派同一个变更时，后一个以冲突（退出码 5）结束。（已满足：C-632, C-640）
- S4 负责人选的一天实际使用中，没有测试因为几组整组测试同时跑而超时。
