## 目标

主 agent 不用负责人提醒，就知道现在有哪些活可以派、哪些事要它判断、哪些要问负责人；canon 让它看到的上下文准确、及时，判断交给它（D-152）。

## 用户

在 canon 项目里调度工作的主 agent（Claude Code 主会话），以及从总览看进度的负责人。

## 范围

四个模块，各自的成功标准写在模块文件里：
- F-1 状态：每个变更现在在哪一步，从命令写下的事实算出（D-151 第一、二部分）。
- F-2 通知：该让主 agent 知道的事按事件告诉它，处理结论记下来；总览只给当前状态（D-151 第三、四部分）。
- F-3 监控：机器容量和每个 worker 在做什么、做了多久。
- F-4 调度：可以派哪些活、派几个、何时派，共用的重资源排队。

## 不做

- 不替主 agent 选模型、不自动派活：canon 给事实和建议，主 agent 决定（D-152）。
- 不定时重复提醒（D-151）。
- 不新增 D-139 四类以外的拒绝。

## 成功标准

- S1 F-1 到 F-4 的成功标准全部已满足。
- S2 负责人在 zhushenkongjian 实际用一天后确认：主 agent 不用他提醒，就能说出现在可以派什么、要判断什么、要问他什么。

## 故事地图切片

主 agent 一次调度的流程：会话开始看议程 → 派可派的活 → worker 写代码、跑测试、合入 → 主 agent 收到合入和新可派的活 → 处理要判断的事、问负责人的事。四个模块各管其中一段，行为写在各变更的规则里。
