## 为什么

议程只给“派出去”一种做法（BR-2581），打断提醒写死了下一步（BR-2606），主会话照做的结果不好：

- zhushenkongjian 近 7 天 60% 的派发被交回或收回，95 个派出去的变更里主会话合入了 84 个；
- canon 这一轮 `C-661` 和 `C-662` 共用 `BR-2527` 却同时派出去，后者被拒，只好收回。

负责人要求主 agent 自己判断调度，同时保留 D-128。

## 要改什么

设计变更，只写决定和计划中的规则，代码在后续的实现变更里写：

- D-156：调度由主 agent 判断。
- BR-2607：议程写出两种做法和事实，修订 BR-2581。
- BR-2608：牵连提示。
- BR-2609：设计没定的提示。
- BR-2610：子 agent 直接认领，修订 BR-2498。
- BR-2611：stats 按执行方式对比。
- BR-2606（`C-663` 要实现的）：改成写出两种做法和事实，不写死下一步。
- work/delegation 加业务“派活前的提醒”，work/stats 加业务“按执行方式的结果”。

## 陷阱和假设

- BR-2610 认“别的会话启动的 worker”靠环境里的 `CANON_SUBAGENT` 或 `CLAUDE_DELEGATE_CHILD=1`，canon 命令本身仍不核对 `--as`（BR-2023）。
