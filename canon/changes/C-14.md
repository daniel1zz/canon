## 为什么

C-1 合入时规则评审提了几条不拦截的建议：BR-2052 和 BR-2044 的标题还写着已经拆出去的行为；BR-2046 的扩展名列表容易误读；BR-2060 和 BR-2011 的例子缺少能看懂结论的细节；BR-2056、BR-2058 没写前一条 hook 命令失败后后面的还跑不跑；`canon doc list` 已经实现，但没有规则。

## 要改什么

- 改 BR-2052、BR-2044 的标题；BR-2046 直接列出 12 种扩展名；BR-2060、BR-2011 的例子补上细节。
- BR-2056、BR-2058 写明：某条命令失败后，后面的命令照样运行（代码本来就这样），测试补上这个边界。
- 新规则 BR-2061 描述 `canon doc list`：找不到类型时退出码 3（和 `canon doc new` 一致），没给 `--type` 或给内置类型时退出码 2 并提示对应的 list 命令。
- BR-2056 写明 setup 先于 `after_start`、接手已有 worktree 时照样运行；BR-2058 写明没有认领时不运行 `after_stop`。
