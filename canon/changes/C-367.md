## 为什么

D-64 第三步：canon 不再读任何语言的源码。`canon work test` 选测试里依赖语言的三条（相对导入、CLI 命令表、按路径读数据文件）和 BR-2181（`test-reads-skip-path`）读源码的部分，改由项目自己的 `test_select_command` 回答；canon 自己的项目把现有的读法原样搬进 `scripts/select-tests/`。

## 要改什么

- 新增配置 `test_select_command`（BR-2346）：标准输入是改动的路径，标准输出是要运行的测试文件和理由；`canon work test` 把它选出的文件加进选择，命令出错或打印了不是测试文件的路径时退出码 4；没配置时每次说明一句。
- `scripts/select-tests/`（BR-2347 到 BR-2351）：相对导入、CLI 命令表（D-60）、读数据文件（#117）和 BR-2181 的路径读法，原样搬来，测试跟着搬；多一条：按路径读改动的非代码文件的测试也选出。
- BR-2164：只改 `floor_skip_paths` 下文件的合入，跳过 floor 前先问 `test_select_command`，选出任何测试就照常跑 floor。BR-2181 退役，`canon check` 不再有 `test-reads-skip-path`。
- 删 src/work/verify/cli-tests.ts、`data-reads.ts`、src/knowledge/check/skip-reads.ts。
- 对照：用事件表里最近 138 个合入的改动路径，旧的 `selectTests`（efae07a）和新的脚本选出的语言相关的测试文件集合完全一样。

## 陷阱和假设

- 已安装的（旧）canon 不认 `test_select_command`，写进 `canon/config.yaml` 会让每条命令都报错（BR-2248）。所以本变更只加支持，不在 canon 自己的配置里用它，`floor_skip_paths` 也还没有“必须配 `test_select_command`”的约束；要等已安装的 canon 重编后，另开一个变更写 `test_select_command: "bun scripts/select-tests/main.ts"` 并加上这条约束。在那之前 canon 自己的 `canon work test` 不按导入选测试（会提示一句），后台 floor 不再跳过只改文档的合入。
- `canon/rules` 的领域和 `code_root: src` 一一对应（BR-2118），脚本不在 `src/` 下，没法给它开领域，所以它的规则放在 `work/verify`。
