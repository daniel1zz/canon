## 为什么

- issue #63：`review: ~/bin/review.sh` 被当成仓库根目录下名为 `~` 的目录里的脚本，读配置时报“文件不存在”，所有命令退出码 2；而 shell 运行时会把 `~` 展开成主目录，命令本来能跑。
- 同一个函数只按空白切第一个词，`'scripts/my review.sh' --fast` 被切成 `scripts/my`，同样被误判为不存在。
- 怎样认“命令以路径开头”只有 BR-2045 一句话，引号、`~`、`$` 这些情况没有规则写明（baseline 核对 N-4 说的“没有规则的行为”之一）。
- issue #64：BR-2045 说数值不大于 0 就是配置错误，而 BR-2177 规定 `land_keep_place_minutes: 0` 有效（不保留排队位置），代码和 schema 都接受 0。两条规则文字矛盾，代码按 BR-2177 做。
- BR-2045 的配置错误清单里没有 `test_command`（C-121 的评审建议）。

## 要改什么

- `src/config/config.ts` 的 `missingScript` 按 `sh` 的方式取第一个词：引号括起来的整段；不在引号里的 `~/` 是主目录；`~name`、含 `$`、反引号、反斜杠、词中间有引号、引号没闭合时不检查。
- 新规则 BR-2197 写明这些情况；BR-2045 的路径一项指向它。
- BR-2045：数值下限写明 `land_keep_place_minutes` 的例外（BR-2177），清单补上 `test_command`（BR-2160），补例子。
- 测试：BR-2197 的每个例子；BR-2045 的 0 边界。

## 陷阱和假设

- 主目录用 `os.homedir()`：先看 `HOME`，没有时查用户数据库，和 bash 展开 `~` 的做法一样；hook 和 floor 用同样的环境运行。
- D-3 也写着“数值必须大于 0”；决策记录的是当时的理由，这里不改它，以规则为准（BR-2177 后来定下 0 的含义）。
- 只认整个第一个词被引号括起来的写法；词中间有引号（`scripts/"my review".sh`）时不检查，免得切错后误报不存在。

## 教训

- 读配置时“猜 shell 怎么理解命令”的地方，每多一种 shell 语法就多一种误判 → 现在由 BR-2197 的例子和测试保证；拿不准的写法一律不检查，宁可漏检不误拒。
