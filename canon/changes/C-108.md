## 为什么

GitHub issue #30（C-101 合入后的代码评审发现）：C-101 让合入期间的认领记着合入进程（BR-2142），但 `renewClaim` 每次都把认领的进程改成当前会话进程。会话在合入等待时执行 `canon work stop`（正常的收尾方式），认领又记回会话进程；会话随后退出，别人就能在合入还在跑时接手，#17 的问题又回来了。

## 要改什么

子领域：work/claims（`src/work/claims/claims.ts` 的 `renewClaim`）。

- 认领记着的进程正是这个 worktree 在队列里（waiting / landing）的合入进程，且续期的是持有者本人时，只续租约，不改进程。
- BR-2142 补一句规则和一个例子；测试在合入等待时用会话进程续期，然后让会话进程退出。

## 陷阱和假设

- 合入期间会话换了进程（会话恢复，BR-2100），认领仍记合入进程；合入结束时改回合入开始时的会话进程，旧进程已不在时认领会空出来，直到新会话的下一个工作命令。比 #30 的情况窄得多，这里不处理。
- 判断依据是 queue 表里同一 worktree、同一 pid 和启动时间的活动条目，不新增字段。
