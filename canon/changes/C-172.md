## 为什么

baseline 核对（N-4）在 `canon stats` 里找到三处代码和规则不一致：

- #68：BR-2068 说“记录里没有改动指纹 → `unknown`”，但代码只在之后有 `land.ok` 时才看指纹；指纹是 null 的拒绝（`ownDiffId` 算不出时）在之后被放弃或还没结果时，被算成 `abandoned` 或 `pending`。
- #69：BR-2069 要求“Due for review”下附上运行次数、拒绝次数和拒绝去向，代码只打印 `changed` 和 `same` 两种去向。
- #70：BR-2121 说共享代码那一行在最后，代码把 `searches:` 行打印在它后面。

## 要改什么

- `outcomeOf` 先看拒绝自己有没有指纹，没有就是 `unknown`，再看之后发生了什么；BR-2068 加例子。
- 待复审行列出五种去向；BR-2069 加例子写明这一行的样子。
- `canon stats` 先打印搜索行，再打印共享代码行；BR-2135 写明搜索行在共享代码行之前，BR-2121 不改意思。
- 回归测试：#68、#69 放在 `src/work/stats/stats.test.ts`；#70 要经过命令行，放在新文件 `src/work/stats/commands.test.ts`。

## 陷阱和假设

- #70 选择改代码而不是改 BR-2121：规则已经写明共享代码行在最后，改规则才是改变已定的意思。
- 拒绝有指纹、之后的 `land.ok` 没有指纹时仍是 `unknown`（原来就这样），例子里写明。
