## 为什么

解决 GitHub issue #123：仓库还没有任何提交时，`canon init` 没有提示 main 还没有提交；第一次 `canon work start` 先分配了 C-1（按 BR-2002 永不复用，白白占掉），再报 git 的原始错误 `invalid reference: main`，没说该先提交 `canon init` 写的文件。

## 要改什么

- BR-2012：`canon work start`（新建和 `C-n`）在分配编号、调用 `git worktree add` 之前检查 main 有没有提交；没有就退出码 4，不分配编号、不记 `id.allocate`，提示里给出提交命令。加两侧例子。
- BR-2032：`canon init` 在 main 还没有提交时结尾加同样的下一步。
- BR-2022：退出码 4 的情形里加上这一条。
- 代码：`src/kernel/git.ts` 的 `mainIsUnborn`、`firstCommitStep`，`src/work/session/session.ts` 的 `start`，`src/cli/install/commands.ts` 的 init。

## 陷阱和假设

- 只在仓库一个分支都没有时算“没有提交”；有别的分支、只是配置的 main 写错，仍走原来的“git cannot read <main>”。
- 主检出有 main 签出时 `corpusOf` 直接读 worktree，所以空仓库不会在读 main 时就失败，必须在 `start` 开头检查。
