## 为什么

C-464 的 H 步（D-89）：发版要发布已验收的提交，而不是 main 的最新提交；没有验收过的提交时拒绝。原来 shipped_at 取开始时 main 的提交（D-61），合入时在合入的树上重算发布条件（BR-2335）——验收之后 main 又合入的变更会让发版合入被误拒，重新引入 D-89 要消灭的不收敛；手写 shipped_at 只要伪造一条事件就能过（D-61 已承认的洞）。

## 要改什么

- ship 取 `refs/canon/accepted`：没有 → 退出码 1 提示 canon accept；R-n 不在其上 → 3；R-n 在 main 上改过 → 1 提示重新验收；落后 main 时输出写明（BR-2334）。
- 合入不重算条件（executionStates 读活的 green，冻结树重算会翻），改查 shipped_at 已验收（是 accepted 或其祖先且有 accept.ok 事件）+ 负责人确认仍有效（BR-2335）；顺带堵上手写 shipped_at 的洞。取舍见 D-105（amends D-61）。
- 「已发布」判定看 main 当前文档，不看快照。

## 陷阱和假设

- 不能在冻结树上重算条件：规则「已通过」读活的 refs/canon/green，重算会从已通过翻成待重新执行（D-105 方案 2 的否决理由）。
