## 为什么

负责人定了方向：设计只由主会话做，worker 只执行，需要设计时通知主会话（#232）。现在 canon 不拦 worker 写决策、改规则、在变更文件里写设计约定再自己合入。负责人在 Codex 给的两个方案里选了“worker 在固定的设计版本内自己合入，canon 拦它改设计，合入后评审补强”（D-128）。

## 要改什么

这个变更只发布设计：决策 D-128，新领域 `work/delegation`，规划中的规则 BR-2497 到 BR-2503。实现放在后面的变更里，按这份设计派发。

- BR-2497：`canon work delegate` 固定设计负责人、设计版本、契约清单、任务和代次；重新派发。
- BR-2498：worker 只能认领派给它的变更，派发绑定第一个认领的会话，不能新建变更和杂务。
- BR-2499：`canon work need-design` 和 `canon work design-answer`，请求跟着变更走。
- BR-2500：设计负责人跨进程 `take`，要 worker 已停、没有合入在进行（`will_amend: [BR-2336]`）。
- BR-2501：worker 合入时的四项检查，批量合入按成员检查，`land.ok` 记下派发。
- BR-2502：worker 不能分档和关闭评审意见（`will_amend: [BR-2477, BR-2478]`）。
- BR-2503：合入后代码评审对 worker 合入另找契约清单没写到的业务选择（`will_amend: [BR-2070, BR-2071]`）。

## 陷阱和假设

- 实现要在 BR-2498 生效的同一次合入里改 `canon-parallel` skill 和 `canon brief` 的流程说明，否则子 agent 按旧说明 `canon work start --title` 会被拒绝。
- 执行者只是标签（D-125），检查防的是正常使用里的错误。
