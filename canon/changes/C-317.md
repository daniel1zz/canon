## 为什么

`canon work test` 只选出自己被改、导入了改过的文件、或测试名点名了碰过的规则的测试文件（BR-2157）。通过启动 CLI（`Bun.spawn(["bun", MAIN, "work", "status"])`）来测改动代码的测试不导入被改的模块，所以选不出来。实际红过两次 main：C-309 改了 `canon work status` 的输出，`src/work/session/brief.test.ts` 里的 BR-2192 用例（启动 CLI）没被选出，main 一直红到 C-313。完整测试集要更少地运行，合入前的选择必须更准。

## 要改什么

- 选择时读出每个测试启动的 CLI 入口文件和它点名的命令（`"work", "status"`），按命令表里 `entry(...)` 注册该命令的模块，把测试当作导入了这个模块；模块或它导入的文件改过就选出，理由写 `drives canon work status (src/work/session/commands.ts changed)`。测试还依赖入口文件和它导入的文件，但不依赖没点名的命令的模块（D-60）。
- 改 BR-2157（原地改，加条件和两侧例子），测试走真实 CLI、临时仓库。
- D-60 记方案和被否决的方案，状态 proposed，不 accept。
