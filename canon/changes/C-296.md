## 为什么

Claude Code 让子 agent 用 worktree 隔离时，会在项目里建 `.claude/worktrees/<名字>`。在用 canon 的项目里这个目录是未跟踪的，主检出因此有未跟踪文件，合入被 `main-dirty` 拒绝，所有合入都被挡住，直到有人手动把它藏起来。本仓库今天复现过，是手动往 `.git/info/exclude` 追加 `/.claude/worktrees/` 解开的（只在本地，没提交）。

## 要改什么

- 新规则 BR-2305（cli/install）：`canon init`、`canon install`、`canon update` 保证 git 公共目录的 `info/exclude` 里有 `/.claude/worktrees/`，只追加一次；`canon update --check` 缺它时列出一项，`canon update` 只有它和 git hook 过期时直接写好，不开变更。
- 把 BR-2176 用的追加逻辑从 `src/config/reference/reference.ts` 挪到 `src/kernel/exclude.ts`，两处共用，不写第二份。
- 不改 `.gitignore`：没有被跟踪的文件变化，也不会让每个项目都多一个要提交的改动。选 `info/exclude` 而不是 `.gitignore`，理由和 BR-2176 对 `.canon/` 的一样；这是沿用已有做法，不另写决策。
