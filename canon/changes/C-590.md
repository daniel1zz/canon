## 为什么

issue #249。C-583（D-130）加了功能模块文档 `canon/features/F-n.md`：模块有自己的目标、范围、不做和成功标准，规则用 `feature: F-n` 挂上去，版本用 `features` 列出组成它的模块（BR-2507、BR-2509）。但合入后的规则评审只看 `canon/rules`、`canon/decisions`、`canon/releases` 下改动的文件（BR-2009 决定评审什么，BR-2010 决定要不要评审），所以：

- 只改了一个模块文档的合入根本不评审；
- 同时改了模块和版本的合入，评审只收到版本，`reviewed entries` 里没有模块（issue 里用 `reviewScope` 在 main 49a696b3 上复现过，2026-11-18 在 main 10bde003 上读代码确认仍然如此）；
- 版本有 BR-2327 那一段（范围、不做、标着它的规则清单），评审可以拦“规则做了版本不做的事”；模块没有对应的一段，模块的“不做”和挂在它上面的规则矛盾、模块的范围超出列着它的版本的范围，评审都看不到。

## 要改什么

想要的行为：

- 一次合入新增、修改或删除了 `canon/features` 下的文件，和改了版本文档一样触发合入后的规则评审（BR-2010），评审收到模块的新文字、被删掉的模块在 main 上的原文（BR-2009）。只改了 `links` 记录或只是移动、内容不变的模块文件，和规则、决策一样不算改动。
- 评审提示里，每个改动的模块，和每条改动的、带 `feature` 标签的规则所挂的模块，各有一段（对应 BR-2327 的版本段）：模块编号、标题、状态，没有出现在改动文档里的模块还有它的全文；挂在它上面的规则（不含作废的）一行一条；列着这个模块的版本，每个一行：编号、标题、状态。要求里写明：挂在模块上的规则做了模块“不做”里排除的事或超出它的“范围”、模块的“不做”和自己的“范围”矛盾、模块的范围超出列着它的某个版本的“范围”或做了那个版本“不做”的事，评审都可以拦。拦的类别沿用 `release`，不新开一类。
- 评审分次调用时（BR-2359），模块段和版本段一样处理：完整的一段只在第一次调用里，之后的调用只留一行 `- F-n <标题> (<状态>)`。
- 合入前的 `canon work review` 看到的范围和合入后一致。

要改的规则：BR-2009、BR-2010（加上 `canon/features`）、BR-2327（加模块段，或者新建一条模块段的规则、BR-2327 引用它，按 canon-rules 判断哪种更清楚）、BR-2359（分次调用时模块段的处理）。动手前先 `canon search features` 和 `canon context src/work/land/checks` 看还有没有别的规则写死了这三个目录（例如 `canon accept` 按提交找评审范围，BR-2462）。

回归测试：一次合入只改 `canon/features/F-1.md` → 评审被调用，收到 `F-1` 的全文；一次合入改了一条 `feature: F-1` 的规则 → 提示里有 `F-1` 那一段，列出挂着的规则和列着它的版本；只改了 `F-1` 的 `links` → 不评审。

不做：

- 不给模块加新的 `canon check` 检查（文字矛盾是评审的事）。
- 不改模块成功标准的计算和 `canon overview`（BR-2504、BR-2505）。
- 不改版本段本身的内容。
