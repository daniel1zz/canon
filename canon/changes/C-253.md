## 为什么

一次独立评审（2026-11-04）发现 D-45 的佐证会给出错误的标记：对照不看记录里的问题是不是第 n 个问题，碰巧相同的短选项就标成“一致”；按操作者而不是会话对照，共用 `CANON_ACTOR` 的会话会对上别人的记录；“没有对应记录”混了 agent 没用提问工具、回答不同、hook 没装、记录失败几种情况；D-45 引的文档摘录出自 `tool_input` 表，而那一行恰好说明 hook 能替人填回答。负责人 2026-11-04 选了“D-45 回答佐证 (推荐)”，要求按评审修订 D-45。新决策 D-47（部分修改 D-45）写明怎么改、哪些否决。

## 要改什么

- 新决策 D-47（`amends: [D-45]`，保持 proposed，由主 agent 先找人质疑再接受）。
- BR-2275：`canon human record` 按问题记下文字、回答和备注（`questions`），多选的数组回答用 `, ` 连起来，另存 `transcript_path` 和 `afk_timeout_ms`；拒绝时写带原因和会话的 `human.asked.refuse`。顺带处理它的两条评审建议：写明没有 `response` 时事件里是 `null`，写明操作者不看 `CLAUDECODE` 是有意的。
- BR-2276：转述的回答按 `CLAUDE_CODE_SESSION_ID` 和第 n 个问题的文字对照，标记分成 `match`、`differs`、`record-failed`、`unasked`、`no-hook`、`no-record`、`no-session`。
- 新规则 BR-2289：`canon human pending --all` 怎么显示这些标记（从 BR-2276 拆出来，处理 BR-2276 那条“显示是另一个命令的输出”的评审建议）；D-45 之前的 `none` 照旧显示。
- `canon brief` 里提问那一行写明：用提问工具问第 n 个问题时照抄它的文字，并在同一会话里转述。
- 代码：`src/work/humans/questions.ts`、`src/work/humans/commands.ts`、`src/work/humans/guide.ts`，测试在 `src/work/humans/questions.test.ts`。

## 陷阱和假设

- 假设 Bash 工具的子进程里有 `CLAUDE_CODE_SESSION_ID`，且和 hook 数据里的 `session_id` 相同（env-vars 文档写明了）。没有时标 `no-session`，不退回去按操作者对照。
- 子 agent 和主会话共用会话 id（D-18），所以子 agent 转述主会话问到的回答也能对上；提问工具在子 agent 里本来就不能用。
- `no-hook` 只看主 checkout 的 `.claude/settings.json`：Claude Code 从会话启动的目录读设置，通常是主 checkout，不是 worktree。
- 旧记录（D-45 时期的 `human.asked`）没有 `questions`，只有 `answers` 和不分问题的 `notes`：对照时用 `answers` 里的问题和回答，备注不用，以免碰巧对上。
- 旧的 `witness = none` 不改写，照旧显示原来的说明。

## 教训

- 评审指出的问题里，有两处是引用的摘录本身就说明了方案的漏洞（`tool_input` 那一行写着可以用 `updatedInput` 替人回答）：只检查摘录在页面上存在，查不出摘录和结论对不上 → 待负责人确认是否固化（例如规则评审时要求核对每条摘录支持的是哪句结论）。
- D-45 用“只看最近一条”压低碰巧对上，实际漏掉的是“对上的是不是同一个问题”这个更直接的约束 → 只靠文字：这是设计判断，没有能机械检查的形式。
