## 为什么

zhushenkongjian 2026-11-27 从笔记本迁到 Mac Studio 后，协调数据库里存的绝对路径还是旧机器的：`claims.worktree` 是 `/Users/apple/Projects/zz/canon.worktrees/C-603` 这样的路径，after_land 日志也按旧路径找（canon 自己的 SessionStart 报 `the log /Users/apple/Projects/zz/canon/.git/canon/logs/after-land-958.log is missing`）；git 自己的 worktree 登记也要手工跑 `git worktree repair`。新会话因此读到错误的工作状态，违反 P3（连续性）。换机器或挪动 checkout 是正常动作，不是不正常配置（D-54）。

## 要改什么

- 新规则 BR-2649：`canon brief` 先找旧位置（认领、交接、队列里不存在、而新 worktree 目录下有同名目录的路径；或日志路径指向的旧 `.git/canon/logs/`，而新位置有同名日志），找到后在一个事务里改写认领、队列、交接、事件的 worktree 列，评审日志路径和事件详情里的旧路径，清掉改写过的认领记下的进程，对新 worktree 目录跑 `git worktree repair`，记 `state.relocate` 事件，brief 报一行。
- 没选“改成存相对路径”：协调数据库里存路径的地方有十几处读写，全改成相对路径要动每个读写点和已有数据；路径只在仓库挪动时失效，挪动一次修一次更简单，也能顺带修好 git 自己的 worktree 链接。
- D-165 的后果改成：仓库挪过之后，旧机器上的进程号由 BR-2649 清掉。

## 复现

把一个有进行中变更的 canon 仓库连同 `<名字>.worktrees/` 一起挪到别的目录，运行 `canon brief`、`canon work status`：worktree 路径和日志路径仍指向旧位置。
