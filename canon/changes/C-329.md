## 为什么

hooks.test.ts 和 watch.test.ts 启动了后台进程（等 `go` 文件的 after_land 循环；脱离进程组的 `canon floor watch` 及其无限循环的 floor / after_green），只在测试成功路径上结束它们。断言先失败、超时，或测试进程被 SIGKILL 时，这些循环变成 ppid 为 1 的孤儿，一直跑到重启（GitHub #119、#120）。

## 要改什么

只改测试和测试工具，不改产品行为，不新增或修改规则（`canon search orphan` 没有相关规则）。
- `src/work/testkit.ts` 增加共享工具：`boundedLoop` / `runsUntilKilled`（夹具里的 shell 循环最多活 60 秒），`processReaper`（登记测试启动的进程和进程组，`killAll` 用 SIGKILL 杀整个组）。
- hooks.test.ts：等 `go` 的循环改成有上限；afterEach 给所有登记的目录写 `go`，失败也会执行。
- watch.test.ts：每个 detached 的 watcher、`ready.pid` 里的 hook、`sleep 30` 邻居都登记；afterEach 还会杀掉 watcher 表里仍存活、且自己是进程组组长的 watcher（`canon brief` 启动的那种）；无限循环全部改成有上限。

## 陷阱和假设

测试进程被 SIGKILL 时 afterEach 不会执行，只靠循环自己的 60 秒上限收尾，所以孤儿最多再活约 60 秒。

## 教训

测试自己启动的进程必须在失败路径上也被结束 → 待负责人确认是否固化（例如检查测试里的 `detached: true` 和 `while` 循环是否使用 testkit 工具）
