## 为什么

在 canon 项目里启动的 Claude Code 会话，仍然会加载你全局配置里给旧 lore 写的东西，可能照着旧流程做事：

- `~/.claude/settings.json` 里 20 个旧 lore 的 hook，对所有项目生效。
- `~/.claude/rules/lore-user-*.md`：里面要求用 `lore start`、`lore land`、`lore report-issue`，派 `lore-implementer` 子 agent。
- `~/.claude/skills/lore-*`：40 个指向旧仓库的 skill，按旧流程写的。
- `~/.claude/agents/lore-implementer.md`、`lore-reader.md`。

## 要改什么

这些都是负责人的全局配置，影响所有项目，每一项都要负责人决定，不能由 agent 自行改动：

1. 先在 canon 里实测：旧的全局 hook 在 canon 项目里会不会触发、会不会误拦。
2. 列出每一条和 canon 冲突的全局规则，给出修改建议，交负责人确认。
3. 旧 lore 退役的时间：退役后移除旧 hook、旧 skill 链接和旧 agent 定义（先备份）。
4. 决定 canon 需要哪些 skill：从旧 skill 里按价值挑（参考旧仓库审计结论），改写成 canon 的命令。

## 任务

- [ ] 实测旧 hook 在 canon 里的影响
- [ ] 冲突规则清单和修改建议
- [ ] 负责人确认后执行
