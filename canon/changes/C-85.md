## 为什么

C-84 合入时的规则评审指出几处边界（不拦截），其中两处是真实的漏洞：

- `shared` 的一项可以等于或落在某个领域的目录里（例如 `shared: [src/work]`）。这时同一个路径有两个归属：BR-2118 当它是共享代码，`canon context` 却按约定把它算进 work，BR-2119 说落在 `shared` 里的导入不带领域，实现里也会带上 work。
- `shared` 某一项的上级目录（例如 `src/lib`，`shared: [src/lib/kernel]`）里直接放的文件没有检查，绕开了“每个文件都有归属”。实现只检查 `code_root` 下直接放的文件。

另外两处只是没写清：BR-2121 总行数为 0 时输出什么；D-15 的“决定”对 BR-2118 的概括漏了上级目录的例外。

## 要改什么

- BR-2118：`shared` 和领域目录重叠时报 `code-layout`（报在 `canon/config.yaml` 上）；`shared` 上级目录里直接放的文件和 `code_root` 下的一样报出。实现和测试跟着改。
- BR-2121：总行数为 0 时百分比按 0 算（现有实现如此），加例子和测试。
- D-15 的“决定”补全对 BR-2118 的概括。
