## 为什么

#132：评审命令以非 0 退出时，拒绝信息只带标准错误的前 500 个字符（BR-2216 现在就这么规定）。`claude -p` 把出错原因（例如 `Prompt is too long`）写在标准输出，标准错误是空的，于是合入被拒时只看到 `review command exited 1: `，冒号后面什么都没有，要手工重跑评审命令才知道原因。

复现（main be6c0d7，临时项目）：`review` 配成一个读完标准输入、向标准输出写 `Prompt is too long`、以 1 退出的脚本，改一条规则后 `canon work land` → `land refused (review): the rule review could not run: review command exited 1: `，原因为空。

## 要改什么

评审命令以非 0 退出时，拒绝信息要写出原因：

- 标准错误不为空：和现在一样，取标准错误的前 500 个字符。
- 标准错误为空（去掉空白后）、标准输出不为空：取标准输出的最后 500 个字符，并标明来自标准输出（例如 `review command exited 1 (stdout): Prompt is too long`）。取结尾是因为出错的工具通常把原因写在最后。
- 两个都不为空：两段都写，各自标明来源，各取 500 个字符。
- 两个都为空：写明 `no output`，不留一个空的冒号。

改 BR-2216 的规则文字和例子：保留现有的 `boom` 写在标准错误、退出码 3 的例子；新增“只在标准输出写 `Prompt is too long`、退出码 1”，“两个都有输出”，“两个都为空”三个例子。常驻说明的重复评审（BR-2143）用同一个运行函数，自动得到同样的信息，不另写规则。

不在范围内：评审提示太大本身（#133，另一个变更）；超时、被信号终止、无效结论的信息不变。
