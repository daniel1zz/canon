## 为什么

继续给没划业务的领域划。invocation 8 条里只有 1 条写了业务。这个领域是所有命令共用的约定，里面是四摊事：退出码、参数解析、帮助、配置读错时怎么失败。

## 要改什么

README 的业务一节写出 4 个业务，8 条生效规则全部归属。只加 front matter 的 `business`，`## 规则` 和 `## 例子` 一字不动，行为哈希不变（BR-2236）。

- 退出码（1）：BR-2022
- 参数怎么解析（3）：BR-2097、BR-2228、BR-2382
- 帮助（2）：BR-2101、BR-2194
- 配置读错时怎么失败（2）：BR-2045、BR-2197

## 陷阱和假设

- BR-2194（帮助选项只在 `--` 之前生效）归在「帮助」而不是「参数怎么解析」：它说的是帮助这个选项什么时候算数，改帮助的行为时和 BR-2101 一起看。
- 配置里每一项各自的行为仍归用它的领域（D-63），这个业务只管读错时怎么失败。
