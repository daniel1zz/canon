## 为什么

issue #2：BR-2009 说合入改动了 `canon/rules` 或 `canon/decisions` 下的文件就要评审，但代码只评审“在新树上还能读成文档”的文件，所以只改领域 README、或者 `git rm` 删掉规则的合入完全不经过评审，也不写 `review.skip`。复现见 issue：评审配置成永远 `block`，这样的合入照样合进了 main。

## 要改什么

- 合入时按 `git diff --name-status --no-renames` 找出这两个目录下所有新增、修改、删除的文件：规则和决策给新文字，被删除的给它在 main 上的原文，README 被改的领域给完整上下文。
- 事件和输出里列出被评审的东西，包括 `(deleted)` 和 `README`。
- BR-2009、BR-2010 写明包括删除和 README；补两个测试。
