## 为什么

D-47（C-253 合入，proposed）的第二次独立评审（2026-11-04）提出几处问题，逐条对着 `src/work/humans/questions.ts` 和 `commands.ts` 核对过。负责人 2026-11-04 定了“不要设想不存在的问题”：只修正常转述时真会碰到的，以及规则和代码直接矛盾的。

要修的两处：

- `witnessFor` 把整次提问的 `response` 也算作第 n 个问题的回答（`const said = [q.answer, q.note, r.response]`），和 BR-2276 自己的“只用这个问题的回答和备注”矛盾。Agent SDK 文档说 `response` 是不回答任何具体问题的笼统回复；一次问 4 个问题，人回一句“好”，转述其中任何一个都标 `match`。
- 对照只用 `--relayed` 的原话，不看存下的回答。`canon human answer 1 no --relayed "yes"` 在人选了 `yes` 时标 `match`，`pending --all` 显示 `→ no (… "yes") [matches Claude Code's record]`，读起来像回答 `no` 得到了佐证。

属实但不修（不太可能在正常转述里碰到，写进 D-47 后果）：失败不分问题、盖住 `unasked`；配置错误和操作者不合法时写不进失败；同文字问题共用记录、问题创建前的记录也算；多选换顺序或只说一部分标 `differs`。评审说“多选数组”那条是推测，只改了 D-47 背景的措辞。

## 要改什么

- BR-2276：`response` 只在这条记录只问了一个问题时才算这个问题的回答；写明比较的是原话和记录，不是存下的回答；补两侧的例子。
- BR-2289：`match`、`differs` 的说明改成 ` [the human's words match Claude Code's record]`、` [the human's words differ from Claude Code's record of this question]`，补“回答和原话不同但 `match`”的例子。
- BR-2275：例子里“人在 Other 里打字”改成“人没回答具体问题、自己打了一段回复”：Other 里打的字在 `answers` 里，不在 `response` 里（文档原文）。
- 顺带处理 C-253 留在这几条规则上的评审提示：BR-2275 写明 `agent:` 前缀检查只在 `CLAUDECODE=1` 时生效并补例子和测试、写明哪几个字段缺了记 `null`；BR-2276 把 `no-record` 的条件直接写出来。
- D-47 保持 proposed，原地修订：背景补第二次评审的发现，方案 1 写明 `response` 和“比较原话”，新增方案 7（完全不用 `response`）、8（要求回答也和记录相同）、9（其余几处现在就处理）并否决，决定和后果相应改，后果逐条写“已知、不处理”。
- 代码：`src/work/humans/questions.ts` 的 `witnessFor` 和显示的说明；测试在 `src/work/humans/questions.test.ts`。

## 教训

- 子 agent 按评审修订时，先把评审的每条发现都做出来，负责人再收窄范围，做好的部分只能拆掉 → 待负责人确认是否固化（可以做成派发评审修订时的 brief 模板里的一条：每条发现先标“正常使用会碰到 / 推测”，只做前者）。
