## 为什么

C-190 让 `canon check` 对来源路径现在不是文件的决策报 `source-malformed`，对所有决策生效，包括已被取代的。这样以后有人挪走一个被来源引用的文件，就得去改每一份引用它的旧决策（包括已经被取代、只是历史的决策），而来源本来写的就是做决定时那个文件的原文。负责人 2026-11-04 在 AskUserQuestion 里选择：“只报历史上从没有过的路径”。做法和 D-25 对反引号路径（`path-missing`）的处理一致：git 历史里有过的文件是被挪走或删除了，不报；历史里从没有过的（错别字、把 `arXiv` 这样的词当成路径）照样报。

## 要改什么

- BR-2110：不是网址的来源目标去掉 `:行号` 后，现在是仓库里的文件，或者 HEAD 的 git 历史里有过这个文件（被挪走或删除了），都不报；两样都不是时报 `source-malformed`。读不到 git 历史（目录不是 git 仓库）时照样报，消息写明读不到历史；仓库还没有提交时历史为空，照样报。
- 代码：`src/knowledge/check/check.ts` 的来源检查复用 `src/knowledge/check/paths.ts` 里读历史的函数（`historyOf`，导出它，出错消息里写明是哪项检查读的历史），只对现在不是文件的来源调用一次 git。
- 测试：`src/knowledge/check/check.test.ts` 里 BR-2110 的用例放进一个 git 仓库，加上“历史里有过、现在挪走了”不报的边界。

## 陷阱和假设

- 只认历史里一模一样的文件路径：`src/knowledge` 现在是目录，历史里也只有它下面的文件，仍然报。
- 合入时的来源核对（BR-2111）不变：本次新增的来源仍要在将成为 main 的树里是文件、并包含摘录；所以新写的来源不能指向已挪走的文件，只有 main 上已有的旧来源受益。
- 本变更和 C-182 都改 `src/knowledge/check`，改动尽量小，先合入。
