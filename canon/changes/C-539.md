## 为什么

#209：BR-2464 在有未处理的评审意见时不让开新变更，让人用杂务处理；zhushenkongjian 的 `before_land` hook 不让杂务改规则，而有的意见只能改规则来修。两条合起来，这些意见处理不掉，新变更也一直开不了。C-531 已经发布，那边现在就卡着。

## 要改什么

按 BR-2464：`canon work start --settles <编号>[,<编号>]` 点名要处理的未处理意见，这样的变更不算新活，照常开工；编号必须都是未处理的意见，否则退出码 3、原因 `settles`。被拒的信息也提到 `--settles`。代码在 `src/work/session`（session.ts、commands.ts）。

## 教训

- 加一道拦截前，没有查用 canon 的项目自己的 hook 会不会把唯一的出路也堵上 → 只靠文字：项目的 hook 是任意脚本，canon 读不出它拦什么。
