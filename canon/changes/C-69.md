## 为什么

C-50 合入后的代码评审提了 issue #11：认领只在 `canon work start` 时检查执行者。`canon work stop`、`stop --release` 和 `land` 按 worktree 路径找认领，谁在那个目录里运行都被当成持有者。另一个会话被 `start` 拒绝后，可以进入提示里写出的 worktree，用 `stop --release` 删掉别人的认领，或者直接 `land --finish` 把别人做了一半的分支合入 main。

## 要改什么

- `renewClaim` 只给持有者续期：别的执行者在认领仍然有效（BR-2100 的判断）时被拒绝（退出码 5，记 `claim.refuse`）；认领已失效时由它接手（`claim.take`）。
- `canon work stop`（带不带 `--release`）都先经过这个检查；`canon work land` 在一开始检查，拒绝原因为 `claimed`，退出码 5，不记 `land.refuse`（这是认领冲突，算 `claim` 检查，BR-2067 不变）。
- 新规则 BR-2104；BR-2011、BR-2022 引用它。

## 陷阱和假设

- 同一个会话的子 agent 执行者相同，这个检查分不开它们（同 C-50）。
