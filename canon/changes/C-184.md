## 为什么

issue #87：C-181 在同一次合入里新增配置项 `floor_timing` 并写成 `after`。`after` 下 PATH 上的 canon 只在 main 测过后重新构建（`after_green`，D-31），旧的 canon 不认识新配置项就以退出码 2 失败（BR-2045）。从合入到后台测试通过的约 8 分钟里，所有会话的 canon 命令都不能用；如果那次测试失败，PATH 上的 canon 一直读不了配置，连 `canon work start --fix-main` 都跑不起来。负责人选了“合入时拦下”。

## 要改什么

- 新规则 BR-2224：被合入的那棵树是 `after` 时，合入在移动 main 之前用 PATH 上的 `canon` 在 worktree 里跑 `canon config --schema`；退出码不是 0（读不了配置），或 PATH 上没有 `canon`，就拒绝，原因 `config`，提示先合入新配置项、等 main 通过后再启用它。
- `src/work/land/land.ts`：在 after 模式下加这一步。
- BR-2218 的步骤列表提到 BR-2224；`canon/rules/work/watch/README.md` 补一句。

## 教训

- 新增配置项并在同一次合入里启用，after 模式下会让 PATH 上的 canon 读不了配置 → 现在由 BR-2224 在合入时拒绝。
