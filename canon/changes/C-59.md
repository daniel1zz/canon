## 为什么

lore 的 CLAUDE.md 涨到 164.6KB，压缩后 4 天又涨到 52.8KB（SPEC-095、KN-409），只靠写规范拦不住；但按内容做的检查误报很多（SPEC-146）。另外在 canon 自己的仓库里，CLAUDE.md 的“怎么干活”和“东西在哪”与 `canon brief` 输出的工作说明每个会话都同时加载，有一部分重复，以后会各自改、各自过期；lore 的教训（SPEC-179）是同一条规则有两份，比晚一轮生效更糟。负责人 2026-11-04 要求现在做（“先保证其他”）。

## 要改什么

- D-37：只按字节量、在 `canon check` 里提示、不拒绝合入，以及否决的方案。
- BR-2256：`canon check --sizes` 在标准错误里报出 `CLAUDE.md`、工作说明、每个 skill 描述的字节数和合计。
- BR-2257：新配置项 `session_text_budget`（`src/knowledge/check/config-keys.ts`）；合计超过它时 `canon check` 和 `canon work test` 在标准错误提示一行，不算发现，退出码不变。
- 代码：`src/knowledge/check/session-text.ts` 量大小、写提示；`src/knowledge/check/commands.ts` 加 `--sizes`；`src/work/verify/verify.ts` 在 canon check 那一步之后输出提示。
- canon 仓库的 `CLAUDE.md` 只留工作说明没有写的、canon 仓库自己的约定（用 canon-context-optimizer 的做法逐句追踪）。
- 顺带：`src/work/drop/drop.test.ts` 里 BR-2026 那个测试建 7 个临时仓库，机器负载高（load 25）时超过默认的 5 秒，main 上同样失败；给它 60 秒。
- 第一次合入只新增键、不写进 `canon/config.yaml`（BR-2248）；第二次合入在 canon 仓库的 `canon/config.yaml` 写 `session_text_budget: 12000`（删减后合计 11226 字节，留一点余量）。

## 陷阱和假设

- 原文：`CLAUDE.md` 删减前是提交 94c3c10 里的版本（`git show 94c3c10:CLAUDE.md`）。
- 大小（UTF-8 字节，`canon check --sizes` 的量法）：删减前 `CLAUDE.md` 3342、工作说明 3543、10 个 skill 描述 5620，合计 12505；删减后 `CLAUDE.md` 2063，工作说明和 skill 描述不变，合计 11226。
- `CLAUDE.md` 删掉的 10 处都还在别处：规则文件的位置、决策和变更是什么（工作说明开头一句）；领域 README 写什么（BR-2037、BR-2006）；子领域不写代码位置（BR-2117）；超过 25 条拆分（BR-2114，`canon rule domains` 自己提示）；代码位置和 `shared`（工作说明的 “Code lives in the matching directory”、D-15、BR-2116、BR-2118）；十个 skill 的名字和用途（每个 skill 的描述本身就常驻）；“canon 更新后 canon brief 会提示”（`canon brief` 自己打印）；“canon check 报出没有领域的目录”（BR-2118，合入时检查）；“读上下文、开变更……”这串工作说明目录（并进开头的一句）。删掉的条目交给另一个模型（sonnet）逐条判定，10 条都判为不丢指令。命令、参数和退出码用脚本对过：除了上面这些删掉的，全部保留；对的时候发现我凭记忆写的退出码 75 那一句是旧版，已按原文恢复。
