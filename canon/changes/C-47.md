## 为什么

只有规则的段落结构由 `canon check` 强制（BR-2033、BR-2034）。决策和变更虽然有模板，但写完后缺段或把段名改掉都不会被发现：现有 46 个变更里有 6 个不合格（5 个用了“改了什么”而不是“要改什么”，1 个没有“任务”）。新会话接手时靠固定段落快速找到信息，结构不一致就会漏读。

## 要改什么

- 文档类型可以声明必需的段落（`types.<类型>.sections`，BR-2092）。内置默认：决策要 背景/方案/决定/后果，变更要 为什么/要改什么/任务；规则形状固定，不能声明；笔记不要求。项目模板缺必需段落是配置错误。
- `canon check` 新增 `doc-missing-section`：缺段或段内只有占位行就报，不看状态；领域 README 必须有非空的 `## 术语`（BR-2091）。
- 没有模板的声明类型，新建时按必需段落生成带占位的正文（BR-2093），BR-2055 的文字随之更新。
- 统一现有文档：C-4、C-5、C-6、C-10、C-11、C-12 的“改了什么”改为“要改什么”，C-6 补上“任务”。
