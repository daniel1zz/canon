## 为什么

issue #84：做完快照后清理旧快照用一个 `git update-ref --stdin` 事务。两个 hook 同时清理同一批旧快照时，后到的一个在 ref 锁上失败，`canon snapshot take` 以非 0 退出，hook 的 `|| echo` 告诉用户“uncommitted work was not snapshotted”，其实新快照已经做好了。

## 要改什么

- `src/work/snapshots/snapshot.ts`：清理失败时重新读快照列表再试一次（另一个 hook 删掉的就不在列表里了）；还失败时新快照照样算做成，带上失败原因。
- `src/work/snapshots/commands.ts`：带 `--hook` 时输出 `systemMessage`（快照已做好、删除旧快照失败），退出码 0；不带时写到标准错误，退出码 4。
- BR-2183 写明这些并加两个例子；测试用 ref 的 `.lock` 文件让删除一直失败（不加修复时失败）。
