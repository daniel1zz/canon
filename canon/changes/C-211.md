## 为什么

issue #85：C-180 的 worktree 锁只用在 session 代码里。`canon work land` 一起测时的临时 worktree、合入移动 main 前读列表、`canon work drop` 的删除和列表，还有 C-181 新加的后台测试的临时 worktree，都直接调用 git，不持锁。它们建了一半的登记会让并发的 `canon work start` 失败（#32 的错误），反过来它们也会读到别人建了一半的登记。

## 要改什么

- `src/kernel/git.ts` 加 `pruneWorktrees`；`land.ts`、`drop.ts`、`watch.ts` 改用 `addWorktree`、`removeWorktree`、`pruneWorktrees`、`listWorktreesLocked`，drop 的列表用共享锁。
- BR-2223 去掉“不在范围内”一段，列出全部持锁的地方，加一个例子；新测试扫描源码，`kernel/git.ts` 以外不许直接运行这几个 git 命令（改之前它找到 13 处）。

## 教训

- 锁只有所有调用方都用才有效，漏一处就等于没有 → 现在由 BR-2223 的源码扫描测试保证。
