## 为什么

C-70 合入后的代码评审（issue #18）：`holdClaim` 遇到同一个操作者写的行就当作自己的，于是同一个操作者的 drop 能接管 clean 正在用的占位；`unholdClaim` 只按变更、`hold:<路径>` 和操作者删除，clean 结束时会删掉 drop 还在用的占位，drop 最后的 `releaseClaim` 又按变更编号删除，会删掉此后别人拿到的认领，又回到 issue #12 的症状。

## 要改什么

- 每次占位的标记唯一：`hold:<路径>#<随机 id>`；`holdClaim` 返回这个占位，`unholdClaim` 只删这一行。
- 别的命令的占位只要还有效（BR-2100），对谁都算有效认领，同一个操作者也不能接管。
- drop 成功结束时只放开自己的占位，不再按变更编号删除认领。
- BR-2064 写明这一点并补例子。
