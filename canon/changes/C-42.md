## 为什么

`canon stats` 的目的是回答“这个检查值不值得留”（P6、C-9）。现在 3 次评审拦截的去向都是 `unknown`，原因是它们发生在加入代码指纹之前。但还有一个更根本的问题：评审拦截之后，作者一定会改文字，所以按现在的算法，评审拦截永远会被算成 `changed`（拦对了），无法区分“真问题”和“为了过评审而改字”。

## 要改什么

- 先用新数据确认：指纹加入之后的拒绝是否都能被正确判定，修掉仍然判成 `unknown` 的情况。
- 对评审拦截单独设计判定方式，例如定期抽样，由一个没有参与该变更的 agent 对照拦截前后的文字判断拦得对不对，结果写回事件表；或者其他能区分“真问题”和“改字过关”的办法。在设计时决定并写成决策。
- 规则和测试。
