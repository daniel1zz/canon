## 为什么

issue #256。合入时的措辞判断（BR-2239）几乎把每处 `## 规则` 段的改动都判成 `behaviour`，包括只是把代码已有的范围写清楚、或者解决上一轮评审意见的改动。判成行为就要在点名这条规则的测试里改一行（BR-2241），于是一个代码早已满足的措辞修改要多被拒一次、多写一个只为过门的测试。某个项目 2026-11-18 一晚上：6 条意见 → 一次措辞修改 → 两次因为“行为”被拒 → 自己的措辞又引来 2 条新意见 → 再改一次措辞。canon 自己的 C-592 也是这样：给 BR-2111 一句话加上“没被取代的决策”这个限定，被判成行为。

而且拒绝信息只说“BR-n 要按行为修改执行”，不说是哪一句要求了什么新东西，会话不知道该测什么。

负责人 2026-11-18 定的方向（在 #256 的四个方案里选了“评审点名要测的句子”，没选“给评审看已有测试”“声明范围澄清可免新测试”和“不改”）：门不放松，但判 `behaviour` 必须给出依据。

相关：#250（C-591，只改注释的测试行），#166。

## 要改什么

想要的行为：

- 措辞判断的回答格式改成：每条规则答 `"wording"`，或者答一个对象 `{"verdict": "behaviour", "quote": "<现在的 ## 规则 段里的原文>", "requires": "<这句要求了什么上一次通过时没有要求的东西>"}`。提示写明：只有新文字要求了产品做以前不必做的事、或不再做以前必须做的事，才答 `behaviour`；只是写清已有范围、换说法、加引用的，答 `wording`。
- `quote` 必须是现在 `## 规则` 段里的一段原文（比较前合并连续空白，和来源摘录的比较方式一样）。答 `behaviour` 但没给 `quote`、`quote` 为空或不在原文里 → 这条按 `wording` 处理，输出一行写明“behaviour without a quote from the rule: treated as wording”。
- 判成 `behaviour` 的拒绝信息写出 `quote` 和 `requires`，让会话知道该测什么。
- 旧格式 `"BR-1": "behaviour"`（字符串）按“没给引用”处理，即算措辞，并输出同样那一行。
- `review.wording` 事件记下每条的 `quote` 和 `requires`。
- `canon work review` 的措辞预判（BR-2358）用同样的格式和处理。

要改的规则：BR-2239（回答格式、引用的核对、拒绝信息、例子），BR-2358（预判同样处理），评审命令输出格式的规则 BR-2216（如果它写了措辞判断的格式）。

回归测试：命令答 `{"verdict":"behaviour","quote":"<规则里的一句>","requires":"x"}` → 拒绝，信息含这句和 `x`；`quote` 不在规则原文里 → 合入继续，输出含 `treated as wording`；答字符串 `"behaviour"` → 合入继续，同样的输出；答 `"wording"` → 照旧。

不做：

- 不把已有测试放进提示（负责人没选这个方案）。
- 不加“范围澄清”的声明。
- 不改证据门本身（BR-2241）。
