## 为什么

C-593 合入后的规则评审记了一条拦截意见 #166，标准是 `contradiction`，可它的文字结尾自己写着“没有矛盾。未发现阻断问题。”。canon 照样把它记成未处理的拦截意见：按“不成立”关闭要另一个会话出意见或负责人批准（这次是负责人批准的，human #61），没人处理时 4 小时后还会挡住所有会话开新变更（BR-2464）。C-596 合入后的 #167、#168 也是评审误读后标成 `contradiction` 的，但那两条文字没有自认无问题，不在这次范围。

负责人 2026-11-18 同意把这条教训做成机制（会话里回答“可以”）。已有同类做法：D-119、BR-2481 把没引原文的 `contradiction`、`restatement` 降成提示。

## 要改什么

想要的行为：

- 评审回答里一条带拦截标准的意见，文字里含有“自认没有问题”的说法时，canon 把它当提示（`note`），不记成拦截意见，文字后面加一句 `(canon: given as [<标准>] but its own text says there is no problem, so taken as a note)`，和 BR-2481 的降级同一种写法。
- 认的说法是一张固定的表，写在规则里，比较前去掉空白、不分大小写，例如：`未发现阻断问题`、`未发现问题`、`没有矛盾`、`不构成矛盾`、`并不矛盾`、`no blocking`、`no contradiction`、`not a contradiction`、`does not contradict`。表里只放结论性的说法，不放“可能没有”这类不确定的话。动手前用事件表里已有的 `review.block` 意见文字统计一下（`canon events --kind review.block --json`），看这张表会命中哪些、会不会误伤真问题，按结果定表并写进决策。
- 评审提示同时写明：结论是没有问题的意见用 `note`，不要用拦截标准。
- 合入后的规则评审、合入前的 `canon work review` 预检，以及措辞判断里带的意见，都用同一个解析（`parseAnswer`），所以三处一起生效。

要改的规则：BR-2481（或在它旁边新建一条，按 canon-rules 判断哪种更清楚）、评审提示的规则（`canon search "note"` 找写提示要求的那条）。这是有真实取舍的选择（固定说法表 vs 让评审多答一个字段 vs 只改提示），写一份决策（D-119 的修订或新决策）。

回归测试：评审答 `{"findings":[{"criterion":"contradiction","text":"BR-1 与 BR-2 …，没有矛盾。未发现阻断问题。"}]}` → 结论 `ok`，意见是提示，带 canon 的说明，没有记成未处理意见；同样的意见去掉最后两句 → 照旧拦截；英文 `… overall no blocking defect.` 同样降级；`… no conflict, but … duplicates …` 照旧拦截（统计里的误伤例子）。

不做：

- 不改 B、C 级关闭的规矩（BR-2477）。
- 不让 canon 判断意见本身对不对，只认文字自己给出的结论。

## 方案依据

2026-11-18 统计了两个项目全部 `review.block` 事件里的拦截意见（count 脚本按说法去空白、不分大小写匹配）：canon 316 条、zhushenkongjian 2166 条，共 2482 条。

- 真正自认无问题的只有 2 条：canon 事件 #13245（即意见 #166，“没有矛盾。未发现阻断问题。”）和 zhushenkongjian 事件 #26215（“overall no blocking defect from this call's shown rules”）。
- 会误伤的说法：`does not contradict`（#26217，后面还要求核对复述）、`no conflict`（#26214，“no conflict, but … duplicates …”，是真问题）。`没有矛盾` 单独出现时常接“但是”，不放进表。
- 所以说法表只放整体结论句：`未发现阻断`、`no blocking defect`、`no blocking issue`；两项目里命中 2 条，误伤 0 条。
- 收益小（约千分之一的意见），但每条误报都要负责人批准关闭、没人处理还会挡住所有会话开新变更（BR-2464），实现只是 `parseAnswer` 里多一个判断，所以仍做；按这个统计，“要改什么”里列的长说法表收窄成上面三句。
