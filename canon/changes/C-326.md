## 为什么

负责人在全局设置里加了 `promptCacheTtl: "1h"`，让主会话停顿时缓存不过期；本仓库的 `claude -p` 评审本来也走 1 小时缓存。评审每次都是新会话，开头约 1.6 万 token 的固定前缀（系统提示和工具定义）各次共用，后面的评审内容每次都不同、写进缓存后不会再读。1 小时档的写入单价是输入价的 2 倍，5 分钟档是 1.25 倍，所以评审内容这部分用 5 分钟档更便宜。2026-11-01 到 11-05 本仓库 sonnet 评审约 $15，几乎全是 1 小时档写入。负责人选择“评审改用 5 分钟缓存”。

## 要改什么

- `scripts/review-claude.sh`（规则评审）用 `env FORCE_PROMPT_CACHING_5M=1` 启动 `claude -p`。
- `canon/config.yaml` 的 `after_land` 代码评审命令前加 `FORCE_PROMPT_CACHING_5M=1`；`src/knowledge/review/code-review.ts` 启动评审命令时继承环境，变量能传到 `claude -p`。
- 实测（同一条短提示各跑两次，sonnet）：不加时写 1h 约 1.1 万 token、读 1.57 万，$0.0466；加了以后写 5m 约 1.1 万、读 1.59 万，$0.0297。固定前缀在 5 分钟档里冷的时候要多写一次约 1.6 万 token（约 $0.04），评审内容越长省得越多。
- 不改规则和 canon 自带的默认命令（BR-2070），只改本仓库自己的设置。

## 陷阱和假设

- `FORCE_PROMPT_CACHING_5M=1 exec claude …` 在 sh 里不保证把变量传给新程序，所以脚本用 `exec env FORCE_PROMPT_CACHING_5M=1 claude …`。
- 依赖 Claude Code 2.1.318 的行为：`FORCE_PROMPT_CACHING_5M` 优先于 `promptCacheTtl` 设置。
