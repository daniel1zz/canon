## 为什么

GitHub issue #39（C-126 合入后的代码评审发现）：skill canon-parallel 让每个子 agent 运行不带变更编号的 `canon work after-land --wait`。不带编号时它看的是所有人里最新的一次合入，几个子 agent 接连合入时，子 agent A 可能拿到 B 的结果（全部 0），把自己失败的代码评审当成通过。主 agent 的核对步骤也只看 `land.ok` 和 `land.refuse`，同样发现不了。

## 要改什么

子领域：cli/install（canon 自带的 skill）。

- 子 agent 的说明改成 `canon work after-land <C-n> --wait`，并写明不带编号的后果。
- 主 agent 的核对步骤加一条：对每个变更运行 `canon work after-land <C-n>`，确认它自己的后台命令都以 0 退出、看代码评审说了什么。
