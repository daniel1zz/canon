## 为什么

负责人选定用本会话的子 agent 做多会话实测（C-43），并指出“canon 分不开它们本身就是一个问题”（2026-11-03）。实测：主会话和子 agent 的环境变量完全一样（`CLAUDE_CODE_SESSION_ID`、`CLAUDE_PID` 相同，每次 Bash 调用都是新 shell），所以同一个执行者可以重新 start 别的子 agent 正在做的变更、drop 掉它的 worktree。C-43 实测前还需要一个“轮到我合入了”的事件，才能把排队时间和 floor 时间分开。

## 要改什么

- 有效的认领挡住所有 start，同一个执行者也一样；是同一个执行者时提示直接进入那个 worktree（BR-2011）。
- 有效的认领挡住 drop，同一个执行者也一样，要先在那个 worktree 里放开（BR-2064）。
- 合入轮到自己时写 `land.turn` 事件（BR-2122）。

## 陷阱和假设

- 这只防住了“同一个会话的子 agent 互相覆盖”，事件里仍分不出是哪个子 agent 做的。lore 用 PreToolUse hook 给每条 Bash 命令加上带 `agent_id` 的身份（lore SPEC-245），要不要照做由负责人决定。
