## 为什么

#117：`canon work test` 只看导入、规则编号和启动 CLI 的命令，所以只改了 `.claude/skills/canon-*/SKILL.md` 时，运行时读这个目录的 install/init/update/uninstall 测试一个都选不出来（`src/cli/install/install.ts` 的 `skillsSource` 用 `join(import.meta.dir, "..", "..", "..", ".claude", "skills")` 读它，没有导入）。合入前的完整测试集现在分批运行（最晚 60 分钟后），漏选会让 main 红得更久。

## 要改什么

- 测量：`src/` 里用 `import.meta.dir` 加字符串字面量拼出非代码文件路径的源码文件只有 `install.ts` 一个（`watch.ts` 拼的是 `main.ts`，是代码文件）；其余读文件的地方都以项目根目录为起点（`join(root, ".claude", …)`），读的是被测项目而不是 canon 自己的文件。
- 新增 `src/work/verify/data-reads.ts`：从源码里读出这类路径（沿用 D-60 读测试里 `join(import.meta.dir, …)` 的同一个函数），改过的非代码文件落在这个路径下时，这个模块算“读到了改动”。`selectTests` 在导入遍历和 CLI 命令遍历里遇到这样的模块就记一条理由 `reads <路径> (<改过的文件> changed, via <模块>[, through …])`。不用手写清单。
- 规则 BR-2157 原地加条件和例子；决定 D-60 原地加一段（2026-11-05，#117）；`verify.test.ts` 加两条 BR-2157 用例。
