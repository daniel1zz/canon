## 为什么

D-15 定了代码目录和规则领域一一对应，C-82 做了机制。这个变更让 canon 自己启用它（`code_root: src`、`shared: [src/kernel]`）：顶层 README 去掉 `code:`，代码按领域挪到对应目录，`canon context <文件>` 落到真正相关的子领域。只挪动和拆分，不改任何行为；floor 的全量测试是判据。

## 要改什么

- `canon/config.yaml` 加 `code_root: src`、`shared: [src/kernel]`；顶层领域 README 去掉 `code:`。
- 新子领域 `cli/install`，把安装和更新的规则 BR-2080 到 BR-2087、BR-2089、BR-2096 挪进去（内容不变）。
- 代码挪动：
  - `src/work/`：`db.ts`（原 `src/coord`）、`workspace.ts`（原 `src/app`，另外放进原来在 `work.ts` 的 `Say` 类型）、`testkit.ts`。
  - `src/work/session/`：`session.ts`（从 `work.ts` 拆出 start、stop、clean）、`handoffs.ts`（从 `state.ts` 拆出）、`overlap.ts`。
  - `src/work/claims/`：`claims.ts`（从 `state.ts` 拆出认领）、`liveness.ts`。
  - `src/work/land/`：`land.ts`（从 `work.ts` 拆出合入和来源核对）、`queue.ts`（从 `state.ts` 拆出合入队列）。
  - `src/work/drop/`、`src/work/humans/questions.ts`（从 `state.ts` 拆出）、`src/work/stats/`。
  - `src/knowledge/documents/`（read、write、templates、docfile、model、types）、`check/`、`query/`、`review/`。
  - `src/config/`：`config.ts`、`hooks.ts`；`src/cli/install/`：原 `src/skills`；`src/kernel/`：`result.ts`、`git.ts`、`process.ts`。
- 测试跟着代码走：`work.test.ts` 拆成 `session/session.test.ts` 和 `land/land.test.ts`，`state.test.ts` 拆成 `claims/claims.test.ts`、`land/queue.test.ts`、`humans/questions.test.ts`、`db.test.ts`；每个 describe 原样搬过去，测试总数不变（201 个）。
- 跟着改路径：所有 import、测试里按 `import.meta.dir` 找 `main.ts`、`.claude/skills`、`scripts/code-review.ts` 的路径，`install.ts` 找 skill 源目录的路径，`scripts/code-review.ts`，CLAUDE.md，两个 skill 里提到的源码路径，D-14、D-15 的来源路径，BR-2110 例子里的路径。

和建议布局不同的地方：

- `src/knowledge/types.ts` 放进 `knowledge/documents`，不放 `config`：它定义文档类型的模型（内置的四种类型、编号格式），整个知识部分都用它；config 只负责读取和校验 `types:` 的声明（`config.ts` 的 `readTypes`），所以 config 领域的 README 改成写明这一分工，不再列这个文件。
- `handoffs` 放在 `work/session`（`stop` 写、`brief` 读）；`land.ts` 在 `--finish` 时也会删 handoff，通过导入 `session/handoffs.ts` 做到。
- `Say` 类型从 `work.ts` 挪到 `src/work/workspace.ts`，因为 session、land、drop 和 `cli/install` 都用它。
- `scripts/` 在 `code_root` 之外，没有领域；`canon context scripts/code-review.ts` 通过它的导入带上 `knowledge/review`。
