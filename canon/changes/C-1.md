## 为什么

D-2 要求 canon 从一开始就可配置、可扩展，原来的实现把策略参数写死在代码里，文档类型固定为四种，只有 `review` 和 `after_land` 两个扩展点，配置里的未知 key 会被悄悄忽略。另外，2026-11-03 的 baseline 核对发现两个和这些参数直接相关的缺陷，一起在这里修：认领租约从不续期（issue #1），合入的心跳在 floor 结束后就停了，评审跑得久时后面的合入者会把它当成掉线（C-13 原本列了这一项，因为要配置掉线时间才测得出来，挪到这里）。

## 要改什么

配置文件的形状见 D-3。

1. 策略参数进 `canon/config.yaml`，都有默认值：`claim_lease_hours`（BR-2011）、`lander_stale_minutes`（BR-2044）、`land_timeout_minutes`（BR-2048，从 BR-2044 拆出）、`worktrees`（BR-2047）、`tests`（BR-2046，补上原来没有规则的默认查找方式）。
2. 文档类型可扩展：`types:` 声明类型；读取、`canon check`、搜索、上下文、编号分配都按声明工作；新命令 `canon doc new|list|status`；内置类型可以加必填字段（BR-2050 到 BR-2054）。
3. 生命周期 hook：`after_start`、`before_land`、`after_land`、`after_stop`（BR-2056 到 BR-2059，修改 BR-2030）。`review` 保留为内置的第一个 `before_land` 步骤；顶层 `after_land` 挪到 `hooks.after_land`，canon 自己的配置同步修改。
4. 文档模板：`canon/templates/<类型>.md`（BR-2055）。
5. 配置严格校验：所有命令在配置写错时以退出码 2 失败（BR-2045，修改 BR-2022）。
6. 修复：`canon work land` 和 `canon work stop` 续期租约（BR-2011，issue #1）；心跳覆盖整个合入（BR-2049）。

注意：PATH 上的 `canon` 是合入前构建的，不认识 `hooks.after_land`，这次合入后不会自动重建，要在主 checkout 手动跑一次 `bun run build`。
