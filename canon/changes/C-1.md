## 为什么

D-2 要求 canon 从一开始就可配置、可扩展，现在的实现把策略参数写死在代码里，文档类型固定为四种，只有 `review` 和 `after_land` 两个扩展点。

## 要改什么

按 D-2 的四个扩展点实现，每一项都要有新规则（`canon rule new`）和以规则编号命名的测试：

1. 策略参数进 `canon/config.yaml`：认领租约、掉线判定、排队超时、worktree 位置、测试匹配规则。改动现有规则 BR-2011、BR-2012、BR-2020 的写死数字，改成“默认值 + 可配”。
2. 文档类型可扩展：配置里声明类型（前缀、目录、状态、默认状态）。读取、`canon check`、搜索、上下文、编号分配都按声明工作。现在 `src/knowledge/model.ts` 和 `read.ts` 里写死的四种类型改成内置声明。
3. 生命周期 hook：`after_start`、`before_land`、`after_land`、`after_stop`。`before_land` 退出码非 0 拒绝合入（退出码 1），原因写进事件表。现有 `review` 改成内置的 `before_land` 步骤，`after_land` 并入 hook。
4. 文档模板：`canon/templates/<类型>.md`，没有时用内置模板。
5. 配置校验：未知 key、类型错误、引用不存在的模板文件时，所有命令以退出码 2 失败。
