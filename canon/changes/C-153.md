## 为什么

#46：分配编号时只数解析成功的文档。一个文件 front matter 坏了（比如 `D-7.md` 的 title 为空），它的编号不算，新建决策会从 `D-1` 起，分到 `D-7` 时就和这个文件撞号，违反 BR-2002。`canon work start --title` 分配变更编号时也有同样的问题（它自己数 `corpus.docs`）。

## 要改什么

- 读文档库时按文件名记下每个前缀出现过的最大编号（`Corpus.numbers`），解析失败的文件也记。
- `highestNumber` 同时看文档编号和文件名里的编号；`work start` 分配变更编号改用 `highestNumber`。
- BR-2002 写明解析失败的文件也算，并加一条例子；补测试：BR-2002 例子 3（数据库在 `D-9`、文件最大 `D-3` → `D-10`）、解析失败的文件占号、BR-2028 作废规则的编号不再分配。

## 教训

- 同一个“最大编号”在两处各算一遍（`write.ts` 和 `session.ts`），修一处漏一处 → 只靠文字：这次合成一处，没有通用的检查能发现重复实现。
