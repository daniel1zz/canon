## 为什么

issue #27：BR-2132 要求并发的 `canon work start` 不写 `.git/config`，但 `git worktree add -b <分支> <路径> main` 没加 `--no-track`。git 配置了 `branch.autoSetupMerge=always` 时，从本地分支建分支也会写 `branch.<分支>.remote`/`merge`，每个 start 都要去锁 `.git/config`，抢不到锁的就失败。原有测试只在默认配置（`autoSetupMerge=true`）下跑，测不出来。

## 要改什么

- `src/work/session/session.ts`：新建分支时 `git worktree add --no-track -b …`。
- BR-2132：规则写明分支不设 upstream，与 git 配置无关；例子加上 `autoSetupMerge=always` 两侧。
- 测试：`autoSetupMerge=always` 下 8 个并发 start，断言都成功且没有 `branch.change/…` 配置。

## 陷阱和假设

- 复现时（git 2.50.1）8 个并发 start 都退出 0，只是每个分支都写了 upstream 配置：BR-2223 之后 canon 的 `git worktree add` 已经在 worktree 锁里一个一个跑，canon 自己的几个 add 之间不再抢 `.git/config`；但同一时刻别的 git 进程写配置时仍会抢锁，所以根因仍是"写了配置"，测试断言的是配置为空，去掉 `--no-track` 这条测试就失败。
- 已有分支（`hasBranch`）走 `git worktree add <路径> <分支>`，不建分支，不写 upstream。

## 教训

- 并发和 git 行为相关的测试只在默认 git 配置下跑，会漏掉用户的 git 配置改变 git 行为的情况 → 待负责人确认是否固化（例如测试工具给 git 子进程设一份固定的、非默认的全局配置）
