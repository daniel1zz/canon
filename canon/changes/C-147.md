## 为什么

C-144 里 agent 用 Bash 改了文件、没提交，又用 `git checkout <文件>` 撤销实验，把改动一起清掉了；git 和 Claude Code 的 `/rewind` 都找不回。负责人要求由 canon 在项目级别安装防护（D-30）。

## 要改什么

- 新子领域 `work/snapshots`：`canon snapshot take [--hook]`（BR-2182）、保留策略（BR-2183）、`canon snapshot list`（BR-2184），工作说明加一行。
- `cli/install`：init、install、update 把 PreToolUse（`Bash`）快照 hook 合并进 `.claude/settings.json`，`update --check` 报告缺失（BR-2185）；本仓库的 `.claude/settings.json` 也加上。
- install、update 的测试数据加上快照条目（“canon 当前该装的全部条目”多了一项）。

## 陷阱和假设

- 合入后到 `after_land` 重新构建 `dist/canon` 之前，PATH 上的旧 canon 没有 `snapshot` 命令，每次 Bash 调用会看到一条“snapshot take failed”的提示，构建完就消失。
- 快照的时间来自 `takeSnapshot` 的 `now` 参数（提交日期按它写），保留策略的测试靠它造出旧快照。

## 教训

- 实验做在未提交的工作上，又用 `git checkout <文件>` 撤销 → BR-2182 到 BR-2185（快照让这类丢失可以找回）；负责人确认固化，原话：“这个 hook 应该是安装了canon才会在项目级别安装啊。我们所有的东西应该是通过项目级别安装canon实现啊”。
- 同一会话里我又在主 checkout 里改文件再用 `git checkout` 还原 → 同上：快照覆盖了这种情况；“共享 checkout 不改文件”本身仍只靠文字，canon 不判断 agent 在哪里改文件。
