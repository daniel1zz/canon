## 为什么

C-724 压缩后每个会话固定加载的文字还有 15823 字节，预算 12000。负责人 2026-11-28：「12000的话看看有哪些可以动态加载的，而不是全部直接注入」「不一定要CLAUDECODE的按需注入啊，你直接在一级注入中用一个引用，让AI自己判断需不需要注入就行啊」。

## 要改什么

D-169、BR-2654：

- 新命令 `canon guide [主题]`（`src/invocation/reference/commands.ts`）：不带主题列出全部主题和各自的时机，带主题输出全文；主题由各领域的 `guide.ts` 导出，和工作说明同一个来源。
- 工作说明只留每次都要守的；只在某个时刻用得上的挪进主题 work、findings、test、land、human、issues，说明里那一行写明时机和 `canon guide <主题>`。会让 main 出错或丢数据的约束（subagent 加 `--as`、什么时候才问人、`canon work drop`、快照）留在说明里。BR-2090 相应修改。
- canon-behavior 的证据分级、教训和提 issue 的流程挪进主题 evidence、lessons、issues；规则里留触发条件和禁止项（非 trivial 结论一律写证据标记、确认前不固化及不能改什么、简单问题的定义）。
- 在那个时刻由命令自己提示，不占常驻文字：合入第一次排队等待时说明它在后台继续、怎么跟和怎么停；合入成功后提示 `canon work after-land --wait <C-n>`；`canon human ask` 记下问题后说明照原文提问、用 `--relayed` 记下原话。
- canon 自己的 CLAUDE.md：退出码清单换成指向 BR-2022 的一句；删掉和工作说明、常驻规则重复的两句（architecture.md 是什么、issue 用 GitHub）；补上常驻规则的位置。

结果：canon 自己的会话固定加载 11951 字节（CLAUDE.md 1582、工作说明约 3200、规则约 4170、skill 描述 3034），回到 12000 以内。

## 核对

- 脚本比对：原工作说明里的每个命令、参数和占位符都还在常驻说明或主题里。
- 另一个模型（sonnet 子 agent）逐句评判了前后文本。它指出的弱化这样处理：worker 不能新建变更已由命令拒绝（`src/work/delegation/access.ts`），不挪回；合入后台运行、after-land、问人的记录方式改成在那个时刻由命令输出；评审的分档、证据标记、不能改的东西、简单问题的定义挪回常驻文字。

## 教训

- 新加说明前先问它是每次都要守的，还是只在某个时刻用得上；后者写成 `canon guide` 主题或命令在那一刻的输出，不进常驻文字 → D-169（这个做法是负责人 2026-11-28 要的工作本身，按 D-78 不另外确认）
