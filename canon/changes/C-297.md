## 为什么

评审命令在要合入的 worktree 里运行（BR-2216），变更可以改评审脚本，`claude -p` 也会读变更自己的 CLAUDE.md、.claude/settings.json 和 skills，变更仍能影响它自己的评审者（#115 剩下的口子）。

## 要改什么

评审命令改在 main 提交上的临时 worktree（分离 HEAD、建在 canon 状态目录下）里运行，规则评审和重复评审共用，结束后删，信号时也删。改 BR-2216，D-51 加方案 10（保持 proposed）。

## 陷阱和假设

评审命令的相对路径现在按 main 提交里的文件解析，被 git 忽略的文件（node_modules）在那里没有。
