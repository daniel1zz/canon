## 为什么

baseline 核对发现 cli/install 里三个互不相关的小问题，各自一个根因：

- #50：删撤回的放行规则时，`withoutRetired` 只要 `PreToolUse` 是列表就重建它，重建后为空就删掉，所以一个原来就空的 `PreToolUse: []` 也被删了（BR-2130 说原来就是空的不动）。
- `canon update` 的合入排队超时时退出码 1，BR-2022 规定排队超时是 75：调用方据此决定“再跑一次”还是“修问题”。核实：`updateProject` 把 timeout 和 refused 合成一种结果，命令一律退出 1。
- `canon update --check` 先调用 `workspace()`，它会打开并新建 `.git/canon/state.db`；BR-2084 说 `--check` 只读。

## 要改什么

- `withoutRetired` 只在 `PreToolUse` 里确实有撤回的 hook 时重建它。
- `UpdateOutcome` 区分 `refused` 和 `timeout`，`canon update` 对 timeout 退出 75。
- `canon update --check` 只用 git 找仓库根目录，不打开协调数据库。
- 规则：BR-2022、BR-2084、BR-2086、BR-2130 补上对应的句子和例子；补测试：BR-2086 合入被拒退出 1 且变更和 worktree 留着。
