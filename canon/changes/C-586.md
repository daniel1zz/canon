## 为什么

zhushenkongjian 按负责人的决定（那边的问题 #51）把 `R-2` 到 `R-4` 并进 `R-5`：`canon release drop --into` 记下了 `merged_into`，但 BR-2512 还要求把 130 条规则逐条改标成 `R-5`，改完又触发 103 条业务映射（BR-2431）和 280 KB 的合入后评审。这是 C-583 的设计漏洞。负责人在两种修法里选了“自动算进目标版本”（问题 #53）。

## 要改什么

- D-133（修订 D-130）：并进别的版本的版本把规则、计划、模块和成功标准带进最终并入的版本，否决逐条改标签加免检查。
- BR-2521（新）：顺着 `merged_into` 找最终并入的版本；那个版本的规则、计划、模块、成功标准、发布条件和冻结都把并进来的算上。
- BR-2512：只拦无处可去的取消版本；允许一路并下去，走不到没取消的版本才报。
- BR-2509、BR-2505：“标着版本的规则”和总览的 `并入` 行。
