## 为什么

负责人先要求核查 Codex 模式，确认身份、安装入口、事件解析和评审覆盖只识别 Claude 后，明确要求开始适配。现在 Codex 被记成人，子 agent 不能使用 --as，安装后的入口也不会自动加载。

## 要改什么

按 D-101 扩展运行时身份和存活探测；新增明确的安装目标，沿用已有的技能清单、预检和合入流程；合并 Codex 的 hooks 与 AGENTS.md 管理段；解析 apply_patch 和原生问答事件；将 Codex 指令与技能纳入评审、路径检查和上下文统计；新建 Codex 项目使用非交互 Codex reviewer，已有 reviewer 配置不变。为身份、安装和生命周期、工具事件及回归写真实 CLI 测试。

## 陷阱和假设

- Claude 的身份格式和无目标参数的新仓库默认值不变，两个宿主共用一份 .claude/skills 技能源。
- 实机父子会话验证了 CODEX_SESSION_ID 被继承、CODEX_THREAD_ID 随子会话变化。原生 Codex hook 没有这些环境变量，启动输入的关系记录在共享事件表；只有线程 id 的后续命令从这里恢复。没有稳定会话标识的客户端不能凭工具名称猜身份。
- Codex hooks 必须在宿主里完成 trust；异步提问客户端的未来回复不是一次同步工具结果，不能伪造佐证。

## 教训

Codex 原生 hook 进程不继承 shell 会话变量；只验证带环境变量的模拟输入会漏掉这一点。先用真实宿主验证启动入口，再按真实 payload 恢复会话，避免把缺少环境变量的原生线程记成人。原有 Claude 流程允许仅有 CLAUDE_CODE_SESSION_ID 的问答佐证和快照输入，这次归一化仍保留该边界。
