## 为什么

用 `--title` 新建的变更，变更文件只在它自己的分支上，合入前 main 上没有。会话没写交接就结束后，新会话执行 `canon work start C-n` 只在 main 上找，得到退出码 3，接不上这项工作（违反 P3）。

## 要改什么

- `start(C-n)` 在 main 上找不到时，找 `change/C-n` 或 `change/C-n-*` 分支，从它（或签出它的 worktree）读变更文件，沿用这个分支和 worktree；worktree 不在了就从分支重建（BR-2107）。
- 有多个这样的分支时拒绝并列出；认领检查不变（另一个执行者有效持有时退出码 5）。
- BR-2038、BR-2022 的文字指向新规则。

## 陷阱和假设

- `change/C-1` 不能匹配 `change/C-12-…`：只认等于 `change/C-n` 或以 `change/C-n-` 开头的分支。
- 分支签出在 worktree 里时读的是 worktree 里的文件（可能有未提交的改动），这正是接手时要看到的状态。
