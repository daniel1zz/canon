## 为什么

注入会话的内容（skill 描述、MCP 说明和工具名、插件 hook、规则文件）每次都占上下文，但有没有用只能靠人偶尔审计（N-2）。和 C-9 统计检查准确率一样，注入内容也应该能被衡量，用不上的就去掉。

## 要改什么

- 一个命令（例如在 `canon stats` 里加一节）：读取本项目的 Claude Code 会话记录（`~/.claude/projects/<项目路径编码>/**/*.jsonl`），按名称统计 skill 调用、MCP 工具调用、子 agent 类型的使用次数和最近一次使用时间。
- 对照当前会话可用的 skill 和 MCP 清单，列出“可用但 N 天没用过”的项，附上它们的大致注入量。
- 只报告，不自动改任何配置；改全局配置要人决定。
- 规则和测试；测试用伪造的会话记录目录。
