## 为什么

注入会话的内容（skill 描述、MCP 说明和工具名、插件 hook、规则文件）每次都占上下文，但有没有用只能靠人偶尔审计（N-2）。和 C-9 统计检查准确率一样，注入内容也应该能被衡量，用不上的就去掉。

## 要改什么

- 一个命令（例如在 `canon stats` 里加一节）：读取本项目的 Claude Code 会话记录（`~/.claude/projects/<项目路径编码>/**/*.jsonl`），按名称统计 skill 调用、MCP 工具调用、子 agent 类型的使用次数和最近一次使用时间。
- 对照当前会话可用的 skill 和 MCP 清单，列出“可用但 N 天没用过”的项，附上它们的大致注入量。
- 只报告，不自动改任何配置；改全局配置要人决定。
- 规则和测试；测试用伪造的会话记录目录。

落实（D-40）：

- `canon usage [--days N] [--json]`，代码在 `src/work/stats/usage.ts`，命令在 `src/work/stats/commands.ts`。
- BR-2265：读哪些目录、怎么数 skill、MCP 服务、子 agent 类型的使用，只读。
- BR-2266：可用清单取自窗口内各个会话实际注入的内容，列出 N 天没用过的项、注入量和最后注入时间。
- 测试 `src/work/stats/usage.test.ts`，用 `CLAUDE_CONFIG_DIR` 指向伪造的会话记录目录。

## 陷阱和假设

- 会话记录的格式是 Claude Code 内部的，没有公开文档；2026-11-04 用 `head` 和按关键字截取核对过（D-40 背景）。格式变了时统计会变成 0、清单找不到，报告写明，不悄悄给出错的数字。
- 同一个 `tool_use` 会在记录里出现不止一次，按 `id` 去重。
- 只取最新一个会话的清单会漏：短会话结束时 MCP 服务可能还没连上（实测只连上 2 个），所以取窗口内各会话的并集。
- 规则文件（`CLAUDE.md`、`~/.claude/rules`）的大小不在这里报告：C-59 可能在 `canon check` 里加大小报告，这里不重复。
- 不改任何配置，也不写会话记录目录；测试核对运行前后文件内容和修改时间不变。
- 路径编码：Claude Code 对很长的路径可能另有处理，这里只按“字母数字以外换成 `-`”匹配，本项目的路径实测对得上。

## 教训

- 先按“最新一个会话的清单”写了代码，在真实数据上一跑才发现 MCP 服务少了一大半（短会话没连上），改成窗口内的并集 → 只靠文字：这是“在真实数据上跑一遍再定规则”的习惯；C-34 的要求里已经写了先核对真实格式，但只核对格式不够，还要核对结果。
