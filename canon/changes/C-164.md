## 为什么

baseline 核对（N-4）在 `canon brief`、重叠提示和 `canon work status` 里找到：

- issue #55：BR-2063 写“`brief` 只读，不写事件”，但 brief 会写 `.canon/config.schema.json`（BR-2176）和 `hook.exit` 事件（BR-2137）。代码按新规则做，BR-2063 的文字要改成它真正保证的：不写 `overlap.notice`。
- brief 读 main 上的变更或待办清单时 git 出错，代码抛普通异常，退出码 70（canon 的 bug），而 BR-2022 规定 git 出错是 4。
- `overlapsOf` 吞掉 git 错误：列不出 worktree、算不出某个分支的改动时当作没有重叠，提示静默消失。
- `canon work status` 的输出和 `--json` 没有规则。
- BR-2090“配置错误的原因出现在 stdout”、BR-2163“评审建议、after_land 日志路径、after_stop 的输出都在 `lessons:` 之前”两个例子没有测试。

## 要改什么

- `briefState` 返回 Result，读 main 出错时按错误的种类退出（git 出错是 4），stdout 照样有 `canon brief failed:`；改 BR-2090。
- `overlapsOf` 同时返回比较不了的地方；`canon work start`、`canon work land` 打印 `overlap: cannot compare …`，brief 打印 `Overlap check failed: …`，都不改变退出码；改 BR-2062、BR-2063（同时修 #55 的文字）。
- 新规则 BR-2192 写 `canon work status` 现在的输出。
- 新测试放在 `src/work/session/brief.test.ts`，不碰 `session.test.ts`，免得和同时在合入的 C-158 冲突。

## 陷阱和假设

- `canon work status` 列认领表的每一行，不判断租约和进程（BR-2192 照实写了）；是否改成只列仍然有效的认领，留给负责人。
- brief 里 sqlite 或临时目录出错仍是抛异常、退出码 70，这次只改了 git 读 main 的路径。
