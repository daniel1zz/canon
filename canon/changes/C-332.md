## 为什么

领域应按业务能力命名和划分（DDD），现在只有 `canon brief` 里一句话，没有任何检查；canon 自己的基线就有 `cli`、`config` 这样按技术层命名的领域。负责人要把指导里能检查的部分做成检查（指导 skill `canon-domains` 由另一个会话写）。

## 要改什么

- `canon rule domain <名字>`：名字最后一段是技术层的词（代码里 `TECHNICAL_LAYER_WORDS`）时照常建出、退出码 0，多一行 `hint:`（BR-2317）。
- `canon check` 把这样的已有领域作为 `note:` 写在标准错误上，不算发现、不拦截合入；`canon rule domains` 在领域那一行旁边也说（BR-2318）。
- 领域 README 必须有 `## 术语`：测量后这条检查已经存在（BR-2091，`doc-missing-section`），canon 自己所有 README 都有；只补「整节缺失」的例子和测试，不改行为。

## 陷阱和假设

- 测量：canon/rules 下 26 个 README（`find canon/rules -name README.md`）都有 `## 术语`；技术层名字的有 `cli`、`config`（顶层），所以第二项只能是提示。
- `canon work land` 的输出没有加这条提示（只加在 `canon check` 和 `canon rule domains`），避免每次合入都重复。
- 不改 canon 自己的领域名。
