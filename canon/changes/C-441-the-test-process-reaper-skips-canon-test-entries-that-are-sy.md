## 为什么

#163：清理测试遗留进程的脚本（C-429）把运行目录下每个名字像 `canon-test.<pid>.<随机>` 的条目都当成一次测试运行，只检查它是不是目录。符号链接也算目录，进到里面时又解析成真实路径，所以一个指向别处的同名符号链接，会让脚本把那个目录里正在运行的进程全部用 SIGKILL 杀掉。在多人共用的 `/tmp` 里，别的用户可以造出这样的链接。

## 要改什么

- 测试脚本启动时清理旧运行、手动运行清理脚本（列出或 `--kill`）时，只认这个用户自己拥有的真实目录；符号链接和别的用户的目录跳过，不列出、不杀、不删。
- `--run <目录>` 给的是符号链接时，不跟过去。
- 测试：一个指向别的目录的同名符号链接，目录里的进程在三种入口下都不被列出或杀掉，目录本身也不被删除。别的用户拥有的目录在测试里造不出来，只靠代码里的 `// reason:` 说明。

不做：不改按工作目录找遗留进程的办法。
