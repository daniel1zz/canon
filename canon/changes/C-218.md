## 为什么

`canon/rules/work/land` 直接放了 34 条规则，超过 CLAUDE.md 定的一个领域 25 条的拆分线，读合入相关的规则要从一长串里挑。负责人 2026-11-04 选择“现在拆 (推荐)”。

## 要改什么

按业务能力把 work/land 拆成四个子领域，规则文件用 `git mv` 移动、内容不变、编号不变；代码目录跟着规则领域走（D-15，`code_root: src`），行为不变。

- `work/land/checks`（合入的检查）：BR-2013、BR-2014、BR-2015、BR-2016、BR-2031、BR-2043、BR-2094、BR-2105、BR-2106、BR-2164、BR-2248。代码 `src/work/land/checks/`：每个变更自己的步骤（`canon check`、执行记录、来源核对、评审、`before_land`）、floor 和跳过 floor、BR-2248 的配置键和检查名比较。
- `work/land/queue`（排队和轮次）：BR-2020、BR-2044、BR-2048、BR-2049、BR-2098、BR-2099、BR-2122、BR-2144、BR-2153、BR-2177、BR-2178、BR-2232。代码 `src/work/land/queue/`：队列表的读写、优先级、等待时的轮询间隔、冲突预测、失去轮次。
- `work/land/batch`（一起测）：BR-2172、BR-2173、BR-2190、BR-2191。代码 `src/work/land/batch/`：组批、在临时 worktree 里测、锁定、成员被合入后的收尾。
- `work/land/finish`（移动 main 和收尾）：BR-2017、BR-2018、BR-2030、BR-2125、BR-2161、BR-2229。代码 `src/work/land/finish/`：比较并交换移动 main、放行标记、关闭提交的撤回、`--finish` 释放认领、`after_land`。
- 留在 `work/land` 本身：BR-2193（git 或文件操作本身失败时以 `environment` 拒绝），它横跨关闭提交、rebase、读 main 和移动 main 几步，不属于任何一个子领域。`src/work/land/` 直接放的文件是整个合入流程（`land.ts`：从进队列到移动 main 的编排）和几个子领域共用的东西（结果类型、worktree 状态、配置键、命令、工作说明），BR-2118 允许有子领域的领域目录直接放文件，它们属于 work/land。
- 测试跟着它测的代码移动；测整个流程、横跨几个子领域的测试文件（`land.test.ts`、`cli.test.ts`、`boundaries.test.ts`、`environment.test.ts`）留在 `src/work/land/`。
- work/land 的 README 只留横跨整个领域的说明和术语，其余写进各子领域的 README。
- 代码移动后，D-14、D-21、D-32 的来源里引用的摘录从 `src/work/land/land.ts` 移到了 `src/work/land/checks/steps.ts`，来源路径跟着改；D-32 上 C-182 留下的评审意见（“不挡任何合入”和 BR-2033、BR-2034 的发现矛盾）在这里处理：D-32 那句改成“缺测试不挡合入”。
- 其他目录只改移动逼出来的 import：`src/cli/install/githook.ts`（`LAND_MARKER`）、`src/work/session/commands.ts`、`src/cli/install/update.test.ts`、`src/work/claims/claims.test.ts`、`src/work/stats/stats.test.ts`、`src/work/watch/land-after.test.ts`（队列）。

## 陷阱和假设

- 这次移动了很多文件：34 个规则文件和 work/land 下的大部分代码、测试。规则文件是纯改名，内容不变，所以合入时不重新评审，执行记录的哈希也不变（D-32 按内容算）；改了的只有 README、三个决策和代码。
- 代码只搬函数、不改函数体；`land.ts` 原来的私有函数改成从子目录导出。行为不变由 `canon work test --all` 证明。
- `src/work/watch` 正由另一个会话修 #90，这里只改 `land-after.test.ts` 里一行 import（`queue.ts` 的新位置）。
- BR-2248 认 `config-keys.ts` 和 `checks.ts` 时不看目录，`src/work/land/config-keys.ts` 留在原处。

## 教训

- 搬代码会让决策来源里引用的摘录悄悄失效：`canon check`（BR-2110）只看来源文件还在不在，不看摘录还在不在文件里，合入时的核对（BR-2111）只核对新增的来源；这次 D-14、D-21、D-32 的三条来源是靠 grep `canon/decisions` 找出来的 → 待负责人确认是否固化（可以让 `canon check` 离线核对文件来源的摘录仍在文件里）。
- 移动测试文件时，静态 import 由类型检查兜底，但 `import.meta.dir` 拼出来的路径（`../../cli/main.ts`）只有运行测试才会发现 → 由 `canon work test --all` 保证（路径错了测试直接失败）。
