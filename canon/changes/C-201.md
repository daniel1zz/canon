## 为什么

baseline 核对（N-4）发现两处读 main 的问题：`canon work clean` 用 `git branch -d` 删已合入的分支，而 git 按主 checkout 当前签出的提交判断，主 checkout 不在 main 上时已合入的分支被悄悄留下（BR-2188）；`canon work start C-99` 在 git 读不出 main 时退出码 3 而不是 4（issue #77，`corpusOf` 把“读不出 main”当成“main 上没有 canon/”）。负责人 2026-11-04 选择推荐方案：“全部按推荐”。

## 要改什么

- `src/work/session/session.ts`：clean 删掉 worktree 后，读分支现在的提交，确认它完全包含在 main 里，再用 `git update-ref -d refs/heads/<分支> <提交>` 按这个提交删除；改 BR-2188 的规则和第三个例子。
- `corpusOf`：没有 worktree 签出这个 ref 时，先 `git rev-parse --verify <ref>^{commit}`，读不出就返回环境错误（退出码 4），写明 git 读不出哪个分支；BR-2022 已有这个例子，补测试。
- BR-2188 上的评审建议（和 BR-2019 不冲突、git 拒绝删时分支留下）：规则改成按 main 判断后，“git 拒绝”换成“有不在 main 上的提交或删前动过”，仍然写明分支留下、不报错。

## 陷阱和假设

- 主 checkout 签出 main 时（即使 main 还没有提交），`corpusOf` 从那个 worktree 读，不走 git，所以新仓库里 `canon brief` 不受影响。
- 按提交删除：分支在确认之后多了提交时 `update-ref -d` 失败，分支留下，不丢工作（BR-2019）。
