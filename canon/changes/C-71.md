## 为什么

`canon work land` 的 floor 在 agent 自己的 worktree 里跑，HEAD 在 floor 之后才读：floor 运行期间做的提交会不经测试进入 main。排队等待期间留下的未提交改动会让 rebase 失败，却被报成文件列表为空的 `conflict`，看不出真正原因。

## 要改什么

- rebase 之前再检查 worktree，有未提交改动就以 `dirty` 拒绝并列出文件（BR-2105）。
- rebase 之后记下 HEAD；评审和 `before_land` 都用这个提交；移动 main 之前确认 HEAD 没变、worktree 干净，否则以新原因 `moved-during-land` 拒绝（退出码 1），写明变了什么（BR-2106）。
- `canon stats` 的检查顺序加入 `moved-during-land`（BR-2067）；BR-2013、BR-2022 引用新规则。

## 陷阱和假设

- floor 写出没有被 git 忽略的文件也算 worktree 变了。被测的树里有这些文件，合入的树里没有，所以要拒绝；项目应当把这类产物加进 `.gitignore`。
- 只在移动 main 之前检查一次，所以 floor 期间的改动要等评审和 `before_land` 跑完才发现；这样 `canon stats` 里各步的顺序是准确的。
