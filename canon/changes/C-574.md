## 为什么

#237：zhushenkongjian 的 `C-704` 只给版本文件 `R-5.md` 加了一行（点名 `power` 领域的规则），合入后评审却计划了 127 次调用、约 74 MB 提示，停下来问负责人。原因是改动的决策或版本会把它全文点名的所有规则的顶层领域整个放进评审（`contextTops`、`namedTops`），那个版本点名了 116 条规则，几乎覆盖所有领域。

## 要改什么

main 上已有的决策或版本，只取这次合入新写或改动的行里点名的规则的顶层领域（`ReviewExtras.namedInAdded`，在 `review-scope.ts` 按合入的 base 算出，传给合入后评审、预览和小评审，分部分时跟着它的文档走）；新建的决策或版本照旧按全文。每次调用都带全部规则的标题索引（BR-2036），版本标注的规则列表另外加，所以没改的行点名的规则仍能被对照。BR-2009 写明这一点并加例子。
