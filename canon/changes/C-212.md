## 为什么

评审建议不拦截合入，只挂在它点名的文档上，等下次改这份文档的人处理（D-21、BR-2145）。现在只有 `canon context`（BR-2146）和变更 worktree 里的 `canon brief`（BR-2147，只看变更文件提到的编号）会列出它们；动手时没看 `canon context`、或者改了变更文件没提到的规则，就会漏掉，C-199 就漏了这样的建议。合入前人人都要跑 `canon work test`，在那里提示最不容易漏。负责人 2026-11-04 在 AskUserQuestion 里选择：“改规则时提示它未处理的评审建议”。

## 要改什么

- 新规则 BR-2249（work/verify）：`canon work test` 在 `canon check` 之后，对本变更改到的每个规则和决策列出未处理的评审建议，只作提示，不影响退出码。
- 代码：`src/work/verify/verify.ts`。`changesOf` 另外算出改到的决策（改动过的决策文件）；`workTest` 用 `src/knowledge/review/notes.ts` 的 `openNotes`（`canon context` 用的同一个函数）查建议并输出。
- 测试：`src/work/verify/verify.test.ts`，按 BR-2249 的例子。

## 陷阱和假设

- “改到的规则”沿用 BR-2157 选测试时已经算出的那一组（改动过的规则文件，加改动过的变更文件 `rules:` 里的规则），不另定一套。
- 输出格式跟 BR-2147 的 `Open review note on <编号>: <建议>` 一致，后面加上 `canon context` 也显示的来源变更和日期。
- 只作提示：退出码和 `work.test` 事件都不变，所以 BR-2158 不用改。
