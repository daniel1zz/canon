## 为什么

编译后的 `canon rule --help` 输出 `USAGE canon /$bunfs/root/canon new|list|...`，`canon decision --help` 也一样。原因是 citty 的 `renderUsage` 在命令没有 `meta.name` 时用 `process.argv[1]` 当名字：编译后的二进制里它是 `/$bunfs/root/canon`，用 `bun src/cli/main.ts` 运行时是脚本路径。再往下一层（`canon rule new --help`）还会丢掉 `rule`，因为 citty 只拼上一层的名字。

## 要改什么

- `src/cli/main.ts` 的帮助输出：把解析出的命令路径交给 `renderUsage`，命令名用最后一个词，上一层的名字用 `canon` 加前面的词。
- 新规则 BR-2101，测试经 `bun src/cli/main.ts` 运行：脚本路径和二进制路径是同一个缺陷，所以不需要编译就能测；编译后的二进制另外手动验证过（`./dist/canon rule --help` → `USAGE canon rule new|list|retire|domain|domains`）。
