## 为什么

C-136 和 C-139 合入时，规则评审对 BR-2176 提了三条建议：清理和放弃时 `.canon` 算可以重建，是 `canon work clean`、`canon work drop` 的行为，应该单独成规则；`canon config` 写不了 schema 时的那一侧没有例子；两个会话同时追加留下重复行后，再运行是否还追加没有钉住。C-139 改了 BR-2176 却没处理这些建议，这里补上。

## 要改什么

- 新规则 BR-2179（work/session）：清理或放弃 worktree 时 `.canon` 总算可以重建；测试分别放在 clean 和 drop 的测试文件里。
- BR-2176 去掉这一段，改为指向 BR-2179；补“已有两行不再追加”和“`canon config` 写不了时照常列出”两个例子和测试。

## 教训

- 改一份有未处理评审建议的文档时漏看了建议 → 只靠文字：`canon brief` 在变更 worktree 里已经会列出未处理的建议（BR-2147），这次是我开完变更没读 brief 的输出，不是机制缺口。
