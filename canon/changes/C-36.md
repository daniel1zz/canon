## 为什么

负责人要求：canon 装进项目的所有东西（不只是 skill）都要能自动发现更新，告诉用户，用户要求时更新；不要自动更新。参考了旧系统 lore 的同类机制和教训，取舍见 D-10。

## 要改什么

- 版本号由 skill 内容算出；`canon update --check` 当场比较并列出过期项（BR-2084）。
- `canon brief`、`canon work start` 过期时提示一行（BR-2085）。
- `canon update` 作为单独的变更安装、提交、合入（BR-2086）。
- 会话开始时运行 `canon brief` 的 hook 合并进项目的 `.claude/settings.json`（BR-2087）；`canon init` 和 `canon install` 都装它。
- `canon skills install` 改名为 `canon install`；BR-2080 到 BR-2083、BR-2022、CLAUDE.md 同步。

## 陷阱和假设

- 生成给其他项目的变更说明不能引用 canon 自己的编号，否则那个项目的 `canon check` 会报悬空引用（开发时实际踩到）。
- canon 自己的仓库里，skill 的源头就是目标，所以只会装 hook。
