## 为什么

baseline 核对（N-4）发现：字符串选项的值以 `-` 开头时（`--title "-x"`），命令行解析把它当成选项，以退出码 2 拒绝；只有写成 `--title=-x` 才行。负责人 2026-11-04 选择推荐方案：“全部按推荐”：字符串选项总是把下一个词当作值，`--title=-x` 照常可用。

另外处理 C-189 合入时的评审建议（不拦截，但改的是同一组文档）：cli 领域 README 的术语表仍写“75 排队超时”；BR-2123 写守卫在没有配置文件时守 `main`，和 `canon init` 现在守当前分支对不上；分离 HEAD 的拒绝和 BR-2124 别人的 hook 的拒绝谁先没写明。

## 要改什么

- 新规则 BR-2228：字符串选项 `--名字 <词>` 总是把下一个词当作值（包括 `-x`、`--json`、`--help`、`--`），`--名字=<值>` 照常；布尔选项不变。
- BR-2194：帮助选项只在选项位置生效，字符串选项后面的 `--help` 是值。
- 代码：解析是共用的（`src/cli/strict.ts`，所有命令都经过 `src/cli/main.ts` 的同一入口，没有命令自己读 `process.argv`），加 `bindValues`：按层找到声明这个字符串选项的命令，把 `--名字 -x` 合成 `--名字=-x` 再交给 citty；参数检查（BR-2097）也改成总是吃掉下一个词。
- 评审建议：cli README 的 75 改成新含义；BR-2123 写明 `canon init` 没有配置文件时守它要写进配置的当前分支；BR-2032、BR-2124 写明分离 HEAD 的拒绝（4）在别人的 hook（5）之前，加例子和测试。
- 测试：新文件 `src/cli/string-option.test.ts`（不放进 `src/cli/main.test.ts`）；`src/cli/install/init.test.ts` 加先后顺序的例子。

## 陷阱和假设

- 只合并值以 `-` 开头的那一对：citty 对其他值本来就读对；对空字符串值 `--title ""` 合成 `--title=` 反而会让 citty 去吃再下一个词。
- 合并在 `--help` 检查之前做，所以 `--title --help` 不打印帮助；这是 BR-2194 改过的边界。
- `--title` 在行尾、后面没有词时行为不变，这次不定义。

## 教训

- 帮助、`--`、参数检查和 citty 的解析各自判断“这个词是不是选项”，四处必须一致；这次把判断集中在 `bindValues` 一处之后再交给其余三处 → 由 BR-2228 的测试保证（四处任一不一致，`--title --help` 或 `--title -x` 的例子会失败）。
