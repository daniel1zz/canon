## 为什么

D-1 的目标设计里，编辑时不做任何拦截，“两个变更改了同一个文件”只在合入时由 rebase 冲突暴露（BR-2015）。等到合入才发现，后合入的一方往往要返工。旧系统的锚点检查用“编辑前拦截”的方式处理这件事，误拒率很高（270 次里 148 次误拒）；这里只做提示，不拦。

## 要改什么

1. `canon work start` 和 `canon work land` 时，对比当前变更分支和其他进行中变更的分支各自相对 main 改了哪些文件（`git diff --name-only main...<分支>`），有重叠就提示：哪个变更、哪些文件。
2. 只提示，不改变退出码；提示写进事件表（`overlap.notice`），以后可以统计提示有没有用。
3. `canon brief` 里也显示当前变更和别人重叠的文件。

范围：只比较已提交的改动；“进行中的变更”指 worktree 目录（BR-2047）下签出了变更分支的 worktree，不管认领是否已释放。`brief` 只读，不写事件。
