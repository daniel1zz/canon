## 为什么

合入后的代码评审发现（#44）：`canon brief` 和 `canon config` 往 git 公共目录的 `info/exclude` 加 `/.canon/` 时，先读出整个文件再整个写回。写回会先清空文件，另一个 worktree 这时运行 git 会读到空的 exclude，只靠它忽略的文件变成未跟踪，合入被判成 dirty；读和写之间别人追加的行也会被覆盖掉。

## 要改什么

- `src/config/reference/reference.ts` 改成只在末尾追加一行，不重写文件。
- BR-2176 写明“只追加”，补一个已有内容保留的例子和测试。
