## 为什么

C-39（D-38，BR-2259 到 BR-2263）已经合入，main 的后台测试在包含它的提交 3bca962 上通过，PATH 上的 canon 已从那里重新构建、认得 `remote` 这个配置项。现在在本仓库打开它，让每次合入后 main 自动推到 GitHub，不再靠人手动推。

负责人 2026-11-04 的选择（原话）：“做好就打开并推送”。

## 要改什么

- `canon/config.yaml` 加 `remote: origin`（`origin` 是 `git@github-daniel1zz:daniel1zz/canon.git`，已用 `git remote -v` 核对）；`remote_timeout_seconds` 用默认的 60 秒。
- 不改规则和代码。这次合入本身就会第一次推送：把本地 main 上全部没推的提交一次推上去，只推 `main`，不推标签和别的分支，不强推（BR-2259）。

## 陷阱和假设

- 开始前远端的 main 是 `11c5ebf`，是本地 main 的祖先，所以第一次推送是快进；如果合入前有人往 GitHub 推了本地没有的提交，推送会以 `push.fail` 失败、合入照样成功（BR-2260），这时不强推、不合并，交给负责人决定。
- 新配置项不能和新增它的代码同一次合入（BR-2248），所以分成 C-39 和这个变更两次。
