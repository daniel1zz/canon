## 为什么

#158：机器负载很高时（load 61 到 175），证明 BR-2044 的心跳测试会超时：合入在 20 秒内没进入队列。分拣时（8fa69dbc，load 20 到 46）单独跑这个测试文件 11 个全过，没有复现。入队前合入要先跑几次同步的 git 命令（续认领、读 HEAD、检查是否干净、找重叠），负载高时每次都慢，而测试等待的时限是固定的 20 秒。根因还没确定。

## 要改什么

- 先测量：在高负载下给入队前的每一步计时，找出哪一步慢、慢多少。
- 如果是某一步本身异常慢，把它改快，按它所属的规则补测试。
- 如果每一步只是按负载等比例变慢，就让测试的等待时限随机器负载放宽（改测试工具，不改产品行为），并在代码里用 `// reason:` 写明测得的数据。
- 不把超时直接调大了事；结论和数据写进这个变更文件。

不做：不改 BR-2044 本身的心跳行为。
