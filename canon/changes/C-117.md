## 为什么

GitHub issue #34（C-115 合入后的代码评审发现）：`reopen` 先查最上面的提交，再单独执行 `git reset --keep HEAD~1`，两步之间会话若在同一个 worktree 里提交了修复，reset 会把分支移回关闭提交，修复提交和文件都没了。

## 要改什么

子领域：work/land（`src/work/land/land.ts` 的 `reopen`）。

- 先取一次 HEAD 的提交编号，检查都针对这个编号；分支用 `git update-ref HEAD <父提交> <检查过的提交>` 比较并交换地移回，再用 `git read-tree -m -u` 更新变更文件；后者因本地改动失败时把分支交换回去。
- BR-2018 改写撤回的方式，补一个例子和测试。

## 陷阱和假设

- `update-ref` 和 `read-tree` 之间仍有极短的窗口：这时提交的话，暂存区里的变更文件还是 done，会随那个提交留下，但不会丢任何提交。
