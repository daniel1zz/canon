## 为什么

#94（C-34 合入后的代码评审）：`canon usage` 先列出目录和文件，之后才读。Claude Code 会话启动时会删掉超过 `cleanupPeriodDays`（默认 30 天）的旧会话记录，于是一个已经列出的文件或目录可能在读之前消失，`readFileSync`、`statSync`、`readdirSync` 抛出 ENOENT，没人接住，命令以退出码 70（canon 的 bug）结束，什么报告都没有。只读的报告应该跳过消失的文件。

## 要改什么

- BR-2265：列出之后、读到之前被删掉的文件或目录跳过，不算进文件数，不报错；补例子。
- 代码：`src/work/stats/usage.ts` 里列目录、判断目录、列文件、读文件都经过 `unlessGone`，ENOENT 和 ENOTDIR 时当作不存在，其他错误照样抛出；`usageReport` 多一个可选的 `read` 参数，测试用它在扫描中途删文件。
- 测试：`src/work/stats/usage.test.ts` 加 BR-2265 的用例：扫描中途删掉一个文件和一个目录。

## 陷阱和假设

- 只吞 ENOENT 和 ENOTDIR：权限错误之类仍然抛出，不会悄悄少算。

## 教训

- 读一个别的程序会同时清理的目录时，“先列出再读”之间有空档 → 只靠文字：C-34 写代码时没有想到 Claude Code 自己会删旧记录；合入后的代码评审这次抓到了，和 BR-2205（`canon stats` 数共享代码时跳过消失的文件）是同一类问题。
