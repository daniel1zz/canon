## 为什么

baseline 核对（N-4）在 knowledge/documents 里发现几处没有规则描述、要负责人选的行为，负责人 2026-11-04 选择推荐方案：“全部按推荐”。

- `canon change drop` 对已完成（done）的变更照样把它改成 dropped，事件表里也多一条 `change.status`；已完成的工作被记成“没做”，统计（`work/stats` 把 dropped 算作放弃）跟着出错。
- `canon rule retire` 对已经作废的规则照样重写文件、再记一条 `rule.status` 事件，同一次作废记了两遍。
- D-3 的“决定”写着数值“必须大于 0”，而 BR-2177 允许 `land_keep_place_minutes` 为 0（表示不保留位置），读 D-3 的人会以为两者矛盾。

## 要改什么

- BR-2041：`canon change drop` 只对 open 的变更生效；变更已是 done 或 dropped 时退出码 2，不写文件，不记事件。
- BR-2028：`canon rule retire` 对已经作废的规则不写文件、不记事件，输出 `already retired`，退出码 0。
- `src/knowledge/documents/commands.ts`：在 `setStatus` 写文件之前做这两项判断。
- D-3：在“决定”里那句“必须大于 0”后面加一句注：`land_keep_place_minutes` 可以是 0（BR-2177）。没有规则禁止改已接受的决策的文字，只是补一句说明，不改决定本身，所以不新建决策。

## 陷阱和假设

- `canon work drop`（`work/drop`）是另一回事：它删除 worktree 和分支，不经过 `canon change drop`，这里不动它。
- 对已作废的规则再作废算成功（退出码 0），因为结果已经是用户要的；对 done 的变更 drop 是拒绝（退出码 2），因为那会改写已完成的事实。两者不对称是负责人选的。
