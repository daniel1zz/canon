## 为什么

主神空间 2026-11-23：`C-1163` 带 `owner_gate`、验收项留给负责人看帧定，`C-1060`→`C-1070`→`C-1071` 都排在它后面，整条到发布的链停了一夜。独立复核（子 agent 读了两个仓库）发现 canon 没有挡开工（BR-2564），真正的问题是看不见：主神空间的议程 `judge: 192`，`owner-gate:C-1163` 在第三档、开始时间是 `-`，被 117 条 `commitments`、24 条 `review-failed` 埋掉，主会话一直没去问负责人。负责人：「不要卡在某个小点，保证大流程的进度」「canon的一些约束是给你兜底的，而不应该变成卡住你的上限」，在三个方案里选了「机制+提示」。

- 新规则 BR-2635：议程里说某个变更的项（owner-gate、land-refused、stalled、slow、interrupt、awaiting-close、design、reverted，以及关于这个变更的问题），在有打开的变更等它时写明挡住了哪些（按 BR-2564 的未满足依赖一层层往下找），从第三档移到第二档、档内按挡住的个数排前、不和同类合成一行；`--json` 多 `holds`；`owner-gate` 的开始时间取这个变更最早的事件。
- BR-2527 指向 BR-2635。
- `canon brief` 问负责人那一条加一句：挡住了别的变更的项先处理，等负责人时现在就问，或者不带 `--finish` 先合入给负责人看。
