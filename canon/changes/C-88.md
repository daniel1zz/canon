title: 在变更的 worktree 里，canon brief 只显示这个 worktree 自己的工作
status: open

## 为什么

`canon brief` 由会话开始的 hook 注入每个会话。今天它在变更的 worktree 里也输出“Unfinished changes with handoffs: …”和等人回答的问题数量，把别的会话的工作塞给一个只该做自己变更的会话。lore 实测过同样的注入，结论见 lore SPEC-166（`docs/requirements/spec/SPEC-166-session-start-injection-carries-only-the-session-s.md`）：

> `latest_handoffs` | 3 plan handoffs | NEGATIVE — the feed rule forbids acting on them, so a counter-rule exists only to neutralize the injection

> only a session opened in a linked worktree (a seat) is handed anything at start, and only that seat's own open items … Corpus-global state becomes pull-only

另外，C-87 之后租约有效时 `canon work start` 总是被拒绝，但 BR-2011 还写着 worktree 里的 `canon work start` 会续期（合入评审指出）。

## 要改什么

- 认领了变更的 worktree 里，`canon brief` 只输出工作说明、这个变更、它的 handoff 和重叠提示；别的变更的 handoff 列表和问题数量只在主 checkout 或没有认领的 worktree 里输出（BR-2024）。BR-2085 的过期提示两处都照样输出：它说的是项目里装的文件，不是别人的工作。
- BR-2011：续期的命令里去掉 `canon work start`。

## 陷阱和假设

- 主 checkout 里的会话看得到所有 handoff，这是它挑工作的入口；拉取全局状态用 `canon work status`、`canon human pending`。
