## 为什么

C-603 的 E 步。合入拒绝里，合入时的措辞判断拒了 137 次、证据检查拒了 27 次，是最大的两个来源；两者都是「流程是否走全」的检查，按 D-139 应该是标准加提醒，不是拒绝。措辞判断还是合入里唯一的模型调用，和 D-137 的「合入只做机械检查」相反。负责人 2026-11-20 另外把关键程度从「合入前验收」改成「合入后验收，不拦」。决策见 D-141（修改 D-137、D-32）。

## 要改什么

- 证据检查不拒绝：没有证据的规则不写通过记录、照常合入，以待重新执行进 main；合入输出每条规则怎样补证据，记 `execution.unverified` 事件，`canon work due`（和 `canon brief` 的 Due now）列出 `unverified:<C-n>`，直到这些规则有了当前文字的通过记录（BR-2241、BR-2527）。`canon work test` 列出这些规则只作提示，不再因此失败（BR-2456）。
- 措辞判断挪到合入之后：合入不调用模型；关闭提交照旧写 `… wording` 记录，合入后的评审单独问一次措辞判断，没确认的规则记成挂在它上面的未处理评审意见（标准 `wording`），不撤回、不拒绝（BR-2239、BR-2243、BR-2010、BR-2441）。`canon work review` 的提示语跟着改（BR-2358）。
- 合入自己跑相关测试：排队前跑改动的测试文件和点名碰过的规则、还没有当前内容报告的测试文件，失败就不排队（BR-2542）；rebase 后在被合入的树上同样跑没有报告的相关文件（BR-2381，取代原来只跑「rebase 合进来的」文件）。`canon work test` 跑过的不重跑。
- 关键程度和合入后验收写成规划中的规则 BR-2543、BR-2544，本变更不实现（需要一个能从真实入口驱动产品的验收 agent 和它的配置）。负责人 2026-11-20 定：这两条并进质量标准的变更一起做，那边的「独立 agent 从真实入口判定」和这里的合入后验收是同一套东西，只做一次。
- 提到合入时措辞判断或证据拒绝的规则和文档一并改：BR-2022、BR-2074、BR-2216、BR-2296、BR-2366、BR-2490、BR-2014、BR-2057、BR-2106、BR-2218、BR-2049、BR-2388、BR-2407、BR-2062、BR-2237、BR-2245、BR-2344，三个领域 README 和 `canon/architecture.md`；D-127、D-137 里引用 BR-2241 旧文字的来源改成引用 D-32。

## 方案依据

沿用 D-139（重提醒、轻拦截）和 D-89（评审在合入之后），新选的是：缺证据和措辞未确认都落成已有的「待重新执行」状态和评审意见，而不是新的拒绝；合入自己跑测试取代 `test-report-missing` 在合入时的拒绝。最坏的失败：没有证据的规则以待重新执行进 main 后没人补，`unverified:` 一直挂着；或者措辞判断判成行为的规则在意见处理之前显示为已通过。如果 `unverified:` 项在 `canon work due` 里停留超过一周的变多，就说明提醒不够，应让它们进入按规则的验收（knowledge/accept）挡住那几条规则，而不是改回拒绝合入。

本变更没有新的持久化结构：`execution.unverified` 只是事件表里的一种新事件，丢了只是少一条提醒（规则的执行状态照样由通过记录算出）；措辞意见用已有的 `review_findings` 表。

## 陷阱和假设

- 合入本变更时用的是 PATH 上已发布的 canon，它还带着旧的证据检查和措辞判断：本变更改了行为哈希的每条规则，都要在点名它的测试里有改动行，否则旧 canon 会拒绝。
- 合入前自己跑测试发生在关闭提交之前，所以关闭提交的通过记录读得到这些报告；若放到 rebase 之后，记录会和合入时重算的不同，被 BR-2242 以 `passes` 拒绝。
- 措辞判断的 `wording` 意见不在规则评审的标准列表里（评审不能给出它），只由 canon 在合入后写。

## 教训

- 合入用的是已发布的 canon，改合入检查的变更自己先要过旧检查 → 只靠文字：这是发布方式决定的，写在本变更的陷阱里，没有检查能提前告诉会话哪些旧检查还会生效。
