## 为什么

本仓库合入时的规则评审（`scripts/review-claude.sh`）和合入后的代码评审（`scripts/code-review.ts`）都调用 `claude -p`，没指定模型，用的是默认的 opus；每次都是新会话，内容全部按写缓存计费。2026-11-04 的用量里，合入内的 `claude -p` 约 280 个 opus 请求、约 3000 万 token 写缓存。负责人选择“两个都用 sonnet (推荐)”。

## 要改什么

- `scripts/review-claude.sh` 改为 `claude -p --model sonnet --output-format text`。
- `canon/config.yaml` 的 `after_land` 用 `CANON_CODE_REVIEW_AI='claude -p --model sonnet --output-format text'` 运行代码评审。脚本和 canon 自带的默认命令不变（BR-2070），只改本仓库自己的设置。
- 实测：`echo 'Reply with exactly: ok' | claude -p --model sonnet --output-format json` 的 `modelUsage` 只有 `claude-sonnet-5-5`。
- 不改规则和代码。
