## 为什么

#327（zhushenkongjian 的 `C-1400` 报告）：把一整块业务迁出仓库时，领域的规则全部 `canon rule retire`，代码目录删掉，`canon check` 却二选一必报：README 留着 `code:` 报 `domain-code-missing`，去掉 `code:` 报 `file-invalid`。退役的规则因此合不进去，除非留着死代码或死路径。

## 要改什么

- 新规则 BR-2653：一个领域连同子领域至少有一条规则、而且全部 retired 时，不再要求代码：没有 `code_root` 时 README 可以不写 `code:`、写的路径可以不存在；有 `code_root` 时可以没有目录。BR-2006、BR-2079、BR-2118 各加一句例外。
- `src/knowledge/documents/model.ts` 加 `domainRetired`；`read.ts` 读完全部规则后才判断 `code:` 为空；`check.ts` 的 `domain-code-missing` 和 `code-layout` 跳过退役的领域。

没有规则的新领域、还有 active 或 planned 规则的领域照旧检查。没有新做 `canon rule domain --retire` 命令：规则全部 retired 本身就说明领域退役了，不需要另记状态。
