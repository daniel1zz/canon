## 为什么

lore 的 KN-534 实测：子 agent 的 worktree 默认从 `origin/main` 建，有一次比本地 main 落后 56 个提交，子 agent 在旧代码上干了活。这台电脑在全局设置里设了 `worktree.baseRef: head`，但别的用 canon 的项目、别的电脑没有。

## 要改什么

- 新规则 BR-2264：`canon init`、`canon install`、`canon update` 把 `worktree.baseRef: "head"` 合并进项目的 `.claude/settings.json`（和会话 hook 同一次写入，只管这一项，BR-2087 的做法）；缺少或不是 `"head"` 时 `canon update --check` 列为过期。
- BR-2084 的过期项清单、BR-2087 里“canon 只管哪几项”加上它。
- 代码：`src/cli/install/hook.ts` 的 `hookStatus`、`planHook` 多管一项；`src/cli/install/update.ts` 的 `assetsStatus` 多列一行。
- canon 自己仓库的 `.claude/settings.json` 同一个提交里加上这一项，否则合入后 main 上的 `canon update --check` 立刻报过期，所有会话的 `canon brief` 都会提示。
- 测试：`src/cli/install/update.test.ts` 加 BR-2264 的用例；原来按整份 settings 比对的用例（BR-2087、BR-2130）和 BR-2196 的“要改什么”多了这一项，相应更新。

## 核实（Claude Code 官方文档，2026-11-04 查）

- 设置名和取值：https://code.claude.com/docs/en/settings-reference.md 的 `worktree.baseRef`：“Choose which ref new worktrees branch from. `"fresh"` branches from `origin/<default-branch>` for a clean tree matching the remote; `"head"` branches from your current local `HEAD`, so unpushed commits and feature-branch state are present in the worktree.” 默认值：“**Default**: `"fresh"`”。
- 项目级生效：同一条的作用范围是 “**Scope**: [`Any file`]”，文档开头的解释是 “`Project` is `.claude/settings.json` … `Any file` means all four”。所以写在项目的 `.claude/settings.json` 里生效。
- 子 agent 也用它：https://code.claude.com/docs/en/worktrees.md：“Subagent worktrees use the same [base branch](#choose-the-base-branch) as `--worktree`, so they branch from your repository's default branch unless `worktree.baseRef` is set to `"head"`.”
- 在 worktree 里再建 worktree：“Inside a linked worktree, `"head"` resolves to that worktree's `HEAD`, not the main checkout's.” 子 agent 从 canon 变更的 worktree 里派出时，就从那个变更的当前提交建，这正是要的。
- 不能写分支名：“You can't set `worktree.baseRef` to a branch name.” 所以只有 `"fresh"` 和 `"head"` 两种值。

## 陷阱和假设

- 设置的优先级是本地（`.claude/settings.local.json`）高于项目，项目高于用户：某个人在自己的本地设置里写了 `"fresh"` 会盖过 canon 写的值，canon 不管本地设置，也不管 `~/.claude`。
- `baseRef` 是别的值时 canon 改成 `"head"`：“只管这一项”指 canon 拥有这个键，和会话 hook 的旧形式被原地改写一样。项目真想要 `"fresh"` 时没有办法让 canon 不改它；目前没有这种需求，有了再加。
- C-39（合入后自动推送）做完后 origin 不再落后，这个问题会变小，但离线或推送失败时仍然存在。
