## 为什么

C-89 合入后的代码评审提了 issue #24：`ensureGuard` 直接截断并重写 hook 文件，之后才 chmod。这段时间里另一个会话的 git 可能执行到空的、写了一半的或还不可执行的 hook：写了一半会让正常的合入在 floor 通过后被拒绝，空文件或不可执行会让直接提交到 main 绕过守卫。C-88、C-89 的合入评审还提了三处措辞：`work/claims` README 说持有者的每个工作命令都会续期（C-87 之后 start 不再续期）；BR-2107 没写同一个执行者再次 start 也被拒绝；BR-2084 列 git 守卫过期情形时漏了“不可执行”。

## 要改什么

- `ensureGuard` 先写同目录下的临时文件、设为可执行，再 `rename` 换上；失败时删掉临时文件（BR-2123 写明，测试检查不留临时文件）。
- BR-2084 补“不可执行”；BR-2107 补同一执行者被拒的例子；`work/claims` README 改成只有 land 和不带 `--release` 的 stop 续期。
