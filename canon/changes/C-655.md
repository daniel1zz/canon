## 为什么

#286：zhushenkongjian 的 `C-1090` 由 `canon work start --fix-main` 生成变更文件，里面已经有带占位的 `## 要改什么`、`## 教训`；会话在文件末尾又追加了一份填好的，文件里于是有两个 `## 教训`。canon 只读第一个，合入拒绝时说“没有填好的 `## 教训`”，没说重复，会话照着提示去填，越改越乱。

## 要改什么

- 新规则 BR-2596：`canon check` 对代码块以外重复的 `## ` 标题报 `section-duplicate`，每个标题一条，写明文件里的每一处行号；已关闭的变更不报（历史，D-24 同理）。实测 canon 仓库没有这样的文档；zhushenkongjian 只有已经 `done` 的 `C-929` 有两个 `## 教训`，不会因此报错。
- BR-2161：`land --finish` 时 `## 教训` 出现不止一次，按 `lessons` 拒绝，提示写明重复和每一处行号，不再说没填。
- 代码：`src/knowledge/documents/templates.ts` 加 `duplicateHeadings`、`linesSaid`；`src/knowledge/check/check.ts` 的 `structureFindings` 报 `section-duplicate`；`src/work/land/land.ts` 的教训检查先查重复。
- 测试：`src/knowledge/check/check.test.ts`（BR-2596）、`src/work/land/finish/finish.test.ts`（BR-2161 重复的情况）。

## 教训

无（BR-2596 和 BR-2161 的改动是这个变更自己的修复，不是教训，D-78）
