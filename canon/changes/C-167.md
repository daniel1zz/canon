## 为什么

baseline 核对列出 cli 和 cli/install 里几处没有规则描述的行为，和一些规则例子没有测试检查：

- `--help`、`-h` 出现在命令行任何位置都输出帮助，包括 `--` 之后；按 citty 的解析，`--` 之后都是位置参数，所以 `canon search -- --help` 搜不了 `--help` 这个词。
- 清单 `.claude/skills/.canon-skills.json` 不是合法 JSON 时退出码 2，没有规则写。
- `canon update` 自动写的变更标题、说明和提交信息，没有规则写。
- 没有测试的例子：BR-2080 第 6 条（在 canon 自己的仓库里 hook 真的写进了 settings.json）、BR-2082 第 2 条（编译出的 `dist/canon` 从它所在仓库的 `.claude/skills` 安装）、BR-2084 的“内容变了版本就变”、BR-2085 的“无法检查”一行。

## 要改什么

- `src/cli/main.ts`：只在 `--` 之前找 `--help`、`-h`。新规则 BR-2194。
- 新规则 BR-2195（清单不是合法 JSON）、BR-2196（`canon update` 写的变更文字），写的是现在的行为，代码不变。
- 补上面几条例子的测试。

## 陷阱和假设

- BR-2022 的例子“git 读不出 main 时 `canon work start C-99` → 4”现在实际是 3（`src/work/session/session.ts` 的 `corpusOf` 把读不出 main 当作 main 上没有 canon/），不在 cli 领域，提了 #77，这里不补这条测试。
- `canon init` 往 `canon/config.yaml` 写 `main: main`，不管当前分支叫什么；是否该改留给负责人，这里没写规则。
