## 为什么

#110（C-260 合入后的代码评审）：`canon change list` 和 `canon brief` 先用 `git for-each-ref` 列出变更分支的名字，之后再按名字逐个 `ls-tree`、`show`。中间别的会话 `canon work drop`、`canon work clean` 删掉分支，或者 `canon work start --title` 失败撤销时删掉刚建的分支，按名字读就失败，命令以退出码 4 结束，brief 说“canon brief failed”，其实什么都没坏。

## 要改什么

- `src/work/session/inflight.ts`：`for-each-ref` 同时取分支指向的提交，之后按这个提交读变更文件，不再按名字读；分支在中间被删掉，提交对象还在，照样读出列出时那一刻的状态。
- BR-2291 加一条例子：分支在列出之后、读文件之前被删掉 → 照样按列出时的提交列出，不失败。
