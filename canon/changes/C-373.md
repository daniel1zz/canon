## 为什么

D-65 的最后一部分：总览里讲 D-62、D-64 的段落要按 main 的现状改；每个会话要先读总览（CLAUDE.md 和 `canon brief` 各一句）；canon-design 和 canon-domains 要知道总览；父领域 README 不再手写子领域清单。每次会话加载的文字之前已经超出 `session_text_budget`（12188 对 12000），加了“先读总览”之后也要在预算内，所以同一个变更里删减，不上调预算。

## 要改什么

- `canon/architecture.md`：容器“主 checkout 与变更 worktree”（`--as`、子 agent 的名字、`work take`、`check-as` 的代码位置）、“装进项目的 hook、skill 和 git 守卫”（check-as hook、模板）、“合入流水线”（`canon work test` 的选测试、JUnit 报告和记账）、“`canon/` 文档树”（`canon check` 读记账）、上下文“项目自己的命令”（`test_select_command`、测试报告）、主要流程第 1 步；决策编号补 D-62、D-64、D-65。
- BR-2090：项目有 `canon/architecture.md` 时 `canon brief` 的工作说明第一项是 `Read canon/architecture.md first.`（`src/invocation/guide.ts` 的 `guideFor`）；`canon check --sizes` 和预算按这份说明量。
- CLAUDE.md 的“东西在哪”加一条总览（它在哪、改部件时要同步改）；“先读它”只由 `canon brief` 的那一句说，CLAUDE.md 不再写第二遍（合入评审的重复检查拦过一次：D-65 原文要两处各写“先读”，同一条要求写两处会各自漂移）。canon-domains 只写总览能回答什么，不写“先读”。
- canon-design（第 4 节加“改了容器或主要流程就更新总览”，mode-architecture 的第 4 阶段指向总览、不再给一份通用的 Architecture 文档模板）、canon-domains（读总览）。
- `work/land` 和 `invocation` 的 README 删掉手写的子领域清单，改指 `canon rule domains`。
- 预算：删掉 9 个 skill description 里“它做什么”的说明句（触发词和 NOT 保留，skill 正文里都有），会话文字 12188 字节降到 11501。

## 陷阱和假设

- 预算只靠删 skill description 里的说明句达到；触发词和 NOT 一条没动，所以 skill 被选中的方式不变。
- `canon brief` 的那一句只看有没有文件，不看有没有内容：模板（只有标题）也算有，这样刚 `canon init` 的项目也会被告知有这个文件。
