## 为什么

issue #252。合入时的措辞判断（BR-2239）收到读不了的回答（没有 `wording`、意见没有标准）时会再问一次（#227、C-552），两次都读不了就拒绝合入，原因 `review`，信息是“the wording judgement could not run … (asked twice; neither answer could be read)”。评审其实运行了，也写了具体内容，例如 `["BR-389：新增格子式与阅读式界面的布局例外…，改变了规则的适用范围和显示要求。"]`，但这些文字只在拒绝信息里出现一次，没有记成意见，会话只能从拒绝信息里猜。某个项目一晚上在三个不同的变更上碰到三次，每次丢掉的正好是会话要知道的（哪条规则被判成了行为改动），每次都多一轮合入。

代码路径：`src/work/land/checks/steps.ts` 里措辞判断的第二次回答还是读不了时，直接 `refuse("review", couldNotRun(...))`。

和 #238 不一样：#238 是评审根本没运行（额度、网络），负责人定的是拒绝，这一点不变。

## 要改什么

想要的行为：

- 两次回答都读不了，但第二次的回答里有文字（意见数组里的字符串或对象的 `text`；没有时是 JSON 之外的正文；没有 JSON 或解析不了时是整个输出）时：拒绝信息在 `what the reviewer wrote:` 下面完整写出每段文字（不再只露出前 200 个字符），并记一条 `review.unparsed` 事件。合入照样拒绝，原因 `review`；会话按文字改，再合入时重新判断。
- 不记成评审意见：负责人 2026-11-18 选了“只挡这次合入”，没选“记成意见”。记成意见的话，会话没处理就走了，4 小时后开新变更的欠账检查（BR-2464）会挡住所有会话；评审写的可能是乱话，按“不成立”关闭还要另一个会话出意见。
- 回答没有任何文字时，和现在一样按“没能运行”拒绝，信息末尾写 `asked twice; neither answer could be read`。
- 命令失败、超时不变，按 #238 和 BR-2239 拒绝。
- 合入后的规则评审（BR-2441）不动：查过，它读不了回答时这次评审记为失败，错误信息写进 `review.fail` 事件并打印，任务保持失败。

要改的规则：BR-2239（读不了的回答的处理和例子）。

回归测试：评审命令两次都输出 `{"findings":["BR-1 changes when the line shows"]}` → 合入被拒，原因 `review`，信息完整写出这句，有 `review.unparsed` 事件，没有开着的评审意见；两次都输出一段超过 200 字符的纯文字 → 信息完整写出；没有文字 → 照旧 `asked twice`。

不做：

- 不放宽拒绝：读不了的回答仍然不让合入通过。
- 不改重问的次数和提示。
- 不尝试从读不了的回答里猜 `wording` / `behaviour`。
