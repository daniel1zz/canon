## 为什么

issue #252。合入时的措辞判断（BR-2239）收到读不了的回答（没有 `wording`、意见没有标准）时会再问一次（#227、C-552），两次都读不了就拒绝合入，原因 `review`，信息是“the wording judgement could not run … (asked twice; neither answer could be read)”。评审其实运行了，也写了具体内容，例如 `["BR-389：新增格子式与阅读式界面的布局例外…，改变了规则的适用范围和显示要求。"]`，但这些文字只在拒绝信息里出现一次，没有记成意见，会话只能从拒绝信息里猜。某个项目一晚上在三个不同的变更上碰到三次，每次丢掉的正好是会话要知道的（哪条规则被判成了行为改动），每次都多一轮合入。

代码路径：`src/work/land/checks/steps.ts` 里措辞判断的第二次回答还是读不了时，直接 `refuse("review", couldNotRun(...))`。

和 #238 不一样：#238 是评审根本没运行（额度、网络），负责人定的是拒绝，这一点不变。

## 要改什么

想要的行为：

- 两次回答都读不了，但第二次（没有就第一次）的回答里有文字（意见数组里有非空字符串，或者 JSON 之外有非空正文）时：把这些文字记成开着的拦截评审意见，标准记 `unparsed`，挂在文字点名的文档上（按评审意见现有的认法找编号）；一个都没点名时挂在正在合入的变更上。合入照样拒绝，原因 `review`，信息列出新记的意见编号，会话按平常的方式处理这些意见（`canon finding tier`、`close`）。
- 回答没有任何文字（空输出、只有空白、JSON 里没有任何内容）时，和现在一样按“没能运行”拒绝，不记意见。
- 命令失败、超时（退出码不是 0）不变，按 #238 和 BR-2239 拒绝。
- 合入后的规则评审（BR-2441）对读不了的回答怎么处理，动手前查一下：如果也是丢掉文字，同样记成 `unparsed` 意见；如果已经保留，就不动。

要改的规则：BR-2239（读不了的回答的处理和例子），BR-2437 或记录评审意见标准的那条规则（加 `unparsed` 这个标准，`canon search criterion` 查列出标准的规则）。

回归测试：评审命令两次都输出 `{"findings":["BR-1: changes behaviour"]}` → 合入被拒，原因 `review`，有一条挂在 `BR-1` 上、标准 `unparsed`、文字是 `BR-1: changes behaviour` 的开着的意见；评审命令两次都输出空 → 被拒，没有新意见；第二次能读 → 照常判断，不记意见。

不做：

- 不放宽拒绝：读不了的回答仍然不让合入通过。
- 不改重问的次数和提示。
- 不尝试从读不了的回答里猜 `wording` / `behaviour`。
