## 为什么

C-228 改了 BR-2265，但没有处理它上面还开着的评审意见（C-34 合入时的两条），C-228 合入时又多了一条。这些意见都指出规则没写清楚的边界：斜杠命令算不算 skill 调用取决于 `--days` 的窗口；主 checkout 子目录里启动的会话读不读；扫描中目录被删掉时目录数怎么算、全被删掉时退出码是几。行为不变，只是写进规则并用测试钉住。

## 要改什么

- BR-2265：写明斜杠命令的计数随窗口变化；主 checkout 子目录里的会话不读及原因；目录数是列出时的数目；列出后全被删掉时退出码 0、文件数 0。补这几种情况的例子。
- 测试：`src/work/stats/usage.test.ts` 加对应用例。

## 陷阱和假设

- 主 checkout 子目录的会话不读是有意的：路径编码后 `/w/p/src` 和 `/w/p-src` 都是 `-w-p-src`，分不开。

## 教训

- 改一条规则时，`canon work test` 提示了它上面开着的评审意见，C-228 没处理就合入了 → 只靠文字：`canon work test` 已经在输出里提示，合入没有拦；要不要让合入拦下“改了规则却没处理它的评审意见”待负责人确认是否固化。
