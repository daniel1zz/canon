## 为什么

C-360 写架构总览时核对发现：`work` 的 README 列了 9 个子领域，实际有 13 个，漏了 `work/execution`、`work/hooks`、`work/remote`、`work/snapshots`；`knowledge` 的 README 漏了 `knowledge/releases`。README 是领域的导览，漏列会让新会话找不到这些子领域。

## 要改什么

两份 README 的子领域列表补齐，每个一句话，取自各子领域 README 的开头。不改规则。

## 教训

- 新建子领域时没有同步父领域 README 的列表 → 待负责人确认是否固化（可做成检查：父领域 README 必须列出每个现有子领域）。
