## 为什么

D-62 的第三部分：派发子 agent 的说明文字。C-358 做了 `--as` 和 `canon work take`，C-364 做了 hook；skill 和工作说明还在教“主会话替子 agent 认领”，这在 D-62 之后会让子 agent 的 `land` 被拒。

## 要改什么

- canon-parallel skill：子 agent 自己 `canon work start ... --as <agent_id>`，主会话不替它认领；主会话已经认领的先 `stop --release --next` 再让子 agent start；`land`、`stop`、`drop` 也带 `--as`，子 agent 不运行 `take`；核对步骤加：执行者有没有名字、`hook.skip` 次数、子 agent 返回后用 `canon work take`。
- `canon brief` 的工作说明（`src/work/session/guide.ts`）加一句：进入 worktree 只用 `canon work start` 打印的路径；子 agent 带 `--as`，主会话不带。
- 不新增规则：这是说明文字，行为规则已在 BR-2023、BR-2340 等里。

## 陷阱和假设

- 工作说明加的字数会涨每个会话固定加载的文字合计，超过 `session_text_budget` 时只提示（BR-2257）。
