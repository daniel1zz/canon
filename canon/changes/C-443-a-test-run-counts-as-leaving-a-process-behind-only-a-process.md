## 为什么

#171：负载高时（load 18 到 50），`src/work/watch/batch.test.ts` 9 个测试全过，测试脚本却报“留下了还在运行的进程”，整次运行判失败；被报的进程在点名时已经查不到命令行（`killed:` 后面是空的）。也就是说，按工作目录找到它时它还在，到点名时已经自己退出了：它只是退出得慢，并没有留着不走。负载 7 时 4 次全过。合入后台的 floor 跑全部测试，负载高时会被它卡住。

负责人 2026-11-09 认为这样判失败不合理，同意改成只算点名时还在运行的进程。

## 要改什么

- 清理脚本按工作目录找到的进程，点名前再确认一次还在不在；已经退出的不报、不算、不杀。三个入口（测试结束时 `--run`、手动列出、`--kill`）都一样。
- 真正留着不走的进程（例如测试启动了 `sleep 61` 没停）照旧让测试失败、被点名、被杀。
- 测试：用一个替身 `lsof` 同时报一个已经不存在的进程和一个活着的进程，只有活着的那个被报告和杀掉；只报不存在的进程时，什么都不输出，退出码 0。有 `/proc` 的系统上脚本不用 `lsof`，这个测试跳过。

不做：不加等待时间；不去找 batch 测试里那个退出慢的进程（它不会堆积）。
