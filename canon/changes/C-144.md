## 为什么

C-136 发现：参数严格检查（BR-2097）只检查没有子命令的最后一层，一个既有子命令、不带子命令名也能自己运行的命令，它自己的选项不会被检查，`--bogus` 会被悄悄忽略。canon 现在还没有这样的命令（C-136 因此让 `canon config` 用 `--schema` 选项而不是子命令），负责人决定修掉这个缺口。

## 要改什么

- `src/cli/strict.ts` 新增 `argumentProblem`，按层检查整行命令；最后一层有子命令但自己能运行时也检查。`src/cli/main.ts` 改为调用它。
- BR-2097 写明按层检查和这个情形，补例子；测试用一棵构造出来的命令树。

## 教训

- 用 `git checkout <文件>` 还原临时改动时，把这个文件里还没提交的改动一起丢了 → 只靠文字：做“删掉改动看测试会不会失败”这种检验前先提交，或用 `git stash`；这是操作习惯，没有能检查的信号。
