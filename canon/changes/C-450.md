## 为什么

每次 Bash 调用前的快照（BR-2182）收进没被 git 忽略的未跟踪文件和改动。用户忘了写进 `.gitignore` 的明文密钥文件（如 `.env`）因此被复制进本机 `refs/canon/snapshots/*`，文件删了以后还留在 git 对象里 14 天，`git push --mirror` 时还会推出去。负责人 2026-11-11 定了：快照要把密钥文件留在外面。背景见 D-85 和 skill `canon-secrets`。

## 要改什么

- 新规则 BR-2406（领域 `work/snapshots`）：文件名在固定名单上的改动过、已暂存或未跟踪文件，按 BR-2182 对大文件的办法留在快照外并在提交说明里写明。名单：`.env`、`.env.*`（`.env.schema`、`.env.example`、`.env.sample`、`.env.template` 除外）、`*.pem`、`*.key`、`*.p12`、`*.pfx`、`id_rsa`/`id_ecdsa`/`id_ed25519` 及加后缀的名字（`.pub` 除外）、`keys.txt`。
- `src/work/snapshots/snapshot.ts`：加名单判断，留下的密钥文件并进 `skipped`，提交说明多一行 `left out, secret files: ...`；`leftOut()` 返回所有 `left out` 行。
- BR-2184：`canon snapshot list` 写明快照留下的所有文件（大文件和密钥文件），加一条例子和测试。
- D-85 的最后一条后果（快照逻辑不改）被负责人 2026-11-11 的决定取代，由主 agent 在这次之后更新 D-85，本变更不改它。

## 陷阱和假设

- 已暂存的密钥文件也要处理：快照从 worktree 自己的索引复制开始，`git add .env` 后工作区和索引一样，`ls-files --modified` 和 `--others` 都列不出它，所以另外用 `git diff --cached --name-only HEAD` 找。大文件的判断不改，仍只看改动过和未跟踪的文件。
