## 为什么

#181 原先报告：规则评审按整条文字去重，同一个缺陷换几种说法会成为几条拦截意见。最初分析发现跨调用的重复不能只靠每次调用的提示消除，引用不同原文的意见也不能靠原文哈希合并。因此当时交接为等待非阻塞评审的方向确定，再决定是否增加一次模型分组调用。

等待期间，负责人确定的替代流程已经落地：C-474 实现意见身份和唯一记账，C-475 把评审移到合入后，C-494 按 D-99 把意见交给主 agent 处理。#181 的已有评论把它归入 C-464 的 A、B 步；A、B 都已合入。这个变更只记录核对结果，结束旧方案的等待，不改变产品行为。

## 要改什么

按现有 D-89、D-99 和 BR-2433、BR-2434 收尾，不新增模型分组调用，不改变意见身份：

- 已落地的保证是同一身份只保留一条未处理记录；身份由现有规则定义，不是由模型判断根因是否相同。
- 合入后的评审已经调用记账流程，意见不再因重复报告而把同一个变更反复挡在合入前。
- 引用原文不同、或没有引用而整条文字不同的意见仍可能是不同身份；没有实现任意措辞、任意引用的语义去重，不把这一边界当成已修复。
- 原来的三项备选仅是当时的分析，不再等待负责人在旧选项里重选。依据是之后已经接受并实施的决策，不是本变更新定方向。
- #181 按被后续决策替代的旧方案说明结果；评论区保留上述边界，不能标为已经实现完整语义去重。

不在范围内：修改规则、评审提示、身份算法、记账逻辑、验收流程或新增自动化机制。
