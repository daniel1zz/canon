## 为什么

D-65：已装 canon 的项目也要拿到只有标题的 `canon/architecture.md`，规则评审要读总览（A2）。C-371 已合入 A3 到 A5 的检查，这一步补模板和评审输入。

## 要改什么

- BR-2032：`canon init` 多写一个只有标题（上下文、容器、主要流程）的 `canon/architecture.md`；BR-2084、BR-2085：没有这个文件算“过期”一项；BR-2086：`canon update` 把模板写进变更合入，已有的文件不覆盖。实现在 `src/install/update.ts`、`src/install/commands.ts`。
- BR-2009：总览除标题外有内容时作为上下文交给规则评审，写明这次合入有没有改它、改了的附差异；只改总览的合入不评审；只有这次合入改的那部分总览和规则或决策矛盾才拦。实现在 `src/knowledge/review/review.ts` 和 `src/work/land/checks/steps.ts`。
- `knowledge/documents` README 和 `model.ts` 头部注释加一行说明总览。

## 陷阱和假设

- 更新变更的“要改什么”会写进项目的变更文件，里面不能出现 canon 自己仓库才有的编号（D-65），否则 `canon check` 在那个项目报 `ref-dangling`；测试抓到过这一点。
- “只改了总览的合入不评审”靠的是评审的触发条件没变（BR-2074 列的三个目录），不是新加的判断。
