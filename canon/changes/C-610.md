## 为什么

D-136 已经把防忘事的检查改成提醒，但分类只写在它的一个方案里，`canon/product.md` 和设计 skill 都没有。2026-11-20 设计质量标准时，主会话又接连提出六个硬拦截，负责人逐条纠正，并要求「重提醒，轻拦截」固化进 canon（D-139 背景）。

## 要改什么

- 新决策 D-139（修订 D-136）：只有四类检查拒绝，其余给标准、相关时提醒、主 agent 判断并写理由；拒绝也只挡相关的工作。
- `canon/product.md` 新增「检查的分寸」一节。
- canon-design skill 的横切检查加一行「Refusals」。
- BR-2009：规则评审的说明要求对不属于四类、或挡住无关工作的新拒绝提一条 `note`（不拦）；`src/knowledge/review/review.ts` 加这条说明，`review.test.ts` 加测试。

总览不受影响：D-139 只改检查的分类原则，不改部件、数据位置和主要流程；总览引用 D-136 的两处（派发时按机器容量拒绝、评审意见不挡开工）在 D-139 下照旧成立。

现有的拒绝不在这个变更里复查，另开变更逐个过一遍（负责人 2026-11-20 要求）。

## 教训

- 提醒被忽略过，就直接改成拒绝，没有看被挡的工作是否相关、主 agent 能否自己判断 → product.md「检查的分寸」、canon-design 的 Refusals 一行、BR-2009 的评审意见（负责人已确认固化）。
