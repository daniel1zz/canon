title: 后台命令输出不以换行结尾时也能认出它已结束
status: open
rules:
  - BR-2137
---

## 为什么

issue #61：后台的 `after_land` 命令输出最后没有换行时（例如 `printf foo`），`src/config/hooks.ts` 紧接着写的退出行 `[hook 1/2 exited 0]` 和输出粘在同一行，变成 `foo[hook 1/2 exited 0]`；读日志的正则只认行首的退出行，于是这条命令永远是 `still running`：`canon work after-land` 退出码 75，`--wait` 一直等到超时，也不写 `hook.exit`。

## 要改什么

- 后台脚本写退出行之前，看日志文件的最后一个字节：不是换行（而且日志不为空）时先补一个换行。输出以换行结尾时日志和原来一字不差。
- BR-2137 写明输出不以换行结尾的命令也照样认出已结束，补例子。
- 回归测试：`printf foo` 和 `echo bar` 两条命令，`--wait` 读到两条都以 0 结束；`printf 'code-review: no findings'` 的评审行原样照抄，不带退出行。

## 陷阱和假设

- 补换行靠 `tail -c 1` 读日志的最后一个字节，假设日志只有这个后台 shell 在写（日志名带排队序号，每次合入一个文件）。
- 不能简单地每次都先写一个空行：那样所有日志都会多出空行，读日志的人和按行比较日志的测试都会受影响。

## 教训

- 日志的“行首”格式由写的一方和读的一方各自假设，中间是用户命令的任意输出 → 现在由 BR-2137 的例子和它的测试保证。
