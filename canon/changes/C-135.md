## 为什么

纯机械重构，行为不变。从事件 #978 起的事件表里，10 次冲突拒绝和大部分重叠提示集中在“每加一个功能就追加一行”的中心登记文件上：配置代码 `src/config/config.ts` 加上 `canon/config.yaml` 有 2 次冲突、26 次重叠提示，因为每个新配置项都要在 config.ts 里同时改接口、默认值、已知键列表、校验和返回值五处。负责人选的改法和 C-132、C-133 一样：每个领域在自己的目录里声明自己的配置项，config.ts 只组装和校验，只在新增领域时才改（D-15）。`canon/config.yaml` 是项目自己的文件，不动。

## 要改什么

涉及的子领域：config、knowledge/check、knowledge/review、work/claims、work/land、work/session、work/stats、work/verify。

- 新文件 `src/config/key.ts`：一个配置项的声明 `ConfigKey`（yaml 里的名字、说明、默认值、校验函数、在“已知键”列表里的位置 `listed`、校验顺序 `checked`、它引用的命令 `commands`、它取代的旧键 `replaces`），以及几个领域共用的读法（字符串、正数、相对路径）。
- 各领域的 `config-keys.ts`，校验代码原样搬过去：
  - `src/work/land/config-keys.ts`：main、floor、lander_stale_minutes、land_timeout_minutes、floor_skip_paths、land_batch_max
  - `src/work/verify/config-keys.ts`：test_command（和 `FILE_PLACEHOLDER`）
  - `src/work/session/config-keys.ts`：setup、worktrees、regenerable（和 `DEFAULT_REGENERABLE`、`worktreesDirOf`）
  - `src/work/claims/config-keys.ts`：claim_lease_hours
  - `src/work/stats/config-keys.ts`：check_reviews
  - `src/knowledge/check/config-keys.ts`：tests
  - `src/knowledge/review/config-keys.ts`：review、instructions
  - `src/config/config-keys.ts`：hooks、types、code_root、shared 和模板的读取，按 config README 它们属于本领域
- `src/config/config.ts` 只剩：领域列表、由各领域声明推出的 `Config` 类型、解析 YAML、拒绝未知键和已搬走的键、按 `checked` 顺序校验每一项（第一个错误就返回）、检查命令引用的脚本是否存在、读模板。两个领域声明同一个字段或键名时加载就抛错。
- 引用搬走内容的 `hooks.ts`、`verify.ts`、`overlap.ts`、`session.ts` 改成从新位置导入。
- `canon/rules/config/README.md` 写明配置项在哪里声明。不改任何规则。

证明行为没变：写了一个探针，对 165 份配置（每一项的合法值、非法值、null、空字符串，几项同时出错时报哪一个，脚本不存在，模板缺章节或类型不存在，一份全项合法的配置）分别调用改动前后的 `readConfig`，把结果（成功时的完整配置，失败时的错误码和错误文字）逐行输出，两边逐字节相同；其中 109 份是错误。错误文字和第一个报出的错误都没变，退出码由错误码决定（BR-2022），所以也没变。worktree 里跑了 `canon work test` 和一次全量测试（逐个文件一个进程）。新增 `src/config/key.test.ts`：各项的名字、两个位置都不重复，`shared` 在 `code_root` 之后校验。

## 陷阱和假设

- “已知键”列表的顺序和校验顺序本来就不一样，为了错误文字和多处出错时报出的那一个都不变，每项带两个位置：`listed` 和 `checked`。新加一项时两个都要挑一个不重复的数（`src/config/key.test.ts` 会拦住重复）。
- `shared` 的校验直接读 `ctx.raw` 里的 `code_root`，靠的是 `code_root` 先校验；改它们的 `checked` 时要保持这个先后。
- 另一个会话正在做的变更（让 `instructions` 列出的文件必须存在）改了 config.ts 里 `instructions` 的校验；它 rebase 时这段代码已经搬到 `src/knowledge/review/config-keys.ts`，需要把它的三行改到那里（校验函数的第二个参数 `ctx.root` 就是仓库根目录）。
