## 为什么

issue #5：规则评审几乎每次合入都建议拆规则，14 条被点名，其中包括退出码定义表和同一个命令的出错情况。CLAUDE.md 没定义“一个行为”是什么，所以评审和写规则的人各按各的理解。

## 要改什么

- 决策 D-5 定下标准：一个触发点、一个结果；同一触发点的出错情况和定义表不拆。
- 评审提示写明这个标准（BR-2036）。
- 按标准拆开 5 条：BR-2008 → BR-2073，BR-2010 → BR-2074，BR-2021 → BR-2075，BR-2032 → BR-2076，BR-2051 → BR-2077；对应的测试改为引用新编号，并为 BR-2075 补一个测试。其余 9 条按标准不拆。
- 顺带补上 C-19、C-20 评审提的例子：BR-2021 写明操作者不是 `human:` 时都写事件；BR-2022 补“文档不存在 → 3、git 读不出 → 4”。
