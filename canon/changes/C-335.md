## 为什么

独立审查认为 canon-domains skill 在列出的修改之后才够用。缺的是：没说清一个 canon 领域同时是子领域和限界上下文、两者不一一对应时怎么办；上下文映射只有几个词；README“依赖”行容易被当成有检查；找一词多义没有可执行步骤；没有“划分到什么时候算完”的标准；决策该记什么没写全；核心、支撑、通用没给判断的坐标轴；反模式不全；新项目从哪里开始、横切的质量承诺不是领域也没提。

## 要改什么

- `.claude/skills/canon-domains/SKILL.md`：补上以上各点，保持精简。
- `canon/notes/N-5.md`：补读 core-domain-charts、Evans Reference 的合作、开放主机服务等原文，补上对应的来源行和反模式，读不到的标成转述。
- 不新增或修改规则。

## 陷阱和假设

skill 正文不能引用 canon 的文档编号。“约 25 条”“1 到 3 条”是 canon 自己的经验值，不是 DDD 的。README“依赖”行 canon 不检查。
