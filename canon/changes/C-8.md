## 为什么

P4 要求不丢工作，P7 要求只有留给人的决定才等人。旧系统 30 天里有 78 次这类升级给人（删除带未合入工作的 worktree 42 次、丢弃 stash 11 次、放松检查 25 次），说明需求真实存在。canon 现在只保证自己的命令不丢工作（BR-2019、BR-2029），没有提供“想做一件会丢工作的事”时的正规路径，agent 只能自己用 git 硬来。

## 要改什么

1. 提供一个命令（例如 `canon work drop <C-n>`）：放弃一个变更及其 worktree。worktree 干净且所有提交都已在 main 上时直接执行；否则不执行，而是用 `canon human ask` 生成一个问题，列出会丢掉的提交和未提交文件；人在终端回答同意后，再次执行时才真正删除。
2. 覆盖的操作至少包括：删除带未合入提交或未提交改动的 worktree、删除未合入的变更分支。
3. 每次升级和人的回答都写事件表。
4. 不拦截 agent 直接用 git 做的操作（那是检查做法，D-1 不做）；只提供一条安全、可追溯的正规路径，并在 CLAUDE.md 里写明。
