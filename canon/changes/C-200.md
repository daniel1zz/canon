## 为什么

baseline 修复那一轮（N-4）留下两个要负责人定的行为，负责人 2026-11-04 选择推荐方案：“全部按推荐”。

- 合入后代码评审按标题搜同根因 issue（`gh issue list --search`）失败时，现在当作没找到，直接新建 issue，可能和已有的重复。负责人在待答问题 #2 里选了报错退出（`code-review: <原因>`，退出码 1，不提交这条发现）。
- `canon context BR-99999` 这样不存在的编号现在和路径一样输出 “No domain, rule or document matches” 并以 0 退出，打错的编号看不出来。

## 要改什么

- `src/knowledge/review/code-review.ts`：搜索失败时返回错误，`scripts/code-review.ts` 照 BR-2211 输出 `code-review: <原因>` 并以 1 退出；搜索在分组时、新建和评论之前，所以这次评审一条发现都不提交。改 BR-2211，去掉“待负责人决定”那句。
- `src/knowledge/query/commands.ts`：`canon context` 的目标是编号的样子而没有这个文档时以退出码 3 失败；路径照旧以 0 退出并提示。新规则 BR-2234。

## 陷阱和假设

- 评审指出的编号是带标签的未关闭 issue 时不搜索，搜索坏了也不影响这条发现。
- “编号的样子”和 `canon search` 判断按编号搜索用的是同一个函数（`isIdQuery`），和 `canon show` 一样不区分大小写。
