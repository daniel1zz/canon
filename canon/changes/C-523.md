## 为什么

清 292 条可疑引用要用 `canon links confirm` 改约 156 份文档的 frontmatter，按现在的 BR-2009 会触发全量合入后评审（十几次模型调用 + 大量无关意见）。见 D-106。

## 要改什么

- `reviewScope` 把只有 `links` 记录变了、正文和其余 frontmatter 相同的文件排除出评审范围（BR-2009 补写豁免和例子，D-106 记录取舍）。
- 合入输出加一行写明有几份文件只是重记了引用。
- `canon accept` 的评审完整性（BR-2462）：一条评审记录覆盖它那次合入的全部提交（`base..head`），之前只认最后一个提交，多提交的合入会被误报，main 上实跑列出 26 个误报；没被任何记录覆盖的提交按 `reviewEntries` 判断有没有要评审的文件，只改 links 或只挪路径的不算缺评审。
- 架构总览补上评审范围的豁免和 D-106。
- 可疑引用复核里发现的过时链：D-89 的 `amends` 补上 D-67、D-76（它们写的“合入时评审被拒”已被 D-89 改成合入后评审），D-100 的 `amends` 补上 D-65（canon update 现在走杂务，不再开变更）；BR-2432 的例子改用 install README 现在的业务名「更新」和真正属于它的 BR-2084、BR-2086、BR-2089。旧决策原文按 BR-2140 不改。

- 总览不受影响的部分：总览点名 D-65 的句子是总览的维护约定、点名 D-76 的句子是 `canon check` 从 main 读评审预算，两者都没被这次补的 amends 改变
