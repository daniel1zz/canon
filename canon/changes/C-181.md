## 为什么

合入要等 floor（本仓库约 4 到 6.5 分钟，随负载变化），排队最长 44 分钟。负责人要求在开发阶段先合后测、失败时向前修，并做成每个项目可选的开关（D-31）。

## 要改什么

- `floor_timing: before | after`（默认 `before`），`after` 下合入不跑 floor、不分批（BR-2218）；BR-2014、BR-2106 写明例外。
- 新子领域 `work/watch`：`canon floor watch` 后台测试（BR-2219），失败记录和 brief 提示（BR-2220），`canon work start --fix-main`（BR-2221），通过时 `refs/canon/green`、清记录、新 hook 事件 `after_green`（BR-2222）。
- `product.md` 的 P4、config README 的 hook 事件列表。
- 本仓库：`floor_timing: after`，`bun run build` 从 `after_land` 挪到 `after_green`（输出到 `$CANON_PRIMARY/dist/canon`）。

## 陷阱和假设

- 后台测试用的临时 worktree 在 git 公共目录下，每次要先跑 `setup`（`bun install`）。
- 本仓库切到 `after` 的那次合入本身仍按 `before` 跑（读的是被合入那棵树的配置，那棵树里已经是 `after`：这次合入就不跑 floor）。
- 修复变更合入时插队是下一个变更做的。
