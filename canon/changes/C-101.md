## 为什么

GitHub issue #17 还没修的部分：合入期间 keepClaim 只延长租约，认领里的 pid 仍是发起合入的 Claude Code 会话进程。这个会话在合入途中退出，BR-2100 就认为认领不再有效，另一个会话可以 `canon work start` 接手，在同一个 worktree 里提交半成品；轮到合入时 rebase 会把这些提交一起带上 main，并且 main 上的变更已标成 done。BR-2108 承诺的“合入期间没人能拿走认领”在会话进程退出时就不成立。

## 要改什么

子领域：work/claims（`src/work/claims/claims.ts`）和 work/land（`src/work/land/land.ts`）。

- claims 新增 `bindToLander` / `unbindFromLander`：合入进入队列后，把本执行者在本 worktree 的认领改为记下合入进程；结束时只要认领仍记着这个合入进程，就改回原会话进程。
- land 在进入队列后绑定，在 `land()` 的 finally 和信号处理里解绑。
- 新规则 BR-2142。BR-2108（续期）和 BR-2100（进程不在就可接手）不变。

被否决的做法：只在 rebase 前和移动 main 前复查认领持有者。它能挡住把别人的提交合进 main，但别人照样能在合入途中接手并在 worktree 里提交，合入只能被拒绝，问题没有消失；绑定合入进程让接手本身不会发生。

## 陷阱和假设

- 只绑定记下了进程的认领：只按租约判断的认领本来就不会因进程退出而失效，绑定反而会让一个被 SIGKILL 的合入立刻放掉认领。
- SIGKILL 时解绑不会运行，认领停在已死的合入进程上，于是立刻可被接手；这和会话已退出时 BR-2100 的结果一致。
- 合入途中同一执行者在新会话进程下续期（BR-2100），认领就不再记着合入进程，结束时不改回旧进程。
