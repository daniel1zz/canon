## 为什么

按内容审计旧 skill（D-8）时发现 canon 自己有几处缺口：领域 README 的 `code:` 写了不存在的路径不会被发现，`canon context` 会因此悄悄漏掉这个领域；变更文件没有地方写“新会话最容易踩的坑和依赖的假设”；CLAUDE.md 没写哪些操作一定要问人、worktree 里该跑多少测试、停下前该检查什么。D-8 合入时评审还指出它的总数和名单没有对齐。

## 要改什么

- `canon check` 新增 `domain-code-missing`（BR-2079）；测试夹具里的领域代码目录改成真实存在。
- 变更模板加“陷阱和假设”一节，没有内容时整节删掉（BR-2037）。
- CLAUDE.md 补四条：必须问人的情形、worktree 里只跑相关测试、`// reason:` 注释、停下前的检查。
- 合入后代码评审的提示加“报告前先试着推翻一次”。
- D-8 写全 42 个 skill 的归类。
