## 为什么

实现已接受的 D-62 的 canon 侧：同一个会话里主会话误进子 agent 持有的 worktree（C-337）时，canon 要能分得开两者。D-62 的实现分三个变更：本变更做 `--as` 和 `canon work take`，之后是 hook，再之后是 skill 和说明文字。

## 要改什么

- `canon work start`、`stop`、`land`、`drop` 加 `--as <名字>`，执行者记成 `agent:<会话>:<名字>`；名字格式不对、不在 Claude Code 会话里、和 `CANON_ACTOR` 同时给 → 退出码 2，什么都不写（BR-2023）。
- 持有者是本会话的子 agent 而来的是主会话时，拒绝提示指向 `canon work take`（BR-2011、BR-2104）。
- 新命令 `canon work take <C-n> --from <agent_id>`，只主会话，事件 `claim.handover`（BR-2336）。
- `canon stats --since` 的摘要加认领接手和 hook 跳过的次数（BR-2155；`hook.skip` 由下一个变更写入）。
- 规则：BR-2023、BR-2011、BR-2104、BR-2131、BR-2155 原地改，新规则 BR-2336。
- 顺带：C-352 的教训一行改为负责人的决定。

## 陷阱和假设

- 不带 `--as` 且没装 hook 的子 agent 认领，持有者是会话一级，没有保护（D-62 已写明）；`hook` 在下一个变更里加。
- `canon work take` 证明不了子 agent 已结束，只靠主 agent 看到 Agent 工具已返回。
- 实测（2026-11-05，Claude Code 2.1.318，`claude -p --model haiku`，假 canon，允许规则 `--allowedTools "Bash(canon work *)"`，原始输出在 /private/tmp/claude-501/-Users-apple-Projects-zz-canon/0b2e14ae-7ccf-499b-9f18-e0c549f25f21/scratchpad/hookexp/d62/s/raw_compound_*.jsonl）：default 和 dontAsk 下，`cd <项目内目录> && canon work land --as abc`、`canon work test | tail -5; canon work land`、`cd <项目内目录>; canon work stop --release --next y`、`canon work land --finish && echo done` 都直接执行（`is_error: false`），和不带 `--as` 一样匹配 `Bash(canon work *)`；`cd /tmp && canon work land` 被 Claude Code 自己的“只能 cd 到允许的目录”拒绝，与 `--as` 和 hook 无关。D-62 的这一项前提成立。
