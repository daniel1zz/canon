## 为什么

负责人 2026-11-27（经 zhushenkongjian 主会话转述）：「你同步给CANON的CLAUDE会话，让他看看哪些需要放到CANON中管理，并且canon管理的话这些资产应该是同步到项目级别的」。起因是 zhushenkongjian 从笔记本迁到 Mac Studio：项目依赖的外部工具没有任何地方声明、也没有任何地方检查，交接文档靠手工列还漏了几项，缺的东西只在某个 hook 失败时才暴露。例如 canon 的 PreToolUse hook `canon snapshot take --hook` 一直报错，最后查出是 git-lfs 没装。

新会话（或新机器上的会话）不知道环境缺什么，是 P3（连续性）的缺口，也是 D-152 说的“上下文缺了”：应该补上下文，不加拦截。

## 谁管什么（判断）

canon 只管机制和它自己需要的东西，项目的工具链由项目自己声明：

| 东西 | 谁管 | 理由 |
| --- | --- | --- |
| git、canon 自己 | canon 内置检查 | canon 运行的前提 |
| git-lfs | canon 内置检查（项目 `.gitattributes` 里有 `filter=lfs` 时） | 缺了会让 canon 的快照 hook 失败，canon 能从仓库判断出需要它 |
| gh 且已登录 | canon 内置检查（配了 `remote` 或项目用 GitHub issue 时） | canon 的 issue、代码评审、canon-triage 依赖它 |
| agent-browser | canon 内置检查（项目装了引用它的 canon skill 时） | canon-product、canon-uat 引用它；skill 本身怎么进项目见另一个变更 |
| Godot 和导出模板、gdtoolkit、bun、`@danielzz/delegate`、`@concord-ai/concord-mcp`、delegate 和 concord-relay 的 skill | 项目在 `requires` 里声明 | 是项目选的工具，canon 不认识也不该认识 |
| `.claude/*.local.json`（delegate、worker-mcp 的本机配置） | 项目在 `requires` 里声明一条检查 | 按设计不进 git，换机器必须重建，检查能报出来 |
| 提交进 git 的本机绝对路径（如 zhushenkongjian `.mcp.json` 里 concord 的 node 路径） | 项目自己修（改成 PATH 上的命令名） | 是项目的 bug；canon 可以顺带提示，但不在本变更 |
| 协调数据库里的绝对路径、git worktree 登记 | canon（C-706） | canon 自己的数据 |

## 要改什么

- `canon/config.yaml` 加一节 `requires`：每项写名字、检测命令（退出码 0 算有）、安装说明或命令、可选的用途说明。canon 不替人执行安装命令（会装全局软件，可能要钱或要权限），只报出来。
- canon 内置上表中 canon 自己的几项，和项目的 `requires` 一起检查。
- 报告位置：`canon brief` / SessionStart 报出缺的项和怎么装（只报缺的，全有时不输出，守 session_text_budget）；另给一个命令列出全部项和结果，供换机器时逐项补装。检测要快，结果按机器缓存，避免每个会话都跑一遍慢命令。
- canon 自己的 hook 因为缺依赖失败时（如快照遇到 git-lfs 缺失），错误信息点名缺的工具和安装方法，不只给原始报错。
- 只提醒，不拒绝任何操作（D-139、D-152）。
- 先用 canon-design 定写法并记成决策（备选：放在项目 README 手工维护、用 mise/asdf 这类版本管理工具声明、Brewfile、canon 自己的 `requires`），再写规则。
