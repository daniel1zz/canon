## 为什么

负责人 2026-11-27（经 zhushenkongjian 主会话转述）：「你同步给CANON的CLAUDE会话，让他看看哪些需要放到CANON中管理，并且canon管理的话这些资产应该是同步到项目级别的」。起因是 zhushenkongjian 从笔记本迁到 Mac Studio：项目依赖的外部工具没有任何地方声明、也没有任何地方检查，交接文档靠手工列还漏了几项，缺的东西只在某个 hook 失败时才暴露。例如 canon 的 PreToolUse hook `canon snapshot take --hook` 一直报错，最后查出是 git-lfs 没装。

新会话（或新机器上的会话）不知道环境缺什么，是 P3（连续性）的缺口，也是 D-152 说的“上下文缺了”：应该补上下文，不加拦截。

## 范围（负责人 2026-11-27 定）

评估后负责人说「C-707缩」：不做通用的 `requires` 声明和会话开始时的检查。换机器很少，而且是人在场时一次性做的准备；项目自己的工具链（Godot、gdtoolkit、bun、delegate、concord 等）由项目自己用检查脚本或 Brewfile 这类工具管，canon 不认识这些工具。user-* 规则和 skill 见 C-708，协调数据库里的路径见 C-706。

## 要改什么

- canon 自己调用外部工具失败、原因是工具没装时，报错写明缺的是哪个工具、它做什么用、怎么装，不只转出原始报错。至少包括：
  - git-lfs：项目 `.gitattributes` 里有 `filter=lfs`，而 `git lfs` 不可用时，快照（`canon snapshot take --hook`）和其他调 git 的命令。
  - gh：没装或没登录时，提 issue、代码评审写 issue 这些用到它的地方。
- 只改报错文字，不加拦截，不在会话开始时检测（D-152）。
- 退出码照旧按 BR-2022（环境错误是 4）；动到的规则在同一个提交里改。
