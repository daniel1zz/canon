## 为什么

负责人指出：C-19 只认 `human:` 操作者，使他在 Claude Code 里（对话或 `!` 命令）都没法回答给人的问题；而 C-2 的代码评审试跑又发现这道检查本来就能被 agent 改环境变量绕过。负责人选择允许 agent 转述并如实记录（D-6）。

同一次试跑还发现两个真问题，在这里一起修：回答一个问题是先读后写、不是原子的，两个同时到达的回答可能都成功；合入时找规则改动用的 `git diff --name-status` 会把非 ASCII 路径加引号转义，导致这类文件匹配不上、不被评审。

## 要改什么

- `canon human answer` 加 `--relayed "<人的原话>"`：agent 用它转述，记录回答者和原话；`human:` 直接回答；其他情况退出码 2。显示和事件里区分转述（BR-2021）。
- `canon work drop` 接受转述的同意（BR-2066）。
- 回答改成带 `answer IS NULL` 条件的原子写入（BR-2040）。
- 合入的评审用 `git -c core.quotePath=false`（BR-2009）。
- 协调数据库的 `questions` 表加 `relayed` 列，旧数据库打开时自动补上。
- CLAUDE.md 写明：先用提问工具问负责人，再转述原话。
