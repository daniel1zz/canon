## 为什么

C-155 合入后的代码评审发现（issue #78）：C-155 假设 `git worktree remove --force` 失败时什么都没删，其实 git 先删文件、再删 `.git/worktrees/<id>` 登记，文件删不完也照样删登记。于是 drop 建回分支后提示 `nothing was deleted`，而 worktree 实际上已经被删了一部分、也不再是 git worktree，只能从存档恢复。已复现：一个权限 555 的子目录让删除失败，其余文件和登记都没了。

## 要改什么

- 删除失败后检查 worktree 是否仍然登记且 `.git` 还在；不完整时提示写明“被删了一部分”、存档 ref 和恢复命令，`drop.refuse` 记 `worktree_intact`。分支照样建回。
- BR-2064 写明这种情形并加一个例子；`drop.test.ts` 加对应的测试。

## 教训

- C-155 凭对 git 的假设写了回滚，没有对删到一半的情形做实验 → 现在由 BR-2064 的“删除中途失败”测试保证。
