## 为什么

用 canon 的项目里，多个 worktree 同时启动开发服务器、数据库这类本地服务时会抢同一个端口；git worktree 本身不隔离这些。2026-11-03 对并发隔离方式的调研发现，社区工具的做法是每个 worktree 分一个端口：uzi 从配置的 `portRange` 里给每个 agent 分配 `$PORT`（github.com/devflowinc/uzi），Conductor 提供 `CONDUCTOR_PORT`（conductor.build 文档）。canon 自己是命令行工具，用不上；这是给接入 canon 的项目用的。同一次调研还发现每个 worktree 装依赖的成本可以压到很低：bun 在 macOS 上默认用 clonefile（实测 40 毫秒），pnpm 有 `virtualStoreType: global`（pnpm.io/git-worktrees）。

## 要改什么

- 归属：`config` 领域（setup 和 hook 命令的运行环境，代码在 `src/config/hooks.ts`）。
- `setup` 和各个 hook 命令的环境里加 `CANON_PORT`：每个变更一个，在配置的范围里分配（例如 `ports: 4100-4199`），同一个变更每次拿到同一个值，两个进行中的变更不会拿到同一个值；怎么分配（按编号算还是记在协调数据库里）在设计时写成决策。
- 在 `canon/config.yaml` 的说明里推荐依赖安装的配置：bun 用默认设置，pnpm 用 `virtualStoreType: global`，`setup` 只做依赖安装。
- 规则和测试。
