## 为什么

C-297 起评审在 main 提交的临时 worktree 里运行（BR-2216）。重复评审的提示里，skill 只有 description，没有正文；评审要判断正文是否重复时自己去读文件，读到的是 main 上的旧正文。分支 `change/C-323` 上的改动删掉了 canon-parallel 里和工作说明重复的句子，三次合入都被拦，评审引用的正是已删掉的句子（`canon events --subject C-323 --kind review.block`，#122）。D-51 里“评审提示已带着全部文字，换目录不丢信息”对 skill 不成立。

## 要改什么

重复评审的提示附上这次合入改动过的每个 `.claude/skills/<名字>/SKILL.md` 在被合入的树里的全文。BR-2143 写明这一点并改例子；BR-2216 改那句“提示已带着全部文字”；D-51 记下这处起初不成立。`review.test.ts` 的 skill 测试断言提示里有改动后的正文。

## 教训

- 声称“提示带着全部所需文字”时只核对了规则评审，没核对重复评审对 skill 正文的依赖 → 现在由 BR-2143 的例子和测试保证改动过的 skill 正文在提示里。
