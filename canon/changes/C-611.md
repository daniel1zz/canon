## 为什么

负责人希望每个项目都能有一份更适合自己的 canon：看清 canon 的流程有哪些步骤，每一步由哪些配置项控制，哪些步骤能关、哪些不能，再按项目去调。现在 `canon config` 把 51 个配置项平铺成一张表，看不出它们在流程的哪一步起作用，也看不出哪一步在这个项目里根本没开。负责人要的是图形界面（“我要ui可视化的，更清晰的看清楚流程”），在 delegate 项目上看过一份手写的原型后，选了“做进 canon”，见 D-140。

## 要改什么

- `src/invocation/flow.ts`（新）：流程的骨架，八个阶段和它们的步骤，内置步骤标明支撑的承诺。只有骨架，不写配置项。
- `src/invocation/key.ts`：`ConfigKey` 加必填的 `flow`：配置的步骤（至少一个，步骤 id 是类型）、类别（必需写明缺了会怎样，可选写明怎么关，可调）、哪个值让某一步不运行、映射型配置项（`hooks`）在某一步用的是哪个子键。
- 每个领域的 `config-keys.ts`：给自己声明的每个配置项写 `flow`。
- `src/invocation/reference/flow-view.ts`（新）：从配置和骨架算出流程视图，输出文字和 JSON；`flow-page.ts`（新）：生成不连网的只读 HTML。
- `canon config --flow [--json]`：BR-2540；写 `.canon/flow.html`：BR-2541。
- `canon/product.md` 的“不做的事”：网页 dashboard 加上只读流程图这个例外（D-140）。
- `canon/architecture.md`：invocation/reference 的代码和 `.canon/` 的数据各加一句。

## 方案依据

- 沿用 D-28 方案 8 决定的部分：生成的文件放进被 git 忽略的 `.canon/`，由当前运行的 canon 生成，不提交、不走合入。原文：“`canon brief`（每个会话开始时运行）和 `canon config` 把 schema 写进被 git 忽略的 `.canon/config.schema.json`”。写入方式沿用 BR-2176（内容没变不重写，先写临时文件再改名）。前提没变：页面和 schema 一样，是由当前 canon 和当前配置算出来的东西，没有需要保留的项目改动。
- 新的选择（D-140，负责人定的方向）：`canon/product.md` 原文是“网页 dashboard 或 HTTP API：人直接看仓库里或 GitHub 上的文件”，这里给它加一个例外：一个本地、只读、不连网的静态页面；不加 HTTP 服务、不加常驻进程、不加改配置的入口。
- 页面文件的生命周期：`.canon/flow.html` 是派生出来的，不是数据源。每次运行 `canon config --flow` 整份重新生成；没有版本号，也不迁移：canon 升级后格式变了，下次运行写出的就是新格式。文件损坏或被删，再运行一次就恢复；清理 worktree 时 `.canon` 算可重建（BR-2179）。配置改了而没有重新运行，页面就是旧的：页面上写明它是哪个 `canon/config.yaml` 在运行那一刻的快照。
- 最坏的失败：人按过期的页面或写错的类别判断某一步开没开、能不能关，比如把能关的当成不能关。页面不改配置，也不参与合入，所以后果只限于读错，不会改坏 main 或配置。已经试过最小的失败情形：`.canon` 是普通文件、写不了页面时，流程照常输出、退出码 0（BR-2541 的测试）。
- 证据：在 delegate 项目里运行 `canon config --flow`，页面生成后 `git status` 仍是干净的；用无界面浏览器打开页面，用真实的鼠标点击步骤，右侧面板能切换；测试检查页面里没有外部资源，嵌入的数据和 `--flow --json` 的输出相同。
- 什么结果能证明这个选择错了：负责人或会话经常因为页面过期而看错，需要实时状态；或者确实需要在页面上直接改配置。那时要重新决策，但改配置仍然不能绕过合入（D-28）。

## 陷阱和假设

- 配置项的类别和它属于哪一步是人判断的，写在各自领域的声明里；判断依据是配置项自己的说明（比如 `floor` 的 “required to land” 对应 `src/work/land/land.ts` 的 `no-floor` 拒绝）。新加配置项时必须写 `flow`，否则类型检查不过。
- “运行”的意思是：必需的配置项都写了，也没有哪个配置把这一步关掉。canon 自己不启动、要靠项目命令启动的步骤（合入后的代码评审靠 `hooks.after_land`），要把那个命令所在的配置项也挂到这一步上，让它决定这一步运行还是没开；不然页面会把从来没跑过的步骤显示成“运行”（第一版就这样显示过 delegate 的代码评审）。
- 页面是运行那一刻的快照，配置改了要重新运行 `canon config --flow`。
- 流程视图用中文（负责人要求），配置项自带的说明仍是英文原文；canon 其他命令的输出不变，仍是英文。
