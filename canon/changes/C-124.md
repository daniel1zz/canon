## 为什么

GitHub issue #37（C-118 合入后的代码评审发现）：`canon stats --since` 的检查统计、并发摘要、搜索统计是三次独立的查询，没有共同的上限。并发运行时别的会话在两次查询之间写下 `land.ok`，同一份输出里检查统计和摘要的合入次数就对不上，输出也没写覆盖到哪个编号，无法复查。这正是这个命令要用的场合。

## 要改什么

子领域：work/stats（`src/work/stats/`），CLI 接线在 `src/cli/main.ts`。

- 运行开始时取一次最大事件编号，三部分都只看不大于它的事件；摘要写明 `up to #m`，JSON 里是 `window.until`。
- BR-2155 写明这一点并补例子；顺带处理两条评审建议：没有 worktree 的旧事件不算一个 worktree（BR-2155），`--since` 比最大编号还大时全是 0（BR-2154）。

## 陷阱和假设

- 用编号上限而不是读事务：编号由 SQLite 自增分配，提交顺序和编号顺序在单个写锁下一致，上限之后不会再出现更小的编号。
