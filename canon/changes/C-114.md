## 为什么

N-3：`canon work clean` 只能清全部已合入、没人认领的 worktree，几个 agent 并发时，一个 agent 的 clean 会把另一个 agent 已合入、还没来得及自己处理的 worktree 一起删掉。要能只清自己的。

## 要改什么

子领域 `work/session`（clean 本身）和 `cli`（参数检查）。

- `canon work clean <C-n>...`：只考虑列出的变更的 worktree，检查和以前完全一样（BR-2019：当前所在、认领、未提交改动、不在 main 上的提交、不能重新生成的被忽略文件、进程，删除期间占住认领）。有一个编号不是变更（没有 worktree、main 上没有变更文件、也没有变更分支）→ 什么都不删，退出码 3。是变更但没有 worktree → 保留列表写 “no worktree”。不带编号时行为不变。新规则 BR-2152。
- `cli/strict.ts`：BR-2097 原来拒绝比声明多的位置参数；加 `takesMany` 标记一个命令最后的位置参数可以有多个，只给 `work clean` 用。BR-2097 写明这个例外。
- `canon work land --finish` 结束时的提示改成 `canon work clean <C-n>`，只清自己的。
- 工作说明（`src/cli/guide.ts`）和 CLAUDE.md 里没有提到 `canon work clean` 的行，不用改。

## 陷阱和假设

- 编号是否是变更，先看 worktree 目录，再看 main 上的变更文件，最后看变更分支（和 start 找变更的顺序一致）；只有前两者都没有时才查分支。
