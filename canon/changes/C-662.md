## 为什么

D-155 第 2 步：负责人要的档位，以及按档位排开工和合入的顺序。

## 要改什么

- 让计划中的 BR-2602、BR-2603、BR-2604、BR-2605 生效，同时改 BR-2148、BR-2232、BR-2363。
- 代码：`src/work/priority`（协调数据库的档位表、`canon priority set` 命令、负责人和主 agent 的规则）、`src/knowledge/changes/state.ts`（按档位排）、`src/work/land/queue/queue.ts`（`rankOf` 按档位）、`src/work/land/queue/urgent.ts`（`backlog urgent` 记成负责人的 `P1`）、`canon change list` 和 `canon work status` 的显示。

## 教训

- 派给 worker 的变更，规划中的规则带 `will_amend` 时，worker 合入只能把规则改成生效、删掉 `will_amend`（BR-2501），改不了它列出的生效规则；生效之后那些规则的文字要和新规则一致，就只能由设计负责人改。这次把 BR-2148、BR-2232、BR-2363 的新文字写成提议（提议目录，BR-2524），由设计负责人 `canon rule apply C-662`。设计负责人在派发前把 `will_amend` 目标的新文字一起发布到 main，worker 就不用交回。`C-661` 也一样 → 待负责人确认是否固化
- 主 agent 给负责人已经定的档位再设同一档时不改任何东西（仍算负责人定的，`backlog urgent` 的标记也留着），否则同一档里负责人标的优先会被主 agent 无意中降成普通的 `P1` → BR-2602
