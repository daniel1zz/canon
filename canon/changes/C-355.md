## 为什么

`config` 里还剩五条各讲一个配置项的规则，用这些配置项的是别的领域：`tests` 和 `code_root`、`shared` 给 `canon check` 用，`instructions` 给合入评审用，`test_command` 给 `canon work test` 用，`floor_skip_paths` 给合入时跳过 floor 用。这是 D-63（方案 D）的第 3 步。

## 要改什么

- 规则原样搬动（一个只含 `git mv` 的提交，BR-2009）：BR-2046、BR-2116 到 `knowledge/check`，BR-2151 到 `knowledge/review`，BR-2160 到 `work/verify`，BR-2165 到 `work/land/checks`（BR-2164 在那里）。
- 另起提交：`code_root`、`shared` 的声明从 `src/config/` 下的 `config-keys.ts` 并进 `src/knowledge/check/config-keys.ts`（BR-2046 的 `tests` 已在那里，`instructions`、`test_command`、`floor_skip_paths` 的声明本来就在使用者的 `config-keys.ts`），删掉空了的那个文件，改 `src/config/config.ts` 的汇总；两个 README 同步。
- 验证：`src/config/config.test.ts`、`key.test.ts` 和 reference 的测试（错误信息和已知键顺序不变；顺序由每项的 `listed`、`checked` 数值决定，不由 `DOMAINS` 数组的顺序决定）、`canon check`、`canon rule domains` 没有新增提示。

## 陷阱和假设

- 测试名引用这五条规则的用例仍在 `src/config/config.test.ts`：它们通过 `readConfig` 和命令行测的是“读配置时报错”，和配置读取放在一起；这次不拆测试文件。
