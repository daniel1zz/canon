## 怎么测的

2026-11-03，在 canon 主 checkout 和 `canon work start C-3` 建的 worktree 里，把模拟的 hook 输入（JSON，经 stdin）逐个喂给 `~/.claude/settings.json` 配置的 20 个 hook 脚本，记录退出码和输出。子 agent 的情形在输入里带 `agent_id`。测试脚本只读，不改任何全局文件。

## hook 实测结果

会误拦的（退出码 2）：

| hook | 情形 | 结果 | 判断 |
| --- | --- | --- | --- |
| `pre-edit-anchor-gate` | 任何子 agent 在 canon（主 checkout 或 worktree）里 Edit/Write | 拒绝：`lore anchor scope` 找不到 Lore 数据库 | 全部误拦。canon 里子 agent 改不了任何文件 |
| `pre-bash-git-safety-gate` | `git reset --hard HEAD`（工作区干净） | 拒绝，自己也判断“不会丢东西” | 误拦 |
| `pre-bash-git-safety-gate` | `git stash drop`（stash 为空） | 拒绝，自己也判断“是空操作” | 误拦 |
| `pre-bash-git-safety-gate` | `git worktree remove`、`git branch -D` | 拒绝 | 有时是真风险；canon 的正规路径见 C-8 |
| `pre-bash-git-safety-gate` | `git checkout -- <文件>`（本会话实际遇到，2026-11-03；这些文件的改动已另存为 patch） | 拒绝，自己也判断“不会丢东西” | 误拦；只好改成先提交、再在临时 worktree 里反向打 patch 来做反向验证 |
| `subagent-stop-commit-guard` | 子 agent 结束时 worktree 有未提交文件 | 拒绝结束 | 检查做法，D-1 不做；结果上与 canon 不冲突 |
| `pre-helper-foreign-working-copy-gate` | 在 worktree 里的子 agent 改主 checkout 的文件 | 拒绝 | 与 canon “共享 checkout 不改文件”一致，可以保留 |

不拦、但注入误导内容的：

- `run-register`（SessionStart、SubagentStart）：每个会话开头注入“`lore run register` 失败，本次运行的写入会被拒绝”。canon 里不会被拒，这句话是假的。
- `subagent-context`（SubagentStart）：给每个子 agent 注入旧 lore 的 `lore pending --ask` 流程和旧系统的规则编号（如 `BR-1375`）。
- `user-prompt-fragments`（UserPromptSubmit）：每轮注入“代码/注释/文档：English”，和 canon“`canon/` 下的文档一律用中文”冲突。
- `pre-tool-harness-run`：给每条 Bash 命令前面加 `export LORE_HARNESS_RUN=...`，不影响结果。

没有影响的：`session-start-resume`、`session-start-marker`、`session-trail-start`、`user-prompt-turn-start`、`post-edit-mark`、`post-ask-decide`、`run-end`、`subagent-trail`、`stop-turn-review`（读 `.lore/config.yaml`，canon 里没有，默认关闭）。

canon 自己的命令（`canon work land`、`canon work clean`）在子进程里调用 git，不经过这些 hook，所以不受 git 安全检查影响。

## 建议的处理顺序

1. 立即（影响 canon 正常工作）：对 canon 关掉 `pre-edit-anchor-gate`、`run-register`、`subagent-context`。最小的改法是让这三个脚本在找不到 Lore 数据库时直接放行、不输出（对其他 lore 项目不变）；更彻底的改法是旧 lore 退役后整组移除。
2. 同时：改写上表中的四个规则文件和语言注入段。
3. 旧 lore 退役时：备份后移除 20 个 hook、40 个 skill 链接和三个 agent 定义；`pre-bash-git-safety-gate` 的需求由 C-8 的 `canon work drop`（已实现，BR-2064 到 BR-2066）接手。

另外：这个 git 安全检查也拦下了 canon 自己没法删除的临时 worktree（反向验证用的 scratch worktree 需要 `git worktree remove --force`），只能请负责人手动删。

## 执行结果（2026-11-03，负责人确认后执行）

- agent：移除 `lore-implementer`、`lore-reader`、`researcher`。
