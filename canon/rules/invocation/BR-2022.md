## 规则

0 成功（包括 `canon events --follow` 被 SIGTERM 或 SIGINT 停止，它只能这样结束，BR-2357、D-69）；1 被结果检查拒绝，情形只有这些：floor 失败、`canon check` 发现问题、评审拦截（包括评审命令运行失败、超过时限被停下或没有给出有效结论，BR-2296）、需要评审却没有配置 `review` 或在同一次合入里关掉了评审（合入，BR-2074、BR-2143、BR-2295；会改 SKILL.md 的 `canon update`，BR-2086）、`before_land` hook 失败、rebase 冲突、合入过程中 worktree 变了（BR-2106）、main 在合入或 `canon sync` 过程中被移动、签出了 main 的 worktree 有未提交改动（合入和 `canon sync` 都是，BR-2262）、新 worktree 的 setup 失败、`canon update --check` 发现过期的项、`canon update` 的变更没能合入（BR-2084、BR-2086）、`canon uninstall` 的变更没能合入（BR-2278）；2 用法错误（包括缺参数、未知命令、不带子命令、命令没有声明的选项或多出的位置参数，BR-2097）、输入无效（包括回答方式不符合 BR-2021）或 `canon/config.yaml` 写错（BR-2045）；3 找不到；4 环境错误：不在 git 仓库里、git 命令失败、协调数据库打不开、读不到 main 上的文档、仓库还没有任何提交时 `canon work start`（BR-2012）、找不到 canon 自带的 skill（BR-2082）、放弃变更时存档失败或列不出进程（BR-2103、BR-2064）、还没有 `canon/config.yaml` 时在分离的 HEAD 上 `canon init`（BR-2032）、hook 目录不支持硬链接、装不了 git 守卫（BR-2124）（D-4）；5 冲突，情形只有这些：变更被另一个 worktree 或另一个执行者认领（BR-2011；在别人认领的 worktree 里停下、放开或合入也算，BR-2104；在正被 `canon work clean` 或 `canon work drop` 删除的 worktree 里停下也算，BR-2025）、问题已经回答过、要新建的单个文档或领域已经存在（`canon init` 遇到已有文件不算，BR-2076）、安装 skill 会覆盖项目里改过的文件（BR-2081）、hook 目录里已有不是 canon 写的 `reference-transaction` hook（BR-2124）、要放弃的变更被别的操作者认领或它的 worktree 正被别的进程使用（BR-2064）、`canon sync` 时本地 main 和远端 main 分叉（BR-2263；`canon uninstall` 先做的同步也是）、`canon uninstall` 遇到进行中的工作（BR-2277）、会删掉项目里改过的 skill 文件（BR-2279）、有会丢工作而删不掉的 worktree 或分支（BR-2280）、`--remove-knowledge` 时主检出不在 main 上或 `canon/` 下有未提交改动（BR-2282）；75 还没完成、稍后再运行，情形只有这些：合入排队超时（`canon work land`、`canon update` 和 `canon uninstall` 的合入都是）、`canon uninstall` 要清理本地时上一次合入的后台 `after_land` 命令或后台 floor 观察进程还在运行（BR-2283）、`canon work after-land` 报告的命令还在运行（不带 `--wait`，或 `--wait` 等到了超时，BR-2166、BR-2167）；70 canon 自身的 bug（未处理的异常）；`canon work land` 被信号终止时按 shell 惯例退出 128 加信号编号：SIGTERM 143、SIGINT 130（BR-2099）。

## 例子

- `canon show BR-999`（不存在）→ 3
- 改了一条规则、配置里没有 `review` 时 `canon work land` → 1
- `canon check` 发现问题 → 1
- `canon work start` 不带参数 → 2
- `canon show` 不带编号、`canon bogus`（没有这个命令）→ 2
- `canon work land --dry-run`（`land` 没有这个选项）→ 2，什么也不做
- 在 git 仓库外执行 `canon show BR-1` → 4
- main 上和变更分支上都没有 `C-99` 时 `canon work start C-99` → 3（文档不存在）；git 读不出 main 时 → 4（环境错误）
- 另一个 worktree 认领 `C-1` 期间再认领它 → 5
- `canon work land` 在 floor 中途收到 SIGTERM → 143
- `canon events --follow` 运行中收到 SIGTERM → 0（不是 143）
- 别的会话认领着 C-12 时 `canon uninstall` → 5；卸载合入后 `after_land` 还在运行 → 75
- `canon update` 的变更等到超时还在排队 → 75（不是 1）
- `canon work after-land` 不带 `--wait`，后台命令还没有失败、也还没全部结束 → 75；全部以 0 结束 → 0
- `canon sync` 时本地 main 和远端 main 分叉 → 5（不是 1）；签出了 main 的主 checkout 有未提交改动 → 1
