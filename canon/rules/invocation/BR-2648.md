## 规则

canon 命令树里每个能运行的命令 `canon <词…>`，必须至少在下面一处被原样提到（后面紧跟的不是字母或 `-`，所以 `canon work take` 不算提到 `canon work takeover`）：

- 工作说明的源码（各领域的 `guide.ts`，`canon brief` 由它们拼出）；
- canon 自带的 skill（`.claude/skills/canon-*/` 下的 Markdown）；
- canon 的源码里会输出给 agent 的文字（议程的下一步、拒绝信息、提示行等），不算注释，也不算这个命令自己：注册它的那个 `commands.ts`，和以它的最后一个词命名的文件（`canon work adopt` 的 `adopt.ts`）只是在描述它自己。

不需要引导的命令列在一份豁免清单里，每个写明理由：由宿主 hook 或 git hook 运行的、只给人用的、只是列出文档而工作说明里已经提到能找到同样文档的命令的、只用于项目自己声明的文档类型的。豁免清单里的命令必须存在；除了由 hook 运行和只给人用的，豁免的命令一旦有了引导就要从清单里删掉。

这条由 `src/invocation/every-command-guided.test.ts` 检查：新加一个命令却没有任何地方告诉 agent 去用它，测试就失败。

## 例子

- 新加 `canon work adopt`，只在它自己的 `adopt.ts` 和注册它的 `commands.ts` 里出现 → 测试失败，列出 `work adopt`
- 议程的一项下一步写着 `canon work adopt --from <owner>`（`due.ts`）→ 算有引导
- `canon goal start` 只在 `goal.ts` 的一行注释里出现 → 不算，测试失败
- `canon work check-as` 只由 PreToolUse hook 运行，列在豁免清单里并写明这一点 → 通过
- 豁免清单里有 `canon rule list`，后来 canon-rules skill 提到了它 → 测试失败，要求把它从清单里删掉
