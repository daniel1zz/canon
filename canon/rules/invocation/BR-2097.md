## 规则

每个 canon 命令只接受它自己声明的参数：命令没有声明的选项（`--名字`、`--no-名字`、单字母 `-x`），布尔选项带了 `true`、`false` 以外的值，或者位置参数比命令声明的多（`canon work clean` 接受任意多个变更编号，BR-2152），都以退出码 2 拒绝；一行命令经过的每一层都检查：子命令名前面的参数按上一层命令检查，其余的按最后那个命令检查；最后那个命令有子命令、但不带子命令名也能自己运行时，同样检查它自己的选项（只用来归组、自己不能运行的命令，不带子命令名时由命令行解析以退出码 2 拒绝）。错误信息写明是哪个参数、这个命令有哪些选项，并且在命令做任何事情（读写文件、协调数据库、git）之前就拒绝。`--help` 不受影响，照常输出用法、退出码 0。紧跟在字符串选项后面、处在它的值位置的词是这个选项的值，不按选项检查（BR-2228）：`--title -x` 不报 `-x`。这样 `--dry-run` 一类拼错或不存在的选项不会被悄悄忽略、让命令真的执行。

## 例子

- `canon search brief --jsno` → 退出码 2，信息里有 `--jsno` 和 `--limit, --json`；`canon search brief --json` → 退出码 0
- `canon rule new --domain billing --title X --dry-run` → 退出码 2，`canon/rules/billing/` 下没有新文件；去掉 `--dry-run` → 退出码 0，新建一条规则
- `canon stats extra`（`stats` 没有位置参数）→ 退出码 2；`canon search a b`（只有一个位置参数）→ 退出码 2，信息里有 `"b"`
- `canon show C-1 --json`（`show` 没有选项）→ 退出码 2
- `canon stats --json=yes` → 退出码 2；`canon stats --json=true` → 退出码 0
- `canon stats --bogus --help` → 退出码 0，输出用法
- `canon work clean C-1 C-2` → 不算多出的位置参数，两个编号都交给 clean
- 命令 `x` 有子命令 `sub`，自己也能运行，只声明了 `--json`：`canon x --bogus` → 退出码 2，信息里有 `canon x` 和 `--bogus`；`canon x --json` → 照常运行；`canon x sub --json`（`sub` 没有这个选项）→ 退出码 2
- `canon decision --bogus`（`decision` 只用来归组）→ 退出码 2
