## 规则

canon 通过它的 git 调用（`src/kernel/git.ts` 的 `git`、`gitEnv`）运行的 git 命令失败，而 git 的输出里有 `git-lfs: command not found`、`'git-lfs' was not found on your path` 或 `git-lfs: not found`（仓库的 `.gitattributes` 用了 Git LFS，git-lfs 却不在 PATH 上）时，错误信息在 git 的原始输出后面另起一行：`git-lfs is not installed, but this repository uses Git LFS (see .gitattributes): install it (macOS: brew install git-lfs; others: https://git-lfs.com), then run git lfs install`。退出码和别的处理不变（环境错误按 BR-2022）；别的 git 失败不加这一行。只改错误信息，不在会话开始时检测，也不拦任何操作（D-152）。

这样快照 hook（`canon snapshot take --hook`）、合入等因为缺 git-lfs 失败时，看到的是缺什么、怎么装，而不只是 git 的原始报错。

## 例子

- 仓库的 `.gitattributes` 有 `*.bin filter=lfs`，PATH 上没有 git-lfs，canon 运行 `git add a.bin` 失败 → 信息是 git 的 `git-lfs filter-process: git-lfs: command not found`，下一行是安装提示
- 同一个仓库里 `git rev-parse --verify no-such-ref` 失败 → 信息里没有 git-lfs 的提示
