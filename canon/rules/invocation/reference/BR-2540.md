## 规则

`canon config --flow` 按流程的顺序列出 canon 的八个阶段：会话开始、开工、测试、评审预览、合入、合入后、停下与收尾、验收。每个阶段写出它的命令，阶段下是它的步骤，步骤下是配置这一步的配置项。canon 认识的每个配置项至少出现在一个步骤下，配置几个步骤就出现几次，比如 `review` 同时出现在评审预览和合入后的规则评审下。

每个步骤标明在这份配置下是运行还是没开；没开时写明是哪个配置项的什么值让它没开。没开的情形只有下面这些，其余步骤总是运行：

- `review` 是 `none` 或没写：评审预览的规则评审、合入后的规则评审；
- `remote` 没写：合入后的推送；
- `related_pick_command` 没写：评审预览的挑相关文档；
- `typecheck_command` 没写：测试阶段的类型检查；
- `floor_timing` 是 `after`：合入阶段的 floor；`floor_timing` 是 `before`（默认）：合入后的后台 floor 和 after_green hook；
- `hooks` 里某个事件没有命令：这个事件的 hook 步骤；`hooks.after_land` 没有命令时还有合入后的代码评审，因为 canon 不自己启动代码评审，要由项目在 after_land 里运行评审脚本；
- 必需的配置项没写：它配置的每一步，原因写明缺了它会怎样。

一个步骤同时有几个原因时，都写出来。canon 内置、没有配置能关掉的步骤（认领、合入排队、移动 main、`canon check`）标明是内置的，以及它支撑哪条承诺。

每个配置项写出当前值，取法同 BR-2174：文件里写了就是写的值，没写就是默认值或标明没写；值按 JSON 写成一行，列表和映射也整个写出，不截断；还写出它属于哪一类：必需（写明缺了它哪个命令失败）、可选（写明怎么关）、可调。映射型配置项只写这一步用到的子键，比如 before_land 这一步只写 `hooks.before_land`。配置项属于哪一步、哪一类，由声明它的领域在它的声明里写明（D-140）。

加 `--json` 时输出同样的内容：一个对象，`stages` 是阶段数组；每个步骤带 `id`、`title`、`runs`，没开时带 `idle`，内置时带 `builtin`；每个配置项在 BR-2174 的字段之外带 `role`，可选的带 `off`，必需的带 `why`。`--flow` 和 `--schema` 一起给是用法错误，退出码 2。配置写错时按 BR-2045 以退出码 2 失败。

## 例子

- 没写 `remote` → 合入后阶段的推送步骤没开，原因点名 `remote`；写了 `remote: origin` → 这一步在运行
- 没写 `floor_timing` → 合入阶段的 floor 步骤在运行，合入后阶段的后台 floor 没开；写了 `floor_timing: after` → 正好反过来
- `review: none` → 评审预览和合入后的规则评审都没开，原因点名 `review`
- `hooks` 里配了 `before_land: ./check.sh` → before_land 步骤在运行，下面只有 `hooks.before_land = "./check.sh"`；没配 → 这一步没开
- 没写 `hooks.after_land` → 合入后的代码评审没开；配了 → 代码评审在运行
- 没写 `floor` → 合入阶段的 floor 和合入后的后台 floor 都没开，原因点名 `floor`
- canon 认识的每个配置项都出现在至少一个步骤下
- `shared: [src/kernel, src/util]` → `shared` 的值是 `["src/kernel","src/util"]`，整个写出
- `floor` 是必需，`remote` 是可选，`claim_lease_hours` 是可调
- 认领步骤标为内置，支撑 P4
- `--flow --json` → 标准输出能整个解析成 JSON，`floor` 那项的 `role` 是 `required`
- `--flow --schema` → 退出码 2
