## 规则

`canon config --flow` 在当前 checkout 的根目录写 `.canon/flow.html`：一个在浏览器里直接打开的页面，显示 BR-2540 列出的同一份流程，数据就是 `--flow --json` 的输出，嵌在页面里。页面不从网络加载任何东西（没有外部脚本、样式表、字体和图片），离线也能看。

页面是只读的：没有改配置的控件，页面上写明改配置要编辑 `canon/config.yaml`，再像别的改动一样走合入；每个配置项给出一行可以复制的 YAML 写法。

写入方式、`info/exclude` 的处理，以及写不了时怎样报告，都同 BR-2176：报告的那行点名 `.canon/flow.html`，流程照常输出，退出码不变。不带 `--json` 时，最后一行给出页面的绝对路径。只有 `--flow` 写这个文件，不带 `--flow` 的 `canon config` 和 `canon brief` 都不写。页面是运行那一刻的快照，配置改了要重新运行。只读、本地、不连网，是 `canon/product.md` 不做网页 dashboard 的例外能成立的条件（D-140）。

## 例子

- 运行 `canon config --flow` → `.canon/flow.html` 存在，`git status --porcelain` 为空，最后一行是它的绝对路径
- 页面里没有 `<script src`、`<link`、`@import`、`url(`
- 页面里嵌的数据和同一配置下 `canon config --flow --json` 的输出相同
- 只运行 `canon config` → 不写 `.canon/flow.html`
- `.canon` 是一个普通文件 → 输出一行 `cannot write .canon/flow.html: ...`，流程照常输出，退出码 0
