## 规则

0 成功；1 被结果检查拒绝，情形只有这些：floor 失败、`canon check` 发现问题、评审拦截（包括评审命令运行失败或没有给出有效结论）、`before_land` hook 失败、rebase 冲突、main 在合入过程中被移动、签出了 main 的 worktree 有未提交改动、新 worktree 的 setup 失败、放弃变更需要人同意或人没有同意（BR-2065、BR-2066）；2 用法错误（包括缺参数、未知命令、不带子命令）、输入无效（包括回答方式不符合 BR-2021）或 `canon/config.yaml` 写错（BR-2045）；3 找不到；4 环境错误：不在 git 仓库里、git 命令失败、协调数据库打不开、读不到 main 上的文档（D-4）；5 冲突，情形只有这些：变更被另一个 worktree 认领、问题已经回答过、要新建的单个文档或领域已经存在（`canon init` 遇到已有文件不算，BR-2076）；75 合入排队超时；70 canon 自身的 bug（未处理的异常）。

## 例子

- `canon show BR-999`（不存在）→ 3
- `canon check` 发现问题 → 1
- `canon work start` 不带参数 → 2
- `canon show` 不带编号、`canon bogus`（没有这个命令）→ 2
- 在 git 仓库外执行 `canon show BR-1` → 4
- main 上没有 `C-99` 时 `canon work start C-99` → 3（文档不存在）；git 读不出 main 时 → 4（环境错误）
- 另一个 worktree 认领 `C-1` 期间再认领它 → 5
