## 规则

`canon init --floor <命令>` 在仓库根目录建出 `canon/product.md`（中文标题：目的、使用者、承诺、不做的事）、`canon/config.yaml`（第一行是指向 schema 的 modeline 注释，见 BR-2176；再写入 `main` 和 floor）和 `canon/rules`、`canon/decisions`、`canon/changes`、`canon/notes`；没给 floor 时提示必须先配置。

写进 `main` 的是当前分支名（`git symbolic-ref --short HEAD` 的结果），不管它叫什么；还没有任何提交的仓库也有当前分支名，照写。git hook 守卫（BR-2123）守的就是这个分支。`canon/config.yaml` 还不存在而 HEAD 是分离的（不在任何分支上）时，`canon init` 在写任何文件之前、也在其他所有检查（包括 BR-2124 的别人的 git hook）之前以退出码 4 拒绝，提示先签出要当主分支的那个分支再运行；`canon/config.yaml` 已经存在时它不被覆盖（BR-2076），也不看当前分支，分离的 HEAD 不影响。

## 例子

- 新仓库执行 `canon init` → 建出上述文件和目录，提示 set `floor`
- `canon init --floor "bun test"` → `canon/config.yaml` 第一行是 `# yaml-language-server: $schema=../.canon/config.schema.json`，并有 `floor: "bun test"`
- 在分支 `trunk` 上执行 `canon init` → `canon/config.yaml` 里是 `main: trunk`，守卫守 `trunk`；在分支 `main` 上 → `main: main`
- 用 `git init -b dev` 建的、还没有提交的仓库 → `main: dev`
- 签出某个提交（分离的 HEAD）、还没有 `canon/config.yaml` → 退出码 4，提示里有 `detached`，`canon/` 和 `.claude/skills` 都没有被写
- 分离的 HEAD、还没有 `canon/config.yaml`，hook 目录里又有别人写的 `reference-transaction` → 退出码 4（不是 5），那个 hook 不变
- 分离的 HEAD，但 `canon/config.yaml` 已经存在 → 照常执行，退出码 0，配置内容不变
