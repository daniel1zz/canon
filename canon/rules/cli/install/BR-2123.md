title: canon install 把 main 的守卫装进仓库的 git hook 目录

## 规则

`canon init`、`canon install` 和 `canon update` 把 canon 的 `reference-transaction` hook（行为见 BR-2126）写进 `git rev-parse --git-path hooks` 给出的目录（设置了 `core.hooksPath` 时就是那个目录；所有 worktree 共用），文件可执行，第二行是 canon 的标识行 `# canon: reference-transaction guard. …`，main 的分支名取自 `canon/config.yaml` 的 `main`（没有配置文件时：`canon init` 用它马上要写进配置的当前分支名，BR-2032；`canon install` 和 `canon update` 用 `main`），可以是 git 接受的任何分支名（比如 `rel+1`、`a$b`），写进 hook 时 shell 不会把它当成别的东西；git 不接受的名字（`git check-ref-format` 拒绝的，比如 `a..b`）算配置写错，`canon init`、`canon install`、`canon update` 和 `canon update --check` 在写任何文件之前以退出码 2 拒绝。这个文件不在仓库的提交里，所以：`canon update --check` 在它缺少、内容和当前 canon 写的不同或不可执行时，列出一行 `git hook: main moves only through canon work land (<路径>)`（旧内容另加 `older form`），退出码 1；`canon install` 写好它：先写同目录下的临时文件、设为可执行，再改名换上，所以同时运行的 git 只会看到旧的或完整的新 hook；`canon update` 在只有它过期时直接装好、不开变更，和别的过期项一起过期时在更新变更的 worktree 里一并装好。在 canon 自己的仓库里也装。

## 例子

- 刚 `canon init` 完 → `.git/hooks/reference-transaction` 存在、可执行、第二行是标识行；`canon update --check` 退出码 0
- 设置了 `core.hooksPath=.githooks` 再 `canon install` → 文件写在 `.githooks/reference-transaction`，`.git/hooks` 下没有
- 删掉这个文件 → `canon update --check` 退出码 1，列出 `git hook: main moves only through canon work land`；`canon update` 退出码 0，文件回来了，main 上没有新提交
- `canon/config.yaml` 里 `main: "rel+1"`，执行 `canon install` → 退出码 0，之后直接在 `rel+1` 上 `git commit` 被拒绝，在名为 `main` 的分支上提交照常
- `main: "a..b"` → `canon install` 退出码 2，`.claude` 和 hook 都没有写
- 标识行还在、内容是旧版本 → `canon update --check` 列出 `older form`；`canon install` 换成当前内容，hook 目录里不留临时文件
