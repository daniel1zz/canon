## 规则

main 上没有 `canon/config.yaml`（刚合入的卸载，或别的克隆合入、本克隆已同步到的卸载）时，`canon uninstall` 只清理本仓库里不进版本库的 canon 的东西：第二行是 canon 标识的 `reference-transaction` hook（任何版本；别人写的不动）、按 BR-2019 能安全删掉的 change worktree 和已合入 main 的 `change/*` 分支、`<git 公共目录>/canon/`、`.canon/` 目录和 `.git/info/exclude` 里的 `/.canon/` 一行、`refs/canon/*` 里除 `archive/` 和 `snapshots/` 以外的 ref。先按顺序找到要看的分支：工作区里还有 `canon/config.yaml` 时用它写的 `main`，否则用 canon 守卫里写的分支，再否则用当前分支；然后从这个分支上删除 `canon/config.yaml` 之前的那份配置读出 `main` 和 `worktrees`，清理时一律用这份配置里的值。删不掉的 worktree 或分支每项一行列出原因，以退出码 5 结束，其余照常清理。什么都没有可清理时说 `canon is not installed here` 并以退出码 0 结束；再运行一次结果相同。

## 例子

- 卸载合入之后 → git hook 目录里没有 `reference-transaction`，`.git/canon/` 不存在，`git for-each-ref refs/canon/green` 为空，在 main 上直接 `git commit` 成功
- hook 目录里的 `reference-transaction` 是 lefthook 写的 → 原样保留，输出里说明没动它
- 刚卸载完再运行一次 → 退出码 0，`canon is not installed here`
- 别的克隆：`git pull` 拿到卸载提交后运行 `canon uninstall` → 只做本地清理，不开变更
- 工作区里没有 `canon/config.yaml`，守卫守的是 `trunk`，当前签出的是 `side` → 看 `trunk` 上删除前的配置，清理按其中的 `main: trunk` 判断哪些分支已合入
