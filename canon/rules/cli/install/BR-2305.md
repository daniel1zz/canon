title: canon init、install、update 把 /.claude/worktrees/ 写进 git 公共目录的 info/exclude
status: active
---

## 规则

Claude Code 让子 agent 在 worktree 里干活时，会在项目里建 `.claude/worktrees/<名字>`。这个目录没有被忽略，主检出就有未跟踪文件，合入因 `main-dirty` 被拒。所以 `canon init`、`canon install` 和 `canon update` 确认 `git rev-parse --git-common-dir` 给出的目录（所有 worktree 共用，在链接的 worktree 里运行也指向主仓库的那个）下 `info/exclude` 里有一行 `/.claude/worktrees/`，没有就在末尾追加：只追加、不重写，原有的行原样保留，已经有这一行时什么都不加（不会出现重复行）；文件或 `info/` 目录不存在时先建出来。只动这个本地文件，不改 `.gitignore`，没有任何被跟踪的文件变化。写法和 BR-2176 对 `/.canon/` 用的一样。

这一行不在仓库的提交里，所以和 BR-2123 的 git hook 一样：`canon update --check` 在它缺少时列出一行 `git exclude: /.claude/worktrees/ (<info/exclude 的路径>)`，退出码 1；`canon update` 在只有它（和 git hook）过期时直接写好、不开变更，和别的过期项一起过期时在更新变更的 worktree 里一并写好。

## 例子

- 新仓库里 `canon init` → `.git/info/exclude` 含一行 `/.claude/worktrees/`；之后 `mkdir -p .claude/worktrees/x && touch .claude/worktrees/x/f`，`git status --porcelain` 里没有 `.claude/worktrees`
- 再运行一次 `canon install`、`canon update` → exclude 文件内容不变，这一行仍只有一行
- exclude 原来是 `.env`（末尾没有换行）→ 变成 `.env`、`/.claude/worktrees/` 两行，`.env` 原样保留
- 没有 `.git/info/exclude`，甚至没有 `.git/info/` 目录 → `canon init` 之后两者都有了，内容是这一行
- 在链接的 worktree 里运行 `canon install` → 写进主仓库 `.git/info/exclude`，那个 worktree 的 `.git` 文件指向的目录里没有新建 exclude
- 删掉这一行 → `canon update --check` 退出码 1，列出 `git exclude: /.claude/worktrees/`；`canon update` 退出码 0，这一行回来了，main 上没有新提交
- 这一行在，其他都最新 → `canon update --check` 退出码 0
- 项目里有 `.gitignore` → `canon init` 之后它的内容不变
