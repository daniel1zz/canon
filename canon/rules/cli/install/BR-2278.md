status: active

## 规则

在 main 分支上还有 `canon/config.yaml` 的项目里（看 main 这个分支，不看工作区：被守卫拒绝的 `git pull` 会让工作区领先于 main），`canon uninstall`（检查都通过后）先在配了 `remote` 时同步 main（同 `canon sync`，分叉时以退出码 5 拒绝），然后开一个变更，在它的 worktree 里删掉：清单 `.claude/skills/.canon-skills.json` 记下的、内容仍和清单一致的 skill 文件，清单本身，因此变空的 `canon-*` 目录，`.claude/settings.json` 里 canon 的条目（SessionStart 的 `canon brief` 两种形式、PreToolUse 的快照条目、PostToolUse 的提问记录条目、canon 撤回的条目，BR-2130），以及 `canon/config.yaml`；写好变更说明后提交，用删除之前读到的配置（`floor`、评审等）按正常流程 `--finish` 合入。`settings.json` 里其余内容原样保留，`worktree.baseRef` 也保留并在输出里说明；某个条目、列表或对象因为删掉 canon 的项而变空时一起删掉，整个文件变成 `{}` 时删掉文件。合入被拒以退出码 1、排队超时以 75 结束，本地什么都不清理。合入成功后同一次运行接着做本地清理（BR-2280）。

## 例子

- 装着 canon、`floor: "true"`、没有进行中的工作 → 退出码 0；main 上没有 `canon/config.yaml`、`.claude/skills/canon-*` 和清单；`.claude/settings.json` 只剩 `{"worktree": {"baseRef": "head"}}`；`canon/rules` 等文档还在
- `settings.json` 里还有项目自己的 `PreToolUse` 条目 `{"matcher": "Edit", ...}` → 卸载后这个条目还在，canon 的快照条目没了
- `floor` 命令失败 → 退出码 1，main 上仍有 `canon/config.yaml`，git 守卫还在
