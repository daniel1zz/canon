## 规则

`canon update --check` 比较项目里 canon 装的文件和当前 canon 带的版本，每次都当场重新计算，不用缓存：项目里改过、canon 没有新版本的文件不算过期（BR-2089）。全部一致时输出 `up to date` 和版本号，退出码 0；否则逐行列出过期的项（缺少、内容不同或 canon 已经删掉的 skill 文件，缺少的或旧形式的会话 hook，BR-2087；缺少的或旧形式的 `canon hook pre-bash` hook、缺少的放行规则，BR-2128；缺少、旧的、不可执行或不是 canon 写的 git 守卫，BR-2123、BR-2124），项目里改过的 skill 文件标出 `(edited in this project)`，退出码 1。它只读，不改任何文件。版本号由 canon 带的全部 skill 文件的内容算出，内容变了版本就变。

## 例子

- 刚 `canon init` 完 → 退出码 0，`up to date`
- canon 更新了 `canon-a/SKILL.md` → 退出码 1，列出 `skill canon-a/SKILL.md`，项目里的文件不变
- 项目里改过 `canon-b/SKILL.md`，canon 也更新了它 → 这一行带 `(edited in this project)`
- `.claude/settings.json` 里没有运行 `canon brief` 的 hook → 列出 `hook: canon brief at session start`
- `.claude/settings.json` 里的 hook 是旧的 `canon brief` → 列出 `hook: canon brief at session start, older form`
- `.claude/settings.json` 里没有 PreToolUse 的 `canon hook pre-bash` → 列出 `hook: canon hook pre-bash before each Bash call`
