## 规则

main 守卫（BR-2126）拒绝一行 `refs/heads/<main>` 时，如果新提交在某个远端跟踪分支（`refs/remotes/*`）上、就是 `FETCH_HEAD`，或者是 `git pull` 自己刚在 main 上造的合并提交（`GIT_REFLOG_ACTION` 以 `pull` 开头、第一个父提交是 main 的提交），stderr 在拒绝的话后面多一行 `canon: to take in the remote's <main>, run canon sync.`：要把远端的 main 拿进来，受支持的办法是 `canon sync`（BR-2262、D-38）。其余被拒绝的新提交（本地的 `git commit`、本地分支的合并）不加这一行。

## 例子

- clone 的 main 落后远端，`git pull origin main` 被拒绝 → stderr 有 `to take in the remote's main, run canon sync`
- main 和远端各自前移过，`git pull --no-rebase origin main` 造出合并提交后被拒绝 → stderr 也有这一行
- 在签出 main 的 checkout 里 `git commit` 被拒绝 → stderr 没有 `canon sync`
- `git merge --no-ff -m m x`（x 是本地分支）被拒绝 → stderr 没有 `canon sync`
