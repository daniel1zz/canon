## 规则

`canon brief` 每次都先输出一段 canon 的工作说明（改代码前读上下文、每项工作是一个变更、行为变了同时改规则、怎么合入和停下、什么时候问人并如实记下、怎么放弃变更、不修的问题怎么记），排在 `canon brief` 所有其他输出之前（BR-2024 的内容、BR-2063 的重叠提示、BR-2085 的过期提示都在它后面）。这段说明写在 canon 程序里，不作为文件装进项目，所以总是和正在运行的 canon 一致。说明在 `canon brief` 做任何可能失败的事（找仓库、读 `canon/config.yaml`、打开协调数据库）之前输出；之后失败时，`canon brief` 除了照常在 stderr 报错、按 BR-2022 退出，还在 stdout 输出 `canon brief failed:` 加错误原因，以及修好后重新运行 `canon brief`、在那之前不要直接改 main 的提示（会话开始的 hook 只把 stdout 给模型看）。

## 例子

- 没有认领、handoff 和问题的项目执行 `canon brief` → 只输出工作说明，其中有 `canon context`、`canon work start`、`canon work land --finish`、`--relayed`
- 在认领了 `C-1` 的 worktree 里执行 `canon brief` → 先是工作说明，后面是 `You are in C-1`
- 在 git 仓库外执行 `canon brief` → 退出码 4，stdout 先是工作说明，后面是 `canon brief failed:` 和 `not a git repository`、`run canon brief again`
- `canon/config.yaml` 写错时执行 `canon brief` → 退出码 2，stdout 先是工作说明，后面是 `canon brief failed:` 和配置错误的原因
