---
id: BR-2285
title: 后台测试被 SIGTERM 或 SIGINT 终止时，先停掉它启动的全部进程、等它们结束再交出位置
status: active
---

## 规则

`canon floor watch` 收到 SIGTERM 或 SIGINT 时（只发给它自己，不是整个进程组），先停掉它启动的全部进程、等它们全部结束，再删掉临时 worktree、交出后台测试的位置（BR-2219），然后退出：SIGTERM 以 143、SIGINT 以 130 结束（BR-2022）。这次正在测的提交不记结果（BR-2219），正在跑的 `after_green` 不记 `floor.after_green`（BR-2270）。

“它启动的全部进程”是 `setup`、floor、`after_green` 和它们启动的进程，包括在列进程之后才启动的、和父进程已经退出的：

- 不管是不是组长，它的子孙进程都在其中，包括调用 `setpgid` 或 `setsid` 换到别的进程组或会话、但父进程还在的。
- 后台测试是自己进程组的组长时（合入、`canon brief` 和交接都这样启动它），组里除它以外的每个进程也在其中；父进程退出后，进程换了父进程，但仍留在原来的进程组里，也在其中。
- 不是组长时（在不带作业控制的 shell 里手动运行），只有它的子孙进程，组里别的进程不动；父进程已退出的进程不再是它的子孙，不在其中，不停也不等。
- 调用 `setsid` 离开进程组、而且父进程已经退出的进程（守护进程）不在其中：它既不在组里，也不再是子孙。

停的办法：先给每个发 SIGSTOP，再列一遍，有新的就再停，直到没有新进程，这时谁也启动不了新进程；然后给每个发 SIGTERM 和 SIGCONT。收到 SIGTERM 后 trap 里新启动的进程是它的清理，不再去停。

然后等：后台测试每 50 毫秒列一次，直到它启动的进程（包括 trap 里新启动的）都不在了，才交出位置、退出，所以 TERM trap 里的清理（例如原子替换 PATH 上的 canon）做完以前，下一个后台测试拿不到位置，不会和它同时运行。最多等 10 秒；10 秒后还在的发 SIGKILL（之后冒出来的也发），再等最多 5 秒，日志里写 `sent SIGKILL`，还有没结束的再写 `some of it is still running`。等待和发 SIGKILL 这两步里读不出进程表时，不算都结束了，接着按时间等：10 秒到时最后一次还是读不出，日志写 `10 s after SIGTERM the process table cannot be read`，照样进入发 SIGKILL 那一步；那一步 5 秒里一直读不出、一个 SIGKILL 也没发出去时写 `cannot read the process table to send SIGKILL`，发过 SIGKILL 但最后一次读不出时写 `whether it ended cannot be read`；然后照常删掉临时 worktree、交出位置、退出。等的时候后台测试不做别的事：不记结果，也不启动下一条命令。SIGKILL 之后 5 秒还有进程在，后台测试照样删掉临时 worktree、交出位置、以 143 退出（BR-2270 把这列为停不住的例外）。已经结束、只是还没被回收的进程（僵尸进程）不算。

停进程那一步（列进程、发 SIGSTOP）读不出进程表时没法列全，这时不再等，日志里写 `cannot read the process table` 和 `may not all have been stopped`，照常退出；前面几次读到、已经 SIGSTOP 的进程照样收到 SIGTERM 和 SIGCONT，不会一直停在那里。

## 例子

- `after_green` 是 `( (sleep 1; touch late) & ); while true; do sleep 0.1; done`（放出一个父进程立刻退出的进程），后台测试是组长，运行时只对它发 SIGTERM → 它以 143 结束，1.5 秒后也没有 `late`，没有 `floor.after_green`
- 同样的 `after_green`，只对它发 SIGINT → 它以 130 结束，1.5 秒后没有 `late`
- floor 是 `( (sleep 1; touch late) & ); sleep 30`，运行时只对后台测试发 SIGTERM → 它以 143 结束，1.5 秒后没有 `late`，没有 `floor.pass` 或 `floor.fail`，临时 worktree 已删掉
- 后台测试不是组长、和别的进程在同一个进程组，`after_green` 运行时只对它发 SIGTERM → `after_green` 的进程不在了，组里别的进程照常运行
- `after_green` 是 `trap "sleep 1; touch late; exit 1" TERM; while true; do sleep 0.1; done`，只对后台测试发 SIGTERM → 它退出时 `late` 已经存在，协调数据库里没有它的占位，没有 `floor.after_green`
- `after_green` 是 `trap "" TERM; while true; do sleep 0.1; done`（不理 SIGTERM），只对后台测试发 SIGTERM → 它在至少 10 秒后以 143 结束，日志有 `sent SIGKILL`，`after_green` 的进程已经不在
- 后台测试是组长，`after_green` 是 `trap "sleep 1; touch late; exit 1" TERM; while true; do sleep 0.1; done`，停进程那一步的两次读进程表都成功、等待中的第一次失败，只对后台测试发 SIGTERM → 它退出时 `late` 已经存在，日志里没有 `SIGKILL`，也没有 `may not all have been stopped`
- 后台测试是组长，`after_green` 是 `trap "" TERM; while true; do sleep 0.1; done`（不理 SIGTERM），停进程那一步的两次读进程表都成功、之后每次都失败，只对后台测试发 SIGTERM → 它在至少 15 秒后以 143 结束，日志有 `10 s after SIGTERM the process table cannot be read` 和 `cannot read the process table to send SIGKILL`
- 进程表里一直列着一个后台测试组里的进程（收不到信号，例如卡在内核里），只对后台测试发 SIGTERM → 日志有 `sent SIGKILL, and some of it is still running`，它以 143 结束，协调数据库里没有它的占位
- `after_green` 先启动一个调用 `setsid` 的进程，它 1 秒后写 `late`，只对后台测试发 SIGTERM → 它照常以 143 结束，`late` 照样写出来：这个进程不在它启动的进程之列
- 读不出进程表（`ps -axo pid=,ppid=,pgid=,stat=` 失败），只对后台测试发 SIGTERM → 日志有 `cannot read the process table`，它以 143 结束，`after_green` 的进程还在
- 第一次读进程表成功、第二次失败（已经对 `after_green` 的进程发了 SIGSTOP），后台测试不是组长，只对它发 SIGTERM → 它以 143 结束，日志有 `may not all have been stopped`，`after_green` 的进程收到 SIGTERM 和 SIGCONT 后结束
- 后台测试不是组长，`after_green` 是 `( (sleep 1; touch late) & ); while true; do sleep 0.1; done`，只对它发 SIGTERM → 它以 143 结束，`late` 照样写出来：父进程已退出的进程不在它启动的进程之列
- 后台测试是组长，`after_green` 是 `perl x.pl & wait`，`x.pl` 先调用 `setsid`、1 秒后写 `late`（它的父 shell 还在等它），只对后台测试发 SIGTERM → 1.5 秒后没有 `late`
