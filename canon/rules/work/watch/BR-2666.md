## 规则

后台测试（BR-2219）跑了 floor（或 `setup`）、以非 0 结束、而且没有按 BR-2534 记为不稳定测试时，canon 在 floor 结束那一刻读机器的 5 分钟负载。负载达到重步骤的负载上限 `L`（BR-2665：`heavy_max_load_per_cpu` × CPU 数，用主 checkout 读到的配置，和后台 floor 过负载关用的是同一个值；比较用没有取整的值，达到算）时，这次失败是**过载失败**：负载高到测试可能是被自己的时限杀掉的，失败说明不了 main 有问题（#317）。

过载失败按它是连续的第几次处理。连续指协调事件表里，往前数到最近一个 `floor.pass`、`floor.fail` 或 `floor.skip` 为止的 `floor.overload` 个数（不分提交）：

- **第 1、2 次**：记一条 `floor.overload` 事件（提交、日志、退出码、原因、负载（一位小数）、CPU 数、`L`、第几次），**不**记 `floor.fail`，**不**记“main 没通过”（BR-2220），所以不触发撤回（BR-2535、BR-2536），合入不因它暂停（BR-2644），`canon work due` 也没有 `red-main`。日志末尾和后台测试的输出都写一行 `floor watch: main <提交前 9 位> failed (<原因>) while the 5-minute load was <负载> on <CPU 数> CPUs (limit <L>): overload failure <n> of 3 in a row, not recorded as a failing main; tested again once the load falls (BR-2666)`。这个提交不算测过（BR-2219），同一个后台测试接着按 BR-2311 再测 main 的最新提交（main 没动就是同一个提交，动了就是包含它的更新的提交），重测照常先过负载关（BR-2630），所以要等负载降到 `L` 以下才开始。
- **第 3 次**：按普通失败处理：记 `floor.fail`（详情另含 `overload`：负载、CPU 数、`L`、第几次）、记“main 没通过”（BR-2220），之后照常撤回和暂停合入。原因写成 `<原来的原因> while the 5-minute load was <负载> on <CPU 数> CPUs (limit <L>), overload failure 3 of 3 in a row, so it counts as failing; the machine may be too loaded for this floor (BR-2666)`，写进 `floor.fail`、后台测试的输出和日志末尾（所以也出现在 `canon brief` 显示的输出尾部）。这样无论负载多高，一个真坏的 main 最多被重测两次就会被记下，不会一直重测下去。

以下情况不是过载失败，照 BR-2220 直接按失败处理：负载低于 `L`；读不到负载（三个平均值都是 0，或读取失败）；被测提交的 `canon/config.yaml` 读不了或没有 floor（什么也没跑）。

后台测试进程在过载失败之后被停下或被杀：`floor.overload` 已经记下，这个提交仍不算测过，下一个启动的后台测试照常重测，连续次数接着数。

依据：D-172。

## 例子

- 8 个 CPU，没写 `heavy_max_load_per_cpu`（`L` 16），floor 开始时负载 3.0，结束时 16.0，floor 退出码 1 → 记 `floor.overload`（`attempt` 1），没有 `floor.fail`，没有“main 没通过”，没有撤回；输出含 `overload failure 1 of 3 in a row`；接着重测同一个提交，等负载降到 15.9 才开始
- 同上，重测时负载 15.9、floor 仍以 1 结束 → 记 `floor.fail`、“main 没通过”，照常撤回
- 已经连续 2 次过载失败，第 3 次结束时负载 30.0 → 记 `floor.fail`，原因含 `overload failure 3 of 3 in a row, so it counts as failing`，详情的 `overload` 是 `{ load: 30, cpus: 8, limit: 16, attempt: 3 }`，main 记为没通过
- 事件依次是过载失败、`floor.pass`、过载失败，再一次过载失败 → 这一次是第 2 次，记 `floor.overload`
- floor 结束时负载 15.9 → 不是过载失败，按 BR-2220 记失败
- 读不到负载 → 按 BR-2220 记失败
- 4 个分片都以 142 被自己的时限杀掉，floor 结束时负载 28.0（`L` 16） → 第 1 次过载失败，所有合入照常进行
- 过载失败的 floor 带 `{report}` 并列出了失败的测试文件，重跑这些文件全部通过 → 按 BR-2534 记为不稳定测试、按通过处理，不看负载
