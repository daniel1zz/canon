## 规则

已发布的 canon：会话们在合入之后运行的那个 canon，就是 PATH 上的 `canon`。canon 自己的仓库里它是主 checkout 的 `dist/canon`，只由 `after_green` 从测过的提交发布（BR-2222、BR-2412），所以会比 main 旧；用 canon 的项目没有自己的发布，它是项目装的 canon，通常也就是运行这次合入的 canon。

被合入的那棵树里 `floor_timing` 是 `after` 时，`canon work land` 在 rebase 之后、`canon check` 之前，在变更的 worktree 里运行 PATH 上的 `canon config --schema`，取已发布的 canon 读配置时用的 JSON Schema（它不读配置，BR-2175），拿这棵树的 `canon/config.yaml` 去比：

- 有它不认识的键（顶层的键，或 schema 里列出了全部键的下一层，例如 `hooks` 下的 hook 名、`check_reviews` 下的检查名），或它会拒绝的值：合入以原因 `config` 被拒（退出码 1），main 不动；信息写明 PATH 上 canon 的路径，按 `<上一层>.<键>` 点名每个不认识的键、每个会被拒绝的值，并提示：等包含它们的 canon 发布之后（main 的后台测试通过，`after_green` 从通过的提交发布），再在另一次合入里写进 `canon/config.yaml`。理由：读到它不认识的键，已发布的 canon 所有命令都以退出码 2 失败（BR-2045）。
- 取不到 schema 时不猜、也不当成认识：PATH 上找不到 `canon`，它以非 0 退出（信息写明退出码和 stderr 的前 5 行），或者输出不是一个能用的 JSON Schema（不是 JSON 对象，或者不能按 draft-07 编译成校验器；不限制任何东西的 `{}` 算能用，它接受任何配置），合入同样以原因 `config` 被拒（退出码 1），信息写明是哪一种。这是对“合入后会话用的 canon 能不能读这份配置”的判定被拒，不是环境错误（退出码 4）：判定不了就不许合入。

schema 接受的配置 canon 不一定接受（BR-2175 列出的例外，比如脚本路径是否存在），这一步不比较这些。`floor_timing` 是 `before` 时不做这一步：先测再合时 main 只在测过之后前移，项目在 `after_land` 里马上重新构建。

## 例子

- `floor_timing: after`，`canon/config.yaml` 写着 `links_since: <完整编号>`，PATH 上的 canon 的 schema 里没有 `links_since` → 退出码 1，原因 `config`，信息里有它的路径、`links_since` 和 `wait for a release`，main 不动，`land.refuse` 带 `reason: "config"`
- 同样的配置，PATH 上的 canon 的 schema 里有 `links_since` → 照常合入
- `hooks:` 下写了 `after_merge`，schema 的 `hooks` 只列出 `after_land` 等 → 退出码 1，信息里有 `hooks.after_merge`
- `check_reviews:` 下写了 `passes`，schema 的检查名里没有它 → 退出码 1，信息里有 `check_reviews.passes`
- schema 认识 `land_batch_max`，只允许不小于 1 的整数，配置写 `land_batch_max: 0` → 退出码 1，信息点名 `land_batch_max`
- PATH 上的 `canon config --schema` 在 stderr 写 `boom` 并 `exit 2` → 退出码 1，原因 `config`，信息里有 `exited 2` 和 `boom`
- PATH 上的 `canon config --schema` 退出码 0 但什么也不输出 → 退出码 1，原因 `config`，信息里有 `not a JSON Schema`
- PATH 上的 `canon config --schema` 输出 `[]` → 退出码 1，原因 `config`，信息里有 `not a JSON Schema`；输出 `{}` → 这一步通过
- `floor_timing: after`，PATH 上没有 `canon` → 退出码 1，原因 `config`，信息里有 `canon is not on PATH`
- `floor_timing: before`，PATH 上的 `canon` 读配置时 `exit 2` → 不运行它，照常按 floor 的结果决定
