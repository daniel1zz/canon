id: BR-2224
title: after 模式下，PATH 上的 canon 读不了合入后的配置时拒绝合入
status: active
---

## 规则

被合入的那棵树里 `floor_timing` 是 `after` 时，`canon work land` 在 rebase 之后、`canon check` 之前，在变更的 worktree 里运行 PATH 上的 `canon config --schema`（输出丢弃），看会话们合入后用的那个 canon 能不能读这棵树的 `canon/config.yaml`。它以非 0 退出，或者 PATH 上找不到 `canon`，合入以原因 `config` 被拒（退出码 1），main 不动；信息写明 PATH 上 canon 的路径、它的退出码和 stderr 的前几行，并提示：新增的配置项先合入，等 main 的后台测试通过、PATH 上的 canon 从通过的提交重新构建（`after_green`，BR-2222）之后，再在另一次合入里启用它。`floor_timing` 是 `before` 时不做这一步，因为先测再合下 `after_land` 会马上重新构建。

## 例子

- `floor_timing: after`，PATH 上的 `canon` 是一个读配置时 `exit 2` 并在 stderr 写 `unknown key` 的程序 → 退出码 1，原因 `config`，信息里有它的路径、`exited 2` 和 `unknown key`，main 不动，`land.refuse` 带 `reason: "config"`
- `floor_timing: after`，PATH 上的 `canon` 读配置时 `exit 0` → 照常合入
- `floor_timing: after`，PATH 上没有 `canon` → 退出码 1，原因 `config`，信息里有 `canon is not on PATH`
- `floor_timing: before`，PATH 上的 `canon` 读配置时 `exit 2` → 不运行它，照常按 floor 的结果决定
