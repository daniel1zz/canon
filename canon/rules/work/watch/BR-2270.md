## 规则

后台测试在一个提交上通过、而且要运行 `hooks.after_green`（BR-2222）时，`floor.pass` 事件里记 `after_green: true`，表示它的 `after_green` 还欠着；`after_green` 的命令全部跑完（不管退出码）后记一条 `floor.after_green` 事件（带 `sha`，以及第一条失败的命令 `failed`，全部成功时为空），这个提交就不再欠。

`refs/canon/green` 指向的提交还欠着 `after_green`（运行它的进程在跑完前被杀掉，例如 OOM、重启、杀进程组）时：

- 合入或 `canon brief` 启动后台测试的条件（BR-2219）多一种：main 的最新提交已经测过，但这个提交还欠着，也启动一个，输出写明 `after_green for main <sha> did not finish`。
- `canon floor watch` 拿到后台测试的位置后，先在一个检出这个提交的临时 worktree 里运行它的 `setup`，再运行它的 `after_green`（环境和 BR-2222 一样），不重跑 floor，跑完同样记 `floor.after_green`（带 `rerun: true`）。`setup` 失败时不运行 `after_green`，也记 `floor.after_green`（带 `setup_exit`），这次就算结束，不会每次都重试。补跑的 `after_green` 每一条都以 0 结束时，照 BR-2251 交给 PATH 上的 canon；否则接着测 main 的最新提交（BR-2219）。补跑时又被杀掉，这个提交仍欠着，下一个后台测试再补跑。

后台测试被 SIGTERM 或 SIGINT 终止时，照 BR-2285 先停掉它启动的全部进程（`after_green` 的也在其中），等它们结束再退出；这次不记 `floor.after_green`，仍欠着。所以补跑时不会有上一次的 `after_green` 还在后台跑，两份不会同时写同一个文件（例如 PATH 上的 canon）。

只看 `refs/canon/green` 指向的那个提交：之后又有提交通过时，那次通过自己运行 `after_green`，前一个欠着的不再补。`floor.pass` 里没有 `after_green: true` 的提交（没配 `after_green`、`floor_timing` 不是 `after`、或者是这条规则之前记下的）从不算欠着。`floor.after_green` 不算 floor 的运行，不进 `canon stats`（BR-2067）。

## 例子

- A 通过，`after_green` 运行期间整个进程组被 SIGKILL 杀掉 → 有 A 的 `floor.pass`（`after_green: true`），没有 `floor.after_green`；之后 `canon brief` 输出 `after_green for main <A> did not finish` 并启动后台测试；它只补跑 A 的 `after_green`，floor 不再跑，记一条 `floor.after_green`（`sha` 是 A）；`after_green` 以 0 结束，照 BR-2251 记 `floor.handoff`
- 补跑完以后再运行 `canon brief` → 不再启动后台测试
- A 通过，`after_green` 以 1 结束 → 记 `floor.after_green`（`failed` 是这条命令）；之后的 `canon brief` 不再为它启动后台测试
- 没配 `after_green` 的项目里 A 通过 → `floor.pass` 里没有 `after_green`，从不补跑
- A 的 `floor.pass` 欠着 `after_green`，但 `refs/canon/green` 已经是 B、B 的 `after_green` 跑完了 → `canon brief` 不启动后台测试，A 的不补跑
- 补跑时 `setup` 以 1 结束 → 不运行 `after_green`，记 `floor.after_green`（`setup_exit` 为 1），没有 `floor.handoff`，之后不再补跑；同一个进程接着照 BR-2219 看 main 的最新提交：它已经测过，floor 不再跑，这个进程交出位置结束
- `after_green` 运行时只对后台测试的进程发 SIGTERM → 它以 143 结束，`after_green` 的进程也不在了（BR-2285），没有 `floor.after_green`，仍欠着
