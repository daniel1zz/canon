## 规则

后台测试通过时：`refs/canon/green` 用比较并交换移到这个提交；“main 没通过”的记录删除；然后在测试用的临时 worktree 里（检出的正是这个提交）运行 `hooks.after_green` 的命令，环境里有 `CANON_GREEN`（这个提交）和 `CANON_PRIMARY`（主 checkout 的路径），像 `after_land` 一样每条命令写一条事件、记下退出码（BR-2059、BR-2137），全部结束后再删临时 worktree。`after_green` 失败不改变测试结果。用来放只应该来自测过代码的步骤，比如重新构建 PATH 上的程序：`after` 模式下 `after_land` 运行在没测过的 main 上。`floor_timing` 为 `before` 时不运行 `after_green`。

## 例子

- 在 A 上通过，之前有失败记录 → `refs/canon/green` 是 A，记录没了，`canon brief` 不再出现 main 没通过的段落
- `hooks.after_green: ["echo $CANON_GREEN > green.txt"]` → 临时 worktree 里写出 A，事件表有这条命令的退出码
- `after_green` 命令以 1 退出 → `floor.pass` 照常，`refs/canon/green` 照常移到 A
- 在 C 上失败 → `refs/canon/green` 不动，`after_green` 不运行
