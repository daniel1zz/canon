## 规则

`canon floor watch` 对 main 的最新提交，和最近一个测过的提交（有 `floor.pass`、`floor.fail` 或 `floor.skip`）相比，改动的路径全都在 `floor_skip_paths` 之下、且没有测试文件时（`floorSkip`，BR-2164），不跑 floor，不建临时 worktree：记一条 `floor.skip` 事件（`sha`、`base`、`paths`、`under`），日志写 “marked tested without a run”；这个提交从此算测过，进程不等阈值，直接记。`floor.skip` 不移动 `refs/canon/green`，不清 “main 没通过” 的记录，不运行 `after_green`，也不进 `canon stats`（只算 `floor.pass`、`floor.fail`，BR-2067）。没有最近测过的提交时照常测。

## 例子

- 基线已测，之后合入只改了 `canon/rules/x/BR-1.md` → 不跑 floor，没有临时 worktree，一条 `floor.skip`（`under` 是 `canon/rules`），进程以 0 结束
- 之后合入两个：先改 `canon/rules/x/BR-1.md`，再加 `src/y.ts` → 相比基线有 `src` 下的文件，没有 `floor.skip`；到点（BR-2311）时测最新提交
