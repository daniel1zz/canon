## 规则

main 没通过、还没人修（BR-2598）时，主会话运行的 `canon work test` 在开始跑测试之前先输出 BR-2598 的提示（标准错误，一段），不等它也不拒绝；跑完之后，失败的文件里凡是也列在这条记录里（BR-2599）的，单独列成一行 `failing on main too: <文件>…`，说明它们是 main 的失败，不是这个变更造成的，再重复一次 BR-2598 的提示。退出码不因此改变（D-155）。记录里没有文件时，跑完只重复提示，不列文件。worker 的 `canon work test` 按 BR-2598 给 worker 的写法提示。已经有修复变更时两处都只写一行正在哪个变更里修。

## 例子

- main 没通过、记录里有 `a.test.ts`，没人修；主会话的 `canon work test` 失败了 `a.test.ts` 和 `b.test.ts` → 开跑前有提示；跑完有 `failing on main too: a.test.ts`，再次提示；退出码 1
- 同样的情况，测试全部通过 → 开跑前有提示，跑完再提示一次，退出码 0
- 记录里没有文件（floor 不带 `{report}`）→ 跑完只重复提示
- 已有修复变更 `C-9` → 开跑前和跑完各一行 `being fixed in C-9`
- main 通过 → 没有这些输出
