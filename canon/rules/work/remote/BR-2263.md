status: active

## 规则

`canon sync` 取到远端的 main 后，两边都有对方没有的提交（谁也不是谁的祖先）时，不合并、不 rebase、不移动 main、不改任何 worktree 的文件，以退出码 5 结束，写一条 `sync.refuse` 事件（原因 `diverged`，带本地和远端的提交），输出两边各领先几个提交，并说明怎样合并由人决定。

## 例子

- 本地 main 有提交 L，裸仓库的 main 有提交 R，两者的共同祖先是 B → 退出码 5，本地 main 还是 L，没有合并提交，`sync.refuse` 的原因 `diverged`，输出有 `1` 和 `diverged`
- 本地 main 是 R 的祖先 → 不属于这条，照 BR-2262 快进
