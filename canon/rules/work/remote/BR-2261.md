title: canon brief 提示 main 上有多少提交没推到远端
status: active
---

## 规则

main 上已提交的 `canon/config.yaml` 写了 `remote`、当前 worktree 没有认领变更时，`canon brief` 只在本地（不联网）数出没推上去的提交：`git rev-list --count refs/remotes/<远端>/<main>..<main>`，本机还没有 `refs/remotes/<远端>/<main>` 时数 main 上全部的提交。数目大于 0 时输出一行 `<N> commit(s) on <main> not pushed to <远端>`，写明下次合入会推、`canon sync` 能拉取远端；事件表里最近的一条推送事件是 `push.fail` 时，同一行带上它的原因的第一行。数目是 0、没写 `remote`、或者在认领了变更的 worktree 里时，不输出这一行。

## 例子

- `remote: origin`，`refs/remotes/origin/main` 落后本地 main 3 个提交，在主 checkout 里 `canon brief` → 输出有 `3 commit(s) on main not pushed to origin`
- 同上，最近一条推送事件是 `push.fail`，原因第一行是 `! [rejected] main (fetch first)` → 那一行里也有 `[rejected]`
- 同上，最近一条推送事件是 `push.ok`（后来又有本地提交没推）→ 有数目，没有失败原因
- 本地 main 和 `refs/remotes/origin/main` 相同 → 没有这一行
- 没写 `remote` → 没有这一行
- 在认领了 `C-1` 的 worktree 里 `canon brief` → 没有这一行
- 本机没有 `refs/remotes/origin/main`，main 上有 5 个提交 → `5 commit(s) on main not pushed to origin`
