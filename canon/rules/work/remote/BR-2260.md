## 规则

BR-2259 的推送没推上去时（git 以非 0 退出而远端的 main 不包含要推的提交，包括远端有本地没有的提交、远端名字不存在、连不上；超过 `remote_timeout_seconds` 被终止），合入的结果不变：main 照样已经移动，`canon work land` 的退出码和不推送时一样，`--finish` 照样关闭变更。canon 写一条 `push.fail` 事件（`remote`、`sha`、`reason`：git 输出的前 10 行，超时写明等了几秒），在输出里写一行 `push to <远端> failed: <原因>`，并说明这些提交会在下次合入时再推。canon 不重试、不强推、不合并。推送和它被拒后取远端的 main 合起来最多等 `remote_timeout_seconds` 秒：推送已经用掉的时间从取远端的时间里扣，用完就不再取（按推送失败记），所以远端挂住时合入者最多多等这一个时间，不是两倍。

## 例子

- `remote: origin`，裸仓库的 main 上有一个本地没有的提交 X，合入 `C-1` → 退出码 0，main 已移动，裸仓库的 main 还是 X，事件表有 `push.fail`，`reason` 里有 `rejected`，输出有 `push to origin failed`
- `remote: nowhere`（没有这个远端）→ 退出码 0，main 已移动，`push.fail` 的 `reason` 里有 git 的报错
- `remote_timeout_seconds: 1`，主 checkout 有一个睡 30 秒的 `pre-push` hook → 大约 1 秒后推送被终止，退出码 0，`push.fail` 的 `reason` 写明等了 1 秒
- `remote_timeout_seconds: 3`，推送在 2 秒后失败（`pre-push` hook 睡 2 秒后退出 1），之后的取远端会一直挂住 → 推送和取远端合起来大约 3 秒就结束（不是 5 秒），记一条 `push.fail`，远端的 main 不变
- 推送失败后 `canon work land --finish` 的变更 → 照样是 `done`，认领照样放开
