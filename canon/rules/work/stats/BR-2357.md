---
id: BR-2357
title: canon events --follow 每秒查一次，持续输出新事件，收到 SIGTERM 以 0 退出
status: active
---

## 规则

`canon events --follow` 先输出编号大于起点的、符合条件的已有事件，然后一直运行：每秒按事件编号查一次协调数据库（`id` 大于上次已查到的最大编号），每出现一条符合条件的新事件就输出一行并立即刷新输出，按编号从小到大。

- 起点：不加 `--since` 时是命令启动时最新事件的编号，不重放历史；加了 `--since <n>` 时是 `n`（先输出 `n` 之后已有的事件）。
- `--kind`、`--subject`、`--since` 的含义和格式照 BR-2156；`--follow` 只读数据库，不写事件。
- 文字输出的每行和 BR-2156 的一样；没有符合条件的事件时什么也不输出（不输出 `(no events)`）。
- 加 `--json` 时每行是一个 JSON 对象（JSON Lines，不是数组），字段同 BR-2156，一行里不换行。
- 收到 SIGTERM 或 SIGINT 以退出码 0 结束；协调数据库打不开时和不加 `--follow` 时一样退出。
- 不加 `--follow` 时行为不变（BR-2156）。

不用监听数据库文件（WAL）：各平台的文件监听表现不一致，合并写入时会漏通知；每秒一次按主键的查询开销可以忽略。

## 例子

- 启动时最新事件是 #5，之后出现 `handoff.write` → 输出一行 `#6 ... handoff.write ...`，#5 及以前的不输出
- `--since 3`，已有 #4、#5 → 启动后立即输出 #4、#5，之后的新事件接着输出
- `--kind land.ok --follow`，之后依次出现 `land.refuse`、`land.ok` → 只输出 `land.ok` 那一行
- `--json --follow` → 每行是一个对象，能单独 `JSON.parse`，不是数组的一部分
- 运行中收到 SIGTERM → 退出码 0
- 没有任何新事件 → 一直不输出，也不输出 `(no events)`
