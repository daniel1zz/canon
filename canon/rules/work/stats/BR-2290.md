## 规则

`canon verdict run --limit <n>` 依次处理最早的 `n` 个这样的拦截：可以判定（BR-2253），找得到拦截时的提交，并且至少有一条意见还没有 `model` 的判定。每个拦截运行一次判定命令，判定命令就是项目配置的 `review` 命令（D-49）。运行前把拦截时的提交用 `git archive` 导出到一个新建的临时目录，目录里没有 `.git`；判定命令在这个目录里运行，命令开头是相对路径、并且这个路径在当前 worktree 里是一个文件时，换成当前 worktree 里的绝对路径；运行完删掉临时目录。提示从 stdin 给出，里面只有变更编号、拦截时的提交相对 `base`（BR-2253）改了哪些文件、和按编号列出的每条意见，不给合入的提交、修复和之后的历史。判定命令在 stdout 输出 JSON `{"verdicts":[{"finding":<意见编号>,"verdict":"real"|"spurious"|"unclear","reason":"<理由>"}]}`，每条意见恰好一项、理由不为空。canon 对每条还没有 `model` 判定的意见写一条 `review.verdict`（字段同 BR-2254），`judge` 是 `model`，另加 `command`（配置里的命令原文）；同一个拦截的这些写入和查重在一个写事务里，别的运行已经写了的意见跳过。每处理完一个拦截输出一行 `#<拦截事件编号> <变更编号>: real <n>, spurious <n>, unclear <n> (prompt <提示字符数> characters)`，最后一行是 `judged <k> block(s), <m> finding(s); <s> block(s) without a blocked commit skipped; prompts <合计字符数> characters`，`s` 是可以判定、还缺 `model` 判定、但拦截时的提交是 `?` 的拦截数。加 `--dry-run` 时不导出、不运行命令、不写事件，每个拦截输出 `#<拦截事件编号> <变更编号>: <意见条数> finding(s), prompt <提示字符数> characters`，最后一行以 `would judge` 开头，其余同上。`--limit` 没给或不是正整数 → 退出码 2；没有配置 `review` → 退出码 4，什么都不写。判定命令退出码不是 0、输出里没有 JSON、或者 JSON 不符合上面的格式（缺一条意见、多出编号、结论不是这三个之一、理由为空）→ 这个拦截什么都不写，不再处理后面的拦截，退出码 4，信息写明拦截事件编号和原因；之前已经写下的判定保留。

## 例子

- 两个可以判定的拦截（事件 10 有 2 条意见，事件 20 有 1 条），`--limit 1` → 只运行一次判定命令，判事件 10，写 2 条 `judge: model` 的 `review.verdict`；最后一行 `judged 1 block(s), 2 finding(s); 0 block(s) without a blocked commit skipped; prompts <n> characters`
- 判定命令运行时：工作目录里有拦截时提交里的文件，没有 `.git`，没有修复提交才加的文件；提示里有两条意见原文，没有合入的提交
- 配置是 `review: scripts/judge.sh`，当前 worktree 里有 `scripts/judge.sh` → 运行当前 worktree 里的那个脚本，不是导出目录里的
- 事件 10 的第 1 条意见已经有 `model` 的判定 → 再运行时只写第 2 条；两条都有了 → 不再判事件 10
- 事件 30 可以判定但拦截时的提交是 `?` → 不运行命令，最后一行的 `s` 是 1
- 判定命令输出的 `verdicts` 只有第 1 条 → 退出码 4，事件 10 什么都不写，事件 20 不判
- 判定命令以 1 退出 → 退出码 4，什么都不写
- `--dry-run --limit 5` → 不运行命令，事件表不变，最后一行以 `would judge 2 block(s), 3 finding(s)` 开头
- 没有 `--limit`、`--limit 0`、`--limit x` → 退出码 2
- 项目没有配置 `review` → 退出码 4
- 运行之后临时目录不在了
