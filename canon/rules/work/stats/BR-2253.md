title: canon verdict pending 按拦截列出每条评审意见、它已有的判定和拦截时的提交
status: active

## 规则

`canon verdict pending` 列出可以判定的评审拦截，按 `review.block` 事件编号从小到大。一条 `review.block` 可以判定，当它记了变更编号、它有意见（`detail.findings` 不为空），它之后有同一变更、原因为 `review` 的 `land.refuse`（取第一条，就是这次拦截的拒绝），这条拒绝之后这个变更合入成功过（有 `land.ok`），并且它至少有一条意见还缺 `model` 或 `human` 的判定（BR-2254、BR-2290）。不按执行者过滤（D-49）。每次拦截写一行 `#<拦截事件编号> <变更编号> <拒绝日期 YYYY-MM-DD，取事件时间的 UTC 日期>  blocked commit <拦截时的提交>`，下面每条意见一行 `  <意见编号>. model <结论或 -> · human <结论或 -> · <意见原文>`，意见从 1 编号，结论是已有判定的 `real`、`spurious` 或 `unclear`，没有判定写 `-`；两次拦截之间空一行。拦截时的提交是拒绝之后第一条 `land.ok` 的 `base..sha` 之间（`land.ok` 没有记 `base` 时用它之前最近一条 `land.ok` 的 `sha`：这些合入都在 `canon sync` 出现之前，main 只靠合入前移）、从 `base` 到它、`canon/changes` 以外的零上下文 diff 的 `git patch-id` 等于拒绝时改动指纹（BR-2068）的最早一个提交；拒绝没有指纹、`land.ok` 没有 `sha`、找不到 `base`、或者没有一个提交对得上时写 `?`。不写合入的提交：判定的是拦截时有没有问题，不看作者后来怎么改。没有可列的写 `(nothing to judge)`。加 `--json` 时输出数组，每项字段为 `block`、`refusal`、`subject`、`ts`、`before`（找不到时为 null）和 `findings`，`findings` 每项字段为 `n`、`text`、`model`、`human`（没有判定时为 null）。

## 例子

- `C-1` 的 `review.block`（事件 10，两条意见）之后是 `land.refuse`（事件 11，原因 `review`，指纹等于提交 `X` 相对 `base` 的指纹），之后又提交 `Y` 并合入 → 列出 `#10 C-1 2026-11-04  blocked commit X`，下面两行 `  1. model - · human - · <第一条意见>` 和 `  2. model - · human - · <第二条意见>`；输出里没有 `Y`
- 第 1 条意见有 `model` 的 `real`，第 2 条有 `human` 的 `spurious` → 两行分别是 `  1. model real · human - · ...` 和 `  2. model - · human spurious · ...`
- 两条意见都已有 `model` 和 `human` 的判定 → 不列
- `C-2` 被评审拦下后还没合入成功 → 不列
- `C-3` 被 `floor` 拦下后合入成功，没有 `review.block` → 不列
- 一条原因为 `review` 的拒绝之前没有 `review.block`（评审没能运行）→ 不列
- `agent:a` 是 `C-1` 的作者，`agent:a` 执行 → 照样列出
- 拒绝没有记改动指纹（指纹加入之前）→ 照样列出，拦截时的提交写 `?`
- `C-4` 的 `land.ok` 没有 `base`，它之前的一条 `land.ok` 的 `sha` 是 `M`，拦截时的指纹等于 `M` 到提交 `Z` 的指纹 → 拦截时的提交是 `Z`
- 没有任何评审拦截 → 输出 `(nothing to judge)`
