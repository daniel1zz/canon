## 规则

可用清单是窗口内各个会话最后注入的内容的并集。窗口是运行时刻往前 N 天（`--days N`，正整数，默认 30，否则退出码 2）。只看本项目子目录里直接放着的会话文件（不含 `subagents` 下的子 agent 记录），文件里有任何一条带 `attachment` 的记录的 `timestamp` 在窗口内的才算；每个这样的文件从第一行起按顺序叠加，得到这个会话最后的状态：`attachment.type` 为 `skill_listing` 的记录，`isInitial` 为 true 时替换全部 skill，否则加入或替换它列出的 skill；`agent_listing_delta`，`isInitial` 为 true 时先清空，再加入 `addedTypes`（每个的描述是 `addedLines` 里以 `- <类型>:` 开头的那行），去掉 `removedTypes`；`mcp_instructions_delta` 加入 `addedNames`（说明是对应的 `addedBlocks`），去掉 `removedNames`；`deferred_tools_delta` 里以 `mcp__` 开头的 `addedNames` 加入它的服务和工具名，`removedNames` 去掉工具名，一个工具名都不剩、也没有说明的服务在这个会话里不可用。MCP 说明里的服务名按把字母、数字、`_`、`-` 以外的字符换成 `_` 后和工具名里的服务对应（`claude.ai Linear` 对应 `claude_ai_Linear`）。注入量是字符数：skill 是清单里它那一项的文字（从 `- <名字>:` 到下一项之前），子 agent 类型是它那行描述，MCP 服务是它的说明加上它每个工具名各一行；一个项在几个会话里都有时，注入量取最后一个会话（按文件里最后一条带 `attachment` 的记录的 `timestamp`）里的。可用、且在窗口内没有用过（BR-2265）的项列在 `unused for N days` 下，写出种类、范围（`scope`）、名字、注入量、最近一次使用时间（没用过写 `never`）和最后注入它的会话的时间（这个会话最后一条带 `attachment` 的记录的 `timestamp`），后者让人看出一项是不是已经从配置里去掉了，注入量大的在前，相同按名字排，`scope` 是 `project` 当且仅当本项目自己的文件定义了这一项：skill 是主 checkout 的 `.claude/skills/<名字>` 存在，子 agent 类型是 `.claude/agents/<名字>.md` 存在，MCP 服务是 `.mcp.json` 的 `mcpServers` 里有它（名字按上面的规则换字符后比较）；其余都是 `other`（用户、插件、账号连接器或内置，canon 分不清，也不去读用户配置）。`--json` 的每个未用项多一个 `scope` 字段。合计行是它们的个数和注入量合计，之后固定再写一行 `scope other = user, plugin, account or built-in: judged on this project's sessions only, so other projects may use it and a built-in one cannot be removed`。窗口内没有一个会话文件有 skill 清单时写明 `no listing of available skills found`，不列没用过的项。只报告，不改任何配置。

## 例子

- 窗口内唯一的会话注入了 `a`、`b` 两个 skill，`a` 昨天用过，`--days 30` → 只列 `b`，最近一次 `never`
- `b` 40 天前用过一次，`--days 30` → 列出 `b`，写出那次的时间；`--days 60` → 不列
- 会话 1（两天前）注入了 MCP 服务 `serena`，会话 2（今天）在 `serena` 连上之前就结束了 → `serena` 可用
- 50 天前的会话注入了 `old`，窗口内的会话都没有 → `old` 不可用，不列
- 10 天前的会话注入了 `x`，之后的会话都没有，`--days 30` → 列出 `x`，最后注入时间是 10 天前那个会话的时间
- 一个会话里完整清单之后又有一条 `skill_listing`（不是完整清单）加了 `c` → `c` 可用
- `mcp_instructions_delta` 加了 `serena`（说明 120 个字符），`deferred_tools_delta` 加了 `mcp__serena__a` 和 `mcp__serena__bb` → `serena` 注入量 120 + 15 + 16 = 151
- 同一个会话之后 `mcp_instructions_delta` 的 `removedNames` 有 `serena`，`deferred_tools_delta` 的 `removedNames` 有它的两个工具名 → 这个会话里 `serena` 不可用
- `agent_listing_delta` 写在完整 skill 清单之前 → 照样算进这个会话的子 agent 类型
- 子 agent 的记录（`subagents/agent-x.jsonl`）里有清单 → 不用它
- 未用的 skill `mine` 在主 checkout 的 `.claude/skills/mine` 存在、`global` 不存在 → `mine` 的 `scope` 是 `project`，`global` 是 `other`；输出末尾有 `scope other` 那一行
- `.mcp.json` 里有 `my.srv`，它注入了且没用过 → `scope` 是 `project`；账号连接器 `claude.ai Vercel` 不在里面 → `other`
- `--days 0` 或 `--days x` → 退出码 2
- 窗口内没有一份 skill 清单 → 输出 `no listing of available skills found`
