## 规则

`canon stats` 的文字输出里有一节 `Execution`，放在按模型的合入（BR-2532）之后；`--json` 的字段不变（BR-2202），这一节只在文字输出里。它看第一次合入（`land.ok`）落在统计范围里的变更（带 `--since` 时是这之后的事件，否则是全部），每个变更只算一次，分三组：

- `main session itself`：第一次合入之前没有派发事件（`delegation.create` 或 `delegation.update`）；
- `delegated, worker landed`：有派发，第一次合入的执行者是 worker（`agent:<会话>:<名字>`）；
- `delegated, main session landed`：有派发，第一次合入的执行者不是 worker（交回或收回之后由主会话合入）。

每组一行，写：变更数；从开工（自己做的，第一次 `start.ok`）或派发（派出去的，第一次派发事件）到第一次合入的整分钟数的中位数；第一次合入之前 `land.refuse` 的平均次数（一位小数）；第一次合入之前 `canon work test`（`work.test` 事件）次数的中位数；这次合入改动的行数（增加加删除，不算 `canon/` 下的文件）的中位数。中位数在偶数个时取中间两个的平均再四舍五入。没有开工也没有派发事件的变更不算。一组没有变更时变更数写 0，其余写 `-`，这一行不省略；范围里没有一个算得上的变更时整节不输出。

## 例子

- 范围里 3 个自己做的、2 个 worker 合入的、1 个交回后主会话合入的 → `Execution` 下三行，变更数 3、2、1
- 范围里没有派出去的 → 后两行写 `0 change(s)` 和 `-`
- 一个变更在范围前合入过一次、范围里又合入 → 不算
- 自己做的变更开工 10:00、被拒一次、跑了 2 次 `canon work test`、10:42 合入、改了 120 行代码和一个 `canon/` 下的文件 → 这一行是 1 个、42m、1 次被拒、2 次测试、120 行
- 范围里没有合入 → 没有 `Execution` 这一节
