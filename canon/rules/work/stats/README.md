# 检查统计（work/stats）

`canon stats` 从事件表算出每个检查运行了多少次、拒绝了多少次、拒绝之后发生了什么，用来判断一个检查值不值得留（P6）；`canon check` 的拒绝按发现种类拆开。`canon stats --since <事件编号>` 只看某个编号之后的事件，并给出这段时间的并发摘要；`canon events` 列出原始事件。两者用来核对一次并发运行，不靠 agent 自己报的数字。`canon usage` 读本项目的 Claude Code 会话记录（只读），统计 skill、MCP 服务、子 agent 类型用了几次，列出注入了却很久没用的项和它们的注入量，供人决定去掉什么（D-40）。评审拦截之后作者一定会改文字，指纹说明不了拦得对不对，所以另由没参与的执行者判定：`canon verdict pending` 列出待判定的评审拦截，`canon verdict record` 记下判定，`canon stats` 按判定者分开报告（D-35）。

## 术语

- **去向**：一次拒绝之后的结果：改了再合入、原样合入、放弃、还没结果、无法判断。
- **复审日期**：每个检查需要重新判断是否保留的日期。
- **判定**：没参与这个变更的执行者对一次评审拦截的结论，`real`（真问题）或 `wording`（改字过关），按判定者是 `agent` 还是 `human` 分开记。
- **注入量**：一项（skill、MCP 服务、子 agent 类型）在每个会话里占的上下文，按会话记录里实际注入的字符数算。
- **事件窗口**：编号大于某个事件编号的全部事件，`--since` 指定。
