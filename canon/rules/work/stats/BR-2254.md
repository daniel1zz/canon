## 规则

`canon verdict record <拦截事件编号> <意见编号> <real|spurious|unclear> --reason "<理由>"` 在事件表里写一条 `review.verdict`，主题是那次拦截的变更编号，详情有 `block`（拦截事件编号）、`refusal`（这次拦截的 `land.refuse` 编号，BR-2253；没有时为 null）、`finding`（意见编号）、`verdict`、`judge`、`reason`、`before`（拦截事件记的评审看到的提交，BR-2253；拦截事件没有记时为 null）。`real` 表示这条意见说的问题在拦截时的代码里确实存在，`spurious` 表示不存在，`unclear` 表示从拦截时的代码判断不了。`judge` 一律是 `human`：这是自报的判定，canon 只知道它不是在 Claude Code 会话里记的，不在 Claude Code 里跑的 agent 也会记成 `human`（BR-2023、D-49）。以下情况什么都不写，按这个顺序检查，先成立的决定退出码：判定不是这三个之一、`--reason` 没给或去掉首尾空白后为空、意见编号不是正整数、拦截事件编号不是整数 → 退出码 2；拦截事件编号不是一条记了变更编号的 `review.block`，或者意见编号大于它的意见条数 → 退出码 3；执行者以 `agent:` 开头 → 退出码 1，信息写明 agent 的判定不手工记；这条意见已经有 `human` 的判定 → 退出码 5。查重和写入在同一个写事务里，两个人同时判定同一条意见时只有一个写进去。

## 例子

- `human:alice` 执行 `canon verdict record 10 2 real --reason "BR-2244 正文确实混进了残片"`，事件 10 是 `C-182` 的 `review.block`，有 3 条意见 → 写一条 `review.verdict`，主题 `C-182`，`block` 10、`finding` 2、`judge` 是 `human`
- 同一条意见已有 `model` 的判定，`human:alice` 再记 → 照样写进去
- 同一条意见 `human:bob` 再记一次 → 退出码 5，什么都不写
- 同一次拦截的第 3 条意见，`human:bob` 记 → 写进去
- `agent:b` 执行 → 退出码 1，什么都不写
- 意见编号是 4（只有 3 条），或者拦截事件编号是一条 `land.refuse`，或者根本不存在 → 退出码 3
- 判定写成 `wording`、意见编号写成 `0` 或 `x`、拦截事件编号写成 `x`、`--reason "  "` → 退出码 2
- 判定写成 `maybe`，拦截事件编号也不存在 → 退出码 2
- `agent:b` 记一条不存在的拦截 → 退出码 3
