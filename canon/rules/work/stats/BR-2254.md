---
id: BR-2254
title: canon verdict record 记下一次评审拦截拦得对不对，判定者不能是这个变更的作者
status: active
---

## 规则

`canon verdict record <拒绝事件编号> <real|wording> --reason "<理由>"` 在事件表里写一条 `review.verdict`，主题是那次拒绝的变更编号，详情有 `refusal`（拒绝事件编号）、`verdict`、`judge`、`reason`。`real` 表示评审指出的是拦截时代码里的真问题，`wording` 表示拦截时没有真问题、作者只是改了文字让评审放行。`judge` 由执行者决定，不由参数给出：`agent:` 开头的是 `agent`，其他是 `human`（BR-2023）。以下情况什么都不写，按这个顺序检查，先成立的决定退出码：判定不是 `real` 或 `wording`、`--reason` 没给或去掉首尾空白后为空 → 退出码 2；编号不是一条原因为 `review` 的 `land.refuse`，或者那条拒绝没有记变更编号 → 退出码 3；执行者是这个变更的作者，即事件表里以这个变更编号为主题、种类不是 `review.verdict` 的事件里出现过这个执行者（判定过同一变更另一次拦截不算作者） → 退出码 1；这次拒绝已经有同一种判定者（`agent` 或 `human`）写的判定 → 退出码 5。查重和写入在同一个写事务里，两个执行者同时判定同一次拦截时只有一个写进去。

## 例子

- `agent:b` 执行 `canon verdict record 3057 real --reason "BR-2244 正文确实混进了残片"`，拒绝 3057 是 `C-182` 的评审拦截，`agent:b` 没在 `C-182` 上写过事件 → 写一条 `review.verdict`，主题 `C-182`，`judge` 是 `agent`
- 同一次拦截，之后 `human:alice` 判定 `wording` → 也写进去，`judge` 是 `human`
- 同一次拦截，`agent:c` 再判定一次 → 退出码 5，什么都不写
- `agent:a` 认领过 `C-182`，执行判定 → 退出码 1，什么都不写
- 编号是一条 `floor` 拒绝，或者根本不存在 → 退出码 3
- 判定写成 `maybe`，或者 `--reason "  "` → 退出码 2
- 判定写成 `maybe`，编号也不存在 → 退出码 2
- `agent:a` 是 `C-182` 的作者，而这次拦截已经有 `agent` 的判定 → 退出码 1
- `agent:b` 判定过 `C-182` 的第一次评审拦截，再判定它的第二次拦截 → 写进去，不算作者
