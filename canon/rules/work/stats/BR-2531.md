## 规则

`canon work model --hook [--runtime claude|codex]`（不传 `--runtime` 时按 BR-2023 的宿主识别，识别不出时当作 claude）从标准输入读宿主 hook 的 JSON，记下这个会话现在用的模型（D-137）：

- 模型取自：Claude Code 的 `SessionStart` 输入的 `model`，`PostModelSwitch` 输入的 `to_model`；Codex 任何 hook 输入的 `model`。该字段缺少、不是字符串或去掉两侧空白后为空时，模型记为未知，原因写 `<hook_event_name> input had no model`。
- 会话取自输入的 `session_id`，执行者按 BR-2023 的格式：Claude Code 是 `agent:` 加它的前 8 个字符；Codex 是 `agent:codex-<session_id>`，输入带非空的 `agent_id` 时再加 `:<agent_id>`。
- 记一条 `session.model` 事件，执行者和主题都是这个会话的执行者，详情是 `host`（`claude-code` 或 `codex`）、`model`（字符串，未知时为 null）、`via`（输入的 `hook_event_name`），未知时还有 `reason`。这个执行者最近一条 `session.model` 的 `host` 和 `model` 都相同时不再记，所以每轮都调用的 hook 不会让事件变多。
- 成功时什么也不输出，退出码 0，会话开始时的上下文里不多出任何文字。输入不是 JSON 对象、`session_id` 缺少或为空、`hook_event_name` 不是字符串、Codex 的 `agent_id` 含字母、数字、`-`、`_` 以外的字符时退出码 2，什么也不写；协调数据库写不了时退出码 4。

Codex 的启动 hook（`canon brief --hook --runtime codex`，BR-2023）读到的同一份输入也按本条记下模型，Codex 不另装开始时的这条 hook。之前的事件没有模型，不补写。

## 例子

- Claude Code 的 SessionStart 输入 `{"session_id":"3b9f74d5-5bc9-…","hook_event_name":"SessionStart","model":"claude-opus-5-5"}` → 记 `session.model`，执行者 `agent:3b9f74d5`，详情 `{"host":"claude-code","model":"claude-opus-5-5","via":"SessionStart"}`，没有输出
- 同一会话 `/model` 切到 Sonnet，PostModelSwitch 输入 `"to_model":"claude-sonnet-5-5"` → 再记一条，`model` 是 `claude-sonnet-5-5`，`via` 是 `PostModelSwitch`
- SessionStart 输入没有 `model` → 记 `{"host":"claude-code","model":null,"via":"SessionStart","reason":"SessionStart input had no model"}`
- Codex 的 Stop 输入 `"model":"gpt-6.1"`，这个会话最近一条已经是 codex、gpt-6.1 → 不记新事件
- Codex 子线程的 SubagentStart 输入带 `"agent_id":"child-1"` → 执行者 `agent:codex-<session_id>:child-1`
- 输入是 `not json` 或没有 `session_id` → 退出码 2，事件表不变
