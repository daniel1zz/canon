## 规则

加了 `--since <n>` 时，`canon stats` 在检查统计前面多输出一段摘要，只看编号大于 `n` 的事件：

- 事件条数，第一条和最后一条的时间；
- 合入：成功次数（`land.ok`），被拒次数和按原因分的次数（`land.refuse` 的 `reason`，多的在前），丢失次数（`land.lost`），被信号终止次数（`land.killed`）；
- 排队等待：轮到合入的次数（`land.turn`），等待时间的中位数和最大值（偶数个时中位数取中间两个的平均）；没有轮到的合入时两者都是空；
- 冲突：原因为 `conflict` 的拒绝次数，其中排队时提前发现的（`early`）有几次；回到保留位置重新合入的次数（带 `kept_place` 的 `queue.enter`，BR-2177），以及从被拒到重新排队时间（`resolve_ms`）的中位数，没有时为空；
- 停止等待：被信号终止（`land.killed`）、超时（原因 `timeout`）或被别的合入者标为放弃（`queue.abandon`，BR-2380）的次数，以及回到保留位置重新合入的次数（`queue.enter` 带 `kept_place` 且 `kept_after` 是 `killed`、`timeout` 或 `abandoned`，BR-2368、BR-2380）和 `resolve_ms` 的中位数，没有时为空；上一行冲突的回到保留位置只数 `kept_after` 是 `conflict` 或没有这个字段的；
- 同文件提示（`overlap.notice`）和认领被拒（`claim.refuse`）的次数；认领被主会话接手（`claim.handover`，BR-2336）的次数；hook 跳过检查（`hook.skip`）的次数；
- 出现过的不同执行者和不同 worktree，各自列出并计数：带 `--as` 的子 agent 各是一个执行者（`agent:<会话>:<agent_id>`），主会话是 `agent:<会话>`，另算一个，所以同一次派发里执行者数是子 agent 数加主会话；没有记下 worktree 的旧事件（BR-2131 之前写的）不算一个 worktree。

这次运行开始时先取一次当时最大的事件编号 `m`，摘要、检查统计和搜索统计都只看编号大于 `n`、不大于 `m` 的事件，摘要写明 `m`（`up to #m`，JSON 里是 `window.until`）。运行期间别的会话新写的事件不进任何一部分，三部分说的是同一段事件。

加 `--json` 时输出一个对象，`since` 是 `n`，`checks` 是检查统计，`window` 是这段摘要。不加 `--since` 时没有这段摘要，`--json` 的输出仍是检查统计的数组。

## 例子

- 编号 10 之后：两次 `land.ok`、一次 `conflict` 拒绝（`early`）、一次 `floor` 拒绝、三次 `land.turn` 分别等了 1000、3000、8000 毫秒 → 合入 2 次成功、2 次被拒（`conflict 1, floor 1`）；排队 3 次，中位数 3.0s，最大 8.0s；冲突 1 次，其中提前发现 1 次
- 两次 `conflict` 拒绝后，两次带 `kept_place` 的 `queue.enter` 分别用了 101000、245000 毫秒解决，另有一次不带的 → 回到保留位置 2 次，中位数 173.0s
- 一次 `land.killed`、一次原因为 `timeout` 的拒绝，随后两次带 `kept_place` 的 `queue.enter`（`kept_after` 分别是 `killed`、`timeout`，`resolve_ms` 分别是 40000、120000）→ 停止等待 2 次，回到保留位置 2 次，中位数 80.0s；冲突一行的回到保留位置仍是 0 次
- 两次 `queue.abandon`（别的合入者把条目标为放弃，BR-2380），随后一次带 `kept_place` 的 `queue.enter`（`kept_after` 是 `abandoned`，`resolve_ms` 是 30000）→ 停止等待 2 次，回到保留位置 1 次，中位数 30.0s；冲突一行不数这次回到保留位置
- 四次 `land.turn` 分别等了 1000、2000、4000、9000 毫秒 → 中位数 3.0s
- 编号 10 之后没有事件 → 事件 0 条，没有时间，排队 0 次，中位数和最大值为空
- 编号 10 之前有一次 `land.ok`、之后没有 → 摘要里合入成功 0 次
- 两个子 agent（`agent:s:a`、`agent:s:b`）和主会话（`agent:s`）各写了事件 → 执行者 3 个
- 一次 `claim.handover`、两次 `hook.skip` → 摘要里认领接手 1 次，hook 跳过 2 次
- `agent:a` 在两个 worktree 里各写了事件、`agent:b` 在主目录写了一条 → 执行者 2 个，worktree 3 个
- 另有一条没有 worktree 的旧事件 → worktree 仍是 3 个
- 开始时最大编号是 20，算完检查统计、算摘要之前别的会话写下编号 21 的 `land.ok` → 检查统计和摘要都不算它，摘要写 `up to #20`
- `canon stats --json` 不加 `--since` → 输出数组；加 `--since 10` → 输出带 `since`、`checks`、`window` 的对象
