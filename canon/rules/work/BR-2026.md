title: "边界上的每次拒绝都带原因记进事件表"
status: active
---
## 规则

认领被拒绝、开始一个找不到或不是 open 的变更、`canon work start` 建 worktree 失败（原因 `worktree`）、setup 失败（`setup`）、写或提交新变更文件失败（`change-file`），合入的任何一种拒绝、`canon work drop` 的任何一种拒绝（`drop.refuse`：原因 `claimed`、`in-use`、`no-process-list`、`git`（读分支或列出会丢的东西时 git 命令失败）、`archive`、`remove`，BR-2064、BR-2103），以及 `canon human answer` 的拒绝（`human.answer.refuse`，BR-2021、BR-2040），都在事件表里写一条事件，记录操作者、变更编号和原因；每种拒绝的原因各不相同。`canon work drop` 的用法错误（退出码 2：在要删除的 worktree 里执行、worktree 签出的是 main、变更的分支签出在 worktree 目录以外，BR-2233）和找不到（退出码 3：既没有 worktree 也没有分支）不算边界上的拒绝，不写事件。drop 的代码里每种拒绝都只能经过同一个写事件的函数返回，调用时必须给出原因。

## 例子

- 有未提交改动时合入 → 事件表多一条 `land.refuse`，原因 `dirty`
- 另一个 worktree 抢认领被拒 → 事件表多一条 `claim.refuse`
- `canon work start C-3`，而 `C-3` 已是 done → 事件表多一条 `start.refuse`，原因 `not-open`
- 主 checkout 签出 main 且有未提交改动时合入 → `land.refuse` 的原因是 `main-dirty`，不是 `main-moved`
- 在没有认领的 worktree 里 `canon work land --finish` → 原因 `no-claim`
- worktree 目录的位置被一个普通文件占着，`canon work start --title "X"` 建不了 worktree → `start.refuse`，原因 `worktree`
- `canon work drop C-1` 时 `C-1` 的 worktree 正被另一个进程使用 → 事件表多一条 `drop.refuse`，原因 `in-use`
- `canon/config.yaml` 的 `main` 写成一个不存在的分支，`canon work drop C-1` 列不出会丢的东西 → 退出码 4，事件表多一条 `drop.refuse`，原因 `git`
- `canon work drop C-99`，没有 worktree 也没有分支 → 退出码 3，事件表里没有 `drop.refuse`
- 在 `C-1` 自己的 worktree 里 `canon work drop C-1` → 退出码 2，事件表里没有 `drop.refuse`
