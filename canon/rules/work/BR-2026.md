## 规则

认领被拒绝、开始一个找不到或不是 open 的变更、`canon work start` 建 worktree 失败（原因 `worktree`）、setup 失败（`setup`）、写或提交新变更文件失败（`change-file`），以及合入的任何一种拒绝，都在事件表里写一条事件，记录操作者、变更编号和原因；每种拒绝的原因各不相同。

## 例子

- 有未提交改动时合入 → 事件表多一条 `land.refuse`，原因 `dirty`
- 另一个 worktree 抢认领被拒 → 事件表多一条 `claim.refuse`
- `canon work start C-3`，而 `C-3` 已是 done → 事件表多一条 `start.refuse`，原因 `not-open`
- 主 checkout 签出 main 且有未提交改动时合入 → `land.refuse` 的原因是 `main-dirty`，不是 `main-moved`
- 在没有认领的 worktree 里 `canon work land --finish` → 原因 `no-claim`
- worktree 目录的位置被一个普通文件占着，`canon work start --title "X"` 建不了 worktree → `start.refuse`，原因 `worktree`
