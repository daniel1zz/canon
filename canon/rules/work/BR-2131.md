---
id: BR-2131
title: 每条协调事件都记下运行它的 worktree
status: active
---

## 规则

canon 往协调数据库的事件表（`events`）写的每一条事件，都在 `worktree` 列记下运行这条命令的 worktree 的顶层目录（主 checkout 里运行时就是主 checkout 的路径），和执行者（BR-2023）一起说明是谁、在哪里做的。不带 `--as` 的调用里，同一个会话的几个 agent 是同一个执行者，靠这一列分开（D-18）；带 `--as` 的子 agent 的执行者本身带名字（BR-2023，D-62），这一列仍照记。旧数据库没有这一列时打开时补上（BR-2078），之前的事件这一列为空。

## 例子

- 在 `/r.worktrees/C-1` 里运行 `canon work stop --next x` → 新的事件的 `worktree` 是 `/r.worktrees/C-1`
- 同一个会话的两个子 agent 都不带 `--as`，分别在 `/r.worktrees/C-1` 和 `/r.worktrees/C-2` 里合入 → 两条 `land.ok` 的执行者相同，`worktree` 不同
- 两个子 agent 带 `--as a`、`--as b` 在 `/r.worktrees/C-1`、`/r.worktrees/C-2` 里合入 → 两条 `land.ok` 的执行者是 `agent:<会话>:a`、`agent:<会话>:b`，`worktree` 各自照记
- 在主 checkout `/r` 里运行 `canon work start --title x` → `id.allocate` 和 `start.ok` 的 `worktree` 是 `/r`
- 没有 `events.worktree` 的旧数据库 → 打开后有这一列，原有事件的 `worktree` 为空
