title: main 上没有的变更，从它自己的变更分支接着做

## 规则

`canon work start <C-n>` 在 main 上找不到 `C-n` 时，再找名字正好是 `change/C-n` 或以 `change/C-n-` 开头的分支：只有一个时，从这个分支读变更文件（分支签出在某个 worktree 里时读那个 worktree），沿用这个分支和它已有的 worktree；worktree 已经不在时，从这个分支重新建 worktree。认领规则（BR-2011、BR-2100）照常适用：另一个执行者仍然有效地持有它时拒绝，退出码 5。这样的分支有两个以上时拒绝，退出码 2，列出这些分支；一个也没有时退出码 3。

## 例子

- agent:a 用 `--title` 新建了 `C-1`（只在分支 `change/C-1-only-on-branch` 上），会话没写交接就结束，认领已失效 → agent:b 执行 `canon work start C-1` 成功，进入原来的 worktree，认领归 agent:b
- 同样情形，但 worktree 已被删掉、分支还在 → 成功，从分支重建 worktree，分支上的提交都在
- agent:a 的认领仍然有效 → agent:b 被拒绝，退出码 5；agent:a 自己再执行一次也被拒绝，退出码 5（BR-2011）
- 分支名里带 shell 语法，例如 `change/C-1-$(touch …)` → 照常从它接着做，名字里的命令不会被执行
- 只有分支 `change/C-12-other`，执行 `canon work start C-1` → 退出码 3（`change/C-12-…` 不是 `C-1` 的分支）
