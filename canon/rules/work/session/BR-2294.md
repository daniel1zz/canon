## 规则

当前 checkout 里没有、main 的最新提交上也没有（按 main 判断，不按当前 checkout）、只在它自己的变更分支上的变更，分支上的状态是 `done` 时（`canon work land --finish` 写了关闭提交，合入还没到 main 进程就被杀掉，没来得及撤回，BR-2018），它的工作没有合入：`canon change list` 不带 `--all` 也列出它，`canon brief` 的待办行也列出它，标记 `closed on branch, not landed`（在 `on branch` 之后）；`canon work start C-n` 接手它，不因为它不是 `open` 而拒绝，接手后照常 `canon work land --finish` 合入。main 上是 `done` 的变更照旧（不带 `--all` 不列）；只在分支上 `dropped` 的变更不带 `--all` 不列，`canon work start` 照旧拒绝。

## 例子

- `change/C-6-x` 上的 `C-6.md` 是 `status: done`，main 上没有 `C-6` → `canon change list` 有 `C-6      done       … (on branch change/C-6-x; closed on branch, not landed)`；`canon brief` 有 `C-6 (on branch change/C-6-x, closed on branch, not landed)`
- 同样情形 → `canon work start C-6` 退出码 0
- main 上的 `C-6` 是 `done` → 不带 `--all` 不列
- `change/C-6-x` 上是 `status: dropped` → 不带 `--all` 不列，`canon work start C-6` 退出码 2
- 在一个很久没 rebase 的旧 worktree 里，`C-146` 合入后 main 上是 `done`、分支 `change/C-146` 留着没删，这个 worktree 的变更文件里还没有 `C-146` → `canon change list` 不列 `C-146`（不标 `closed on branch, not landed`），和主 checkout 里 `canon brief` 列的是同一组
