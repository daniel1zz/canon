title: canon work start 列出别的进行中变更在改哪些地方
status: active

## 规则

`canon work start` 开始一个变更之后（在 BR-2062 的重叠提示之后），对 worktree 目录（BR-2047）下其他每个签出了变更分支、分支相对 main 已提交了 `canon/changes/` 以外改动的 worktree，输出一行 `in flight: <变更> changes <地方>`：地方是改动文件所在的目录，最多取前两级（`src/work/land/a.ts` → `src/work/`，`src/a.ts` → `src/`），放在顶层的文件就是文件名本身；去重后按字母排序，一行最多列 5 个，多的写 `, … (<k> more)`。按变更编号排序，最多 10 行，多的另起一行 `in flight: … and <k> more change(s)`。这只是告诉开工的人别人在动哪里，不是重叠判定：不写事件，不拦截，不改变退出码。比较时 git 出错，对每个出错的地方输出一行 `in flight: cannot …`（同 BR-2062），不当作那个变更没有改动。只提交了自己变更文件的变更不列；`canon work start` 被拒绝时什么都不列。

## 例子

- `C-2` 已提交了对 `src/work/land/a.ts` 和 `README.md` 的改动，开始 `C-3` → 输出 `in flight: C-2 changes README.md, src/work/`
- `C-2` 只提交了 `canon/changes/C-2.md` → 不列 `C-2`
- `C-2` 改了 7 个顶层文件 `a.txt` 到 `g.txt` → 那一行列 `a.txt` 到 `e.txt`，后面是 `, … (2 more)`
- 有 12 个变更已提交改动 → 列 10 行，再加一行 `in flight: … and 2 more change(s)`
- 另一个变更的 worktree 签出的分支和 main 没有共同祖先 → 输出 `in flight: cannot compare <那个分支> with main: …`，照常开始
