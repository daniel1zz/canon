---
id: BR-2149
title: 在主 checkout 里，canon brief 按待办顺序列出未完成的变更并标出已被认领的
status: active
---

## 规则

在主 checkout 或没有认领的 worktree 里，有未完成的变更时（main 上 `open` 的；main 上还没有、只在变更分支上 `open` 的，BR-2291；以及只在变更分支上标成 `done`、还没合入的，BR-2294），`canon brief` 输出一行 `Open changes in the owner's order`，按 BR-2148 和 BR-2291 的顺序（待办清单读 main 上的 `canon/backlog.md`）列出它们的编号，和 `canon change list` 在 main 上列的是同一组；认领仍然有效的编号后面的括号里有 `claimed`（租约没到期，且记下的会话进程还在；和 `canon work start` 接手认领用同一个判断，BR-2100），认领已经失效的不加，因为 start 会直接接手它；括号里的其他标记见 BR-2291；并提示没有任务时取第一个没被认领的。这样的变更一个都没有时不输出这一行；在认领了变更的 worktree 里不输出这一行（BR-2024）。

## 例子

- main 上有 `C-1`、`C-2`，清单是 `- C-2`，`C-2` 被认领 → 输出 `Open changes in the owner's order (canon change list); with no task, take the first unclaimed one: C-2 (claimed), C-1`
- 同样的清单，`C-2` 的认领租约已经到期 → 输出 `... take the first unclaimed one: C-2, C-1`
- `C-2` 的认领租约没到期，但记下的会话进程已经不在 → `C-2` 后面不加 `(claimed)`
- main 上没有未完成的变更，也没有只在分支上的 → 没有这一行
- main 上没有任何变更，`C-1` 只在分支 `change/C-1-x` 上、没有 handoff、认领已不在 → 输出 `... take the first unclaimed one: C-1 (on branch change/C-1-x)`
- 在认领了 `C-1` 的 worktree 里 → 没有这一行
- main 上有 `C-1`，`C-6` 只在分支 `change/C-6-x` 上、状态是 `done` → 输出 `... take the first unclaimed one: C-6 (on branch change/C-6-x, closed on branch, not landed), C-1`
