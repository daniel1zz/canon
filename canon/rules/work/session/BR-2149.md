id: BR-2149
title: 在主 checkout 里，canon brief 按待办顺序列出未完成的变更并标出已被认领的
status: active
---

## 规则

在主 checkout 或没有认领的 worktree 里，main 上有未完成（`open`）的变更时，`canon brief` 输出一行 `Open changes in the owner's order`，按 BR-2148 的顺序（待办清单读 main 上的 `canon/backlog.md`）列出它们的编号，认领仍然有效的编号后面加 `(claimed)`（租约没到期，且记下的会话进程还在；和 `canon work start` 接手认领用同一个判断，BR-2100），认领已经失效的不加，因为 start 会直接接手它；并提示没有任务时取第一个没被认领的。main 上没有未完成的变更时不输出这一行；在认领了变更的 worktree 里不输出这一行（BR-2024）。

## 例子

- main 上有 `C-1`、`C-2`，清单是 `- C-2`，`C-2` 被认领 → 输出 `Open changes in the owner's order (canon change list); with no task, take the first unclaimed one: C-2 (claimed), C-1`
- 同样的清单，`C-2` 的认领租约已经到期 → 输出 `... take the first unclaimed one: C-2, C-1`
- `C-2` 的认领租约没到期，但记下的会话进程已经不在 → `C-2` 后面不加 `(claimed)`
- main 上没有未完成的变更 → 没有这一行
- 在认领了 `C-1` 的 worktree 里 → 没有这一行
