title: 分支上的变更文件读不了时只影响这一项：brief 说一行照样列其余的，change list 列完其余的再以退出码 4 失败
status: active
---

## 规则

变更分支上有、当前 checkout（brief 用 main）里没有的变更文件读不出编号、标题或合法状态时（例如没有 front matter），只影响这一项，别的变更照常列出（BR-2291）：`canon brief` 输出一行 `Unreadable change file, not listed: <文件> on branch <分支>: <原因>`，照样输出待办行，退出码 0，因为 brief 不能因为别人做了一半的工作对所有会话失败；`canon change list`（含 `--json`）先照常输出其余的变更，再在标准错误上为每个读不了的文件写一行 `unreadable change file: <文件> on branch <分支>: <原因>`，退出码 4。同一个编号另一个分支上的文件读得出时，按读得出的那份列出，标记是 `ambiguous`（BR-2293）。git 本身出错（读不了分支或提交）仍让命令失败。

## 例子

- main 上有 open 的 `C-1`，分支 `change/C-3-broken` 上的 `canon/changes/C-3.md` 没有 front matter → `canon brief` 输出含 `Unreadable change file, not listed: canon/changes/C-3.md on branch change/C-3-broken` 和 `take the first unclaimed, not ambiguous one: C-1`，退出码 0
- 同样情形 → `canon change list` 标准输出有 `C-1` 那一行、没有 `C-3`，标准错误含 `unreadable change file: canon/changes/C-3.md on branch change/C-3-broken`，退出码 4
- 没有读不了的文件 → 没有这两种提示，退出码 0
