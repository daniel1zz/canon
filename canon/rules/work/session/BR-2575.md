## 规则

`canon work handoff-reason <C-n> --reason <原因> [--on <问题或成功标准>]` 把 `<C-n>` 已有交接的原因改成给出的这个，下一步、备注、操作者和时间不变，记一条 `handoff.reason` 事件（含新旧原因），输出 `<C-n>: handoff reason <原因>`，退出码 0。不需要持有认领，worktree 已经删掉的交接也能改：在 D-151 之前只写了文字、没有原因的交接（原因显示为 `unrecorded`）就用它迁移，由主会话按交接文字判断后逐个补上。

原因和 `--on` 的写法、用法错误和退出码都按 BR-2025。`<C-n>` 没有交接 → 退出码 3，什么都不写。

## 例子

- `C-406` 的旧交接只写着“等负责人恢复招降”，没有原因；先 `canon human ask --change C-406 "…"` 得到 #20，再 `canon work handoff-reason C-406 --reason owner --on 20` → 交接原因 `owner #20`，下一步文字不变，主状态是 `waiting-owner`（BR-2571）
- `C-1047` 的旧交接写着“做完了等主会话合入”→ `canon work handoff-reason C-1047 --reason land` → 原因 `land`
- `canon work handoff-reason C-5 --reason land`，`C-5` 没有交接 → 退出码 3
- `canon work handoff-reason C-406 --reason waiting` → 退出码 2，提示列出五种原因
