id: BR-2132
title: 不同变更同时 canon work start 都成功，分支从本地 main 建
status: active
---

## 规则

多个执行者同时对不同的变更运行 `canon work start`（包括同时用 `--title` 新建）时，每一个都必须成功（退出码 0），各自得到自己的变更编号、分支和 worktree。新建的变更分支必须从本地的 main 分支（配置里的 `main`）创建，不能从 `origin/main` 这类远程跟踪引用创建，并且明确不设 upstream（`--no-track`），所以不管用户或系统的 git 配置怎么设（包括 `branch.autoSetupMerge=always`，这时 git 从本地分支建分支也会设 upstream），都不会往 `.git/config` 写 `branch.<分支>.remote`/`merge` 这类 upstream 配置。原因：从远程跟踪引用建分支时 git 要锁 `.git/config` 写 upstream，并发时会有一部分失败，报 `could not lock config file .git/config: File exists`（git 2.50.1 实测 8 个并发里失败 3 个；从本地分支建时 8 个全部成功）。

## 例子

- 仓库有远程 `origin`、`origin/main` 存在，8 个进程同时 `canon work start --title "T<i>"` → 8 个都退出码 0，有 8 个不同的变更 worktree，`.git/config` 里没有任何 `branch.change/…` 配置
- 同样情形，如果分支改成从 `origin/main` 建 → 会写 upstream 配置，并发时可能有进程因锁不到 `.git/config` 失败；本规则禁止这种做法
- git 配置了 `branch.autoSetupMerge=always`（仓库、用户或系统级都算），8 个进程同时 `canon work start --title "T<i>"` → 8 个都退出码 0，`.git/config` 里同样没有任何 `branch.change/…` 配置（issue #27）
- 同样配置下，如果建分支时不加 `--no-track` → git 给每个新分支写 `branch.<分支>.remote=.` 和 `merge=refs/heads/main`；本规则禁止这种结果
- 协调数据库还不存在（第一次在这个仓库用 canon），8 个进程同时第一次打开它 → 都成功，不会有进程报 `cannot open coordination DB … database is locked`
- 只有一个进程 `canon work start --title "T"` → 成功，分支同样没有 upstream 配置
