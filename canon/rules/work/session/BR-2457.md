## 规则

`canon chore start "<标题>"` 创建独立工作树、分支和认领，输出杂务身份与工作树路径；身份、分支和恢复依据见 D-100。不创建 Change 文档、不分配 C 编号、不产生开工文档提交。标题为空以退出码 2 拒绝。新工作树的 setup 失败按 BR-2029 清理，认领竞争和 worktree 锁沿用现有开工要求。

`canon chore start <杂务身份>` 从匹配分支接回，不依赖 Change 文档、现存认领或 handoff；只有分支也能重建工作树。候选不唯一、认领与分支身份不一致时退出码 5，不猜测；找不到分支退出码 3。活着的其他持有者按认领规则拒绝。没有完成记录的空杂务分支仍能接回。事件缺失时明确说完整标题不可恢复，只显示分支 slug，接回照常成功。

## 例子

- 开始标题 `更新工具` → 输出 chore 身份与工作树，工作树 HEAD 等于开工时 main，没有新增 Change 文档；下一次业务开工仍使用原来的下一个 C
- 再开始同标题 → 不同身份、分支和工作树
- 标题为空 → 退出码 2，无新认领、分支或工作树
- 停下并释放认领、删除干净工作树但保留分支，再按身份开工 → 接回原分支，不产生 C
- 分支存在且从未提交修改 → 仍能接回，不把它当成已经完成
- 接回一个没有分支的杂务身份 → 退出码 3，无新认领、分支或工作树
- 两个分支声明同一杂务身份 → 退出码 5，两者不变
- 认领指向的工作树和分支身份对不上 → 退出码 5，什么都不改
- 杂务的事件被清除后按身份接回 → 接回成功，输出完整标题不可恢复、只显示分支 slug
- 另一个活着的会话持有杂务 → 退出码 5，原认领与修改不变
