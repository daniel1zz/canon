## 规则

`canon change list`（含 `--all` 和 `--json`）除了当前 checkout 里的变更，还列出名字是 `change/C-n` 或以 `change/C-n-` 开头的本地分支上有、当前 checkout 里没有的变更：变更文件从列出分支那一刻它指向的提交读（`git show <提交>:canon/changes/…`），不需要分支的 worktree 还在，分支在列出之后被别的会话删掉也照样读出；状态的过滤和当前 checkout 里的变更一样（不带 `--all` 只列 `open` 的）。分支上没有这个变更文件时不列；有文件但读不出编号、标题和合法状态时命令以退出码 4 失败，写明分支和文件，不跳过。同一个编号有几个这样的分支时列一次，标出全部分支。

每个变更行尾的括号里依次标出（没有就不加括号）：只在分支上时 `on branch <分支>`（几个分支时 `on branches <分支>, <分支>`）；有 handoff 时 `handoff: <下一步>`；认领仍然有效时 `claimed`（和 `canon work start` 接手认领用同一个判断，BR-2100），各项用 `; ` 隔开。`--json` 的每一项多三个键：`on_branch`（读它的分支列表，当前 checkout 里有它时是空列表）、`handoff`（`next`、`actor`、`updated_at`，没有时是 `null`）、`claimed`（布尔值）。

顺序按 BR-2148。只在分支上的变更有变更分支，算已经开始的；待办清单又列不了它（`canon check` 会报 `ref-dangling`，BR-2150），所以它总排在清单之后、没开始的变更之前。

在主 checkout 或没有认领的 worktree 里，`canon brief` 的待办行（BR-2149）列的是同一组变更（以 main 为当前 checkout，只列 `open` 的），顺序相同，标记写成 `(on branch <分支>, handoff, claimed)`，handoff 只写 `handoff` 不写下一步。

## 例子

- main 上有没开始的 `C-1`；agent 用 `canon work start --title "Only on branch"` 新建了 `C-2`（只在分支 `change/C-2-only-on-branch` 上），执行 `canon work stop --release --next "land it"` → 在主 checkout 里 `canon change list` 依次输出 `C-2 … (on branch change/C-2-only-on-branch; handoff: land it)` 和不带括号的 `C-1`；`--json` 里 `C-2` 的 `on_branch` 是 `["change/C-2-only-on-branch"]`、`handoff.next` 是 `land it`、`claimed` 是 `false`，`C-1` 的 `on_branch` 是 `[]`、`handoff` 是 `null`；`canon brief` 输出 `… take the first unclaimed one: C-2 (on branch change/C-2-only-on-branch, handoff), C-1`
- 同样情形，`C-2` 的 worktree 已被删掉、分支还在 → 照样列出 `C-2`，标记不变
- `C-2` 没有 `--release`，认领仍然有效 → 括号里多一项 `claimed`，brief 里是 `(on branch change/C-2-only-on-branch, handoff, claimed)`
- 待办清单是 `- C-1` → `C-1` 排在 `C-2` 前面
- 没有 handoff、只有变更分支的 `C-2`（会话没写交接就结束了）→ 仍然列出，排在没开始的 `C-1` 前面
- `C-2` 合入后 main 上它是 `done`，分支还没删 → 不带 `--all` 时不列；带 `--all` 时列出，不带 `on branch`
- 列出 `change/C-2-only-on-branch` 之后、读它的变更文件之前，别的会话 `canon work drop C-2` 删掉了分支 → 照样按列出时的提交列出 `C-2`，退出码 0
- 分支 `change/C-3-broken` 上的 `canon/changes/C-3.md` 没有 front matter → `canon change list` 退出码 4，信息里有 `C-3.md on branch change/C-3-broken`
- 分支 `change/C-4-empty` 上没有 `C-4` 的变更文件 → 不列 `C-4`，退出码 0
