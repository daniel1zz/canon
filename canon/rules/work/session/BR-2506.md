## 规则

在没有认领变更或杂务的地方，`canon brief` 在工作说明之后、交接和待办之前，先打印整体进度摘要（D-129，取自 `canon overview` 的前三节，BR-2505），第一行是 `Overall progress (canon overview):`，后面缩进两个空格：

- 有当前版本时两行：`<编号>  <状态>  <标题>`（不算规则的执行状态：那要读每条规则的通过记录，大项目里要几秒，每个会话开头都付不起；规则的数量看 `canon overview`），当前版本是因为没有 `active` 才取的 `planned` 时末尾加 `  (no release is active: the lowest planned one)`；和 `成功标准 <总数> 条：已满足 <a>  未满足 <b>  待负责人 <c>  未证明 <d>`；没有当前版本时一行 `no release in progress`。
- 有没做完的计划（已完成的步数少于总步数）时一行 `plans not done: ` 加每个计划的 `<C-n> <已完成>/<总数> (<百分比>%)`，用逗号分隔；没有就不输出这一行。
- main 上最近 7 天有改了目标的提交（BR-2505、D-130）时一行 `goal changed in the last 7 days: <提交号前 9 位，逗号分隔> (canon overview)`；没有时不输出。
- `canon overview` 的 `## 等负责人` 里有东西时一行 `waiting for the owner: <q> question(s), <f> tier-C finding(s), <c> criterion(s)`；都是 0 时不输出这一行。

没有当前版本、没有没做完的计划、没有最近的目标改动、也没有等负责人的事时，整个摘要都不打印，brief 照 BR-2024 只有工作说明。认领了变更或杂务的 worktree 里不打印，理由同 BR-2024：别的工作的情况会把这个会话拉离它自己的变更。摘要读不出来（例如 main 上的文档读不了）时说一行原因，brief 照样输出其余内容。

## 例子

- 主 checkout，`R-3` active，4 条成功标准各一种状态，计划 C-5 做了 2/4，1 个问题等回答 → `Overall progress (canon overview):` 下面四行：`R-3  active  <标题>`、`成功标准 4 条：已满足 1  未满足 1  待负责人 1  未证明 1`、`plans not done: C-5 2/4 (50%)`、`waiting for the owner: 1 question(s), 0 tier-C finding(s), 1 criterion(s)`
- 没有版本、没有计划、没有等负责人的事 → 不出现 `Overall progress`
- 没有版本，但有 1 个问题等回答 → `Overall progress (canon overview):`、`  no release in progress`、`  waiting for the owner: 1 question(s), 0 tier-C finding(s), 0 criterion(s)`
- 没有 active，`R-2` planned → 第一行 `R-2  planned  <标题>  (no release is active: the lowest planned one)`
- 计划 C-5 4/4 已全部完成 → 不出现 `plans not done:` 那一行
- 在认领了 C-9 的 worktree 里 → 不出现 `Overall progress`
