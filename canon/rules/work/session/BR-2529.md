## 规则

主会话（不是 worker 的执行者，BR-2023）在主 checkout 或没有认领的 worktree 里运行 `canon brief` 时，在 BR-2024 列出的内容之后输出议程摘要（D-151）。议程为空时不输出这一节。

**议程摘要**的格式（合入之后 BR-2584 和 `canon work watch` 启动时 BR-2528 用同一个）：第一行 `Agenda (canon work due):`，然后每个不空的组一行，缩进两个空格，顺序同 BR-2527：

- 可派：BR-2581 的组头，有空时后面加 `: <变更编号，逗号分隔>`（最多 5 个）；没空时就是那个组头；
- 要判断：`judge: <条数>: <前 3 项>`，每项是键，或合成的一类写 `<类> ×<条数>`，多于 3 项时加 `, … +<k>`；
- 等负责人：`owner: <条数>: <前 3 项>`，写法同上；
- 正在跑的整组测试：BR-2582 的那一行。

全文用 `canon work due` 看。

运行在 Claude Code 里（`CLAUDECODE=1`）时，还要输出一行，有没有议程都输出：

`Keep canon work watch running under Monitor (timeout 30 min); when it expires, re-arm with --since <the last event number it printed>.`

Codex 和别的宿主不输出这一行，因为它们没有 Monitor；它们只靠这里、合入之后（BR-2584）和 `canon work start`（BR-2530）看到议程。

认领了变更的 worktree 里的 brief 不变（BR-2024），worker 也一样：worker 是无界面运行的会话，挂不了 Monitor。

依据：D-151 第三部分第 7 条（修改 D-136）。

## 例子

- Claude Code 主会话，意见 #12 开了 2 小时，`C-9` 可派、机器有空 → 输出含 `Agenda (canon work due):`、`  delegate: room for … : C-9`、`  judge: 1: finding:12`，以及 `Keep canon work watch running under Monitor …`
- 停滞的 `C-5`、`C-6` 和 5 条 A 档意见 → `  judge: 7: stalled ×2, finding A ×5`
- 要判断的有 5 类 → 列前 3 类，再 `, … +2`
- Claude Code 主会话，议程为空 → 没有 `Agenda`，仍有 `Keep canon work watch running …`
- Codex 主会话，有意见 #12 → 有 `Agenda` 和 `finding:12`，没有 `Monitor` 那一行
- 在认领了 `C-1` 的 worktree 里 → 两者都没有
- worker（`agent:s:w1`）→ 两者都没有
