# 变更的开始、停下和交接（work/session）

工作从开始到结束在 worktree 里怎么过：业务变更用 C 文档，杂务按 D-100 只有工作身份；两者共享交接和安全清理。`canon work start` 新建或接手一个变更（worktree、分支、变更文件、认领），`canon work stop` 记下下一步，下一个会话由 `canon brief` 看到自己在做什么和别的变更；`canon work clean` 删除已经合入、没人在用、也不会丢东西的 worktree。

不管：认领的规则（`work/claims`）、合入（`work/land`）、放弃（`work/drop`）。

## 业务

- **开工**：一个会话怎么拿到一个变更和它自己的工作树：新建还是接手、并发时各拿各的、半成品不留下。
- **按计划开工**：开工时说明这个变更做的是哪个计划的哪几步，这几步已经有人在做时说一声。
- **开工时的提示**：开工之后把周围的情况摆出来：别的变更在改哪些地方、和本变更重叠的文件、机器忙不忙。
- **工作树的存放和清理**：变更的工作树建在哪、什么时候可以删、删的时候绝不丢工作、签出 main 的工作树跟着 main 走。
- **会话开始读到什么**：`canon brief` 在每个会话开头给出的那一份：工作说明、手上这个变更的状态和交接、重叠的文件、还没处理的评审建议、没人认领时该接哪一个。
- **停下和交接**：停下时留下下一步给下一个会话，停下和关闭时提醒教训要先问负责人。
- **现在有哪些活**：把全机和全仓库现在的状况列出来：认领、队列、交接、等人回答的问题、负责人标的优先，以及只在分支上的变更怎么算。

## 术语

- **worktree 目录**：变更的 worktree 放在 `<仓库名>.worktrees/C-n`（可配置）。
- **setup**：新 worktree 建好后运行的项目命令，失败时不留下半成品。
- **重叠**：两个进行中的变更改了同一个文件。
