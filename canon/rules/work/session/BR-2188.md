## 规则

`canon work clean` 删掉一个 worktree（BR-2019）之后，在主 checkout 里删掉这个 worktree 签出的分支：先读分支现在的提交，确认它完全包含在 main 里（`git merge-base --is-ancestor <提交> <main>`），再按这个提交删除（`git update-ref -d refs/heads/<分支> <提交>`），不看主 checkout 当前签出的是哪个分支（`git branch -d` 按 HEAD 判断，主 checkout 不在 main 上时会把已合入的分支留下）。分支有不在 main 上的提交，或者在确认之后又动过（按读到的提交删不掉）时，分支留下，clean 不报错、不列出，worktree 照样算已删除，退出码不变。保留下来的 worktree 的分支不动。

## 例子

- 主 checkout 签出 main，C-1 已合入，`canon work clean` → C-1 的 worktree 和分支 `change/C-1-x` 都没了
- C-2 有一个没合入的提交，被保留 → 分支 `change/C-2-y` 还在
- 主 checkout 签出的是另一个分支 `other`，它不含 C-3 合入的提交，C-3 已合入 main → C-3 的 worktree 和分支 `change/C-3-z` 都被删，输出只有 `removed …`，退出码 0
