---
id: BR-2293
title: 同一个变更在几个分支上时标成 ambiguous，没有任务的 agent 跳过它
status: active
---

## 规则

当前 checkout 里没有、从它自己的变更分支读出来的变更 `C-n`，名字是 `change/C-n` 或以 `change/C-n-` 开头的本地分支有两个以上时（不管其余分支上有没有它的变更文件、读不读得了，和 `canon work start` 数分支的方法一样），`canon change list` 和 `canon brief` 只列它一次，标记写成 `ambiguous: <分支>, <分支>`（全部这些分支，按分支名排序，代替 `on branch`），`--json` 的 `on_branch` 列出这些分支。`canon work start C-n` 这时拒绝（BR-2107，退出码 2），所以工作说明让没有任务的 agent 跳过标了 `ambiguous` 的变更；用 `canon work drop` 去掉多余的分支后它恢复成 `on branch`。其中某个分支上的文件读不了时，照样按读得出的那份列出、标 `ambiguous`，读不了的那份另外提示（BR-2292）。

## 例子

- `change/C-5-a` 和 `change/C-5-c` 上都有 `C-5.md` → `canon change list` 的 `C-5` 行带 `(ambiguous: change/C-5-a, change/C-5-c)`，`--json` 里 `on_branch` 是这两个分支；`canon brief` 里是 `C-5 (ambiguous: change/C-5-a, change/C-5-c)`
- 同样情形 → `canon work start C-5` 退出码 2
- 只有 `change/C-5-a` 上有 `C-5.md`，另有一个没有这个文件的分支 `change/C-5-b` → 仍标 `ambiguous: change/C-5-a, change/C-5-b`，`canon work start C-5` 退出码 2
- `change/C-5-a` 上的 `C-5.md` 读得出，`change/C-5-c` 上的没有 front matter → 列出 `C-5`，标 `ambiguous: change/C-5-a, change/C-5-c`，另有一行读不了 `change/C-5-c` 上文件的提示
- 只有一个分支 `change/C-5-a` → 标 `on branch change/C-5-a`
