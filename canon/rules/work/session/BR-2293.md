---
id: BR-2293
title: 同一个变更在几个分支上时标成 ambiguous，没有任务的 agent 跳过它
status: active
---

## 规则

当前 checkout 里没有的变更 `C-n`，在两个以上它自己的变更分支（`change/C-n`、`change/C-n-…`）上都有变更文件时，`canon change list` 和 `canon brief` 只列它一次，标记写成 `ambiguous: <分支>, <分支>`（按分支名排序，代替 `on branch`），`--json` 的 `on_branch` 列出这些分支。`canon work start C-n` 这时拒绝（BR-2107，退出码 2），所以工作说明让没有任务的 agent 跳过标了 `ambiguous` 的变更；用 `canon work drop` 去掉多余的分支后它恢复成 `on branch`。只有一个分支上有这个变更文件时照常标 `on branch`。

## 例子

- `change/C-5-a` 和 `change/C-5-b` 上都有 `C-5.md` → `canon change list` 的 `C-5` 行带 `(ambiguous: change/C-5-a, change/C-5-b)`，`--json` 里 `on_branch` 是这两个分支；`canon brief` 里是 `C-5 (ambiguous: change/C-5-a, change/C-5-b)`
- 同样情形 → `canon work start C-5` 退出码 2
- 只有 `change/C-5-a` 上有 `C-5.md`，`change/C-5-b` 上没有 → 标 `on branch change/C-5-a`
