## 规则

`canon work start` 和 `canon work land` 把当前变更分支相对 main 改过的文件（`git diff --name-only main...<分支>`，只看已提交的改动）和 worktree 目录（BR-2047）下其他每个签出了变更分支的 worktree 的分支改过的文件对比（不看变更状态：已经 done、但 worktree 还没清理的也算）；合入时在所有不进队列的拒绝（BR-2013、BR-2031、BR-2043、BR-2048 的 `--timeout` 不合法，以及 `--finish` 时没有认领、要关闭的变更没写好教训（BR-2161）、要执行的规则缺证据（原因 `evidence`，BR-2241））之后、进入队列之前比较，所以这些拒绝不会打印提示；有重叠时，对每个重叠的变更打印一行提示（哪个变更、哪些文件），并写一条 `overlap.notice` 事件（时机、对方变更、文件）。比较时 git 出错（列不出 worktree，或算不出某个分支相对 main 的改动），对每个出错的地方打印一行 `overlap: cannot …`，写明哪个分支和错误，不当作没有重叠。提示不拦截任何操作，不改变退出码。

## 例子

- `C-1` 和 `C-2` 都提交了对 `src/a.ts` 的改动，`C-1` 合入 → 打印 `overlap: C-2 also changes src/a.ts`，事件表多一条 `overlap.notice`，合入照常进行
- `C-1` 改了 `src/a.ts`，`C-2` 改了 `src/b.ts` → 不提示
- `C-2` 对 `src/a.ts` 的改动还没提交 → 不提示
- 新建的变更只提交了它自己的变更文件 → 开始时不提示
- `canon work start` 被拒绝（例如变更不是 open）→ 不提示
- 有未提交改动的合入被拒绝（BR-2013）→ 不打印提示，不写 `overlap.notice`
- `C-1` 和 `C-2` 都改了 `src/a.ts`，`C-1` 加 `--finish` 合入时因缺证据被拒（`evidence`）→ 不打印提示，不写 `overlap.notice`
- 另一个变更的 worktree 签出的分支和 main 没有共同祖先 → 打印 `overlap: cannot compare <那个分支> with main: …`，照常开始或合入
