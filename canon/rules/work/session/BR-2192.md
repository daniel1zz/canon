## 规则

`canon work status` 依次输出五段：`Claims:` 下每个认领一行（变更编号、执行者、worktree、租约到期时间 `until <时间>`），列的是认领表里的每一行，失效的也列出，但在行尾标出：租约已经到期的标 `(expired: lease ended)`，租约没到期但记下的会话进程已经不在的标 `(expired: session process exited)`，判断和 `canon work start` 接手认领时一样（BR-2100）；仍然有效的不标；`Landing queue:` 下先是等待中和正在合入的条目（`#<编号> <状态> <变更> <worktree>`），再是因冲突被拒、仍保留位置的条目（`#<编号> resolving <变更> <worktree> keeps its place until <时间>`，BR-2177）；`Landings with no result yet:` 下是还没有结果的合入（内容见 BR-2308）；`Handoffs:` 下每个 handoff 一行（变更编号、`next: <下一步>`、执行者和时间），最新的在前；最后一行 `Questions waiting for a human: <数量>`。某一段没有内容时只输出标题；有负责人标的优先时，在 `Handoffs:` 之前多一段 `Urgent by the owner:`（BR-2365），没有时不输出。加 `--json` 时输出一个 JSON 对象，键是 `claims`、`queue`、`landings`、`resolving`、`handoffs`、`questions`、`urgent`（负责人标的优先，BR-2365），值是对应的列表（`questions` 是等人回答的问题本身，不是数量）；`claims` 的每一项有 `state`：`live`、`expired`（租约到期）或 `holder-gone`（会话进程不在）。不改认领、队列和 handoff，也不写事件，只有一种例外：发现认领失效时第一次写一条 `claim.expired` 或 `claim.holder-gone`（BR-2360）。

## 例子

- 什么都没有 → 输出 `Claims:`、`Landing queue:`、`Landings with no result yet:`、`Handoffs:` 四个标题和 `Questions waiting for a human: 0`
- `C-1` 被 agent:a 认领并有 handoff“land it”，有一个等人回答的问题 → `Claims:` 下有一行含 `C-1`、`agent:a` 和 `until`，`Handoffs:` 下有 `C-1` 和 `next: land it`，最后一行 `Questions waiting for a human: 1`
- 同样状态加 `--json` → `claims` 有一项，`subject` 是 `C-1`；`handoffs` 有一项，`next` 是 `land it`；`questions` 有一项；`queue`、`landings` 和 `resolving` 是空列表
- `C-1` 的租约已经到期 → 仍列在 `Claims:` 下，行尾是 `(expired: lease ended)`；`--json` 里它的 `state` 是 `expired`
- `C-1` 的租约没到期，记下的会话进程已经不在 → 行尾是 `(expired: session process exited)`，`state` 是 `holder-gone`
- `C-1` 的认领仍然有效 → 行尾没有 `expired`，`state` 是 `live`
