## 规则

`canon work status` 依次输出四段：`Claims:` 下每个认领一行（变更编号、执行者、worktree、租约到期时间 `until <时间>`），列的是认领表里的每一行，不判断租约是否到期、会话进程是否还在；`Landing queue:` 下先是等待中和正在合入的条目（`#<编号> <状态> <变更> <worktree>`），再是因冲突被拒、仍保留位置的条目（`#<编号> resolving <变更> <worktree> keeps its place until <时间>`，BR-2177）；`Handoffs:` 下每个 handoff 一行（变更编号、`next: <下一步>`、执行者和时间），最新的在前；最后一行 `Questions waiting for a human: <数量>`。某一段没有内容时只输出标题。加 `--json` 时输出一个 JSON 对象，键是 `claims`、`queue`、`resolving`、`handoffs`、`questions`，值是对应的列表（`questions` 是等人回答的问题本身，不是数量）。只读，不写事件。

## 例子

- 什么都没有 → 输出 `Claims:`、`Landing queue:`、`Handoffs:` 三个标题和 `Questions waiting for a human: 0`
- `C-1` 被 agent:a 认领并有 handoff“land it”，有一个等人回答的问题 → `Claims:` 下有一行含 `C-1`、`agent:a` 和 `until`，`Handoffs:` 下有 `C-1` 和 `next: land it`，最后一行 `Questions waiting for a human: 1`
- 同样状态加 `--json` → `claims` 有一项，`subject` 是 `C-1`；`handoffs` 有一项，`next` 是 `land it`；`questions` 有一项；`queue` 和 `resolving` 是空列表
- `C-1` 的租约已经到期 → 仍列在 `Claims:` 下
