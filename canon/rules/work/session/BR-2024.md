## 规则

在认领了变更的 worktree 里，`canon brief` 只输出这个变更自己的东西：变更编号、查看和取上下文的命令、这个变更的 handoff 和它的重叠提示（BR-2063），不提别的变更的 handoff，也不提等人回答的问题数量。在主 checkout 或没有认领的 worktree 里，`canon brief` 列出有 handoff 的变更和等人回答的问题数量。都没有时不输出这些内容（工作说明和 BR-2085 的过期提示照样输出）。原因：lore 实测把别的会话的 handoff 注入新会话会把它引到别人的工作上，只好再写一条规则去抵消这段注入（lore SPEC-166）。

## 例子

- 在认领了 `C-1` 的 worktree 里，`C-1` 有 handoff“land it” → 输出包含 `You are in C-1` 和 `next — land it`
- `C-1`、`C-2` 都有 handoff，还有一个等人回答的问题；在认领了 `C-1` 的 worktree 里执行 → 输出 `C-1` 的 handoff，不出现 `C-2`、`Unfinished changes with handoffs` 和 `wait for a human`
- 同样的状态在主 checkout 里执行 → 输出 `Unfinished changes with handoffs: C-1, C-2` 和 `1 question(s) wait for a human`
- 没有任何认领、handoff 和问题，装进项目的东西也是最新的 → 除了工作说明什么也不输出
