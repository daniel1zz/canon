---
id: BR-2400
title: 机器负载达到 CPU 数的 2 倍时，canon work start 开新变更照常开工并提示负载
status: active
---

## 规则

`canon work start` 新建了 worktree（不是 `--fix-main`，也不是接回已经存在的 worktree）之后，读机器的 5 分钟平均负载和 CPU 数（`availableParallelism`）：负载达到 CPU 数的 2 倍或以上时，照常开工、退出码不变，另输出一行 `machine busy: …`，写明负载（一位小数）、CPU 数、这个 2 倍的数、现在还有效的认领数，并建议等负载降下来或先合入已经开着的变更。最近 200 次合入轮次（`land.turn`，它记下当时的负载 `load` 和 CPU 数 `cpus`）里，以 `land.ok` 结束的、当时负载达到 2 倍的和不到 2 倍的各有至少 3 次时，再输出一行这两组从 `land.turn` 到 `land.ok` 的中位时长（分钟，一位小数）和次数。负载低于 2 倍时什么都不输出；平台读不到负载（三个平均值都是 0）时也什么都不输出、不报错。比较用的是没有取整的负载。`land.turn` 记的负载见 BR-2122。

## 例子

- 8 个 CPU、负载 16.0 → 输出 `machine busy: 5-minute load 16.0 on 8 CPUs (at or over 16); …`，开工照常，退出码 0
- 8 个 CPU、负载 15.9 → 不输出
- 8 个 CPU、负载 15.96（显示会是 16.0）→ 不输出：比较的是没有取整的负载
- `--fix-main` 开工，负载 40 → 不输出
- 接回自己已有 worktree 的变更，负载 40 → 不输出
- 读不到负载（全是 0）→ 不输出，不报错
- 负载达到 2 倍时合入 3 次各用 10 分钟、不到 2 倍时 3 次各用 4 分钟 → 多一行 `median 10.0 min at a load this high (3), 4.0 min below it (3)`；某一组不到 3 次 → 没有这一行
- 一次轮次以 `land.refuse` 结束 → 不计入中位时长
