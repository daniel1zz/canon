## 规则

`canon work clean <C-n>...` 只考虑列出的变更的 worktree，别的 worktree 不删、也不列出；对列出的每一个，保留还是删除按 BR-2019 的同一套检查（当前所在、认领、未提交改动、不在 main 上的提交、不能重新生成的被忽略文件、进程，以及删除期间占住认领）。每个编号都要是一个变更：在 worktree 目录（BR-2047）下有它的 worktree，或者 main 上有这个变更文件，或者有它的变更分支；有一个不是，就什么都不删，退出码 3，信息里写明是哪个编号。是变更但没有 worktree 的，保留列表里写“no worktree”，退出码 0。不带编号时行为不变，考虑全部 worktree。编号不分大小写，和 `canon work start` 一样（`c-1` 就是 `C-1`）；同一个编号写两次（包括大小写不同）只算一次。

## 例子

- C-1 和 C-2 都已合入、没人认领，`canon work clean C-1` → 只删除 C-1 的 worktree，C-2 的还在，也不出现在输出里
- `canon work clean C-1 C-2` → 两个都删除
- C-3 有一个没合入的提交，`canon work clean C-3` → 保留，原因是“1 commit(s) not on main”
- `canon work clean C-1 C-99`，C-99 既没有 worktree、main 上没有变更文件、也没有分支 → 退出码 3，信息里有 C-99，C-1 的 worktree 也没删
- `canon work clean foo` → 退出码 3
- C-1 已合入、没人认领，`canon work clean c-1` → 删除 C-1 的 worktree
- C-4 在 main 上，它的 worktree 已经被删了，`canon work clean C-4` → 退出码 0，输出“kept C-4: no worktree”
- `canon work clean`（不带编号）→ 和以前一样删除所有已合入、没人认领的 worktree
