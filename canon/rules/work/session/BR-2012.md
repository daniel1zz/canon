## 规则

`canon work start --title <标题>` 分配变更编号，在 worktree 目录（BR-2047）下的 `<C-n>` 基于 main 建新分支 `change/<C-n>-<slug>`（`<slug>` 是标题转小写、连续的非字母数字字符换成一个 `-`、去掉首尾的 `-`，最多 60 个字符；标题含非 ASCII 字符时分支为 `change/<C-n>`；整个分支名最多 80 个字符，超出的截掉），在那里提交变更文件，并由这个 worktree 认领该变更。

`canon work start`（新建和 `C-n` 两种）在分配编号、调用 `git worktree add` 之前先检查 main 有没有提交：仓库里还没有任何提交（刚 `git init`，main 是还没出生的分支）时以退出码 4 拒绝（BR-2022），不分配编号（BR-2002）、不记 `id.allocate` 事件、不建 worktree，提示说清下一步：先把 `canon init` 写的文件提交到 main（`git add canon .claude && git commit -m "canon init"`）。仓库有别的分支、只是配置的 main 写错时不属于这种情况，仍按读不出 main 处理（退出码 4，`git cannot read <main>`）。

## 例子

- 在 `~/p/app` 执行 `canon work start --title "Refund window"` → 建出 `~/p/app.worktrees/C-1`，分支 `change/C-1-refund-window`，变更文件已提交，`C-1` 被它认领
- 标题为 `中文变更` → 分支 `change/C-2`
- 标题是 100 个 `a` → 分支名是 `change/C-3-` 加 60 个 `a`
- `canon init` 之后 main 还没有提交，`canon work start --title "T"` → 退出码 4，提示里有 `has no commit yet` 和 `git commit`，没有 `invalid reference`；`canon events` 里没有 `id.allocate`，也没有新分支和 worktree
- 同一仓库把 `canon init` 写的文件提交到 main 后再 `canon work start --title "T"` → 退出码 0，得到 `C-1`（上一次被拒绝的启动没有占用编号）
- 同一仓库没有提交时 `canon work start C-1` → 同样退出码 4 和同样的提示
