## 规则

`canon work start <C-n>` 从变更分支接着做一个 main 上没有的变更（BR-2107）时，拿到认领之后、建 worktree 之前，再确认一次那个分支还在。分支在这之间被删掉了（例如另一个会话的 `canon work drop` 刚好跑完），就放掉刚拿到的认领，不建 worktree、不建分支，退出码 3，和 drop 先跑完时的结果一样。

## 例子

- `C-5` 只在 `change/C-5-x` 上；start 读完分支、拿认领之前，另一个会话的 drop 删掉了分支和 worktree → start 退出码 3，没有 `change/C-5-x` 分支，没有 `C-5` 的 worktree，没有 `C-5` 的认领
- 同样情形，分支还在、只是 worktree 被删了 → start 成功，从分支重建 worktree（BR-2107）
