title: 有未处理的评审意见时，canon work start 不开新变更
status: active
business: 开工
---

## 规则

`canon work start` 要开始一个还没开始过的变更（`--title` 新建的，或 main 上还没有 `change/<编号>` 分支的已有变更）时，先看欠账：未处理的评审意见（BR-2433；有未回答裁决问题的那些不算，它们等的是负责人，BR-2461）。失败的合入后评审不算欠账：评审命令的额度用完时每次评审都会失败，那时挡住所有开工没有用；它照样在 `canon brief` 里提示，验收照样不通过（BR-2462）。有欠账 → 不开工，退出码 1，不分配编号、不建工作树、不认领；信息写明有几条意见并列出编号（最多 10 个），说明用杂务（`canon chore start`）或欠账所属的变更去处理；事件表记一条 `start.refuse`，原因 `debt`。

不受限的：继续一个已经开始过的变更（它有自己的分支）、`canon work start --fix-main`、`canon chore start`。

依据：负责人在 canon human #36 选了“B 欠账时不开新活”。

## 例子

- 有 2 条未处理的评审意见，`canon work start --title 新功能` → 退出码 1，输出列出这两条的编号和 `canon chore start`，没有新的变更编号和工作树，事件表有 `start.refuse`，原因 `debt`
- 有 11 条未处理的意见 → 信息列出前 10 个编号，后面跟 `…`
- 同样的欠账，`canon work start C-5`，`C-5` 在 main 上、还没有 `change/C-5` 分支 → 退出码 1，原因 `debt`
- 同样的欠账，`canon chore start "修评审意见"` → 照常开工
- 同样的欠账，继续已经有分支 `change/C-7` 的 `C-7` → 照常开工
- 同样的欠账，`canon work start --fix-main` → 照常开工
- 唯一一条未处理的意见带着没回答的裁决问题 → 照常开工
- 一次合入后评审失败（例如额度用完）、还没 `--again`，没有未处理的意见 → 照常开工
- 没有欠账 → 照常开工
