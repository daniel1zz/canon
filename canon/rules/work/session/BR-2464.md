## 规则

`canon work start` 要开始一个还没开始过的变更（`--title` 新建的，或 main 上还没有 `change/<编号>` 分支的已有变更）时，先看欠账：未处理的评审意见（BR-2433；有未回答裁决问题的那些不算，它们等的是负责人，BR-2461），和失败后还没重跑成功的合入后评审（BR-2449 列出的那些）。有欠账 → 不开工，退出码 1，不分配编号、不建工作树、不认领；信息逐项列出欠账（意见最多列 10 个编号），说明用杂务（`canon chore start`）或欠账所属的变更去处理；事件表记一条 `start.refuse`，原因 `debt`。

不受限的：继续一个已经开始过的变更（它有自己的分支）、`canon work start --fix-main`、`canon chore start`。

依据：负责人在 canon human #36 选了“B 欠账时不开新活”。

## 例子

- 有 2 条未处理的评审意见，`canon work start --title 新功能` → 退出码 1，输出列出这两条的编号和 `canon chore start`，没有新的变更编号和工作树，事件表有 `start.refuse`，原因 `debt`
- 同样的欠账，`canon chore start "修评审意见"` → 照常开工
- 同样的欠账，继续已经有分支 `change/C-7` 的 `C-7` → 照常开工
- 同样的欠账，`canon work start --fix-main` → 照常开工
- 唯一一条未处理的意见带着没回答的裁决问题 → 照常开工
- 一次合入后评审失败、还没 `--again` → `canon work start --title x` 退出码 1，信息含 `canon work review-landed --again`
- 没有欠账 → 照常开工
