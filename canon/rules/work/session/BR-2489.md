## 规则

`canon work start` 带 `--urgent --relayed "<负责人的原话>"` 时，即使有 BR-2464 说的欠账，这个变更也照常开工（新建的、或 main 上还没开始过的已有变更都一样）。开工时输出一行 `urgent (relayed by <操作者>: "<原话>"): starts although review work is owed (BR-2489)`，并列出仍然欠着的账；事件表记一条 `start.urgent`，写下原话 `relayed` 和欠账 `owed`。欠账不因此清掉，下一个不带 `--urgent` 的新变更照样被 BR-2464 拦下。

这个选项只在负责人在对话里要求马上做这件事时用，原话照录。canon 不核对原话（同 D-6 对转述人话的做法），所以它留在事件表里供人查。

用法错误（退出码 2，什么都不开）：`--urgent` 没有 `--relayed`，或原话为空或只有空白；只给 `--relayed` 不给 `--urgent`；`--urgent` 和 `--fix-main` 一起给（`--fix-main` 本来就不受欠账限制）。没有欠账时 `--urgent` 不起作用，照常开工。

BR-2464 的拒绝信息末尾写明这个选项：`work the owner asked for now in the conversation starts with --urgent --relayed "<the owner's own words>" (BR-2489)`。

## 例子

- 有 2 条未处理的意见，`canon work start --title "Hotfix" --urgent --relayed "先修这个线上 bug"` → 开工，输出含 `urgent (relayed by agent:a: "先修这个线上 bug")` 和 `2 open review finding(s)`；事件表有一条 `start.urgent`
- 同上之后再 `canon work start --title "Next"` → 仍被 BR-2464 拦下
- `canon work start --title "Hotfix" --urgent` → 退出码 2，信息含 `--urgent needs --relayed`
- `canon work start --title "Hotfix" --relayed "now"` → 退出码 2

## 验收

负责人用 `canon events --kind start.urgent` 查每一次 `--urgent` 开工：每条记录有操作者、变更和 `relayed` 原话。负责人对照自己在对话里说过的话，确认每条都出自自己的要求；发现不是自己要求的，就在对话里指出，并在 `canon/rules/work/session/BR-2489.md` 或相关变更里记下处理结果。
