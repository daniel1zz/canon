## 规则

canon 往协调数据库的事件表（`events`）写的每一条事件，都在 `canon` 列记下写它的 canon 是哪个构建：发布出去的二进制记它发布时的 main 提交（发布脚本构建时用 `bun build --define CANON_BUILD=<提交>` 编进去），从源码运行（测试、在 checkout 里 `bun src/invocation/main.ts`）时记 `dev`。旧的数据库照 BR-2078 补上这一列，补列前写的事件这一列为空。它和执行者（BR-2023）、worktree（BR-2131）一起说明一条事件是谁、在哪、用哪个 canon 写的，按版本统计时不必靠发布时间推断（D-116）。

## 例子

- 从源码运行，写一条事件 → 它的 `canon` 是 `dev`
- 用发布时同样的 `--define`（提交 `970904dfd00b37f7`）构建出的程序，报告的构建是 `970904dfd00b37f7`
