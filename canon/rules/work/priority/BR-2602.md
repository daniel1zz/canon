## 规则

每个变更有一个档位：`P0`（必须立刻做）、`P1`（紧急）、`P2`（普通，没设时就是它）、`P3`（有空再做）。档位记在协调数据库里，设了立刻对所有 worktree 生效（D-155）。修复 main 的变更（BR-2221）总是 `P0`，它的档位不能设。

- `canon priority set <C-n> <P1|P2|P3> --reason "<为什么>"`：主会话设档位，记为主 agent 定的；
- `canon priority set <C-n> <P0|P1|P2|P3> --relayed "<负责人的原话>"`：记为负责人定的，原话不核对（D-73）；
- `canon priority set <C-n> --clear --reason "<为什么>"` 或 `--clear --relayed "<原话>"`：回到 `P2`。

拒绝时退出码 1、协调数据库不变、记 `priority.refuse` 事件写明原因：worker 运行（`worker`）；主 agent 设 `P0`（`p0-owner-only`）；主 agent 把负责人定的档位调低或清掉（`owner-set`，提示写出负责人定的档位和原话）；改修复 main 的变更（`fix-main`）；变更已经合入或放弃（`closed`）。`--reason` 和 `--relayed` 都没有、都有、或只有空白时退出码 2。成功记 `priority.set`（变更、档位、之前的档位、谁定的、理由或原话），输出一行 `C-n: P1 (by the main agent: <理由>)`。主 agent 调高负责人定的档位可以，之后算主 agent 定的，负责人原来定的档位作为下限留着。`canon backlog urgent <C-n> --relayed` 等同负责人设 `P1`（BR-2363）。

## 例子

- 主会话 `canon priority set C-5 P1 --reason "阻塞 C-7"` → 退出码 0，`C-5: P1 (by the main agent: 阻塞 C-7)`，事件 `priority.set`
- 主会话 `canon priority set C-5 P0 --reason "x"` → 退出码 1，`p0-owner-only`
- `canon priority set C-5 P0 --relayed "这个最急"` → 退出码 0，记为负责人定的
- 负责人定了 `C-6` 为 `P1`；主会话 `canon priority set C-6 P3 --reason "x"` → 退出码 1，`owner-set`，提示写出 `P1` 和原话；主会话设 `P0` 以外的更高档 → 不适用（`P1` 之上只有 `P0`）
- 负责人定了 `C-6` 为 `P1`；主会话也设 `P1` → 退出码 0，什么都不改，仍算负责人定的（`backlog urgent` 的标记也留着）
- 负责人定了 `C-6` 为 `P2`；主会话设 `P1` → 成功；之后主会话设 `P3` → 退出码 1，`owner-set`（下限是 `P2`）
- worker 运行 → 退出码 1，`worker`
- 修复 main 的变更 `C-9` → 退出码 1，`fix-main`
- 没有 `--reason` 也没有 `--relayed` → 退出码 2
- `canon backlog urgent C-8 --relayed "先合这个"` → `C-8` 是负责人定的 `P1`
