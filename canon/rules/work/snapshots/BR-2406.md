---
id: BR-2406
title: 快照不放进密钥文件：按文件名认出的密钥文件留在快照外并写明
status: retired
---

## 规则

文件名（路径的最后一段）在下面这张密钥文件名单上的文件，按 BR-2182 对超过大小上限的文件的办法留在快照外并在提交说明里写明，不论大小；除了 BR-2182 说的改动过和未跟踪的文件，已暂存的也算。名单固定写在代码里，没有配置项：

- `.env`，以及以 `.env.` 开头的名字；但 `.env.schema`、`.env.example`、`.env.sample`、`.env.template` 不算，它们只写有哪些配置、不含值，照常放进快照。
- 以 `.pem`、`.key`、`.p12`、`.pfx` 结尾的名字。
- `id_rsa`、`id_ecdsa`、`id_ed25519`，以及它们加任意后缀的名字（如 `id_rsa.old`）；但以 `.pub` 结尾的公钥不算。
- `keys.txt`（age 的私钥文件）。

名单只看文件名，不区分大小写（macOS、Windows 上读 `.env` 的程序打开的就是 `.ENV`），不看所在目录，也不看内容；被 git 忽略的文件本来就不在快照里（BR-2182），和名单无关。工作区里的文件不动。

## 例子

- 未跟踪的 `.env.local` 和 `notes.txt` → 快照里没有 `.env.local`，有 `notes.txt`；提交说明有 `left out` 和 `.env.local`；之后 `.env.local` 还在工作区里、内容没变
- 未跟踪的 `.env.example`、`.env.schema`、`.env.sample`、`.env.template` → 都在快照里
- 未跟踪的 `config/.env` → 不在快照里（只看文件名）；名字是 `env.txt`、`my.env` 的 → 在快照里
- 未跟踪的 `certs/server.pem`、`tls.key`、`cert.p12`、`cert.pfx` → 都不在快照里
- 未跟踪的 `id_ed25519`、`id_rsa.old` → 不在快照里；`id_ed25519.pub` → 在快照里
- 未跟踪的 `keys.txt` → 不在快照里
- 未跟踪的 `.ENV`、`SERVER.PEM`、`ID_RSA` → 不在快照里（不区分大小写）；`.ENV.EXAMPLE`、`ID_RSA.PUB` → 在快照里
- HEAD 里有跟踪文件 `.env.production`（内容 `A=1`），改成 `A=2` → 快照里的 `.env.production` 仍是 `A=1`，提交说明写明它；工作区里仍是 `A=2`
- 新建 `.env` 并 `git add`，工作区里内容和暂存的一样 → 快照里没有 `.env`
- 只有 `.env.local` 一个未提交的改动 → 快照的树和 HEAD 一样，不新建快照（`same as the last snapshot`）
