## 规则

`canon snapshot take` 对当前目录所在的 git worktree 做快照；带 `--hook` 时从标准输入读宿主的 PreToolUse 输入，对其中 `cwd` 所在的 worktree 做（读不出 `cwd` 时用当前目录），并且对同一个仓库里认领表中持有者是发出这次调用的执行者的其他 worktree 也做：输入里有 `agent_id`（子 agent 的调用）时持有者是 `agent:<会话>:<agent_id>`，没有（主会话的调用）时恰好是 `agent:<会话>`；会话取输入里 `session_id` 的前 8 个字符（没有时取环境变量 `CLAUDE_CODE_SESSION_ID`）。同会话的其他执行者认领的 worktree 不由这次调用做，它们各自的调用会做。这样 `cwd` 是会话的起始目录（常是主 checkout）、命令却 `cd` 进了 `canon work start` 建的 worktree 时，那个 worktree 的工作也有快照。别的会话认领的 worktree 也不做；不看命令里写了什么目录；不带 `--hook` 时只做当前目录的那一个。每个 worktree 各自按下面的条件判断，没有改动的什么都不写。只在这个 worktree 是 canon 项目（根目录有 `canon/config.yaml`）、并且 `git status --porcelain` 不为空时才做；内容和这个 worktree 最近一个快照相同、或和 HEAD 相同时不新建。

Codex 的 hook 带 --runtime codex，按 BR-2023 的 Codex 格式确定持有者：会话取 hook 的 session_id（没有时取 Codex 环境），子 agent 归属按 BR-2023。覆盖名字按 BR-2023，快照的范围仍按第一段。

快照包含跟踪文件的改动（包括删除）和没被 git 忽略的未跟踪文件；被忽略的文件不包含。改动过或未跟踪的文件大于 5 MB 时不放进快照（跟踪文件保留 HEAD 的版本），提交说明里写明留下了哪些。做快照不改 worktree 的文件，也不改它自己的索引：`git status` 前后一样，索引文件一个字节都不变，也不拿索引的锁（`.git/index.lock`），所以同时在这个 worktree 里运行的 git 命令不会因为锁被占而失败。

带 `--hook` 成功时什么都不输出、退出码 0；出错时退出码非 0、错误写到标准错误，hook 命令里的 `|| echo` 接着输出一条给用户看的 `systemMessage`（BR-2185），Bash 调用照常进行。不带 `--hook` 时输出一行：做了快照就写 ref，没做就写原因。

## 例子

- 认领表文件损坏、读不出来，`cwd` 有未提交改动 → `cwd` 的 worktree 照样快照，之后命令报错、退出码非 0（hook 的 `|| echo` 给用户一条提示）
- 会话里没有 `session_id`、环境变量里也没有 `CLAUDE_CODE_SESSION_ID` → 只快照 `cwd`；只有环境变量时按它找认领
- 认领着的 worktree 目录已经不在 → 跳过，不报错
- 改了跟踪文件 `a.txt`、新建了未跟踪的 `new.txt`、`.env` 被忽略 → 新快照里 `a.txt` 是改过的内容，有 `new.txt`，没有 `.env`；之后 `git status --porcelain` 和之前一样
- `.env` 没有被 git 忽略，未提交内容是 `TOKEN=demo` → 快照包含它；被 git 忽略的 `.env` 不包含，不按文件名另行过滤
- 快照之后 `git checkout a.txt` → `git show <ref>:a.txt` 仍是改过的内容
- 工作区干净 → 不新建快照，不带 `--hook` 时输出 `no snapshot: nothing uncommitted`
- 什么都没再改，又调用一次 → 不新建快照（`same as the last snapshot`）
- 删除了跟踪文件 `b.txt` → 快照里没有 `b.txt`
- 未跟踪的 `big.bin` 有 6 MB → 快照里没有它，提交说明有 `left out` 和 `big.bin`；`small.txt` 照常在快照里
- `--hook`，标准输入是 `{"cwd":"<另一个 worktree>"}` → 快照的是那个 worktree
- 跟踪文件 `app.txt` 内容没变、修改时间变了（索引里的 stat 信息过时），又有别的未提交改动 → 做完快照，`.git/index` 的内容和做之前完全一样
- `--hook`，输入没有 `agent_id`，`cwd` 是主 checkout，会话 `abcd1234…` 认领了 worktree `C-11`（持有者 `agent:abcd1234`），它有未提交改动 → 有新快照；持有者是 `agent:abcd1234:worker` 的 `C-12` 也有改动 → 没有新快照
- 同上，另有持有者 `agent:abcd1234`、没有改动的 `C-13` → 没有新快照
- `--hook`，输入有 `agent_id: worker`，`C-14`（持有者 `agent:abcd1234:worker`）有改动 → 有新快照；同会话的子 agent `other` 的 `C-15` 和主会话的 `C-16` 有改动 → 都没有新快照
- 同上，`C-21` 由会话 `ffff0000` 认领、有未提交改动 → 没有快照；持有者 `agent:abcd1234x`（只是前缀相同）的 `C-22` 也没有
- `--hook`，`cwd` 就是已认领的 worktree `C-31` → 它只做一个快照
- 不带 `--hook`，当前目录是主 checkout，别的 worktree 被本会话认领并有改动 → 只做主 checkout 的
- 目录不在 git 仓库里，或仓库里没有 `canon/config.yaml` → 不做快照，退出码 0

- Codex session-a 的 child-1 在主 checkout 调用 hook → agent:codex-session-a:child-1 认领的 worktree 有快照，主会话和 child-2 的没有
