## 规则

`canon human record` 从标准输入读 Claude Code 给 PostToolUse hook 的数据（JSON 对象），`tool_name` 是 `AskUserQuestion` 时，写一条 `human.asked` 事件。操作者按 BR-2023 的顺序确定，只是会话 id 取自数据里的 `session_id`（hook 的环境里不一定有 `CLAUDE_CODE_SESSION_ID`）：设置了 `CANON_ACTOR` 时就是它（在 Claude Code 里必须是 `agent:` 开头，否则按 BR-2023 拒绝）；没有设置时是 `agent:` 加 `session_id` 的前 8 位，和同一会话里不设 `CANON_ACTOR` 的命令认出的操作者一样。事件内容是完整的 `session_id`、`tool_use_id`、每个问题的文字和人的回答（`tool_response.answers`：问题文字对应选中的选项，多选时选项用逗号连起来）、人自己打的回答（`tool_response.response`，没有时为空）和备注（`tool_response.annotations` 里每个 `notes`）。它不输出任何东西、不拦截提问工具。数据不是合法 JSON、不是对象、`tool_name` 不是 `AskUserQuestion`、没有 `session_id`、没有 `tool_response.answers` 对象，或某个回答、`response`、某条 `notes` 存在但不是字符串时，以退出码 2 失败并写明原因，什么也不写。

## 例子

- 数据是 `{"session_id":"3d606482-8b99…","tool_name":"AskUserQuestion","tool_use_id":"toolu_1","tool_input":{…},"tool_response":{"questions":[…],"answers":{"Ship it?":"yes"}}}` → 没有设置 `CANON_ACTOR` 时退出码 0，没有输出，事件表多一条 `human.asked`，操作者 `agent:3d606482`，内容里有问题 `Ship it?` 和回答 `yes`
- 人在 Other 里自己打了字：`tool_response.response` 是 `先别发` → 事件内容的 `response` 是 `先别发`
- 回答带备注：`annotations` 是 `{"Ship it?":{"notes":"周五再发"}}` → 事件内容的 `notes` 是 `["周五再发"]`
- `tool_name` 是 `Bash` → 退出码 2，事件表没有新的 `human.asked`
- 标准输入是 `not json` → 退出码 2，提示里写明不是合法 JSON
- 没有 `tool_response.answers` → 退出码 2，什么也不写
- 同样的数据，环境里 `CANON_ACTOR=agent:89d45e3f:add88b47` → 事件的操作者是 `agent:89d45e3f:add88b47`
- `tool_response.response` 是 `1`（数字），或 `annotations` 里某个 `notes` 是 `true` → 退出码 2，什么也不写
