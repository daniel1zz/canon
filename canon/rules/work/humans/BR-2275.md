## 规则

`canon human record` 从标准输入读 Claude Code 给 PostToolUse hook 的数据（JSON 对象），`tool_name` 是 `AskUserQuestion` 时，写一条 `human.asked` 事件。操作者按 BR-2023 的顺序确定，只是会话 id 取自数据里的 `session_id`：设置了 `CANON_ACTOR` 时就是它（环境里有 `CLAUDECODE=1` 时必须是 `agent:` 开头，否则按 BR-2023 退出码 2，`human.asked` 和 `human.asked.refuse` 都不写）；没有设置时是 `agent:` 加 `session_id` 的前 8 位，和同一会话里不设 `CANON_ACTOR` 的命令认出的操作者一样。没有设置 `CANON_ACTOR` 时不看 `CLAUDECODE`，是有意的例外：数据来自 Claude Code 的 hook，写它的一定是 agent 会话。

事件内容（D-47）：完整的 `session`（`session_id`）、`tool_use_id`、`transcript_path`、`questions`（`tool_response.questions` 里每个问题按顺序一项：`question` 是问题文字，`answer` 是 `tool_response.answers` 里这段文字对应的回答，`note` 是 `tool_response.annotations` 里这段文字的 `notes`；没有的写 `null`；`answers` 里有、`questions` 里没有的问题接在后面）、`response`（人自己打的回答 `tool_response.response`）和 `afk_timeout_ms`（`tool_response.afkTimeoutMs`，原样保存，不解释）；`tool_use_id`、`transcript_path`、`response`、`afk_timeout_ms` 数据里没有时是 `null`（缺了 `tool_response.questions` 或 `answers` 不是记成 `null`，而是按下面的 `malformed` 拒绝）。多选的回答是字符串数组时，用 `, ` 连起来记。它不输出任何东西、不拦截提问工具。

数据不是合法 JSON、不是对象、`tool_name` 不是 `AskUserQuestion`、没有 `session_id`、没有 `tool_response.answers` 对象、`tool_response.questions` 不是每项都有字符串 `question` 的数组，或某个回答不是字符串也不是字符串数组、`response`、某条 `notes`、`tool_use_id`、`transcript_path` 存在但不是字符串、`afkTimeoutMs` 存在但不是数字时，以退出码 2 失败并写明原因，不写 `human.asked`，改写一条 `human.asked.refuse`（BR-2026），内容是原因（`invalid-json`、`not-object`、`not-question-tool`、`no-session`、`malformed` 之一）和数据里的 `session_id`（认不出时为 `null`）；认不出会话时操作者按 BR-2023 确定。

Codex 的 hook 带 --runtime codex，tool_name 必须是 request_user_input。问题从 tool_input.questions 按 id 和 question 读取，回答从 tool_response.answers 中同 id 的 answers 字符串数组读取，以逗号和空格连接；空数组的 answer 记 null，不猜答案。问题 id 重复、回答指向未知 id、类型不符时按 malformed 拒绝；以 hook 数据的 session_id 与 agent_id 替代环境里的会话标识，再按 BR-2023 记操作者；覆盖的优先次序和拒绝 human 覆盖按 BR-2023。isSecret 为 true 的问题只记问题文字、回答记 null，不把秘密写进事件。不会把异步工具仅返回的请求 id 当成人的回答。

## 例子

- 数据是 `{"session_id":"3d606482-8b99…","tool_name":"AskUserQuestion","tool_use_id":"toolu_1","transcript_path":"/x/t.jsonl","tool_input":{…},"tool_response":{"questions":[{"question":"Ship it?",…}],"answers":{"Ship it?":"yes"}}}` → 没有设置 `CANON_ACTOR` 时退出码 0，没有输出，事件表多一条 `human.asked`，操作者 `agent:3d606482`，`questions` 是 `[{"question":"Ship it?","answer":"yes","note":null}]`，`response` 和 `afk_timeout_ms` 是 `null`，`transcript_path` 是 `/x/t.jsonl`
- 人没有回答具体的问题，自己打了一段回复：`tool_response.response` 是 `先别发` → 事件内容的 `response` 是 `先别发`
- 回答带备注：`annotations` 是 `{"Ship it?":{"notes":"周五再发"}}` → `Ship it?` 那一项的 `note` 是 `周五再发`
- 多选回答是 `["a","b"]` → 那一项的 `answer` 是 `a, b`
- `afkTimeoutMs` 是 `60000` → `afk_timeout_ms` 是 `60000`
- 同样的数据，环境里 `CANON_ACTOR=agent:89d45e3f:add88b47` → 事件的操作者是 `agent:89d45e3f:add88b47`
- 同样的数据，环境里 `CLAUDECODE=1`、`CANON_ACTOR=human:x` → 退出码 2，不写 `human.asked`，也不写 `human.asked.refuse`
- `tool_name` 是 `Bash` → 退出码 2，没有新的 `human.asked`，多一条 `human.asked.refuse`，原因 `not-question-tool`，`session` 是数据里的 `session_id`
- 标准输入是 `not json` → 退出码 2，提示里写明不是合法 JSON；`human.asked.refuse` 的原因是 `invalid-json`，`session` 是 `null`
- 没有 `tool_response.answers`，或没有 `tool_response.questions` → 退出码 2，原因 `malformed`
- `tool_response.response` 是 `1`（数字），或 `annotations` 里某个 `notes` 是 `true` → 退出码 2，原因 `malformed`

- Codex 问题 id 为 ship、文字 Ship it?，回答 ship.answers=[yes] → human.asked 的问题文字仍为 Ship it?、回答 yes，执行者为 `agent:codex-session-a`（输入的 session_id 是 session-a）
- 回答是未知问题 id、或 answers 是字符串而非数组 → 退出码 2，只有 human.asked.refuse，无 human.asked
- isSecret 为 true、回答包含凭证 → 事件中只记问题，回答 null

- Codex 输入 session_id=session-a、agent_id=child-1，环境里残留另一会话 id → 仍记 agent:codex-session-a:child-1
- Codex hook 中 CANON_ACTOR=human:x → 退出码 2，无 human.asked 和 human.asked.refuse

- Codex 回答 ship.answers=[] → answer=null；ship.answers=1 或 ship.answers="yes" → malformed，退出码 2，无 human.asked。

- Codex 工具只返回 `{"request_id":"pending-1"}`、没有 `answers` → 退出码 2，原因 malformed，不写 human.asked，不能作为转述的回答佐证。
