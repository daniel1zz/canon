## 规则

`canon human answer <编号> <回答>` 有两种合法的回答方式：`human:` 操作者在交互式终端里直接回答；或者 agent 用 `--relayed "<人的原话>"` 转述人在它的会话里说的话，记录为转述（回答者是这个 agent，并保存原话）。其他情况都以退出码 2 拒绝，并写一条 `human.answer.refuse` 事件，原因各不相同（BR-2026）：`human:` 操作者带 `--relayed`（原话是空的也算带了）→ `human-relayed`；`human:` 操作者没有 TTY → `no-tty`；agent 不带 `--relayed`，或原话去掉首尾空白后是空的 → `not-human-no-relay`（agent 有没有 TTY 都一样）。`canon human pending --all` 把转述的回答显示成 `<agent> relaying the human: "<原话>"`，和人直接回答的区分开。canon 不能从技术上分辨转述和编造，所以不假装能阻止，而是如实记录（D-6）。

## 例子

- agent 会话（没有 TTY）执行 `canon human answer 1 yes` → 退出码 2，提示要么在终端回答，要么用 `--relayed`
- agent 执行 `canon human answer 1 yes --relayed "好的，发吧"` → 回答成功，显示 `→ yes (agent:x relaying the human: "好的，发吧")`
- `human:dz` 在终端里执行 `canon human answer 1 yes` → 回答成功，显示 `→ yes (human:dz)`
- `human:dz` 加了 `--relayed` → 退出码 2，原因 `human-relayed`
- `human:dz` 没有 TTY，执行 `canon human answer 1 yes --relayed ""` → 退出码 2，原因 `human-relayed`，问题仍然没有回答
- agent 没有 TTY，执行 `canon human answer 1 yes` → 退出码 2，事件表多一条原因为 `not-human-no-relay` 的 `human.answer.refuse`
- `human:dz` 没有 TTY，执行 `canon human answer 1 yes` → 退出码 2，原因 `no-tty`
