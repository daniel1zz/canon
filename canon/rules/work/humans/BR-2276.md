## 规则

下文的会话标识和记录 hook 位置在 Claude 下分别为 CLAUDE_CODE_SESSION_ID 与主 checkout 的 .claude/settings.json；在 Codex 下分别为 BR-2023 确定的所属会话与主 checkout 的 .codex/hooks.json 中 BR-2459 的提问记录 hook。以下按“会话标识”“记录 hook”统一判断，先后顺序不变。

agent 用 `canon human answer <编号> <回答> --relayed "<原话>"` 记下转述的回答时（BR-2021），canon 用会话标识认出会话，对照这个会话的 `human.asked` 记录（BR-2275，按记录里的 `session`，不看操作者），按下面的顺序取第一个成立的标记（D-47）：

1. `no-session`：没有会话标识。
2. `match` 或 `differs`：这个会话里有记录包含第 n 个问题，即记录里某个问题的文字去掉首尾空白后和第 n 个问题的文字（去掉首尾空白）完全相同；取其中最近的一条。原话去掉首尾空白后，和这个问题的回答、这个问题的备注，或者这条记录只问了这一个问题时人自己打的回答（`response`，各自去掉首尾空白）完全相同，就是 `match`，否则是 `differs`。只用这个问题的回答和备注，不用同一次提问里别的问题的；一次问了几个问题时，`response` 不属于其中任何一个，不用。比较的是原话和记录，不是存下的 `<回答>`。
3. `record-failed`：这个会话有 `human.asked.refuse`（BR-2275）。
4. `unasked`：这个会话有 `human.asked`，但都不包含第 n 个问题。
5. `no-hook`：没有对应宿主的记录 hook（文件读不出来也算没有）。
6. `no-record`：这个会话一条 `human.asked`、`human.asked.refuse` 都没有，而有对应宿主的记录 hook。

D-47 之前的记录没有 `questions` 时，用它的 `answers` 里的问题和回答，不用它的 `notes`。标记存进这个问题，也写进 `human.answer` 事件的 `witness`。对照本身不拦截：不管哪种标记，回答照样记下，退出码 0（问题带选项时，回答和原话的关系由 BR-2021 检查，不是这里）。人直接回答的不对照，`witness` 为空。

## 例子

- 第 1 个问题是 `Ship it?`；会话 `3d606482-…` 的记录里 `Ship it?` 的回答是 `yes`；在这个会话里执行 `canon human answer 1 yes --relayed " yes "` → 退出码 0，`witness` 是 `match`
- 同样的记录，`--relayed "好的，发吧"` → `differs`
- 记录里只有问题 `Proceed?`，回答 `yes`，第 1 个问题是 `Ship it?`，`--relayed "yes"` → `unasked`，不是 `match`
- 一次提问里有 `Ship it?`（回答 `no`）和 `Proceed?`（回答 `yes`），转述 `Ship it?` 的 `--relayed "yes"` → `differs`
- 记录里 `Ship it?` 的回答是 `yes`，后来同一会话又问了一次 `Ship it?`，回答 `no`，`--relayed "no"` → `match`；`--relayed "yes"` → `differs`（取最近的一条）
- 记录只问了 `Ship it?`，`response` 是 `先别发`；或 `Ship it?` 的备注是 `周五再发`；`--relayed` 用这两句之一 → `match`
- 一次提问问了 `Ship it?`、`Proceed?` 和 `Merge?`，`response` 是 `好`，转述 `Ship it?` 的 `--relayed "好"` → `differs`，不是 `match`
- 问题没有选项：`canon human answer 1 no --relayed "yes"`，记录里 `Ship it?` 的回答是 `yes` → `match`（标记只说原话对得上；`pending --all` 把回答 `no` 和原话 `yes` 并排显示，BR-2289）
- 记录是另一个会话的（`session` 不同），哪怕操作者同名 → 不算这个会话的；这个会话没有别的记录、hook 已装 → `no-record`
- 转述时 `CANON_ACTOR=agent:k`，记录的操作者是 `agent:3d606482`，会话相同 → 照样对照
- 环境里没有 `CLAUDE_CODE_SESSION_ID` → `no-session`
- 这个会话只有一条 `human.asked.refuse` → `record-failed`
- 这个会话什么记录都没有，`.claude/settings.json` 里没有记录 hook → `no-hook`；有记录 hook → `no-record`
- `human:dz` 在终端里直接回答 → 不对照，`witness` 为空

- Codex 仅设置 CODEX_THREAD_ID=session-a、有原生提问记录 hook、当前会话无记录 → no-record；移除该 hook → no-hook；Claude 配置是否存在不改变结果。
- Codex 子线程的启动归属为 session-a，hook 记录也是 session-a 的同一问题和 yes → 转述 yes 的 witness=match。
