## 规则

`canon stats` 对每次合入检查的拒绝，看同一个变更之后发生了什么，归入一类：之后合入成功且自己的改动和被拒时不同 → `changed`（拦下了真问题）；之后合入成功且改动相同 → `same`（疑似误拒）；之后没有合入成功，但变更被放弃（`canon work drop` 真正删除了它，或状态改为 dropped；`canon work drop` 被拒绝、什么都没删时不算）→ `abandoned`；之后既没有合入成功也没有被放弃（包括又被拒绝了几次）→ `pending`；拒绝没有记录变更编号，或者记录里没有改动指纹 → `unknown`。“自己的改动”指从和 main 的分叉点到 HEAD、`canon/changes` 以外已提交改动的指纹（零上下文 diff 的 `git patch-id`），rebase 到新的 main 不会改变它。

## 例子

- `C-1` 因 floor 被拒，改了代码后合入成功 → 这次拒绝算 `changed`
- `C-2` 因评审被拒，只改了 `canon/changes/C-2.md` 就合入成功 → 算 `same`
- `C-3` 被拒后执行了 `canon work drop C-3` → 算 `abandoned`
- `C-4` 被拒后又被拒一次，还没合入成功 → 两次都算 `pending`
- `C-5` 被拒后 `canon work drop C-5` 因存档失败什么都没删 → 算 `pending`
- 拒绝发生在没有认领的 worktree 里，没有变更编号 → 算 `unknown`
