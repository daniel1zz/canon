---

## 规则

main 上还没有任何已完成变更带通过记录时，加 `--finish` 的关闭提交除了 BR-2242 的记录，还为每条不在这个变更 `rules:` 里、生效、有会运行的测试在标题里点名它（同 BR-2005 的认法）的规则写一条 `<行为哈希> migration`：迁移时已有的测试。只靠 `untested:`、没有测试点名的生效规则不写迁移记录，它们是待重新执行，直到某个变更在 `rules:` 里列出它并写一行验收（BR-2241）：迁移时没有人验证过它，不能算通过。main 上已经有通过记录时，不写迁移记录；带 `migration` 的记录出现在这样的合入里时按 BR-2242 拒绝，原因 `passes`。

## 例子

- main 上没有任何 `passes`，`BR-1`、`BR-2` 生效且有测试点名，`BR-3` 生效、带 `untested:`、没有测试，`C-1` 的 `rules: []` → `C-1` 的关闭提交写 `BR-1: "<哈希> migration"` 和 `BR-2: "<哈希> migration"`，没有 `BR-3`
- 同上，`C-1` 的 `rules: [BR-1]`，`C-1` 改了 `it("BR-1: …")` → `BR-1` 记 `test`，`BR-2` 记 `migration`
- main 上已有 `C-0` 的 `passes` → `C-1` 不写迁移记录
- main 上已有 `passes`，`C-1` 的文件里手写了 `BR-2: "<哈希> migration"` → 关闭提交换掉它；合入的树里还有它时拒绝，原因 `passes`
- 规则是规划中，有测试点名 → 不写迁移记录
