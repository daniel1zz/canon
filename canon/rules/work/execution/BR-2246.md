## 规则

每条不是作废的规则有一种执行状态，由读到的树里的规则和已完成变更的通过记录算出，没有手写的状态字段：

- 规划中：`status: planned`。
- 已通过（C-n）：生效，某个已完成变更有这条规则的通过记录，哈希等于它现在的行为哈希，而且这条记录算数；C-n 是这样的变更里编号最大的。
- 待 main 测试（C-n）：生效，有哈希相同的记录，但都还不算数；C-n 同上。
- 待重新执行：生效，没有哈希相同的记录。

记录算不算数看项目的 `floor_timing`：`before`（先测再合）时 main 上每个提交合入前都测过，记录都算数；`after`（先合后测，D-31）时只有 `refs/canon/green`（最近一次后台测试通过的提交，BR-2222）里同一个变更文件也有这一项（同一规则、同一哈希）才算数；没有 `refs/canon/green` 时一条都不算。这样，没测过的提交上的记录永远不会显示为已通过。

## 例子

- `BR-1` 是 `planned` → 规划中
- `BR-1` 生效，`C-3` 和 `C-7` 都有和它现在哈希相同的记录，`floor_timing: before` → 已通过（C-7）
- `BR-1` 生效，`C-3` 的记录是旧哈希（之后有人改了例子）→ 待重新执行
- `floor_timing: after`，`C-7` 的记录哈希相同，`refs/canon/green` 里 `C-7` 文件也有这一项 → 已通过（C-7）
- `floor_timing: after`，`C-7` 刚合入，`refs/canon/green` 还停在它之前的提交 → 待 main 测试（C-7）
- `floor_timing: after`，没有 `refs/canon/green` → 有记录的规则都是待 main 测试
- `BR-1` 作废 → 没有执行状态，不列出
