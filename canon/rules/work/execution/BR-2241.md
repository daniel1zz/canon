title: 加 --finish 合入时，要执行的规则每条都要有证据
status: active

## 规则

加 `--finish` 合入一个未完成的变更时，在做关闭提交之前，它 `rules:` 里每条要执行的规则都要有证据。要执行的规则：在工作树里是生效的，而且当前行为哈希（BR-2236）没有和别的已完成变更的任何通过记录相同（规划中、作废的规则，以及已经有相同记录的规则都不用）。证据按顺序取第一种：

1. 测试：这个变更的合入里（这次合入自己的提交，加上事件表里同一变更之前每次合入的 `base..sha`），某个测试文件（`tests` 配置或默认的测试文件）里有一行被加上、改掉或删掉，这一行落在一个会运行的、标题点名这条规则的 `test`、`it` 或 `describe` 调用里（从调用名到它的右括号，按那次合入之后的文件算；标题的认法同 BR-2005）。方式记 `test`。
2. 验收：规则带 `untested:`，变更正文的 `## 验收` 段里有一行 `- BR-n：<怎么验的> → <看到了什么>`（冒号全角半角都行，`→` 两边都不能为空）。方式记 `acceptance`。
3. 措辞：BR-2243 的情况。

有一条规则三种都没有，就拒绝合入，原因 `evidence`，不做关闭提交，信息对每条规则写出编号和可以给的证据。

## 例子

- `C-1` 的 `rules: [BR-1]`，`BR-1` 生效、没有通过记录，`C-1` 的提交在 `it("BR-1: refunds", …)` 里改了一行 → 有证据，方式 `test`
- 同上，但 `C-1` 只改了 `it("BR-2: …")` 里的一行 → 拒绝，原因 `evidence`，信息含 `BR-1`，`C-1` 还是 `open`，没有关闭提交
- `C-1` 改了一行的那个测试是 `it.skip("BR-1: …")` → 不算证据
- `C-1` 在第一次合入（不加 `--finish`）时改了 `it("BR-1: …")`，第二次加 `--finish` 合入时只改了文档 → 有证据，方式 `test`
- `BR-1` 带 `untested: 由服务商保证`，`C-1` 的 `## 验收` 有 `- BR-1：在沙箱下单退款 → 服务商后台显示已退` → 有证据，方式 `acceptance`
- 同上，验收行写成 `- BR-1：在沙箱下单退款` 没有 `→` 和结果 → 拒绝，原因 `evidence`
- `BR-1` 在 `C-1` 的 `rules:` 里，但当前行为哈希已经有 `C-0` 的通过记录（`C-1` 只改了标题）→ 不要求证据，`C-1` 不写它的记录
- `BR-1` 在 `rules:` 里，是 `planned` 或 `retired` → 不要求证据
- 不加 `--finish` 的合入 → 不做这项检查
