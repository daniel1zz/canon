## 规则

加 `--finish` 合入一个未完成的变更时，在做关闭提交之前，它每条要执行的规则都要有证据。这个变更执行的规则有两种来源：它 `rules:` 里列出的规则，以及这个变更的合入（这次合入，加上事件表里同一变更之前每次合入的 `base..sha`）改了行为哈希（BR-2236）的规则，没列进 `rules:` 也算：按规则编号比较每段合入前后两棵树里这条规则的行为哈希，不同就算改了，新建的规则（之前没有）也算；只移动文件、`## 规则` 和 `## 例子` 没变的规则哈希不变，不算。其中要执行的规则：在工作树里是生效的，而且当前行为哈希没有和别的已完成变更的任何通过记录相同（规划中、作废的规则，以及已经有相同记录的规则都不用；作废的规则没有执行状态，BR-2246）。证据按顺序取第一种：

1. 测试：这个变更的合入里（这次合入自己的提交，加上事件表里同一变更之前每次合入的 `base..sha`），某个测试文件（`tests` 配置或默认的测试文件）被改过，而这个文件在那次合入之后的内容（git blob 哈希）在记账里的报告（BR-2337、BR-2339）按下面两种方式给出证据；改过的文件在记账里没有这个内容的报告时没有证据，也按 BR-2344 报 `test-report-missing`。
   - 报告里每个 `testcase` 都有 `line`：每个改动的行（新一侧；被删掉的行算在删除点之后的那一行）归给 `line` 不大于它的、最近的那个 `testcase`（在第一个 `testcase` 之前的不归给任何测试）；那个 `testcase` 会运行，而且它的名字（BR-2005 的认法，外层 `testsuite` 名也算）点名了这条规则，就是证据，方式记 `test`。`line` 的起点和指向各框架不一样（bun 从 1 起、指向调用那一行，pytest xunit1 从 0 起、指向第一个装饰器），canon 不校正，所以紧挨着两个测试交界的那一行可能多算给后一个测试。
   - 有的 `testcase` 没有 `line`：这个文件退到文件一级，文件里有一个会运行的 `testcase` 点名这条规则就是证据，方式记 `test-file`，让评审和后来的人看得出这条证据粗。要精确到测试，项目就让它的报告带 `line`。
2. 验收：规则带 `untested:`，变更正文的 `## 验收` 段里有一行 `- BR-n：<怎么验的> → <看到了什么>`（冒号全角半角都行，`→` 两边都不能为空）。方式记 `acceptance`。
3. 措辞：BR-2243 的情况。

有一条规则三种都没有，就拒绝合入，原因 `evidence`，不做关闭提交，信息对每条规则写出编号和可以给的证据。

## 例子

- `C-1` 的 `rules: [BR-1]`，`BR-1` 生效、没有通过记录，`C-1` 的提交改了 `src/a.test.ts` 的第 12 行，报告里 `BR-1: refunds` 的 `line` 是 10、下一个测试的 `line` 是 20 → 有证据，方式 `test`
- 同上，但 `C-1` 只改了第 22 行，归给 `line` 是 20 的 `BR-2: …` → 拒绝，原因 `evidence`，信息含 `BR-1`，`C-1` 还是 `open`，没有关闭提交
- `C-1` 改了一行的那个测试在报告里带 `skipped` → 不算证据
- `C-1` 在第一次合入（不加 `--finish`）时改了 `it("BR-1: …")`，第二次加 `--finish` 合入时只改了文档 → 有证据，方式 `test`
- `BR-1` 带 `untested: 由服务商保证`，`C-1` 的 `## 验收` 有 `- BR-1：在沙箱下单退款 → 服务商后台显示已退` → 有证据，方式 `acceptance`
- 同上，验收行写成 `- BR-1：在沙箱下单退款` 没有 `→` 和结果 → 拒绝，原因 `evidence`
- `BR-1` 在 `C-1` 的 `rules:` 里，但当前行为哈希已经有 `C-0` 的通过记录（`C-1` 只改了标题）→ 不要求证据，`C-1` 不写它的记录
- `BR-1` 在 `rules:` 里，是 `planned` 或 `retired` → 不要求证据
- 不加 `--finish` 的合入 → 不做这项检查
- `C-1` 在 `BR-1: refunds`（`line` 是 10）里删掉一行，删除点在第 12 行之后，下一个测试在第 20 行 → 有证据，方式 `test`
- 改动行在文件第一个 `testcase` 的 `line` 之前（比如 `import` 那几行）→ 不归给任何测试，没有证据
- 报告里有一个 `testcase` 没有 `line`（gdUnit4 的报告），`C-1` 改了这个文件、文件里有会运行的测试 `test_BR_1` 改写成的 `BR-1` → 有证据，方式 `test-file`，关闭提交记 `BR-1: "<哈希> test-file"`
- `C-1` 改了测试文件，但记账里没有它当前内容的报告 → 没有证据，`canon check` 报 `test-report-missing`
- `C-1` 的 `rules: []`，改了 `BR-1` 的一个例子，没改测试 → 拒绝，原因 `evidence`，信息含 `BR-1`；再改一行归给 `BR-1: …` 的测试 → 关闭提交记 `BR-1: "<新哈希> test"`
- `C-1` 的 `rules: []`，只改了 `BR-2` 的 `## 规则` 措辞 → 按 BR-2243 记 `… wording`，交给合入时的措辞判断（BR-2239）
- `C-1` 的 `rules: []`，只把 `BR-1` 移到子领域目录、只改 `BR-2` 的标题、把 `BR-3` 改成 `retired` → 都不要求证据，不写记录
- `C-1` 的 `rules: []`，新建生效的 `BR-6`，没有测试也没有验收行 → 拒绝，原因 `evidence`，信息含 `BR-6`
