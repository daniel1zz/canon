## 规则

本仓库的 `test_select_command`（BR-2347）还选出自己读仓库里改动的非代码文件的测试文件（`.js`、`.ts`、`.jsx`、`.tsx`，含 `.mjs`、`.cjs`、`.mts`、`.cts`）：认得的写法有——用测试自己的位置（`import.meta.dir`、`import.meta.dirname`、`__dirname`、`new URL("字面量", import.meta.url)`）、用 `process.cwd()`（floor 在仓库根运行）、或用同一个文件里用这些赋值的变量，加字符串字面量拼出的路径（`join`、`resolve`、模板字符串）；直接传给读文件调用（`readFileSync`、`readFile`、`existsSync`、`readdirSync`、`statSync`、`Bun.file` 等）的字符串字面量（相对仓库根）；以及 `cwd:` 设成这样的路径。路径等于改动的文件、改动的文件在它下面、或者路径后面还有测试自己算出的部分而前缀是仓库根，就选出，理由 `reads <路径> (<改动的文件> changed, line <行号>)`；只是把仓库根赋给一个变量、没有读任何东西，不算。测试里临时仓库的路径、指向仓库之外的路径、别的语言的测试文件都不算；别的方式拼出的路径（别的文件里的辅助函数、运行时算出的字符串）看不到。这是 BR-2164 要求的 floor 跳过依据：只改 `floor_skip_paths` 下文件的合入，由它说有没有测试读这些文件。改动的代码文件归 BR-2347。

## 例子

- 改了 `canon/rules/x/BR-1.md`，`src/a/root.test.ts` 里有 `const ROOT = join(import.meta.dir, "..", "..");` 和 `readFileSync(join(ROOT, "canon/rules/x/BR-1.md"))` → 选出，理由 `reads canon/rules/x/BR-1.md (canon/rules/x/BR-1.md changed, line 2)`
- 同上，`src/a/partial.test.ts` 里是 `readFileSync(join(ROOT, "canon", n))`（后面还有算出的部分）→ 选出，理由 `reads canon (…)`
- `src/a/forms.test.ts` 里用 `` `${ROOT}/canon/notes/N-1.md` ``、`new URL("../../canon/rules/x.md", import.meta.url)`、`readFileSync("canon/rules/x.md")`、`join(process.cwd(), "canon/rules")`、`{ cwd: ROOT }` → 改了 `canon/rules/x/BR-1.md` 时按目录那一条选出，并因 `cwd: ROOT` 写 `reads the repository root`
- 测试里 `mkdtempSync` 建的临时仓库里写 `canon/rules/x/BR-1.md`，或路径用多出来的 `..` 指向仓库之外 → 不选出
- `tests/a.py` 里读同样的路径 → 不选出
- 改了 `docs/other.md` 和 `src/lib.ts`，没有测试按路径读它们 → 不选出
