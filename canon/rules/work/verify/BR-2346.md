---
id: BR-2346
title: canon work test 向 test_select_command 问哪些测试文件会受改动影响，命令出错时失败
status: active
---

## 规则

`canon/config.yaml` 可以写 `test_select_command`：一条 shell 命令，在仓库根运行。`canon work test`（不带 `--all`）把改动的路径（BR-2157 那一份：已提交的、未提交的、未跟踪的，删掉的也在）每行一个写进它的标准输入，读它的标准输出：每行一个测试文件路径，路径后可以用制表符写理由，空输出表示没有；选出的文件加进选择，理由写 `chosen by test_select_command: <理由>`（没写理由就是 `chosen by test_select_command`），标准错误的每一行打印成 `test_select_command: <行>`。命令打印的路径必须是存在的、匹配 `tests` 的文件；有不是的、命令以非 0 退出、或者两分钟内没有结束，`canon work test` 以退出码 4 失败，信息写明原因（不是测试文件的列出前 5 个，非 0 退出的带输出的末尾），不运行任何测试，也不退回只按别的理由选。没有配置 `test_select_command` 时，每次不带 `--all` 的运行打印一行 `no test_select_command configured: selecting only changed test files, test files whose tests name a touched rule, and always_tests; selecting by imports was removed (D-64)`，只按改动的测试文件、报告里点名本变更碰过的规则（BR-2157）和 `always_tests`（BR-2297）选。`canon check` 不运行这条命令。

## 例子

- `test_select_command: "sh select.sh"`，改了 `src/a.ts`，`select.sh` 打印 `src/b.test.ts<制表符>imports src/a.ts` → 选出 `src/b.test.ts`，理由 `chosen by test_select_command: imports src/a.ts`
- 同上，`src/b.test.ts` 自己也改了 → 理由是 `changed; chosen by test_select_command: imports src/a.ts`
- 改了 `README.md`、提交了 `docs/committed.md`、新建了 `docs/untracked.md`、删掉了 `src/d.test.ts` → 标准输入是这四行，加上变更文件
- 命令打印 `src/a.ts`（不匹配 `tests`）和 `src/gone.test.ts`（不存在）→ 退出码 4，信息含 `printed 2 path(s) that are not existing files matching \`tests\``，一个测试都不运行
- 命令以退出码 3 结束并在标准错误写了 `select exploded` → 退出码 4，信息含 `exited 3` 和 `select exploded`
- 命令只在标准错误写了 `2 file(s) spawn the CLI`，标准输出为空 → 退出码 0，输出里有 `test_select_command: 2 file(s) spawn the CLI`，没有选出文件
- 没配置 `test_select_command`，改了 `src/a.ts` → 打印那一行说明，只选改动的测试文件、点名规则的测试文件和 `always_tests`
- 没配置 `test_select_command`，带 `--all` → 全部测试文件照常运行，不打印那一行说明
