## 规则

`canon work test` 把当前 worktree 和 main 的合并基点比较，得到改过的文件：已提交的、未提交的和未跟踪的，删掉的也算。在 `tests` 配置（BR-2046）找到的测试文件里，满足下面任一条的被选出：自己被改过；它的相对导入（按 BR-2119 的读法），直接或经过别的源码文件，导入了一个改过的文件（被删掉的文件照样按 BR-2119 的方式解析，所以不带扩展名或写成 `.js` 的导入也能对上它）；它真正运行的测试名里写了本变更碰过的规则编号，碰过的规则指文件被改过的规则，加上被改过的变更文件 `rules:` 里列的规则。输出先列出每个被选出的文件和理由（`changed`、`imports <文件> (through <中间文件> → …)`、`names <规则编号>`），再说明哪些测试不会被选出、怎样全部运行。

## 例子

- 改了 `src/a.ts`，`src/b.test.ts` 有 `import "./a.ts"` → 选出 `src/b.test.ts`，理由 `imports src/a.ts`
- 改了 `src/a.ts`，`src/c.test.ts` 导入 `./b.ts`，`src/b.ts` 导入 `./a.ts` → 选出 `src/c.test.ts`，理由 `imports src/a.ts (through src/b.ts)`
- 只改了 `src/d.test.ts`，没有别的测试导入它 → 只选出 `src/d.test.ts`，理由 `changed`
- 改了规则 `BR-7` 的文件，`src/e.test.ts` 有 `it("BR-7: ...")` → 选出，理由 `names BR-7`
- `src/f.test.ts` 只有 `it.skip("BR-7: ...")`，也不导入改过的文件 → 不选出
- 删掉了 `src/a.ts`，`src/g.test.ts` 有 `import "./a"`，`src/h.test.ts` 有 `import "./a.js"` → 两个都选出，理由 `imports src/a.ts`
- 改了 `README.md`，没有测试导入它，也没有改规则 → 一个都不选出
