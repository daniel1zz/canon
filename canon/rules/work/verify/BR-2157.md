## 规则

`canon work test` 把当前 worktree 和 main 的合并基点比较，得到改过的文件：已提交的、未提交的和未跟踪的，删掉的也算。在 `tests` 配置（BR-2046）找到的测试文件里，满足下面任一条的被选出：自己被改过；它的相对导入（按 BR-2119 的读法），直接或经过别的源码文件，导入了一个改过的文件（被删掉的文件照样按 BR-2119 的方式解析，所以不带扩展名或写成 `.js` 的导入也能对上它）；它启动 CLI（用 `join(import.meta.dir, …)` 之类只由字符串写成的路径指向一个入口文件，入口文件导入的源码里有 `entry("名字", 序号, 命令, "分组")` 注册的命令，D-60），并且把某条命令的词写成字符串（`"work", "status"` 连着写，或写在同一个字符串里 `"work status --json"`；顶层的单词命令只在作为参数时才算：字符串两侧是 `(`、`[` 或 `,` 和 `,`、`)` 或 `]`，写在 JSON、YAML 文本里或更长的字符串开头（`"brief --json"`）都不算），而这条命令的模块（注册它的文件），或这个模块导入的文件，改过了；这样的测试还依赖入口文件和它导入的文件，但不依赖没被它点名的命令的模块（命令表 `src/invocation/tree.ts` 导入全部命令模块，不顺着它找）；命令词不是字符串字面量（运行时拼出来的）时看不到，这样的测试只在入口文件一侧的文件改过时选出；记账里它当前内容的（没有就是最近的旧）报告里，有会运行的测试的名字写了本变更碰过的规则编号（BR-2005 的认法，BR-2338），碰过的规则指文件被改过的规则，加上被改过的变更文件 `rules:` 里列的规则；测试里用 `join(import.meta.dir, …)` 指向 `main.ts`，却找不到这个文件，或这个入口文件和它导入的文件里没有注册任何命令时，选择无法进行，`canon work test` 以退出码 4（环境错误）失败，信息写明哪个测试指向哪个路径、缺了什么，不退回只看导入的选法；一个源码文件（测试文件也算）用 `join(import.meta.dir, …)` 之类只由字符串写成的路径读一个非代码文件或目录（比如 `src/install/install.ts` 读 `.claude/skills`），而改过的非代码文件就是这个路径或在它下面，这个源码文件算“读到了改动”：导入它（直接或间接）的测试选出，驱动的命令的模块导入它的测试也选出，理由 `reads <路径> (<改过的文件> changed, via <源码文件>[, through <中间文件> → …])`（驱动命令的写在 `drives canon <命令> (…)` 的括号里）；指向代码文件的路径归导入的读法，指向仓库根目录或这个源码文件所在目录的祖先的路径太宽，不算；以项目根目录为起点读文件的（读被测项目的）不在此列；另外，`always_tests`（BR-2297）匹配的测试文件每次都选出，理由 `always`。输出先列出每个被选出的文件和理由（`changed`、`imports <文件> (through <中间文件> → …)`、`reads <路径> (<改过的文件> changed, via <源码文件>[, through …])`、`drives canon <命令> (<改过的文件> changed[, through <中间文件> → …])`、`runs the CLI (<改过的文件> changed[, through …])`、`names <规则编号>`、`always`），并打印一行 `CLI tests: <N> file(s) spawn the CLI, <M> command(s) known`，再说明哪些测试不会被选出、怎样全部运行。

## 例子

- 改了 `src/a.ts`，`src/b.test.ts` 有 `import "./a.ts"` → 选出 `src/b.test.ts`，理由 `imports src/a.ts`
- 改了 `src/a.ts`，`src/c.test.ts` 导入 `./b.ts`，`src/b.ts` 导入 `./a.ts` → 选出 `src/c.test.ts`，理由 `imports src/a.ts (through src/b.ts)`
- 只改了 `src/d.test.ts`，没有别的测试导入它 → 只选出 `src/d.test.ts`，理由 `changed`
- 改了规则 `BR-7` 的文件，`src/e.test.ts` 的报告里有会运行的测试 `BR-7: ...` → 选出，理由 `names BR-7`
- `src/f.test.ts` 的报告里 `BR-7: ...` 带 `skipped`，也不导入改过的文件 → 不选出；`src/g2.test.ts` 没有任何记账 → 不因点名规则选出
- 删掉了 `src/a.ts`，`src/g.test.ts` 有 `import "./a"`，`src/h.test.ts` 有 `import "./a.js"` → 两个都选出，理由 `imports src/a.ts`
- 改了 `README.md`，没有测试导入它，也没有改规则 → 一个都不选出
- 改了 `.claude/skills/canon-test/SKILL.md`，`src/install/install.ts` 里有 `join(import.meta.dir, "..", "..", "..", ".claude", "skills")`，`src/install/init.test.ts` 导入它 → 选出，理由 `reads .claude/skills (.claude/skills/canon-test/SKILL.md changed, via src/install/install.ts)`；启动 CLI 并传 `"init"` 的测试（`init` 的模块导入 `install.ts`）选出，理由 `drives canon init (reads .claude/skills (.claude/skills/canon-test/SKILL.md changed, via src/install/install.ts, through src/install/commands.ts))`
- 改了 `canon/notes/n.md`，没有源码文件用字符串路径读它 → 一个都不选出
- 源码文件的路径字符串只指向一个 `.ts` 文件或仓库根目录 → 改了非代码文件也不因此选出
- 改了 `src/a/commands.ts`（注册 `work one`），`src/a/a.test.ts` 启动入口文件 `src/invocation/main.ts` 并传 `"work", "one"` → 选出，理由 `drives canon work one (src/a/commands.ts changed)`；写成 `"work one --json"` 的 `src/a/spaced.test.ts` 同样选出
- 改了 `src/a/a.ts`，`src/a/commands.ts` 导入它 → 同上两个测试选出，理由 `drives canon work one (src/a/a.ts changed, through src/a/commands.ts)`
- 改了 `src/b/commands.ts`（注册 `two`）→ 只选出传 `"two"` 的 `src/b/b.test.ts`；点名 `work one` 的测试和一条命令都没点名的 `src/c/c.test.ts` 都不选出
- 改了入口文件导入的 `src/invocation/strict.ts`，或改了命令表 `src/invocation/tree.ts` → 每个启动 CLI 的测试都选出，理由 `runs the CLI (src/invocation/strict.ts changed, through src/invocation/main.ts)`
- `src/d/d.test.ts` 里有 `"two"` 字符串，但没有指向入口文件的路径 → 改了 `src/b/commands.ts` 也不选出
- 命令模块 `src/g/commands.ts`（注册 `three`）导入命令模块 `src/h/commands.ts`（注册 `four`），改了 `src/h/commands.ts` → 点名 `"three"` 的测试选出，理由 `drives canon three (src/h/commands.ts changed, through src/g/commands.ts)`；点名 `"four"` 的测试理由是 `drives canon four (src/h/commands.ts changed)`
- 测试里有 JSON 文本 `{"two":"ok"}`，没有把 `"two"` 当参数传 → 改了注册 `two` 的模块也不选出；写成 `canon(wt, "two")` 的选出
- 测试只传 `"two --json"`（单词命令写在更长的字符串里）→ 不算点名 `two`，改了它的模块不选出
- 测试用 `...process.argv` 这样运行时才拼出命令词 → 改了某条命令的模块不选出；改了入口文件导入的 `src/invocation/strict.ts` 才选出，理由 `runs the CLI (…)`
- `src/a/a.test.ts` 指向 `src/invocation/main.ts`，而命令表里没有任何 `entry(...)` 注册 → `canon work test` 退出码 4，信息含 `src/a/a.test.ts spawns src/invocation/main.ts` 和 `the command table is empty`，一个测试都不运行
- 测试指向 `gone/main.ts`，项目里没有这个文件 → 退出码 4，信息含 `spawns gone/main.ts, which is not a file in the project`
- 本仓库自己的测试和命令表：识别出至少 50 个启动 CLI 的测试文件和至少 30 条命令；`entry(...)` 的写法或入口路径变了，这条测试就失败
- 选出结果的输出里有 `CLI tests: 4 file(s) spawn the CLI, 2 command(s) known`（数字随项目）
