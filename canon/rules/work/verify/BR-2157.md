## 规则

`canon work test` 把当前 worktree 和 main 的合并基点比较，得到改过的文件：已提交的、未提交的和未跟踪的，删掉的也算。在 `tests` 配置（BR-2046）找到的测试文件里，满足下面任一条的被选出：自己被改过；它的相对导入（按 BR-2119 的读法），直接或经过别的源码文件，导入了一个改过的文件（被删掉的文件照样按 BR-2119 的方式解析，所以不带扩展名或写成 `.js` 的导入也能对上它）；它启动 CLI（用 `join(import.meta.dir, …)` 之类只由字符串写成的路径指向一个入口文件，入口文件导入的源码里有 `entry("名字", 序号, 命令, "分组")` 注册的命令，D-60），并且把某条命令的词写成字符串（`"work", "status"` 连着写，或写在同一个字符串里 `"work status --json"`；顶层的单词命令要整个字符串就是这个词），而这条命令的模块（注册它的文件），或这个模块导入的文件，改过了；这样的测试还依赖入口文件和它导入的文件，但不依赖没被它点名的命令的模块（命令表 `src/cli/tree.ts` 导入全部命令模块，不顺着它找）；命令词不是字符串字面量（运行时拼出来的）时看不到，这样的测试只在入口文件一侧的文件改过时选出；它真正运行的测试名里写了本变更碰过的规则编号，碰过的规则指文件被改过的规则，加上被改过的变更文件 `rules:` 里列的规则；另外，`always_tests`（BR-2297）匹配的测试文件每次都选出，理由 `always`。输出先列出每个被选出的文件和理由（`changed`、`imports <文件> (through <中间文件> → …)`、`drives canon <命令> (<改过的文件> changed[, through <中间文件> → …])`、`runs the CLI (<改过的文件> changed[, through …])`、`names <规则编号>`、`always`），再说明哪些测试不会被选出、怎样全部运行。

## 例子

- 改了 `src/a.ts`，`src/b.test.ts` 有 `import "./a.ts"` → 选出 `src/b.test.ts`，理由 `imports src/a.ts`
- 改了 `src/a.ts`，`src/c.test.ts` 导入 `./b.ts`，`src/b.ts` 导入 `./a.ts` → 选出 `src/c.test.ts`，理由 `imports src/a.ts (through src/b.ts)`
- 只改了 `src/d.test.ts`，没有别的测试导入它 → 只选出 `src/d.test.ts`，理由 `changed`
- 改了规则 `BR-7` 的文件，`src/e.test.ts` 有 `it("BR-7: ...")` → 选出，理由 `names BR-7`
- `src/f.test.ts` 只有 `it.skip("BR-7: ...")`，也不导入改过的文件 → 不选出
- 删掉了 `src/a.ts`，`src/g.test.ts` 有 `import "./a"`，`src/h.test.ts` 有 `import "./a.js"` → 两个都选出，理由 `imports src/a.ts`
- 改了 `README.md`，没有测试导入它，也没有改规则 → 一个都不选出
- 改了 `src/a/commands.ts`（注册 `work one`），`src/a/a.test.ts` 启动入口文件 `src/cli/main.ts` 并传 `"work", "one"` → 选出，理由 `drives canon work one (src/a/commands.ts changed)`；写成 `"work one --json"` 的 `src/a/spaced.test.ts` 同样选出
- 改了 `src/a/a.ts`，`src/a/commands.ts` 导入它 → 同上两个测试选出，理由 `drives canon work one (src/a/a.ts changed, through src/a/commands.ts)`
- 改了 `src/b/commands.ts`（注册 `two`）→ 只选出传 `"two"` 的 `src/b/b.test.ts`；点名 `work one` 的测试和一条命令都没点名的 `src/c/c.test.ts` 都不选出
- 改了入口文件导入的 `src/cli/strict.ts`，或改了命令表 `src/cli/tree.ts` → 每个启动 CLI 的测试都选出，理由 `runs the CLI (src/cli/strict.ts changed, through src/cli/main.ts)`
- `src/d/d.test.ts` 里有 `"two"` 字符串，但没有指向入口文件的路径 → 改了 `src/b/commands.ts` 也不选出
