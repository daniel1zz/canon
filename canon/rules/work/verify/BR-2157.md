## 规则

`canon work test` 把当前 worktree 和 main 的合并基点比较，得到改过的文件：已提交的、未提交的和未跟踪的，删掉的也算。在 `tests` 配置（BR-2046）找到的测试文件里，满足下面任一条的被选出：自己被改过；记账里它当前内容的（没有就是最近的旧）报告里，有会运行的测试的名字写了本变更碰过的规则编号（BR-2005 的认法，BR-2338），碰过的规则指文件被改过的规则，加上被改过的变更文件 `rules:` 里列的规则；`test_select_command` 为这些改动的路径选出它（BR-2346）；另外，`always_tests`（BR-2297）匹配的测试文件每次都选出，理由 `always`。canon 自己不读测试或源码：导入、CLI 命令、按路径读的数据文件这些要读语言才知道的理由，由项目的 `test_select_command` 负责（本仓库的见 BR-2347 到 BR-2351）。输出先列出每个被选出的文件和理由（`changed`、`chosen by test_select_command[: <理由>]`、`names <规则编号>`、`always`），再说明哪些测试不会被选出、怎样全部运行。在命令行点名测试文件（`canon work test <文件>…`）时不做选择，只运行这些文件，理由 `named on the command line`，用来补它们的报告（BR-2344）；点名的每个文件都必须是 `tests` 找到的文件，不能和 `--all` 同用，否则退出码 2，不运行任何测试。

## 例子

- 只改了 `src/d.test.ts`，没有别的测试被选出 → 只选出 `src/d.test.ts`，理由 `changed`；未跟踪的测试文件同样
- 改了规则 `BR-7` 的文件，`src/e.test.ts` 的报告里有会运行的测试 `BR-7: ...` → 选出，理由 `names BR-7`
- `src/f.test.ts` 的报告里 `BR-7: ...` 带 `skipped` → 不选出；没有任何记账的测试文件也不因点名规则选出
- 改了变更文件，它的 `rules:` 里有 `BR-7` → `src/e.test.ts` 选出，理由 `names BR-7`
- 改了 `README.md`，没有配置 `test_select_command`，也没有改规则 → 一个都不选出，输出 `0 test file(s) related to this change`、`Not selected:` 和 `nothing to run`
- `test_select_command` 为 `src/a.ts` 选出 `src/b.test.ts` → 选出，理由 `chosen by test_select_command: <命令写的理由>`，输出里这行在运行结果之前
- `canon work test src/d.test.ts`，本变更改了别的文件 → 只运行 `src/d.test.ts`，输出 `1 test file(s) named on the command line`，记它的报告
- `canon work test README.md`（不是 `tests` 找到的文件）、或 `canon work test --all src/d.test.ts` → 退出码 2，不运行任何测试
