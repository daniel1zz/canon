title: canon work test 把 test_command 写出的 JUnit 报告按测试文件记进协调数据库
status: active
---

## 规则

`test_command` 含 `{report}` 时，`canon work test` 运行每个测试文件前把 `{report}` 换成一个临时路径（加单引号转义），命令把 JUnit XML 报告写到那里；命令结束后 canon 按 BR-2338 读它，把这个测试文件当前内容的 git blob 哈希和报告里的 `testcase` 列表记进协调数据库（`state.db`，所有 worktree 共用）的 `test_reports` 表，一个（路径，哈希）一行，同一个（路径，哈希）再记一次就替换那一行，同一个路径最多留最近的 5 行，然后删掉临时报告。这次运行的退出码照常：测试失败就是失败，报告照样记。命令没写出报告、报告读不了或超过 64 MiB 时，这个文件不记账，`canon work test` 输出“<文件>：…”说明原因并以失败退出（命令本身已失败的，退出码保持原样）。`test_command` 不含 `{report}` 时所有命令都以退出码 2 失败（BR-2160），所以不会有不记账的运行。

## 例子

- `test_command: "sh run.sh {file} {report}"`，`run.sh` 把 `<testsuite name="a"><testcase name="BR-7: x" classname="" /></testsuite>` 写进第二个参数 → `canon work test` 退出码 0，`test_reports` 里有这个文件路径和它的 blob 哈希一行，`cases` 里有 `BR-7: x`；这个文件的内容改了再运行 → 新哈希一行，旧哈希那一行还在
- 同一个文件、同一个内容运行两次 → 还是一行，时间是第二次的
- 同一个文件的内容连续改 6 次、每次都运行 → 这个路径只剩最近 5 行
- 命令写了 `<skipped />` 的 testcase 又以退出码 1 结束 → 退出码 1，仍记账，该 testcase 的 `runs` 是 false
- 命令什么都没写（退出码 0）→ `canon work test` 退出码 1，输出“<文件>：the test command wrote no report”，表里没有这个文件的行
- 命令写出的不是 XML → 退出码 1，输出“the report is not valid JUnit XML”，不记账
- `test_command: "sh run.sh {file}"`（没有 `{report}`）→ `canon work test` 退出码 2，信息含 `must contain {report}`，表里没有行
