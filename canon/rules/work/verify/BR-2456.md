## 规则

在一个未完成变更的 worktree 里，`canon work test` 跑完 `canon check`（BR-2227）之后，按 `canon work land --finish` 做关闭提交之前的同一套算法（BR-2241，用这次运行刚记下的测试报告）算出这个变更要执行、却还没有证据的规则。有这样的规则时，逐条输出一行 `evidence: <规则编号>: change a line in a running test whose title names <规则编号>`（规则写了 `untested:` 时再接 `, or add a line under ## 验收`），最后一行 `evidence: <n> rule(s) would land as 待重新执行, with no pass record (BR-2241); a note, not a failure`；这只是提示，不改变退出码（D-141），`work.test` 事件记下条数 `evidence`。只改了措辞、交给合入后措辞判断的规则（BR-2243）不算缺证据，不在这里列。不在变更 worktree 里、或变更已经完成时不做这一步。

## 例子

- 变更改了 `BR-7` 的 `## 例子`，没有改任何点名 `BR-7` 的测试 → 输出 `evidence: BR-7: change a line in a running test whose title names BR-7` 和 `evidence: 1 rule(s) would land as 待重新执行, with no pass record (BR-2241); a note, not a failure`，所有测试都通过时退出码 0
- 同一个变更改了点名 `BR-7` 的测试文件里的一行，这次运行跑了它并记下报告 → 不列 `BR-7`，退出码 0
- `BR-8` 写了 `untested:`，例子改了 → 那一行接 `, or add a line under ## 验收`
- 只改了 `BR-9` 的 `## 规则` 措辞、`## 例子` 没变 → 不列
- 在主 checkout 里运行 → 没有 `evidence:` 行
