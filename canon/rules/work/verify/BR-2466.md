## 规则

一次 `canon work test` 从开始算起超过 `test_timeout_minutes`（默认 30，可以带小数）时，像收到终止信号那样停下（停掉正在跑的测试进程，已经结束的文件照常记下，按 BR-2304），然后以退出码 1 结束，并依次输出：

- `canon work test ran past test_timeout_minutes (<分钟>) and was stopped: <n> test file(s) were running, <m> not started`；
- `slowest that ended: <文件> <用时>, …`：已经结束的文件里最慢的 5 个，从慢到快；没有结束的文件时没有这一行；
- 开始时和停下时的机器负载（5 分钟平均）和 CPU 数，以及判断：开始或停下时负载超过 CPU 数 → 写明机器比它的 CPU 忙，多半是别的运行拖慢了它，等机器空一些再跑；否则 → 写明测试套件本身太慢，要让最慢的文件变快（等定时器的测试应该用很短的时长）。

`work.test` 事件带 `timedOut: true`、开始和停下时的负载（`loadAtStart`、`loadAtEnd`），不带 `signal`。

## 例子

- `test_timeout_minutes: 0.05`，一个测试文件要跑 30 秒 → 大约 3 秒后停下，退出码 1，输出含 `ran past test_timeout_minutes (0.05)` 和 `1 test file(s) were running`，已结束的 `b.test.ts` 出现在 `slowest that ended` 里，事件有 `timedOut: true`
- 停下时负载 12、开始时 15.6、8 个 CPU → 判断是机器比 CPU 忙
- 负载 3 和 4、8 个 CPU → 判断是测试套件本身太慢
- 开始和停下时负载都正好是 8、8 个 CPU → 不算超过，判断是测试套件本身太慢
- 没配 `test_timeout_minutes` → 按 30 分钟
- `test_timeout_minutes: 0` 或 `-1` → 配置错误，退出码 2
