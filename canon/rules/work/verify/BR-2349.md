id: BR-2349
title: canon 自己仓库的 test_select_command 选出导入了按路径读取改动数据文件的模块的测试
status: active
---

## 规则

本仓库的 `test_select_command`（BR-2347）把这样的源码文件当作“读到了改动”：它用 `join(import.meta.dir, …)` 之类只由字符串写成的路径读一个非代码文件或目录（比如 `src/install/install.ts` 读 `.claude/skills`），而改动的非代码文件就是这个路径或在它下面。导入它（直接或间接）的测试选出，驱动的命令的模块导入它的测试（BR-2348）也选出，理由 `reads <路径> (<改动的文件> changed, via <源码文件>[, through <中间文件> → …])`，驱动命令的写在 `drives canon <命令> (…)` 的括号里。指向代码文件的路径归 BR-2347；指向仓库根目录或这个源码文件所在目录的祖先的路径太宽，不算；以项目根目录为起点读文件的（读被测项目的）不在此列。

## 例子

- 改了 `.claude/skills/canon-test/SKILL.md`，`src/a/a.ts` 里有 `join(import.meta.dir, "..", "..", ".claude", "skills")`，`src/i/i.test.ts` 导入它 → 选出 `src/i/i.test.ts`，理由 `reads .claude/skills (.claude/skills/canon-test/SKILL.md changed, via src/a/a.ts)`；启动 CLI 并传 `"work", "one"` 的测试（`work one` 的模块导入 `a.ts`）选出，理由 `drives canon work one (reads .claude/skills (.claude/skills/canon-test/SKILL.md changed, via src/a/a.ts, through src/a/commands.ts))`
- 改了 `canon/notes/n.md`，没有源码文件用字符串路径读它 → 一个都不选出
- 源码文件的路径字符串只指向一个 `.ts` 文件或仓库根目录 → 改了非代码文件也不因此选出
