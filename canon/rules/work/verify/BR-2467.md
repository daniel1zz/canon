## 规则

`canon work test`（带不带 `--all`、文件名都一样）不自己跑测试：它在自己的进程组里启动一个后台的 `canon work test` 去跑（同样的参数，没有标准输入，输出写进运行目录），事件表记一条 `test.spawn`（运行目录、参数），然后跟随它：照常打印它的输出，它结束后以它的退出码结束。所以 agent 的命令时限、断开或 Ctrl-C 结束的只是跟随的命令，测试照常跑完，结果照常记下（BR-2463、BR-2466）。跟随的命令收到 SIGTERM、SIGINT 或 SIGHUP 时，打印 `the test run goes on in the background`、后台进程号、再跟随用 `canon work test`、停下用 `canon work test --stop`，以退出码 75 结束。

同一个 worktree 里再运行 `canon work test` 时：上一次还在跑 → 打印它还在跑、跟随它而不是另开一次（参数不同也一样）；上一次已经结束、还没有人看到它的结尾 → 打印它的输出、以它的退出码结束，不另开；上一次的进程没有记下结果就不在了 → 说明一句，另开一次；其余情况另开一次。两个 `canon work test` 同时开始时只开一次运行。

`canon work test --stop` 给这个 worktree 还在跑的那次运行发 SIGTERM（它按 BR-2304 停下），跟随它到结束，以它的退出码结束；没有在跑的运行时退出码 3；`--stop` 和 `--all`、文件名一起给时是用法错误，退出码 2。

## 例子

- `canon work test` 跑到一半被 agent 的命令时限终止 → 退出码 75，输出含 `the test run goes on in the background`，测试文件的进程还在跑
- 接着再运行 `canon work test` → 输出含 `still running; following it instead of starting another`，跟随到它结束
- 再接着 `canon work test --stop` → 退出码 143，输出含 `stopped by SIGTERM: 1 test file(s) were running`，测试进程都不在了
- 没有在跑的运行时 `canon work test --stop` → 退出码 3
- 运行在没人跟随时跑完，再运行 `canon work test` → 打印那次的输出和退出码，不另开
- 给在后台跑测试的那个 canon 进程发 SIGTERM → 按 BR-2304 停下，跟随的命令以 143 结束
- 同一个 worktree 里两个 `canon work test` 同时开始 → 只记一条 `test.spawn`，两条命令跟随同一次运行
- 上一次运行没人跟随时被 SIGKILL，再运行 `canon work test` → 输出含 `ended without recording a result`，另开一次（第二条 `test.spawn`）
- 有人跟随时运行被 SIGKILL → 跟随的命令说明它没有记下结果，以 75 结束；之后再运行 `canon work test` 直接另开一次，不再说明
- `canon work test --stop --all` → 用法错误，退出码 2
