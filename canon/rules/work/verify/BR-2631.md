## 规则

**`canon heavy run [--] <命令> [参数…]`**：先按 BR-2630 过负载关（步骤种类 `heavy-run`；队列和等待行里的主题是运行它的 worktree 认领的变更或杂务编号，没有认领时是执行者），过关后在前台运行这个命令：标准输入输出直接接上，收到的 SIGINT、SIGTERM、SIGHUP 转给它，以它的退出码结束。等负载时被信号停下按 BR-2630，命令不运行。没给命令 → 用法错误，退出码 2。它在哪里都能运行，不要求认领。

**`heavy_commands`**：`canon/config.yaml` 里可选的字符串列表，每项是一个正则（JavaScript 语法），用来认出项目的重命令（录制、导出、构建）。默认空列表。不是字符串列表、或某项不是合法正则 → 配置错误，退出码 2，指出哪一项（BR-2045）。

**Bash 前的 hook**：Claude Code 和 Codex 的会话每次运行 Bash 命令之前，canon 的 hook 把命令全文和 `heavy_commands` 的每一项比：

- 没有一项匹配，或命令去掉开头的空白和环境变量赋值后以 `canon heavy run` 开头 → 放行；
- 匹配，按 BR-2630 要排队 → 拒绝，原因写 `heavy command while 5-minute load is <一位小数> on <CPU 数> CPUs (limit <L>)` 或 `heavy command while <n> heavy step(s) wait for the load`，再写 `run it as: canon heavy run -- <命令>; a compound command goes in sh -c '…' (BR-2631)`；事件表记一条 `heavy.refuse`，详情含匹配的那一项、负载和 `L`；
- 匹配但 BR-2630 会让它立刻开始 → 放行，不提示；
- 读不到负载 → 放行。

只看命令文字：先 `cd` 再跑重命令的复合命令，开头不是 `canon heavy run` 时按没经过算；hook 不展开脚本，项目在脚本里跑的重命令要由脚本自己写成 `canon heavy run …`，或把脚本名加进 `heavy_commands`。

依据：D-161。

## 例子

- `heavy_commands: ["godot .*--export", "scripts/record\\.sh"]`，8 个 CPU、负载 17.0，会话运行 `scripts/record.sh level1` → hook 拒绝，原因含 `heavy command while 5-minute load is 17.0 on 8 CPUs (limit 16)` 和 `canon heavy run -- scripts/record.sh level1`，事件表有 `heavy.refuse`
- 同上，运行 `canon heavy run -- scripts/record.sh level1` → hook 放行；命令输出 BR-2630 的等待行，负载降下来后录制开始，退出码是录制脚本的退出码
- 同上，负载 12.0、队列空 → `scripts/record.sh level1` 直接放行
- 负载 12.0，但队列里有一个 `canon work test` 在等 → `scripts/record.sh level1` 被拒，原因含 `1 heavy step(s) wait for the load`
- `CI=1 canon heavy run -- godot --export x` → 放行
- `cd game && godot --headless --export x`，负载 17.0 → 拒绝，原因提示 `sh -c`
- `heavy_commands: ["("]` → 配置错误，退出码 2，点名这一项
- 没配 `heavy_commands` → hook 什么都不拦
- `canon heavy run`（没给命令）→ 退出码 2
- `canon heavy run -- false`，负载低 → 退出码 1
