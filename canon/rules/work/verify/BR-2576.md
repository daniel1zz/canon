## 规则

整组测试指：不点名测试文件的 `canon work test`（选出相关文件的和 `--all` 都算），以及 floor watch 在后台对整个 floor 的运行（D-151，F-4/S2）。整组测试在类型检查和任何测试开始之前，先在整台机器的队列里拿一个名额：队列覆盖这个仓库的所有 worktree，也覆盖这台机器上其他用 canon 的仓库；同时跑的整组测试不超过 `full_test_slots`（BR-2579），先来的先跑。

名额不够、要排队时输出一行：`canon: waiting for a full test run slot: <n> full run(s) ahead on this machine: <前面每一组>; the wait does not count toward test_timeout_minutes`；前面每一组写成 `<变更或杂务编号，main 的后台 floor 写 main floor>（<worktree 路径>，running <m> min 或 waiting）`。前面的组数变化时再输出一行；有名额时不输出这一行。

点名了测试文件的 `canon work test <文件…>` 不排队、不拿名额；只跑 floor 的一个范围（`floor_scopes`）的合入也不拿。排队时收到 SIGTERM、SIGINT 或 SIGHUP：退出队列、不跑任何测试、以信号对应的退出码结束（BR-2304）。

## 例子

- `full_test_slots` 是 1，worktree A 的整组测试在跑，B 里再运行 `canon work test` → B 输出含 `1 full run(s) ahead` 和 A 的变更编号、路径、`running` 的行，A 结束后 B 才开始类型检查
- 队列里一组在跑、一组在等，C 来了 → C 的行写 `2 full run(s) ahead`，两组都列出
- 另一个仓库的 worktree 里有整组测试在跑 → 这里的整组测试同样排队
- `canon work test src/a.test.ts` 在整组测试跑着时运行 → 立刻开始，不输出等待行
- 没有别的整组测试 → 立刻开始，没有等待行
- 排队的命令被 SIGTERM 停下 → 它退出队列，队列里排在它后面的往前一位，退出码 143
- main 的后台 floor 在跑，一个变更里运行 `canon work test` → 排队，前面那组写成 `main floor`
