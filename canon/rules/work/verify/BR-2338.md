## 规则

canon 读一份 JUnit XML 报告时，每个 `testcase` 记下：它外层每一层 `testsuite` 的 `name`（从外到内）、它自己的 `classname` 和 `name`（缺的当空串）、有没有 `skipped` 子元素（有就是不会运行，`failure`、`error` 的测试仍算会运行）、`line` 属性（是非负整数才记）；另外读 `file` 属性，但只有 floor 的报告用它把 `testcase` 归到测试文件（BR-2339），`canon work test` 的报告不用它，也不记进账里。别的属性和内容一律不读，canon 也不认识任何一种测试语言或框架。没有 `testcase` 的报告是合法的空报告。不是合法 XML、根元素不是 `testsuites` 或 `testsuite`、定义了实体的 DOCTYPE，都是无效的报告（BR-2337 的失败）。

## 例子

- bun 的报告：`describe("BR-1")` 里的 `it("first")` → 一个 testcase，suites 是 `[c.test.ts, BR-1]`，`name` 是 `first`，`line` 是它那一行，会运行
- bun 的 `it.skip`、`test.todo`（`<skipped message="TODO" />`）→ `runs` 是 false；`test.each` 两组 → 两个 testcase；带 `<failure>` 的测试 → `runs` 是 true
- 注释里写的 `BR-1` → 报告里没有任何 testcase 带它
- pytest 默认（xunit2）的报告只有 `classname` 和 `name` → 照常读出，没有 `line`
- gdUnit4 的报告没有 `file`、`line`，被跳过的测试带 `<skipped>` → `runs` 是 false；它的报告不能给 floor 用（BR-2339 要求每个 `testcase` 有 `file`），只能逐个文件运行记账（BR-2337）
- bun 的报告每个 `testcase` 带 `file` → 读出，floor 用它按测试文件记账（BR-2339）；`canon work test` 记账时不存它
- `<testsuites></testsuites>` → 合法，零个 testcase
- 根元素是 `<html>` → 无效，说明根元素是什么；`<testsuite>` 没有关闭 → 无效；`<!DOCTYPE x [<!ENTITY y "z">]>` → 无效
