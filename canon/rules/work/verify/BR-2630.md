## 规则

每个重步骤（work/verify 的术语表：`canon work test`，点名文件的也算；合入在被合入的树上跑的 floor 和它自己补跑的测试文件；后台 floor watch 对 main 的运行；`canon heavy run`，BR-2631）在跑第一个项目命令之前过一道负载关（D-161）。不管是主会话、子 agent、轻派发还是重派发的 worker 跑的（BR-2632），都一样。

**什么时候过关**：负载上限 `L` 按 BR-2526 第 2 条算（`delegate_max_load_per_cpu` × CPU 数，比较用没有取整的 5 分钟负载）。

- 负载低于 `L`、负载队列里没有在等的步骤 → 立刻开始，不进队列，不输出。
- 否则进负载队列（术语表），按到达顺序排。排在第一个、负载低于 `L`、并且离上一个从队列放行的步骤开始已有至少 60 秒时，它开始。一次只放一个：5 分钟负载跟不上刚开始的步骤，几组同时放行会把负载推回上限之上。
- 进程已经不在的队列项不算，排在后面的往前移（同 BR-2577）。

**和别的关的先后**：整组测试先按 BR-2576 拿名额，再过负载关，等负载时名额不放。合入是在拿到合入的轮次之后、跑 floor 和补跑测试之前过关；合入这一轮不跑 floor 也不补跑测试（例如只改了 `floor_skip_paths` 里的路径）时不过关。`setup`、`before_land` 和生命周期 hook 不是重步骤，不过关。

**等的时候**：进队列时输出一行 `canon: waiting for the machine load: 5-minute load <一位小数> on <CPU 数> CPUs (limit <L>); <n> step(s) ahead on this machine; the wait does not count toward test_timeout_minutes`；前面的步骤数变了再输出一行，此外最多每 5 分钟输出一行当时的负载。后台合入和后台测试的这一行写进它们的日志，跟随的 `canon work land`、`canon work test` 照常转出来。

- 不设等待上限：等到负载降下来，或被停下。等的时间不算进 `test_timeout_minutes`（BR-2466）、合入的 floor 时限和 `work.test` 事件的 `ms`。
- 收到 SIGTERM、SIGINT 或 SIGHUP：退出队列，不跑任何项目命令，以信号对应的退出码结束（BR-2304）；`canon work test --stop`、`canon work land --stop` 也这样停下等待中的步骤。
- 读不到负载（三个平均值都是 0，BR-2526 的测不到）→ 不过关，直接开始，不输出。

**事件**：进队列时记 `load.wait`（详情：步骤种类 `test`、`land`、`floor`、`heavy-run`，负载、`L`、前面几个）；从队列放行时记 `load.start`（详情含等了多少毫秒）。立刻开始的不记。

依据：D-161。

## 例子

- 8 个 CPU、负载 17.0（`L` 16），worker `w1` 在 `C-9` 的 worktree 里运行 `canon work test src/a.test.ts` → 输出 `canon: waiting for the machine load: 5-minute load 17.0 on 8 CPUs (limit 16); 0 step(s) ahead on this machine; …`，负载降到 15.9 后开始类型检查，事件表有 `load.wait` 和 `load.start`
- 同上，`w1` 是轻派发（BR-2632）→ 一样等
- 主会话自己在 worktree 里运行 `canon work test`，负载 17.0 → 一样等
- 负载 12.0，队列空 → 立刻开始，没有等待行，没有 `load.wait`
- 负载 15.96 → 低于 16，立刻开始
- 负载 17.0 时 `C-9`、`C-10`、`C-11` 先后进队列；负载降到 14.0 → `C-9` 开始，`C-10` 的等待行变成 `0 step(s) ahead`；60 秒内负载一直是 14.0，`C-10` 仍不开始；`C-9` 开始满 60 秒、负载仍低于 16 → `C-10` 开始
- 负载 12.0，但队列里还有 `C-9` 在等（离上次放行不到 60 秒）→ 新来的 `C-12` 排在 `C-9` 后面，不插队
- `full_test_slots` 是 1，负载 17.0，`C-9` 拿到整组测试名额后在等负载，`C-10` 的整组测试来了 → `C-10` 按 BR-2576 等名额，`C-9` 的名额不放
- 负载 17.0，`C-9` 合入，这一轮要跑 floor → 拿到轮次后输出等待行，负载降下来后跑 floor；只改了 `canon/notes/` 的合入 → 不等
- 负载 17.0，后台 floor watch 要测 main → 等，等待行写进它的日志
- `test_timeout_minutes` 是 30，等负载 40 分钟，测试跑了 5 分钟 → 不超时
- 等负载时 `canon work test --stop` → 退出队列，没有跑任何测试
- 排在第一个的 `C-9` 的进程被杀，队列项还在 → 不算，`C-10` 按条件开始
- Windows 读不到负载 → 直接开始，没有等待行
