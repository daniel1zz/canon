## 规则

`canon/config.yaml` 的 `heavy_max_load_per_cpu` 是重步骤的负载上限按每个 CPU 算的倍数：重步骤的负载上限 `L` = 它 × CPU 数（`availableParallelism`）。用它的有三处：重步骤的负载关（BR-2630）、Bash 前的 hook 拦 `heavy_commands`（BR-2631）、后台 floor 失败时判断是不是过载失败（BR-2666）。大于 0 的数，可以带小数，默认 2（不写时取 2）。0、负数、`null`、不是数 → 配置错误，退出码 2，信息写明这个键（BR-2045）。

它和 `delegate_max_load_per_cpu`（BR-2526 第 2 条，只管派发和议程的可派一组）互不影响：不写 `heavy_max_load_per_cpu` 时取固定的默认值 2，**不**跟着 `delegate_max_load_per_cpu` 走。所以项目把 `delegate_max_load_per_cpu` 调得很大来放开派发时，重步骤照样在负载 2 × CPU 数时等（D-172）。

## 例子

- 8 个 CPU，没写 `heavy_max_load_per_cpu`，负载 17.0 → 重步骤等，等待行写 `(limit 16)`
- 8 个 CPU，`delegate_max_load_per_cpu: 1000`，没写 `heavy_max_load_per_cpu`，负载 17.0 → 派发不因负载拒绝；`canon work test`、合入的 floor、后台 floor watch 照样等，等待行写 `(limit 16)`；hook 照样拦匹配 `heavy_commands` 的命令
- 8 个 CPU，`heavy_max_load_per_cpu: 3`，负载 17.0 → 重步骤立刻开始；负载 24.0 → 等，`(limit 24)`
- `heavy_max_load_per_cpu: 0`、`-1` 或 `"high"` → 配置错误，退出码 2，信息含 `heavy_max_load_per_cpu`
