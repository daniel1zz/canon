---
id: BR-2226
title: canon work test 在运行测试前执行项目配置的 typecheck_command，失败时退出码 1
status: active
---

## 规则

`canon/config.yaml` 可以写 `typecheck_command`：一条 shell 命令，`canon work test`（带不带 `--all` 都一样）在运行选出的测试文件之前，在 worktree 根目录下执行它一次；一个测试文件都没选出时也执行。结束时打印一行：`pass` 或 `FAIL`、用时、`typecheck`，失败的还有退出码和它输出的最后 40 行。失败时照样运行选出的测试文件和 `canon check`（BR-2227），最后退出码 1，汇总里写明类型检查失败。没写 `typecheck_command`（或写成 null）时不执行任何类型检查，也不打印这一行；canon 不猜测项目用什么类型检查工具。`typecheck_command` 不是字符串，或者以路径开头而那个文件不存在时，所有命令都以退出码 2 失败（BR-2045、BR-2197）。

## 例子

- `typecheck_command: "sh tc.sh"`，`tc.sh` 以 0 结束，选出 1 个测试文件并通过 → 先打印 `pass … typecheck`，再运行测试文件，退出码 0
- `typecheck_command: "sh tc.sh"`，`tc.sh` 输出 `type error` 并以 2 结束，选出的测试都通过 → `FAIL … typecheck (exit 2)` 和 `type error`，测试文件照样运行，汇总里有 `typecheck failed`，退出码 1
- `typecheck_command` 失败，一个测试文件都没选出 → 照样执行类型检查，`nothing to run`，退出码 1
- 没写 `typecheck_command` → 输出里没有 `typecheck` 这一行，结果只由测试和 `canon check` 决定
- `typecheck_command: 3` → 所有命令退出码 2
