## 规则

本仓库的 `test_select_command` 是 `scripts/select-tests/main.ts`（本规则到 BR-2351 说的都是这个脚本，不是 canon 的行为：canon 不认识任何语言，D-64）。收到改动的路径后，它在 `tests` 找到的测试文件里选出这样的：用相对导入（`import … from "./x"`、`import "./x"`、`require("./x")`、`import("./x")`、`export … from "./x"`），直接或经过别的源码文件，导入了一个改动的文件。导入的路径按打包工具的方式解析：照写的、加源码扩展名（`.ts`、`.tsx`、`.mts`、`.cts`、`.js`、`.jsx`、`.mjs`、`.cjs`）或当作目录的 `index`；写成 `.js` 的指向同名的 `.ts`；解析不到的原样保留；被删掉的文件照样解析，所以不带扩展名或写成 `.js` 的导入也能对上它。理由写 `imports <改动的文件>`，经过别的文件时再写 ` (through <文件> → …)`，取最短的一条链。不是以 `./` 或 `../` 开头的导入、写在字符串里的路径都不算。

## 例子

- 改了 `src/a.ts`，`src/b.test.ts` 有 `import "./a.ts"` → 选出 `src/b.test.ts`，理由 `imports src/a.ts`
- 改了 `src/a.ts`，`src/c.test.ts` 导入 `./b.ts`，`src/b.ts` 导入 `./a.ts` → 选出 `src/c.test.ts`，理由 `imports src/a.ts (through src/b.ts)`
- 删掉了 `src/a.ts`，`src/g.test.ts` 有 `import "./a"`，`src/h.test.ts` 有 `import "./a.js"` → 两个都选出，理由 `imports src/a.ts`
- 改了 `README.md`，没有测试导入它 → 一个都不选出
- 测试里有 `const s = "./a.ts"`，改了 `src/a.ts` → 不选出
- 测试里有 `import { a } from "a"`、`import x from "node:path"`，改了 `src/a.ts` → 不选出
