## 规则

`canon work test` 对每个选出的测试文件单独运行一次 `test_command`（BR-2160），`{file}` 换成这个文件的路径，在 worktree 根目录下依次运行。每个文件结束时打印一行：`pass` 或 `FAIL`、用时、路径，失败的还有退出码和它输出的最后 40 行。最后打印汇总：文件数、通过数、失败数、总用时，有失败时再列出失败的文件。有任何文件失败时退出码 1；全部通过时退出码由类型检查（BR-2226）、`canon check`（BR-2227）和 `always_tests` 有没有匹配不到的 glob（BR-2297）决定，都通过时 0。一个文件都没选出时打印 `nothing to run`，不运行 `test_command`，类型检查和 `canon check` 照样运行。每次运行（包括一个文件都没选出的）在事件表里记一条 `work.test`，带文件数、失败数、用时、类型检查的退出码（`typecheck`，没配置时为 null）、`canon check` 的发现数（`check`）和匹配不到的 `always_tests` glob 数（`unmatched`）；没选出文件时文件数是 0。

## 例子

- 选出 2 个文件，都通过 → 两行 `pass`，汇总 `2 file(s): 2 passed, 0 failed, …`，退出码 0
- 选出 2 个文件，第二个失败 → 第二行 `FAIL … (exit 1)` 和它输出的最后几行，汇总 `1 passed, 1 failed`，`failed: <文件>`，退出码 1
- 选出 2 个文件 → `test_command` 运行两次，每次只带一个文件
- 一个都没选出，`canon check` 没有发现，没配置类型检查 → `nothing to run`，退出码 0，事件表多一条 `work.test`，文件数 0，`typecheck` 为 null，`check` 为 0
- 一个都没选出，`canon check` 有 1 条发现 → `nothing to run`，退出码 1，`work.test` 的 `check` 为 1
