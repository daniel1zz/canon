## 规则

本仓库的 `test_select_command`（`bun scripts/select-tests/main.ts`，BR-2347）在仓库根运行：标准输入是改动的路径，每行一个；测试文件是 `canon/config.yaml` 的 `tests` 列出的 glob 找到的、存在的文件（没写 `tests` 就没有测试文件）；标准输出每个选出的测试文件一行，路径、制表符、理由（理由用 `; ` 连起来）；标准错误一行 `select-tests: <N> file(s) spawn the CLI, <M> command(s) known`；退出码 0。没有改动的路径时输出为空。有测试用 `main.ts` 之类的路径指向 CLI 入口而那个文件不存在，或入口和它导入的文件里没有注册任何命令（BR-2348）时，选择无法进行：退出码 1，标准输出为空，标准错误写明哪个测试指向哪个路径、缺了什么，不退回只看导入的选法。

## 例子

- 标准输入 `src/a.ts`，`src/b.test.ts` 导入它，`src/c.test.ts` 经过 `src/b.ts` 导入它 → 标准输出两行：`src/b.test.ts<制表符>imports src/a.ts` 和 `src/c.test.ts<制表符>imports src/a.ts (through src/b.ts)`，标准错误有 `0 file(s) spawn the CLI`，退出码 0
- 标准输入为空 → 标准输出为空，退出码 0
- 某个测试指向 `gone/main.ts`，项目里没有这个文件 → 退出码 1，标准错误含 `src/x.test.ts spawns gone/main.ts, which is not a file in the project: no CLI entry found`
- 某个测试指向的 `src/invocation/main.ts` 和它导入的文件里没有 `entry(...)` 注册 → 退出码 1，标准错误含 `the command table is empty`
- `canon/config.yaml` 没有 `tests` → 标准输出为空，退出码 0
