---
id: BR-2297
title: always_tests 配置的测试文件总是被 canon work test 选出，理由 always
status: active
---

## 规则

`canon/config.yaml` 可以写 `always_tests`：一个 glob 列表。`tests` 配置（BR-2046）找到的测试文件里，匹配其中任一个 glob 的，`canon work test` 每次都选出，理由 `always`，和这个变更改了什么无关；它同时满足 BR-2157 的条件时，`always` 写在那些理由后面。给不靠导入、也不在测试名里写规则编号就能被改动弄坏的测试用，例如读遍整个源码目录的测试；canon 不认语言，所以只按文件路径选。`--all` 时理由照旧只写 `--all`（BR-2159）。有一个 glob 在 `tests` 找到的测试文件里一个都匹配不到时（带不带 `--all` 都一样），`canon work test` 照样运行别的，输出一行 `always_tests: "<glob>" matches no test file`，最后退出码 1：文件改名或删掉之后这一项就不再生效，不能悄悄失效。`always_tests` 不是列表、列表里有不是字符串或是空字符串的项时，所有命令都以退出码 2 失败（BR-2045）；没写或写成 null 时没有总是选出的测试。

## 例子

- `always_tests: ["src/scan.test.ts"]`，只改了 `README.md` → 选出 `src/scan.test.ts`，理由 `always`，并运行它
- 同一配置，改了 `src/scan.test.ts` → 理由 `changed; always`
- `always_tests: ["src/**/scan-*.test.ts"]`，有 `src/a/scan-x.test.ts` 和 `src/b/scan-y.test.ts` → 两个都选出，理由 `always`
- 没写 `always_tests`，只改了 `README.md` → 一个都不选出
- `always_tests: ["src/gone.test.ts"]`，没有这个文件 → 输出 `always_tests: "src/gone.test.ts" matches no test file`，退出码 1
- `always_tests: ["src/gone.test.ts"]`，运行 `canon work test --all` → 照样运行全部测试文件，同样输出这一行，退出码 1
- `always_tests: ["tools/x.test.ts"]`，文件存在但 `tests` 只配置了 `src/**/*.test.ts` → 同样算匹配不到，退出码 1
- `always_tests: "src/scan.test.ts"`（不是列表）、`always_tests: [3]` 或 `always_tests: [""]` → 所有命令退出码 2，信息里有 `always_tests`
