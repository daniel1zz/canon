## 规则

`canon/config.yaml` 可以写 `test_command`：运行一个测试文件的 shell 命令，必须含 `{file}`，运行时换成测试文件的路径（加单引号转义），也必须含 `{report}`，换成命令写 JUnit XML 报告的临时路径（BR-2337）：canon 靠报告知道文件里有哪些测试、会不会运行。`test_command` 不是字符串、不含 `{file}`、不含 `{report}`，或者以路径开头而那个文件不存在时，所有命令都以退出码 2 失败（BR-2045），缺 `{report}` 或 `{file}` 的信息里写出各框架的写法（bun、pytest、gotestsum、vitest、jest、Godot），以及没有 `file` 属性的报告只能用在 `canon work test` 上（BR-2339）。没写 `test_command` 时，别的命令照常执行，`canon work test` 以退出码 2 失败，提示要写这一项并给出例子，不猜测项目用什么测试工具。

## 例子

- `test_command: "bun test {file}"` → 选出 `src/a.test.ts` 时运行 `bun test 'src/a.test.ts'`
- `test_command: "bun test {file} --reporter=junit --reporter-outfile={report}"` → 选出 `src/a.test.ts` 时 `{file}` 换成 `'src/a.test.ts'`，`{report}` 换成一个临时路径
- `test_command: "npx vitest run {file}"`（没有 `{report}`）→ 所有命令退出码 2，信息含 `must contain {report}` 和各框架的写法
- `test_command: "bun test"` → 所有命令退出码 2，提示必须含 `{file}`
- `test_command: 3` → 退出码 2
- `test_command: "scripts/missing.sh {file}"`，文件不存在 → 退出码 2
- 没写 `test_command` → `canon check` 照常，`canon work test` 退出码 2，提示写 `test_command: "bun test {file}"` 这样的一项
