id: BR-2304
title: canon work test 被 SIGTERM、SIGINT 或 SIGHUP 终止时停掉它启动的全部进程
status: active
---

## 规则

`canon work test` 把类型检查、每个测试文件和每次单独重跑（BR-2226、BR-2302、BR-2303）的命令都放在各自的进程组里启动（`detached`），所以终端的 Ctrl-C 只到 canon，由 canon 去停它们。收到 SIGTERM、SIGINT 或 SIGHUP 时：不再开始新的文件，不开始单独重跑，给每个正在运行的命令的进程组发 SIGTERM，等这些进程组里的进程都结束，最多 10 秒；10 秒后，或等的时候收到第二个信号（任何一种）时，给还在的进程组发 SIGKILL，再等最多 5 秒。SIGTERM 和 SIGHUP 同样处理。不读进程表，不追离开了自己进程组的进程（`setsid`、`setpgid`），canon 自己被 SIGKILL 时测试文件的进程也留下：和 `canon floor watch`（BR-2285、D-55）一样，只处理真实发生的情况。发过 SIGKILL 时打印一行：`sent SIGKILL <10 s after SIGTERM 或 after a second signal>`，还有进程组没结束时加 `, and <n> process group(s) still run`。

停完打印 `stopped by <信号>: <r> test file(s) were running, <m> not started`，不运行 `canon check`，不打印汇总，记一条 `work.test`（比平常多 `signal`，值是信号名），退出码 SIGTERM 143、SIGINT 130、SIGHUP 129（和 BR-2099 一样）。数法：r 是收到信号时正在运行的文件个数（类型检查时 0）；m 是没有最终结果的其余文件，包括没开始的，和已经同时失败、还在等单独重跑的（BR-2303）：这些文件不算失败。`work.test` 的文件数和失败数只算已经有最终结果的文件（通过，或失败而且不会再重跑）。

一个文件的进程因为信号结束（`signalCode` 有值，或 `sh` 以 129、130、143 退出），而 canon 在这之前已经收到停止信号，或在这之后 0.5 秒内收到，这个文件不算失败、不重跑、不记结果，算在收到信号时正在运行的 r 里。canon 给进程组发 SIGTERM 后，文件因 SIGTERM 结束，也属于这一种：不会再开新文件，也不会重跑；有人往一个文件自己的进程组单独发信号、canon 紧接着也收到信号时同样。因为信号结束而 canon 没有收到停止信号的文件（例如被 OOM 杀掉），照常算失败。

## 例子

- 同时运行 3 个文件、还有 5 个没开始时收到 SIGTERM → 3 个文件的 `sh`、`bun test` 和它们启动的 git 都结束，打印 `stopped by SIGTERM: 3 test file(s) were running, 5 not started`，没有 `canon check:` 行，退出码 143，`work.test` 带 `signal: "SIGTERM"`，失败数 0
- 一次一个（`test_jobs: 1`）运行第 2 个文件时收到 SIGINT → 它的进程全部结束，打印 `stopped by SIGINT: 1 test file(s) were running, <剩下的个数> not started`，退出码 130
- 在终端按 Ctrl-C（SIGINT 只到 canon），正在运行 2 个文件 → canon 给两个文件的进程组发 SIGTERM，它们因 SIGTERM 结束，一个也不算失败，不开新文件，不重跑，退出码 130
- 类型检查运行时收到 SIGTERM → 类型检查的进程结束，`stopped by SIGTERM: 0 test file(s) were running, <选出的个数> not started`，退出码 143
- 单独重跑阶段，2 个同时失败的文件还没重跑，收到 SIGTERM → `stopped by SIGTERM: 0 test file(s) were running, 2 not started`（再加上没开始的），这 2 个不算失败，`work.test` 的失败数不含它们
- 一个测试文件的进程忽略 SIGTERM → 10 秒后它的进程组收到 SIGKILL，打印 `sent SIGKILL 10 s after SIGTERM`，然后才打印 `stopped by` 那一行并退出
- 测试文件是 `sleep 30 & wait`，收到 SIGTERM → `sleep` 也结束，进程组里一个进程都不剩
- 测试文件启动了调用 `setsid` 的进程 → 这个进程不在其中，照常运行（不追）
- 等的时候又收到一次 SIGINT → 立刻对还在的进程发 SIGKILL，不再等 10 秒，退出码仍由第一个信号决定
- 收到 SIGHUP → 和 SIGTERM 一样，退出码 129
- 一个文件被外部的 `kill -9` 杀掉，canon 没有收到信号 → 算失败（`FAIL`，退出码 137）
- 没收到信号、正常结束 → `work.test` 没有 `signal`
