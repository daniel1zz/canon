id: BR-2304
title: canon work test 被 SIGTERM 或 SIGINT 终止时停掉每个正在运行的测试文件的全部进程
status: planned
---

## 规则

`canon work test` 运行期间（类型检查、测试文件或单独重跑的时候，BR-2226、BR-2302、BR-2303）收到 SIGTERM 或 SIGINT 时：不再开始新的测试文件；把它启动的全部进程（每个正在运行的 `test_command` 或 `typecheck_command` 和它们启动的进程）按 BR-2285 的做法停掉，先 SIGTERM，最多等 10 秒，还在的 SIGKILL；进程表读不出来、可能没停干净时按 BR-2285 打印那一行。然后打印 `stopped by <信号>: <n> test file(s) were running, <m> not started`，不运行 `canon check`，不打印汇总，记一条 `work.test`，比平常多一个 `signal`（信号名），`files` 和 `failed` 只算已经结束的文件；退出码 SIGTERM 时 143、SIGINT 时 130（和 BR-2099 一样）。测试文件的进程和 canon 在同一个进程组里，所以从外面杀整个进程组时它们也一起收到信号。

## 例子

- 同时运行 3 个文件、还有 5 个没开始时收到 SIGTERM → 3 个文件的 `sh`、`bun test` 和它们启动的 git 都结束，打印 `stopped by SIGTERM: 3 test file(s) were running, 5 not started`，没有 `canon check:` 行，退出码 143，`work.test` 带 `signal: "SIGTERM"`
- 一次一个（`test_jobs: 1`）运行第 2 个文件时收到 SIGINT → 它的进程全部结束，`stopped by SIGINT: 1 test file(s) were running, …`，退出码 130
- 类型检查运行时收到 SIGTERM → 类型检查的进程结束，`stopped by SIGTERM: 0 test file(s) were running, <选出的个数> not started`，退出码 143
- 一个测试文件的进程忽略 SIGTERM → 10 秒后收到 SIGKILL，然后才打印 `stopped by` 那一行并退出
- 没收到信号、正常结束 → `work.test` 没有 `signal`
