# 合入前的验证（work/verify）

合入前在变更的 worktree 里验证改动：`canon work test` 先跑项目配置的类型检查，再挑出和本变更相关的测试文件、每个文件单独运行一次（按机器空闲的 CPU 同时运行一个或几个，BR-2302），最后跑 `canon check`，把要等 floor 或合入时的检查才发现的失败提前到合入之前；它还提示本变更改到的规则和决策上未处理的评审建议（BR-2249），只作提示。

不管：合入时的 floor 和检查（`work/land`），规则和测试名的对应（`knowledge/check`）。

## 业务

- **挑哪些测试跑**：一次 `canon work test` 跑哪些测试文件：按本变更改了什么挑、项目配的总是要跑的、`--all` 一个不漏，每个都说明为什么挑它。
- **canon 自己的选测脚本**：本仓库的 `test_select_command` 怎么从改动的路径找到受影响的测试：相对导入、驱动 CLI 的、按路径读数据文件的。
- **怎么跑这些测试**：选出来之后怎么执行：一个文件一次、同时跑几个、同时失败的单独重跑、被终止时把进程全停掉。
- **顺带做的检查和提示**：同一次 `canon work test` 在测试之外还做的事：先跑类型检查、最后跑 `canon check`、说出未处理的评审建议和和别人重叠的文件，指出大部分时间在空等的测试文件。
- **测试报告的记账**：测试命令写出的 JUnit 报告怎么读、按文件记在哪，供「这条规则有没有测试点名」和「这个文件有没有当前内容的报告」用。

## 术语

- **相关的测试文件**：本变更改过的测试文件、项目的 `test_select_command` 为改动选出的测试文件（BR-2346）、报告里测试名写了本变更碰过的规则的测试文件（BR-2157），以及 `always_tests` 配置的、每次都选出的测试文件（BR-2297）。
- **test_command**：项目配置的、运行一个测试文件的命令（BR-2160）；含 `{report}` 时它写出的 JUnit 报告按测试文件记账（BR-2337、BR-2338）。
- **test_jobs**：最多同时运行几个测试文件，`auto` 或数字；到上限之前每多开一个都要有空闲的 CPU（BR-2302）。
- **test_select_command**：项目配置的命令：收到改动的路径，打印会受影响的测试文件（BR-2346）；canon 不读源码，读语言的部分都在它里面；本仓库的是 `scripts/select-tests/main.ts`（BR-2347 到 BR-2351）。
- **typecheck_command**：项目配置的、在测试之前运行一次的类型检查命令；没配置时不跑（BR-2226）。
