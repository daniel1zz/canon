## 规则

操作者按顺序确定：`canon work start`、`stop`、`land`、`drop` 和 `canon chore start`、`land` 带 `--as <名字>` 时按宿主的会话执行者格式追加 `:<名字>`（Claude 用会话 ID 前 8 个字符，Codex 用下述带 codex- 前缀的完整会话 ID）（名字是宿主给子 agent 的 id，别的会话启动的 Claude Code worker 会话用自己定的名字，BR-2468；名字只含字母、数字、`-`、`_`，不在 Claude Code 或 Codex 会话里、或 `CANON_ACTOR` 也有值时退出码 2，什么都不写）；否则 `CANON_ACTOR` 去掉首尾空白后有值时用它（在 Claude Code 或 Codex 会话里必须以 `agent:` 开头，否则退出码 2、什么都不写）；否则在 Claude Code 会话里（`CLAUDECODE=1`）用 `agent:` 加 `CLAUDE_CODE_SESSION_ID` 的前 8 个字符，该变量为空时用 `agent:unknown`；Codex 会话由非空的 `CODEX_SESSION_ID` 或 `CODEX_THREAD_ID` 识别，优先取前者作完整会话 id；没有前者时，先取本仓库启动 hook 已记录的线程归属，没有记录才把线程当成独立会话。执行者为 `agent:codex-<完整会话id>`；线程与已确定的会话不同则为子会话，未传 `--as` 的子会话自动追加 `:<CODEX_THREAD_ID>`，传了 `--as` 时必须等于它自己的线程 id，否则退出码 2。Codex 优先于继承来的 Claude 环境；普通终端（没有上述宿主标识）才用 `human:<操作系统用户名>`。Claude Code 不带 `--as` 的调用，同一个会话的主会话和所有子 agent 是同一个执行者 `agent:<会话>`；子 agent 带 `--as <自己的 agent_id>` 时是 `agent:<会话>:<agent_id>`，和主会话分得开，主会话不带名字（D-62，装了 hook 的项目里由 hook 强制，BR-2340）。canon 不给子 agent 注入身份；Claude Code 中也不验证 `--as` 的值是不是它的 `agent_id`（事件里记的 worktree 见 BR-2131）。`CANON_ACTOR` 的值是一个不透明的名字，`agent:x:y` 这种含冒号的值也照原样使用，不解析。

Codex 的启动 hook（canon brief --hook --runtime codex）读取原生 SessionStart 或 SubagentStart 的 session_id 和 agent_id，把归属记为 session.codex 事件；操作者仍按本规则的 agent 身份记录。相同线程的相同归属重复启动不重复记事件，改变时记新事件。之后只有 CODEX_THREAD_ID 的 shell 也能在本仓库共用协调数据中取到亲缘，不猜父线程。不是启动事件、缺少会话或子 agent id 的输入退出码 2，不写归属；读不到已有归属时以退出码 4 报环境错误，不把子线程当成人。

## 例子

- Claude Code 会话，会话 ID `89d45e3f-b9c5` → `agent:89d45e3f`
- Claude Code 会话里设置 `CANON_ACTOR=human:alice` → 退出码 2
- 普通终端，用户 `apple` → `human:apple`
- `CANON_ACTOR` 只有空格 → 当作没有设置，按后面的顺序确定
- 会话 `3d606482-8b99` 的子 agent 不带 `--as`（环境和主会话一样）→ `agent:3d606482`，和主会话相同
- 会话 `3d606482-8b99` 的子 agent `a1b2` 运行 `canon work start C-1 --as a1b2` → `agent:3d606482:a1b2`，认领的持有者是它；主会话 `agent:3d606482` 在那个 worktree 运行 `canon work land` → 退出码 5
- `--as a1b2` 和 `CANON_ACTOR=agent:x:y` 同时给 → 退出码 2，没有认领、没有事件
- `--as 'a b'`、`--as ''`、`--as a:b` → 退出码 2，什么都不写
- 普通终端（没有任何宿主标识）里 `canon work start C-1 --as a1b2` → 退出码 2
- 子 agent 第二次运行 `canon work land` 忘了 `--as` → 执行者是 `agent:3d606482`，不是持有者 `agent:3d606482:a1b2`，退出码 5
- Claude Code 会话 `3d606482-8b99` 里设置 `CANON_ACTOR=agent:89d45e3f:add88b47` → 照用 `agent:89d45e3f:add88b47`

- Codex 会话 CODEX_THREAD_ID=session-a、没有 CODEX_SESSION_ID → agent:codex-session-a；另一会话 session-b → agent:codex-session-b
- Codex 主会话 CODEX_SESSION_ID=session-a、CODEX_THREAD_ID=session-a → agent:codex-session-a；子会话 CODEX_THREAD_ID=child-1 → agent:codex-session-a:child-1，带 --as child-1 结果相同，带 --as other 退出码 2
- Codex 设置 CANON_ACTOR=human:alice → 退出码 2，什么也不写
- Claude 和 Codex 的 session 文本相同 → 两者的执行者仍不同

- 原生 SessionStart 输入 session_id=root；SubagentStart 输入 session_id=root、agent_id=child → 各记一条 session.codex；重复相同启动不增加事件，只有 CODEX_THREAD_ID=child 的后续命令仍归 root。
- SubagentStart 缺 agent_id → 退出码 2，不记归属；已记录的归属损坏 → 后续命令退出码 4，不创建认领。
- Codex 主会话直接运行带 --as worker 的 CLI → 追加 :worker；原生 Bash hook 对主会话带 --as 的限制另见 BR-2340。
