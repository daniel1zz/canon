## 规则

`canon work after-land` 找到最近一次合入（按合入排队的顺序，和 BR-2138 相同）在后台运行的那批 `after_land` 命令；给了变更编号 `C-n` 时，找的是这个变更最近一次合入的那批。它先像 `canon brief` 一样把已结束的命令记成 `hook.exit` 事件（BR-2137），再输出：

- 第一行：变更编号、日志路径和总的结论：全部以 0 结束（`all finished, all exited 0`）、没有失败但还没结束（`not finished yet`）、有失败而其余命令还在运行（`failed; others still running`）、全部结束且有失败（`finished; some failed`）；
- 每条命令一行：序号、命令、`exited <退出码>` 或 `still running`；
- 日志里以 `code-review:` 开头的行，原样照抄（例如建了哪个 issue、评论了哪个 issue、`no findings`）；
- 同一次合入（同一个排队号）的合入后评审（BR-2441）有的话：一行 `review after the landing of <变更> (log: <日志路径>): <状态>`，状态是 `queued, not started yet`、`running`、`finished` 或 `could not run`，下面是这次评审日志的每一行，各缩进两格。项目没有 `after_land` 命令、找不到那批命令时，报告这个变更（没给变更时是全部）最近一次合入的评审。

读到的一批总是完整的，因为合入在启动后台命令之前就把整批记下（BR-2059）。

退出码：全部命令都以 0 结束、评审（有的话）已完成为 0；有已结束且退出码不为 0 的命令，或评审 `could not run`，为 1（不管其余是否结束）；没有失败但还有命令没结束、或评审还在排队或运行，为 75；日志文件不见了为 4，输出一行说明退出码无法得知并给出路径；没有任何一次合入运行过后台命令或合入后评审、或给出的变更没有这样的合入时为 3。评审给出的意见不影响退出码。加 `--json` 时输出这批命令（变更、日志、每条命令和退出码、`code-review:` 行、`state`）和 `landedReview`（评审的状态、日志和日志的每一行，没有时为 `null`），退出码相同。

## 例子

- 最近一次合入的变更是 `C-5`，日志里有 `[hook 1/2 exited 0]`、`code-review: no findings`、`[hook 2/2 exited 0]` → 输出 `[1/2] ... exited 0`、`[2/2] ... exited 0` 和 `code-review: no findings`，退出码 0
- 最近一次合入的第二条命令以 1 退出，第一条以 0 退出 → 退出码 1，第一行的结论是 `finished; some failed`
- 第一条以 2 退出，第二条还在运行 → 第二条显示 `still running`，结论是 `failed; others still running`，退出码 1
- 两条都还在运行 → 退出码 75
- `canon work after-land C-4`，这个变更的合入早于最近一次合入 → 报告它那批，不是最近一次
- `canon work after-land C-999`，这个变更没有这样的合入 → 退出码 3
- 日志被删掉 → 退出码 4，输出里有 `the log is missing`
- 运行之后，已结束的命令各有一条 `hook.exit`，再运行一次不会重复
