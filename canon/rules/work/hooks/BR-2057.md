## 规则

合入时，`canon check` 和合入自己的其余步骤（BR-2014）都通过之后、floor 之前（BR-2014；`floor_timing` 为 `after` 时没有 floor 这一步，BR-2218），在即将成为 main 的代码树（已经 rebase 的变更 worktree）里依次运行 `hooks.before_land` 的命令，环境变量有 `CANON_EVENT=before_land`、`CANON_CHANGE`、`CANON_BASE`（合入前的 main）、`CANON_HEAD`（将成为 main 的提交）、`CANON_BRANCH`。一起测的那批里，`before_land` 在哪棵树上运行、`CANON_BASE` 和 `CANON_HEAD` 是哪两个提交，见 BR-2172。第一个退出码非 0 的命令让合入被拒绝（退出码 1，原因 `hook`），后面的命令不再运行，main 不动。

## 例子

- `before_land: "test -e CHANGELOG.md"`，树里没有这个文件 → 合入被拒绝，退出码 1，main 不变，`land.refuse` 的原因是 `hook`
- 同一个配置，树里有 `CHANGELOG.md` → 合入成功
- floor 失败（`before_land` 已通过）→ 合入被拒绝，原因 `floor`；`before_land` 失败 → floor 不运行
- `canon check` 或措辞判断（BR-2239）拒绝 → `before_land` 的命令不运行
