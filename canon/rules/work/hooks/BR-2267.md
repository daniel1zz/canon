id: BR-2267
title: setup 和 hook 命令拿到变更的端口 CANON_PORT，同一变更不变，进行中的两个变更不同
status: active
business: 变更的端口
---

## 规则

`canon/config.yaml` 设了 `ports`（BR-2268）时，`canon work start` 跑的 `setup` 命令和每条 hook 命令（事件是关于某个变更的：`after_start`、`before_land`、`after_land`、`after_stop`）的环境里有 `CANON_PORT`，值是这个变更的端口（D-41、D-48）：在范围内；同一个变更每次都是同一个值（停下再开始、跑不同事件的 hook 都一样），只要 `ports` 没改；两个变更的 worktree 都还在时，它们的端口不同，几个 `canon work start` 同时运行也一样。

只有知道变更的 worktree 在哪的地方会为变更新分配端口并记下这个 worktree：`canon work start`（`setup` 和 `after_start` 用它这次分到的端口；范围用完分不到时两者的 `CANON_PORT` 是空字符串，开始照常进行，BR-2269）和 `after_stop`（在变更的 worktree 里运行；分不到时见 BR-2287）。`before_land` 和 `after_land` 只读变更已有的记录，从不新建或改动记录：没有记录，或者记下的端口不在范围内（`ports` 改过）时，这两个事件的 `CANON_PORT` 是空字符串（BR-2287）。记下的端口不在范围内时，下一次分配给这个变更重新分配。

一个变更的 worktree 被清理或放弃之后，它的端口可以分给别的变更（顺序和探测见 BR-2288）。没设 `ports`，或者事件不关于任何变更（`after_green`）时，`CANON_PORT` 是空字符串；事件没有要运行的命令时不查端口。一起测（D-26）时批的临时 worktree 里跑的 `setup` 不属于任何一个变更，`CANON_PORT` 是空字符串。运行 canon 的进程环境里原有的 `CANON_PORT` 不会传给 `setup`、批的 `setup` 和 hook 命令（BR-2199：同名时 canon 设的值优先）。

## 例子

- `ports: 4100-4199`，`setup: 'echo "$CANON_PORT" > port.txt'`，新开第一个变更 → `port.txt` 是 `4100`；再开一个 → 新 worktree 的 `port.txt` 是 `4101`
- 同样配置，`after_start` 和 `after_stop` 都写 `echo "$CANON_PORT" >> ports.txt`，开始、停下、再开始同一个变更 → 三行都是同一个值
- `ports: 4100-4199`，8 个进程同时 `canon work start --title "T<i>"` → 8 个都成功，`setup` 写出的 8 个端口两两不同，都在 4100 到 4199 之间
- `ports: 4100-4101`，开 C-1（4100）、C-2（4101），`canon work clean C-1` 删掉 C-1 的 worktree 之后开 C-3 → C-3 拿到 4100
- 没设 `ports`，运行 canon 的环境里有 `CANON_PORT=9999`，`setup: 'echo "[$CANON_PORT]" > port.txt'` → `port.txt` 是 `[]`
- C-1 在 `ports: 4100-4199` 下拿到 4100，之后配置改成 `ports: 5000-5099` → C-1 下一次的 `after_stop` 拿到 5000
- `ports: 4100-4199`，C-1 在 `ports` 配置之前就开始、没有端口记录，它的 worktree 已经清理，合入后跑 `after_land: 'echo "[$CANON_PORT]" > port.txt'` → `port.txt` 是 `[]`，协调数据库里没有 C-1 的端口记录
- 同样配置，C-1 在 4100 有记录，`after_land` 和 `before_land` 读到的 `CANON_PORT` → 都是 `4100`
- `ports: 4100-4199`，`land_batch_max: 2`，`setup` 在批的 worktree 里写 `echo "[$CANON_PORT]"`，运行 canon 的环境里有 `CANON_PORT=9999`，两个变更一起测 → 批的 `setup` 写出 `[]`
