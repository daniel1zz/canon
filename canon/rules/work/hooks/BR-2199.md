## 规则

每条 hook 命令（五个事件都一样）作为 `sh -c <命令>` 运行，工作目录是这个事件规定的目录（BR-2056、BR-2057、BR-2058、BR-2030、BR-2222）。环境变量是运行 canon 的进程的全部环境变量，再加上 `CANON_EVENT`（事件名）、`CANON_CHANGE`（变更编号，没有变更时为空字符串；杂务也为空）、`CANON_SUBJECT`（此次工作的完整身份，没有关联工作时为空）、`CANON_KIND`（业务变更为 change、杂务为 chore，没有关联工作时为空）、`CANON_ACTOR`（运行 canon 的身份）、`CANON_WORKTREE`（命令运行的目录）、`CANON_PORT`（变更的端口，没有时为空字符串，BR-2267），以及各事件自己的变量（如 `CANON_BASE`、`CANON_HEAD`、`CANON_NEXT`、`CANON_GREEN`）；同名时 canon 设的值优先。标准输入是空的：读标准输入的命令立刻读到结尾，不会停下来等输入。

## 例子

- `after_start: 'echo "$CANON_ACTOR $CANON_WORKTREE" > who.txt'`，以 `agent:a` 开始变更 → `who.txt` 是 `agent:a` 和新 worktree 的路径
- 杂务执行 before_land → CANON_SUBJECT 是杂务身份，CANON_KIND 是 chore，CANON_CHANGE 为空；业务变更的 CANON_CHANGE 不变
- `after_stop: 'echo "$CANON_EVENT" > e.txt'` → `e.txt` 是 `after_stop`
- 运行 canon 时环境里有 `FOO=1`，hook 是 `echo "$FOO" > foo.txt` → `foo.txt` 是 `1`
- hook 是 `cat; echo done > done.txt` → 立刻结束，`done.txt` 是 `done`
- 运行 canon 时环境里已有 `CANON_EVENT=x`，`after_start` 的命令读到的 `CANON_EVENT` → `after_start`
