## 规则

`canon work land` 和 `canon chore land` 在排队之前预跑；顺序是先按 BR-2542 补跑测试，再做 `--finish` 的关闭提交，然后才是这次预跑。预跑在变更的 worktree 里按 BR-2057 的顺序运行一次 `hooks.before_land` 的每个命令。环境变量同 BR-2057，只是 `CANON_BASE` 是分支和 main 的分叉点、`CANON_HEAD` 是分支现在的提交，另加 `CANON_HOOK_PREVIEW=1`，hook 可以凭它在预跑时跳过自己。

第一个退出码非 0 的命令让合入被拒（退出码 1，原因 `hook`），不进队列，后面的命令不再运行；`--finish` 做的关闭提交照 BR-2018 撤回。信息和 BR-2057 一样写明命令、退出码和输出，再加一句这是排队前在分支上预跑的：要是这个 hook 只有 rebase 到 main 之后才会通过，就先 rebase 再合入。预跑的每个命令照常记一条 `hook.run` 事件，另带 `preview: true`。都通过时照常排队，轮到时照 BR-2057 在要成为 main 的树上再跑一次（D-168）。没有配置 `hooks.before_land` 时什么都不做。

## 例子

- `before_land: "test -e CHANGELOG.md"`，分支上没有这个文件 → 排队前被拒，退出码 1，原因 `hook`，没有 `queue.enter` 事件
- 同一个配置，分支上有这个文件 → 预跑通过，排队；轮到时在 rebase 后的树上再跑一次
- hook 是 `test "$CANON_HOOK_PREVIEW" = 1 || check.sh`，check.sh 会失败 → 预跑通过，轮到时被拒
- 预跑和轮次里各跑一次 `exit 0` → 两条 `hook.run`，前一条带 `preview: true`
- 没有配置 `hooks.before_land` → 不预跑，照常排队
