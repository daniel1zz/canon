title: hooks 的每个事件写一条命令或一个命令列表，别的写法是配置错误
status: active
business: hook 怎么运行
---

## 规则

`canon/config.yaml` 的 `hooks` 是一个 mapping，键只能是 `after_start`、`before_land`、`after_land`、`after_stop`、`after_green`（BR-2222），每个键的值是一条命令（字符串）或命令（字符串）的列表，命令里必须有空白以外的字符；一条命令等于只有它一项的列表。`hooks` 本身写 `null`、写空 mapping，或某个事件写空列表，都表示这些事件没有命令。下面任何一种都是配置错误，所有命令以退出码 2 失败（BR-2045），提示写明出错的 `hooks.<事件>`：`hooks` 不是 mapping；有别的事件名；某个事件的值是 `null`、数字、布尔值或 mapping；列表里有一项不是字符串，或者是空白。

## 例子

- `hooks: {after_land: "bun run build"}` → `after_land` 有一条命令
- `hooks: {after_land: ["bun run build", "bun run notify"]}` → 两条命令，按顺序运行
- `hooks: {after_green: "bun run build"}` → `after_green` 有一条命令（BR-2222）
- `hooks: null`、`hooks: {}` 或 `hooks: {after_start: []}` → 照常执行，没有 hook 命令
- `hooks: [x]` → 退出码 2，提示 `hooks` 必须是 mapping
- `hooks: {before_start: x}` → 退出码 2，提示 unknown hook event
- `hooks: {after_start: ""}` 或 `hooks: {after_start: "  "}` → 退出码 2，提示里有 `hooks.after_start`
- `hooks: {after_start: null}` → 退出码 2
- `hooks: {after_start: [true]}`（YAML 的布尔值）→ 退出码 2；写成 `["true"]` → 是一条命令 `true`
