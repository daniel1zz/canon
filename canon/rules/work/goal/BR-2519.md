## 规则

`canon goal check --hook [--runtime claude|codex]` 由会话的 Stop hook 运行（BR-2520），从标准输入读宿主的 JSON，用其中的 `session_id` 认出会话（身份算法同 BR-2518），总是在标准输出写一个 JSON 对象、退出码 0（D-132）。

- 这个会话没有目标 → 输出 `{}`，放行。
- 目标的版本和它们的模块（`dropped` 的不算）里的成功标准（BR-2504）全部已满足 → 输出 `{"systemMessage": "goal reached: <版本编号>"}`，删掉这个会话的目标，放行。
- 没有未满足和未证明的、但有待负责人的 → 输出 `{"systemMessage": "goal: only the owner's acceptance is left: <条数> criterion(s)"}`，放行，目标保留。
- 还有未满足或未证明的成功标准，但这已经是连续第三次停下时都没有进展（下一段）→ 输出 `{"systemMessage": "goal: 3 continuations in a row without progress; stopping, the goal stays (canon goal stop ends it)"}`，放行，目标保留，计数清零。
- 否则拦下：输出 `{"decision": "block", "reason": "<说明>"}`。说明依次写：`Goal (canon goal): <版本编号> not reached: <n> success criteria still unmet or unproven.`；最多 5 条这样的成功标准，每条一行 `- <文档编号>/<编号或 -> [<状态>] <文字>`，有推进它的变更时加 `  (advanced by <变更编号>)`（同 BR-2505 的推进关系）；然后一行 `Next: continue a change that advances one of them, or start one with advances: [<文档编号>/S<k>]; land it, then stop again.`；最近 5 次合入的变更里有不推进目标（`advances` 没写、写 none 或没有指向目标里的成功标准）的时，再一行 `Drift: <k> of the last <m> landed changes advance none of these criteria.`。

**没有进展**：每次拦下时记下 main 的提交、hook 运行所在工作树的提交和 `git status --porcelain` 的输出；下一次停下时三者都和记下的一样，就算没有进展，连续计数加一；有任何一样变了，计数清零。计数到 3 时放行（上一条）。

canon 读不了项目或协调数据库时，输出 `{"systemMessage": "canon goal check failed: <原因>"}` 放行，不困住会话。

## 例子

- 会话没开目标 → `{}`
- 目标 `R-5`，它和模块 `F-1` 的成功标准全部已满足 → `goal reached: R-5`，`canon goal` 之后是 `no goal`
- 剩下的只有一条待负责人 → `only the owner's acceptance is left: 1 criterion(s)`，放行
- 还有 `F-1/S1` 未满足（`C-9` 推进它）→ `decision: block`，reason 里有 `- F-1/S1 [未满足] … (advanced by C-9)` 和 `Next:` 一行
- 最近 5 次合入有 3 个没写 `advances` → reason 里有 `Drift: 3 of the last 5 landed changes advance none of these criteria.`
- 拦下之后连着三次停下，中间什么都没变 → 前两次照常拦下，第三次放行，systemMessage 写 `3 continuations in a row without progress`
- 两次停下之间提交了一次 → 计数清零，照常拦下
- 协调数据库读不了 → `canon goal check failed: …`，放行
