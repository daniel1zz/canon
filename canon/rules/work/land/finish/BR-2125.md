title: canon work land 只给自己移动 main 的那条 git 命令带上放行标记
status: active
---

## 规则

`canon work land` 移动 main 时，只在那一条 git 命令的环境里设置 `CANON_LAND_MAIN=<main 的新提交>`：main 没有被签出时是比较并交换的 `git update-ref`，有 worktree 签出了 main 时是在那里快进的 `git merge --ff-only`（BR-2039）。所以装了 canon 的 git hook（BR-2126）以后，两种情况都照常合入；canon 的其他 git 命令（rebase、`--finish` 在变更分支上的关闭提交）不带这个标记，也不需要，因为它们不移动 main。

## 例子

- 装了 canon 的 git hook，主 checkout 签出了 main 且干净，合入 `C-1` → 成功，main 和主 checkout 的文件都是新的
- 装了 canon 的 git hook，主 checkout 处于 detached 状态，合入 `C-1` → 成功，main 指向新提交
- 合入结束后，canon 进程的环境里没有 `CANON_LAND_MAIN`
