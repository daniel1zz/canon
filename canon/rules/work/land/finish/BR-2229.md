## 规则

`canon work land --finish` 已经把变更文件改成 `status: done`、但 `git commit` 失败（例如项目的 pre-commit hook 拒绝）时，canon 只取消暂存，不再把变更文件改回去：文件留在工作区里，是一处没有提交的改动，里面是 `status: done` 加上这期间任何人保存的编辑。文件系统没有跨进程的比较并交换，canon 无论怎样核对后再写回，都可能盖掉核对之后别人保存的编辑，所以不写回。拒绝按 BR-2193 以 `environment`、退出码 4 结束，不进队列；信息写明变更文件 `is left with status: done and not committed`，以及下一步：修好让提交失败的原因，把 `status` 改回 `open`（`git diff` 里只有这一行时可以用 `git checkout -- <文件>`），再 `canon work land --finish`。

改变更文件这一步本身失败（还没写）时，文件保持原样，信息里没有这句。

## 例子

- 项目的 pre-commit hook 退出码 1，`canon work land --finish` → 退出码 4，原因 `environment`，分支上没有 `canon: close C-1` 提交，`git status --porcelain` 只有一行 ` M canon/changes/C-1.md`，文件里是 `status: done`，信息含 `is left with status: done and not committed` 和 `land --finish`
- pre-commit hook 往变更文件里追加一行后退出码 1 → 原因 `environment`，追加的那行和 `status: done` 都在，信息同上
- hook 通过，提交成功 → 照常进队列，没有这句信息，`git status` 干净
