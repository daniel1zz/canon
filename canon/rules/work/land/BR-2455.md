## 规则

`canon work unstall <C-n> --reason "<理由>"` 放行一个按 BR-2454 停下的变更。按这个顺序检查，先成立的决定退出码，被拒时什么都不写：

- 变更编号格式不对、`--reason` 没给或去掉首尾空白后为空 → 退出码 2；
- 执行者是子 agent（`agent:<会话>:<名字>`）→ 退出码 1，信息写明只有主会话或人能放行；
- 事件表里没有这个变更的任何合入事件 → 退出码 3；
- 按 BR-2454 数出的连续被拒次数少于 3 → 退出码 1，信息写明现在是几次、不需要放行。

通过时写一条 `land.unstall` 事件（主题是这个变更，详情有 `reason` 和放行前的 `refusals`），输出 `C-n may land again; 3 more refusals in a row stop it again`，退出码 0。认领不变：子 agent 接着在自己的 worktree 里改，再 `canon work land`。

## 例子

- C-5 连续被拒 3 次，主会话运行 `canon work unstall C-5 --reason "拆出了代码改动，冲突的文件交给 C-7"` → 写 `land.unstall`，`refusals` 为 3，退出码 0；子 agent 下一次合入照常入队
- 子 agent 自己运行 `canon work unstall C-5 --reason x` → 退出码 1，什么都不写
- C-5 只被拒过 2 次 → 退出码 1，信息写明 2 次
- `canon work unstall C-5` 不带 `--reason` → 退出码 2
- `canon work unstall C-999 --reason x`，没有它的合入事件 → 退出码 3
- 人在终端里运行（执行者不是 agent）→ 和主会话一样可以放行
