## 规则

`canon work unstall <工作身份> --reason "<理由>"` 放行一份按 BR-2454 停下的工作，工作身份是变更编号（`C-n`）或杂务身份（`chore-<UUID>`）。按这个顺序检查，先成立的决定退出码，被拒时不写 `land.unstall`、不改任何状态：

- 工作身份既不是变更编号也不是杂务身份、`--reason` 没给或去掉首尾空白后为空 → 退出码 2；
- 执行者是子 agent（`agent:<会话>:<名字>`）→ 退出码 1，信息写明只有主会话或人能放行；子 agent 运行时 check-as hook 先拦下它（BR-2340）；
- 事件表里没有这份工作的任何合入事件 → 退出码 3；
- 按 BR-2454 还没有停下 → 退出码 1，信息写明现在连续被拒几次、不需要放行。

通过时写一条 `land.unstall` 事件（主题是这份工作的身份，详情有 `reason` 和放行前的 `refusals`），输出 `<工作身份> may land again; its count of refusals in a row starts from zero`，退出码 0。认领不变：子 agent 接着在自己的 worktree 里改，再 `canon work land`。

## 例子

- C-5 连续被拒 3 次，主会话运行 `canon work unstall C-5 --reason "拆出了代码改动，冲突的文件交给 C-7"` → 写 `land.unstall`，`refusals` 为 3，退出码 0；子 agent 下一次合入照常入队
- 子 agent 自己运行 `canon work unstall C-5 --reason x` → 退出码 1，什么都不写
- C-5 只被拒过 2 次、还没停下 → 退出码 1，信息写明 2 次
- `canon work unstall C-5` 不带 `--reason` → 退出码 2
- `canon work unstall C-999 --reason x`，没有它的合入事件 → 退出码 3
- `canon work unstall chore-1f0e2d3c-4b5a-6978-8a9b-0c1d2e3f4a5b --reason x`，没有它的合入事件 → 退出码 3，杂务身份不是用法错误
- `canon work unstall chore-abc --reason x`，`chore-` 后不是完整 UUID → 退出码 2
- 人在终端里运行（执行者不是 agent）→ 和主会话一样可以放行
