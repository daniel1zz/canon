title: "合入时加 --finish 会关闭变更并释放认领"
status: active

## 规则

`canon work land --finish` 在进入队列前，用一个随工作一起合入的提交（`canon: close C-n`）把变更状态设为 `done`，所以 floor、`canon check` 和评审验证的就是会成为 main 的那棵树；合入成功后释放认领，并删除这个变更的 handoff。

这次合入没有让 main 移动（任何一种拒绝、排队超时、被信号终止）时，撤回这个关闭提交，所以变更只会和合入一起变成 `done`：

- 撤回的条件：HEAD 仍是检查过的那个关闭提交（分支用比较并交换移回它之前，这期间新做的提交不会被丢掉），并且变更文件没有未提交的改动。条件满足时，变更在 worktree 里回到 `open`，输出写明 `reopened`，认领不变。
- 条件不满足（关闭提交已不在最上面，例如 `before_land` 或会话又提交了东西；或变更文件有未提交的改动）时，不改动分支和文件，输出写明 `was not reopened` 和原因，以及变更仍显示 done 但没有合入。

例外：一起测的成员被锁定之后（BR-2172）被信号终止，它自己不撤回关闭提交；如果 main 最后没有移动，领头在成员的合入进程已经不在时，按上面同样的条件替它撤回；成员进程还在，就等它自己的合入结束时按本规则处理。

变更在合入前就已经是 `done`（例如之前一次合入没能撤回关闭提交）时，`--finish` 不再做关闭提交，照常合入，合入后照样释放认领。

只放开仍由自己在这个 worktree 里持有的认领，也只在放开了它时删除 handoff：合入结束时认领已经不归自己（合入期间认领记着合入进程，BR-2142，正常情况下别人接手不了；这一条防的是认领在这之外被改掉，例如有人直接改了协调数据库）时，别人的认领和 handoff 都保持不变，输出里写明 `claimed by another session now`。

## 例子

- `canon work land --finish` 成功 → main 上 `C-1` 的状态是 `done`，`canon work status` 里没有 `C-1` 的认领和 handoff
- 合入等待期间 `C-1` 的认领在协调数据库里被改成 agent:b 的、agent:b 写了 handoff → 合入成功、`C-1` 是 `done`，但认领仍归 agent:b，handoff 还在
- `canon work land --finish` 的 floor 失败 → 拒绝，main 不动，worktree 最上面不再有 `canon: close C-1` 提交，`C-1` 仍是 `open`，输出 `reopened`，认领还在
- 一起测时 B 被锁定后进程没了，main 的比较并交换又失败 → 领头撤回 B 的关闭提交，B 的变更回到 `open`；B 的进程还在时不动它
- `canon work land --finish` 排队超时，或合入进程收到 SIGTERM → 同样撤回关闭提交，`C-1` 仍是 `open`
- 正在做关闭提交、还没进队列时收到 SIGTERM → 关闭提交照样撤回，退出码 143，`C-1` 仍是 `open`
- 合入被拒后、撤回之前，会话在 worktree 里又提交了一个修复 → 不撤回，修复提交和文件都在，输出 `was not reopened`，写明 `C-1` 仍显示 done 但没有合入
- `C-1` 在分支上已经是 `done`，`canon work land --finish` → 没有新的 `canon: close C-1` 提交，合入成功，认领释放
- 撤回时 `canon/changes/C-1.md` 有未提交的改动 → 不撤回，HEAD 仍是关闭提交，改动保留，输出 `was not reopened`
