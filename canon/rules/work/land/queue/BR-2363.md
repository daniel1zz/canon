id: BR-2363
title: 负责人用 canon backlog urgent 标的优先在下一次轮次生效，到变更合入或被撤销为止
status: active
---

## 规则

`canon backlog urgent <C-n> --relayed "<原话>"` 把一个开着的变更记进协调数据库，作为负责人标的优先。等待合入的条目按这个顺序轮到（BR-2232 的顺序在修复变更和 `优先合入` 之间插入这一级）：修复 main 的变更，负责人用这个命令标的变更，main 上 `优先合入` 一节的变更，其余；同一级里按入队顺序（BR-2020）。优先级在每次查看轮次时重读，所以命令执行之后的下一次轮次就生效，不用等任何合入。正在合入的条目不被打断（BR-2178）；一起测取成员也按同样顺序（BR-2172）。标记在这个变更合入时（单独合入或在一批里）自动删除，或在 `canon backlog urgent <C-n> --clear --relayed "<原话>"` 时删除；变更不是开着的（已合入、关闭）时标记被拒绝，退出码 2，不记。对已经标过的变更再标一次只更新原话。`--clear` 的变更没有被标时退出码 3。

## 例子

- C-1、C-2 在队列里等，`canon backlog urgent C-2 --relayed "C-2 先合"` → 下一次轮次 C-2 先轮到，C-1 在它之后
- C-1、C-2 在等，C-3 是 main 没通过时的修复变更，C-2 被标了优先 → 顺序 C-3、C-2、C-1
- C-2 被标了优先，main 的 `优先合入` 里列着 C-1，两者都在等 → C-2 先于 C-1
- C-1 正在合入，C-2 刚被标优先 → C-2 等 C-1 合入结束才轮到
- C-2 被标优先后合入成功 → 数据库里 C-2 的标记没有了，之后 `canon work status` 不再列它
- C-2 被标优先后执行 `canon backlog urgent C-2 --clear --relayed "不用了"` → 标记没有了，C-1 先于 C-2
- 没有被标过的 C-2 执行 `--clear --relayed "不用了"` → 退出码 3
- C-5 已经合入（状态不是 open），`canon backlog urgent C-5 --relayed "x"` → 退出码 2，没有记录标记
- 已经停止或放弃、标记还在的变更，`--clear` 照常能清掉标记（标记不自动清，由负责人撤销）
- 没有人执行过这个命令 → 顺序和 BR-2232 完全一样
