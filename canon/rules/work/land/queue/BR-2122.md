## 规则

`canon work land` 排队后轮到自己时，写一条 `land.turn` 事件，记下队列条目编号、从进入队列到轮到自己的毫秒数（`waited_ms`），以及那时机器的 5 分钟平均负载（`load`，一位小数）和 CPU 数（`cpus`），这样排队等待的时间和 floor 用的时间能分开算，`canon work start` 也能比较负载高低时合入用多久（BR-2400）；平台读不到负载（三个平均值都是 0）时不带 `load` 和 `cpus`。没轮到就超时或被终止时不写这条事件。`land.turn` 不是拒绝，不算进 `canon stats` 的检查。

## 例子

- 队列里没有别人，执行 `canon work land` → 有一条 `land.turn`，`waited_ms` 接近 0
- 前面有一个合入者，等它结束后轮到自己 → `land.turn` 的 `waited_ms` 不小于前一个合入者占用的时间
- 排队时被 SIGTERM 终止 → 没有 `land.turn`，有 `land.killed`
- 轮到时 5 分钟负载是 12.34、8 个 CPU → `land.turn` 带 `load: 12.3`、`cpus: 8`
- 平台读不到负载 → `land.turn` 没有 `load` 和 `cpus`
