## 规则

合入者在队列里等待期间（正在别人的批里被测时除外，BR-2172），每当发现 main 和上次看到的不同（包括第一次看），就在内存里把 main 和自己的 HEAD 合并一次（`git merge-tree --write-tree`，D-22），不碰 worktree 和暂存区。合并有冲突时，不再等轮次，立刻以退出码 1 拒绝，原因 `conflict`，提示写明这是等待时发现的、和 main 的哪个提交、冲突的文件，以及在自己的 worktree 里 `git rebase main` 解决后重新合入，排队位置保留到什么时候（BR-2177）；排队条目标为失败，事件表记一条原因 `conflict` 的 `land.refuse`，worktree 的提交和文件都不变。合并没有冲突就照常等待。预测跑不起来（例如 git 低于 2.38）时打印一行 `conflict check while waiting did not run` 和原因，照常等待，轮到时由真正的 rebase 决定（BR-2015）。

## 例子

- C-2 改了 `app.txt` 第 2 行，正在排队，前面有人在合入；这时 main 上多了一个也改 `app.txt` 第 2 行的提交 → C-2 在几秒内以 `conflict` 拒绝，提示列出 `app.txt`，前面的人仍在合入，C-2 的 HEAD 和工作区不变，没有 C-2 的 `land.turn`
- 等待期间 main 上多了一个只加了 `theirs.txt` 的提交 → C-2 继续等待，前面的人合入结束后 C-2 照常合入
- 预测跑不起来（例如给 `git merge-tree` 的提交不存在）→ 不拒绝，打印 `conflict check while waiting did not run` 和原因
