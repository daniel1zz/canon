status: active

## 规则

等待合入的条目按优先级决定谁先轮到：修复 main 的变更（`canon work start --fix-main` 开的那个，BR-2221）最先；其次是负责人用 `canon backlog urgent` 标的变更（BR-2363）；再其次是 main 上 `canon/backlog.md` 里标题为 `优先合入` 的那一节列出的变更（这一节到下一个同级或更高级的标题为止，列表项的认定和 BR-2148 一样）；其余的最后；同一优先级里按进入队列的顺序（BR-2020）。优先级在每次等待的合入者查看轮次时从 main 上已提交的待办清单和协调数据库重新读取，所以负责人在别人排队期间改清单也会生效；变更在自己 worktree 里改的待办清单不起作用。正在合入的条目不被打断（BR-2178），一起测（BR-2172）取成员时也按同样的顺序。没有 `canon/backlog.md` 或没有这一节时，不存在 `优先合入` 这一级，其余级别（修复变更、命令标的变更）照常。

## 例子

- 队列里 C-1、C-2 在等，main 上的待办清单有 `## 优先合入` 一节，下面列着 `- C-2` → C-2 先轮到，C-1 在它之后
- 同样的清单，C-2 只改了自己 worktree 里的 `canon/backlog.md`、main 上没有这一节 → C-1 先轮到
- C-1、C-2 在等，C-2 是 main 没通过时用 `--fix-main` 开的修复变更 → C-2 先轮到；C-3 在 `优先合入` 里时，C-2 仍先于 C-3
- C-1 正在合入，C-2 是修复变更、刚进队列 → C-2 等 C-1 合入结束后才轮到
- `优先合入` 下面列着 C-2，紧接着是 `## 其他` 一节，列着 C-1 → 只有 C-2 优先
- C-2 既是修复 main 的变更、又列在 `优先合入` 里，或又被命令标了优先 → 按最高的一级算一次，C-2 先轮到
