---
id: BR-2309
title: 同一个 worktree 的下一次合入先报出上一次被杀掉的合入并清理现场
status: active
---

## 规则

`canon work land` 认领续期成功、记下自己的 `land.start` 之前，如果这个 worktree 最近一次合入是 `interrupted`（BR-2308），先说出来（pid、开始时间、没有记录合入结果），清理它留下的东西，记一条 `land.interrupt`（内容有那条 `land.start` 的事件编号），再照常合入。清理：这个进程在队列里的 `waiting` 或 `landing` 条目标成 `abandoned`、结果 `lander process gone`；分支最新提交正是这个变更的关闭提交、而且没有 rebase 在进行时，撤回它（BR-2018，和信号处理一样）；rebase 做到一半时不撤销，只写出 `git rebase --abort` 和该 worktree，因为它可能是人在被杀之后自己开始的。上一次是 `running`（进程还在）时只说一句“上一次合入的进程 <pid> 还在跑”，不清理、不记 `land.interrupt`。之前没有 `land.start`，或上一次已有终结事件，什么都不说。

## 例子

- 上一次在 floor 里被 `kill -9` → 下一次 `land --finish` 先说上一次被杀掉，条目标 `abandoned`，关闭提交撤回后重新做一次，合入成功；事件里有 `land.interrupt`
- 上一次在做关闭提交之后、入队之前被 `kill -9` → 同样先报，关闭提交撤回
- 上一次被 `kill -9`，worktree 里有做到一半的 rebase → 报出并写明 `git rebase --abort`，rebase 原样留着，合入因此被拒绝，原因在信息里
- 上一次以 `land.refuse` 结束 → 不说，不记 `land.interrupt`
- 上一次的进程还在跑（两个 `land` 同时在同一个 worktree）→ 只说进程还在跑，不记 `land.interrupt`
- 同一次被杀掉的合入报过一次、记了 `land.interrupt` 之后，再下一次合入 → 不再报
