---
id: BR-2309
title: 同一个 worktree 的下一次合入先报出上一次被杀掉的合入并清理现场
status: active
---

## 规则

`canon work land` 认领续期成功、记下自己的 `land.start` 之前，如果这个 worktree 最近一次合入是 `interrupted`（BR-2308），先说出来（pid、开始时间、没有记录合入结果），清理它留下的东西，记一条 `land.interrupt`（内容有那条 `land.start` 的事件编号），再照常合入。清理：这个进程在队列里的 `waiting` 或 `landing` 条目标成 `abandoned`、结果 `lander process gone`；分支最新提交正是这个变更的关闭提交、而且没有 rebase 在进行时，撤回它（BR-2018，和信号处理一样）；rebase 做到一半时不撤销，只写出 `git rebase --abort` 和该 worktree，因为它可能是人在被杀之后自己开始的。上一次是 `landed`（进程已经不在、分支最新提交已经在 main 上，BR-2308）时，不撤回关闭提交，不放弃条目：这个进程的条目标成 `landed`，补记一条 `land.ok`（`sha` 是这个提交，`recovered: true`，没有 `base` 和 `diff`），说“上一次合入已经到了 main”，带 `--finish` 时照常释放认领，然后结束，不再合入第二次；记 `land.ok` 而不是 `land.interrupt`，因为统计、红 main 的修复判定和变更的合入记录只认 `land.ok`。上一次是 `running`（进程还在）而且带 `run` 时，前台已经接上了它，不会开始这次合入（BR-2392）；不带 `run`（例如旧版本 canon 开始的合入）时只说一句“上一次合入的进程 <pid> 还在跑”，不清理、不记 `land.interrupt`。之前没有 `land.start`，或上一次已有终结事件，什么都不说。

## 例子

- 上一次在 floor 里被 `kill -9` → 下一次 `land --finish` 先说上一次被杀掉，条目标 `abandoned`，关闭提交撤回后重新做一次，合入成功；事件里有 `land.interrupt`
- 上一次在做关闭提交之后、入队之前被 `kill -9` → 同样先报，关闭提交撤回
- 上一次在 main 已经移动之后、记 `land.ok` 之前被 `kill -9` → 下一次 `land --finish` 说上一次合入已经到了 main，条目标 `landed`，事件里补一条 `land.ok`（`recovered: true`），main 和分支都不动，退出码 0；没有 `land.interrupt`，没有撤回关闭提交
- 上一次被 `kill -9`，worktree 里有做到一半的 rebase → 报出并写明 `git rebase --abort`，rebase 原样留着，合入因此被拒绝，原因在信息里
- 上一次以 `land.refuse` 结束 → 不说，不记 `land.interrupt`
- 上一次的进程还在跑（两个 `land` 同时在同一个 worktree）→ 只说进程还在跑，不记 `land.interrupt`
- 同一次被杀掉的合入报过一次、记了 `land.interrupt` 之后，再下一次合入 → 不再报
