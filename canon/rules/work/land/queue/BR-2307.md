id: BR-2307
title: 合入开始时记 land.start，带上合入者的进程
status: active
business: 被中断的合入
---

## 规则

`canon work land` 认领续期成功之后、做任何慢的事（关闭提交、入队、rebase、floor）之前，在事件表记一条 `land.start`，内容有合入者自己的 `pid` 和 `pid_start`（进程启动时间，D-11），合入者是后台合入进程（BR-2390），不是跟随它的前台；读不到进程表时两项为空。后台合入还记 `run`（它的运行目录）。认领被别人持有而拒绝（`claim.refuse`）的合入不记。一次合入以一条终结事件结束：`land.ok`、`land.refuse`、`land.killed`、`land.lost` 或 `land.interrupt`（BR-2308）；一起测时领头为成员记的 `land.ok` 也算成员那次合入的终结事件。被信号终止的合入照常以 `land.killed` 结束（BR-2099），所以不会被当成被杀掉的；信号处理函数在入队前运行时也记 `land.killed`。`land.ok` 也可以由下一次合入补记（`recovered: true`，BR-2309）。canon 怎样判定一次 `land.start` 之后合入已经结束、进程是否还在，见 BR-2308。

## 例子

- 合入成功 → 事件依次是 `land.start`、`queue.enter`、`land.turn`、`land.ok`；`land.start` 的 `pid` 是后台合入进程，不是前台的 `canon work land`
- 因为有未提交的改动被拒绝 → `land.start` 之后是 `land.refuse`（`reason: dirty`）
- 认领被另一个执行者持有 → 只有 `claim.refuse`，没有 `land.start`
- 关闭提交做到一半时收到 SIGTERM → 最后一条事件是 `land.killed`，退出码 143，`canon work status` 不报被杀掉
- 在跑的合入被 `kill -9` → 有 `land.start`，没有任何终结事件
