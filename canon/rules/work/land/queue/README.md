# 排队和轮次（work/land/queue）

合入怎样排队、谁先轮到：一次只有一个合入者，按进入队列的顺序轮流，修复 main 的变更和负责人标为优先合入的变更先轮到；等待有时限；合入者掉线（心跳过期、进程不在）或被信号终止时，它的轮次立刻让出；被 `kill -9` 杀掉、来不及记任何结果的合入由 `land.start` 加进程探测发现并报出来（BR-2307 起，D-58），被判定放弃的条目不能再拿轮次；排队时 main 每变一次就预测一次冲突，会冲突就立刻拒绝；因冲突被拒、等待时超时或被信号终止的合入在限定时间内重新合入时回到原来的位置（D-29、D-75）。

不管：轮到之后的检查（`work/land/checks`）、一起测怎样取成员和测（`work/land/batch`，取成员的顺序用这里的优先级）、移动 main（`work/land/finish`）。

合入者被信号终止（BR-2099）放在这里，因为它首先是让出轮次；顺带撤回关闭提交的部分按 BR-2018（`work/land/finish`）处理。

## 术语

- **land.start**：合入开始时记的事件，带合入者的进程；它之后没有结果事件、进程又不在，这次合入就是被杀掉的（BR-2307、BR-2308）。
- **队列条目**：一次合入的排队记录，记下合入者的进程（pid 和启动时间）和心跳。
- **心跳**：合入者定期更新的时间；等待时每次查轮次写一次，拿到轮次后定时写，停止更新的合入者会被跳过。
- **掉线时间**：`lander_stale_minutes`，心跳超过它没更新的合入者被标成放弃。
- **保留位置（resolving）**：因冲突被拒、等待时超时或被信号终止的条目在 `land_keep_place_minutes` 内等它自己的合入者重新合入，期间不挡任何人（BR-2177、BR-2368）。
- **优先级**：修复 main 的变更最先，其次是负责人用 `canon backlog urgent` 标的变更（记在协调数据库里，下一次轮次生效，合入后自动结束），再其次是待办清单 `优先合入` 一节里的变更，其余最后（BR-2232、BR-2363、D-34、D-73）。
