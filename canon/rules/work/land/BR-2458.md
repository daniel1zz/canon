## 规则

从已认领杂务（轻变更，BR-2457）的工作树运行 `canon chore land`，使用业务变更相同的队列、检查、floor 配置时机、main 比较并交换和后台结果；合入者不是 worker 时不因修改代码、规则、决策或配置路径而拒绝，worker 的杂务按 BR-2501 第 1 项检查；也不因杂务身份跳过原检查。

排队之前，合入做一个关闭提交 `canon: close <杂务身份>`（提交说明的正文是 `<C-n> <标题>`），里面只新建这个轻变更的变更文件 `canon/changes/<C-n>-<标题的 slug>.md`（D-148、D-150），main 上不另有开工提交。变更文件的 front matter 是 `id`、`title`（`canon chore start` 记下的标题；记录不在时用分支 slug，并输出一行 `<杂务身份>: full title unavailable; the change file takes the branch slug as its title`）、`status: done`、`rules: []` 和 `chore: <杂务身份>`，正文为空。C 编号在第一次做关闭提交时分配，同一份杂务之后再合入沿用这个编号；工作树里已经有 `chore` 写着这个身份的变更文件时不再新建。这个关闭提交和变更的关闭提交一样：合入没到 main 就撤回（BR-2018），引用复核记录和新增决策的接受并进它（BR-2440、BR-2355）。轻变更不计算执行证据，不写 `passes`。`chore` 只能是杂务身份（`chore-<UUID>`），写成别的值时这个变更文件不读入，`canon check` 报 `file-invalid`；它是 canon 自己的字段，项目声明的文档类型不能在 `fields` 里用它。

合入成功释放本会话的认领和 handoff，输出 `<杂务身份> completed as <C-n>`。没有杂务认领以退出码 2 拒绝，不匿名排队。失败、超时、后台跟随和中断沿用共享合入要求。

通用 work 命令按 D-100 的身份处理杂务的交接、状态、测试、预评审、接手、解锁、后台结果、清理及归档；brief 显示杂务身份与 handoff，不要求读取不存在的文档。杂务改动文档仍进入合入后评审。执行证据继续按业务 Change 的规则检查，不因杂务身份绕过。

## 例子

- 杂务提交代码后合入 → main 包含修改，最上面的提交是 `canon: close <杂务身份>`，它只新建 `canon/changes/C-<n>-<slug>.md`（`status: done`、`chore: <杂务身份>`、标题是开工时的标题），main 上没有 `canon: open` 提交，认领和 handoff 被释放，输出含 `completed as C-<n>`
- 合入被拒后修好再合入 → 变更文件用第一次分配的同一个 C 编号
- 合入被拒后 `canon work drop <杂务身份>` 放弃 → main 上没有它的变更文件，`canon change list` 不列它
- 开工后协调数据库里的标题记录被清掉 → 照常合入，变更文件的标题是分支 slug，输出含 `full title unavailable`
- 变更文件写 `chore: abc` → `canon check` 报 `file-invalid`，信息含 `chore`
- floor 失败 → 退出码 1，main 不动，关闭提交撤回、工作树里没有变更文件，工作与认领保留
- 杂务改有效的 active 规则 → 不因路径拒绝，仍接受检查与合入后评审
- worker 在 BR-2498 生效之前开始的杂务改了一条规则 → 退出码 1，按 BR-2501 第 1 项点名那条规则；只改代码 → 照常合入
- 杂务伪造其他 Change 的 passes → 原执行证据检查拒绝，main 不动
- 杂务改 active 规则的行为并合入 → 轻变更的变更文件不写 `passes`，不计算也不新增执行证据，这条规则已有的通过记录保持原样
- 杂务和业务变更同时排队，两种身份分别领头 → 每个成员仍执行自己的检查、关联自己的身份，不互相覆盖
- 在业务变更或未认领的工作树运行 chore land → 退出码 2，无杂务排队
- 杂务停下并交接 → 下一会话 brief 显示下一步，不输出 canon show 杂务身份
- `canon work status` → 按 BR-2192 列出未完成的杂务
- 未完成的杂务（工作树干净、没有自己的提交）遇到 `canon work clean` → 保留，理由是杂务还没完成合入
- `canon work drop <杂务身份>` 碰到未合入的提交或未提交文件 → 先归档到 refs/canon/archive 再删除
- 子 agent 的杂务连续被拒 → 按 BR-2454 停下，主会话按 BR-2455 放行
