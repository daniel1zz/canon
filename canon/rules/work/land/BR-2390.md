id: BR-2390
title: canon work land 在独立的后台合入进程里合入，前台跟随输出并用它的退出码退出
status: active
---

## 规则

`canon work land` 不在自己的进程里合入：它启动一个后台合入进程（自己的进程组，不接标准输入），后台合入进程的标准输出和标准错误分别写进协调数据库旁 `logs/` 下这次合入自己的目录（`out`、`err`），结束时把退出码写进同一目录的 `exit`；`canon work land` 把这两路输出按原来的流打印出来，后台合入结束时以它写下的退出码退出，并在目录里记下 `seen`（结果已经被打印到结尾，BR-2392）。后台合入进程就是 `canon work land` 本身，带环境变量 `CANON_LAND_RUN`，值是 `<前台进程号>:<那个目录>`：只有父进程正是这个前台进程的 `canon work land` 才是后台合入，它照常合入（本领域其余规则说的都是它），`land.start` 记的 `pid` 是它自己，另记 `run`（那个目录）。floor、hook 里再运行的 `canon work land` 也会继承这个变量，但它们的父进程不是那个前台进程，所以照常作为前台启动自己的后台合入，不会把结果写进别人的目录。`--finish`、`--timeout`、`--as` 原样交给后台合入。后台合入进程没写 `exit` 就不在了（例如被 `kill -9`，BR-2099 管不到）→ 前台说明合入进程没有记录结果就结束了、要再运行 `canon work land`（它按 BR-2309 报出并清理），以 75 退出（D-80）。

## 例子

- 合入成功 → 前台打印的输出和后台合入写的一样，退出码 0；`land.start` 的 `pid` 不是前台进程，带 `run`
- worktree 有未提交的改动，后台合入拒绝 → 前台退出码 2，拒绝信息出现在标准错误
- `CANON_LAND_RUN` 是 `41:/x/run`、父进程是 41 → 这个进程是后台合入，目录 `/x/run`；父进程是 42，或值里没有进程号 → 不是后台合入
- 后台合入进程在 floor 里被 `kill -9` → 前台说明它没有记录结果就结束了，退出码 75；再运行 `canon work land` 报出上一次被杀掉（BR-2309）
