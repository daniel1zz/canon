## 规则

`canon work land` 在 rebase 之后记下 HEAD 的提交，floor、`canon check`、措辞判断和 `before_land` 都针对这个提交，合入后的评审（BR-2441）也评审它（`CANON_HEAD` 就是它；`floor_timing` 为 `after` 时没有这一步的 floor，BR-2218）。一起测的那批（BR-2172）里，floor 和移动 main 针对整条链的顶，成为 main 的是它；每个变更自己的 `canon check`、措辞判断和 `before_land` 针对它那一段的顶（BR-2172）；成员的 worktree 在加入后变了怎么办按 BR-2173。移动 main 之前再看一次 worktree：HEAD 不再是这个提交，或者有未提交、未跟踪的改动（包括 floor 自己写出、没有被 git 忽略的文件）→ 不移动 main，拒绝，原因 `moved-during-land`，退出码 1，提示写明 HEAD 从哪个提交移到了哪个提交、多出来的提交和未提交的文件。

## 例子

- floor 跑的时候有人在这个 worktree 里提交了 `sneaky` → 原因 `moved-during-land`，提示里有 `sneaky`，main 不动
- floor 在 worktree 里写出没有被忽略的 `stray.txt` → 原因 `moved-during-land`，提示里有 `uncommitted: ?? stray.txt`
- floor 结束后 HEAD 还是 rebase 后的提交、worktree 干净 → 合入的正是这个提交
