## 规则

`canon work land --finish` 写完引用复核记录之后，在 BR-2440 能改关闭提交的同样情况下，把这个变更新增的、仍是 `proposed` 的决策改成 `accepted`，并把它们 `supersedes` 列出的决策改成 `superseded`（和 `canon decision accept` 一样，BR-2027），这些改动并进关闭提交，输出一行 `accepted <D-n>, … on landing, in <C-n>'s close commit`（有被取代的再写 `; superseded <D-n>, …`）。新增的决策：在分支离开 main 的那个提交里没有、在 rebase 前的分支上有的决策文件。关闭提交撤回时（BR-2018、BR-2309）这些状态随它一起撤回。写文件或改提交失败时合入被拒，原因 `environment`。

之后，相对 main 新增、在被合入的树上仍是 `proposed` 的决策（BR-2440 不能改关闭提交的那些合入，以及杂务）→ 合入照常进行，不拒绝；通过 `canon check` 和 `before_land` 之后，对每个这样的决策各打印一行 `proposed decision: <D-n> <标题> lands still proposed …`，写明用 `canon decision accept <D-n>`；事件表记一条 `land.proposed`，带这些决策的编号。只修改了 main 上已有的 `proposed` 决策、或这次合入没有新增决策 → 不打印，不记事件，也不改它的状态。

依据：决策合进 main 时它的规则已经生效、代码已经在跑（D-109）；留在 `proposed` 只会让评审和 `canon context` 当它不存在。还要等负责人决定的方向不合入，按 `canon human ask` 记成待答问题。

## 例子

- `canon work land --finish`，变更新增 `D-5`，状态 `proposed` → 关闭提交里 `D-5` 是 `accepted`，输出含 `accepted D-5 on landing`，没有 `proposed decision:` 一行，没有 `land.proposed` 事件
- 同上，`D-5` 写着 `supersedes: [D-2]` → `D-5` 是 `accepted`，`D-2` 是 `superseded`，输出含 `superseded D-2`
- 带 `--finish` 的合入没到 main（floor 不过）→ 关闭提交撤回，分支上 `D-5` 仍是 `proposed`
- 不带 `--finish` 的合入新增 `D-5`，状态 `proposed` → 合入成功，输出含 `proposed decision: D-5`，事件表有一条 `land.proposed`，编号是 `D-5`
- 杂务新增 `D-5` 和 `D-6`，都是 `proposed` → 每个决策一行提示，一条事件带两个编号
- 合入新增 `D-5`，状态已是 `accepted` → 不打印，不记事件
- 合入只改了 main 上已有的 `proposed` 决策 `D-3` 的文字 → 不打印，不记事件，`D-3` 仍是 `proposed`
- 合入没有碰 `canon/decisions/` → 不打印，不记事件
