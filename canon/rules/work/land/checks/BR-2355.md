title: 合入新增了仍为 proposed 的决策时，输出提示并记事件，不拒绝

business: 合入的步骤

## 规则

`canon work land` 合入的改动里，相对 main 新增了决策文件（`canon/decisions/` 下 main 上没有的文件）、而且它在被合入的树上 `status` 是 `proposed` 时 → 合入照常进行，不拒绝；通过 `canon check` 和 `before_land` 之后，对每个这样的决策各打印一行：`proposed decision: <D-n> <标题> lands still proposed; accept it with \`canon decision accept <D-n>\` in a change (after its challenge), or say in the change file why it stays proposed`；事件表记一条 `land.proposed`，带这些决策的编号。合入新增的决策已经是 `accepted`、只是修改了 main 上已有的 `proposed` 决策、或这次合入没有碰决策 → 不打印，不记事件。一起测的合入，每个成员各自判断。

依据：子 agent 并行工作时按设计把决策合成 `proposed`，等负责人或之后的变更确认（canon-parallel）；拒绝会挡住这些合入，所以只提示。提示的作用是让“新增的决策还没人接受”在合入时被看见，而不是等到实现时才被发现（#129）。

## 例子

- 合入新增 `D-5`，状态 `proposed` → 合入成功，输出含 `proposed decision: D-5`，事件表有一条 `land.proposed`，编号是 `D-5`
- 合入新增 `D-5` 和 `D-6`，都是 `proposed` → 每个决策一行提示，一条事件带两个编号
- 合入新增 `D-5`，状态已是 `accepted` → 不打印，不记事件
- 合入只改了 main 上已有的 `proposed` 决策 `D-3` 的文字 → 不打印，不记事件
- 合入没有碰 `canon/decisions/` → 不打印，不记事件
