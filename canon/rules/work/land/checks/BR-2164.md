## 规则

`canon work land` rebase 之后，比较 main 和 rebase 后的提交，列出这次合入改动的每个路径（新增、修改、删除，改名算两边）。`canon/config.yaml` 配了 `floor_skip_paths`，而且每个改动的路径都等于其中一项或在其中一项的目录下，同时没有一个改动的路径是测试文件（`tests` 找到的文件），并且项目的 `test_select_command`（BR-2346）收到这些路径后没有选出任何测试文件 → 不跑 floor，打印 `floor: skipped` 和原因（改了几个路径、都在哪几项下），事件表记一条 `floor.skip`（带改动的路径），这次合入的 `land.ok` 或之后的 `land.refuse` 带 `floor_skipped: true`，`canon stats` 不把它算成 floor 的一次运行。`canon check`、来源核对、`before_land` 和比较并交换照常进行，合入后的评审照常排队（BR-2441）。没配 `floor_skip_paths`（默认是空的）、有一个路径不在这些项下、改了测试文件、或者 `test_select_command` 选出了测试文件 → floor 照常运行，选出了的打印 `floor not skipped: test_select_command selects <N> test file(s) for these paths: <文件（理由）>…`；`test_select_command` 以非 0 退出、超时或打印了不是测试文件的路径时，同样不跳过，打印 `floor not skipped: <原因>`。这些情形都不是拒绝：合入继续，floor 照常运行，退出码和事件表不受影响（多跑一次 floor 是安全的一侧；`canon work test` 以退出码 4 失败，是因为它要回答“跑哪些测试”，BR-2346）。配了 `floor_skip_paths` 却没配 `test_select_command` 是配置错误，所有命令以退出码 2 失败（BR-2165）：不然跳过就没有任何依据。

判断用的是 rebase 后那棵树上的 `canon/config.yaml`（即将成为 main 的配置），不是开始合入时读到的配置。

依据：只改这些路径时，代码树和 main 上已经被 floor 测过的那棵完全一样；这些路径由项目自己声明为测试读不到的文件，所以默认不跳过。测试读不读得到由项目的 `test_select_command` 在合入时回答：它认得的写法里有测试读这些路径下的文件，floor 就照常运行（本仓库的脚本见 BR-2350）；认不出的写法仍靠项目自己保证，canon 不读测试源码（D-64）。规则文字和代码列表的核对放在 `canon check` 里（BR-2180），不放在读规则文件的测试里。

## 例子

- `floor_skip_paths: [canon/rules, canon/notes]`，合入只改了 `canon/rules/x/BR-1.md` 和 `canon/notes/N-1.md` → 不跑 floor（floor 命令是 `false` 也照样合入），打印 `floor: skipped`，记一条 `floor.skip`
- 同样的配置，合入还改了 `app.txt` → floor 照常运行
- 同样的配置，合入只改了 `canon/rulesx/a.md` → 不在 `canon/rules` 目录下，floor 照常运行
- `floor_skip_paths: [docs]`，`tests: ["docs/**/*.test.ts"]`，合入只改了 `docs/a.test.ts` → 是测试文件，floor 照常运行
- 开工时 `floor_skip_paths` 含 `canon/notes`，等待期间 main 上的配置把它去掉，合入只改了 `canon/notes/N-1.md` → floor 照常运行
- 没配 `floor_skip_paths`，合入只改了 `canon/notes/N-1.md` → floor 照常运行
- 同样的配置，`test_select_command` 对 `canon/notes/N-1.md` 选出 `src/a.test.ts`（理由 `reads canon/notes`）→ floor 照常运行，打印 `floor not skipped: test_select_command selects 1 test file(s) for these paths: src/a.test.ts (reads canon/notes)`
- 同样的配置，`test_select_command` 什么都没选出 → 不跑 floor；它以退出码 3 结束 → floor 照常运行，打印 `floor not skipped: test_select_command exited 3`
- 配了 `floor_skip_paths`，没配 `test_select_command` → 所有命令退出码 2
- 跳过 floor 后 `canon check` 有问题 → 照样拒绝，原因 `check`，事件带 `floor_skipped: true`
