title: floor 命令写出带 file 的 JUnit 报告时，按测试文件记进协调数据库
status: active
---

## 规则

`floor` 命令含 `{report}` 时，canon 运行它前把 `{report}` 换成一个临时路径（加单引号转义），命令结束后不论 floor 通过与否都读那里的 JUnit 报告（读法见 BR-2338）。每个 `testcase` 必须有 `file`（相对 floor 运行目录，或该目录下的绝对路径）；匹配 `tests` 的文件，各按这棵树里它的 git blob 哈希、这个文件下的全部 `testcase` 记一行（和 BR-2337 同一张表，来源是 `floor`）；不匹配 `tests` 的文件不记，日志里写一行说明。floor 通过却没写出报告、报告读不了、有 `testcase` 没有 `file` 或 `file` 在仓库之外时，这次 floor 以失败结束，日志里写明原因，缺 `file` 的写明“改用 `canon work test --all` 逐个文件记账”，整份报告都不记；floor 本身已经失败时保持它的退出码，报告的问题只写进日志。`floor_timing: after` 的后台 floor 同样记账。

## 例子

- floor 是 `sh f.sh {report}`，`f.sh` 写出两个带 `file="src/a.test.ts"`、`file="src/b.test.ts"` 的 testcase，`tests` 匹配它们 → 合入通过，表里两行，来源是 `floor`，哈希是合入的树里这两个文件的哈希
- 报告里还有一个 `file="scripts/x.ts"` 的 testcase，`tests` 不匹配它 → 不记它，日志有一行说明
- floor 通过但没写报告 → 合入被拒（`floor exited 1`），日志写“the floor wrote no report”
- 报告里的 testcase 没有 `file`（gdUnit4、gotestsum 的情形）→ 合入被拒，日志写 `no file attribute` 和 `canon work test --all`，表里没有任何行
- `file="/etc/passwd"` → 被拒，日志写 outside the repository
- floor 以退出码 3 结束又没写报告 → 退出码仍是 3，不报第二个错误
- floor 不含 `{report}` → 照常，不记账
