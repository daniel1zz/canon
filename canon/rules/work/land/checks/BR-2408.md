## 规则

需要做 BR-2407 的扫描时，canon 先找被合入树的 `node_modules/.bin/varlock`，没有就找 PATH 上的 `varlock`。都找不到时合入失败，原因 `environment`，退出码 4（BR-2022），信息写明缺 varlock 以及安装办法（`npm i -D varlock`）。找到后先运行 `varlock load --agent`：它以非 0 退出（例如没有 sops 的 age 私钥，取不到值，varlock 报 `Configuration is currently invalid`）时同样以 `environment` 失败、退出码 4，信息里带 varlock 的错误输出（stderr），不带它的 stdout。这一步不能省：取不到值时 `varlock scan` 会说没有可扫的敏感值并以 0 退出，等于悄悄放行。`varlock scan` 以 0 和 1 以外的码退出，或以 1 退出却没有一条能认出的发现（路径是本次扫描的文件之一的 `路径:行:列 变量名` 行）时，也以 `environment` 失败，退出码 4，且不输出它的原始输出。这些失败都不跑措辞判断、不排合入后的评审，main 不动。

## 例子

- 树里有 `.env.schema`，`node_modules/.bin` 里和 PATH 上都没有 varlock → 退出码 4，原因 `environment`，信息里有 `varlock` 和 `npm i -D varlock`
- 树的 `node_modules/.bin/varlock` 和 PATH 上的 varlock 都在 → 运行的是树里的那个
- 树里没有 `node_modules/.bin/varlock`，PATH 上有 → 运行 PATH 上的那个
- `varlock load --agent` 以 1 退出，stderr 写着 `Configuration is currently invalid` → 退出码 4，信息里有这句话，评审命令没有运行，也没有排合入后的评审
- `varlock scan` 以 1 退出，输出里没有能认出的发现行 → 退出码 4，原因 `environment`，信息里没有它的原始输出
- 树里没有 `.env.schema`，也没有 varlock → 照常合入
