status: planned

will_amend: [BR-2458]

## 规则

合入者是 worker（`agent:<会话>:<名字>`，BR-2023）时，`canon work land` 在重新基于 main 之后、移动 main 之前，按下面几项检查（D-128），有一项不过就拒绝合入，退出码 1，main 不动，提示写明哪一项、哪些文件、规则或请求，并写明“交回设计负责人：canon work need-design（BR-2499），或由设计负责人 canon work take（BR-2500）”：

1. **改了设计**：候选（合入的 base 到候选提交）新增、修改、删除或改名了设计文档（`work/delegation` 的术语表），例外只有激活：契约清单里 main 上是规划中的规则，只把 `status: planned` 改成 `active`、删掉 `will_amend`，其他文字一个字都不变。变更文件 `## 为什么`、`## 要改什么` 两段和派发记下的任务哈希比（BR-2497），不和 base 比：主会话派发前在分支上写好的这两段，worker 原样带着合入不算改。规则文字要随实现改（包括 `will_amend` 的目标），交回设计负责人。
2. **派发后设计变了**：契约清单里每一项在这次合入要接上去的那个提交上的内容哈希，和派发时记下的不一样。单独合入时这个提交是当前 main；批量合入时是 main 加上批里排在它前面的成员。清单在派发时固定，候选改了 `rules:` 也不影响它。设计负责人重新派发（BR-2497）之后才放行。
3. **还有没回答的设计请求**：这个变更上有 `pending` 的设计请求（BR-2499），不管是哪个 worker 提的。
4. **代次作废**：合入者不是派发的接受者，或这次合入的代次不是派发现在的代次（重新派发、`take` 之后，BR-2497、BR-2500）。这次合入的代次在 `canon work land` 排队时从认领读一次记在队列项上，之后不再变：排队后 worker 接受了新设计，这次合入仍按排队时的代次算。在移动 main 之前，和重新派发、`take` 在同一个协调数据库事务里再查一次：排队期间作废的也拒绝。

worker 在 BR-2498 生效之前开始的杂务，合入时只查第 1 项；生效时 BR-2458 的“不因修改代码、规则、决策或配置路径而拒绝”改成：不是 worker 的合入者不因此拒绝，worker 的杂务按本条第 1 项。

设计文档的范围和 `design_paths` 从 main（合入的 base）读，不从候选读：候选改了它们也不影响这次检查。

批量合入里每个成员按它自己的合入者和派发检查，不按领头的成员。worker 合入成功时，`land.ok` 事件记下合入者、派发的代次、设计负责人、设计版本和契约清单，是这次合入当时的派发的快照。

不是 worker 的合入者不做这些检查。

## 例子

- `agent:s7:w1` 合入 `C-9`，候选改了 `canon/decisions/D-40.md` → 退出码 1，点名 `D-40` 和交回的两个办法
- 同上，候选只把 `BR-50` 的 `status: planned` 改成 `active` → 放行
- 同上，候选把 `BR-50` 改成 `active` 并改了一句例子 → 退出码 1，点名 `BR-50`
- 同上，候选激活 `BR-50`，它的 `will_amend: [BR-30]`，候选改了 `BR-30` → 退出码 1，点名 `BR-30`
- 主会话在 `change/C-9` 上写好 `C-9.md` 的两段后派发，`w1` 原样带着合入 → 第 1 项放行；`w1` 改了 `## 要改什么` → 退出码 1
- 派发之后 `agent:s1` 在 main 上改了 `BR-50`、`BR-30` 或 `design_paths` 里的 `docs/DESIGN.md` → `w1` 合入退出码 1，写明哪一项变了；`agent:s1` 重新派发后再合入 → 放行
- 候选从 `rules:` 里删掉 `BR-50`，而 main 上 `BR-50` 在派发后改过 → 仍然退出码 1（清单按派发时固定）
- `C-9` 上有 `pending` 的 `#3`（不管是谁提的）→ 退出码 1，点名 `#3`
- 候选在 `canon/config.yaml` 里把 `design_paths` 删掉，同时改了 `docs/DESIGN.md` → 退出码 1，点名两个文件（范围按 main 读）
- `w1` 的合入在排队（代次 1），`agent:s1` 重新派发（代次 2），`w1` 接着 `accept-design` → 排队的那次合入轮到时仍退出码 1，写明代次已作废；`w1` 再运行 `canon work land` → 按代次 2 检查
- 一个批量合入里先是主会话改 `BR-50` 的变更，后是按旧 `BR-50` 派发的 `w1` 的 `C-9` → `C-9` 被退回，写明 `BR-50` 变了，前一个成员照常合入
- 主会话 `agent:s1` 领头一个批量合入，成员里有 `agent:s7:w1` 的 `C-9` 改了 `D-40` → `C-9` 被退回，其他成员照常
- 主会话 `agent:s1` 合入同样的候选 → 不做这些检查
