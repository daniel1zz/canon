## 规则

floor 命令在 worktree rebase 到 main 之后、这个变更自己的全部步骤都通过之后运行（这些步骤依次是配置键核对、`canon check`、执行记录、来源核对、措辞判断（BR-2239）和 `before_land`，BR-2248、BR-2016、BR-2111、BR-2057；规则评审和重复评审在合入之后运行，不是合入的步骤，BR-2441；一起测时每个成员的这些步骤也在整批的 floor 之前，BR-2172）：任何一步拒绝时不运行 floor，拒绝原因不变，`canon stats` 不把这次合入算作一次 floor 运行（BR-2067）。以前先跑 floor 的单独合入，现在靠 `canon work test` 写下的测试报告记账通过 `canon check`，不再靠这次 floor 当场写出报告：这次合入碰过的测试文件没有当前内容的报告时以 `test-report-missing` 被拒（BR-2344），信息提示先运行 `canon work test`，不运行 floor。floor 的例外：只改了 `floor_skip_paths` 下文件的合入不跑 floor，代码树就是 main 上已经测过的那棵，见 BR-2164；`floor_timing` 为 `after` 时合入不跑 floor，改在 main 上后台测试，见 BR-2218；只改了 `floor_scopes` 某一项范围内文件的合入跑那一项的命令代替 floor，同样在即将成为 main 的树上、同样在自己的步骤之后，见 BR-2398）；退出码非 0 时拒绝合入（退出码 1），main 不动，完整输出保存在日志里，拒绝信息写明日志路径。

## 例子

- 被合入的树有 `.env.schema`，不论 varlock 是否存在或能否运行 → 合入不调用 varlock，不因 schema 或密钥扫描拒绝；其他检查和 floor 照本规则执行（D-88）
- 分支里多了一个让 floor 失败的文件，其余步骤都通过 → 合入被拒绝，退出码 1，原因 `floor`，main 仍是原来的提交，提示里有日志路径
- 措辞判断答 `behaviour` → 原因 `review`，不运行 floor，日志里没有 floor 的输出
- 改了规则、floor 失败 → 原因 `floor`，没有排合入后的评审
- `canon check` 有发现 → 原因 `check`，不运行 floor
- `before_land` 失败 → 原因 `hook`，不运行 floor
- 变更改了测试文件，没有运行过 `canon work test` → 原因 `check`，信息里有 `test-report-missing`，不运行 floor（以前这次 floor 会写出报告，合入通过）
