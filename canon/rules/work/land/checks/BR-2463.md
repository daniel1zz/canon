title: 同一个提交上 canon work test 留下失败时，合入在排队前拒绝
status: active
business: 合入的前提
---

## 规则

`canon work test` 每次运行在 `work.test` 事件里记下开始时 worktree 的提交（`head`）、当时有没有未提交的改动（`clean`）、跑出结果的测试文件（`ranFiles`）和其中失败的（`failedFiles`）；被信号停下时记已经有结果的那些。

`canon work land`（杂务的 `canon chore land` 同样）在 worktree 干净的检查之后、排队之前，看这个 worktree 在当前提交上、`clean` 为真的那些运行，按先后合起来：一个测试文件以它在这个提交上最后一次的结果为准，类型检查也以最后一次有结果的运行为准。还有失败的文件或类型检查不是 0 时拒绝，原因 `check`，不排队，信息列出失败的文件和类型检查的退出码，并给出只重跑这些文件的命令 `canon work test <文件…>`。在别的提交上、或带着未提交改动的运行不算；这个提交上没有运行过也不拦，测试报告的检查（BR-2344）和 floor 照旧。

## 例子

- 提交 `a1` 上 `canon work test` 跑了 `x.test.ts`、`y.test.ts`，`y.test.ts` 失败，然后 `canon work land` → 退出码 1，原因 `check`，信息含 `y.test.ts` 和 `canon work test y.test.ts`，没有排队
- 同上，接着在 `a1` 上只跑 `canon work test y.test.ts` 并通过 → 合入照常排队
- `y.test.ts` 在 `a1` 上失败，修好后提交成 `a2`，没有再跑测试 → 不按这条拦（提交不同）
- 带着未提交的改动跑测试有失败，提交后合入 → 不按这条拦
- `a1` 上类型检查退出 2，之后在 `a1` 上再跑类型检查通过 → 不拦
- `a1` 上从没跑过 `canon work test` → 不按这条拦
