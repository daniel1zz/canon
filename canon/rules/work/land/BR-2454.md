title: 子 agent 的变更连续被拒三次后，第四次合入在入队前就拒绝，交给主 agent
status: active
business: 连续被拒
---

## 规则

执行者是子 agent（`agent:<会话>:<名字>`，BR-2023）时，`canon work land` 在续上认领之后、写 `land.start` 之前，数这个变更自它最近一次 `land.ok` 或 `land.unstall`（BR-2455）以来的 `land.refuse`，不管是谁的合入被拒。只数子 agent 能改、或派活时能避免的拒绝；这些原因不数：`claimed`、`environment`、`main-dirty`、`main-moved`、`moved-during-land`、`lost-turn`、`no-floor`、`no-claim`、`on-main`，以及本条自己的 `stalled`。排队超时不是拒绝，也不数。

- 数到 3 或更多 → 不入队，以原因 `stalled`、退出码 1 拒绝，记一条 `land.refuse`（原因 `stalled`，带 `refusals` 次数）；信息列出这几次拒绝的时间和原因，并写明：停下，把情况报给主 agent；主 agent 处理之后（指点子 agent 怎么改、用 `canon work take` 接手、或 `canon work drop`）运行 `canon work unstall <C-n> --reason "<理由>"` 放行。
- 一次被数的拒绝让次数正好到 3 时，这次拒绝的信息最后多一行同样的话，子 agent 当场就知道要停下。

主会话（`agent:<会话>`）和人运行 `canon work land` 时不数、不拒绝、也不加这一行：做判断的就是他们自己。

## 例子

- 子 agent 的 C-5 依次因 `conflict`、`dirty`、`check` 被拒 → 第三次的信息最后一行写明连续被拒 3 次、停下报给主 agent、`canon work unstall`；第四次 `canon work land` 不入队，原因 `stalled`、退出码 1，列出三次的原因
- 同样三次之间夹着一次 `environment` 和一次排队超时 → 只数 3 次，第四次照样拒绝
- 两次 `conflict` 后合入成功（`land.ok`），之后又被拒一次 → 只算 1 次，照常入队
- 被拒 3 次后主会话运行了 `canon work unstall C-5` → 子 agent 再合入照常入队
- 主会话自己认领的 C-6 被拒 3 次 → 第四次照常入队，信息没有那一行
- `stalled` 的拒绝本身不算：被 `stalled` 拒绝两次后，计数仍是 3
