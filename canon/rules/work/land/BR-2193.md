id: BR-2193
title: 合入中 git 或文件操作本身失败时以 environment 拒绝，退出码 4，不算任何检查的拒绝
status: active
---

## 规则

`canon work land` 在下面这些地方遇到 git 命令或文件写入本身失败（不是某个检查的判定）时，拒绝，原因 `environment`，退出码 4（BR-2022），main 不动；`land.refuse` 事件照常记下原因和 git 的报错（BR-2026）。`environment` 不在 `canon stats` 的检查列表里（BR-2067），所以这些失败不会算成 `check`、`conflict` 或 `main-moved` 的拒绝：

- `--finish` 的关闭提交做不成（改变更文件失败，或 `git commit` 失败，例如项目的 pre-commit hook 拒绝）：变更文件恢复成提交前的样子，worktree 和合入前一样，不进队列。
- 轮到之后读不到 main 的提交，或 rebase 之后读不到 HEAD。
- rebase 失败，但没有任何冲突的文件（例如 worktree 的 `index.lock` 已经存在）：拒绝信息是 git 的报错，不说冲突，也不保留排队位置（BR-2177 只对冲突保留）。
- 移动 main 前读不到 worktree 列表。

rebase 失败并且有冲突的文件时，仍按冲突处理（BR-2015）。

## 例子

- 项目的 pre-commit hook 退出码 1，`canon work land --finish` → 退出码 4，原因 `environment`，分支上没有 `canon: close C-1` 提交，`git status` 干净，`C-1` 仍是 `open`
- 轮到时 worktree 的 `index.lock` 已经存在，rebase 失败 → 退出码 4，原因 `environment`，信息里有 `index.lock`，没有 `keeps its place`
- C-1 和 C-2 改了同一行 → 仍以 `conflict` 拒绝，退出码 1
- 一次 `environment` 拒绝 → `canon stats` 里 `check`、`conflict`、`main-moved` 的拒绝次数都不变
