## 规则

一起测（BR-2172）时，领头自己的步骤（`canon check`、密钥扫描、来源核对、措辞判断、`before_land`，见 BR-2014）先在它自己那一段上跑，不通过就以那一步的原因拒绝领头，成员全部回到队列。之后每个成员按排队顺序加到链上：在链上 rebase 冲突，或者它自己的步骤不通过，它就离开这一批、回到队列原来的位置（之后仍可以被拉进别的批，记一条 `batch.drop`），后面的成员接着加到它前面那个成员之上，别的成员都不受影响；被步骤拒绝的成员不在批里被判失败，轮到它自己或进了下一批时重新检查。

floor 只在链顶跑一次。不通过时按前缀二分：依次对链的某个前缀（领头加前面几个成员）的顶跑 floor，找出最短的不通过前缀，它最上面的那个变更就是“加入后 floor 开始不通过”的变更，约 log₂(批的大小) 次 floor。这个变更以 `floor` 被拒，拒绝信息写明是在谁领头的批里、加入后 floor 不通过，并附 floor 输出的尾部；它前面的前缀已经通过 floor，照常一起合入；它后面的成员回到队列，之后仍可以被拉进别的批。这个变更是领头时，领头以 `floor` 被拒，成员全部回到队列。成员的合入者在读到这个拒绝之前收到信号（SIGTERM、SIGINT）时，同样撤回它的关闭提交（BR-2018），记一条 `land.refuse`，以 143 或 130 退出。记一条 `batch.fail`，带被找出的变更（`culprit`）和这一批一共跑了几次 floor（`floors`）。

移动 main 之前，要合入的每个成员的 worktree 都要和加入时一样（HEAD 是加入时的提交、没有未提交的改动），条目也还在这一批里：第一个不满足的成员和它后面的成员回到队列，剩下的前缀如果还没跑过 floor 就再跑一次，通过后合入。领头自己的 worktree 变了 → 领头以 `moved-during-land` 被拒，成员全部回到队列。临时 worktree 里的 `setup` 失败 → 这一批没法测，成员全部回到队列，记 `batch.fail`，领头接着单独合入自己。领头的合入者在这一批中途停了（条目不再是 `landing`、进程不在，或心跳过期），成员下一次查轮次时就不再等它，回到队列照常等。

## 例子

- A 领头、B 加了一个让 floor 失败的文件 → 整批的 floor 不通过；只含 A 的前缀通过，A 合入；B 以 `floor` 被拒，信息里有 `the floor failed once <B> joined the batch of <A>`；floor 共跑 2 次，记 1 条 `batch.fail`，`floors: 2`
- A、B、C 一起测，B 让 floor 失败 → A 合入，B 以 `floor` 被拒，C 回到队列、之后合入；这一批跑 3 次 floor（整批、A、A+B），C 自己再跑 1 次
- A 自己就让 floor 失败、B 在后面 → A 以 `floor` 被拒，B 回到队列、之后合入；floor 共跑 3 次
- A、B、C 一起测，B 的 `canon check` 不通过 → A 和 C 一起合入，floor 只跑 1 次，C 的 `land.ok` 带 `batched_by`；B 回到队列，轮到它自己时以 `check` 被拒；记 1 条 `batch.drop`，没有 `batch.fail`
- 这批的 floor 运行期间 B 的 worktree 里多了一个提交 → B 回到队列；只含 A 的前缀再跑一次 floor 后 A 合入；B 带着新提交之后合入；floor 共跑 3 次
- A、B、C 一起测，floor 运行期间 C 的合入者被 SIGTERM 终止 → C 的条目记为 `killed`；A、B 再跑一次 floor 后一起合入，没有 `batch.fail`
- `setup` 在临时 worktree 里退出码非 0 → 记 1 条 `batch.fail`，原因写明 `setup exited`；A、B 各自合入，floor 共跑 2 次
- A 领头时被 SIGKILL 杀掉，B 在它的批里 → B 不再等 A，A 被跳过后 B 拿到轮次
- B 已被锁定后 A 被 SIGKILL 杀掉 → B 同样回到队列照常等，不再被锁定；之后 B 被信号终止时自己撤回关闭提交（BR-2018）
- A 移动了 main、还没记下 B 已合入就死了 → B 回到队列再合入一次，rebase 后没有新内容，main 不变
- B 被领头在批里以 `floor` 拒绝，B 的合入者还没读到就收到 SIGTERM → 退出码 143，B 的 worktree 回到加入前的提交，变更仍是 `status: open`
