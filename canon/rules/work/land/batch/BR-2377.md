## 规则

领头选出至少一个成员之后（BR-2172），记一条 `batch.start`，这一批无论怎么结束都记一条 `batch.end`，详情是：

- `leader`：`landed`（领头合入了，成员可能一个也没有合入）、`refused`（领头被拒，`reason` 是被拒的原因，如 `floor`、`check`、`moved-during-land`、`main-dirty`）、`lost-turn`（领头在移动 main 之前不再持有轮次，BR-2190）、`alone`（这一批没法测或没法锁定，成员全部送回，领头接着单独合入；`reason` 是 `setup`、`no-worktree` 或 `lock`；`setup` 和 `lock` 同时记 `batch.fail`，`no-worktree` 不记，BR-2190）、`error`（异常结束，异常本身会报出原因）；
- `landed`：随领头一起合入的成员的队列条目编号；
- `sent_back`：没有合入的成员，每个一项 `{ entry, reason }`，原因和这个成员的 `batch.drop` 一致（BR-2378）；
- `floors`：这一批跑了几次 floor。

`batch.start` 也在临时 worktree 建不了的时候记（那时 `leader` 是 `alone`）。领头的进程在这一批中途被终止时没有机会记 `batch.end`，所以有 `batch.start` 没有 `batch.end` 就是领头在批中途停了。

## 例子

- A 领头，B、C 在批里，B 的 `canon check` 不通过，A 和 C 合入 → 1 条 `batch.end`：`leader: landed`，`landed` 是 C 的条目，`sent_back` 是 B 的条目加 `steps`，`floors: 1`
- A 领头、B 让 floor 失败 → `leader: landed`，`landed` 为空，`sent_back` 是 B 加 `floor`，`floors: 2`
- A 自己让 floor 失败，B 在批里 → `leader: refused`，`reason: floor`，B 以 `leader-refused` 送回
- 批的 `setup` 失败 → `leader: alone`，`reason: setup`，成员以 `batch-failed` 送回，`floors: 0`
- 临时 worktree 建不了 → 有 `batch.start`，`leader: alone`，`reason: no-worktree`
- 领头在移动 main 之前失去轮次 → `leader: lost-turn`，成员以 `leader-lost-turn` 送回
- 主 checkout 有未提交的改动，main 没动 → `leader: refused`，`reason: main-dirty`，成员以 `main-not-moved` 送回
- 成员的合入者在 floor 运行期间被终止 → `leader: landed`，`landed` 里没有它，`sent_back` 里是它加 `lander-gone`
