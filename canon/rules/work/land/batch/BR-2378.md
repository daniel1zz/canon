id: BR-2378
title: 成员没有合入就离开一批时，都记一条 batch.drop，原因取自固定的几种
status: active
---

## 规则

一起测（BR-2172）里的成员不是随这一批合入的，只要它离开这一批，就记一条 `batch.drop`，详情有成员的条目编号 `entry`、领头的条目编号 `leader` 和 `reason`；一个成员在一批里最多记一条。`reason` 只有这几种：

- `steps`：它自己的步骤不通过，`step` 写步骤的拒绝原因（`check`、`review`、`before_land` 等，BR-2173）。
- `rebase`：它在链上 rebase 冲突（BR-2172）。
- `floor`：它加入后 floor 开始不通过，被拒（BR-2173）；它不回到队列，别的原因都回到队列原来的位置。
- `behind`：它自己没问题，只因为链上它前面的变更离开了（floor 找出的变更在它前面，带 `culprit`；前面的成员变了或走了，带 `because`）。
- `changed`：它的 worktree 在加入之后有了新提交或未提交的改动（BR-2106）。
- `lander-gone`：它的条目不再在这一批里，通常是它的合入者被终止。
- `leader-refused`：领头被拒（自己的步骤、floor，或领头自己的 worktree 在批里变了而以 `moved-during-land` 被拒），成员都送回。
- `leader-lost-turn`：领头在移动 main 之前失去轮次（BR-2190）。
- `batch-failed`：这一批没法测或没法锁定（`setup` 失败、临时 worktree 建不了、锁定时有成员已离开），成员都送回，批的 `batch.fail` 或 `batch.end` 里写明原因。
- `main-not-moved`：领头已经把成员锁定，移动 main 这一步本身没成功（别人在这一批测试期间移动了 main、主 checkout 不干净），成员解锁、回到队列；领头的 worktree 变了不算，那是 `leader-refused`。

一批里中间的前缀合入、成员先被送回再合入的情况照常；每个送回的成员之后仍可以被拉进别的批（BR-2173）。

## 例子

- B 的 `canon check` 不通过 → 1 条 `batch.drop`：`reason: steps`、`step: check`
- B 和 C 在批里，B 让 floor 失败 → B 记 `floor`，C 记 `behind` 且 `culprit` 是 B
- A 领头，B 和 A 改了同一行 → B 记 `rebase`
- 批的 floor 运行期间 B 的 worktree 里多了一个提交 → B 记 `changed`
- 批的 floor 运行期间 C 的合入者被终止 → C 记 `lander-gone`
- 领头自己让 floor 失败 → 每个成员记 `leader-refused`
- 批的 floor 运行期间领头自己的 worktree 里多了一个提交，领头以 `moved-during-land` 被拒 → 每个成员记 `leader-refused`，不记 `main-not-moved`
- 领头自己的 `canon check` 不通过 → 每个成员记 `leader-refused`
- 领头在移动 main 之前失去轮次 → 成员记 `leader-lost-turn`
- `setup` 失败、临时 worktree 建不了 → 每个成员记 `batch-failed`
- 主 checkout 有未提交的改动 → 成员记 `main-not-moved`
