---
id: BR-2392
title: 同一个 worktree 再运行 canon work land 接上还在跑的合入，或报出没人看到结尾的结果
status: active
---

## 规则

`canon work land` 开始一次新的合入之前，先看这个 worktree 是否有另一个 `canon work land` 已经开始、但还没记下 `land.start` 的合入：最近一条 `land.spawn` 之后没有同一个 `run` 的 `land.start`、这次合入还没写退出码，而且合入进程还在（它的进程号写进 `run` 目录之后）或者开始它的那个 `canon work land` 还在（写进之前）→ 不新开合入，在标准错误说明它还在启动，等它的进程号写下后跟随它，规则同 BR-2390、BR-2391；开始它的 `canon work land` 在启动合入前就没了的，不算在启动。判断有没有合入在启动和记下 `land.spawn` 在同一个写事务里完成，所以同时运行的两个 `canon work land` 只有一个开始合入。然后看这个 worktree 最近一条 `land.start`（BR-2307）：它带 `run`（BR-2390），而且这次合入还没有结果、进程还在（BR-2308 的 `running`）→ 不新开合入，在标准错误说明它还在跑（开始时间、进程号），从头打印它的输出并跟随，规则同 BR-2390、BR-2391；它带 `run`、已经写下退出码，但没有 `seen`（结果没有被任何前台打印到结尾，例如前台在它结束前脱离了）→ 不新开合入，说明它在没人跟随时结束了，打印它的全部输出，以它的退出码退出并记下 `seen`。其余情况（没有 `land.start`、不带 `run`、已有 `seen`、进程不在却没写退出码）照常开始新的合入；进程不在又没写退出码的，由新的合入按 BR-2309 报出并清理。`--finish`、`--timeout` 只对新开的合入起作用（D-80）。

## 例子

- 前台在 floor 里脱离后，合入还在跑时再运行 `canon work land` → 说明还在跑，打印从头开始的输出；合入成功后退出码 0；事件表只有一条 `land.start`
- 前台脱离后合入被 `canon check` 拒绝，再运行 `canon work land` → 打印那次的拒绝，退出码 1，不新开合入；接着再运行一次 → 新开一次合入（第二条 `land.start`）
- 同一个 worktree 同时运行两个 `canon work land` → 只有一条 `land.spawn`、一条 `land.start`；两个都跟随这次合入，都以它的退出码退出，其中一个说明它在跟随而不是另开
- 合入进程已经起来、还没记下 `land.start` 时前台脱离（退出码 75），马上再运行 `canon work land` → 跟随那次合入，不新开；事件表只有一条 `land.start`
- 上一次合入的前台一直跟到结尾 → 再运行就是新的合入
- 上一次合入被 `kill -9`，没写退出码 → 新开合入，按 BR-2309 报出上一次被杀掉
