## 规则

`canon work land --stop` 向这个 worktree 正在运行的合入（最近一条 `land.start` 没有结果、进程还在，BR-2308）的进程发 SIGTERM，合入按 BR-2099 让出轮次、撤回关闭提交并记 `land.killed`；它等这个进程结束（合入先按 BR-2099 停下它启动的命令和它们的子进程），带 `run` 时打印它的输出（并记下 `seen`）。合入在 `land.killed` 里记下 SIGKILL 之后还剩进程的进程组、而且现在组里还有进程 → `--stop` 不说已经停止，自己以 4 退出（后台合入进程本身仍按 BR-2099 以 143 或 130 退出），信息写明这些进程组和停下它们的命令 `kill -KILL -<进程组>`；否则说明已经停止、以 0 退出。两种情况下，worktree 里有和 HEAD 不同的已跟踪文件时都再输出一行，列出这些文件（最多 10 个，多的写出还有几个），提示提交前先用 `git diff` 看过：停下的命令可能把改到一半的文件留在那里，`git commit -a` 会把它们当成真的改动提交（#262）。这个 worktree 没有正在运行的合入 → 退出码 3，信息写明没有在跑的合入；进程发不了信号（例如属于别的用户）→ 退出码 4。`--stop` 只能和 `--as` 一起用，带 `--finish` 或 `--timeout` → 退出码 2，什么都不做（D-80）。

## 例子

- 合入在跑 floor 时 `canon work land --stop` → 退出码 0；排队条目失败、结果 `killed`；事件表有 `land.killed`；后台合入进程已经不在
- 合入在跑 `before_land`，它的命令启动的子进程把 `app.txt` 改了、收到 SIGTERM 也不改回去 → 子进程在 `--stop` 退出前已经不在；退出码 0，输出里有一行列出 `app.txt`
- 同上，子进程收到 SIGTERM 时把 `app.txt` 改回去 → 退出码 0，不列文件
- 合入记下的 `left_running` 里有进程组，`--stop` 时组里还有进程 → 退出码 4，信息写明进程组和 `kill -KILL -<进程组>`；组里已经没有进程 → 退出码 0
- 没有在跑的合入时 `canon work land --stop` → 退出码 3
- `canon work land --stop --finish` → 退出码 2，不发信号
- 记下的合入进程属于别的用户（例如 pid 1），发信号被拒绝 → 退出码 4，信息写明发不了信号
