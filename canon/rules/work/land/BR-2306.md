title: 合入时 main 没通过的话，合入成功和被拒的输出里也写出这件事和谁在修
status: active
---

## 规则

协调数据库里有“main 没通过”的记录（BR-2220）时，`canon work land` 不管合入成功还是被拒，在输出末尾写两行，和 `canon brief` 里那一段的第一行和最后一行相同：`main is failing floor since ...`，以及“已在 `<变更>` 里修”，或者“还没有人在修”并提示 `canon work start --fix-main`。成功时写到标准输出，被拒时写到标准错误，退出码不变。没有记录时什么都不加。这样已经在干活、不再运行 `canon brief` 的会话，合入时也知道 main 是红的，以及自己变更之外的失败不是自己造成的。

## 例子

- main 没通过、还没有修复变更，合入成功 → 输出里有 `main is failing floor since` 和 `nobody is fixing it yet`，提示 `canon work start --fix-main`，退出码 0
- main 没通过、修复变更是 C-9，合入成功 → 输出里有 `being fixed in C-9`
- main 没通过，合入被拒（比如 worktree 有未提交的改动）→ 标准错误里除了拒绝原因，还有同样两行，退出码不变
- main 通过了、没有记录 → 输出里没有 `main is failing`
