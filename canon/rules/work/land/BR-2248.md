---
id: BR-2248
title: 同一次合入里新增并使用配置键或检查名时拒绝合入
status: active
---

## 规则

main 的 base 提交里有 canon 声明配置键的文件（任何目录下名为 `config-keys.ts` 的文件，里面每个键写成一行 `key: "<键名>",`）时，`canon work land` 在 rebase 之后、`canon check` 之前（`floor_timing` 为 `before` 时在 floor 之后，为 `after` 时在 BR-2224 那一步之后），比较被合入的树里 `canon/config.yaml` 顶层用到的键：其中有键在被合入的树里声明了、而 main 的 base 提交里没有声明，合入以原因 `config-key` 被拒（退出码 1），main 不动；信息列出这些键，并提示先合入只新增键、不使用它的变更，等各会话装的 canon 重新构建之后，在第二次合入里再写进 `canon/config.yaml`。理由：读到未知键的 canon 所有命令都以退出码 2 失败（BR-2045），其他会话装的旧 canon 在新 main 上会一直失败到重新构建。两种 `floor_timing` 下都做这一步。一起测（BR-2172）时每个成员都和 main 的 base 比较，不和批里排在它前面的成员比较，因为整批一起让 main 前移。main 的 base 提交里没有任何 `config-keys.ts` 声明（用 canon 的普通项目，不是 canon 自己的仓库）时不比较配置键。

检查名在同一步同样比较：main 的 base 提交里有 canon 声明检查名的文件（任何目录下名为 `checks.ts` 的文件，里面用双引号写的每个名字，例如 `"on-main"`）时，比较被合入的树里 `canon/config.yaml` 的 `check_reviews` 用到的检查名：其中有名字在被合入的树里声明了、而 main 的 base 提交里没有声明，合入同样以原因 `config-key` 被拒（退出码 1），main 不动；信息列出这些检查名，并提示先合入只新增检查的变更，在第二次合入里再把它的复审日期写进 `check_reviews`。理由：读到不认识的检查名的 canon 同样所有命令都以退出码 2 失败（BR-2069、BR-2045）。两种 `floor_timing` 和一起测时的比较对象都和配置键一样。main 的 base 提交里没有任何 `checks.ts` 时不比较检查名，配置键照常比较。两棵树都没声明的检查名（拼错）不在这一步报，由 BR-2069 的配置错误处理。

## 例子

- main 声明了 `floor` 和 `setup`，变更在 `src/work/verify/config-keys.ts` 里新增 `key: "typecheck_command",`，并在 `canon/config.yaml` 里写 `typecheck_command: "bunx tsc --noEmit"` → 退出码 1，原因 `config-key`，信息里有 `typecheck_command` 和“先合入”的提示，main 不动，`land.refuse` 带 `reason: "config-key"`
- 同一变更只新增键，`canon/config.yaml` 不写它 → 照常合入
- main 已经声明了 `typecheck_command`，变更只在 `canon/config.yaml` 里写上它 → 这一步不拒绝
- `floor_timing: before` 下新增并使用 `typecheck_command` → 同样以 `config-key` 被拒
- 一起测的批里，排在前面的成员新增 `typecheck_command`，后面的成员在 `canon/config.yaml` 里用上它 → 后面的成员在批里被拒，整批不合入，成员回去各自单独合入（BR-2173）
- main 的 base 提交里没有任何 `config-keys.ts`（普通项目）→ 不比较配置键
- main 的 `src/work/stats/checks.ts` 声明了 `"floor"` 和 `"check"`，变更在里面新增 `"passes"`，并在 `check_reviews` 里写 `passes: "2027-02-04"` → 退出码 1，原因 `config-key`，信息里有 `passes` 和“先合入检查”的提示，main 不动
- 同一变更只新增 `"passes"`，`check_reviews` 不写它 → 照常合入；之后另一个变更只在 `check_reviews` 里写上 `passes` → 这一步不拒绝
- main 的 base 提交里没有任何 `checks.ts`，变更新增一个 `checks.ts` 并在 `check_reviews` 里写上其中的名字 → 不比较检查名
