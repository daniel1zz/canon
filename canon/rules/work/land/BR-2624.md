## 规则

合入（BR-2463 的检查之后、排队之前）对这次合入新增的每个文档（main 上没有、这个分支加了的文件），按 main 上的类型声明（BR-2619、BR-2623）找出它缺的新建时表态字段；有缺的就拒绝，原因 `fields`，退出码 1，不排队，信息对每个缺的字段写一行 `canon doc set <编号> <字段> <值>` 和允许的格式（D-159）。轮到这次合入、变基到 main 之后，再按那时 main 上的声明查一次，缺的照样拒绝，原因 `fields`：排队期间别的合入可能给 main 加了新字段（#297）。这样复制文件、手写文件、`canon rule apply` 写出的新文档，以及声明在分支开始之后才加的字段，都在合入前补上。已经在 main 上的文档不检查缺字段（旧文档不追溯）。杂务合入写出的变更文件不检查。决策的 `revised_because` 按 BR-2623 的条件检查。本检查上线时已经在做、只在分支上的文档也照此检查，不设过渡：第一次合入被拒一次，照信息补上（负责人 2026-11-21 的选择）。

## 例子

- 分支上复制出 `C-9.md`，没有 `owner_gate` → 拒绝，原因 `fields`，信息有 `canon doc set C-9 owner_gate <值>`
- 用 `canon work start --title` 建的变更，表态字段都在 → 照常
- main 上的旧变更被这次合入改了、没有 `owner_gate` → 不拒绝
- main 在分支开始后给变更加了 `due: create` 的新字段 → 这个分支新增的变更缺它 → 拒绝，补上后照常
- 排队前 main 还没有 `risk`，排队期间别的合入给变更加了 `due: create` 的 `risk` → 轮到时变基后拒绝，原因 `fields`，信息有 `canon doc set C-9 risk <值>`
- 本检查上线前开工、变更文件只在分支上、没有 `owner_gate` 和 `advances` → 拒绝一次，信息有两行 `canon doc set`；补上后照常
- 分支新增的决策 `amends: [D-3]`，`D-3` 存在，没有 `revised_because` → 拒绝；`amends: "none: 新的选择"` → 不要求
