title: 因变更自身内容被拒后，内容和 main 都没变时再合入，入队前就以同样的原因拒绝
status: active

## 规则

合入因变更自身的内容被拒绝时（原因是 `check`、`source`、`release` 或 `review`：在同样的内容和同样的 main 上再跑一遍，结果相同），`land.refuse` 事件记下这次的内容树（变更分支去掉关闭提交后的树）和 rebase 到的 main 提交。之后 `canon work land` 在入队之前（在检查 worktree 干净之后、做关闭提交之前）查这个变更最近的一个合入事件（`land.ok`、`land.refuse`、`land.killed`、`land.lost`、`land.interrupt`）：它是这样一个拒绝，并且现在的内容树和 main 的提交都和它记下的相同，就不入队，立即以同样的原因拒绝（退出码和原来的相同，`check`、`review` 等都是 1），信息写明和哪个时间、哪个事件的拒绝相同、什么都没变、要改内容或等 main 前移，后面附上原来的拒绝信息；同样记一条 `land.refuse`，原因不变，多一个 `repeat_of`（原来那个事件的编号）。内容或 main 有任何变化、最近的合入事件不是这样的拒绝、或者拒绝的原因是冲突、floor、超时、有未提交的改动、main 前移等，照常入队。

## 例子

- `C-1` 合入因 `canon check` 报 `ref-dangling` 被拒（原因 `check`），什么都不改再 `canon work land` → 不入队，退出码 1，信息含 `nothing changed since`，事件表多一条原因 `check`、带 `repeat_of` 的 `land.refuse`
- 同样被拒之后，改了一个文件并提交 → 照常入队，按新的内容检查
- 同样被拒之后，main 前移了一个提交（内容没改）→ 照常入队
- 合入因 floor 失败被拒（原因 `floor`），什么都不改再合入 → 照常入队
- 被拒之后又合入成功过一次（最近的事件是 `land.ok`）→ 照常入队
- 第二次被立即拒绝之后，再合入一次（仍然什么都没变）→ 仍然立即拒绝，`repeat_of` 仍指向最初那次拒绝
