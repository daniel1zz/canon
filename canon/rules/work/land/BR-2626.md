## 规则

带关卡的变更 `C-n`，负责人答过 `approve C-n: <旧文字>?` 之后 `owner_gate` 改了文字（BR-2616 不再认那个回答）。改动只是措辞、没有让负责人多批准什么时（例如改错别字），主会话不必再问负责人，自己判断后运行 `canon work keep-approval C-n --question <n> --reason "<为什么新文字没有要求负责人没批准的东西>"`：

- 条件都成立时记一条 `owner-gate.keep` 事件（问题编号、旧文字、新文字、理由），退出码 0，输出写明问题 #n 对旧文字的批准现在覆盖新文字，`canon overview` 会列出来。此后按 BR-2616 判断时，没有问新文字的已回答问题，就算批准；
- 沿用只在负责人对旧文字的最近回答仍是批准时有效：之后对旧文字又答了不批准，沿用失效；之后问了新文字并回答，以那个回答为准（问新文字的回答优先）；
- 拒绝的情形，都不记事件：`--reason` 为空 → 退出码 2；执行者是 worker（`agent:<会话>:<子 agent>`）→ 退出码 1，写明只有主会话或人能沿用（#296 防的正是 worker 在批准后改文字）；问题 #n 不是 `approve C-n` 的问题、或变更不存在 → 退出码 3；#n 问的就是现在的文字、#n 没写问的是哪段文字、或负责人对那段旧文字的最近回答不是批准 → 退出码 1；变更没有 `owner_gate` → 退出码 1。

判断交给主会话，不交给 canon：只有主会话知道两段文字是不是同一件事。判断写在事件里，`canon overview` 的 `## 不需负责人批准` 一节（BR-2625）列出最近 7 天的每次沿用，每行 `<C-n> <标题>  沿用旧批准 <时间>：#<n> 批准的「<旧文字>」沿用到「<新文字>」，<理由>`，供负责人抽查。BR-2616 的拒绝信息和 BR-2617 的议程项在旧文字被批准过、执行者不是 worker 时，写出这条命令。

## 例子

- #12 `approve C-9: 设计稿?` 负责人答 `批准`，`owner_gate` 改成 `设计稿（含封面）`，主会话运行 `canon work keep-approval C-9 --question 12 --reason "只补了封面这个原本就在稿里的部分"` → 退出码 0；`land --finish` 照常关闭；`canon overview` 有一行 `C-9 <标题>  沿用旧批准 <时间>：#12 批准的「设计稿」沿用到「设计稿（含封面）」，只补了…`
- worker 运行同一条命令 → 退出码 1，不记事件，`land --finish` 仍被拒
- 沿用之后，#15 `approve C-9: 设计稿?` 答 `不批准` → 沿用失效，`land --finish` 被拒
- 沿用之后，#16 `approve C-9: 设计稿（含封面）?` 答 `不批准` → 以 #16 为准，被拒
- #12 答的是 `不批准` → keep-approval 退出码 1
- `--question 12` 而 #12 问的就是现在的文字 → 退出码 1，写明没什么可沿用
- `--reason ""` → 退出码 2
