title: 放弃一个会丢工作的变更时先问人，不删除任何东西
status: active
---

## 规则

`canon work drop <C-n>` 会丢东西时（分支上有不在 main 上的提交、worktree 有未提交的改动或不能重新生成的被 git 忽略的文件（BR-2019），或者别的操作者持有有效的认领），不删除任何东西：用 `canon human ask` 记一个问题，逐条列出会丢掉的提交（短哈希和标题）、未提交的文件、不能重新生成的被忽略文件和认领，选项是 yes 和 no；写一条 `drop.escalate` 事件；退出码 1。同样的情况下再执行，问题还没回答时不重复提问，写一条原因为 `waiting` 的 `drop.refuse` 事件，退出码 1。

## 例子

- `C-1` 的分支上有一个没合入的提交 `a1b2c3d wip` → 不删除，问题里列出 `commit not on main: a1b2c3d wip`，退出码 1
- `C-1` 的 worktree 里有未提交的 `notes.txt` → 问题里列出 `uncommitted: ?? notes.txt`，退出码 1
- `C-1` 的 worktree 里有被忽略的 `.env` → 问题里列出 `ignored: .env`，退出码 1
- 问题还没回答时再次 `canon work drop C-1` → 退出码 1，问题仍只有一个
