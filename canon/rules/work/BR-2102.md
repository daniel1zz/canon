title: 放弃会丢工作的变更时先存档并读回校验，再删除
status: active
---

## 规则

`canon work drop <C-n>` 会丢东西时（分支上有不在 main 上的提交，或者 worktree 有未提交的改动、未跟踪的文件、不能重新生成的被忽略文件（BR-2019）），先存档再删除，不问人（D-13）：把 worktree 当前的全部文件（不含能重新生成的被忽略文件）存成一个以分支最新提交为第一个父提交的提交（没有未提交的东西时就是分支最新提交本身），新建 `refs/canon/archive/<C-n>/<时间>` 指向它；读回校验这个 ref 指向这个提交、包含这棵文件树和分支最新提交、每个未提交和被忽略的文件都在里面、存档后工作区没再变化；全部通过后才删除 worktree、分支、认领和 handoff，退出码 0。`drop.done` 事件记下存档 ref 和丢掉的内容；输出列出丢掉的内容和恢复的命令。worktree 自己的索引和文件在删除前不被改动。

## 例子

- `C-1` 的分支上有一个没合入的提交 `wip`，worktree 干净 → 存档 ref 指向分支的最新提交，删除，退出码 0；`git branch <分支> <提交>` 能恢复
- `C-1` 的 worktree 里有改过的 `app.txt`、未跟踪的 `notes.txt` 和被忽略的 `.env` → 存档提交里有这三个文件的当前内容，`git restore --source=<ref>` 能恢复它们
- `C-1` 的 worktree 里还有被忽略的 `node_modules/` → 不进存档
- 全部合入、没有任何会丢的东西 → 不存档，直接删除（BR-2064）
