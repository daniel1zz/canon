title: 只有认领的持有者能在它的 worktree 里续期、停下、放开或合入

## 规则

在一个被认领的 worktree 里运行 `canon work land`、`canon work stop`（带或不带 `--release`）时，执行者不是认领的持有者、而这个认领仍然有效（租约没到期，且记下的会话进程还在，BR-2100）→ 拒绝，退出码 5，提示写明持有者（持有者是本会话的子 agent 而来的是主会话时，还写明不是那个子 agent 就不要进入这个 worktree，子 agent 已经结束就运行 `canon work take <C-n> --from <agent_id>`，BR-2336）；认领、交接记录和 main 都不变，事件表记一条 `claim.refuse`（算进 `canon stats` 的 `claim` 检查，不算合入检查）。认领已经失效时，这个执行者接手认领（记 `claim.take`），命令照常执行。持有者自己运行时照常续期。边界：持有者是比较执行者得出的（BR-2023）。子 agent 带 `--as <自己的 agent_id>` 认领，持有者是 `agent:<会话>:<agent_id>`，主会话（不带名字）和别的子 agent 都不是它，进它的 worktree 运行 `land`、`stop` 被拒（C-337 的情形，D-62）；认领没带名字（没装 hook 又忘了 `--as`）时持有者是 `agent:<会话>`，同一会话的任何 agent 在那里都算持有者，canon 拦不住，只能事后在 `canon work status`、`canon events` 里看到执行者没有名字；子 agent 认领时带了名字而之后忘了，运行 `land` 被拒。不经 canon 的 `git add`、`git commit` 和改文件不在这条规则里，canon 拦不住（D-62）。

## 例子

- agent:a 认领 `C-1`，agent:b 进入 `C-1` 的 worktree 运行 `canon work stop --release --next x` → 退出码 5，认领仍归 agent:a，没有新的交接记录
- 同样情形下 agent:b 运行 `canon work land --finish` → 退出码 5，main 不动，变更没有被关闭
- agent:a 的租约已经过期，agent:b 在那里运行 `canon work stop --next x` → 成功，认领归 agent:b
- agent:a 自己运行 `canon work stop --release --next x` → 成功，认领被放开
- 子 agent 带 `--as abc` 认领 `C-1`（持有者 `agent:s:abc`），主会话（`agent:s`）进入那个 worktree 运行 `canon work land --finish` → 退出码 5，main 不动，变更没有被关闭，提示里有 `canon work take C-1 --from abc`，记一条 `claim.refuse`
- 同样情形下主会话在同一个调用里先 `cd` 进那个 worktree 再 `canon work stop --next x` → 退出码 5，认领不变
- 同样情形下另一个子 agent（`--as def`，`agent:s:def`）运行 `canon work stop --next x` → 退出码 5
- 同样情形下子 agent 自己带 `--as abc` 运行 `canon work stop --next x` → 成功，租约续期
- 持有者是会话一级的 `agent:s`（认领时没带名字），同一个会话的另一个 agent（也是 `agent:s`）进入那个 worktree 运行 `canon work stop --next x` → 成功，认领仍归 `agent:s`（没有名字的认领没有保护）
- 持有者是 `agent:s`，子 agent 带 `--as abc` 运行 `canon work land` → 退出码 5
