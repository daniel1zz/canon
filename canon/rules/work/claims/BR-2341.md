## 规则

`canon work check-as --hook`（BR-2340）读不了 hook 输入，或者命令里有它读不了的写法时，放行这次调用，并向协调数据库的事件表记一条 `hook.skip`：`detail.reason` 是 `bad-input`（stdin 不是合法 JSON、没有 `tool_input.command`）、`unparsable`，或 `process-table`（要认 worker 时进程表读不出来，BR-2468），`detail.sub` 是命令里 `canon work` 之后的第一个词（没有时不写），不记整条命令。`unparsable` 指：一段的命令词是 `sh`、`bash`、`zsh`、`eval`、`xargs`、`source`、`timeout` 等包装命令，而这一段（含 heredoc 正文）里有 `canon work`；或 `$(…)`、反引号、变量里有 `canon work`；或 `canon work` 之后的子命令是变量拼出来的、带引号的。引号里、heredoc 里、注释里单纯写着 `canon work` 的不算（BR-2340 的不触发例子）。其中同时有写对的认领命令时照样记这一条；有拒绝时只拒绝，不记。事件的执行者在 Claude Code 会话里是会话一级，子 agent 的调用在能带名字时是 `agent:<会话>:<agent_id>`。事件写不进去（协调数据库打不开、不在 git 仓库里）时，放行并输出 `{"systemMessage": ...}`，写明是哪一种 `reason`，没有事件。hook 进程自己失败或 `canon` 不在 PATH 上时，hook 命令里的 `|| echo` 输出 systemMessage，这次调用照样放行，也没有事件（BR-2343）。`canon stats --since` 的摘要给出 `hook.skip` 的次数（BR-2155）。

## 例子

- 子 agent 运行 `sh -c "canon work land"` → 放行，一条 `hook.skip`（`reason: unparsable`，`sub: land`），执行者 `agent:<会话>:<agent_id>`
- `echo C-1 | xargs canon work land`、`eval "canon work stop"`、`x=$(canon work land)` → 放行，各一条 `hook.skip`
- `sh -c "canon work stop"` 之外还有写对的 `canon work land --as a1` → 放行，一条 `hook.skip`
- `echo "canon work land"`、`git commit -m "canon work land"` → 放行，没有 `hook.skip`
- 子 agent 的 `bash run.sh`（命令里没有 `canon work`）→ 放行，没有事件：hook 看不到脚本里面
- stdin 是 `not json` → 放行，一条 `hook.skip`（`reason: bad-input`）
- 不在 git 仓库里的 `cwd` 下遇到 `sh -c "canon work land"` → 放行，输出 `{"systemMessage": ...}` 含 `unparsable`，没有事件
- `sh -c "canon work land"` 同一条命令里还有 `canon work land --as b2`（子 agent `a1`）→ 拒绝，没有 `hook.skip`
