## 规则

`canon work land` 在环境里 `CLAUDECODE=1`、而 worktree 里的 `.claude/settings.json` 没有 canon 管的 `canon work check-as --hook` 条目（BR-2343，`canon update --check` 用同一个判断）时，在输出里加一行：`this project's .claude/settings.json has no canon check-as hook: --as is not checked for subagents; run canon update`。这一行不改退出码，不拒绝合入，合入被拒时也照样输出。没有 `CLAUDECODE=1`，或已装 hook 时没有这一行；`.claude/settings.json` 读不了时也没有这一行（`canon update --check` 会报）。canon 只读项目的 `.claude/settings.json`：用户在用户级 settings 或 `settings.local.json` 里自己装了同样的 hook 时也会提示，hook 在 settings 里但没生效（例如项目没被信任）时检测不到。

## 例子

- 没有 `check-as` 条目的项目，`CLAUDECODE=1` 下 `canon work land` → 输出有这一行
- 同样情形下 `canon work land` 被拒（比如不在变更的 worktree 里）→ 仍有这一行，退出码是原来的
- 已装 hook（`canon update` 之后）→ 没有这一行
- 没有 `CLAUDECODE` 的普通终端 → 没有这一行
