## 规则

`canon work check-as --hook` 是 Claude Code 在每次 Bash 调用前运行的 hook，从 stdin 读 hook 输入（`tool_input.command`、`cwd`，子 agent 的调用还有 `agent_id`）。它只认处于命令位置的 `canon work start`、`land`、`stop`、`drop`、`take`、`unstall`：命令按没有被引号包住的 `&&`、`||`、`;`、`|`、`&`、换行和括号拆成段；引号里的内容、heredoc 正文、`#` 注释不拆也不算；每段开头的 `VAR=值` 赋值、`env`、`command`、`time`、`sudo`、`exec`、`nohup`、`nice`、`!`、`{`、`then`、`do` 之类前缀去掉之后，第一个词是 `canon`（或以 `/canon` 结尾的路径）、第二个词是 `work` 或 `chore`、第三个词是这六个之一，才算一次认领命令（`canon chore start`、`canon chore land` 因此同样被检查）；`--as` 只在这一段里找，加了引号的 `--as` 不算。`test`、`status`、`after-land`、`clean` 等别的子命令不检查。检查结果：

- 有 `agent_id`（子 agent）的调用，`start`、`land`、`stop`、`drop` 没有 `--as <agent_id>`（`--as=<agent_id>` 也行），或有一个 `--as` 的值不等于 `agent_id` → 拒绝，`permissionDecisionReason` 里写 `Re-run the same command with --as <agent_id> appended`，带真实的 `agent_id`；
- 有 `agent_id` 的调用里的 `take`，带不带 `--as` 都拒绝，reason 写 `canon work take is for the main session only`；`unstall` 同样，reason 写 `canon work unstall is for the main session only`（BR-2455）；
- 没有 `agent_id`、也不是 worker（BR-2468）的调用是主会话，带 `--as` → 拒绝，reason 写 `--as is only for subagents`；主会话不带 `--as` 的 `take`、`unstall` 放行；
- 同一条命令里有认领命令、又在命令位置写了 `CANON_ACTOR=值`（前缀赋值或 `export`）→ 不管谁调用都拒绝，reason 写 `do not set CANON_ACTOR`；
- 一条命令里有几段认领命令，每一段都要符合，有一段不符就拒绝；
- 其余命令一律放行，不输出东西。

拒绝时 hook 输出 `hookSpecificOutput`（`permissionDecision: "deny"`）并以 0 退出；它不改写命令，不输出 `updatedInput`，也不输出 `allow`，所以用户已有的 `Bash(canon work *)` 之类的放行规则照常匹配带 `--as` 的命令（实测见 C-364）。不含 `canon` 这个字符串的命令不读任何文件、不打开协调数据库。这个 hook 只管身份参数，不检查 agent 怎么干活（D-1）；`sh -c`、`eval` 等它读不了的写法见 BR-2341。

Codex 的 hook 带 --runtime codex，输入字段和拒绝输出沿用同一协议。原生 hook 的 agent_id 就是子线程的 CODEX_THREAD_ID。输入有 agent_id 时按它检查；缺少时取 BR-2023 在当前进程环境及本仓库启动记录中确定的子线程，没有子线程标识则按主会话检查。检查及拒绝条件沿用上面的约定。

## 例子

会触发（子 agent `a1`，没有 `--as` 或写错 → 拒绝；写对 → 放行）：

- `canon work land --finish` → 拒绝，reason 里有 `--as a1`
- `canon chore land` → 拒绝；`canon chore start "工具" --as a1` → 放行；主会话 `canon chore land --as a1` → 拒绝，reason 里有 `--as is only for subagents`
- `canon work land --as a1 --finish`、`canon work land --as=a1` → 放行
- `canon work land --as b2` → 拒绝，reason 里写 `Got --as 'b2'`
- `cd /x && canon work land --as abc`（主会话）→ 拒绝，reason 里有 `--as is only for subagents`
- `cd /x; canon work stop --release --next y`（子 agent）→ 拒绝
- `canon work test | tail -5; canon work land`（子 agent）→ 拒绝（第二段）
- 多行命令，第二行单独是 `canon work take C-5 --from a1`（子 agent）→ 拒绝；主会话 → 放行
- `canon work unstall C-5 --reason x`（子 agent，带不带 `--as`）→ 拒绝，reason 有 `canon work unstall is for the main session only`；主会话 → 放行
- `CANON_ACTOR=agent:x:y canon work land`（任何调用者）→ 拒绝
- `/usr/local/bin/canon work land`、`time canon work land`、`(cd x && canon work land)`（子 agent，没有 `--as`）→ 拒绝
- `canon work land "--as a1"`（引号里的整个字符串是一个词）、`canon work land --as`（没有值）（子 agent）→ 拒绝
- `git commit -m "a && canon work land" && canon work land --as a1`（子 agent）→ 放行（引号里的 `&&` 不拆，只有第二段是认领命令，且写对）

不触发（子 agent，没有 `--as`）→ 放行，不输出：

- `git commit -m "fix: canon work land refused"`、`echo "canon work land"`、`grep "canon work land" notes.md`
- `git commit -F- <<EOF` 的正文里写着 `canon work land`
- `# canon work land` 注释
- `cat canon/decisions/D-62.md | grep 'canon work take'`
- `canon work status`、`canon work test`
- 命令里没有 `canon` → 放行，也不会打开协调数据库
- 主会话 `canon work land` → 放行

- Codex agent_id=child-1，命令 canon work land → 拒绝；带 --as child-1 → 无输出，放行。
- Codex 输入无 agent_id，环境及启动记录确定当前为 child-1 → 仍要求 --as child-1；没有任何子线程标识 → 主会话不带 --as 放行，带 --as 拒绝。
