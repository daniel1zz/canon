## 规则

在 Claude Code 里（`CLAUDECODE=1`）认领变更时，认领记下这个会话的 Claude Code 进程（环境变量 `CLAUDE_PID`，只在 `CLAUDECODE=1` 时读取，而且只有它确实是当前进程的祖先时才采用；记 pid 和进程启动时间，启动时间一律按 UTC 读取，所以时区设置不同的会话读到的是同一个值；改用 UTC 之前记下的、按本地时区写的启动时间，和按本地时区读到的值相同时也算同一个进程）；同一个执行者之后的工作命令把它更新为当时的进程；当时读不到会话进程（不在可识别的宿主里，或没有可用的宿主祖先进程）时保留原来记下的进程。另一个执行者接手失效的认领时，记下的是它自己当时的会话进程，读不到就不记。另一个执行者认领这个变更时，如果记下的进程已经不在（没有这个 pid，或 pid 被启动时间不同的进程占用），即使租约（BR-2011）还没到期也可以立刻接手。认领没有记下进程（不在可识别的宿主里，或没有可用的宿主祖先进程），或者读不到进程表时，只按租约判断。

宿主选择和同时继承两端环境的优先次序按 BR-2023。Codex 会话认领时采用当前进程祖先链里最近的、可执行文件名为 codex 的进程，记 pid 和 UTC 启动时间，不把临时 shell 或 canon 命令本身当作会话。读不到这样的祖先时只按租约判断，不猜进程；同一 Codex app-server 的多个线程共用进程，单个线程结束不能被这个进程探测证明，仍由释放认领或租约处理。后续续期与接手仍按上述进程记录约定。

## 例子

- agent:a 在会话进程 P 下认领 `C-1`，随后关掉了这个 Claude Code（P 退出），租约还剩 11 小时 → agent:b 认领 `C-1` 成功
- P 还在运行 → agent:b 认领被拒绝，退出码 5
- P 还在运行，agent:b 的 shell 设了 `TZ=UTC` 而 agent:a 的没有 → 读到的启动时间相同，agent:b 仍被拒绝
- 升级前记下的启动时间是本地时间 `Tue Nov  3 11:49:43 2026`，P 还在运行（UTC 读到 03:49:43）→ 仍算同一个进程，agent:b 被拒绝
- 升级前记下的本地时间和现在按 UTC、按本地时区读到的都不同（pid 被别的进程占用）→ 进程已经不在，可以接手；按本地时区重读时读不到进程表 → 只按租约判断
- 人在普通终端里认领 `C-1`（没有 `CLAUDE_PID`）→ 只按租约判断
- 环境里的 `CLAUDE_PID` 指向一个不是当前进程祖先的进程 → 不记进程，只按租约判断
- 同一个 Claude Code 会话的两个子 agent 共用进程 P → 这个探测分不开它们，P 在就算在
- 环境里有 `CLAUDE_PID`、但没有 `CLAUDECODE=1` → 不读 `CLAUDE_PID`，不记进程
- agent:a 在会话进程 P 下认领 `C-1`，之后在普通终端里以 agent:a 执行 `canon work stop` → 认领仍记着 P
- agent:a 的租约过期后，agent:b 在普通终端里接手 → 认领不记进程，只按租约判断

- Codex 祖先进程 P 下认领后 P 退出 → 另一 Codex 会话能立即接手，无须等租约
- 只有一个普通 shell 祖先、没有 codex 祖先 → 不把 shell 记成会话进程，按租约判断

- Codex 环境同时继承 CLAUDECODE=1 和 CLAUDE_PID → 按 BR-2023 选 Codex，再按本规则找 codex 祖先进程，不采用 Claude 进程。
