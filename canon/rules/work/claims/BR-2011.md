id: BR-2011
title: "一个变更同一时间只由一个 worktree 和一个执行者持有"
status: active
---
## 规则

认领把一个变更绑定到一个 worktree 和认领它的执行者（`CANON_ACTOR`，Claude Code 里是会话 id，见 BR-2023）。租约默认 12 小时（配置 `claim_lease_hours`），这个 worktree 里的 `canon work land` 和不带 `--release` 的 `canon work stop` 都会把它从当时起重新计算（租约有效时 `canon work start` 总是被拒绝，不会续期）（只有持有者能续期，BR-2104）。租约有效期内，任何人再认领同一个变更都会被拒绝（退出码 5），同一个执行者也一样，提示里写明持有者；是同一个执行者时，提示还写明这个变更正在那个 worktree 里进行、不是在这个对话里开始的就换一个变更（由开始它的 agent 在原处继续），不提示进入那个 worktree。原因：Claude Code 里一个会话的所有子 agent 共用同一个会话 id 和同一个进程，执行者分不开它们（D-11），分开它们的是各自的 worktree（D-18），所以只能让一个有效的认领挡住所有人，也不能把同一个执行者引进别人的 worktree；租约过期后可以接手，持有者的会话进程已经不在时也可以提前接手（BR-2100）。

## 例子

- `C-1` 由 agent:a 在 worktree A 认领 1 小时前，agent:b 在 worktree B 认领 `C-1` → 拒绝，退出码 5，提示持有者
- `C-1` 由 agent:a 认领 1 小时前，agent:b 运行 `canon work start C-1`（得到的是同一个 worktree 路径）→ 拒绝，退出码 5，认领仍归 agent:a
- agent:a 自己再次运行 `canon work start C-1` → 拒绝，退出码 5，提示里有 `it is in progress in that worktree: if you did not start it in this conversation, pick another change`，没有 `cd`，认领不变
- agent:a 用 `canon work stop --release` 放开 `C-1` 后，agent:b 认领 → 成功
- A 的租约 13 小时前到期，B 认领 `C-1` → 成功
- A 13 小时前认领 `C-1`，3 小时前执行过 `canon work stop` → 租约从那次 stop 起重新计算，还剩 9 小时，B 认领被拒绝
- 配置 `claim_lease_hours: 1`，A 两小时前认领后没再执行工作命令 → B 认领成功
