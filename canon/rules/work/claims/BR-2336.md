## 规则

`canon work take <C-n> --from <agent_id>` 只在 Claude Code 会话的主会话里运行（执行者是 `agent:<会话>`，不带 `--as`）：`C-n` 的认领现在由本会话的子 agent `agent:<会话>:<agent_id>` 持有时，持有者改成 `agent:<会话>`，租约从此刻重新计算，记一条 `claim.handover` 事件（`from` 是 `<agent_id>`，`by` 是 `main-session`），输出新的 worktree 路径，退出码 0。认领已过期或持有者进程已不在时也照样接手。以下情形什么都不改：带 `--as` 或 `--from` 的值含字母、数字、`-`、`_` 以外的字符，或不在 Claude Code 会话里运行，或执行者不是 `agent:<会话>` 的形式 → 退出码 2；`C-n` 没有认领、持有者不是本会话的 `agent:<会话>:<agent_id>`（别的会话、别的子 agent、会话一级的持有者）、或它的 worktree 正被 `clean`、`drop` 删除 → 退出码 5，提示写明实际的持有者，事件表记一条 `claim.refuse`（`reason` 是 `handover`）。事件名是 `claim.handover`，不是 `claim.take`：`claim.take` 只指认领失效后的自动接手（BR-2104）。

canon 不能证明子 agent 已经结束（它和主会话是同一个进程，进程探测分不开，D-11）：对还在运行的子 agent 用了 `take`，它之后带 `--as` 运行的 `land`、`stop` 被拒绝（退出码 5，BR-2104），不是无声地继续。没装 hook 的项目里，不带 `--as` 的子 agent 和主会话分不开，canon 拦不住它运行 `take`（D-62）。

## 例子

- 子 agent `abc` 认领了 `C-1`（持有者 `agent:s1:abc`），主会话 `agent:s1` 运行 `canon work take C-1 --from abc` → 退出码 0，持有者变成 `agent:s1`，有一条 `claim.handover`，主会话随后在那个 worktree 里 `canon work land` 成功
- 同上，但认领的租约已过期 → 仍然成功
- 同上，但 `--from xyz` → 退出码 5，持有者仍是 `agent:s1:abc`，提示里写 `agent:s1:abc`，有一条 `claim.refuse`（`handover`）
- `C-1` 的持有者是别的会话的 `agent:s2:abc` → 退出码 5，认领不变
- `C-1` 的持有者是会话一级的 `agent:s1`（子 agent 没带 `--as` 就认领了）→ 退出码 5，提示持有者已经是本会话
- `C-9` 没有认领 → 退出码 5
- `canon work take C-1 --from abc --as abc` → 退出码 2，认领不变，没有事件
- `--from 'a b'` → 退出码 2
- 在普通终端（没有 `CLAUDECODE`）运行 → 退出码 2
- 接手之后子 agent 带 `--as abc` 运行 `canon work land` → 退出码 5，main 不动
