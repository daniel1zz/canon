---
id: BR-2142
title: 合入期间认领记下合入进程，会话退出也不会被别人接手
status: active
---

## 规则

`canon work land` 从进入队列到结束，把本执行者在这个 worktree 里持有、并且记下了会话进程（BR-2100）的认领，改为记下合入进程自己；合入结束时（合入、被拒绝、超时，或被 SIGTERM / SIGINT 打断），如果认领仍记着这个合入进程，就改回原来的会话进程。所以发起合入的 Claude Code 会话在合入途中退出，合入期间别人仍然认领不到这个变更；合入结束后，会话进程已经不在，认领照 BR-2100 立刻可以接手。没有记下进程的认领（只按租约判断）不改。合入还在队列里或正在进行时，同一个执行者在这个 worktree 里的其他工作命令（例如等待期间的 `canon work stop`）只续租约，认领仍记着合入进程。这是 BR-2100 里“同一个执行者之后的工作命令把它更新为当时的进程”在 `canon work land` 期间的例外；“原来的会话进程”指合入开始时按 BR-2100 更新之后认领记着的那个进程。合入进程被 SIGKILL 杀掉时改不回去，认领记着已经不在的合入进程，按 BR-2100 立刻可以接手，和会话已经退出时一样。

## 例子

- agent:a 的认领记着会话进程 P，`canon work land` 在队列里等待时 P 退出 → agent:b `canon work start C-1` 被拒绝，退出码 5；合入照常完成
- 同样情形，合入（不带 --finish）完成后 → 认领又记着 P，P 已不在，agent:b 认领成功
- P 一直在运行，合入完成后 → 认领记着 P，agent:b 仍被拒绝
- 认领没有记下进程（普通终端里认领）→ 合入期间和之后都只按租约判断，认领里仍然没有进程
- 合入进程在等待时被 SIGKILL 杀掉 → 认领记着已经不在的合入进程，agent:b 认领成功
- 合入在队列里等待时，会话在 worktree 里执行 `canon work stop --next …`，然后 P 退出 → 认领仍记着合入进程，agent:b 认领被拒绝
