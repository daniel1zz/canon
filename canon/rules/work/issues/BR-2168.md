status: active

## 规则

`canon issues` 通过 `gh issue list` 读出项目在 GitHub 上所有开着的 issue，按编号从大到小列出：每个一行 `#<编号>  <标题>`，下面一行写明 main 上有没有提交写明修复了它（BR-2169）：有的列出每个这样的提交（短编号和标题），没有的写 `open: no commit on <main> names it as fixed`。最后一行汇总开着的数量和被写明修复的编号；有被写明修复的时，再提示先核对、再用 `gh issue close` 关闭。canon 只读，不关闭、不评论、不改任何 issue。`--json` 输出同样的内容。

## 例子

- 开着 #29 和 #34，main 上有提交 `Take the close commit back ... (C-117, #34)` → #34 下面列出这个提交，#29 下面是 `open: no commit on main names it as fixed`，汇总 `2 open issue(s); 1 named as fixed by a commit on main: #34`
- 没有开着的 issue → 只有汇总 `0 open issue(s); 0 named as fixed by a commit on main`
- 运行前后，gh 只收到 `issue list` 和 `auth status` 这样的只读调用
