## 规则

合入时，在 `canon check` 之后、移动 main 之前核对决策的来源（拒绝原因 `source`）。本次新增的决策文件，`## 方案` 里一条来源都没有时，合入输出一行 `note: ` 开头的提醒，写明这个决策是新的、没有任何来源，照常合入（D-139）。

本次新增或改动的决策里，main 上同一决策还没有的每条来源都要核对：文件路径要在将成为 main 的那棵树里是一个文件，且内容包含摘录；网址打开后（2xx）是网页或文本时，页面去掉标签和脚本后的文字要包含摘录；比较前把连续空白合并成一个空格；网址的摘录和页面文字比较时再去掉所有反引号和空白，因为页面把代码标记渲染成标签，去掉标签后没有反引号、标签的位置变成空格（摘录“`x`, y”在页面上是“x , y”）。文件不成立、网页里没有摘录、或网址回答 404 或 410（来源已经不在了）时拒绝合入。网址打不开（超时、DNS 失败）、回答别的非 2xx（401、403、429、5xx 这类拒绝服务 canon 的）、或内容不是网页或文本（PDF 等）时不拒绝：每条输出一行 `note: <决策>: <原因>; the quote was not verified and the landing goes on (BR-2111)`，并记一条 `source.unverified` 事件（变更、决策、原因），照常合入，因为第三方网站给不给看说明不了文档是否说谎（D-139、D-166）。main 上已有的来源在这一步不重复核对：没被取代的决策里的文件路径来源由 `canon check` 每次核对（BR-2110、BR-2252），被取代的决策的来源和网址来源都不再核对。`canon check` 在这一步之前运行，没被取代的决策里不是文件的路径（BR-2110）和文件里没有摘录的来源（BR-2252）已经由它报出，这时拒绝原因是 `check`，不是 `source`。

## 例子

- 网址来源的摘录是“A hook, `tools/check.py`, refuses it”，页面是 `<p>A hook, <code>tools/check.py</code>, refuses it</p>` → 核对通过
- 新来源是 `https://blocked.example/`，它回答 403 → 输出一行 note，照常合入；回答 404 → 拒绝
- 新来源是一个 PDF 网址 → 输出一行 note（内容不是网页或文本），照常合入
- 新决策 `D-9` 的方案里没有任何来源 → 输出一行 `note: D-9 is new and cites no source …`，照常合入，退出码 0
- 来源 `src/a.ts “function refund(”`，文件里确实有这段 → 通过
- 已接受的新决策，来源 `src/a.ts “function refund(item)”`，文件里没有这段 → 拒绝，原因 `check`（`source-quote-missing`，BR-2252）
- 来源网址返回 404 → 拒绝
- 来源网址能打开，但页面里没有这段摘录 → 拒绝
- 只改了 `D-2` 某个方案的措辞，没有新增来源 → 不核对，也不提醒
- 网络不通，本次没有新增来源 → 照常合入

依据：D-139（没有来源只提醒；已有的来源仍逐条核对，摘录不在或格式不对就拒绝）；D-166（打不开或读不出的网址只提醒）。
