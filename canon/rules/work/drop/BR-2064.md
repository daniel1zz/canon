---
id: BR-2064
title: 放弃一个不会丢工作的变更时直接删除它的 worktree 和分支
status: active
---

## 规则

`canon work drop <C-n>` 放弃一个变更正在进行的工作：删除它在 worktree 目录（BR-2047）下的 worktree、它的变更分支、认领和 handoff，写一条 `drop.done` 事件，退出码 0。不会丢任何东西时直接删除：分支上没有不在 main 上的提交，worktree 没有未提交的改动、也没有不能重新生成的被 git 忽略的文件（按 `regenerable` 判断，见 BR-2019）；会丢东西时先存档（BR-2102）。变更编号不区分大小写（`c-1` 就是 `C-1`）。检查按这个顺序进行，前一项不通过就不再看后面的：既没有 worktree 也没有分支时退出码 3；worktree 签出的是 main 时退出码 2，main 永远不删；在要删除的 worktree 里执行时退出码 2；有人持有有效的认领（租约没到期，且记下的会话进程还在，BR-2100；同一个操作者也算，因为同一个会话的子 agent 共用操作者，D-11），或者另一次 clean 或 drop 正占住它（同一个操作者也算）时，什么都不删，写一条原因为 `claimed` 的 `drop.refuse` 事件，退出码 5；有别的进程把当前目录放在这个 worktree 里时什么都不删，写一条原因为 `in-use` 的 `drop.refuse` 事件，退出码 5，提示写明 pid 和命令名；查不出有哪些进程时什么都不删，写一条原因为 `no-process-list` 的 `drop.refuse` 事件，退出码 4。认领和进程的检查在存档之前，所以这两种情况下不存档。认领检查通过时，drop 在同一个事务里占住这个变更的认领，一直到删除结束（失败时放开，并恢复原来的认领记录）；这期间对它的 `canon work start`、另一次 `canon work drop` 或 `canon work clean` 都被拒（start 和 drop 退出码 5，clean 保留它并写“claimed”），同一个操作者也一样；结束时只放开自己这一次的占位，不删别人此后拿到的认领；占住时记下 drop 自己的进程，drop 被杀掉后占位随进程失效（BR-2100）。删除是全有或全无的：先按读到的最新提交删除分支，再删除 worktree；worktree 删不掉（例如被 `git worktree lock` 锁住）时，把分支按原来的提交建回来，什么都不删，写一条原因为 `remove` 的 `drop.refuse` 事件，退出码 4，提示写明失败的原因，存过档时还写明存档 ref。git 删除 worktree 时先删文件、再删它的登记，文件删不完也照样删掉登记，所以删到一半失败时 worktree 已经不完整、也不再是 git worktree：这时分支同样建回来，`drop.refuse` 记下 `worktree_intact: false`，提示不说 `nothing was deleted`，而是写明 worktree 被删了一部分、存档 ref 和恢复命令。变更文件的状态不改；它在 main 上仍是 open 时，提示用 `canon change drop` 标记。

## 例子

- `C-1` 已经全部合入，worktree 干净 → 直接删除 worktree 和分支，不存档，退出码 0
- 只剩分支 `change/C-2`，上面的提交都已在 main 上 → 删除分支，退出码 0
- `C-3` 已全部合入，worktree 里只有被忽略的 `node_modules/` → 直接删除，不存档，退出码 0
- `C-4` 已全部合入，worktree 里有被忽略的 `.env` → `.env` 算会丢的东西，先存档再删除（BR-2102）
- `agent:b` 持有 `C-1` 的有效认领，`agent:a` 执行 `canon work drop C-1` → 不删除、不存档，退出码 5
- `agent:b` 认领 `C-1` 的租约没到期，但记下的会话进程已经不在 → 不算有效认领，照常放弃（会丢的东西先存档）
- pid 4242 的 `sleep` 当前目录在 `C-1` 的 worktree 里 → 不删除，退出码 5，提示写明 `pid 4242 (sleep)`
- `C-5` 有没合入的提交，同时 pid 4242 在它的 worktree 里 → 不存档、不删除，退出码 5
- `canon work drop C-1` 正在存档时，另一个会话执行 `canon work start C-1` → 退出码 5，drop 照常完成
- `human:x` 在一个终端 clean C-1 的同时，在另一个终端 `canon work drop C-1` → drop 退出码 5
- 列不出进程（`lsof` 执行失败）→ 不删除，退出码 4，`drop.refuse` 原因 `no-process-list`
- 在 `C-1` 自己的 worktree 里执行 `canon work drop C-1` → 退出码 2（调用它的 shell 就在这个 worktree 里，所以这项检查在进程检查之前）
- `canon work drop C-99`，没有对应的 worktree 和分支 → 退出码 3
- `agent:a` 自己持有 `C-1` 的有效认领，`agent:a` 执行 `canon work drop C-1` → 不删除，退出码 5，提示先在那个 worktree 里 `canon work stop --release`
- `canon work drop c-1` → 和 `canon work drop C-1` 一样，输出 `dropped C-1`
- `C-7` 的 worktree 签出的是 `main` → 退出码 2，提示 `refusing to delete main`，什么都不删
- `C-1` 的 worktree 被 `git worktree lock` 锁住，分支上有没合入的提交 → 存档后删除 worktree 失败，分支建回原来的提交，worktree 不变，退出码 4，提示里有存档 ref 和 `nothing was deleted`，`drop.refuse` 原因 `remove`
- `C-1` 已合入但在 main 上仍是 open → 删除后提示 ``mark it with `canon change drop C-1` ``
- `C-1` 的 worktree 里有一个文件删不掉的目录（权限 555），分支上有没合入的提交 → 其余文件被删、登记没了，分支建回原来的提交，退出码 4，提示里有 `partly deleted` 和 `git branch <分支> <提交>`，没有 `nothing was deleted`
