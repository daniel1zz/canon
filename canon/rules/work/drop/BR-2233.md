---
id: BR-2233
title: 变更的分支签出在 worktree 目录以外时，canon work drop 什么都不删
status: active
---

## 规则

`canon work drop <C-n>` 先看所有登记的 worktree：只要有一个不是 worktree 目录（BR-2047）下的 `<C-n>`，却签出了这个变更的分支（`change/<C-n>` 或 `change/<C-n>-<slug>`），比如按旧的目录布局建的，或者用 `git worktree move` 挪走了，就什么都不删（不删分支、不删 worktree、不存档、不动认领），退出码 2，提示写明那个 worktree 的路径、它签出的分支，以及把它挪回去的 `git worktree move` 命令。这是用法上的拒绝，不写 `drop.refuse` 事件（BR-2026）。这项检查在“既没有 worktree 也没有分支”之前，因为分支在那里就不算没有。worktree 在 worktree 目录下的 `<C-n>`，或者只剩分支、没有签出它的 worktree 时，照常放弃（BR-2064）。

## 例子

- `C-1` 的分支 `change/C-1-x` 签出在 worktree 目录以外的 `/old/C-1` → 退出码 2，提示里有 `/old/C-1` 和 `git worktree move`，分支和 `/old/C-1` 都还在，没有 `drop.refuse` 事件
- `C-1` 的 worktree 在 worktree 目录下，已全部合入 → 照常删除，退出码 0
- `C-1` 只剩分支 `change/C-1-x`，没有 worktree 签出它 → 照常删除分支，退出码 0
