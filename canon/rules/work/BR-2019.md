## 规则

`canon work clean` 只删除同时满足以下条件的 worktree：不是当前所在的 worktree、没有被认领、没有未提交改动、所有提交都已在 main 上、没有不能重新生成的被 git 忽略的文件、没有别的进程把当前目录放在它里面；其余的保留，并列出原因（被忽略的文件列出路径，进程列出 pid 和命令名）。被忽略的文件只要路径里有一段匹配 `canon/config.yaml` 的 `regenerable`（文件或目录名，可以用 glob，不含 `/`），就算能重新生成；配置了 `regenerable` 时它取代默认列表，没配置时默认是 `node_modules`、`dist`、`build`、`out`、`coverage`、`.next`、`.nuxt`、`.turbo`、`.cache`、`.parcel-cache`、`target`、`__pycache__`、`.pytest_cache`、`.mypy_cache`、`.venv`、`venv`、`.gradle`、`*.pyc`、`.DS_Store`。查不出有哪些进程时，保留并写明原因。

## 例子

- C-1 已经 `--finish` 合入 → 被删除
- C-2 有一个没合入的提交 → 保留，原因是“1 commit(s) not on main”
- C-3 已合入，worktree 里有被忽略的 `.env` → 保留，原因列出 `.env`
- C-4 已合入，只有被忽略的 `node_modules/` → 被删除
- 配置 `regenerable: ["cache-*"]`：`cache-v1/` 能重新生成，`node_modules/` 不再算能重新生成 → 只有后者所在的 worktree 被保留
- 列不出进程（`lsof` 执行失败）→ 已合入的 worktree 也保留，原因写明列不出进程
- C-5 已合入，pid 4242 的 `zsh` 当前目录在 C-5 里 → 保留，原因是“in use by pid 4242 (zsh)”
