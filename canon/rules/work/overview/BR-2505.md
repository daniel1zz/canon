## 规则

`canon overview`（D-129）在 canon 项目里任何位置运行，按下面的顺序输出五节，每节以 `## <节名>` 开头，退出码 0：

1. `## 当前版本`：当前版本是状态 `active` 的版本中编号数值最小的；没有 `active` 时取状态 `planned` 中编号数值最小的；都没有时这一节只有一行 `(no release in progress)`。有当前版本时，先输出它在 `canon release status` 里的那一行（BR-2328）；当前版本是因为没有 `active` 才取的 `planned` 时，再一行 `(没有 active 的版本，取编号最小的 planned；正在做的版本把 status 改成 active)`；然后一行 `成功标准 <总数> 条：已满足 <a>  未满足 <b>  待负责人 <c>  未证明 <d>`，然后每条成功标准一行，按文档里的顺序：`  [<状态>] <文字>`，已满足的后面加 `  证据：<编号，用逗号分隔>`（状态和文字按 BR-2504）。
2. `## 计划`：和不带编号的 `canon plan status` 输出的行一样（BR-2373）；没有计划时 `(no plans)`。
3. `## 等负责人`：先每个等人回答的问题一行 `问题 #<n> <问题的第一行>`（同 `canon human pending` 的范围），再每个分级为 C 的未处理评审意见一行 `意见 #<n> <点名的编号>: <意见文字的第一行>`，最后当前版本每条待负责人的成功标准一行 `成功标准 <版本编号>: <文字>`；三样都没有时 `(nothing)`。
4. `## 待办顺序`：`canon change list` 列出的未完成变更里排在最前面的 5 个，顺序和标记同 `canon change list`（BR-2149、BR-2291），每个一行 `<C-n> <标题>`，有标记时后面加 `  (<标记>)`；多于 5 个时再一行 `… 还有 <k> 个（canon change list）`；没有时 `(none)`。
5. `## 最近合入`：最近 5 次合入的变更（协调事件里主题是变更编号的 `land.ok`，杂务不算），最新的在前，每个一行 `<C-n> <标题> <合入时间，UTC，到分钟>`；标题取 main 上的变更文件，读不到时只写编号；没有时 `(none)`。

`--json` 输出一个对象，内容相同：`release`（没有当前版本时 `null`，否则含 `id`、`title`、`status`、`counts`（同 `canon release status --json`）和 `criteria`：每条含 `text`、`state`（`met`、`unmet`、`owner`、`unproven`）、`evidence`（编号数组））、`plans`（每项含 `id`、`title`、`total`、`done`、`percent`）、`waiting`（含 `questions`、`findings`、`criteria` 三个数组）、`backlog`（每项含 `id`、`title`、`marks`）、`backlog_more`（没列出的个数）、`landed`（每项含 `id`、`title`、`at`）。

## 例子

- `R-1` shipped、`R-2` planned、`R-3` active → 当前版本 `R-3`
- `R-1` shipped、`R-2` planned、`R-3` planned → 当前版本 `R-2`，它那一行下面有 `(没有 active 的版本，…)` 的提示
- `R-3` active → 没有这行提示
- `R-10` 和 `R-9` 都是 planned、没有 active → 当前版本 `R-9`
- 所有版本都 shipped，或没有版本 → `## 当前版本` 下只有 `(no release in progress)`，其余四节照常输出
- 当前版本 `R-2` 有 3 条成功标准：一条已满足（证据 C-4）、一条待负责人、一条没标记 → `成功标准 3 条：已满足 1  未满足 0  待负责人 1  未证明 1`，三行分别以 `[已满足]`、`[待负责人]`、`[未证明]` 开头，第一行末尾 `证据：C-4`；`## 等负责人` 里有一行 `成功标准 R-2: <那条的文字>`
- 有 1 个等人回答的问题 #7、1 条分级 C 的意见 #3、1 条分级 A 的意见 #4 → `## 等负责人` 有 `问题 #7 …` 和 `意见 #3 …`，没有 #4
- 7 个未完成变更 → `## 待办顺序` 列前 5 个，再一行 `… 还有 2 个（canon change list）`
- 被认领的变更 → 那一行末尾 `  (claimed)`
- 最近合入了 C-8、一个杂务、C-9 → `## 最近合入` 第一行 C-9，第二行 C-8，没有杂务
- `--json`，没有当前版本 → `release` 是 `null`
