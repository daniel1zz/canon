## 规则

`canon overview`（D-129、D-131，按 D-151 第四部分改成只给当前状态）在 canon 项目里任何位置运行，按下面的顺序输出四节，每节以 `## <节名>` 开头，节之间空一行，退出码 0。没有计划一节（D-148）。

1. `## 当前版本`：进行中的版本是状态 `active` 的全部版本，按编号的数值排序；没有 `active` 时取状态 `planned` 中编号数值最小的一个；都没有时这一节第一行是 `(no release in progress)`。每个进行中的版本依次输出：
   - 状态行：`<编号>  <状态>  <标题>`；因为没有 `active` 才取的 `planned` 版本，下面一行 `(没有 active 的版本，取编号最小的 planned；正在做的版本把 status 改成 active)`；
   - 规则计数行：`规则 <总数> 条：规划中 <a>  已通过 <b>  待 main 测试 <c>  待重新执行 <d>`（数法同 `canon release status`，BR-2328）；
   - 成功标准计数行：`成功标准 <总数> 条：已满足 <a>  未满足 <b>  待负责人 <c>  未证明 <d>`，数它自己的、它 `features` 里每个模块（不存在的和 `dropped` 的不算，并进它的版本列的模块算）和并进它的版本自己的成功标准（BR-2521）；
   - 每条成功标准一行，缩进两个空格：`[<状态>] <文档编号>/<S 编号> <文字的第一句>`，先是版本自己的，再按模块的顺序；第一句是文字到第一个 `。`、`！` 或 `？`（含），没有时是整段文字；状态按 BR-2504；
   - 有并进它的版本时（BR-2521、D-133）一行：`并入 <k> 个版本：<编号，逗号分隔>  成功标准 <总数> 条：已满足 <a>  未满足 <b>  待负责人 <c>  未证明 <d>`，这一行只数并入版本自己的标准；它们不逐条列出，但已算进上面的计数行，待负责人的也在议程的等负责人一组里。

   版本之后（没有进行中的版本时在 `(no release in progress)` 之后）一行质量标准，文字按 BR-2558。
2. `## 议程`：议程（BR-2527）的摘要，每组一行，写法同 BR-2529 的议程摘要（不要第一行 `Agenda …`，不缩进）；议程为空时 `(nothing)`。
3. `## 正在做和在等`：主状态（BR-2571）是 `in-queue`、`in-progress`、`delegated`、`handed-off`、`waiting-owner`、`waiting-deps` 的变更，顺序同 `canon change list`，每个一行 `<C-n> <标题>  <状态>`，状态写法同 `canon change list` 的状态标记（BR-2572，例如 `handed-off: partial`、`waiting-owner: #12`），`waiting-deps` 后面写在等的依赖（BR-2564 的写法）。最多 15 个，多的再一行 `… 还有 <k> 个（canon change list）`；没有时 `(none)`。停滞、合入被拒、待关闭的变更在议程里，可派的变更也在议程里，这里不再列。
4. `## 历史`：只给大纲：
   - main 上最近 7 天有改了目标（BR-2510 的那几种改动，按每个提交和它的父提交比较）的提交时，一行 `最近 7 天的目标改动：<文档编号> <处数> 处，…`，按文档编号排，`<文档编号>` 是改动所在的版本或模块；没有时不输出；
   - 最近 3 次合入，每个一行 `<C-n> <标题>  <合入时间，UTC，到分钟>`，最新的在前；合入事件 `land.ok` 的对象是变更编号的直接取；对象是杂务身份、并且 main 上有写着这个 `chore:` 的轻变更文件（BR-2458）的，写那个轻变更的编号和标题；其余杂务不列；标题读不到时只写编号；没有合入时不输出；
   - 最后一行 `细节：canon overview --history`。

`canon overview --history` 只输出细节：`## 最近 7 天的目标改动`（每个提交一行 `<提交号前 9 位> <提交标题>`，下面每处改动一行，缩进两个空格，最新的提交在前；没有时 `(none)`）和 `## 最近合入`（最近 10 次，每个一行 `<C-n> <标题> <时间>`，后面按它在 main 上的 `advances`（BR-2517）加 `  → <引用>`、`  （不推进：<理由>）` 或 `  （没写 advances）`；没有时 `(none)`）。

`--json` 输出一个对象，内容同文字输出：`releases`（每项含 `id`、`title`、`status`、`fallback`、`rules`（各执行状态的条数）、`criteria`（每条含 `doc`、`id`、`text`（全文）、`state`）、`merged`（含 `ids` 和 `criteria`，`criteria` 是各状态的条数））、`quality`（按 BR-2558）、`agenda`（同 `canon work due --json`）、`changes`（每项含 `id`、`title`、`state`、`mark`）、`changes_more`、`goal_changes`（每项含 `doc`、`count`）、`landed`（每项含 `id`、`title`、`at`）。`--history --json` 输出 `goal_commits`（每项含 `sha`、`subject`、`changes`）和 `landed`（每项再含 `advances`：引用数组、`{"none": "<理由>"}` 或 `null`）。

依据：D-151 第四部分（修改 D-129、D-131）；F-2 的成功标准 S4。

## 例子

- `R-1` shipped、`R-2` planned、`R-3` active → 进行中的版本是 `R-3`
- `R-3`、`R-5` 都是 active → 两个都列，`R-3` 在前
- `R-1` shipped、`R-2` planned、`R-3` planned → 列 `R-2`，状态行下面有 `(没有 active 的版本，…)`
- `R-10` 和 `R-9` 都是 planned、没有 active → 列 `R-9`
- 没有版本 → `## 当前版本` 第一行是 `(no release in progress)`，其余三节照常输出
- `R-3` 有 `S1 五个分支各有构筑通关。验收方式见 Q-1。`（未满足）→ 一行 `  [未满足] R-3/S1 五个分支各有构筑通关。`，不含第二句
- `R-3` 的 `features: [F-1]`，`F-1` 有 2 条标准 → 成功标准计数行 `成功标准 3 条：…`，下面先 `R-3/S1`，再 `F-1/S1`、`F-1/S2`
- `R-5` 并入了 `R-2`、`R-3`、`R-4`，都没有标准 → 一行 `并入 3 个版本：R-2, R-3, R-4  成功标准 0 条：…`，不列它们的标题
- 议程里有 2 个停滞的派发和 1 个问题 → `## 议程` 下 `judge: 2: stalled ×2`、`owner: 1: question:7`
- 议程为空 → `## 议程` 下 `(nothing)`
- `C-349` 交接原因 partial、`C-1058` 等 `C-1057` → `## 正在做和在等` 有 `C-349 <标题>  handed-off: partial` 和 `C-1058 <标题>  waiting-deps: C-1057 (open)`
- `C-9` 可派、`C-5` 停滞 → 两者都不在 `## 正在做和在等`
- 18 个在做和在等的变更 → 列 15 个，再一行 `… 还有 3 个（canon change list）`
- 3 天前一个提交给 `R-3` 加了一条成功标准、改了 `F-1` 的两处 → `最近 7 天的目标改动：F-1 2 处，R-3 1 处`
- 改目标的提交在 8 天前 → 没有这一行
- 最近合入了 `C-8`、一个记成轻变更 `C-12` 的杂务、`C-9` → `## 历史` 里依次是 `C-9`、`C-12 <轻变更的标题>`、`C-8`
- 没有计划一节：有计划 `C-5` 时输出里也没有 `## 计划`
- `canon overview --history` → 两节 `## 最近 7 天的目标改动`、`## 最近合入`，最近合入那一节带 `advances`
- 没有 `canon/quality/`、没有进行中的版本 → `## 当前版本` 是 `(no release in progress)` 和 `质量标准：还没有（canon/quality）。…` 两行（BR-2558）
