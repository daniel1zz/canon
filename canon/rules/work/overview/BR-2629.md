## 规则

`canon work remaining` 一次输出 canon 知道的全部未完成事项，回答“还差哪些没做”时不必记得要拼哪几条命令（#298）。每次从 main 和协调数据库现算，不存东西，退出码 0。输出六节，每节标题写明条数，没有时写 `(none)`：

1. `## 没关闭的变更（<n>）`：主状态（BR-2571）不是 `landed`、`dropped` 的变更，main 上的和只在分支上的都算，顺序同 `canon change list`，每行 `<C-n> <标题>  <主状态和细节>`；
2. `## 没通过的规则（全部，不只当前版本）（<n>）`：不分版本，按执行状态（BR-2246）列规划中、待 main 测试、待重新执行的规则，每种一行 `<状态> <个数>：<编号，逗号分隔>`，没有的那种不写；
3. `## 没关的评审意见（<n>）`：每条一行 `#<n> [<分级，没分级写 untriaged>] [<类别>] <文档编号>: <意见，过长截断>`；
4. `## 待回答的问题（<n>）`：没回答、没撤回（BR-2628）的问题，每个一行 `#<n> [<变更或 ->] <问题>`；
5. `## 没有规则或变更引用的已接受决定（<n>）`：`accepted` 的决定，没有任何没退役的规则、也没有任何变更在正文、标题或确认过的引用（`links`）里写到它的编号，每个一行 `<D-n> <标题>`。这一节只看整个决定有没有被引用；被引用过不代表每一条都落实了，逐条的看第 6 节。
6. `## 决定里没写到规则或变更的条目（最近 30 天加入的已接受决定，--all 看全部）（<n>）`：`accepted` 决定的 `## 决定` 一节逐条看（每个列表项连同它的续行算一条，不是列表的按段落算），一条里没写到任何规则编号（`BR-n`）或变更编号（`C-n`）的，列一行 `<D-n>：<那一条的原文，过长截断>`，提示这一条可能还没写成规则、也没开变更（BR-2469 要求决定写到的规则回指它）。默认只看文件在 main 上加入不到 30 天的决定（按 git 里第一次出现在 main 上、不算改名的那次提交时间；还不在 main 上的算新的），`--all` 看全部已接受的决定，标题括号里相应写 `全部已接受的决定`。最多显示 30 行，多出的写一行 `… 还有 <k> 条（canon work remaining --json）`。

最后一行写项目的 issue 不在 canon 里，要用项目自己的 issue 工具查。`--json` 输出 `changes`（`id`、`title`、`state`）、`rules`（`planned`、`waiting`、`rerun` 三个编号数组）、`findings`（`id`、`tier`、`criterion`、`ids`、`text`）、`questions`（`id`、`subject`、`question`）、`decisions`（`id`、`title`）、`items`（`id`、`item`，第 6 节的全部条目）、`allItems`（是否用了 `--all`），不截断。

## 例子

- 打开的 `C-9`、规划中的 `BR-5`、没关的评审意见 #3、待回答的 #12、没人引用的已接受决定 `D-7` → 五节各列一项，标题的条数都是 1
- `D-8` 被变更 `C-9` 的正文写到 → 不列；`D-7` 只被别的决定写到 → 照列
- 已经撤回的问题 #13 → 不列
- 已关闭的变更、已退役的规则、`proposed` 的决定 → 都不列
- `D-7` 的 `## 决定` 有两条：`- BR-5：按这个做` 和 `- 另外要做 Y` → 第 6 节列 `D-7：- 另外要做 Y`，不列写到 `BR-5` 的那条
- 40 天前加入 main 的 `D-3` 有一条没写到规则 → 默认不列；`--all` 列
- 什么都没有 → 每节 `(none)`，退出码 0
