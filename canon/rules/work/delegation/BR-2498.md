---
id: BR-2498
title: 子 agent 和 worker 只能认领派给它的变更，不能新建变更
status: planned
business: worker 的认领范围
---

## 规则

worker（执行者是 `agent:<会话>:<名字>`）运行 `canon work start`：

- 带 `--title`（新建变更）→ 退出码 1，提示新变更由设计负责人建好再派发（BR-2497），没有新文件、没有认领；
- `canon work start <C-n>`，`C-n` 有派给这个名字的派发 → 按平常的认领规则认领（BR-2011），worktree 是派发时保留的那个，输出里写明设计负责人和设计版本；
- `C-n` 没有派发，或派给了别的名字 → 退出码 1，写明派给了谁（没有派发时写“未派发”），认领不变。

按 D-128。不是 worker 的执行者照旧，不受这一条影响。`canon chore start` 不受这一条影响：杂务不是业务改动，它合入时同样受 BR-2501 的设计文档检查。

## 例子

- `C-9` 派给 `w1`，`agent:s7:w1` 运行 `canon work start C-9` → 认领成功，输出里有设计负责人 `agent:s1` 和设计版本
- `C-9` 派给 `w1`，`agent:s7:w2` 运行 `canon work start C-9` → 退出码 1，提示派给了 `w1`
- `C-10` 没有派发，`agent:s7:w1` 运行 `canon work start C-10` → 退出码 1，提示“未派发”
- `agent:s7:w1` 运行 `canon work start --title "x"` → 退出码 1，没有新建 `C-n`
- 主会话 `agent:s1` 运行 `canon work start --title "x"` → 照旧新建并认领
- `agent:s7:w1` 运行 `canon chore start "整理脚本"` → 照旧开始
