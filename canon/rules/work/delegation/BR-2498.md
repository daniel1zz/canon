id: BR-2498
title: worker 只能认领派给它的变更，派发绑定第一个认领的会话，worker 不能新建变更和杂务
status: planned
business: worker 的认领范围
---

## 规则

worker（执行者是 `agent:<会话>:<名字>`）运行：

- `canon work start --title`（新建变更）或 `canon chore start` → 退出码 1，提示新的工作由设计负责人建好再派发（BR-2497），没有新文件、没有认领；
- `canon work start <C-n>`：`C-n` 有派给这个名字的派发，并且派发的接受者是空的或就是这个执行者 → 按平常的认领规则认领（BR-2011），接受者记成这个执行者，认领记下派发的代次，worktree 是派发时保留的那个，输出里写明设计负责人、设计版本和代次；
- `C-n` 没有派发、派给了别的名字，或接受者是另一个执行者（同名的另一个会话）→ 退出码 1，写明派给了谁、接受者是谁（没有派发时写“未派发”），认领不变。

按 D-128。worker 不能开杂务：杂务没有派发和契约清单，worker 在变更里被挡住时把同样的改动放进杂务就绕过了 BR-2501；要做维护的，由设计负责人自己做，或建一个变更派发。不是 worker 的执行者照旧，不受这一条影响。

## 例子

- `C-9` 派给 `w1`，`agent:s7:w1` 运行 `canon work start C-9` → 认领成功，接受者是 `agent:s7:w1`，输出里有设计负责人 `agent:s1`、设计版本和代次 1
- 同上之后，`agent:s7:w1` 停下又运行 `canon work start C-9` → 认领成功
- 同上之后，另一个会话 `agent:s8:w1` 运行 `canon work start C-9` → 退出码 1，提示接受者是 `agent:s7:w1`
- `C-9` 派给 `w1`，`agent:s7:w2` 运行 `canon work start C-9` → 退出码 1，提示派给了 `w1`
- `C-10` 没有派发，`agent:s7:w1` 运行 `canon work start C-10` → 退出码 1，提示“未派发”
- `agent:s7:w1` 运行 `canon work start --title "x"` 或 `canon chore start "整理脚本"` → 退出码 1，没有新的工作
- 主会话 `agent:s1` 运行 `canon work start --title "x"` 或 `canon chore start "x"` → 照旧
