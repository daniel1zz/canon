## 规则

worker（执行者是 `agent:<会话>:<名字>`）运行：

- `canon work start --title`、`canon work start --fix-main`（新建变更）或 `canon chore start` → 退出码 1，提示新的工作由设计负责人建好再派发（BR-2497），没有新文件、没有认领；
- `canon work start <C-n>`：`C-n` 有派给这个名字的派发，并且派发的接受者是空的或就是这个执行者 → 按平常的认领规则认领（BR-2011），接受者记成这个执行者，认领记下派发的代次，worktree 是派发时保留的那个，输出里写明设计负责人、设计版本和代次；
- `canon work accept-design <C-n>`：运行者是派发的接受者、持有认领，派发的代次比它的认领新 → 认领的代次改成派发现在的代次，输出这两个代次之间契约清单里变了哪几项和这期间回答的设计请求，退出码 0；依赖这些设计的工作从这时继续。代次已经一样 → 退出码 0，输出“已是最新”；不是接受者或没持有认领 → 退出码 5；
- `C-n` 没有派发、派给了别的名字，或接受者是另一个执行者（同名的另一个会话）→ 退出码 1，写明派给了谁、接受者是谁（没有派发时写“未派发”），认领不变。例外：主会话自己的子 agent 开始没有派发、没有活着的认领的变更，按 BR-2610 先替它的会话派发再认领。

按 D-128。worker 不能开杂务：杂务没有派发和契约清单，worker 在变更里被挡住时把同样的改动放进杂务就绕过了 BR-2501；要做维护的，由设计负责人自己做，或建一个变更派发。不是 worker 的执行者照旧，不受这一条影响。启动方标为能设计的 worker（BR-2633，D-162）可以开变更和杂务、接回没有派发也没有活着认领的变更：本条第一项和第四项里“没有派发”的拒绝对它不成立；其余照本条。

派发出去的变更上，worker 的 `canon work stop`、`canon work drop` 和认领续期也要求它是接受者、认领的代次是派发现在的代次，否则退出码 5，认领不变（`take` 或重新派发之后，旧 worker 的这些操作都不生效）。

生效时 BR-2012（`--title` 新建变更）、`--fix-main` 和 BR-2457（`canon chore start`）改成只对不是 worker 的执行者和能设计的 worker（BR-2633）成立，其余 worker 按本条拒绝。

## 例子

- `C-9` 派给 `w1`，`agent:s7:w1` 运行 `canon work start C-9` → 认领成功，接受者是 `agent:s7:w1`，输出里有设计负责人 `agent:s1`、设计版本和代次 1
- 同上之后，`agent:s7:w1` 运行 `canon work stop --release` 再运行 `canon work start C-9` → 认领成功
- 同上之后，另一个会话 `agent:s8:w1` 运行 `canon work start C-9` → 退出码 1，提示接受者是 `agent:s7:w1`
- `C-9` 派给 `w1`，`agent:s7:w2` 运行 `canon work start C-9` → 退出码 1，提示派给了 `w1`
- `C-10` 没有派发，`delegate run` 启动的 worker `agent:s7:w1`（环境里有 `CLAUDE_DELEGATE_CHILD=1`）运行 `canon work start C-10` → 退出码 1，提示“未派发”
- `C-10` 没有派发，主会话 `agent:s7` 自己的子 agent `agent:s7:w1` 运行 `canon work start C-10` → 按 BR-2610 派发后认领
- `agent:s7:w1` 运行 `canon work start --title "x"`、`canon work start --fix-main` 或 `canon chore start "整理脚本"` → 退出码 1，没有新的工作
- `agent:s7:w1` 持有 `C-9`（代次 1），`agent:s1` 重新派发（代次 2）；`agent:s7:w1` 运行 `canon work accept-design C-9` → 退出码 0，输出变了的 `BR-50`，认领代次 2
- 同上，`agent:s1` `take` 之后 `agent:s7:w1` 运行 `canon work stop --release` → 退出码 5，认领仍是 `agent:s1` 的
- 主会话 `agent:s1` 运行 `canon work start --title "x"` 或 `canon chore start "x"` → 照旧
- main 的 `design_profiles: [sub-opus]`，环境有 `CANON_WORKER_PROFILE=sub-opus` 的 `agent:s7:w1` 运行 `canon work start --title "x"` → 按 BR-2633 新建并认领
