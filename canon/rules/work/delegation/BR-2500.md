## 规则

`canon work take <C-n> --from <名字>` 由 `C-n` 派发现在的设计负责人运行（D-128）。认领由名字为 `<名字>` 的 worker 持有，并且下面两项都满足时接手：持有者改成设计负责人，租约从此刻重新计算，派发结束，代次加 1，记一条 `claim.handover` 事件（`from` 是 worker 的执行者，`by` 是 `design-owner`），输出 worktree 路径，退出码 0。

- **没有合入在进行**：这个认领没有排队、正在跑或已经在一个批量合入里的合入（BR-2142 记的合入进程还在）。有 → 退出码 5，什么都不改，写明合入的状态；等它结束（成功或失败）再接手。
- **worker 已停**：认领记下的会话进程已经不在 → 接手。进程还在、或 canon 不知道（认领没有记下进程、进程表读不出、worker 是设计负责人本会话的子 agent 而进程分不开，D-11）→ 不带 `--stopped` 时退出码 5，什么都不改，提示先让派发工具或宿主停下它；带 `--stopped` 表示设计负责人确认宿主或派发工具已经停下 worker，这时接手，事件里记 `stopped: asserted`。进程还在而且和设计负责人不是同一个会话时，带 `--stopped` 也退出码 5。

认领已经不在 worker 手上（它用 `canon work stop --release` 放掉了），或者设计负责人自己已经重新持有它，而派发还没结束时，`take --from <名字>` 只结束派发：代次加 1，记 `claim.handover`（`claim` 为 `none` 或 `owner`），认领不变，退出码 0；没有认领时输出提示用 `canon work start <C-n>` 开始。`<名字>` 不是派发的那个 worker → 退出码 5，什么都不改；这个变更有合入在进行时同样按上面“没有合入在进行”那一项退出码 5，等它结束。这样 worker 留下的规则提议（BR-2524）可以由设计负责人收回、应用。

代次作废是持久的：之后旧 worker 的 `land` 按 BR-2501 第 4 项、`stop`、`drop` 和续期按 BR-2498 被拒绝。

派发出去的变更，认领从接受者转到别人手里只有这一条路：认领失效（BR-2100）时，`canon work start`、`land`、`stop` 的自动接手（BR-2100、BR-2104）也按本条处理：运行者是现在的设计负责人、没有合入在进行，并且 worker 已停 → 当作一次 `take`（派发结束，代次加 1，记 `claim.handover`）再继续这个命令；运行者是别人 → 退出码 5，认领不变，提示由设计负责人接手或重新派发。自动接手没有 `--stopped`，worker 已停这样判断：认领记下的会话进程已经不在 → 已停；进程还在（租约过期了也一样）→ 退出码 5，认领不变，提示先让派发工具或宿主停下 worker，再运行 `canon work take <C-n> --from <名字> --stopped`（进程在别的会话里时和上面一样，进程还在就连 `--stopped` 也不行）；认领没有记下进程、或进程表读不出，canon 判断不了 → 租约过期就算已停，因为没有别的信号可用。生效时 BR-2100 和 BR-2104 的自动接手改成：没有派发的变更照旧，派发出去的变更按本条。

生效时 BR-2336 改成：本会话子 agent 的认领也按派发记录接手，没有派发记录的子 agent 认领（BR-2498 生效之前开始的）仍按 BR-2336 原来的同会话条件接手；BR-2336 只保留这一条过渡情形。

不是现在的设计负责人运行 → 退出码 5，认领不变，有一条 `claim.refuse`（`handover`），信息写明那个设计负责人的会话已经结束时先用 `canon work adopt` 接管（BR-2646、D-165）；现在的设计负责人是派发记录上的那个，派发之后只有 BR-2646 能改它；`C-n` 没有派发且不符合 BR-2336 → 退出码 5；`--from` 的值不合法 → 退出码 2。

## 例子

- `C-9` 由 `agent:s1` 派给 `w1`，另一个进程里的 `agent:s7:w1` 持有认领，它的进程已经退出；`agent:s1` 运行 `canon work take C-9 --from w1` → 退出码 0，持有者 `agent:s1`，代次加 1
- 同上，但 `agent:s7:w1` 的进程还在 → 退出码 5，提示先停下它；带 `--stopped` 仍退出码 5
- 认领没有记下进程 → 不带 `--stopped` 退出码 5；带 `--stopped` → 接手，事件有 `stopped: asserted`
- 本会话子 agent `agent:s1:w1` 持有 → 不带 `--stopped` 退出码 5；子 agent 结束后带 `--stopped` → 接手
- 同上，进程已退出，但它运行的 `canon work land` 还在排队 → 退出码 5，写明合入在排队；合入失败结束后再运行 → 退出码 0
- 同上，`agent:s1` 接手之后，旧代次的认领运行 `canon work land` → 被拒绝，main 不动
- `agent:s2` 不是 `C-9` 的设计负责人，运行同样的命令 → 退出码 5，认领不变，有 `claim.refuse`
- `agent:s7:w1` 的进程已退出，`agent:s2`（不是设计负责人）在那个 worktree 里运行 `canon work start C-9`、`canon work land` 或 `canon work stop --release` → 退出码 5，认领不变
- 同上，由设计负责人 `agent:s1` 运行 `canon work land` → 先当作 `take`（代次加 1，有 `claim.handover`），再按主会话的合入继续
- `agent:s7:w1` 的租约已过期，但它的进程还在；`agent:s1` 运行 `canon work start C-9`、`canon work land` 或 `canon work stop --release` → 退出码 5，认领不变，提示停下 worker 后运行 `canon work take C-9 --from w1 --stopped`；进程还在时带 `--stopped` 的 `take` 也退出码 5
- 本会话子 agent `agent:s1:w1` 的租约已过期，它和设计负责人共用的进程还在；`agent:s1` 运行 `canon work start C-9` → 退出码 5，提示用 `--stopped`；子 agent 结束后带 `--stopped` 的 `take` → 接手
- 认领没有记下进程、租约还没过期 → `agent:s1` 运行 `canon work start C-9` 退出码 5；租约过期后 → 当作 `take`
- `--from 'w 1'` → 退出码 2
- `agent:s7:w1` 用 `canon work stop --release` 放掉了 `C-9` 的认领 → `agent:s1` 运行 `canon work take C-9 --from w1` → 退出码 0，派发结束，代次加 1，没有认领，提示 `canon work start C-9`；`--from w2` → 退出码 5
- 同上，`C-9` 的合入还在排队 → `take --from w1` 退出码 5，派发不变；合入失败结束后再运行 → 退出码 0
- 同上，`agent:s1` 已经用 `canon work start C-9` 重新持有认领、派发还在 → `take --from w1` 退出码 0，派发结束，认领仍是 `agent:s1` 的
