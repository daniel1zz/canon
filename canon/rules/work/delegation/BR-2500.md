## 规则

`canon work take <C-n> --from <名字>` 由 `C-n` 派发记录里的设计负责人运行：认领现在由名字为 `<名字>` 的 worker 持有时（不管它是本会话的子 agent，还是另一个进程里的 worker 会话），持有者改成设计负责人，租约从此刻重新计算，派发结束，记一条 `claim.handover` 事件（`from` 是 worker 的执行者，`by` 是 `design-owner`），输出 worktree 路径，退出码 0。认领已过期或 worker 进程已不在时照样接手。

按 D-128。接手之后，原 worker 的 `land`、`stop` 被拒绝（退出码 5，BR-2104）。canon 停不掉另一个进程里还在运行的 worker，它仍可能改这个 worktree 里的文件；设计负责人接手前先让派发工具停下它，接手后用 `git status` 看清楚 worktree 再继续。

生效时 BR-2336 改成：本会话子 agent 的认领也按派发记录接手，没有派发记录的子 agent 认领（BR-2498 之前开始的）仍按 BR-2336 原来的同会话条件接手；BR-2336 只保留这一条过渡情形。

不是设计负责人的执行者运行 → 退出码 5，认领不变，有一条 `claim.refuse`（`handover`）；`C-n` 没有派发且不符合 BR-2336 → 退出码 5；`--from` 的值不合法 → 退出码 2。

## 例子

- `C-9` 由 `agent:s1` 派给 `w1`，另一个进程里的 `agent:s7:w1` 持有认领；`agent:s1` 运行 `canon work take C-9 --from w1` → 退出码 0，持有者 `agent:s1`，派发结束
- 同上，`agent:s7:w1` 之后运行 `canon work land` → 退出码 5，main 不动
- 同上，但由 `agent:s2` 运行 → 退出码 5，认领不变，有 `claim.refuse`
- 同上，但认领已过期 → 仍然成功
- `--from 'w 1'` → 退出码 2
