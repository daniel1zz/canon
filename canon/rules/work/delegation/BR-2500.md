## 规则

`canon work take <C-n> --from <名字>` 由 `C-n` 派发现在的设计负责人运行（D-128）。认领由名字为 `<名字>` 的 worker 持有，并且下面两项都满足时接手：持有者改成设计负责人，租约从此刻重新计算，派发结束，代次加 1，记一条 `claim.handover` 事件（`from` 是 worker 的执行者，`by` 是 `design-owner`），输出 worktree 路径，退出码 0。

- **没有合入在进行**：这个认领没有排队、正在跑或已经在一个批量合入里的合入（BR-2142 记的合入进程还在）。有 → 退出码 5，什么都不改，写明合入的状态；等它结束（成功或失败）再接手。
- **worker 已停**：worker 在另一个进程里（和设计负责人不是同一个会话），而认领记下的会话进程还在 → 退出码 5，什么都不改，提示先让派发工具停下它。认领没有记下进程、或进程已不在时照样接手。worker 是设计负责人本会话的子 agent 时，进程分不开（D-11），照旧接手；子 agent 之后的 `land`、`stop` 被拒绝（退出码 5，BR-2104）。

代次作废是持久的：之后任何带着旧代次的认领（包括 worker 之后按 BR-2100 自动接手、或重新派发前的迟到重试）运行 `land` 被 BR-2501 第 4 项拒绝。

派发出去的变更，认领者的会话进程不在时，也只有现在的设计负责人能接手（用 `take`，或用 `canon work start`）；别的不是 worker 的执行者按 BR-2100 运行 `canon work start` → 退出码 5，认领不变，提示由设计负责人接手或重新派发。生效时 BR-2100 改成：没有派发的变更照旧，派发出去的变更按本条。

生效时 BR-2336 改成：本会话子 agent 的认领也按派发记录接手，没有派发记录的子 agent 认领（BR-2498 生效之前开始的）仍按 BR-2336 原来的同会话条件接手；BR-2336 只保留这一条过渡情形。

不是现在的设计负责人运行 → 退出码 5，认领不变，有一条 `claim.refuse`（`handover`）；`C-n` 没有派发且不符合 BR-2336 → 退出码 5；`--from` 的值不合法 → 退出码 2。

## 例子

- `C-9` 由 `agent:s1` 派给 `w1`，另一个进程里的 `agent:s7:w1` 持有认领，它的进程已经退出；`agent:s1` 运行 `canon work take C-9 --from w1` → 退出码 0，持有者 `agent:s1`，代次加 1
- 同上，但 `agent:s7:w1` 的进程还在 → 退出码 5，提示先停下它
- 同上，进程已退出，但它运行的 `canon work land` 还在排队 → 退出码 5，写明合入在排队；合入失败结束后再运行 → 退出码 0
- 同上，`agent:s1` 接手之后，旧代次的认领运行 `canon work land` → 被拒绝，main 不动
- `agent:s2` 不是 `C-9` 的设计负责人，运行同样的命令 → 退出码 5，认领不变，有 `claim.refuse`
- `agent:s7:w1` 的进程已退出，`agent:s2`（不是设计负责人）运行 `canon work start C-9` → 退出码 5，认领不变
- `--from 'w 1'` → 退出码 2
