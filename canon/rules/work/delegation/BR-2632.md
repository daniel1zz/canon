## 规则

`canon work delegate <C-n> --to <名字> --light "<理由>"` 把这次派发声明为**轻派发**：派发人判断 worker 在这一段只读资料、写设计或调研，不跑测试、构建这类占 CPU 的命令（D-161）。理由是非空文字，空的或只有空白 → 用法错误，退出码 2，不写派发记录。不写 `--light` 的是**重派发**。

派发记录（BR-2497）记下轻重和理由；`delegation.create` 和 `delegation.update` 事件的详情含 `light`（理由，重派发为 `null`）。重新派发时按这次给没给 `--light` 重写，不沿用上一次的。

容量检查（BR-2526）：

- 轻派发新增 worker 时不看负载（BR-2526 第 2 条），内存和名额照查；负载这一条成立时，成功的输出多一行 `light: <负载原因>, not checked for <C-n>: <理由>; canon work test and the other heavy steps still wait for the load (BR-2632)`。
- 重新派发本来不检查容量（BR-2526，停滞的也一样：停滞的派发不占名额，把它重新派出去可能让占用超过 `delegate_max_workers`，这是 BR-2526 延续下来的、有意允许的超额，本条不改）；把生效的轻派发改成重派发时，只加查 BR-2526 第 2 条的负载，内存和名额仍按 BR-2526 对重新派发的规定不查：负载成立就拒绝，信息、退出码和 `delegation.refuse` 事件同 BR-2526 的容量拒绝，派发记录不变。重改轻、轻改轻、重改重都不检查。
- 轻派发的 worker 跑重步骤（`canon work test` 等）时和别人一样等负载（BR-2630）：轻重只影响派发。

`canon work status` 的派发行（BR-2497）对轻派发加 `light: <理由>`。

合入 `--finish` 关闭的变更，生效的派发是轻派发，而分支改了 `floor_skip_paths` 以外的路径（测试覆盖的代码）时，输出一行 `note: <C-n> was delegated light (<理由>) but changes <n> path(s) outside floor_skip_paths, which tests cover (<最多 5 个路径>); delegate implementation work without --light`。只提醒，不拒绝、不改退出码。

主会话自己的子 agent 的隐式派发（BR-2610）是重派发。

**取代 `cpu_light`**：本条生效时 BR-2627 退役，变更类型不再有内置字段 `cpu_light`（D-160 的做法由 D-161 取代）。还写着 `cpu_light` 的变更，`canon check` 对这个变更文件报一条：`cpu_light` 已废除，派发时改用 `canon work delegate … --light "<理由>"`；它不再影响派发和议程。

## 例子

- 8 个 CPU、负载 17.0（上限 16），内存正常，占用 3 个名额，`canon work delegate C-9 --to w1 --light "只写设计稿"` → 退出码 0，派发记录有 `light: 只写设计稿`，输出含 `light: 5-minute load 17.0 on 8 CPUs (limit 16), not checked for C-9: 只写设计稿`
- 同样的机器，`canon work delegate C-9 --to w1` 不带 `--light` → 退出码 1，信息含 `5-minute load 17.0 on 8 CPUs (limit 16)`，事件表有 `delegation.refuse`、原因 `capacity`，没有派发记录
- 负载 17.0，已有 10 个占用名额的派发（`delegate_max_workers` 10），`--light` 新派 `C-9` → 退出码 1，信息含 `10 of delegate_max_workers (10) in use`，不含负载那一条
- 内存压力等级 2，`--light` 新派 `C-9` → 退出码 1，信息只含 `memory pressure warn`
- `--light ""` 或 `--light "  "` → 退出码 2，没有派发记录
- `C-9` 轻派给 `w1`，`w1` 写完设计 `canon work stop`；负载 17.0 时 `canon work delegate C-9 --to w2`（不带 `--light`）→ 退出码 1，原因是负载，派发记录仍是轻派给 `w1`；负载 12.0 时再派 → 退出码 0，派发记录变成重派给 `w2`
- `C-9` 重派给 `w1`，负载 17.0 时 `canon work delegate C-9 --to w1 --light "只剩改文字"` → 退出码 0，不检查容量
- 负载 17.0，轻派的 `w1` 在 `C-9` 的 worktree 里运行 `canon work test` → 照样等负载，输出 BR-2630 的等待行
- `canon work status` → `C-9` 那一行含 `light: 只写设计稿`
- `C-9` 是轻派发，只改了 `canon/notes/` 下的文件，`land --finish` → 照常关闭，没有提醒；改了 `src/a.ts` → 照常关闭，输出 `note: C-9 was delegated light (只写设计稿) but changes 1 path(s) outside floor_skip_paths …`
- 变更 front matter 还写着 `cpu_light: "只写设计稿"` → `canon check` 报 `cpu_light` 已废除、提示 `--light`；负载 17.0 时不带 `--light` 派发它 → 照常因负载拒绝
- `C-9` 轻派给 `w1` 后停滞，负载 17.0 时重新派给 `w2` 不带 `--light` → 因负载拒绝；带 `--light` → 照常派发，不查容量
