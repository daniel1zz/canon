## 规则

`canon work delegate <C-n> --to <名字>` 不带 `--light`（重派发）新增 worker，被 BR-2526 的容量检查拒绝，而同一时刻轻派发能通过（BR-2632：内存不紧张、名额没用完，被拒只是因为负载）时，拒绝信息在 BR-2526 的那一句后面另起一行，写明：

`A light delegation still fits (<k> more): when the worker only reads, designs or researches, running no tests or builds, canon work delegate <C-n> --to <name> --light "<why>" (BR-2632). Light opens only the delegation: canon work test and the other heavy steps still wait for the load (BR-2630)`

`<k>` 是还空着的 worker 名额（`delegate_max_workers` 减去 BR-2526 算的占用）。`delegation.refuse` 事件的详情多一个 `light_fits: <k>`。退出码、拒绝本身和派发记录都照 BR-2526，不变。

内存紧张或名额用完（轻派发也会被拒）时不写这一行，详情也没有 `light_fits`；把轻派发改成重派发被负载拒绝时（BR-2632）也不写。要不要改用轻派发由派发人判断（D-156），canon 不按变更内容猜它是不是只做设计。

## 例子

- 8 核、负载 17、上限 16、内存正常、10 个名额都空，`canon work delegate C-5 --to w1` → 退出码 1，信息先是负载超限，下一行 `A light delegation still fits (10 more): … --light "<why>" (BR-2632). Light opens only the delegation: …`；事件详情 `light_fits: 10`
- 同上但内存压力 `warn` → 退出码 1，只有内存和负载的原因，没有这一行
- 名额已满、负载也高 → 没有这一行
- 负载正常 → 照常派发，没有这一行
