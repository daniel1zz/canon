## 规则

持有派发来的 `C-n` 的 worker 运行 `canon work need-design <C-n> "<哪里没定或矛盾，涉及哪些规则或文件，哪些工作因此停下>"`：记一条编号为 `#n` 的设计请求（变更、worker、设计负责人、原文、状态 `pending`），记一条 `design.request` 事件，输出 `#n` 和设计负责人，退出码 0。认领不变：不依赖这个问题的部分 worker 可以继续做。

设计负责人的 `canon brief` 和 `canon work status` 列出发给它的 `pending` 请求。设计负责人运行 `canon work design-answer <n> "<回答>"`：状态改成 `answered`，记下回答和这时 main 的提交，记一条 `design.answer` 事件。回答要改设计文档时，设计负责人先把文档合入 main，再回答，再按 BR-2497 重新派发，worker 的设计版本才跟上。worker 的 `canon brief` 列出它的请求和回答。

按 D-128。请求和回答不是人的回答（`canon human`），不算人做的决定（P7）。

不是持有 `C-n` 的 worker 运行 `need-design` → 退出码 2；`C-n` 没有派发 → 退出码 3；原文为空 → 退出码 2。不是请求里的设计负责人运行 `design-answer` → 退出码 2；`#n` 不存在 → 退出码 3；已经回答过 → 退出码 5，回答不变。

## 例子

- `agent:s7:w1` 持有派发来的 `C-9`，运行 `canon work need-design C-9 "BR-50 没写敌人丢失目标后怎么办，寻路部分停下"` → 退出码 0，`#3` 状态 `pending`，`agent:s1` 的 `canon brief` 列出 `#3`
- `agent:s1` 运行 `canon work design-answer 3 "失去目标 2 秒后回巡逻，已写进 BR-50"` → `#3` 变成 `answered`，`agent:s7:w1` 的 `canon brief` 显示回答
- `agent:s2`（不是 `#3` 的设计负责人）运行 `canon work design-answer 3 "x"` → 退出码 2
- 再回答一次 `#3` → 退出码 5
- 主会话 `agent:s1` 运行 `canon work need-design C-9 "x"` → 退出码 2
- `canon work need-design C-9 ""` → 退出码 2
