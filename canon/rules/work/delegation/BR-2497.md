## 规则

`canon work delegate <C-n> --to <名字>` 由不是 worker 的执行者（主会话 `agent:<会话>`，或人）运行：在协调数据库里记一条派发，内容是变更、worker 名字、设计负责人（运行它的执行者）、设计版本（这时 main 的提交），记一条 `delegation.create` 事件，输出这几项，退出码 0。运行它的执行者持有 `C-n` 的认领时，认领放开、worktree 保留，worker 用 `canon work start <C-n>` 认领这个 worktree（BR-2498）。

变更的 `rules:` 列出的规则在 main 上都要存在：有一条只在变更分支上 → 什么都不记，退出码 1，写明哪几条要先合入 main（设计先发布，D-128）。

对已经派出去的变更再运行一次：派发改成新的名字、新的设计负责人和这时的 main 提交，记一条 `delegation.update` 事件（写明原来的三项）；原 worker 还持有认领时，退出码 5，什么都不改，要先 `canon work take`（BR-2500）。

worker 运行它 → 退出码 2；名字含字母、数字、`-`、`_` 以外的字符 → 退出码 2；`C-n` 不存在或已关闭 → 退出码 3；`C-n` 被别的执行者认领着 → 退出码 5。

## 例子

- 主会话 `agent:s1` 持有 `C-9`，`rules: [BR-50]`，`BR-50` 在 main 上是规划中；运行 `canon work delegate C-9 --to w1` → 退出码 0，派发记下 `w1`、`agent:s1`、main 当前提交，`agent:s1` 的认领放开
- 同上，但 `BR-51` 只在 `change/C-9` 分支上 → 退出码 1，提示 `BR-51` 要先合入 main，没有派发
- `C-9` 已经派给 `w1`，`w1` 没认领；主会话 `agent:s2` 运行 `canon work delegate C-9 --to w2` → 退出码 0，派发改成 `w2`、`agent:s2`，有一条 `delegation.update` 写明原来是 `w1`、`agent:s1`
- 同上，但 `w1` 持有 `C-9` 的认领 → 退出码 5，派发不变
- `agent:s1:w1` 运行 `canon work delegate C-9 --to w2` → 退出码 2
- `--to 'w 1'` → 退出码 2
- `C-404` 不存在 → 退出码 3
