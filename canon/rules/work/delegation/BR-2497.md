## 规则

`canon work delegate <C-n> --to <名字>` 记一条派发（D-128），内容是：变更、worker 名字、设计负责人（运行它的执行者）、设计版本（这时 main 的提交）、代次（从 1 开始）、接受者（空，worker 第一次认领时填上，BR-2498），以及在这一刻固定下来的两样东西：

- **契约清单**：变更 `rules:` 列出的规则、这些规则的 `will_amend` 目标、这些规则 `## 规则` 段点名的规则和决策（只取一层）、`canon/product.md`、main 上配置 `design_paths` 列出的文件，再加上 `--contract <编号或路径>[,<编号或路径>...]` 显式补充的项（只给一次，逗号分隔；有空项或重复项是用法错误，退出码 2）；每项记下它在设计版本上的内容哈希。
- **任务**：变更文件 `## 为什么` 和 `## 要改什么` 两段的内容哈希（从变更分支已提交的变更文件读，没有分支时从 main 读）。

记一条 `delegation.create` 事件，输出这几项，退出码 0。运行它的执行者持有 `C-n` 的认领时，认领放开、worktree 保留。

设计要先发布：契约清单里的每一项都要在 main 上存在，并且变更分支从它和 main 的分叉点以来没有改过它；有一项只在分支上、或分支自己改过 → 什么都不记，退出码 1，写明哪几项要先合入 main。分支对规划中规则只做了激活（BR-2501 第 1 项允许的那种：`status` 改成 `active`、删掉 `will_amend`，其他文字不变）不算改过。main 在分叉之后往前走、改了某一项，不算分支改过：分支还是旧内容没有关系，派发按 main 上的内容固定。

对已经派出去的变更再运行一次（重新派发）：

- 名字和原来相同 → 设计版本、契约清单、任务、设计负责人更新成这一刻的，代次加 1，记 `delegation.update` 事件（写明原来的几项）。接受者还持有认领时接受者不变，它要按 BR-2498 接受新设计才能继续合入，`canon brief` 和 `canon work status` 提示它；没有人持有认领时（接受者放开了，或设计负责人 `take` 之后）接受者清空，同名的新会话可以认领，worker 崩溃后就这样恢复；
- 名字不同 → 原 worker 正持有认领时退出码 5，什么都不改，要先 `canon work take`（BR-2500）；没持有时派发改成新名字，接受者清空，代次加 1。

`canon work status` 给每条派发记录一行（派给谁、设计负责人、设计版本、代次、接受者；已被 `take` 结束的写明何时结束）。变更已经关闭（按 BR-2571 的主状态是 `landed` 或 `dropped`，包括只在分支上建过、已经放弃的）的派发记录不再列出：合入不会结束派发记录，变更做完之后它已经不需要谁处理。

运行者是 worker、或执行者认不出会话（`agent:unknown`，BR-2023）→ 退出码 2；名字含字母、数字、`-`、`_` 以外的字符 → 退出码 2；`C-n` 不存在或已关闭 → 退出码 3；`C-n` 被 worker 以外的别的执行者认领着 → 退出码 5。项目的 `after_land` 里没有运行 `scripts/code-review.ts` 的命令时，派发照样成功，输出多一行 `design-gap review: not configured`（BR-2503）。

## 例子

- 主会话 `agent:s1` 持有 `C-9`，`rules: [BR-50]`，`BR-50` 在 main 上是规划中、分支上没改；运行 `canon work delegate C-9 --to w1` → 退出码 0，派发记下 `w1`、`agent:s1`、main 当前提交、代次 1、契约清单含 `BR-50` 和它点名的 `D-40`，`agent:s1` 的认领放开
- `C-9` 的 `rules: [BR-50, BR-51]`，`BR-51` 只在 `change/C-9` 分支上 → 退出码 1，提示 `BR-51` 要先合入 main，没有派发
- 同上，`BR-50` 在分支上改了一句 → 退出码 1，点名 `BR-50`
- `w1` 持有 `C-9`，分支上 `BR-50` 还是旧内容；`agent:s1` 用另一个变更把 `BR-50` 的修改合入 main 后运行 `canon work delegate C-9 --to w1` → 退出码 0，代次 2，设计版本更新，接受者和认领不变
- `BR-50` 的规则段不在反引号里点名另一条规则 → 契约清单含那条规则；只在反引号里写的编号是举例，不算点名
- `--contract D-40,docs/DESIGN.md` → 两项都进契约清单；`--contract D-40,,docs/DESIGN.md` 或 `--contract D-40,D-40` → 退出码 2
- `C-9` 在 `change/C-9` 上改了 `canon/product.md` 的一句 → 退出码 1，点名 `canon/product.md`
- `w1` 在分支上只把 `BR-50` 激活了，`agent:s1` 重新派发 → 退出码 0
- `agent:s7:w1` 崩溃，`agent:s1` `take` 后运行 `canon work delegate C-9 --to w1` → 接受者清空，新会话 `agent:s8:w1` 能认领
- `C-9` 派给 `w1`，`w1` 没认领；`agent:s2` 运行 `canon work delegate C-9 --to w2` → 退出码 0，派发改成 `w2`、`agent:s2`，有 `delegation.update` 写明原来是 `w1`、`agent:s1`
- 同上，但 `w1` 持有 `C-9` 的认领 → 退出码 5，派发不变
- `C-9` 派给 `w1`，还没合入 → `canon work status` 有 `C-9: delegated to w1; design owner agent:s1; …` 一行；`C-9` 合入、在 main 上是 `done` 之后，派发记录还在，这一行不再出现
- `agent:s1:w1` 或 `agent:unknown` 运行 `canon work delegate C-9 --to w2` → 退出码 2
- `--to 'w 1'` → 退出码 2；`C-404` 不存在 → 退出码 3
- 项目没配 `scripts/code-review.ts` → 退出码 0，输出有 `design-gap review: not configured`
