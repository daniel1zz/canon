## 规则

**能设计的 worker**：worker（`agent:<会话>:<名字>`，BR-2023）的环境里有 `CANON_WORKER_PROFILE=<档案名>`，并且这个档案名在 main 上 `canon/config.yaml` 的 `design_profiles` 列表里（D-162）。`CANON_WORKER_PROFILE` 由启动 worker 的工具（派发方）和 `CANON_SUBAGENT` 一起设，写它启动 worker 用的档案（例如 Opus 级模型的档案）；两侧空白去掉，空值按没设。`design_profiles` 是可选的字符串列表，默认空：不配置时没有能设计的 worker，一切照旧。它从合入前的 main 读，不从运行命令的 worktree 读：worker 在自己的分支上把自己加进去不生效。不是字符串列表 → 配置错误，退出码 2（BR-2045）。

能设计的 worker 和别的 worker 只差两处：

1. **可以开新工作**：BR-2498 对新建变更、修复变更和杂务的拒绝对它不成立，按 BR-2012、BR-2457 进行；新建的变更或杂务由它认领，没有派发记录。`work.start` 和 `chore.start` 事件的详情记 `worker_profile: <档案名>`。
2. **可以合入设计**：合入时不做 BR-2501 第 1 项的检查，杂务也一样；派给它的变更其余几项照 BR-2501。

其余照 worker 的规则：只能认领派给它的或自己开的变更（`canon work start <C-n>` 认领别人开的、没派给它的变更仍按 BR-2498 拒绝）；不能 `canon work delegate`（BR-2497）、`take`、`unstall`（BR-2468）；不能给评审意见定档和关闭（BR-2502）。它合入的规则和决策照常走合入后的规则评审，不因它能设计少任何检查。

**防冒充**：Bash 前的 hook（BR-2495 的 `canon work check-as --hook`）看到命令文字里设了 `CANON_WORKER_PROFILE`（`CANON_WORKER_PROFILE=…` 前缀或 `export CANON_WORKER_PROFILE`），拒绝，原因写 `CANON_WORKER_PROFILE is set by the tool that starts the worker, not by a command (BR-2633)`，事件表记 `claim.refuse`。hook 只看命令文字，写进脚本再运行的绕不过 canon 的命令本身，但 hook 看不到：这和 `CANON_SUBAGENT` 一样靠派发方设环境（D-125），刻意绕过属于不正常的动作（D-54），是已知的限制。

## 例子

- main 的 `design_profiles: [sub-opus]`，worker `agent:s7:w1` 的环境有 `CANON_SUBAGENT=w1`、`CANON_WORKER_PROFILE=sub-opus`，运行 `canon work start --title "x" --owner-gate "none: …" --advances "none: …"` → 新建变更并认领，`work.start` 的详情有 `worker_profile: sub-opus`
- 同上，`canon chore start "整理脚本"` → 开始杂务
- 同上，`CANON_WORKER_PROFILE=sub-sonnet` → 退出码 1，按 BR-2498 提示新工作由设计负责人建好再派发
- 没配 `design_profiles`，`CANON_WORKER_PROFILE=sub-opus` → 按 BR-2498 拒绝
- `w1`（`sub-opus`）在自己开的变更里写了 `D-9` 和规则 `BR-50`，`canon work land --finish` → 不因改了设计拒绝，合入后照常排规则评审
- `w2`（`sub-sonnet`）的变更改了 `BR-50` 的 `## 规则` → 按 BR-2501 第 1 项拒绝
- `C-9` 由 `agent:s1` 派给 `w1`（`sub-opus`），`w1` 改了契约清单里的 `BR-50` → 不因第 1 项拒绝；`agent:s1` 之后重新派发、代次变成 2，`w1` 没接受新设计就合入 → 按第 4 项拒绝
- `w1`（`sub-opus`）运行 `canon work start C-12`，`C-12` 是 `agent:s1` 开的、没派给它 → 退出码 1
- `w1`（`sub-opus`）运行 `canon work delegate C-12 --to w3` → 退出码 2
- worker 在自己的 worktree 里把 `design_profiles` 加上 `sub-sonnet` 后运行 `canon work start --title` → 仍按 main 的配置判断，拒绝
- `w2` 运行 `CANON_WORKER_PROFILE=sub-opus canon work start --title "x"` → hook 拒绝，原因含 `set by the tool that starts the worker`
- `design_profiles: sub-opus`（不是列表）→ 配置错误，退出码 2
