## 规则

`canon work delegate <C-n> --to <name>` 只有在会**新增** worker 时才检查机器容量。新增的意思是：这个变更现在没有生效的派发（从没派过，或已被 `take` 结束，BR-2500）。给已有生效派发的变更重新派发，只是换 worker，不新增；把停滞的变更重新派出去（BR-2522）也属于这种情况，不检查。

新增时，下面任一条成立就拒绝：

1. **内存紧张**：
   - macOS：`kern.memorystatus_vm_pressure_level` 是 2（warn）或 4（critical）；
   - Linux：`/proc/pressure/memory` 中 `some` 一行的 `avg10` 达到 10；没有这个文件时，`/proc/meminfo` 里 `MemAvailable` 低于 `MemTotal` 的 10%。
2. **CPU 紧张**：5 分钟平均负载达到 CPU 数（`availableParallelism`）的 `delegate_max_load_per_cpu` 倍（`canon/config.yaml`，大于 0，默认 2）。比较用没有取整的值，和 BR-2400 一样。
3. **名额用完**：占用名额的派发已经有 `delegate_max_workers` 个（`canon/config.yaml`，正整数，默认 10）。一个派发占用名额，要同时满足：它是生效的，它的变更在 main 上不是关闭的（还是 open，或者 main 上还没有这个变更），并且它没有停滞（BR-2522）。

被拒绝时：
- 不写派发记录，退出码 1；
- 信息列出所有成立的条件，每条带上实测值和上限：内存压力等级或 PSI、`MemAvailable` 的比例，负载（一位小数）、CPU 数和上限，占用的名额数和 `delegate_max_workers`；
- 信息建议等一个 worker 合入，或者等负载降下来再派；
- 事件表记一条 `delegation.refuse`，对象是这个变更编号，原因 `capacity`，详情包含各项实测值和成立的条件。

**测不到的信号**：读不到内存信号（不是 macOS 或 Linux，或者读取失败），或者三个负载平均值都是 0，那一项就算测不到。测不到的项不参与判断，派发照常进行，但输出一行 `capacity: <memory|load> not measured on this platform; delegated without that check`，并在派发事件 `delegation.create` 的详情里记 `unmeasured`。名额总是能数出来。

数名额和写派发记录在同一个写事务里（BEGIN IMMEDIATE），两个会话同时派发时，后一个会数到前一个刚写入的派发。停滞和变更是否关闭在进事务之前算好，事务里只数派发记录。

依据：D-136；负责人在 human #67 选了按内存压力判断，并补充「内存和cpu都需要」。

## 例子

- macOS 内存压力等级 1，8 个 CPU、负载 12.7，占用名额 3 个，新派 `C-9` → 照常派发
- 内存压力等级 2，新派 `C-9` → 退出码 1，信息含 `memory pressure warn`，事件表有 `delegation.refuse`、原因 `capacity`，没有派发记录
- 8 个 CPU、负载 16.0，`delegate_max_load_per_cpu` 默认 → 拒绝，信息含 `5-minute load 16.0 on 8 CPUs (limit 16)`；负载 15.96 → 不因负载拒绝
- 已有 10 个占用名额的派发，新派第 11 个 → 拒绝，信息含 `10 of delegate_max_workers (10) in use`
- 10 个派发中有 1 个的变更已在 main 上关闭，或者已经停滞 → 只占 9 个，第 11 个照常派发
- 内存压力等级 4，重新派发停滞的 `C-3` 给新的 worker → 照常派发，因为不新增 worker
- Linux 没有 `/proc/pressure/memory`，`MemAvailable` 是 `MemTotal` 的 8% → 拒绝，信息含 `MemAvailable 8%`
- Windows：内存测不到，负载是 0 0 0 → 照常派发，输出两行 `capacity: memory not measured …` 和 `capacity: load not measured …`，`delegation.create` 的详情有 `unmeasured: ["memory","load"]`
- 两个会话同时新派，派完前已占用 9 个名额 → 只有一个成功，另一个被拒，信息含 `10 of delegate_max_workers (10) in use`
