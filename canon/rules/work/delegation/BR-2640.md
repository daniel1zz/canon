## 规则

`policies.capacity`（BR-2638）设机器什么时候算忙，派活（BR-2526）和议程的可派一组（BR-2581）都按它判断；每一项不写时用括号里的默认值（D-164）：

- `memory_tight_level`（`warn`）：macOS 的内存压力从哪一级起算紧张，`warn` 或 `critical`。写 `critical` 时 `warn` 不算紧张。测试用的 `CANON_MACHINE` 给出的级别同样按它判断。
- `memory_psi_percent`（10）：Linux 的内存 PSI `some avg10` 到这个百分比就算紧张。大于 0、不超过 100。
- `memory_available_percent`（10）：Linux 没有 PSI 时，MemAvailable 占 MemTotal 低于这个百分比就算紧张。大于 0、不超过 100。
- `full_run_load_share`（0.9）：有整组测试在跑时，负载上限按 `delegate_max_load_per_cpu` 算出的上限乘以它（BR-2581）。大于 0、不超过 1。
- `critical_lane`（`true`）：挡着别的变更的变更跑点名文件的测试时走关键链通道（BR-2643），`false` 关掉。

机器满了就不再派新 worker 这件事本身不能关（D-136），这里只改「满」的门槛。

## 例子

- macOS 内存压力 `warn`，`memory_tight_level: critical` → 不算紧张，可以派；`critical` → 算紧张，不派
- 不写 → `warn` 就算紧张
- Linux PSI 12%，`memory_psi_percent: 20` → 不算紧张
- 8 核、`delegate_max_load_per_cpu: 2`、有整组测试在跑、`full_run_load_share: 0.5` → 负载上限 8
- `full_run_load_share: 1.5` → 配置错误，退出码 2
