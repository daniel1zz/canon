## 规则

主会话 `agent:<会话>` 的子 agent（`agent:<会话>:<名字>`，按 BR-2023 认出）运行 `canon work start <C-n> --as <名字>`，而 `C-n` 是打开的、没有派发、没有活着的认领时，canon 先替这个会话做一次派发（同 BR-2497：设计负责人是 `agent:<会话>`、设计版本是 main 现在的提交、契约清单照算；契约里有不在 main 上的设计文档时照 BR-2497 拒绝），派发事件 `delegation.create` 记在 `agent:<会话>` 名下，带 `implicit: true` 和 `by: <子 agent 的执行者>`，输出一行写明替哪个会话派给了哪个子 agent，再让这个子 agent 认领，和先 `canon work delegate C-n --to <名字>` 再认领的结果一样（D-156）。BR-2608 和 BR-2609 的提醒照常输出。机器忙（BR-2526 会拒绝新的派发）时不拒绝：子 agent 已经在跑，拒绝它的认领腾不出机器；改为输出一行 `machine busy: <原因，同 BR-2526>; …`，写明照常开工、机器回落之前不要再开子 agent（D-156 修订 D-136）。变更关闭了或不存在时照开工的规则拒绝（BR-2011）。已经派给别人、或者有活着的认领时照 BR-2498 拒绝。别的会话启动的 worker 不适用，它们只认领派给它们的：运行环境里有 `CANON_SUBAGENT`（BR-2495）或 `CLAUDE_DELEGATE_CHILD=1`（BR-2468）的执行者，即使带 `--as`，也照 BR-2498 处理。

## 例子

- 主会话 `agent:s1` 提前建了 `C-9`，没派；它的子 agent 运行 `canon work start C-9 --as w1` → 退出码 0，派发记录设计负责人 `agent:s1`、接受者 `agent:s1:w1`，`delegation.create` 带 `implicit: true`
- `C-9` 已经派给 `w2` → 照 BR-2498 退出码 1
- `C-9` 被另一个会话认领着（认领活着）→ 照 BR-2498 退出码 1，写“未派发”
- 机器忙（BR-2526 会拒绝新的派发）→ 照常派发和认领，输出里有一行 `machine busy: …`
- 机器有空 → 没有 `machine busy` 这一行
- `delegate run` 启动的 worker（环境里有 `CLAUDE_DELEGATE_CHILD=1`）带 `--as` 认领没派给它的 `C-9` → 照 BR-2498 退出码 1，写“未派发”
