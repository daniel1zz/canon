## 规则

`canon work adopt [<C-n>,...] --from <旧设计负责人> [--gone]` 由主会话（执行者 `agent:<会话>`）或人（`human:<名字>`）运行，把旧设计负责人名下、还没结束的派发的设计负责人改成运行者自己（D-165）；不写变更时接管旧设计负责人名下全部还没结束的派发。只改设计负责人：worker 的认领、派发的代次都不变，之后新设计负责人照 BR-2500 用 `canon work take` 收回，或收回后重新派发。每个接管的变更记一条 `delegation.adopt` 事件（`from`、`to`、`gone`），输出接管了哪些变更和下一步的命令，退出码 0。

旧设计负责人的会话是否已经结束，按它名下认领记下的会话进程判断：

- 有一个进程还在 → 退出码 5，什么都不改，带 `--gone` 也一样：它自己还能收回和派发。
- 有进程已经不在、没有还在的 → 接管，`gone` 记 `proven`。
- 一个进程也没记下（进程记在另一台机器上，或认领从没记下进程）→ 不带 `--gone` 时退出码 5，什么都不改，提示确认它已经结束后带 `--gone` 再运行；带 `--gone` 时接管，`gone` 记 `asserted`。

写出的变更里有一个不是旧设计负责人名下还没结束的派发、旧设计负责人名下一个这样的派发也没有、或 `--from` 就是运行者自己 → 退出码 5，什么都不改。拒绝都记一条 `claim.refuse`（`adopt`）。运行者是 worker 或子 agent（执行者有第三段）、或带了 `--as` → 退出码 2；`--from` 不是 `agent:<会话>` 或 `human:<名字>` 的形式 → 退出码 2。


## 例子

- 笔记本上的主会话 `agent:9e301322` 派出 3 个变更，换到新机器后新主会话 `agent:decd0d37` 运行 `canon work adopt --from agent:9e301322 --gone` → 3 个派发的设计负责人都变成 `agent:decd0d37`，每个一条 `delegation.adopt`（`gone: asserted`），worker 的认领不变
- 同样的情形不带 `--gone` → 退出码 5，什么都不改，提示带 `--gone`
- 旧设计负责人名下有认领，记下的会话进程已经不在 → 不用 `--gone` 就接管，`gone: proven`
- 旧设计负责人名下有认领，记下的会话进程还在 → 退出码 5，带 `--gone` 也是
- `canon work adopt C-9 --from agent:s1`，而 C-9 的派发已经被收回（结束）→ 退出码 5，什么都不改
- worker `agent:s7:w1` 运行 `canon work adopt --from agent:s1` → 退出码 2
