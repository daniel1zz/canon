## 规则

变更的 front matter 可以写 `cpu_light: "<为什么它不跑测试和构建>"`（D-160）：主会话判断这项工作（例如只写设计稿、调研笔记）的 worker 不会跑测试、构建这类占 CPU 的命令。可选字段，新建时不要求；写了就要是非空文字，否则 `canon check` 报这个变更文件的格式错误（同 BR-2619 的字段格式检查）。它是内置变更类型声明的字段，项目不能再给变更声明同名字段（BR-2619）。

写了它的变更：

- `canon work delegate` 不看负载（BR-2526 第 2 条），内存和名额照查；
- 议程只因负载没空时，把它列为现在就能派（BR-2581）；
- `canon work land --finish` 关闭它时，如果这个分支改了 `floor_skip_paths` 以外的路径（测试覆盖的代码），输出一行 `note: <C-n> is cpu_light (<理由>) but changes <n> path(s) outside floor_skip_paths, which tests cover (<最多 5 个路径>); …`，说它的 worker 其实跑了测试、加了负载，以后这类工作别标。只提醒，不拒绝、不改退出码。

没写 `cpu_light` 的变更一切照旧。

## 例子

- `C-9` 写着 `cpu_light: "只写设计稿"`，只改了 `canon/notes/` 下的文件，`land --finish` → 照常关闭，没有这条提醒
- `C-9` 写着 `cpu_light`，却改了 `src/a.ts` → 照常关闭，输出 `note: C-9 is cpu_light (只写设计稿) but changes 1 path(s) outside floor_skip_paths, which tests cover (src/a.ts); …`
- `cpu_light: ""` 或 `cpu_light: true` → `canon check` 报格式错误
- 没写 `cpu_light` 的变更改了 `src/a.ts` → 没有这条提醒
