## 规则

`canon work watch` 一直运行，直到收到 SIGTERM 或 SIGINT（退出码 0），每输出一行就立即刷新。设计上它由宿主挂在 Monitor 之类的工具下，每行会成为会话收到的一条消息，所以只输出值得处理的内容。

1. **启动**：先输出一行 `watch from #<n>`，`<n>` 是当前事件表的最大编号；然后按 BR-2527 的格式输出现在的全部待办，每件一行，前面加 `due`。
2. **事件**：此后每秒按编号读新事件（同 BR-2357），只输出和调用者有关的几类，每行以 `#<事件编号>` 开头，结尾带下一步命令。
   - 主会话看：合入成功或被拒（`land.ok`、`land.refuse`）、新的拦截评审意见、交接、设计请求、问题的提出和回答、认领失效（`claim.holder-gone`、`claim.expired`）、`delegation.refuse`；
   - worker 只看和自己的变更有关的（同 BR-2527 的 worker 待办）。
3. **待办的变化**：每 30 秒重算一次待办清单，和上一次比较：新出现的一件输出一行 `due …`，消失的一件输出一行 `done <键>`。
4. **重复提醒**：还在清单里的待办，每过 `remind_every_minutes`（`canon/config.yaml`，大于 0，默认 30）再输出一次，行首写 `still`，带上已开时长。同一轮要重复的几件合成一行，最多列 10 个键，多出的写 `… and <k> more: canon work due`。
5. **限量**：同一秒要输出的事件行超过 20 条时，只输出前 20 条，再加一行 `… <k> more events: canon events --since <编号>`。
6. **重挂不丢事件**：`--since <n>` 从事件 `<n>` 之后开始，先补出缺的相关事件，再照上面运行；启动时的 `watch from` 行写出这次的起点。宿主到期重挂时，用上一次输出过的最大事件编号作为 `--since`。
7. **出错**：
   - 协调数据库忙时跳过这一轮，同 BR-2357；
   - 其他错误先输出一行 `watch stopped: <原因>; run canon work watch --since <最后编号> again`，再按退出码表退出；
   - 不在没有任何输出的情况下退出。

watch 不改认领、队列和派发，也不登记自己（D-136 的方案 6）；重算待办时判断认领状态，第一次发现失效时按 BR-2360 写事件，此外不写事件。

依据：D-136。

## 例子

- 启动时有意见 #12（B 档，40 分钟）→ 输出 `watch from #5003`、`due finding:12 40m … → … canon finding advise 12`
- 之后别的会话合入 `C-7` → 一行 `#5010 land.ok C-7 …`
- 意见 #12 被关闭 → 30 秒内输出 `done finding:12`
- 意见 #12 一直开着，默认间隔 → 每 30 分钟一行 `still finding:12 1h10m …`
- 一秒内来了 25 条相关事件 → 20 行，再加 `… 5 more events: canon events --since 5030`
- `--since 5003`，事件 5004 到 5010 中有 2 条相关 → 先输出这 2 条
- worker 运行 → 看不到别的变更的 `land.ok`
- 协调数据库文件被删掉 → 输出 `watch stopped: …`，退出码 4
- 收到 SIGTERM → 退出码 0
