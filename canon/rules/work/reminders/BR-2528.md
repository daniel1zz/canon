## 规则

`canon work watch` 一直运行，直到收到 SIGTERM 或 SIGINT（退出码 0），每输出一行就立即刷新。它由宿主挂在 Monitor 之类的工具下，每行会成为会话收到的一条消息，所以只在有事件或状态变化时输出，没有定时重复的行（D-151 修改 D-136）。

1. **启动**：先输出一行 `watch from #<n>`，`<n>` 是当前事件表的最大编号；然后输出议程摘要（BR-2529 的格式：各组的条数和最前面几项，不是全部）；议程为空时不输出摘要。
2. **事件**：此后每秒按编号读新事件（同 BR-2357），只输出和调用者有关的几类，每行 `#<事件编号> <种类> <对象> <执行者>[ <原因>] → <下一步命令>`。
   - 主会话看：合入成功或被拒（`land.ok`、`land.refuse`）、新的拦截评审意见、交接、设计请求、问题的提出和回答、认领失效（`claim.holder-gone`、`claim.expired`）、`delegation.refuse`；
   - worker 只看和自己的变更有关的（同 BR-2527 的 worker 议程）。
3. **合入之后可以开始的**：主会话看到一个变更的 `land.ok` 后，在同一秒重算议程，紧跟那一行再输出一行 `<C-n> landed; <C-m>[, <C-k>…] can start now`，列出合入前不能开始、现在主状态是 `ready-delegatable` 或 `ready-self` 的变更（BR-2571），按 `canon change list` 的顺序；没有这样的变更时不输出这一行。不论这次合入是谁做的（主会话自己还是 worker）。
4. **议程的变化**：每读到一批新事件后重算议程（相关的或会改变状态的事件，例如派发、认领、合入、放弃、评审意见、处理结论、整组测试），另外每 60 秒重算一次，用来发现不产生事件的变化（停滞、推迟到期）。和上一次比较，只输出变化：
   - 新出现的一项：`+ <组> <BR-2527 的项行>`，组是 `delegate`、`judge`、`owner` 或 `yours`；可派的活写成 `+ delegate ready:<C-n> - <标题>`；
   - 消失的一项：`- <键>`；
   - 正在跑的整组测试（BR-2582）的集合或排队数变了：输出新的 `heavy:` 一行，都没有了时输出 `heavy: none`；只是已跑时长变长不输出；
   - 一次新出现的项超过 10 个时，只输出前 10 个，再一行 `… +<k> more: canon work due`。
   还在议程里的项不再输出，不管开了多久。
5. **机器容量**（只对主会话）：每秒读一次机器容量，按 BR-2581 判断有没有空，只在状态翻转的那一刻输出一行，带回差：
   - 从有空变成没空：BR-2581 的任一个没空条件成立时，输出 `capacity busy: <原因，分号分隔>; delegate no new worker`；
   - 从没空变成有空：内存不紧张、名额还有，并且 5 分钟负载低于这时适用的负载上限的 0.9 倍时，输出 `capacity room: room for <k> more[; delegatable: <变更编号，逗号分隔，最多 5 个>]`；
   - 负载在两条线之间来回时不输出。启动时的状态由议程摘要给出，不另输出 `capacity` 行。
6. **限量**：同一秒要输出的事件行超过 20 条时，只输出前 20 条，再加一行 `… <k> more events: canon events --since <编号>`。
7. **重挂不丢事件**：`--since <n>` 从事件 `<n>` 之后开始，先补出缺的相关事件，再输出议程摘要，然后照上面运行；启动时的 `watch from` 行写出这次的起点。宿主到期重挂时，用上一次输出过的最大事件编号作为 `--since`。
8. **出错**：
   - 协调数据库忙时跳过这一轮，同 BR-2357；
   - 其他错误先输出一行 `watch stopped: <原因>; run canon work watch --since <最后编号> again`，再按退出码表退出；
   - 不在没有任何输出的情况下退出。

`remind_every_minutes` 配置键去掉，配置里还写着它时的失败和信息照 BR-2530 对去掉的键的处理，信息说明 watch 不再定时重复。

watch 不改认领、队列和派发，也不登记自己（D-136 的方案 6）；重算议程时判断认领状态，第一次发现失效时按 BR-2360 写事件，此外不写事件。

依据：D-151 第三部分第 7 条（修改 D-136）；F-2 的成功标准 S1、S2，F-3 的 S2。

## 例子

- 启动时有意见 #12（B 档，40 分钟），`C-9` 可派 → `watch from #5003`、`Agenda (canon work due):`、`  delegate: room for …: C-9`、`  judge: 1: finding:12`
- 议程为空 → 只有 `watch from #5003`
- worker 合入 `C-7`，`C-8` 只依赖 `C-7` → `#5010 land.ok C-7 …` 和 `C-7 landed; C-8 can start now`，在合入后 1 秒内
- 合入 `C-7` 后没有变更因此可以开始 → 只有 `#5010 land.ok …`
- 意见 #12 被关闭 → `- finding:12`
- 意见 #12 一直开着，watch 跑了 3 小时 → 启动后再没有关于 #12 的行
- 主 agent 对 `stalled:C-5` 记下交给 `C-9` → `- stalled:C-5`
- 负载上限 16，负载从 15.9 升到 16.1 → 一行 `capacity busy: 5-minute load 16.1 on 8 CPUs (limit 16); delegate no new worker`；之后在 15.0 和 16.3 之间来回 → 不输出；降到 14.3 → 一行 `capacity room: room for …`
- `C-637` 开始整组测试 → `heavy: C-637 full test run 0m`；结束 → `heavy: none`
- 一秒内来了 25 条相关事件 → 20 行，再加 `… 5 more events: canon events --since 5030`
- `--since 5003`，事件 5004 到 5010 中有 2 条相关 → 先输出这 2 条，再是议程摘要
- worker 运行 → 看不到别的变更的 `land.ok`，没有 `capacity` 行
- `canon/config.yaml` 写着 `remind_every_minutes: 30` → 退出码 2，信息含 `remind_every_minutes` was removed
- 协调数据库文件被删掉 → 输出 `watch stopped: …`，退出码 4
- 收到 SIGTERM → 退出码 0
