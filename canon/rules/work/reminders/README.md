# 提醒（work/reminders）

把主 agent 现在该知道的事送到它面前（D-136、D-151）。“该处理什么”只在一处算：议程，它读变更的状态（knowledge/changes，BR-2571）、协调数据库和机器容量，不自己再算一遍状态。送达的地方：`canon brief`、合入之后、`canon work start`，以及长期运行的 `canon work watch`（宿主用 Monitor 之类的工具挂着它）。这里的事只提醒，不挡任何工作（D-139）；不定时重复（D-151）。

不管：保证 main 正确的拒绝（work/land）、派发时的容量限制和派发冲突（work/delegation，BR-2526）、原始事件流 `canon events --follow`（work/stats，BR-2357）、整组测试怎样排队（写事件的一方，本领域只读这些事件）。

## 术语

- **议程**：主会话现在该知道的事，分三组：可派的活、要判断的事、等负责人的事；另加一行正在跑的整组测试。
- **议程项**：议程里的一件事，有一个稳定的键（`finding:12`、`stalled:C-5`、`ready:C-9`），有开始的时间，还有下一步命令。
- **处理结论**：主 agent 对一个议程项写下的「交给 C-n」「推迟，原因」或「不处理，原因」，记成事件。
- **有空**：机器能再加 worker：内存不紧张、负载没超、名额还有（BR-2581）。
- **整组测试**：跑项目全部测试的一次运行（`canon work test --all`、后台 floor），由排队的一方写成 `test.full.*` 事件。
- **主会话视角 / worker 视角**：按调用者的执行者身份（BR-2023）决定看哪些；worker 只看和自己的变更有关的。

## 业务

- **议程**：现在可以派哪些活、要判断哪些事、要问负责人哪些事，每件开了多久，下一步运行什么。
- **机器容量和重活**：机器有没有空、还能派几个，正在跑的整组测试和排队的。
- **处理结论**：主 agent 怎样记下对一条提醒的处理，记下之后它什么时候再出现。
- **送达时机**：议程在哪些时候、以什么形式送到会话：brief、合入之后、开工时、长期运行的 watch。
