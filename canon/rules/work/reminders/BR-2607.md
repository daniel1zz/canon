## 规则

主会话议程（BR-2527）的第一组（BR-2581 的可派一组）改为列出能开工的变更：主状态是 `ready-delegatable` 或 `ready-self` 的（BR-2571），按 BR-2604 的顺序，经过处理结论（BR-2583）过滤；没有时整组不输出。组头照 BR-2581 写机器还能派几个或为什么忙（容量按 BR-2526），后面加 `; start or delegate: your call (D-156)`：canon 不给默认做法，由主 agent 决定（D-156）。机器忙时各项照样列出。

最多 5 项，每项一行：

- 能派的：`ready:<C-n> <档位> - <标题> → canon work start <C-n> | canon work delegate <C-n> --to <name>`；
- 不能派的（`ready-self`）：`ready:<C-n> <档位> - <标题> → canon work start <C-n> (not delegatable: <BR-2571 记下的原因>)`。

多于 5 项时再一行 `… <m> more ready (canon change list)`。每项下面缩进写判断要用的事实，每条一行：和正在进行的变更共用的规则（BR-2608 的行），能派的另写设计没定的地方（BR-2609 的行）；没有就不写。档位照 BR-2603 写（`P0` 到 `P3`）。

`canon work watch` 新出现一项时（BR-2528 第 4 点）写 `+ delegate <同样的项行>`，下面同样缩进写事实。`--json` 的 `delegate` 里多一个 `ready` 数组，每项有 `id`、`tier`、`delegatable`、`not_delegatable`（原因数组）和 `facts`（事实行数组）。议程摘要（BR-2529）照旧只列能派的。

## 例子

- `C-5` 能派、`P2`、没有牵连 → 一行 `ready:C-5 P2 - <标题> → canon work start C-5 | canon work delegate C-5 --to <name>`，下面没有事实行
- `C-6` 和正在做的 `C-4` 都要改 `BR-12` → `C-6` 那行下面一行写 `C-6 shares BR-12 with C-4 (…)`
- `C-7` 是 `ready-self` → 只写 `canon work start C-7`，括号里写不能派的原因
- 机器忙 → 组头写忙的原因和 `start or delegate: your call`，各项照样列出
- 没有能开工的变更 → 整组不输出
