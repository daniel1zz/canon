## 规则

一个打开的变更带关卡（`owner_gate` 写着负责人要批准的文字；写成 `none: <理由>` 的不算，BR-2615），而按 BR-2616 还不算批准时，每个主会话的议程判断组第三档有一项 `owner-gate:<C-n>`（BR-2527），从变更开着起一直在，直到批准或变更关闭（D-158）：

- 没有还没回答、问这段关卡文字的 `approve C-n` 问题 → 项行写 `<C-n> needs the owner's approval of: <owner_gate>; ask when it is ready to show`，最近一次回答不是批准时另写那个问题的编号和回答；只有问别的关卡文字的回答时（`owner_gate` 后来改了，BR-2616），另写那个旧问题的编号和它问的文字，说要重新问；做法是 `canon human ask "approve <C-n>: <owner_gate>?" --option 批准,不批准 --change <C-n>`；
- 有还没回答、问这段关卡文字的 `approve C-n` 问题 → 项行写在等问题 `#<n>` 的回答，做法是在对话里原样问负责人（那个问题本身照 BR-2527 列在等负责人一组）。

它可以按 BR-2583 推后或不处理（例如稿子还没写好）。worker 的议程没有这一项。

## 例子

- `C-9` 带 `owner_gate: "设计稿"`，没问过 → `owner-gate:C-9 … C-9 needs the owner's approval of: 设计稿; ask when it is ready to show → canon human ask "approve C-9: 设计稿?" …`
- 问了 #12，还没回答 → 这一项写在等 #12
- #12 答了 `批准` → 这一项消失
- #12 答了 `不批准` → 这一项写 #12 答的 `不批准`，做法是改好再问
- `C-9` 关闭了 → 消失
- `C-9` 的 `owner_gate` 从 `设计稿` 改成 `上线到生产`，#12 问 `设计稿` 答过 `批准` → 项行写 `question #12 was about an earlier owner_gate text, "设计稿", so ask again`，做法是问 `approve C-9: 上线到生产?`
