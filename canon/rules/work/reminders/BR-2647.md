## 规则

主会话或人（BR-2646 里能运行 `canon work adopt` 的执行者）的议程，对每个设计负责人不是自己、名下有还没结束的派发的执行者，按 BR-2646 的办法判断它的会话：

- 有一个记下的进程还在 → 不提示。
- 有记下的进程已经不在 → 列一项。
- 一个进程也没记下 → 它在事件表里最后一条事件早于 6 小时前（或一条也没有）时列一项；6 小时内有事件就不提示（D-165）。同时开着、没记下进程的另一个主会话就是这样被排除的。

每个这样的执行者一项，在“要判断的事”里，排在挡住别人的那一档：键是 `adopt:<执行者>`，开始时间是它最后一条事件的时间，内容写派发个数、它的会话是已经结束还是看不到又安静了、前 5 个变更编号，下一步是 `canon work adopt --from <执行者>`（看不到时加 `--gone`，并写明确认它已经结束后再运行），接着 `canon work take <C-n> --from <worker>`。接管之后它名下不再有还没结束的派发，这一项自然消失。worker 和子 agent 的议程没有这一项。

## 例子

- 新主会话 `agent:s2` 的议程，`agent:s1` 名下有 2 个还没结束的派发，没记下进程，最后一条事件在 8 小时前 → 一项 `adopt:agent:s1`，下一步 `canon work adopt --from agent:s1 --gone`
- 同样的情形，`agent:s1` 的最后一条事件在 1 小时前 → 没有这一项
- `agent:s1` 名下的认领记下的进程已经不在 → 一项，下一步不带 `--gone`
- `agent:s1` 名下的认领记下的进程还在 → 没有这一项
- worker `agent:s7:w1` 的议程 → 没有这一项
- `agent:s2` 运行 `canon work adopt --from agent:s1 --gone` 之后 → 这一项消失
