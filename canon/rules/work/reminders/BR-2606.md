## 规则

一个 `P0` 或 `P1` 的变更（BR-2602）没有进展时，每个主会话的议程判断组第一档有一项 `interrupt:<C-n>`，`canon work watch` 在它出现的那一刻输出一行（BR-2528）。没有进展是指：它可以开始（BR-2571 的可开始状态）而没有活着的认领，或者派出去以后停滞了（BR-2527 的 `stalled`）。`red-main`（BR-2601）对应的是 `P0`，单独成项，不重复成 `interrupt`。

这一项不写死下一步，写出两种做法和判断要用的事实，由主 agent 决定（D-156）：

- 做法：派出去（`canon work delegate <C-n> --to <名字>`，不用停下手上的活），或者自己做（停下手上的某个变更 `canon work stop --reason partial --next "<下一步>"`，再 `canon work start <C-n>`）；
- 事实：机器还能不能派、还能派几个（BR-2526）；这个会话认领着哪些变更、各自的档位；和正在进行的变更共用契约里的哪些规则（BR-2608）；设计有没有没定的地方（BR-2609）。没有的事实不写。

worker 的议程没有这一项。`P1` 的这一项可以按 BR-2583 推后或不处理；`P0` 的不能，和 `red-main` 一样以退出码 1 拒绝。变更有了活着的认领、开始合入、或档位降到 `P2` 以下以后，这一项消失。

## 例子

- 负责人把没人认领的 `C-7` 定为 `P0`，主会话 A 还能派 2 个、认领着 `P2` 的 `C-5` → A 的议程有 `interrupt:C-7`，写出派出去和停下 `C-5` 自己做两种做法，事实写还能派 2 个、A 认领着 `C-5`（`P2`）；watch 输出一行
- 同样，机器忙 → 两种做法照样写出，事实写机器忙的原因
- `C-7` 和 A 正在做的 `C-5` 共用 `BR-12` → 事实多一行写共用 `BR-12`
- `C-7` 被认领了 → 这一项消失
- 派出去的 `P1` 的 `C-6` 停滞 → 有 `interrupt:C-6`
- `canon work handled interrupt:C-7 --defer "x" --for 1h`（`C-7` 是 `P0`）→ 退出码 1；`C-6` 是 `P1` 时照常推后
- worker 的议程 → 没有这一项
