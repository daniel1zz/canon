## 规则

一个 `P0` 或 `P1` 的变更（BR-2602）没有进展时，每个主会话的议程判断组第一档有一项 `interrupt:<C-n>`，`canon work watch` 在它出现的那一刻输出一行（BR-2528）。没有进展是指：它可以开始（BR-2571 的可开始状态）而没有活着的认领，或者派出去以后停滞了（BR-2527 的 `stalled`）。`red-main`（BR-2601）对应的是 `P0`，单独成项，不重复成 `interrupt`。

这一项的下一步按会话自己的情况写（D-155）：

- 机器还能派 worker（BR-2526）→ 先 `canon work delegate <C-n> --to <名字>`，不用停下手上的活；
- 不能派，而这个会话认领的变更里有档位比它低的 → 停下其中档位最低的那个（`canon work stop --reason partial --next "<下一步>"`），再 `canon work start <C-n>`；
- 这个会话认领的变更都不比它低 → 这一项照样列出，下一步写由别的会话去做，并写出现在谁认领着什么。

worker 的议程没有这一项。`P1` 的这一项可以按 BR-2583 推后或不处理；`P0` 的不能，和 `red-main` 一样以退出码 1 拒绝。变更有了活着的认领、开始合入、或档位降到 `P2` 以下以后，这一项消失。

## 例子

- 负责人把没人认领的 `C-7` 定为 `P0`，主会话 A 还能派 worker → A 的议程有 `interrupt:C-7`，下一步是 `canon work delegate C-7 --to <名字>`；watch 输出一行
- 同样，A 不能派、认领着 `P2` 的 `C-5` → 下一步是停下 `C-5`、开始 `C-7`
- A 认领的变更是 `P0` 的 `C-8` → 这一项列出，下一步写由别的会话去做
- `C-7` 被认领了 → 这一项消失
- 派出去的 `P1` 的 `C-6` 停滞 → 有 `interrupt:C-6`
- `canon work handled interrupt:C-7 --defer "x" --for 1h`（`C-7` 是 `P0`）→ 退出码 1；`C-6` 是 `P1` 时照常推后
- worker 的议程 → 没有这一项
