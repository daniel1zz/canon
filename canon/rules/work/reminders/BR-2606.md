## 规则

一个 `P0` 或 `P1` 的变更（BR-2602）没有进展时，每个主会话的议程判断组第一档有一项 `interrupt:<C-n>`，`canon work watch` 在它出现的那一刻输出一行（BR-2528）。没有进展是指：它可以开始（BR-2571 的可开始状态）而没有活着的认领，或者派出去以后停滞了（BR-2527 的 `stalled`）。`red-main`（BR-2601）对应的是 `P0`，单独成项，不重复成 `interrupt`。

这一项不写死下一步，写出做法和判断要用的事实，由主 agent 决定（D-156）。项行是 `interrupt:<C-n> <时长> <档位> <标题>: <为什么>; <事实> → <做法>`：

- 为什么：`nobody works on it`（可以开始、没有活着的认领），或 `delegated to <worker>, stalled`；
- 事实，用分号隔开：机器还能派几个，或为什么忙（BR-2581，容量按 BR-2526）；这个会话认领着的变更和档位（`you hold C-5 P2, …`，没有时写 `you hold nothing`）；和正在进行的变更共用的规则（BR-2608）；能派的变更里设计没定的地方（BR-2609）；
- 做法：能派的写 `canon work delegate <C-n> --to <name>, or stop one of yours (canon work stop --reason partial --next "<next>") and canon work start <C-n>`；不能派的（`ready-self`）只写后一种，并写出不能派的原因（同 BR-2607）；停滞的写 `canon work delegate <C-n> --to <name> again, or canon work take <C-n>`。

时长从变更档位最近一次设成 `P0` 或 `P1` 算起；停滞的从停滞开始算（BR-2527 的 `stalled`）。停滞的 `P0` 或 `P1` 变更只有这一项，不再另有 `stalled:<C-n>`。

worker 的议程没有这一项。`P1` 的这一项可以按 BR-2583 推后或不处理；`P0` 的不能，和 `red-main` 一样以退出码 1 拒绝。变更有了活着的认领、开始合入、或档位降到 `P2` 以下以后，这一项消失。

## 例子

- 负责人把没人认领的 `C-7` 定为 `P0`，主会话 A 还能派 2 个、认领着 `P2` 的 `C-5` → A 的议程判断组第一档有 `interrupt:C-7 … P0 …: nobody works on it; room for 2 more; you hold C-5 P2 → canon work delegate C-7 --to <name>, or stop one of yours … and canon work start C-7`；watch 输出一行
- 同样，机器忙 → 事实写忙的原因，做法照样两种
- `C-7` 和 A 正在做的 `C-5` 共用 `BR-12` → 事实多一条 `C-7 shares BR-12 with C-5 (…)`
- `C-7` 是 `ready-self` → 做法只写停下一个再 `canon work start C-7`，带不能派的原因
- `C-7` 被认领了 → 这一项消失
- 派出去的 `P1` 的 `C-6` 停滞 → 有 `interrupt:C-6 … delegated to w1, stalled`，没有 `stalled:C-6`
- `C-6` 是 `P2` 时停滞 → 照 BR-2527 只有 `stalled:C-6`
- `canon work handled interrupt:C-7 --defer "x" --for 1h`（`C-7` 是 `P0`）→ 退出码 1，什么都不记；`C-6` 是 `P1` 时照常推后
- worker 的议程 → 没有这一项
