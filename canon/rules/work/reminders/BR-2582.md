## 规则

议程（BR-2527）在三组之后输出一行正在跑的整组测试：

`heavy: <主题> full test run <已跑时长>[, <主题> full test run <已跑时长>…][; <n> waiting]`

`<主题>` 是变更编号、杂务身份，或后台 floor 的 `main`；已跑时长的写法同 BR-2527。只有排队的、没有在跑的时写 `heavy: none running; <n> waiting`。没有在跑也没有排队的，不输出这一行。

在跑和排队只从事件表读（D-151 单一来源），事件由排队的一方写（`canon work test --all` 和后台 floor），本条只读：

- `test.full.start`：详情含 `subject`（变更编号、杂务身份，后台 floor 为 `null`）、`pid`、`pid_start`；
- `test.full.end`：详情含同样的 `subject`、`pid`、`pid_start`，以及 `duration_ms`、`outcome`；
- `test.full.wait`：详情含 `subject`、`pid`、`pid_start`、`ahead`（前面还有几组）。

**在跑**：一条 `test.full.start`，之后没有 `pid` 和 `pid_start` 都相同的 `test.full.end`，并且这个进程还活着（按 `pid` 和进程启动时间判断，同 BR-2219 判断 watcher 的方法）。开始时间取这条事件的时间。
**排队**：一条 `test.full.wait`，之后没有同一进程的 `test.full.start` 或 `test.full.end`，并且进程还活着。

进程已经不在、却没有写 `test.full.end` 的（被杀掉）不算在跑，也不算排队。

`--json` 的 `heavy` 对象：`running`（每项含 `subject`（`null` 为后台 floor）、`since`）和 `waiting`（数目）。

依据：D-151；F-3 的成功标准 S1。

## 例子

- `C-637` 的 `test.full.start` 在 12 分钟前、进程还活着，另有 2 个进程各写了 `test.full.wait` → `heavy: C-637 full test run 12m; 2 waiting`
- 后台 floor 在跑（`subject` 为 `null`）→ `heavy: main full test run 3m`
- `C-637` 的进程已写 `test.full.end` → 不算在跑
- `C-637` 写了 `test.full.start`，进程被杀，没有 `test.full.end` → 不算在跑，没有 `heavy:` 这一行
- 一个进程写了 `test.full.wait`，后来又写了 `test.full.start` → 只算在跑，不算排队
- 什么都没有 → 没有 `heavy:` 这一行
