## 规则

议程（BR-2527）在三组之后输出一行正在跑的整组测试：

`heavy: <主题> full test run <已跑时长>[, <主题> full test run <已跑时长>…][; <n> waiting]`

已跑时长的写法同 BR-2527。只有排队的、没有在跑的时写 `heavy: none running; <n> waiting`。

负载队列（BR-2630）里有在等的重步骤时，这一行末尾再加 `; <m> waiting for the load (<主题> <步骤种类> <已等时长>[, …])`，步骤种类是 `test`、`land`、`floor`、`heavy-run`，主题写法同 BR-2630（别的仓库的带上 worktree 路径），最多列 5 个，多的写 `… +<k>`；只有等负载的、没有整组测试在跑或排队时写 `heavy: none running; <m> waiting for the load (…)`。整组测试、等负载的步骤都没有时，不输出这一行。

在跑和排队读整台机器的整组测试队列（BR-2576、BR-2577）：每一项按下面三种之一算：拿到名额、也过了负载关（BR-2630）的是**在跑**，开始时间取它过关的时间；拿到名额、还在负载队列里的是**等负载**，只列在下面等负载的那一组，不算在跑；还没拿到名额的是**排队**。BR-2581 数“正在跑的整组测试”只数在跑的。队列覆盖这台机器上所有用 canon 的仓库，所以别的仓库的整组测试也算（它们同样占用这台机器）。进程已经不在的队列项不算在跑，也不算排队；读的一方只看不删（删由排队的一方按 BR-2577 做）。整组测试写的 `test.full.wait`、`test.full.start`、`test.full.end` 事件（BR-2576）留给历史和统计，议程不从事件推算。

`<主题>` 取队列项的变更或杂务编号，main 的后台 floor 写 `main`。

`--json` 的 `heavy` 对象：`running`（每项含 `subject`（后台 floor 为 `main`）、`since`）、`waiting`（数目）和 `load_waiting`（每项含 `subject`、`kind`、`since`，按队列顺序）。负载队列和整组测试队列一样只读不删。

依据：D-151；F-3 的成功标准 S1。

## 例子

- `C-637` 12 分钟前拿到名额、进程还活着，另有 2 组在排队 → `heavy: C-637 full test run 12m; 2 waiting`
- 后台 floor 在跑（队列项没有变更编号）→ `heavy: main full test run 3m`
- `C-637` 跑完、队列项已删 → 不算在跑
- `C-637` 的进程被杀，队列项还在 → 不算在跑；没有别的时没有 `heavy:` 这一行
- 只有排队的、没有在跑的 → `heavy: none running; 2 waiting`
- 另一个仓库的整组测试在跑 → 也列出，算进 BR-2581 的容量
- 什么都没有 → 没有 `heavy:` 这一行
- 负载 17.0，`C-9` 的 `canon work test` 等了 4 分钟、`C-10` 的合入等了 1 分钟，没有整组测试 → `heavy: none running; 2 waiting for the load (C-9 test 4m, C-10 land 1m)`
- `C-9` 拿到整组测试名额后在等负载 → 不写成 `C-9 full test run`，写在 `waiting for the load (C-9 test …)` 里
