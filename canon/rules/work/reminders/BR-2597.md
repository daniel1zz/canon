status: active

## 规则

主会话的议程（BR-2527）的判断组，对每个满足下面两条的已接受（`accepted`）决策有一项，只提醒，不挡任何工作（D-154）：

- 没有一条现行规则（`active` 或 `planned`）在正文里点名它（反引号和代码块里的不算）；
- 它的 `## 决定` 里至少有一条没点名任何规则的条目，条目的切法和“没点名”的算法同 BR-2471。

这一项：

- 键 `commitments:<D-n>`，种类 `commitments`，同种类在同一行里折叠（BR-2527），排在判断组的第三档；开始的时间不记（`-`）；
- 摘要写这样的条目有几条，以及第一条的开头；下一步是给它许下的行为写点名这个决策的规则（还没做的写 `status: planned`），或者核对后用 `canon work handled commitments:<D-n> --not-doing "<为什么不涉及产品行为>"` 记下结论（BR-2583）。

提议中（`proposed`）和已被取代（`superseded`）的决策不进；worker 的议程没有这一项。哪些决策符合条件由 `knowledge/check` 算出，议程不自己再算。

## 例子

- 已接受的 `D-265`，没有规则点名它，`决定` 第 3 条没写规则编号 → 判断组有 `commitments:D-265`，摘要说 1 条，带这条的开头
- 同一个 `D-265`，有一条 `status: planned` 的规则正文写了“按 D-265” → 不在议程里
- 规则只在反引号里写了 `` `D-265` `` → 仍在议程里
- 已接受的 `D-7`，没有规则点名它，但 `决定` 每条都写了规则编号 → 不在议程里
- `D-8` 是 `proposed` 或 `superseded` → 不在议程里
- 对 `commitments:D-265` 记了 `--not-doing "只定流程，不涉及产品行为"` → 不再出现
- worker 的 `canon work due` → 没有 commitments 项
