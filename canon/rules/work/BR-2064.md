---
id: BR-2064
title: 放弃一个不会丢工作的变更时直接删除它的 worktree 和分支
status: active
---

## 规则

`canon work drop <C-n>` 放弃一个变更正在进行的工作：删除它在 worktree 目录（BR-2047）下的 worktree、它的变更分支、认领和 handoff，写一条 `drop.done` 事件，退出码 0。不会丢任何东西时直接删除：分支上没有不在 main 上的提交，worktree 没有未提交的改动、也没有不能重新生成的被 git 忽略的文件（按 `regenerable` 判断，见 BR-2019）；会丢东西时先存档（BR-2102）。检查按这个顺序进行，前一项不通过就不再看后面的：在要删除的 worktree 里执行时退出码 2；既没有 worktree 也没有分支时退出码 3；别的操作者持有有效的认领（租约没到期，且记下的会话进程还在，BR-2100）时什么都不删，写一条原因为 `claimed` 的 `drop.refuse` 事件，退出码 5；有别的进程把当前目录放在这个 worktree 里时什么都不删，写一条原因为 `in-use` 的 `drop.refuse` 事件，退出码 5，提示写明 pid 和命令名；查不出有哪些进程时什么都不删，退出码 4。认领和进程的检查在存档之前，所以这两种情况下不存档。认领检查通过时，drop 在同一个事务里占住这个变更的认领，一直到删除结束（失败时放开，并恢复原来的认领记录）；这期间对它的 `canon work start` 以退出码 5 被拒。变更文件的状态不改；它在 main 上仍是 open 时，提示用 `canon change drop` 标记。

## 例子

- `C-1` 已经全部合入，worktree 干净 → 直接删除 worktree 和分支，不存档，退出码 0
- 只剩分支 `change/C-2`，上面的提交都已在 main 上 → 删除分支，退出码 0
- `C-3` 已全部合入，worktree 里只有被忽略的 `node_modules/` → 直接删除，不存档，退出码 0
- `C-4` 已全部合入，worktree 里有被忽略的 `.env` → `.env` 算会丢的东西，先存档再删除（BR-2102）
- `agent:b` 持有 `C-1` 的有效认领，`agent:a` 执行 `canon work drop C-1` → 不删除、不存档，退出码 5
- `agent:b` 认领 `C-1` 的租约没到期，但记下的会话进程已经不在 → 不算有效认领，照常放弃（会丢的东西先存档）
- pid 4242 的 `sleep` 当前目录在 `C-1` 的 worktree 里 → 不删除，退出码 5，提示写明 `pid 4242 (sleep)`
- `C-5` 有没合入的提交，同时 pid 4242 在它的 worktree 里 → 不存档、不删除，退出码 5
- `canon work drop C-1` 正在存档时，另一个会话执行 `canon work start C-1` → 退出码 5，drop 照常完成
- 列不出进程（`lsof` 执行失败）→ 不删除，退出码 4
- 在 `C-1` 自己的 worktree 里执行 `canon work drop C-1` → 退出码 2（调用它的 shell 就在这个 worktree 里，所以这项检查在进程检查之前）
- `canon work drop C-99`，没有对应的 worktree 和分支 → 退出码 3
