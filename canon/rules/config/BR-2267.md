---
id: BR-2267
title: setup 和 hook 命令拿到变更的端口 CANON_PORT，同一变更不变，进行中的两个变更不同
status: active
---

## 规则

`canon/config.yaml` 设了 `ports`（BR-2268）时，`canon work start` 跑的 `setup` 命令和每条 hook 命令（事件是关于某个变更的：`after_start`、`before_land`、`after_land`、`after_stop`）的环境里有 `CANON_PORT`，值是这个变更的端口（D-41）：在范围内；同一个变更每次都是同一个值（停下再开始、跑不同事件的 hook 都一样），只要 `ports` 没改；两个变更的 worktree 都还在时，它们的端口不同，几个 `canon work start` 同时运行也一样。一个变更的 worktree 被清理或放弃之后，它的端口可以分给别的变更。没设 `ports`，或者事件不关于任何变更（`after_green`）时，`CANON_PORT` 是空字符串；事件没有要运行的命令时不分配。运行 canon 的进程环境里原有的 `CANON_PORT` 不会传下去（BR-2199：同名时 canon 设的值优先）。端口记录的 worktree 不在范围内（`ports` 改过）时，这个变更重新分配。

## 例子

- `ports: 4100-4199`，`setup: 'echo "$CANON_PORT" > port.txt'`，新开第一个变更 → `port.txt` 是 `4100`；再开一个 → 新 worktree 的 `port.txt` 是 `4101`
- 同样配置，`after_start` 和 `after_stop` 都写 `echo "$CANON_PORT" >> ports.txt`，开始、停下、再开始同一个变更 → 三行都是同一个值
- `ports: 4100-4199`，8 个进程同时 `canon work start --title "T<i>"` → 8 个都成功，`setup` 写出的 8 个端口两两不同，都在 4100 到 4199 之间
- `ports: 4100-4101`，开 C-1（4100）、C-2（4101），`canon work clean C-1` 删掉 C-1 的 worktree 之后开 C-3 → C-3 拿到 4100
- 没设 `ports`，运行 canon 的环境里有 `CANON_PORT=9999`，`setup: 'echo "[$CANON_PORT]" > port.txt'` → `port.txt` 是 `[]`
- C-1 在 `ports: 4100-4199` 下拿到 4100，之后配置改成 `ports: 5000-5099` → C-1 下一次的 hook 拿到 5000
