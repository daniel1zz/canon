title: canon brief 和 canon config 把 schema 写进被 git 忽略的 .canon 目录
status: active

## 规则

`canon brief` 和 `canon config` 在当前 checkout 的根目录写 `.canon/config.schema.json`，内容就是 `canon config --schema` 的输出；内容没变时不重写，写入是先写临时文件再改名，并发的会话不会读到写了一半的文件。写之前确认 git 公共目录的 `info/exclude` 里有 `/.canon/`，没有就在末尾追加一行：只追加、不重写整个文件，所以别的程序同时读到的不会是空文件，别人刚加的行也不会丢；两个会话同时追加可能留下两行 `/.canon/`，没有害处。所以这个目录不会让任何 worktree 变脏，也不会被提交。schema 文件不提交，是因为它由当前运行的 canon 生成：提交它就要拿合入时的旧版 canon 判断它是否过期，新加配置项的变更会被判成过期而合不进去（D-28）。

清理或放弃 worktree 时，`.canon` 目录总算作可以重建的文件，不算工作，不管配置的 `regenerable` 怎么写（BR-2019）。

写不了（比如目录只读）时，`canon brief` 输出一行说明原因，其余照常；`canon config` 同样输出一行说明，列表照常输出，退出码不变。

## 例子

- 新 clone 里第一次运行 `canon brief` → 出现 `.canon/config.schema.json`，`.git/info/exclude` 多一行 `/.canon/`，`git status --porcelain` 为空
- 再运行一次 `canon brief` → exclude 里仍只有一行 `/.canon/`，文件内容不变
- `info/exclude` 原来是 `.env`（末尾没有换行）→ 变成 `.env`、`/.canon/` 两行，原来的行原样保留
- 在变更 worktree 里运行 `canon brief` 后 `canon work land` → 不因 `.canon` 报 dirty
- `regenerable: [node_modules]`（不含 `.canon`）时 `canon work clean` 一个只有 `.canon/config.schema.json` 这个忽略文件的 worktree → 照常删除，不报“不能重建的忽略文件”
- `.canon` 是一个普通文件、建不了目录 → `canon brief` 输出一行 `cannot write .canon/config.schema.json: ...`，退出码 0
