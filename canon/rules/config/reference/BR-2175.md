## 规则

`canon config --schema` 向标准输出打印 `canon/config.yaml` 的 JSON Schema（draft-07）：顶层是对象，不允许未知键，每个配置项一个属性，带它的说明，有默认值的带文件写法的默认值；`shared` 要求同时有 `code_root`。

canon 读配置时接受的值，schema 一定也接受，编辑器不会把有效配置标红。canon 拒绝的值，schema 尽量也拒绝；只有 schema 表达不了的检查例外，这些只有 canon 读配置时（例如 `canon config`）才报：命令指向的脚本不存在、`shared` 的路径必须在 `code_root` 下、`check_reviews` 的日期必须真实存在（`2026-02-30` 格式对但不存在）、`types` 之间编号前缀和目录不能重复以及内置类型能改哪些字段、模板缺必需段落。

## 例子

- `{"floor": "bun test", "land_batch_max": 4}` → schema 接受，canon 也接受
- `{"bogus": 1}` → schema 拒绝（未知键），canon 也拒绝
- `{"land_batch_max": 0}`、`{"claim_lease_hours": -1}`、`{"test_command": "bun test"}`（没有 `{file}`）、`{"floor_skip_paths": ["canon/templates/x.md"]}` → schema 和 canon 都拒绝
- `{"shared": ["src/kernel"]}`（没有 `code_root`）→ schema 和 canon 都拒绝
- `{"code_root": "src", "shared": ["lib/x"]}` → canon 拒绝（不在 `code_root` 下），schema 接受：表达不了的例外
- `{"check_reviews": {"floor": "2026-02-30"}}` → canon 拒绝，schema 接受（格式对）；`{"check_reviews": {"floor": "tomorrow"}}` → 两者都拒绝
- 每个配置项在 schema 里有 `description`，等于 `canon config` 显示的说明
