title: 最近一次合入的后台命令有失败时，canon brief 提示一行
status: active
---

## 规则

最近一次合入（按合入排队的顺序，不按事件写入的先后）在后台运行的那批 `after_land` 命令里，有已结束且退出码不为 0 的命令时，`canon brief` 输出一行，写明变更编号、失败的命令和退出码、日志路径；不论当前目录是不是一个变更的 worktree。这批命令里没有已结束且失败的（全部以 0 结束，或还没结束），或者更早一批有失败而最近一批没有时，不输出这一行。日志文件不见了时，输出一行说明退出码无法得知，并给出路径。

## 例子

- 最近一次合入的 `bun run build` 以 1 退出 → `canon brief` 输出 `after_land after C-5 failed in the background: \`bun run build\` exited 1 (log: .../after-land-12.log)` 这样的一行
- 上一次合入失败，最近一次合入的命令全部以 0 结束 → 不输出
- 最近一次合入的命令还在运行 → 不输出
- 最近一次合入的日志被删掉 → 输出一行，说明退出码无法得知并给出路径
- 最近一次合入的第一条命令以 2 退出，第二条还在运行 → 输出，只列出第一条
- 排队在后的合入 11 先写下它的后台命令记录（以 1 退出），排队在前的合入 10 之后才写（以 0 退出）→ 输出合入 11 的失败
