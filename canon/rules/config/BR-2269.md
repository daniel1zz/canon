id: BR-2269
title: 范围里的端口都被进行中的变更占着时，开始变更被拒，hook 当作失败
status: active
---

## 规则

一个变更要分配端口（BR-2267），而 `ports` 范围里每个端口都分给了 worktree 还在的其他变更时，不分配、不重复使用已分配的端口，而是明确失败（D-41）：`canon work start` 以退出码 5 失败，信息列出范围和占着端口的变更、提示清理不用的 worktree 或把范围设大；刚为它建的 worktree 和分支撤回、认领释放（和 `setup` 失败时一样，BR-2029），已经存在的 worktree 不动、只释放认领；`setup` 和 `after_start` 不运行。hook 事件要分配时，这个事件的命令都不运行，这次运行当作 hook 失败：前台的事件记一条 `hook.run` 事件（`exit` 为 1，带 `port` 的说明），后台的 `after_land` 每条命令在日志里写明原因、退出码记为 1，由 `canon work after-land` 和 `canon brief` 照常报出（BR-2137、BR-2166）；`before_land` 因此拒绝合入（BR-2057），其他事件结果不变（BR-2056、BR-2058）。

## 例子

- `ports: 4100-4101`，C-1、C-2 的 worktree 都在，`canon work start --title "C"` → 退出码 5，信息里有 `4100-4101`、`C-1` 和 `C-2`，没有新的 worktree 和认领
- 同样情形，先 `canon work clean C-1` 再开 → 成功，拿到 4100
- `ports: 4100-4100`，C-1 拿到 4100；C-2 是 `ports` 配置之前就开始的、还没有端口，C-2 合入时要跑 `before_land` → 合入被拒（退出码 1），`before_land` 的命令没有运行
- 同样情形，C-2 `canon work stop` → 停下照常成功，`after_stop` 的命令没有运行，输出里写明没有空闲端口
