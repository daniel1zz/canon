id: BR-2269
title: 范围里没有能分配的端口时，开始变更被拒
status: active
---

## 规则

`canon work start` 要为变更分配端口（BR-2267），而 `ports` 范围里没有能分配的端口（每个端口要么分给了 worktree 还在的其他变更，要么被 canon 以外的程序占着，BR-2288）时，不分配、不重复使用已分配的端口，而是明确失败（D-41）：`canon work start` 以退出码 5 失败，信息列出范围、占着端口的变更和被别的程序占着的端口、提示清理不用的 worktree、停掉占着端口的程序或把范围设大；刚为它建的 worktree 和分支撤回、认领释放（和 `setup` 失败时一样，BR-2029），已经存在的 worktree 不动、只释放认领；`setup` 和 `after_start` 不运行；事件表记一条 `start.refuse`，原因是 `port`（BR-2026）。设了 `ports` 时不管有没有配 `setup` 和 hook 命令，开始变更都要分配，范围用完照样被拒。hook 分不到端口时不拒绝什么，见 BR-2287。

## 例子

- `ports: 4100-4101`，C-1、C-2 的 worktree 都在，`canon work start --title "C"` → 退出码 5，信息里有 `4100-4101`、`C-1` 和 `C-2`，没有新的 worktree 和认领，事件表里有 `start.refuse`，原因 `port`
- 同样情形，先 `canon work clean C-1` 再开 → 成功，拿到 4100
- `ports: 4100-4101`，只设了 `ports`，没有 `setup`，也没有任何 hook 命令，C-1、C-2 的 worktree 都在 → 开第三个变更照样以退出码 5 被拒
