## 规则

canon 的常驻规则是源头里的 `canon-*.md` 文件：canon 仓库里在 `.claude/rules/`，npm 包里在包的 `.claude/rules/`，发布的 `dist/skills` 里在它指向的目录下的 `.rules/`（发布时和 skill 一起复制进去，同一次切换链接）。选了 Claude 目标（BR-2459）时，`canon init`、`canon install`、`canon update` 把它们复制进项目的 `.claude/rules/`，并写一份清单 `.claude/rules/.canon-rules.json`（每个文件的哈希），和 skill 的安装同样处理（D-167）：

- 项目里的文件还是 canon 上次写的样子才替换；改过的按 BR-2081 拒绝整次安装（`--force` 覆盖），canon 没有新内容时保留本地改动（BR-2089）；源头不再有的、没改过的文件删掉。
- 在 canon 自己的仓库里（BR-2080 的认法），不写规则文件。
- 这个 canon 的源头没有规则目录（比它早的发布）时，不碰规则，也不删已经装的。
- `canon update --check` 把要更新的规则列成 `rule .claude/rules/<文件>`。
- `canon uninstall` 删掉清单列出、没改过的规则文件和清单；改过的按 BR-2279 拒绝（`--force` 也删）。

只处理 `canon-` 开头的规则文件；项目自己的别的规则文件不动。Codex 目标不装规则。

## 例子

- 在新项目执行 `canon init` → 出现 `.claude/rules/canon-behavior.md` 等文件和 `.claude/rules/.canon-rules.json`
- 项目里改过 `.claude/rules/canon-behavior.md`，canon 也更新了它，执行 `canon install` → 退出码 5，什么都不写；加 `--force` → 覆盖
- 项目自己有 `.claude/rules/team.md` → 安装、更新、卸载都不碰它
- 在 canon 自己的仓库里执行 `canon install` → 不写规则文件
- 用一个源头没有规则目录的旧版 canon 执行 `canon update` → 已经装的规则不变
