## 规则

目标的选择与路径映射按 BR-2459；下文的 .claude 路径和 Claude 专用设置仅用于 Claude 目标，Codex 的原生入口和管理段按 BR-2459、BR-2460。

在 main 分支上还有 `canon/config.yaml` 的项目里（看 main 这个分支，不看工作区：被守卫拒绝的 `git pull` 会让工作区领先于 main），`canon uninstall`（检查都通过后）先在配了 `remote` 时同步 main（同 `canon sync`，分叉时以退出码 5 拒绝），然后按 BR-2457 开一个杂务，在它的 worktree 里删掉：清单 `.claude/skills/.canon-skills.json` 记下的、内容仍和清单一致的 skill 文件，清单本身，因此变空的 `canon-*` 目录，`.claude/settings.json` 里 canon 的条目（SessionStart 的 `canon brief` 两种形式、PreToolUse 的快照条目和检查 `--as` 的条目（BR-2343）、PostToolUse 的提问记录条目和编辑后的复述提示条目（BR-2404）、canon 撤回的条目，BR-2130），以及 `canon/config.yaml`；提交后按 BR-2458 合入，不创建 Change 文档。首次合入使用删除前读到的配置；跨进程重试从 main 当前已合入的配置读取 floor 等要求，读取失败明确报错，不使用缺文件时的默认值。删除配置的合入按 BR-2172 不拼批。`settings.json` 里其余内容原样保留，`worktree.baseRef` 也保留并在输出里说明；某个条目、列表或对象因为删掉 canon 的项而变空时一起删掉，整个文件变成 `{}` 时删掉文件。合入被拒以退出码 1、排队超时以 75 结束，本地什么都不清理。合入成功后同一次运行接着做本地清理（BR-2280）。

## 例子

- 装着 canon、`floor: "true"`、没有进行中的工作 → 退出码 0；main 上没有 `canon/config.yaml`、`.claude/skills/canon-*` 和清单；`.claude/settings.json` 只剩 `{"worktree": {"baseRef": "head"}}`；`canon/rules` 等文档还在
- `settings.json` 里还有项目自己的 `PreToolUse` 条目 `{"matcher": "Edit", ...}` → 卸载后这个条目还在，canon 的快照条目和 check-as 条目没了
- `floor` 命令失败 → 退出码 1，main 上仍有 `canon/config.yaml`，git 守卫还在
- 被拒后在另一个进程重试 `canon chore land` → 仍执行 main 当前配置的 `floor`，不用缺文件时的默认配置
- 重试时读不出 main 的配置 → 退出码 4，什么也不合入
- 这次合入排队时前面有领头在取成员 → 按 BR-2172 不进那一批，单独合入

- 只安装 Codex 目标，`.codex/hooks.json` 还有用户 hook、`AGENTS.md` 还有用户文字 → 卸载合入后按 BR-2459、BR-2460 移除原样技能和清单、Canon hook 与管理段，保留用户 hook、文字和用户技能。
