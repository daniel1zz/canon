## 规则

`canon update` 开的变更（BR-2086）由它自己写好：标题是 `更新 canon 装进项目的文件到版本 <版本>`；变更文件的 `## 为什么` 是一句固定说明（项目里 canon 装的文件落后于当前的 canon，按负责人的要求更新），`## 要改什么` 每个过期项一行 `- <项>`，和 `canon update --check` 列出的一样，`## 教训` 是 `无。`，`## 任务` 是勾上的 `由 canon update 安装并合入`；提交信息是 `Update canon project files to <版本> (C-n)`。`<版本>` 是 BR-2084 的版本号。

## 例子

- canon 更新了 `canon-a/SKILL.md`，执行 `canon update` → main 上的变更文件标题是 `更新 canon 装进项目的文件到版本 <版本>`，`## 要改什么` 只有一行 `- skill canon-a/SKILL.md`；那次提交的信息是 `Update canon project files to <版本> (C-n)`
- 同时缺少会话 hook → `## 要改什么` 另有一行 `- hook: canon brief at session start (.claude/settings.json)`
- `.claude/settings.json` 是 `{}`（五个 hook 和 `worktree.baseRef` 都缺）→ 另有六行：`- hook: canon brief at session start (.claude/settings.json)`、`- hook: canon snapshot take before each Bash call (.claude/settings.json)`（BR-2185）、`- hook: canon work check-as before each Bash call (.claude/settings.json)`（BR-2343）、`- hook: canon human record after each answer to the question tool (.claude/settings.json)`（BR-2274）、`- hook: canon restatements --hook after each Write or Edit (.claude/settings.json)`（BR-2404）和 `- setting: worktree.baseRef "head", so subagent worktrees start from local HEAD (.claude/settings.json)`（BR-2264）
