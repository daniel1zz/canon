---
id: BR-2130
title: canon install 和 canon update 移除 canon 撤回的 PreToolUse hook 和放行规则
status: active
---

## 规则

C-91 曾往项目的 `.claude/settings.json` 里装过两项，D-18 撤回了它们：`hooks.PreToolUse` 里命令以 `canon hook pre-bash` 开头的 hook，和 `permissions.allow` 里的 `Bash(export CANON_ACTOR='agent:*')`。文件里还有其中任何一项时，`canon update --check` 把它列为过期，每项一行，原样是 `hook: canon hook pre-bash before each Bash call, withdrawn by canon; install or update removes it (.claude/settings.json)` 和 `permission: Bash(export CANON_ACTOR='agent:*'), withdrawn by canon; install or update removes it (.claude/settings.json)`，退出码 1；`canon init`、`canon install`、`canon update` 在合并会话 hook（BR-2087）的同一次写入里删掉它们。只删这两项：同一个 PreToolUse 条目里的其他 hook、别的条目、别的放行规则和其余设置都原样保留；一个条目、`PreToolUse` 列表、`allow` 列表或 `permissions` 对象因为删掉它们而变空时，一起删掉，原来就是空的不动（同一次写入随后还会往 `PreToolUse` 里加快照条目和检查 `--as` 的条目，BR-2185、BR-2343；后者的命令是 `canon work check-as`，不以撤回的前缀开头，不会被删）。`permissions` 不是对象或 `allow` 不是列表时，不当作有撤回的放行规则，也不改它。

## 例子

- `.claude/settings.json` 里有 SessionStart 的 `canon brief || echo ...`、PreToolUse 里只有 `matcher: "Bash"` 的 `canon hook pre-bash 2>/dev/null || true`、`allow` 里只有那条放行规则 → `canon update --check` 退出码 1，列出两项 `withdrawn by canon`；`canon install` 后文件里没有 `permissions`，`PreToolUse` 只剩 canon 的快照条目（BR-2185），SessionStart 不变；再 `canon update --check` → 退出码 0
- `allow` 是 `["Bash(ls)", "Bash(export CANON_ACTOR='agent:*')"]`，PreToolUse 的 `Bash` 条目里还有一条 `echo pre` → `canon install` 后 `allow` 是 `["Bash(ls)"]`，那个条目只剩 `echo pre`
- `allow` 里是 `Bash(export CANON_ACTOR='agent:x')`（不是 canon 写的那一条）→ 不算过期，不删
- 原来就有 `permissions: { allow: [] }`，没有撤回的项 → `canon install` 后仍是 `{ allow: [] }`
- 原来就有 `PreToolUse: []`，`allow` 是 `["Bash(ls)", "Bash(export CANON_ACTOR='agent:*')"]` → `canon install` 时这个空列表不因删除而被去掉，同一次写入再加入快照条目，结果 `PreToolUse` 只有快照条目，`allow` 是 `["Bash(ls)"]`
