## 规则

已退役：canon 不再给子 agent 注入执行者，`canon hook pre-bash` 已删除（D-18）。以下是退役前的内容。

`canon hook pre-bash` 从 stdin 读 Claude Code 的 PreToolUse 输入（JSON）。输入里有 `agent_id`（只在子 agent 里出现，D-17）、`agent_id` 只由字母、数字、`_`、`-` 组成、`session_id` 的前 8 个字符也是这样、`tool_input.command` 是字符串、`tool_name` 缺省或为 `Bash` 时，它在 stdout 输出一个 JSON：`hookSpecificOutput.hookEventName` 是 `PreToolUse`，`hookSpecificOutput.updatedInput` 是原样的 `tool_input`，只有 `command` 换成 `export CANON_ACTOR='agent:<session_id 前 8 个字符>:<agent_id>'`、一个换行、再接原来的命令（一个字节都不改）。输出里没有 `permissionDecision`，也没有别的字段。其余情况（主会话没有 `agent_id`、输入不是合法 JSON、字段不合要求、命令已经以同一行开头）什么都不输出。任何情况下退出码都是 0，内部出错只写 stderr。

## 例子

- `{"session_id":"3d606482-8b99","agent_id":"add88b47cf722ff32","tool_name":"Bash","tool_input":{"command":"ls\necho 'q'","timeout":5000}}` → 输出的 `updatedInput` 是 `{"command":"export CANON_ACTOR='agent:3d606482:add88b47cf722ff32'\nls\necho 'q'","timeout":5000}`，退出码 0，没有 `permissionDecision`
- 同样的输入去掉 `agent_id`（主会话）→ 什么都不输出，退出码 0
- `agent_id` 是 `a';rm -rf x` → 什么都不输出，退出码 0
- stdin 是 `not json` → 什么都不输出，退出码 0
- `tool_name` 是 `Read` → 什么都不输出
- 命令已经以 `export CANON_ACTOR='agent:3d606482:add88b47cf722ff32'` 加换行开头（hook 配了两次）→ 什么都不输出
