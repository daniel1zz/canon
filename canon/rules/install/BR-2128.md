## 规则

已退役：canon 不再装这个 hook 和放行规则（放行规则过宽，issue #26），已装的由 `canon install`、`canon update` 删掉（D-18、BR-2130）。以下是退役前的内容。

`canon init`、`canon install`、`canon update` 往项目的 `.claude/settings.json` 里合并两项，和会话 hook（BR-2087）在同一次写入里：`hooks.PreToolUse` 里一条 `matcher` 为 `Bash` 的条目，命令是 `canon hook pre-bash 2>/dev/null || true`（canon 不在 PATH 上或失败时什么都不输出、以 0 结束，Bash 调用照常运行）；`permissions.allow` 里一条 `Bash(export CANON_ACTOR='agent:*')`，只放行这个 hook 加在命令前面的那一行（Claude Code 把命令按换行拆开、每一行单独核对权限，所以它不放行后面的命令）。文件里的其他内容原样保留，已有的不重复添加；`matcher` 为 `Bash` 的条目里已有以 `canon hook pre-bash` 开头、但不是当前形式的命令时，`canon update --check` 把它列为 `older form`，安装时原地改成当前形式。`permissions` 不是对象或 `permissions.allow` 不是列表时，和不合法的 JSON、符号链接一样以退出码 2 拒绝，什么也不写。

## 例子

- 已有 `permissions.allow: ["Bash(ls)"]` 和一条 `matcher: "Bash"` 的 PreToolUse hook `echo pre` 的项目执行 `canon init` → `allow` 是 `["Bash(ls)", "Bash(export CANON_ACTOR='agent:*')"]`，PreToolUse 是 `echo pre` 的条目和 canon 的条目两条
- 再执行 `canon install` → 不变
- `.claude/settings.json` 里只有 SessionStart 的 `canon brief || echo ...` → `canon update --check` 退出码 1，列出 `hook: canon hook pre-bash before each Bash call` 和 `permission: the CANON_ACTOR export line`
- PreToolUse 里有 `canon hook pre-bash`（不带 `|| true`）→ `--check` 列出 `older form`；`canon install` 后只有一条，是当前形式
- `permissions` 是 `"all"` → `canon install` 退出码 2，文件不变
- PATH 上没有 canon 时用 shell 执行这条命令，stdin 是子 agent 的输入 → 退出码 0，stdout 为空
