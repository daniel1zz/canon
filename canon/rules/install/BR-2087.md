## 规则

本条只适用于按 BR-2459 选中的 Claude 目标。

canon 往项目的 `.claude/settings.json` 里合并一条 SessionStart hook，命令是 `canon brief || echo '...'`：`canon brief` 失败或 canon 不在 PATH 上时，echo 输出一段说明（这个项目用 canon、不要直接改 main、修好或装上 canon 后运行 `canon brief`），整条命令仍以 0 结束，让会话看得到它。文件里的其他内容原样保留，已经有这条 hook 时不重复添加；已有旧形式的 hook（命令只是 `canon brief`）时，`canon update --check` 把它列为过期，`canon install`、`canon update` 把那条命令原地改成新形式，不会出现两条。canon 只管这一条、PreToolUse 里的快照条目（BR-2185）和检查 `--as` 的条目（BR-2343）、PostToolUse 里记录提问工具回答的条目（BR-2274）、编辑后的复述提示条目（BR-2404）和 `worktree.baseRef`（BR-2264），以及删掉 BR-2130 说的两项撤回的条目，不改别的设置；文件不是合法 JSON、其中的 `worktree` 不是 JSON 对象（BR-2264），或者 `.claude`、`.claude/settings.json` 是符号链接（包括指向不存在的位置的链接）时，以退出码 2 拒绝，什么也不写。这条 hook 只输出信息，不拦截任何操作。

## 例子

- 已有 `permissions` 和另一条 SessionStart hook `echo hi` 的项目执行 `canon init` → `permissions` 不变，SessionStart 是 `echo hi` 和 `canon brief || echo ...` 两条
- 再执行 `canon install` → 仍是两条
- `.claude/settings.json` 内容是 `{ not json` → `canon install` 退出码 2；`canon init` 也是退出码 2，`.claude/skills` 和 `canon/` 都没有出现
- `.claude/settings.json` 是指向项目外一个还不存在的文件的链接 → `canon install` 退出码 2，项目外不会出现这个文件
- SessionStart 里有旧的 `canon brief` → `canon update --check` 退出码 1，列出 `older form`；`canon install` 后只有一条，命令是新形式；再 `canon install` → 不变
- PATH 上没有 canon 时用 shell 执行这条 hook 的命令 → 退出码 0，输出里有 `canon is not on PATH`
- PATH 上的 `canon brief` 失败（退出码 2）→ 整条命令退出码 0，输出里先是 `canon brief` 自己的 stdout，再是 echo 的说明
