## 规则

main 上没有 `canon/config.yaml`（刚合入的卸载，或别的克隆合入、本克隆已同步到的卸载）时，`canon uninstall` 只清理本仓库里不进版本库的 canon 的东西：第二行是 canon 标识的 `reference-transaction` hook（任何版本；别人写的不动）、按 BR-2019 能安全删掉的 change worktree 和已合入 main 的 `change/*` 分支、`<git 公共目录>/canon/`、`.canon/` 目录和 `.git/info/exclude` 里的 `/.canon/` 一行（BR-2305 写的 `/.claude/worktrees/` 一行不删：它忽略的是 Claude Code 的子 agent worktree，和 canon 装不装无关）、`refs/canon/*` 里除 `archive/` 和 `snapshots/` 以外的 ref。先按顺序找到要看的分支：工作区里还有 `canon/config.yaml` 时用它写的 `main`，否则用 canon 守卫里写的分支，再否则用当前分支；然后从这个分支上删除 `canon/config.yaml` 之前的那份配置读出 `main` 和 `worktrees`，清理时一律用这份配置里的值。还有活着的认领、或会丢工作而删不掉的 worktree 或分支时，删完能安全删掉的 worktree 和分支之后就停下：每项一行列出原因，以退出码 5 结束，协调数据库目录、`refs/canon/*`、`.canon/` 都不删，`--remove-knowledge` 也不做，这样还在工作的会话保有它的认领，下一次运行仍能看到它（#105）。什么都没有可清理时说 `canon is not installed here` 并以退出码 0 结束；再运行一次结果相同。

## 例子

- 卸载合入之后 → git hook 目录里没有 `reference-transaction`，`.git/canon/` 不存在，`git for-each-ref refs/canon/green` 为空，在 main 上直接 `git commit` 成功
- hook 目录里的 `reference-transaction` 是 lefthook 写的 → 原样保留，输出里说明没动它
- `.git/info/exclude` 里有 `/.canon/` 和 `/.claude/worktrees/` 两行 → 卸载后只剩 `/.claude/worktrees/`
- 刚卸载完再运行一次 → 退出码 0，`canon is not installed here`
- 别的克隆：`git pull` 拿到卸载提交后运行 `canon uninstall` → 只做本地清理，不开变更
- 工作区里没有 `canon/config.yaml`，守卫守的是 `trunk`，当前签出的是 `side` → 看 `trunk` 上删除前的配置，清理按其中的 `main: trunk` 判断哪些分支已合入
- 本克隆用 `canon sync` 拿到别的克隆合入的卸载，但本克隆里 C-2 还被一个会话认领着 → 退出码 5，列出 `C-2`，`.git/canon/` 还在，C-2 的认领还在
- 本克隆 C-3 的 worktree 没有认领，但有一个没合入 main 的提交 → 退出码 5，列出 `C-3` 和“commit(s) not on main”，C-3 的 worktree 和分支都还在，`.git/canon/` 也还在
