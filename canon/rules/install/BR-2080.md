## 规则

`canon init`、`canon install` 和 `canon update` 把 canon 自带的每个 `canon-*` skill 复制到当前项目的 `.claude/skills/` 下，并写一份清单 `.claude/skills/.canon-skills.json`（每个文件的哈希），再把会话 hook 合并进 `.claude/settings.json`（BR-2087），提示把它们和项目一起提交；还把 main 的 git 守卫写进仓库的 hook 目录（BR-2123，不在提交里）；只装 `canon-` 开头的 skill，不写用户主目录下的任何东西。`canon init` 对已有的 skill 副本和 `canon install` 一样处理（BR-2081），并且在写其他任何文件之前完成，所以 skill 冲突时 `canon init` 什么也不写。在 canon 自己的仓库里（skill 的源头所在的 git 仓库，主 checkout 和它的每个 worktree；源头是发布的 `dist/skills` 时，是 `dist/` 所在的仓库，BR-2412），源头就是目标，安装不写 skill 文件，只装会话 hook 和 git 守卫。

## 例子

- 在新仓库执行 `canon init` → 出现 `.claude/skills/canon-test/SKILL.md` 等文件和清单，`~/.claude` 没有变化
- 源头里还有 `user-own` 这个 skill → 不安装
- 再执行一次 `canon install`，源头没变 → 输出 `canon project files: up to date`
- 项目里已有改过的 `.claude/skills/canon-b/SKILL.md`，canon 也更新了它（BR-2081），执行 `canon init` → 退出码 5，仓库里没有出现 `canon/`
- 在 canon 自己的仓库里执行 `canon install` → 不写任何 skill 文件，退出码 0
- 在 canon 仓库的一个变更 worktree 里，用主 checkout 的 `dist/canon`（源头是发布的 `dist/skills`）执行 `canon install` → 不写任何 skill 文件，退出码 0
- 在 canon 自己的仓库里，`.claude/settings.json` 还没有会话 hook → `canon install` 只把 hook 合并进去（BR-2087）
