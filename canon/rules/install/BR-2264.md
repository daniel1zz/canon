## 规则

本条只适用于按 BR-2459 选中的 Claude 目标。

`canon init`、`canon install`、`canon update` 在合并会话 hook（BR-2087）的同一次写入里，确保项目的 `.claude/settings.json` 里 `worktree.baseRef` 是 `"head"`，让 Claude Code 给子 agent 建的 worktree 从本地当前的 HEAD 建，而不是从远端的默认分支建。canon 只管 `worktree` 里的 `baseRef` 这一项：`worktree` 里别的设置和文件里别的内容原样保留；没有 `worktree` 时新建只含 `baseRef` 的对象；`baseRef` 是别的值（比如 `"fresh"`）时改成 `"head"`；已经是 `"head"` 时不改文件。`worktree` 存在但不是 JSON 对象时，以退出码 2 拒绝，什么也不写。`baseRef` 缺少或不是 `"head"` 时，`canon update --check` 把它列为过期：`setting: worktree.baseRef "head", so subagent worktrees start from local HEAD (.claude/settings.json)`，退出码 1。

## 例子

- 新项目 `canon init` → `.claude/settings.json` 里有 `"worktree": { "baseRef": "head" }`；`canon update --check` 退出码 0
- 已有 `"worktree": { "symlinkDirectories": ["node_modules"] }` → `canon install` 后 `worktree` 是 `{ "symlinkDirectories": ["node_modules"], "baseRef": "head" }`
- 已有 `"worktree": { "baseRef": "fresh" }` → `canon update --check` 退出码 1，列出 `setting: worktree.baseRef`；`canon install` 后是 `"head"`
- 删掉 `worktree` 后 `canon update --check` → 退出码 1，列出 `setting: worktree.baseRef`；`canon install` 后退出码 0
- 已经是 `"head"` → `canon install` 不改文件
- `"worktree": "head"`（不是对象）→ `canon install` 退出码 2，提示 `worktree` 必须是 JSON 对象，文件不变；`canon update --check` 也是退出码 2、同样的提示，不按“缺少”列为过期
