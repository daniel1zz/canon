## 规则

`canon init`、`canon install`、`canon update` 在合并会话 hook（BR-2087）的同一次写入里，确保 `.claude/settings.json` 的 `hooks.PreToolUse` 里有一个 `matcher` 为 `Bash` 的条目，命令是 `canon snapshot take --hook || echo '{"systemMessage":"canon snapshot take failed or canon is not on PATH: uncommitted work was not snapshotted before this Bash call"}'`（BR-2182）；已经有就不动，文件里别的设置原样保留。缺这一项时，`canon update --check` 把它列为过期：`hook: canon snapshot take before each Bash call (.claude/settings.json)`，退出码 1。这个 hook 不拦截任何 Bash 调用：canon 出错或不在 PATH 上时，`echo` 让这一行以 0 结束，并给用户一条提示。

## 例子

- 新项目 `canon init` → `.claude/settings.json` 里有 SessionStart 的 `canon brief` 和 PreToolUse（`Bash`）的快照命令
- 已有别的 PreToolUse 条目（`matcher` 为 `Edit`）→ 保留它，另加快照条目
- 已经装过 → `canon install` 不改文件；`canon update --check` 不列它
- 删掉快照条目后 `canon update --check` → 列出 `hook: canon snapshot take before each Bash call (.claude/settings.json)`，退出码 1
- PATH 上没有 canon 时执行这条命令 → 输出 `{"systemMessage":...}`，退出码 0
