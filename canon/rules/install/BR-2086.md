## 规则

`canon update` 有过期项时，按 BR-2457 开始独立杂务，在它的 worktree 安装（BR-2080）、写提交信息（BR-2196），按 BR-2458 合入；不创建 Change 文档或占 C 编号。项目没有 `canon/architecture.md` 时把 BR-2032 的标题模板一起合入，已有文件不覆盖。已经最新时什么也不做；只有 git 守卫或 `info/exclude` 过期时仍按 BR-2123、BR-2305 在本地处理，不开始杂务。

安装能作出的拒绝都在开始杂务前完成：覆盖项目改过的 skill 文件时退出码 5 并列出文件（`--force` 才覆盖）；路径上有符号链接、清单含 `canon-*` 之外的路径（BR-2083）或 settings 不能改（BR-2087）时退出码 2；不留下工作树、分支或认领。更新的 SKILL.md 评审范围见 BR-2410。

合入被拒退出码 1，列出原因并保留杂务和工作树；排队超时退出码 75，提示在该工作树再次运行 `canon chore land`。合入后保留关于 JUnit 配置的说明。

## 例子

- skill 过期后更新 → main 上新 skill 已提交，无新增 C 文档或关闭提交；再次更新输出 up to date
- 缺少 architecture.md → 在杂务里合入标题模板；已有正文时更新其他项不改正文
- 只有 info/exclude 缺一行 → 补齐本地文件，无新提交、杂务分支或工作树
- floor 失败 → 退出码 1，main 不动，杂务分支和工作树保留
- 排队超过配置时限 → 退出码 75，提示 canon chore land
- 项目改过 skill，未传 --force → 退出码 5，不开始杂务
- 更新 SKILL.md 且未配置 review → 按 BR-2410 正常合入
- skill 路径上有符号链接 → 退出码 2，无新杂务
