title: "canon update 把更新作为一个单独的变更合入"
status: active
---

## 规则

`canon update` 在有过期的项时，开一个单独的变更（标题写明目标版本），在它的 worktree 里安装（BR-2080），自动写好变更说明、提交，按正常流程 `--finish` 合入（队列、floor、`canon check`、评审）。项目里没有 `canon/architecture.md` 时，变更里把只有标题的模板（和 `canon init` 写的一样，BR-2032）写进去一起合入，已有的这个文件从不覆盖、也不碰里面的内容，它在仓库里，缺少时也走变更合入，不像 git 守卫那样直接在本地写；已经是最新时什么也不做；只有 git 守卫或 `info/exclude` 过期时按 BR-2123、BR-2305 处理，不开变更；安装会做的每一项拒绝都在开变更之前做完：会覆盖项目里改过的 skill 文件时以退出码 5 拒绝并列出这些文件（加 `--force` 覆盖），要写的路径上有符号链接或清单里有 `canon-*` 以外的路径（BR-2083）、`.claude/settings.json` 不能改（BR-2087）时以退出码 2 拒绝，都不新建变更、分支或 worktree；更新写的 `SKILL.md` 合入时怎样评审见 BR-2410；合入被拒时退出码 1，列出原因，变更和 worktree 留着待处理；等到超时还在排队时退出码 75（BR-2022），提示在那个 worktree 里再运行 `canon work land --finish`，变更和 worktree 同样留着。

## 例子

- canon 更新了 `canon-a/SKILL.md`，执行 `canon update` → main 上多一个 `canon: close C-n`，`canon-a/SKILL.md` 是新内容，之后 `canon update --check` 退出码 0
- 再执行一次 `canon update` → 输出 `up to date`
- 项目里没有 `canon/architecture.md`，执行 `canon update` → main 上多一个 `canon: close C-n`，`canon/architecture.md` 是只有三个标题的模板，之后 `canon update --check` 退出码 0
- 项目里的 `canon/architecture.md` 有内容，别的东西过期，执行 `canon update` → 合入后它的内容不变
- 合入了更新 → 输出里还有一段 `note: canon now reads JUnit test reports (D-64)`，写明 `canon/config.yaml` 需要 `tests` 和带 `{file}`、`{report}` 的 `test_command`，并列出各框架的写法
- 只有 `info/exclude` 里的 `/.claude/worktrees/` 一行缺少 → `canon update` 退出码 0，这一行回来了，main 上没有新提交，没有 `change/*` 分支和 worktree
- 这一行缺少，同时 `canon-a/SKILL.md` 也过期 → 开变更合入，变更的 worktree 里装好 skill，这一行也写进了 `info/exclude`
- floor 是 `false` → 退出码 1，提示 `did not land: floor`，`change/C-n` 分支和它的 worktree 还在
- 别人正在合入，`land_timeout_minutes` 很短 → 退出码 75，提示 `run canon work land --finish`
- 项目里改过 `canon-b/SKILL.md`，canon 也更新了它 → 退出码 5，没有新建任何变更或 worktree
- canon 更新了 `canon-a/SKILL.md`，`canon/config.yaml` 没有 `review` → 照常开变更合入，退出码 0，main 上 `canon-a/SKILL.md` 是新内容
- 项目里提交了链接 `.claude/skills/canon-a`，canon 更新了 `canon-b/SKILL.md` → 退出码 2，提示里有这个链接，没有 `change/*` 分支，也没有 worktree
