## 规则

canon 的 `reference-transaction` hook 只在 `prepared` 状态检查，只看 `refs/heads/<main>` 这一行。下面的情况都放行：新值是全零（删除，包括 `git pack-refs` 删掉松散的副本）；main 还不存在；新值等于 main 当前的值（不动的行，比如 `git reset` 到同一个提交）；main 当前的提交里还没有 `canon/config.yaml`（canon 还没进 main，比如 `canon init` 之后的第一次提交）；环境变量 `CANON_LAND_MAIN` 等于新值（BR-2125）。其余情况一律拒绝：hook 退出码非 0，git 中止整个 ref 更新，什么也不移动，stderr 里有 `canon: refusing to move <main>` 和 `canon work land`。别的 ref 不受影响。

## 例子

- canon 已经在 main 上，在主 checkout 里 `git commit` → 退出码 128，stderr 有 `canon: refusing to move main` 和 `canon work land`，main 不动
- 同样的状态下 `git merge --no-ff x`、`git update-ref refs/heads/main <x>`、main 没签出时 `git push . x:main` → 都被拒绝，main 不动
- `CANON_LAND_MAIN=<x 的提交> git update-ref refs/heads/main <x>` → 成功；`CANON_LAND_MAIN=<别的提交>` → 拒绝
- `git reset HEAD`、`git pack-refs --all`、移动或删除分支 `y` → 成功
- 仓库的第一次提交、canon 进 main 之前在 main 上 `git commit` → 成功
