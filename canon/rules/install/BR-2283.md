## 规则

本地清理（BR-2280）开始前，如果最近一次合入的后台 `after_land` 命令还在运行，或者后台 floor 观察进程还活着，或者合入后在后台删 worktree 的进程（BR-2486）还在运行（它的日志还没有 `clean: done`、记下的进程还在），`canon uninstall` 什么都不删，在标准错误输出写明在等什么并以退出码 75（还没完成、稍后再运行，BR-2022）结束：`after_land` 在跑时含 `after_land commands are still running`，floor 观察进程活着时含 `background floor watcher is still running`，后台删 worktree 还在跑时含 `still removing the landed worktree of <变更>` 和它的日志路径；三种都写明结束后再运行一次 `canon uninstall`。它们结束后再运行一次就继续清理。卸载自己的那次合入也一样：它的 `after_land` 在跑时，合入成功但本地清理推迟；合入时按 BR-2486 删掉卸载自己的 chore worktree 是合入的一部分，不是这里说的本地清理，不推迟。这个判断在 BR-2277 检查进行中的工作之后（有进行中的工作时先按 BR-2277 以 5 拒绝），在 BR-2280 删除任何 worktree 和分支之前做，成立时以 75 结束，不会走到 BR-2280 的退出码 5。

## 例子

- 刚合入卸载变更，项目配了 `after_land: ["sleep 30"]` → 退出码 75，`.git/canon/` 和 git 守卫都还在，输出提示稍后再运行 `canon uninstall`
- `after_land` 已经结束 → 照常清理，退出码 0
- 协调数据库记着一次后台删除 worktree，进程还活着、日志没有 `clean: done` → 退出码 75，输出含 `still removing the landed worktree of`；日志写完 `clean: done` 后再运行 → 照常清理
