## 规则

`canon init --floor <命令>` 在仓库根目录建出 `canon/product.md`（中文标题：目的、使用者、承诺、不做的事）、`canon/architecture.md`（架构总览，只有标题“上下文”“容器”“主要流程”，没有占位行，所以它不触发任何检查，D-65）、`canon/config.yaml`（第一行是指向 schema 的 modeline 注释，见 BR-2176；再写入 `main`、floor、`tests: []`（前有一行注释说明这里写测试文件的 glob，BR-2046）和按 BR-2459 选择的初始评审命令（Claude 默认 `review: "claude -p --model sonnet --output-format text"`），评审命令前有一行注释说明它评审规则、决策和常驻说明的改动，不想评审时改成 `review: none`，见 BR-2074）和 `canon/rules`、`canon/decisions`、`canon/changes`、`canon/notes`；没给 floor 时提示必须先配置。

写进 `main` 的是当前分支名（`git symbolic-ref --short HEAD` 的结果），不管它叫什么；还没有任何提交的仓库也有当前分支名，照写。git hook 守卫（BR-2123）守的就是这个分支。`canon/config.yaml` 还不存在而 HEAD 是分离的（不在任何分支上）时，`canon init` 在写任何文件之前、也在其他所有检查（包括 BR-2124 的别人的 git hook）之前以退出码 4 拒绝，提示先签出要当主分支的那个分支再运行；`canon/config.yaml` 已经存在时它不被覆盖（BR-2076），也不看当前分支，分离的 HEAD 不影响。

main 已有提交时，`canon init` 新写的 `canon/config.yaml` 末尾还有 `links_since`（前面一行注释说明它），值是 main 当时的完整提交编号（含义见 BR-2424）；main 还没有提交时不写它，输出里说一句 `links_since` 由 `canon update` 写（何时写见 BR-2452）。已经存在的 `canon/config.yaml` 不被改动。

`canon init` 结束时，如果 main 还没有提交（刚 `git init` 的仓库），再多说一句下一步：按 BR-2012 提示首次提交的命令；main 已有提交时不说这句。

## 例子

- 新仓库执行 `canon init` → 建出上述文件和目录，提示 set `floor`
- `canon init` 之后 `canon/architecture.md` 的内容正好是 front matter 加 `# 架构总览` 和 `## 上下文`、`## 容器`、`## 主要流程` 三个空的标题；`canon check` 退出码 0
- `canon/architecture.md` 已经存在、写着别的内容 → `canon init` 输出 `exists canon/architecture.md`，文件不变
- `canon init --floor "bun test"` → `canon/config.yaml` 第一行是 `# yaml-language-server: $schema=../.canon/config.schema.json`，并有 `floor: "bun test"`、`tests: []`、`review: "claude -p --model sonnet --output-format text"`
- 在分支 `trunk` 上执行 `canon init` → `canon/config.yaml` 里是 `main: trunk`，守卫守 `trunk`；在分支 `main` 上 → `main: main`
- 用 `git init -b dev` 建的、还没有提交的仓库 → `main: dev`
- 签出某个提交（分离的 HEAD）、还没有 `canon/config.yaml` → 退出码 4，提示里有 `detached`，`canon/` 和 `.claude/skills` 都没有被写
- 分离的 HEAD、还没有 `canon/config.yaml`，hook 目录里又有别人写的 `reference-transaction` → 退出码 4（不是 5），那个 hook 不变
- 分离的 HEAD，但 `canon/config.yaml` 已经存在 → 照常执行，退出码 0，配置内容不变
- 用 `git init -b main` 建的、还没有提交的仓库执行 `canon init` → 退出码 0，输出最后有 `main has no commit yet` 和 `git commit -m "canon init"`
- main 上已经有提交时执行 `canon init` → 输出里没有 `has no commit yet`
- main 上已经有提交、还没有 `canon/config.yaml` → 写出的配置里有 `links_since: "<main 的完整编号>"`，`canon links list` 不以退出码 4 失败
- 还没有提交的仓库执行 `canon init` → 配置里没有 `links_since`，输出里有 `links_since` 和 `canon update`
- 已有 `canon/config.yaml`、里面没有 `links_since` → `canon init` 不改这个文件
