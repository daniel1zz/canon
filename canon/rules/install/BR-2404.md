## 规则

`canon init`、`canon install`、`canon update` 在合并会话 hook（BR-2087）的同一次写入里，确保项目的 `.claude/settings.json` 的 `hooks.PostToolUse` 里有一个 `matcher` 为 `Write|Edit|MultiEdit` 的条目，命令是 `canon restatements --hook || echo '{"systemMessage":"canon restatements --hook failed or canon is not on PATH: the edited rule or decision was not checked for restatements"}'`（它做什么见 BR-2402）；已经有就不动，`hooks.PostToolUse` 里别的条目和文件里别的设置原样保留。缺这一项时，`canon update --check` 把它列为过期：`hook: canon restatements --hook after each Write or Edit (.claude/settings.json)`，退出码 1。`canon uninstall` 和 canon 的其他条目一起删掉它（BR-2278）。这个 hook 只提示，不拦截：canon 出错或不在 PATH 上时，`echo` 让这一行以 0 结束，并给用户一条提示。

## 例子

- 新项目 `canon init` → `hooks.PostToolUse` 里有 `matcher` 为 `Write|Edit|MultiEdit`、命令是 `canon restatements --hook || echo ...` 的条目
- 已有别的 PostToolUse 条目（`matcher` 为 `Write`）→ `canon install` 保留它，另加这一条
- 删掉这一条后 `canon update --check` → 退出码 1，列出 `hook: canon restatements --hook after each Write or Edit (.claude/settings.json)`；`canon install` 后退出码 0
- PATH 上没有 canon 时执行这条命令 → 输出 `{"systemMessage":...}`，退出码 0
- `canon uninstall` 的变更里 → 这一条被删掉，同一列表里别的条目保留
