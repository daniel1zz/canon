id: BR-2412
title: canon 的发布把编译好的 canon 和它安装的 skill 从同一个测过的提交一起放进 dist
status: active
---

## 规则

发布评审（BR-2411）通过后，`scripts/release.ts` 把这个测过的提交发布到主 checkout 的 `dist/`：编译出的 canon 先写到 `dist/` 下的临时文件，这个提交的每个 `.claude/skills/canon-*` 目录复制到 `dist/skills-<提交>`（先写到临时目录再改名），然后把符号链接 `dist/skills` 切到 `skills-<提交>`（新链接写好后一次改名换上），最后把临时的二进制改名成 `dist/canon`。读 skill 的人看到的是旧的一套或新的一套 skill，不会看到一半（D-55）；二进制和 skill 是两次改名，两次之间短暂是旧二进制配新 skill（两者都是发布过的）；第二次改名失败时以退出码 4 结束，下一次发布再补齐。`skills-<提交>` 已经存在（重新发布同一个提交）时不重写它。切换后只留这一次和切换前链接指向的那次发布的 `skills-*` 目录，更早的删掉；重新发布同一个提交时这两个是同一个。已经发布的提交比这次新（这次的提交是它的祖先）时什么也不换，输出说明后以退出码 0 结束（BR-2222：只往更新的提交走）。编译失败时什么也不换，`dist/` 保持上一次发布的样子，以退出码 4 结束；`dist/skills` 已经存在但不是符号链接时以退出码 4 拒绝、不改动它，信息说明要先把它移开。

## 例子

- 依次发布 v1、v2、v3 三个提交 → `dist/canon` 是 v3 编译出来的，`dist/skills` 指向 `skills-<v3>`，里面的 `canon-a/SKILL.md` 是 v3 的内容，`dist/` 下只剩 `skills-<v2>` 和 `skills-<v3>`，没有临时文件
- 已经发布了 v3，再发布 v1 → 结果是 `older`，`dist/canon` 和 `dist/skills` 仍是 v3 的
- 已经发布了 v1，发布 v2 时编译失败 → `dist/canon` 仍是 v1 的，`dist/skills` 仍指向 `skills-<v1>`，没有 `skills-<v2>`
- `dist/skills` 是手工建的普通目录 → 拒绝，信息含 `is not a symbolic link`，目录里的文件没变，没有写 `dist/canon`
- v3 已经发布，再发布一次 v3 → `skills-<v3>` 不重写，`dist/canon` 换成新编译的，`dist/` 下只剩 `skills-<v3>`
