## 规则

`canon rule new --domain <领域>` 在建出文件之前，先在标准输出上把这个领域现在的业务摆出来：按 README `## 业务` 段的顺序，每个业务一行（名字和说明），下面按编号列出指向它的每条生效和规划中规则的编号和标题；没有规则指向的业务写 `(还没有规则)`。这个领域里没有 `business`、以及 `business` 的名字不在 `## 业务` 里（BR-2431 会拒绝它们）的生效和规划中规则，一起列在最后一组，标成未归属业务。README 没有 `## 业务` 段、或者段里一个业务都没有时，写明这个领域还没有列业务，要先把业务写进 README 再指向它。列完之后才建文件、打印路径，所以路径仍是输出的最后一行。

只有 `canon rule new` 这样列；`canon doc new` 和别的类型不列。

## 例子

- `canon rule new --domain install --title "…"`，install 的 README 列了 `更新策略`，BR-2081、BR-2084、BR-2089 指向它 → 先打印 `更新策略` 和这三条的编号标题，再打印新文件的路径
- 同上，install 里还有 30 条没有 `business` 的规则 → 它们列在最后一组，标成未归属业务
- 领域的 README 列了 `上下文` 但没有规则指向它 → 这一行后面写 `(还没有规则)`
- 领域里有一条规则写 `business: 退货`，README 没有列 `退货` → 它和没有 `business` 的规则一起列在最后一组
- 领域的 README 没有 `## 业务` 段 → 打印这个领域还没有列业务、要先写进 README，然后照常建出文件
- `canon decision new --title "…"` → 不列业务
