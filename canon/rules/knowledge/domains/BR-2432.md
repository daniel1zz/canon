## 规则

`canon rule new --domain <领域>` 在建出文件之前，先在标准输出上把这个领域现在的业务和规则摆出来：第一行以 `businesses of <领域>` 开头，这一行其余部分说明新规则要么补上这些业务没覆盖的边界、要么新建一个业务；下面的分组和每一行的写法同 BR-2007，生效和规划中的规则都算。README 一个业务都没列时，第一行改为写明这个领域还没有列业务、要先把业务写进 README 再指向它，下面按编号列出这个领域现有的规则。

什么都不列的情况只有三种：命令行用法错误（例如缺 `--domain`，退出码 2），被 BR-2409 以在受守卫的 main 上写文档为由拒绝，和 `--domain` 给的领域不存在。按 BR-2409，标题去掉首尾空白后为空时不按守卫拒，所以在受守卫的 main 上用空标题照样先列清单。其余情况一律先列完清单才建文件、打印路径，所以路径仍是输出的最后一行；到建文件这一步才被 BR-2187 拒绝时，清单已经列出来了，但什么文件也没建。

只有 `canon rule new` 这样列；`canon doc new` 和别的类型不列。

## 例子

- `canon rule new --domain install --title "…"`，install 的 README 列了 `更新`，BR-2084、BR-2086、BR-2089 指向它 → 第一行是 `businesses of install …`，然后是按 BR-2007 分组的这三条，最后一行才是新文件的路径
- 领域的 README 没有 `## 业务` 段 → 第一行写明这个领域还没有列业务，下面按编号列出现有的规则，然后照常建出文件
- `canon rule new --domain nowhere --title "x"`，nowhere 这个领域不存在 → 什么也不列，退出码 3
- `canon rule new --domain nowhere --title ""` → 什么也不列（领域不存在），按 BR-2187 以退出码 2 拒绝
- `canon rule new --domain billing --title ""` → 清单已经列出来了，然后按 BR-2187 以退出码 2 拒绝，billing 下没有多出文件
- 在受守卫的 main 上 `canon rule new --domain billing --title "x"` → 什么也不列，按 BR-2409 拒绝
- 在受守卫的 main 上 `canon rule new --domain billing --title ""` → 清单已经列出来了，然后以退出码 2 拒绝，不是守卫的退出码 1
- `canon decision new --title "…"` → 不列业务
- `canon rule new --title "…"`，没给 `--domain` → 不列清单、不建文件，以用法错误（退出码 2）结束
