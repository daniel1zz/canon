## 规则

领域 README（顶层领域和子领域都算）可以有一个 `## 业务` 段，逐条列这个领域管的业务，每条写成 `- **<业务名>**：<这个业务管什么>`；不是这个形式的行不算一个业务，模板留下的占位行（BR-2035）也不算。业务名在同一个领域里唯一：同一个名字写了几行时只算一个业务，取最先出现的那一行。名字只在这个领域里有效，两个领域里写着同一个名字的是两个业务，规则只能指向它自己所在领域列着的业务。

规则的 front matter 可以写 `business: <业务名>`。值不是字符串或者去掉空白后为空时，这个文件报 `file-invalid`，说明 `business` 要写一个业务名。`business` 不算规则的行为（BR-2236），改它不要求重新执行测试。指向的名字在不在 README 的 `## 业务` 里，由 BR-2431 核对。

`canon rule domain` 建出的 README 模板带一个 `## 业务` 段和一行占位，和 `## 术语` 一样要填掉（BR-2035）。

## 例子

- install 的 README `## 业务` 里有 `- **更新策略**：canon 装进项目的文件在上游和项目两边都变了时怎么处理`，BR-2089 的 front matter 写 `business: 更新策略` → 读得出来，`canon check` 不报
- 某条规则写 `business:`（没有值） → 报 `file-invalid`，说明 `business` 要写一个业务名
- README 的 `## 业务` 里写了 `- 更新策略：…`（没有 `**`） → 不算一个业务，指向它的规则按 BR-2431 被报出来
- README 的 `## 业务` 里两行都写 `- **更新策略**：…` → 只算一个业务，说明取最先出现的那一行
- README 的 `## 业务` 还是模板留下的 `- **<业务名>**：<这个业务管什么>` → 一个业务都没有，写 `business: <业务名>` 的规则按 BR-2431 被报出来
- install 和 work/hooks 的 README 都列了 `- **更新策略**：…` → 是两个业务；install 里的规则只能指向 install 的那一个
- 只改一条规则的 `business`，不改 `## 规则` 和 `## 例子` → 行为哈希不变，不要求重新执行测试
- `canon rule domain billing` → 建出的 `canon/rules/billing/README.md` 里有 `## 业务` 段和一行占位
