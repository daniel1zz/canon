## 规则

本次工作新增了一个领域（它的 `canon/rules/<领域路径>/README.md` 在本次工作的基点上还不存在，子领域和顶层领域一样算）时，整棵树里必须有一份状态是 `accepted` 或 `proposed` 的决策，正文里写出这个领域的路径（`<领域>` 或 `<领域>/<子领域>`，写在反引号里也算）。路径整条匹配，两个方向都不算数：只写外层领域不算写了子领域，只写子领域也不算写了外层领域。没有这样的决策时，`canon check` 在这个领域的 README 上报一条 `domain-no-decision`，退出码 1，合入也被拒；信息写明这个领域的路径，并说明新建领域要先记一条决策，写清为什么不复用已有的领域。

本次工作没有新增的领域一条都不报，所以已有的领域不追溯；不在任何变更里时没有本次工作，一条都不报。

## 例子

- 变更新建了 `canon/rules/billing/refunds/README.md`，同一个变更里新写的 `D-9` 正文写了「`billing/refunds` 只管退款」 → 不报
- 同上，但这个变更没有新建决策，已有的 `D-5`（accepted）正文里写了 `billing/refunds` → 不报
- 同上，但没有任何决策点名它，只有一条点名了 `billing` → 报 `domain-no-decision`，退出码 1
- 变更新建了领域，点名它的决策状态是 `superseded` → 报
- 变更新建了顶层领域 `billing`，只有一条决策写了 `billing/refunds` → 报：子领域不算点名了外层领域
- 本次工作一个领域都没新建，而已有的 `billing` 没有任何决策点名它 → 不报
- 在 main 分支的检出里跑 `canon check` → 这一项一条都不报
