## 规则

`canon check` 对本次工作新增或改动的每条生效或规划中的规则核对它的 `business`。「本次工作新增或改动」用 BR-2344 判断一个文件是不是本变更碰过的那套比较，用在 `canon/rules` 下的规则文件上。front matter 没有 `business`，或者它的值不在这条规则所在领域 README 的 `## 业务` 段里（按 BR-2430 的写法读出来），就在这个规则文件上报一条 `rule-business-unmapped`，退出码 1，合入也被拒。信息写明这条规则的编号、它的领域，以及这个领域 README 现有的业务名（一个都没有时写明这个领域还没有 `## 业务` 段），并说明要么指向其中一个，要么先把新业务写进 README。

本次工作没有新增或改动的规则一条都不报，所以存量不追溯、不用迁移；不在任何变更里时没有本次工作，一条都不报。

## 例子

- 变更新建了 `canon/rules/billing/BR-9.md`，front matter 没有 `business` → 报 `rule-business-unmapped`，退出码 1
- 变更改了 BR-2089 的正文，它写 `business: 更新策略`，install 的 README `## 业务` 里有 `- **更新策略**：…` → 不报
- 变更改了 BR-2089，它写 `business: 更新`，install 的 README 里只有 `更新策略` → 报，信息里列出 `更新策略`
- 变更改了 billing 下的一条规则，billing 的 README 没有 `## 业务` 段 → 报，信息里写明这个领域还没有 `## 业务` 段
- install 里另外 32 条规则没有 `business`，本次变更一条都没改到 → 不报
- 本次变更把一条规则从 active 改成 retired，没改别的 → 作废的规则不报
- 在 main 分支的检出里跑 `canon check` → 这一项一条都不报
