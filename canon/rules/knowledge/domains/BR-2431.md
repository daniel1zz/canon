## 规则

`canon check` 对本次工作新增或改动的每条生效或规划中的规则核对它的 `business`。「本次工作新增或改动」用 BR-2344 判断一个文件是不是本变更碰过的那套比较，用在 `canon/rules` 下的规则文件上。只有 front matter 的 `links` 复核记录（BR-2425）变了、正文和其余 front matter 的值都没变的规则不算改动：复核记录由命令写入，不是作者在改这条规则（D-106）。

front matter 没有 `business`，或者它的值不在这条规则所在领域 README 的 `## 业务` 段里（按 BR-2430 的写法读出来）时，`canon check` 在标准错误上写一行以 `note: <规则文件路径>: ` 开头的提醒，末尾写 `(BR-2431)`；`canon work test` 在自己的输出里也打印这一行，不因此失败。退出码不变，不拒绝合入。提醒写明这条规则的编号、它的领域，以及这个领域 README 现有的业务名（一个都没有时写明这个领域还没有 `## 业务` 段），并说明要么指向其中一个，要么先把新业务写进 README。

本次工作没有新增或改动的规则一条都不提醒，所以存量不追溯、不用迁移；不在任何变更里时没有本次工作，一条都不提醒。

依据：D-139（提醒代替拒绝）。

## 例子

- 变更新建了 `canon/rules/billing/BR-9.md`，front matter 没有 `business` → 标准错误有 `note: canon/rules/billing/BR-9.md: BR-9 has no \`business\` … (BR-2431)`，退出码 0
- 变更改了 BR-2089 的正文，它写 `business: 更新策略`，install 的 README `## 业务` 里有 `- **更新策略**：…` → 没有这行提醒
- 变更改了 BR-2089，它写 `business: 更新`，install 的 README 里只有 `更新策略` → 有这行提醒，信息里列出 `更新策略`
- 变更改了 billing 下的一条规则，billing 的 README 没有 `## 业务` 段 → 有这行提醒，信息里写明这个领域还没有 `## 业务` 段
- install 里另外 32 条规则没有 `business`，本次变更一条都没改到 → 没有提醒
- 本次变更把一条规则从 active 改成 retired，没改别的 → 作废的规则不提醒
- 在 main 分支的检出里跑 `canon check` → 这一项一条都不提醒
- 本次工作只用 `canon links confirm` 给一条没有 `business` 的规则记了复核记录 → 没有提醒
- 同一条规则同时改了正文的一个字 → 有提醒
- 这条提醒出现时，合入照常排队 → 退出码 0
