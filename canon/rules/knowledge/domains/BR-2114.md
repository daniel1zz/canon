## 规则

`canon rule domains` 逐行列出每个领域和子领域（子领域缩进）、直接属于它的生效规则数和代码路径；领域 README 列了业务（BR-2430）时，在这个领域的行下面再缩进两格，按 README 里的顺序逐行列出每个业务和指向它的生效规则数，每行写成 `- <业务名>  <n> rules`，以 `- ` 开头（子领域的行不以 `- ` 开头，所以两者分得开）；没有指向任何已列业务的生效规则另起一行 `- in no business  <n> rules`，一条都没有时不列这一行。一个领域既有业务又有子领域时，业务的行紧跟在这个领域自己的行后面，子领域的行排在它们之后。README 一个业务都没列的领域不多出任何行。直接属于一个领域的生效规则超过 25 条时，领域那一行末尾提示可以拆成子领域，并给出建子领域的命令。这只是提示，`canon check` 不报，合入不受影响。名字像技术层的领域在这一行末尾另有提示（BR-2318）。

## 例子

- billing 直接有 26 条生效规则 → billing 那一行末尾有 `consider subdomains, canon rule domain billing/<name>`
- billing 直接有 25 条 → 没有提示
- work 有 3 条直接规则、子领域 work/land 有 18 条 → 两行都没有提示，work/land 缩进显示
- billing 的 README 列了 `退款` 和 `对账`，4 条规则指向 `退款`、没有规则指向 `对账`、另有 2 条没有 `business` → billing 那一行下面是 `- 退款  4 rules`、`- 对账  0 rules`、`- in no business  2 rules`
- 同上，但 6 条规则全都指向 `退款` 或 `对账` → 没有 `- in no business` 这一行
- billing 列了 `退款`、又有子领域 billing/refunds → 顺序是 billing、`- 退款`、`- in no business`，然后才是缩进的 billing/refunds
- billing 的 README 一个业务都没列 → billing 那一行下面不多出任何行
