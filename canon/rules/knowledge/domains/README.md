# 领域怎么分成业务（knowledge/domains）

一个领域管哪些业务写在它的 README 里，规则指向其中一个业务。这一块管这份清单：怎么写、怎么保证它和规则对得上、写新规则的人在哪看到它。领域本身怎么建、代码目录怎么对应，现在还在 `knowledge/documents`、`knowledge/check` 和 `knowledge/query`（D-96）；这些规则被改到时搬过来。

## 术语

- **业务**：一个领域管的一件事，由几条规则描述它的全部边界；名字写在领域 README 的 `## 业务` 段里，只在这个领域里有效。
- **未归属业务的规则**：front matter 没有 `business` 的规则；存量规则大多是这样，只有被改到时才要补上（BR-2431）。

## 业务

- **业务清单**：一个领域管哪些业务写在哪、规则怎么指向它、谁保证这份清单和规则对得上、写新规则的人在哪看到它。
- **领域清单**：`canon rule domains` 怎么把现在有哪些领域、各自多少规则、代码在哪、下面有哪些业务摆出来。
