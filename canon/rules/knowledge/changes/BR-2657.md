title: 合入变更时，改到的规则或路径是别的未结束变更写下的，就提醒可能重复，不拦合入
status: active
business: 重复提醒

## 规则

`canon work land` 合入一个变更（不是杂务）时，在进入队列之前、和同文件重叠提示（BR-2062）同一时刻，把它改到的东西和每个别的未结束变更（主状态不是 `landed`、`dropped`，BR-2571）写下的东西比较（D-171）：

- 规则：正在合入的变更 front matter 的 `rules:`，加上 `git diff --name-only main...HEAD` 里的规则文件的编号；别的变更 front matter 的 `rules:`。有交集就算重合。正文里提到的规则编号不算。
- 路径：`git diff --name-only main...HEAD` 里的路径（不含它自己的变更文件）；别的变更正文里用反引号括起、含 `/`、不含空白的文字。改动的路径等于写下的路径，或写下的路径以 `/` 结尾且是改动路径的前缀，或改动路径以「写下的路径 + `/`」开头，就算重合。
- 模块：两边写了同一个 `feature` 只附在提醒里，单独不算重合。

对每个有重合、而这一对（不分先后）还没有回应过（BR-2658）的变更打印一行：

`possible duplicate: <C-m> <标题> (shared rules: <编号>; shared paths: <路径>; same feature <F-n>)`，没有的部分不写，路径至多列 5 个、多的写 `…`；

之后一行怎样回应：`is <C-m> the same work? canon change duplicate <本变更> <C-m> --same, or --not "<why>"`。同一对在合入阶段第一次提醒时写一条 `duplicate.remind` 事件（对象是本变更，`stage: "land"`、`with`、`rules`、`paths`、`feature`），之后再合入（被拒后重试）只打印，不再写事件。

提醒不拦截合入、不改变退出码（D-139）；BR-2062 那些不进队列的拒绝之后不比较。比较需要的 git 读取出错时打印一行 `duplicate: cannot compare: <错误>`，合入照常进行。

## 例子

- 未结束的 `C-5` 写了 `rules: [BR-7]`，合入的 `C-4` 改了 `canon/rules/x/BR-7.md` → 打印 `possible duplicate: C-5 … (shared rules: BR-7)`，事件表多一条 `duplicate.remind`，合入照常完成，退出码 0
- `C-5` 正文写了 `` `src/work/land/` ``，`C-4` 改了 `src/work/land/land.ts` → 提醒，`shared paths: src/work/land/land.ts`
- `C-5` 正文写了 `` `src/work/land` ``，`C-4` 改了 `src/work/landing.ts` → 不提醒
- 两边都写了 `feature: F-2`，没有共同的规则和路径 → 不提醒
- `C-5` 已经 `done` → 不提醒
- 第一次合入被拒、修好再合入 → 两次都打印，事件只有一条
- 已经 `canon change duplicate C-4 C-5 --not "…"` → 合入时不再提醒 `C-5`
- 合入的是杂务 → 不比较
