## 规则

已经升级、还没把计划迁移成变更的项目，由 `canon check` 提示怎样迁移（D-148）。被检查的树里每个不是 `dropped` 的变更 `C-n`，正文里有标题是 `## 计划` 的一节（围栏代码块里的标题和表都不算），节里第一张 Markdown 表的表头有 `步骤` 和 `内容` 两列时，表的每个数据行是一个旧步骤；一个旧步骤**没做完**，是树里没有一个 `done` 的变更在 front matter 里写着 `plan: C-n` 并且 `steps` 含这个步骤名（步骤名按文字比，`3` 和 `"3"` 相同）。`C-n` 至少有一个没做完的旧步骤时，`canon check` 在标准错误输出一行：

`note: <C-n 的路径>: <C-n> ## 计划 has step(s) no landed change names: <步骤名>, …; plans are gone (D-148): for each step still to do, run canon change new --title "<its 内容>" --depends <the changes made for its 依赖 steps> (BR-2562), then delete its row; a step already done: delete its row too (BR-2595)`

步骤名按表里的先后列出。每个变更最多一行，不管有几个没做完的步骤。这只是提示（D-139）：不算发现，不进标准输出，不改退出码，`--json` 里没有它。没有 `## 计划` 节、节里没有表、表头缺 `步骤` 或 `内容` 列、所有步骤都有 `done` 的变更写着时，不输出。

## 例子

- `open` 的 `C-1` 的计划表有步骤 `1`、`2`，`done` 的 `C-2` 写 `plan: C-1`、`steps: [1]` → 一行 `note:`，含 `C-1`、`has step(s) no landed change names: 2` 和 `canon change new --title`，退出码 0，标准输出和没有这一行时一样
- 同上，`done` 的 `C-3` 再写 `plan: C-1`、`steps: ["2"]` → 不输出
- 做步骤 `2` 的变更只有 `open` 或 `dropped` 的 → 仍输出，列出 `2`
- `done` 的 `C-1` 的计划表只剩已做完的行，每行都有 `done` 的变更写着，表下写着「未做的步骤已转成变更」→ 不输出
- `dropped` 的 `C-1` 有没做完的步骤 → 不输出
- `C-1` 的 `## 计划` 只在 ``` 围起来的代码块里 → 不输出
- `C-1` 有步骤 `1`、`3` 都没做完 → 只有一行，写 `1, 3`
- `C-1` 的 `## 计划` 节里只有文字、没有表 → 不输出
