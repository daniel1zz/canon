## 规则

`canon change graph <R-n 或 F-n>` 每次从变更文件现算，不存任何东西（D-148、D-151）。读的变更和 `canon overview` 一样：main 最新提交上的变更，加上只在变更分支上的变更（BR-2291）。

属于它的变更：版本 `R-n` 是写着 `release: R-n`（或并入它的版本，BR-2521）、或写着 `feature: F-m` 而 `F-m` 是它的模块（BR-2509）的变更；模块 `F-n` 是写着 `feature: F-n` 的变更（BR-2561）。`dropped` 的变更不列。每个变更是下面四种状态之一，按这个先后取第一个符合的：

- 已合入（`landed`）：main 上它的文件是 `done`。
- 进行中（`in_progress`）：有生效的认领，或有变更分支，或有交接；只在分支上写着 `done` 的也算。
- 在等（`waiting`）：`open`，有没满足的依赖（BR-2564）。
- 可开始（`ready`）：其余的 `open` 变更。

输出第一行 `<编号>  <标题>  变更 <总数> 个：已合入 <a>  进行中 <b>  在等 <c>  可开始 <d>`，然后每个变更一行 `<变更编号>  <状态>  <标题>`（状态写中文名，括号里的英文是 `--json` 用的），有 `depends_on` 时后面加 `  depends on <依赖>, …`，在等的再加 `  waiting for …`（写法同 BR-2564 的标记）。顺序是依赖在前（一个变更排在它依赖的、同在这张图里的变更之后），其余按编号的数值；依赖成环的几个按编号排。没有属于它的变更时，第一行之后一行 `(no changes)`。

`--json` 输出一个对象：`id`、`title`、`kind`（`release` 或 `feature`）、`counts`（键 `landed`、`in_progress`、`waiting`、`ready`）、`changes`（按上面的顺序，每项含 `id`、`title`、`state`、`depends_on`（数组）、`waiting_for`（同 `canon change list --json`，BR-2564））。

编号不存在或不是版本、模块，退出码 3，标准输出没有内容；不给编号，退出码 2。这几种状态的计数也是 `canon release status`、`canon feature status` 里的工作量（BR-2568）。

## 例子

- `C-3`、`C-5`、`C-6` 都写着 `release: R-2`，`C-5` 依赖 `C-3`，`C-6` 依赖 `C-5`；`C-3` 在 main 上 `done`，`C-5` 有认领，`C-6` open → `R-2 … 变更 3 个：已合入 1  进行中 1  在等 1  可开始 0`，然后 `C-3 已合入`、`C-5 进行中 … depends on C-3`、`C-6 在等 … depends on C-5  waiting for C-5`
- `C-7` 写着 `feature: F-1`，`R-2` 列着 `F-1` → `C-7` 出现在 `canon change graph R-2` 和 `canon change graph F-1` 里
- `C-8` 只在分支 `change/C-8` 上，写着 `release: R-2` → 列出，进行中
- `C-9` 依赖 `C-30`，`C-30` 不属于 `R-2` 且在 main 上 open → `C-9` 在等，`waiting for C-30`
- `C-4` 写着 `release: R-2`，已 `dropped` → 不列
- `C-10` 依赖 `R-2/S1`，`S1` 待负责人 → 在等，`waiting for R-2/S1: <文字>`
- 没有变更写着 `R-3` → `R-3 … 变更 0 个：…`，下一行 `(no changes)`
- `canon change graph BR-3` → 退出码 3
- `canon change graph R-2 --json` → `counts.landed` 是 1，`changes[2].waiting_for[0].id` 是 `C-5`
