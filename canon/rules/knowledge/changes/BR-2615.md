## 规则

变更 front matter 的 `owner_gate` 写成一段非空文字 `"<负责人要批准什么>"`，例如 `owner_gate: "研究站剧情设计稿"`，表示这个变更要负责人批准后才算完成（D-158）；写成 `none: <理由>` 表示不需要负责人批准，不算带关卡。新建变更时必须给出它（BR-2620、BR-2623）：完成时的检查按 BR-2616，提醒按 BR-2617、BR-2618。`canon check` 对 `owner_gate` 不是字符串、去掉首尾空白后是空的、或 `none:` 后面没写理由的变更文件报 `file-invalid`，信息写明它要一段非空文字或 `none: <理由>`。没有 `owner_gate` 的旧变更和写成 `none: <理由>` 的变更都不受关卡影响。

## 例子

- `owner_gate: "研究站剧情设计稿"` → 合法
- `owner_gate: ""` 或 `owner_gate: "   "` → `file-invalid`
- `owner_gate: true` → `file-invalid`，信息写明要一段文字
- `owner_gate: "none: 内部工具"` → 合法，没有关卡，合入不等负责人
- `owner_gate: "none:"` → `file-invalid`
- 没有 `owner_gate` 的旧变更 → 照旧
