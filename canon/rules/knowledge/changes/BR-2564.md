## 规则

变更 `depends_on`（BR-2561）里的一个变更 `C-a`，按 main 最新提交上的 `C-a` 文件判定（D-148、D-149）：`done` 算满足；`dropped` 且写了 `done_by: C-m` 时按 `C-m` 同样判定（`C-m` 也是这样的就接着往下找，绕回来过的算没满足）；其余都没满足，分四种：在 main 上还是 `open`；只在变更分支上（还没合入，分支上写着 `done` 也算）；`dropped` 却没写 `done_by`；哪里都找不到。

`depends_on` 里的一条成功标准 `R-n/S<k>` 或 `F-n/S<k>`，按 main 最新提交上那份版本或模块文档判定：它的状态是已满足（BR-2504）才算满足，未满足、待负责人、未证明都没满足；所以要负责人确认的依赖写成一条待负责人的成功标准，它只有负责人为某个变更回答过问题才能变成已满足（BR-2510），AI 自己满足不了。文档或这一条在 main 上没有时算找不到。

`canon change list` 列出的每个 `open` 变更，有没满足的依赖时加一个标记 `waiting for <依赖>, <依赖>`：依赖写编号，`dropped` 没写 `done_by` 的写成 `<C-a> (dropped without done_by)`，找不到的写成 `<C-a> (not found)`，经 `done_by` 转到 `C-m` 的写成 `<C-a> (done by <C-m>)`，成功标准写成 `<R-n/S<k>>: <这一条的文字>`（找不到的同样写 `(not found)`）；变更的顺序不变（BR-2148）。`--json` 的每一项加 `waiting_for`：没满足的依赖的数组，每项含 `id` 和 `state`（变更是 `open`、`on-branch`、`dropped`、`not-found`；成功标准是 `unmet`、`owner`、`unproven`、`not-found`，有这一条时再加 `text`），全满足或没有依赖时是空数组。`canon overview` 的 `## 正在做和在等` 一节在 `waiting-deps` 后面用同样的写法列出在等的依赖（BR-2505）。

`canon brief` 在没认领变更的地方（BR-2149），“with no task, take the first …” 那一行不列主状态（BR-2571）是 `waiting-deps`、`waiting-owner`、`awaiting-close` 的变更，它们按同样的顺序各另起一行，没有时不输出那一行：

- `waiting-deps`：`Waiting for dependencies, not ready to start: <C-n> (waiting for <依赖>, …), …`；
- `waiting-owner`：`Waiting for the owner, not ready to start (ask them; canon human pending): <C-n> (<问题编号和成功标准>), …`；
- `awaiting-close`：`Work already on main, close it instead of starting it (canon change close <C-n> --commit <commit>): <C-n>, …`。

有有效认领等主状态排在前面的变更，依赖没满足也照旧在取活那一行，带 `claimed` 等标记，没有任务的会话本来就跳过它。`canon guide work` 里没有任务时取变更的那一句（BR-2654），跳过标着 `waiting` 的变更。依赖没满足只是不列为可开始，`canon work start` 照样能开工这个变更。

## 例子

- `C-5` 写 `depends_on: [C-3]`，`C-3` 在 main 上是 `open` → `canon change list` 里 `C-5` 那一行有 `waiting for C-3`，`canon overview` 有 `C-5 <标题>  waiting-deps: C-3`；`canon brief` 的取活那一行没有 `C-5`，下一行是 `Waiting for dependencies, not ready to start: C-5 (waiting for C-3)`
- `C-3` 合入后在 main 上是 `done` → `C-5` 没有 `waiting` 标记，出现在 brief 的取活那一行
- `C-3` 只在分支 `change/C-3` 上，那里写着 `done` → `C-5` 有 `waiting for C-3`，`--json` 里 `state` 是 `on-branch`
- `C-3` 在 main 上是 `dropped`，写着 `done_by: C-8`，`C-8` 是 `done` → `C-5` 没有 `waiting` 标记
- 同上，但 `C-8` 是 `open` → `waiting for C-3 (done by C-8)`
- `C-3` 是 `dropped`，没写 `done_by` → `waiting for C-3 (dropped without done_by)`
- `C-5` 写 `depends_on: [C-99]`，哪里都没有 `C-99` → `waiting for C-99 (not found)`
- `C-3` 是 `dropped`、`done_by: C-4`，`C-4` 也是 `dropped`、`done_by: C-3` → `C-5` 有 `waiting for C-3 (done by C-4)`
- 所有未完成的变更都在等依赖 → brief 没有取活那一行，只有 `Waiting for dependencies, …` 那一行
- `C-6` 有没回答的问题 #12（`--change C-6`）→ brief 的取活那一行没有 `C-6`，另有 `Waiting for the owner, not ready to start (…): C-6 (#12)`
- main 上 `open` 的 `C-343` 主状态是 `awaiting-close` → 取活那一行没有它，另有 `Work already on main, close it instead of starting it (…): C-343`
- 依赖没满足的 `C-5`，`canon work start C-5` → 照常开工
- `C-5` 没有 `depends_on` → `--json` 里 `waiting_for` 是 `[]`
- `C-6` 写 `depends_on: [R-2/S3]`，main 上 `R-2` 的 `S3` 是 `- S3 负责人逐条回答。（待负责人）` → `C-6` 那一行有 `waiting for R-2/S3: 负责人逐条回答。`，`--json` 里 `state` 是 `owner`；放清单的变更合入了也一样
- 同一条后来改成 `（已满足：C-9）` 并合入 main → `C-6` 没有 `waiting` 标记
- `C-6` 写 `depends_on: [R-2/S8]`，`R-2` 没有 `S8` → `waiting for R-2/S8 (not found)`
