id: BR-2656
title: 新建变更时，按标题列出最多 3 个可能重复的未结束变更，相关度低于 0.4 时不出声
status: active
business: 重复提醒
---

## 规则

`canon change new --title` 和 `canon work start --title` 新建变更成功后，把新标题和每个未结束的变更（主状态不是 `landed`、`dropped`，BR-2571；不含它自己）的标题比相关度，算法按 D-171：分词同 D-90，去掉单独一个汉字的词；每个词的权重是它在 main 和变更分支上全部变更标题（含已结束的）里的 idf；相关度 = 2 × 两个标题共有词的权重和 ÷ 两个标题各自的权重和之和，四舍五入到两位小数。

相关度不低于 0.40 的，按相关度从高到低（相同时按编号）至多列 3 个，每个一行：

`possible duplicate: <C-m> <标题> (relatedness <两位小数>; shared: <共有的词，权重大的在前，逗号分隔>)`

列出时再打印一行怎样回应（BR-2658）：`if one of them is the same work: canon change duplicate <新编号> <C-m> --same; if not: canon change duplicate <新编号> <C-m> --not "<why>"`，并对每个列出的变更写一条 `duplicate.remind` 事件（对象是新变更，`stage: "new"`、`with`、`score`、`shared`）。没有不低于 0.40 的就什么也不打印、不写事件。

提醒不改变命令的退出码、不阻止新建（D-139）；新建被拒时不比较。比较需要的 git 读取出错时打印一行 `duplicate: cannot compare: <错误>`，新建照常成功。

## 例子

- 未结束的 `C-678 声明字段的格式：fields 声明、canon check 校验格式、canon doc set 改值` 存在，`canon change new --title "文档类型声明字段的格式和表态的步骤：新建命令当场要求、canon doc set 改值"` → 退出码 0，输出一行 `possible duplicate: C-678 …`，事件表多一条 `duplicate.remind`
- 只有标题完全不相干的未结束变更 → 退出码 0，没有 `possible duplicate` 行，不写事件
- 5 个未结束变更的相关度都不低于 0.40 → 只列最高的 3 个
- 相关度正好 0.40 → 列出；0.39 → 不列
- 相似的变更已经 `done` → 不列
- 「C-618 的 C 步：教训」已存在，新建「C-626 的 D 步：重复提醒」→ 只共有单个汉字「的」「步」，不列
- `canon work start --title "x" --release R-9`，`R-9` 不存在被拒 → 不比较，不打印
