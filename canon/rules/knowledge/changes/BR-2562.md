## 规则

`canon change new --title "<标题>"` 和 `canon work start --title "<标题>"` 接受同样四个参数，把关联写进新变更文件的 front matter（BR-2561），关联由命令写入，不靠会话事后补（D-148、D-149）：`--release R-n` 写 `release`，`--feature F-n` 写 `feature`，`--issue <n>[,<n>…]` 写 `issues`（编号前可以带 `#`），`--depends C-a[,R-n/S<k>…]` 写 `depends_on`（变更或成功标准，BR-2561）。没给的参数不写对应的键。

`canon change new` 提前建好变更：文件写在当前 checkout 里，状态 `open`，不建 worktree、分支和认领，随所在变更一起合入；在守卫的 main checkout 里照 BR-2409 拒绝。它进了 main 之后，`canon work start <C-n>` 照常开工（BR-2038），关联就是文件里写的，开工不改它们。

参数在分配编号、写文件、建 worktree 之前检查，被拒时什么也不留下：
- 同时给 `--release` 和 `--feature`，`--issue` 里有不是正整数的值，`--depends` 里有既不是变更编号也不是成功标准的值，或者这几个参数和已有变更的编号、`--fix-main` 一起给 → 用法错误，退出码 2。
- `--release` 不是一个版本、`--feature` 不是一个功能模块（`canon change new` 查当前 checkout，`canon work start` 查 main）→ 退出码 3。
- `--depends` 里的变更既不在当前 checkout、也不在 main、也不在任何变更分支上，或里面的成功标准在查版本的那棵树里没有 → 退出码 3，信息写出是哪个。

## 例子

- 变更的 worktree 里 `canon change new --title "导出" --feature F-2 --issue 12,#40 --depends C-3`，`F-2` 和 `C-3` 都存在 → 退出码 0，新文件 front matter 有 `feature: F-2`、`issues: [12, 40]`、`depends_on: [C-3]`，没有新的 worktree 和认领
- 同一个文件随所在变更合入 main 后，`canon work start C-<新编号>` → 开工，文件里的 `feature`、`issues`、`depends_on` 不变
- `canon work start --title "导出" --release R-1 --depends C-3`，`C-3` 只在分支 `change/C-3` 上 → 开工的提交里变更文件有 `release: R-1` 和 `depends_on: [C-3]`
- `canon change new --title "x" --release R-1 --feature F-2` → 退出码 2，没有分配编号
- `canon change new --title "x" --issue abc` → 退出码 2
- `canon work start --title "x" --depends C-99`，哪里都没有 `C-99` → 退出码 3，没有 worktree，没有分配编号
- `canon work start --title "x" --release R-9`，main 上没有 `R-9` → 退出码 3
- `canon change new --title "跟进" --depends R-1/S2`，`R-1` 有 `S2` → 文件里 `depends_on: [R-1/S2]`；`R-1` 没有 `S2` → 退出码 3
- `canon work start C-7 --release R-1` → 退出码 2
- 只给 `--title` → 文件里没有 `release`、`feature`、`issues`、`depends_on`
