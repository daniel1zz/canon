## 规则

计划已经去掉（D-148），步骤之间的先后改写成变更的 `depends_on`（BR-2561）。变更文件 front matter 里的 `plan`、`steps`，和正文里标题是 `## 计划` 的一节，canon 不再读：不论写成什么样（只写一个、格式不对、指向不存在的变更或步骤、表格写错），`canon check` 都不因它们报发现，变更照常读入；在途分支上还带着它们的变更合入时，不因此被拒；`canon change list`（含 `--json`）、`canon brief` 不再输出计划的标记、进度或可开始的步骤，`--json` 里没有 `plan`、`steps`、`plan_progress`。唯一读它们的地方是 BR-2595 的迁移提示。`canon plan` 不再是命令，`canon work start` 不再接受 `--plan` 和 `--step`：都按未知命令或未知选项处理，退出码 2，不建任何东西。两个键仍保留给 canon（BR-2561）。

## 例子

- `C-2` 写 `plan: C-9`、`steps: ["3"]`，没有 `C-9` → `canon check` 没有发现，退出码 0
- `C-2` 只写 `plan: C-1`、没写 `steps`，或写 `steps: [3.1]` → `canon check` 没有发现，`C-2` 照常读入
- `C-1` 的 `## 计划` 节里的表缺 `依赖` 列，或步骤绕成一圈 → `canon check` 没有发现
- 分支 `change/C-5` 上的 `C-5` 写着 `plan: C-1`、`steps: ["2"]`，合入 → 不因这两个字段被拒
- `canon change list --json` → 每一项都没有 `plan`、`steps`、`plan_progress`；`canon change list` 的标记里没有 `plan C-1 step 2`
- `canon plan status` → 退出码 2
- `canon work start --title "x" --plan C-1 --step 1` → 退出码 2，没有分配编号、没有 worktree
