## 规则

`canon change duplicate <C-n> <C-m> --same` 记下「是它」，`canon change duplicate <C-n> <C-m> --not "<理由>"` 记下「不是它」和理由（D-171）。它回应的是事件表里关于这一对变更（不分先后）的 `duplicate.remind`（BR-2656、BR-2657），在哪个 checkout 里运行都行，变更合入、worktree 删掉之后也能回应；不需要认领。

成功时写一条 `duplicate.answer` 事件（对象是 `<C-n>`，`with: <C-m>`、`same`、`reason`），退出码 0，打印 `<C-n> and <C-m>: recorded "same work"` 或 `<C-n> and <C-m>: recorded "not the same work: <理由>"`。同一对可以再回应，最新的一次算数（BR-2659、BR-2571）。回应只是记录，不改变两个变更的状态和文件。

- `--same` 和 `--not` 都没给或都给了、`--not` 的理由去掉空白后为空、少一个编号、两个编号相同 → 用法错误，退出码 2，不写事件；
- 这一对从没记过 `duplicate.remind` → 退出码 3，信息写明没有提醒过这一对，不写事件。

`overlap` 标记（BR-2571）对一个未结束的变更成立，当且仅当它是某条 `duplicate.remind` 的一方，另一方也没结束，而这一对还没有回应。

## 例子

- `C-4` 新建时提醒过 `C-5`，`canon change duplicate C-4 C-5 --same` → 退出码 0，事件表多一条 `duplicate.answer`，`same: true`
- `canon change duplicate C-5 C-4 --not "C-5 只改输出格式"` → 同样记下，对的先后不影响
- 提醒前 `C-4`、`C-5` 在 `canon change list --json` 里 `overlap: true`；回应后两边都是 `false`
- `C-5` 被放弃了，这一对没回应 → `C-4` 的 `overlap` 为 `false`
- `canon change duplicate C-4 C-9 --same`，从没提醒过这一对 → 退出码 3
- `canon change duplicate C-4 C-5`（不带 `--same` 和 `--not`）→ 退出码 2
- `canon change duplicate C-4 C-5 --not "  "` → 退出码 2
