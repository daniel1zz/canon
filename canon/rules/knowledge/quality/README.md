# 质量标准（knowledge/quality）

产品做到什么程度才算好：质量标准文档（`canon/quality/Q-n.md`）、产品的方面清单（`canon/quality/README.md`），以及没有标准或有方面没覆盖时的提醒（D-145、D-146）。

不管：怎样按产品类型调研同类产品、调研结论怎样逐条交代去向（canon-product 的事）；独立 agent 怎样从真实入口判定（C-609 计划的后续步骤）；规则本身怎么写和检查（`knowledge/documents`、`knowledge/check`）；提醒出现在 `canon brief` 和 `canon overview` 的哪个位置（`work/session`、`work/overview`）。

分类：支撑领域。质量标准和规则并列：规则说产品必须怎样工作，由测试证明；质量标准说产品要好到什么程度，由写明的判定人判定。

依赖：`knowledge/documents`（文档的读写和编号）、`knowledge/check`（检查的报告方式）。

## 术语

- **质量标准**：一条能判通过或不通过的产品质量门槛，存为 `canon/quality/Q-n.md`，写明属于哪个方面、来源、由谁判、管哪些领域或路径（BR-2552）。状态 `draft`（AI 起草，已经生效，标明负责人未确认）、`active`（负责人确认过）、`retired`（不再适用，写明原因）。
- **生效的质量标准**：状态是 `draft` 或 `active` 的质量标准。
- **方面**：产品被评判的一个方面，如玩法循环、战斗手感、音效、界面、上手、性能；由调研按产品类型列在 `canon/quality/README.md` 的 `## 方面` 里（BR-2556）。
- **负责人的处置**：方面清单里一个方面写明负责人定为不适用或推迟，附负责人的原话或 `canon human` 的问题编号（BR-2556）。
- **未覆盖的方面**：方面清单里既没有负责人的处置、也没有任何生效的质量标准属于它的方面（BR-2557）。
- **判定人**：谁判一条质量标准过没过：`test`（自动测试）、`agent`（独立 agent）、`owner`（负责人）。
- **判定**：判定人对一条标准在某个构建提交上的一次记录：通过与否、证据路径，写成 `quality.verdict` 事件（BR-2586）；最近记下的一次是现行的。
- **自评**：判定人自己合入过这条标准管的路径上的变更（BR-2588）。
- **判定状态**：已证明、不通过、过期、没判过，由现行判定和之后又合入的变更数算出（BR-2589）。

## 业务

- **质量标准文档**：一条质量标准是什么文档、有哪些字段和节、怎么新建、怎么列出、`canon check` 查它的哪些引用。
- **方面清单**：产品有哪些方面、每个方面是有标准还是负责人定为不适用或推迟、怎样看每个方面的覆盖情况。
- **没有标准时的提醒**：项目一条生效的质量标准都没有、或有方面没覆盖时，在会话开头和总览里怎样提醒；只提醒，不拒绝（D-139）。
- **判定记录**：怎样记下一次判定、负责人的判定怎样引用 `canon human` 的回答、什么算自评（D-145）。
- **判定状态**：现行判定和过期门槛怎样算，列表、状态和总览怎样显示；进议程、开工合入和发布问题里的提醒由 `work/reminders`、`knowledge/releases` 的规则写。
