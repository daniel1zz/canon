## 规则

`canon quality verdict <Q-n> --result pass|fail --evidence <路径> [--commit <提交>] [--by test|agent|owner] [--question <n>]` 记下一条判定（D-145）：

- `<Q-n>` 是生效的质量标准（BR-2552）。不存在，退出码 3；已 `retired`，退出码 2；两种情况都不记。
- `--by` 是这次判定的判定人，不写时取这条标准的 `judge`；写成别的，退出码 2，不记。判定人是 `owner` 的写法按 BR-2587。
- `--commit` 是被判的构建提交，不写时取 main 现在的最新提交；写的提交在仓库里找不到，退出码 3，不记。
- `--evidence` 是证据的路径（录像、截图、报告；可以在仓库外），不能为空，canon 不检查它存不存在。`--result` 只能是 `pass` 或 `fail`。
- 记成一个事件 `quality.verdict`，subject 是标准编号，字段：`commit`（完整提交号）、`result`、`by`、`evidence`、`self`（BR-2588）；负责人的判定另有 `question` 和 `owner_words`（BR-2587）。不写任何文件，所以不需要变更，在 main 的检出里也能运行。
- 输出 `recorded verdict Q-1 pass at <提交前 9 位> by agent`。
- 一条标准可以有多次判定，最近记下的一次是现行的（BR-2589）。

## 例子

- `canon quality verdict Q-1 --result pass --evidence evidence/q1.md`（`Q-1` 的 judge 是 agent）→ 记下 `quality.verdict`，commit 是 main 的最新提交，by 是 agent，退出码 0
- 同上，`Q-1` 的 judge 是 agent，却写 `--by owner` → 退出码 2，不记
- `canon quality verdict Q-9 …`，没有 `Q-9` → 退出码 3，不记
- `--commit` 写一个不存在的提交 → 退出码 3，不记
- `--evidence ""` → 退出码 2，不记
- `Q-1` 已 retired → 退出码 2，不记
