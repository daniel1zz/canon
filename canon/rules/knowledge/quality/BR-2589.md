## 规则

每条生效的质量标准有一个判定状态，每次读时由事件和 git 算出，不存（D-145、D-151）。现行的判定是这条标准最近记下的 `quality.verdict`。

- **没判过**：没有判定。
- **不通过**：现行判定的 `result` 是 `fail`（不论之后合入了多少）。
- **过期**：现行判定是 `pass`，并且之后合入的变更数 N 达到门槛（N 大于或等于门槛），或者现行判定的构建提交在仓库里找不到。
- **已证明**：现行判定是 `pass`，N 小于门槛。

N 是之后的合入数：`land.ok` 事件里，合入的提交在 main 上、不在现行判定的构建提交的历史里，并且改到了这条标准管的范围；一次合入算一个。管的范围按 `covers` 的每一项：写成领域名的，是这个领域的代码目录（领域没有代码目录时是它的规则目录）；其他写法是仓库里的路径（它自己和它之下的文件）；`.` 是整个仓库。

门槛按现行判定的判定人分开设：`by` 是 `owner` 的用 `quality_stale_owner`，默认 150；`by` 是 `agent` 或 `test` 的用 `quality_stale_agent`，默认 30。两个都写在 `canon/config.yaml`，是正整数；写成别的，配置错误，退出码 2。

## 例子

- 没有判定 → 没判过
- 最近一次判定 fail，之后一个变更也没合入 → 不通过
- agent 判 pass，之后在管的路径上合入 29 个变更 → 已证明；30 个 → 过期
- 负责人判 pass，之后合入 30 个 → 已证明（门槛 150）；150 个 → 过期
- 之后合入的 40 个变更都没改管的路径 → 已证明
- 判定 fail 之后又判 pass → 以后一次为准
- 判定的构建提交被改写历史后找不到 → 过期
- `quality_stale_agent: 5` 写在配置里，agent 判 pass 后合入 5 个 → 过期
- `quality_stale_agent: 0` → 配置错误，退出码 2
