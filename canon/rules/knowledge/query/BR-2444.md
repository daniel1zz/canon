## 规则

挑选命令（BR-2443）给出一个能认出的回答后（包括空列表，和含不在候选里、被丢掉的编号的列表），canon 把回答（挑中的编号和理由、丢掉的编号）记在协调数据库的 `related_picks` 表里，键是命令文字和 BR-2443 的整个提示的 SHA-256。之后在这个仓库的任何 checkout 里，`canon context` 或 `canon work review` 遇到同一个键时不运行命令，用记下的回答，输出和第一次相同。所以命令、A 的文字、候选的集合或顺序、某个候选的标题或摘要变了，就再运行一次；只有提示里没有的文字变了，不再运行。

失败（BR-2445 的退出码不为 0、超时、回答认不出）不记，下次照常运行。每次运行命令写一条 `related.pick` 事件，主题是 A 的编号，内容有键、候选数、用时，以及挑中和丢掉的编号或失败的原因；用记下的回答时不写事件。

## 例子

- 同一个 `BR-1` 连续两次 `canon context BR-1` → 命令只运行 1 次，两次输出相同，`related.pick` 事件 1 条
- 第一次在主 checkout 里 `canon context BR-1`，之后在变更 worktree 里对没改过的 `BR-1` 再查 → 不运行命令
- `BR-1` 的正文改了一个字 → 再运行一次
- main 上的命令文字改了 → 再运行一次
- 命令回答 `[]` → 记下；再查时不运行，仍输出 BR-2445 的 `picked none` 那一行
- 命令第一次退出码 1 → 不记；再查时又运行
