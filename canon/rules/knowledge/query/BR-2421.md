## 规则

`canon restatements --hook`（BR-2402）认出被写的文件是一条规则或一个决策时，除了复述，还按 BR-2387 的融合排序算出和它最相关的至多 5 份文档（读文件现在的文字，不调模型）。有相关文档时，标准输出那一行 JSON 的 `additionalContext` 里有一段：第一行 `canon: the documents most related to <编号> (references both ways, shared text and names); check this edit does not contradict them:`，之后每份一行 `- <编号> <标题> (<理由>)`，理由和 BR-2387 的写法相同，不写句子那一行。同时有复述时，复述的说明在前，空一行后是这一段，两段在同一行 JSON 里。没有复述也没有相关文档时什么也不输出。退出码和报错同 BR-2402。

这一段只多花不调模型的计算：在 canon 自己的仓库（962 份文档，其中 474 份候选）上实测，整个 hook 从约 0.26 秒变为约 0.34 秒，排序本身约 80 毫秒（建索引约 60 毫秒，单份文档约 20 毫秒），所以不缓存语料。

## 例子

- 变更的 worktree 里改了 `BR-1`，`shipping` 的 `BR-7` 写 `按 BR-1 退款后发货`，`BR-1` 没有复述 → 输出一行 JSON，`additionalContext` 以 `canon: the documents most related to BR-1` 开头，含 `- BR-7 <标题> (names BR-1`
- 有 8 份相关文档 → 只列 5 行
- 新加的句子复述了 `BR-3`，也有相关文档 → `additionalContext` 先是 `BR-1 restates BR-3` 那一段，空一行后是相关文档那一段
- 仓库里只有 `BR-1` 一条规则，它没有复述 → 没有输出，退出码 0
- `file_path` 是 `src/a.ts` → 没有输出，退出码 0
