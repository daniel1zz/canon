## 规则

`canon context <目标>` 在上下文之后加一段 `# Open review notes`，逐条列出目标（是规则或决策时）、上下文里列出的规则和决策的未处理评审建议（BR-2145），每条一行：`- <文档编号>: <建议原文> (<得到它的变更>, <合入日期 YYYY-MM-DD>)`，那次合入不属于任何变更时括号里只有日期；并说明建议不拦截、不单独开变更，在改这份文档时处理。没有未处理的建议时不输出这一段。

## 例子

- `BR-1` 有未处理的建议“例子缺少边界另一侧”，执行 `canon context billing`（`BR-1` 在 billing 领域）→ 输出 `# Open review notes` 和 `BR-1: 例子缺少边界另一侧`
- 执行 `canon context BR-1` → 同样列出这条建议
- 这条建议是 2026-11-03 合入 `C-9` 时得到的 → 那一行是 `- BR-1: 例子缺少边界另一侧 (C-9, 2026-11-03)`；那次合入不属于任何变更 → `- BR-1: 例子缺少边界另一侧 (2026-11-03)`
- `code_root: src`，`src/work/drop/drop.ts` 导入 `../land/land.ts`，work/land 的 `BR-2` 有未处理的建议，执行 `canon context src/work/drop/drop.ts` → `# Imported domain: work/land` 下列出 `BR-2`，`# Open review notes` 里有 `BR-2` 的建议
- 导入的是别的顶层领域的代码（只列名字，不列规则）→ 不列那个领域里规则的建议
- billing 领域的规则都没有未处理的建议 → 输出里没有 `Open review notes`
