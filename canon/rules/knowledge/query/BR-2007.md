## 规则

`canon context <目标>` 按 BR-2113 选出领域和子领域，对每个选出的领域返回它的 README、它直接包含的每条生效和规划中的规则（规划中的标明，BR-2238）（默认只列标题，`--full` 给全文，BR-2112）、提到其中任一规则的已接受决策，以及提到或在 `rules` 里列出其中任一规则的未完成变更；目标可以是仓库路径（和领域的代码目录双向匹配）、领域名或文档编号。只列标题时，这个领域的 README 列了业务（BR-2430）就按业务分组：按 README 里的顺序，每个业务一个标题行 `business: <业务名> — <README 里的说明>`，下面按编号列出指向它的规则，一条都没有的业务写 `- (no rule yet)`；没有指向任何已列业务的规则排在最后一组，标题行 `in no business (<条数>)`，这样的规则一条都没有时不列这一组；组之间空一行。README 一个业务都没列的领域照旧按编号平铺，其中写了 `business` 的规则在标题后面标 ` [business: <业务名>]`。`--full` 不分组，照旧按编号给每条规则的全文。

## 例子

- 目标 `src/billing/refund.ts`，billing 领域的代码目录是 `src/billing` ，billing 没有子领域 → 返回 billing 的 README 和它的全部生效规则，不返回 auth 领域
- billing 里有一条作废规则、一个提议中的决策 → 两者都不返回
- billing 里有一条规划中的规则 → 返回它
- 目标是变更 `C-1`，它在 `rules` 里列出 billing 的规则 → 返回 billing 领域
- billing 的 README 列了 `退款` 和 `对账`，两条规则写 `business: 退款`、一条没写 `business`，默认只列标题 → 先是 `business: 退款 — …` 和它的两条，然后 `business: 对账 — …` 和 `- (no rule yet)`，最后 `in no business (1)` 和那一条
- billing 的 README 一个业务都没列，一条规则写了 `business: 退款` → 照旧按编号平铺，这一行末尾是 `[business: 退款]`
- billing 的生效规则全都指向已列的业务 → 没有 `in no business` 这一组
- 同一个 billing，加 `--full` → 不分组，按编号给每条规则的全文
