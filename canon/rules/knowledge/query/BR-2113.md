id: BR-2113
title: canon context 按代码路径落到覆盖它的子领域，并带上外层领域
status: active
---

## 规则

领域可以有子领域：`canon/rules/<领域>/<子领域>/`，名字写作 `<领域>/<子领域>`，各有自己的 README。每个领域的代码路径：配置了 `code_root` 时是 `<code_root>/<领域路径>`；没有配置时，顶层领域是 README 的 `code:`，子领域没有代码路径（BR-2116）。`canon context <路径>` 返回代码路径和这个路径匹配的每个领域和子领域，再加上它们外层的每个领域；匹配是双向的：领域的某个代码路径等于目标、是目标所在的目录，或在目标这个目录之下。同一个领域下、代码路径和目标不匹配的子领域不返回（只列名字，BR-2120）。每个返回的领域只带它直接包含的规则（外层领域带的是直接属于外层的规则）；`canon context <领域名>` 返回这个领域、它下面的所有子领域和外层领域；目标是文档编号时，返回它提到的规则所在的领域和外层领域。

## 例子

- `code_root: src`，目标 `src/work/drop/drop.ts` → 返回 work 和 work/drop，不返回 work/land
- `code_root: src`，目标是目录 `src/work`，work/drop 和 work/land 的目录都在它下面 → 返回 work、work/drop 和 work/land
- `code_root: src`，目标 `src/work/db.ts` 只和 work 匹配 → 只返回 work 和直接属于它的规则
- 没有 `code_root`，work 的 `code:` 是 `src/work`，目标 `src/work/drop.ts` → 只返回 work，子领域都不返回
- 目标 `src/work/drop/drop.ts` 导入了 `../land/land.js` 和 `../../billing` → 只返回 work 和 work/drop；不因导入返回 work/land 或 billing，work/land 只在 `Other subdomains, not included` 里列名字，输出里没有 `Imported`（canon 不读源码，D-64）
- 目标 `work` → 返回 work 和它的全部子领域
- 目标是规则 `BR-1`，它在 work/drop 里 → 返回 work 和 work/drop
