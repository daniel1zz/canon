## 规则

领域可以有子领域：`canon/rules/<领域>/<子领域>/`，名字写作 `<领域>/<子领域>`，各有自己的 README 和代码路径。`canon context <路径>` 返回代码路径和这个路径匹配的每个领域和子领域，再加上它们外层的每个领域；匹配是双向的：领域的某个代码路径等于目标、是目标所在的目录，或在目标这个目录之下。同一个领域下、代码路径和目标不匹配的子领域不返回。每个返回的领域只带它直接包含的规则（外层领域带的是直接属于外层的规则）；`canon context <领域名>` 返回这个领域、它下面的所有子领域和外层领域；目标是文档编号时，返回它提到的规则所在的领域和外层领域。

## 例子

- work 的代码是 `src/work`，子领域 work/drop 的代码是 `src/work/drop.ts`，目标 `src/work/drop.ts` → 返回 work 和 work/drop，不返回 work/land
- 目标是目录 `src/work`，work/drop 的代码 `src/work/drop.ts` 和 work/land 的代码 `src/work/work.ts` 都在它下面 → 返回 work、work/drop 和 work/land
- 目标 `src/coord/db.ts` 只和 work 匹配 → 只返回 work 和直接属于它的规则
- 目标 `work` → 返回 work 和它的全部子领域
- 目标是规则 `BR-1`，它在 work/drop 里 → 返回 work 和 work/drop
