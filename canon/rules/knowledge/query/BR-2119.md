## 规则

`canon context <目标>` 的目标是仓库里存在的一个文件时，canon 在运行时读出这个文件里 `import`、`export … from`、`require(...)` 和 `import(...)` 的相对路径（以 `./` 或 `../` 开头），解析成仓库路径：按原样，加源码扩展名（`.ts`、`.tsx`、`.js` 等；写成 `.js` 的也试同名的 `.ts`），或目录下的 `index.*`，都不存在时按原样。每个路径归到代码路径覆盖它、且代码路径最长的那个领域。这些领域里还没有按 BR-2113 选出的，各以 `# Imported domain: <名字>` 列出，写明导入了哪些路径，只列这个领域直接包含的生效规则（默认标题，`--full` 全文），不带它的 README 和外层领域；决策和变更仍只按 BR-2113 选出的领域的规则找。包名导入、落在 `shared` 里或不属于任何领域的路径不带领域。目标是目录、领域名或编号时不读导入。

## 例子

- `code_root: src`，`src/work/land/land.ts` 有 `import { claim } from "../claims/claims.ts"` → 输出有 `# Imported domain: work/claims` 和 work/claims 的规则标题
- 同一个文件导入 `../../kernel/git.ts`，`src/kernel` 在 `shared` 里 → 不因此带任何领域
- 导入 `../db.ts`，它属于已经作为外层领域返回的 work → 不再列一次
- `import { parse } from "yaml"` → 不带领域
- 目标是目录 `src/work/land` → 不读导入
