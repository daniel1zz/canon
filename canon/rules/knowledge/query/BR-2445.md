## 规则

挑选命令（BR-2443）运行后有下面任一情况时，相关文档一段之前输出一行 `related_pick_command: <原因>; the list below is the fused ranking, nothing was picked`，之后这一段和 BR-2387 的输出一样，退出码不变，不当作没有结果、也不悄悄只给融合排序（D-90）：

- 退出码不是 0：原因是 `it exited <退出码>: <标准错误的前 200 个字符，没有时是标准输出的后 200 个字符，都没有时是 no output>`，空白合成一个空格；
- 在 `related_pick_timeout_seconds`（默认 120 秒）内没有结束：canon 停止它和它的子进程，原因是 `it did not finish within <秒数> second(s) (related_pick_timeout_seconds) and was stopped`；
- 标准输出认不出 BR-2443 的 JSON 列表（没有列表、解析不了、是 JSON 却不是列表、某一项既不是字符串也不是带字符串 `id` 的对象、`reason` 不是字符串）：原因写明是哪一种；
- main 上的 `canon/config.yaml` 读不出，或这两个键的值不合格：原因是 `canon/config.yaml on main cannot be read: <原因>`，这时不运行命令。

回答里不在候选中的编号被丢掉，计数写在一行里：还有挑中的候选时，标题行之前输出 `related_pick_command: dropped <个数> id(s) not among the <候选数> candidates: <编号, …>`，列表照 BR-2443；一个也没留下时，原因是 `picked no candidate (dropped <个数> id(s) not among the <候选数> candidates: <编号, …>)`；回答空列表时，原因是 `picked none of the <候选数> candidates`。这两种列表照融合排序。

## 例子

- 命令向标准错误写 `quota exceeded` 后退出码 3 → 一行 `related_pick_command: it exited 3: quota exceeded; the list below is the fused ranking, nothing was picked`，之后是 BR-2387 的那一段，`canon context` 退出码 0
- `related_pick_timeout_seconds: 1`，命令 `sleep 30` → 约 1 秒后输出 `related_pick_command: it did not finish within 1 second(s) …`，命令被停止
- 命令输出 `sorry, no idea` → 原因以 `it printed no JSON list` 开头
- 命令输出 `{"id":"BR-9"}` → 原因以 `it printed JSON that is not a list` 开头
- 命令输出 `[42]` → 原因以 `item 1 of its list is neither an id` 开头
- 命令输出 `["BR-9","BR-999"]`，`BR-999` 不在 5 份候选里 → 标题行之前是 `related_pick_command: dropped 1 id(s) not among the 5 candidates: BR-999`，`BR-9` 列为挑中
- 命令输出 `["BR-999"]` → `related_pick_command: picked no candidate (dropped 1 id(s) not among the 5 candidates: BR-999); the list below is the fused ranking, nothing was picked`
- 命令输出 `[]` → `related_pick_command: picked none of the 5 candidates; the list below is the fused ranking, nothing was picked`
- 命令输出 `["BR-9"]`，退出码 0 → 没有这样的一行
