# 搜索和上下文（knowledge/query）

agent 怎样找到要读的东西：`canon search` 按词或编号找，`canon context <路径|领域|编号>` 给出相关领域的说明、规则、决策和进行中的变更。路径按约定（`code_root` 下的目录和领域一一对应）或顶层领域 README 的 `code:` 对应到和它匹配的领域和子领域，再带上外层领域的说明、目标文件导入的代码所在的领域，以及同一顶层领域下其余子领域的名字；规则默认只列标题，`--full` 给全文。给的是规则或决策的编号时，末尾还列出和它最相关的文档（引用、全文、共用名字三种排名融合，D-90），编辑规则或决策后的 hook 也列这些；main 上配了挑选命令 `related_pick_command` 时，`canon context` 和 `canon work review` 先列它从融合前 50 名里挑中的（BR-2443），hook 不调用它。

## 业务

- **搜索**：`canon search`：按词和按编号找文档，怎么算命中、怎么排、列多少条、找不到时说什么。
- **上下文**：`canon context`：按一个目标（仓库路径、领域名或文档编号）把相关领域现在的全部内容摆出来，给写代码和评审的人用。
- **显示一份文档**：`canon show`：按编号把一份文档的路径和文件原文打印出来。
- **相关文档**：给一份规则或决策找出最相关的几份：怎么排序、列几份、项目可以配一条命令来挑、挑不出来时怎么办。`canon context`、`canon work review` 和编辑后的 hook 都用它。

## 术语

- **上下文**：`canon context` 的输出。
- **代码路径**：配置了 `code_root` 时是 `<code_root>/<领域路径>`；没有时是顶层领域 README 的 `code:`，子领域没有。
- **匹配**：领域的某个代码路径等于目标、是目标所在的目录，或在目标这个目录之下。
- **导入的领域**：目标文件的相对 import 指向的代码所在的领域，运行时从文件里读出，不在任何地方声明。同一个顶层领域下的列出规则标题，别的顶层领域只列名字。
