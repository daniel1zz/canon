## 规则

`canon accept` 验收 main 分支的最新提交（D-89、D-104）。运行处必须签出这个提交且工作区干净，否则以环境错误、退出码 4 结束，什么都不检查。条件按便宜的先行，一次检查完、把不成立的逐条列出：

- `canon check` 没有发现（note 不算发现）；
- 没有未处理的评审意见；其中有未回答裁决问题（BR-2461）的意见不混在普通意见里，单独列成一节 `awaiting the owner's verdict`，每条带问题编号；
- 没有可疑引用（BR-2423），原因里给出条数和 `canon links list`；
- 评审完整：基线（`refs/canon/accepted`，没有时按 D-104 取最早一条合入后评审记录的 `base`，一条记录都没有时这项没有要查的范围）到这个提交之间，`failed` 的评审记录（列出并提示 `canon work review-landed --again <C-n>`）和改了评审要读的文件（BR-2009 的范围：只挪路径或只改 `links` 记录的不算）却不在任何评审记录所属合入里的提交（比如合入时没配 `review`，见 `review.skip`）算不成立；一条评审记录覆盖它那次合入放上 main 的全部提交（记录的 `base` 到 `head`），不只是最后一个；`queued` 或 `running` 的记录不算不成立，算还没完成，每条单独列出写明在等哪一个。

以上有不成立的 → 退出码 1，不跑 floor，还没完成的评审照样列出。都成立但有还没完成的评审 → 退出码 75，也不跑 floor。其余情况看测试：`floor_timing` 不是 `after` 时这个提交在自己的合入里跑过 floor，算测过；是 `after` 时，提交已被后台测过（BR-2222）算测过，main 有未修复的失败记录（BR-2220）→ 列为原因、退出码 1；没测过而后台正在测 → 退出码 75；没测过也没人在测 → 当场跑一次 floor（同 `canon floor watch --now`），失败 → 退出码 1。范围内还有评审在排队或运行、而其他条件都成立 → 退出码 75，信息写明等什么。

全部成立 → 写一条 `accept.ok` 事件（详情有 `commit`），把 `refs/canon/accepted` 比较并交换地移到这个提交：首次创建；新提交必须是旧值的后代，不是 → 退出码 1；并发的另一次验收先移动了，而值已经是这个提交 → 照常成功。输出 `accepted <提交>`，退出码 0。

## 例子

- 全部条件成立、`floor_timing: after`、提交已测过 → `accept.ok` 事件，`refs/canon/accepted` 指向它，输出 `accepted <提交>`
- 再运行一次，什么都没变 → 仍成功，`refs/canon/accepted` 不动
- 有 2 条未处理意见、3 条可疑引用 → 退出码 1，原因列出两项（含 `canon links list`），floor 没有跑
- 一条意见的裁决问题（BR-2461）没人回答 → 退出码 1，这条在 `awaiting the owner's verdict` 一节单独列出，带问题编号
- 范围内一条合入后评审 `failed` → 退出码 1，提示 `canon work review-landed --again <C-n>`
- 范围内一个提交改了 `canon/rules/`，没有评审记录（合入时 `review` 没配）→ 退出码 1，列出这个提交
- 一次合入放上 main 两个改了规则的提交，评审记录只记了后一个，状态 `done` → 两个提交都算评审过，不列出
- 一次合入只改了一份规则 frontmatter 里的 `links` 记录，没有评审记录 → 不列出
- 其他条件都成立，一条评审还在 `queued` → 退出码 75，信息写明在等它，floor 没有跑
- 有 1 条未处理意见，同时一条评审还在 `queued` → 退出码 1，原因列出意见，还没完成一节列出排队的评审
- `floor_timing: after`，提交没测过、当场跑的 floor 失败 → 退出码 1，`refs/canon/accepted` 不动
- main 有未修复的 floor 失败记录（BR-2220）→ 退出码 1，原因写出失败提交和日志，floor 没有再跑
- `refs/canon/accepted` 指向的提交不是这个提交的祖先（分叉的历史）→ 退出码 1，`refs/canon/accepted` 不动
- 两个验收并发，另一个先把 `refs/canon/accepted` 移到了同一个提交 → 这一个照常成功
- `floor_timing: after`，提交没测过、没有后台在测、其他条件都成立 → 当场跑 floor，通过则验收成功，失败退出码 1
- 工作区有未提交文件，或签出的不是 main 的最新提交 → 退出码 4，没有检查、没有事件
- 在 `floor_timing` 不是 `after` 的项目里，其他条件都成立 → 不另跑 floor，直接验收成功
