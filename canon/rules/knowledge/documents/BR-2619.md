## 规则

文档类型（内置的和项目在 `types:` 里声明的）在 `fields` 下按字段名声明 front matter 字段（D-159）：

- `type`：值的格式，取 BR-2546 的槽位类型之一（`text`、`id`、`ids`、`enum`、`pattern`，含义和写法照 BR-2546；`ids` 在 front matter 里写成列表）；
- `none`：可选，`true` 时值也可以写成 `none: <理由>`，理由不能为空，表示会话想过、答案是没有；
- `due`：可选，只能是 `create`，表示这是会话要做的判断，新建这个文档的命令必须当场拿到它（BR-2620）；不写时是可选字段；
- `values`、`pattern`：照 BR-2546。

旧写法（`fields` 是字段名的列表，BR-2054）照样能读：每个名字当作 `type: text`、`due: create`。项目可以给自己的类型声明字段，也可以给内置类型加字段，但不能声明内置类型已经声明的字段（BR-2623），也不能声明 canon 自己写的字段（`id`、`title`、`status`、`passes`、`links` 等，BR-2054 的保留字段）。下面任何一种都是配置错误，所有命令按 BR-2045 以退出码 2 失败，错误写明类型、字段和原因：`type` 不认识；`enum` 没有 `values`；`pattern` 不是合法的 RE2 正则；`due` 不是 `create`；`none` 不是布尔值；声明了内置字段或保留字段。

## 例子

- `types.design.fields.reviewer: { type: text, due: create }` → `canon doc new --type design` 要给 `reviewer`
- `fields: [reviewer]`（旧写法）→ 同上
- `types.change.fields.owner_gate: { type: text }` → 配置错误，`owner_gate` 是内置声明的字段
- `fields.risk: { type: enum }` → 配置错误，`enum` 没有 `values`
- `fields.x: { type: text, due: land }` → 配置错误，`due` 只能是 `create`
