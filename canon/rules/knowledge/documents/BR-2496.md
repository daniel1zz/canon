## 规则

规划中（`status: planned`，BR-2235）的规则可以在 front matter 写 `will_amend: [<规则编号>, ...]`：使它生效的那个变更会一并修改的生效规则（D-127）。

- `will_amend` 不是非空的编号列表（不是列表、空列表、有空字符串）→ `file-invalid`；
- 规则不是规划中却带着 `will_amend` → `file-invalid`，信息说明在使它生效的变更里删掉这个字段，并一并修改它列出的规则；
- 列出的编号是规则自己、不存在、不是规则，或不是生效中的规则 → `canon check` 报 `will-amend-target`，信息写出是哪一种。

带 `will_amend` 的规划中规则，在 `canon context` 的规则全文和规则评审的输入里，`[规划中]` 后面标 `[生效时改 <编号>, ...]`；规则评审输入里改动文档的那一节写一行 `will_amend: <编号>, ...`。评审怎样看待这个声明按 BR-2036。

使规则生效的那次合入（合入前是规划中、带 `will_amend`，合入后是生效、按上面不再带它）的规则评审，输入里另有一节 `# <编号> becomes active in this landing; while planned it declared it would change <目标>`：要求评审把目标当生效规则和它比较，它正文说要在目标里做、目标现在却没有的改动是矛盾；节下给出每条目标的全文（目标也是这次改动的文档时只写一行，全文在上面）。目标在别的顶层领域时也给，预览评审和增量评审都一样；拆分成几次调用时，这一节跟着显示这条规则全文的那一次走，目标的全文也在那一次里。这条规则、它的目标和目标的文本也算进“同样的文档已经评审通过”的判断（BR-2396），所以同样的文档以前通过过，也不复用到这次。

## 例子

- 规划中的 `BR-1022` 写 `will_amend: [BR-300]`，`BR-300` 是生效规则 → `canon check` 不报；`canon context` 里是 `## BR-1022 [规划中] [生效时改 BR-300] …`
- 同上，`BR-300` 已作废 → `will-amend-target`，信息含 `which is retired, not active`
- `will_amend: [BR-1022]`（自己）→ `will-amend-target`，信息含 `itself`；`will_amend: [BR-99]` 不存在 → 信息含 `does not exist`；`will_amend: [D-3]` → 信息含 `not a rule`
- `will_amend: []` 或 `will_amend: BR-300` → `file-invalid`
- 生效规则带 `will_amend: [BR-300]` → `file-invalid`，信息含 `only for a planned rule`
- main 上规划中的 `game/BR-1022` 带 `will_amend: [BR-300]`，`BR-300` 在 `billing`；一次合入把 `BR-1022` 改成生效、删掉字段，没改 `BR-300` → 这次评审的输入含 `# BR-1022 becomes active in this landing; while planned it declared it would change BR-300` 和 `BR-300` 的全文
- 同一次合入把规划中的 `game/BR-1022` 挪到 `game/shipping/BR-1022` 并改成生效 → 仍按编号找到它合入前的版本，评审输入里有激活那一节
