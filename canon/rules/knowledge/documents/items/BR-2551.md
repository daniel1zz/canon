## 规则

内置的变更类型给 `教训` 段声明项的格式（BR-2546）：模板 `{text}(?: → {dest})`，`text` 是文字槽位；`dest` 是 `pattern: "\S.*"`，`required: true`；读不出时提示（`on_mismatch: note`）。`dest` 写这条教训去了哪里：一个机制（规则、检查、命令或 skill 的编号或名字）、`只靠文字：<原因>`，或 `待负责人确认是否固化`（D-24、D-144）。一个变更的教训只有一行 `无`（或以 `无` 开头、后面跟着说明）时，它没有教训，不算项。

## 例子

- `## 教训` 下 `- 子进程拿不到改过的环境 → BR-2101` → 一项，dest `BR-2101`
- `## 教训` 下 `- 评审要先看哈希 → 待负责人确认是否固化` → 一项，dest `待负责人确认是否固化`
- `## 教训` 下 `- 只写了一句话` → 一项，缺少 dest
- `## 教训` 下只有 `无` 或 `无：这是 C-136 自己的缺陷` → 没有项
