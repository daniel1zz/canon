# 文档与编号（knowledge/documents）

每个文档是一个带 front matter 的 Markdown 文件。新建文档时分配编号（永远大于已用过的最大编号）、套用中文模板；状态变化（作废、取代、放弃）只改 front matter，文件保留。

## 业务

- **文档和编号**：一个文档就是一个文件，编号怎么分、不重复、重复了怎么报。
- **新建文档**：新建一份文档时正文从哪来、什么情况下不建、在哪儿不许建。
- **状态变化**：文档在它的状态之间怎么走：接受、作废、放弃，文件都留着。
- **项目声明的文档类型**：项目在 `types:` 下自己声明的文档类型：怎么声明、怎么新建、状态和字段怎么约束、怎么列出和搜索。
- **规则的行为和通过记录**：一条规则的行为由哪几段算出，变更怎么记下它执行过了。
- **领域怎么建**：`canon rule domain` 建出一个领域或子领域：名字怎么写、建在哪、名字像技术层时说一声。
- **待办清单的顺序**：负责人维护的 `canon/backlog.md` 怎么决定变更的先后。

## 术语

- **front matter**：文件开头 `---` 之间的 YAML，写编号、标题、状态等。
- **模板占位行**：模板里 `<...>` 形式的行，必须换成真实内容。
- **待办清单**：`canon/backlog.md`，负责人按先后列出的变更编号；没列进的变更排在后面（D-20）。
- **声明的类型**：项目在 `types:` 下声明的文档类型，有自己的编号前缀、目录和状态；内置的规则、决策、变更、笔记不能删除，只能加必填字段。`types:` 的读取和校验、模板的读取在 `src/knowledge/documents/config-keys.ts`。
- **架构总览**：`canon/architecture.md`，手写，只写上下文、容器和主要流程（D-65）；不是文档类型，没有编号，`canon init` 和 `canon update` 写只有标题的模板。读它的检查在 `knowledge/check`（BR-2352 到 BR-2354），评审把它当上下文（BR-2009）。
- **模板**：`canon/templates/<类型名>.md`，新建文档时的初始正文。
