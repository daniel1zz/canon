## 规则

规则、决策、变更、笔记各自是一个带 YAML front matter 的 Markdown 文件：文件以 `---` 行开头，下一个 `---` 行结束，中间是一个 YAML 映射。front matter 里的 `id` 必须等于文件名里的编号，`title` 不能为空，`status` 必须是这个类型允许的值（规则 active/retired/planned，见 BR-2235；决策 proposed/accepted/superseded，变更 open/done/dropped，不写时取默认值）。文件名是 `BR-n.md`、`D-n-<slug>.md`、`C-n-<slug>.md`、`N-n-<slug>.md`（slug 只含小写字母、数字和连字符）；标题含中文等非 ASCII 字符时只有编号，例如 `D-n.md`；slug 由标题转成小写、非字母数字换成连字符，最多保留 60 个字符。以上任何一条不满足，`canon check` 对这个文件报 `file-invalid`，读取文档库不会因此中断，其余文件照常读取。

## 例子

- `canon/decisions/D-3.md` 的 front matter 写着 `id: D-4` → 报 `file-invalid`，其余文件照常读取
- 标题为 `Use files` 的决策 → 文件名 `D-5-use-files.md`
- 标题为 `知识以文件存放` 的决策 → 文件名 `D-6.md`
- 文件开头没有 `---`、只有开头的 `---` 没有结尾的 `---`，或 front matter 是一个列表 → 报 `file-invalid`
- 决策写 `status: done` → 报 `file-invalid`；变更不写 `status` → 当作 open；规则写 `status: planned` → 合法
- `canon/rules/billing/rule-1.md`、`canon/decisions/D-3_x.md`、`canon/decisions/D-3-Use.md` → 都报 `file-invalid`，文件名格式不对
- 标题是 80 个 `a` 的决策 → 文件名里的 slug 是 60 个 `a`
