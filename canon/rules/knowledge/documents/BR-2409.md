---
id: BR-2409
title: 受守卫的 main 签出里新建文档被拒绝，提示到变更的工作树里去做
status: active
---

## 规则

`canon rule new`、`canon decision new`、`canon change new`、`canon note new`、`canon doc new`、`canon release new` 和 `canon rule domain`（它写领域的 README）在签出了 main 的 checkout 里运行，而且 main 受 canon 的 git 守卫保护时（hook 目录里是 canon 写的 `reference-transaction` hook，任何版本，BR-2123；守卫生效的条件按 BR-2126），退出码 1，不分配编号，不写文件。这样的文件在这里提交不了，留着又会让所有落地以 main-dirty 被拒（BR-2039）。`canon change new` 的提示是 `canon work start --title "<标题>"`；其余命令的提示是在变更的工作树里运行（`canon work start` 开工，进入它打印的路径再运行）。标题去掉首尾空白后为空时仍按 BR-2187 以退出码 2 拒绝。签出的不是 main（变更的工作树、分离的 HEAD）、没有 canon 的守卫（没有 hook，或 hook 不是 canon 写的）、main 上还没有 `canon/config.yaml` 时，行为不变。`canon change new --help` 说明这一点。

## 例子

- `canon init` 并提交到 main 后，在主 checkout 里 `canon change new --title "x"` → 退出码 1，stderr 含 `canon work start --title "x"`，`git status --short` 为空，之后 `canon work start --title "y"` 分到的编号是 C-1
- 同一个主 checkout 里 `canon note new --title "x"` → 退出码 1，stderr 含 `canon work start`，`canon/notes/` 下没有新文件
- 同一个项目里 `canon work start --title "y"` 打印的工作树里 `canon change new --title "x"` → 退出码 0，文件写在那个工作树里
- 删掉 `.git/hooks/reference-transaction` 后，主 checkout 里 `canon note new --title "x"` → 退出码 0，写出 `canon/notes/N-1-x.md`
- `canon init` 之后还没有提交（main 上没有 `canon/config.yaml`），主 checkout 里 `canon decision new --title "x"` → 退出码 0
- 同一个主 checkout 里 `canon rule domain shipping --code src/shipping` → 退出码 1，stderr 含 `canon work start`，`canon/rules/shipping/` 没有建出；在变更的工作树里同一条命令 → 退出码 0，建出 `canon/rules/shipping/README.md`
- 守卫在、main 已提交，主 checkout 里 `canon note new --title "   "` → 退出码 2（BR-2187）
