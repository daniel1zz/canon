## 规则

内置类型声明下面这些新建时表态的字段（`due: create`，BR-2619），新建命令另有同名参数（BR-2620）：

| 类型 | 字段 | 格式 | 参数 |
|---|---|---|---|
| 变更 | `owner_gate` | 文字，或 `none: <理由>` | `--owner-gate` |
| 变更 | `advances` | 成功标准列表（BR-2517），或 `none: <理由>` | `--advances` |
| 规则 | `business` | 文字，必须是它的领域 README 里的业务 | `--business` |
| 决策 | `amends` | 决策编号列表，或 `none: <理由>`（取代用 `--supersedes`，取代的决策也写一个理由） | `--amends` |
| 版本 | `features` | 模块编号列表，或 `none: <理由>` | `--features` |
| 质量标准 | `aspect`、`judge`、`covers` | 照 BR-2552 | 照旧 |

决策的 `amends` 或 `supersedes` 写了决策编号时，`revised_because`（BR-2492 的取值）也是新建时要给的（`--revised-because`）。笔记和模块没有新建时表态的字段。杂务合入时写出的变更文件（BR-2458）不要求这些字段。`owner_gate` 写成 `none: <理由>` 时不算带负责人关卡（BR-2615、BR-2616 只看文字值）。（D-159）

## 例子

- `canon work start --title "x" --owner-gate "研究站剧情设计稿" --advances "R-3/S2"` → 照常
- `canon decision new --title "x" --amends "D-155" --revised-because experience` → 照常；不给 `--revised-because` → 退出码 2
- `canon release new --title "x" --features "none: 先列目标"` → 照常
- `canon feature new --title "x"` → 照常，模块没有表态字段
- 杂务合入写出的变更文件 → 不检查这些字段
