## 规则

`canon rule domain <名字>` 在建出 `canon/rules/<名字>/README.md` 之前，先在标准输出上写一行以 `domains that already exist` 开头的说明：新建的领域是给现有领域都不管的业务用的，为什么要有它按 BR-2446。这一行之后按 BR-2114 的写法列出现在有哪些领域。这一行和这份清单里都不写规则编号，理由同 BR-2096。按 BR-2409 在受守卫的 main 上被拒时什么也不列；下面这些以退出码 2、3、5 拒绝的情况，清单已经列出来了，但什么文件也没建。名字的每一段都只能是小写字母、数字和连字符，否则退出码 2。`<领域>/<子领域>` 只在外层领域已经存在时建出，外层领域不存在时以退出码 3 拒绝，什么也不建。只有没有配置 `code_root` 时的顶层领域写 `--code <路径>`，并且必须写；子领域给了 `--code`、配置了 `code_root` 时给了 `--code`、没有 `code_root` 的顶层领域没给 `--code`，都以退出码 2 拒绝，什么也不建。不带 `--code` 建出的 README 没有 front matter（BR-2117）。领域已经存在时退出码 5，原来的 README 不改动。名字最后一段像技术层的词时按 BR-2317 处理。

## 例子

- 没有 `code_root`，执行 `canon rule domain billing --code src/billing` → 建出 README，front matter 是 `code: [src/billing]`
- 没有 `code_root`，执行 `canon rule domain billing` → 退出码 2
- billing 已存在，执行 `canon rule domain billing/refunds` → 建出 `canon/rules/billing/refunds/README.md`，没有 front matter
- billing 已存在，执行 `canon rule domain billing/refunds --code src/billing/refund.ts` → 退出码 2，没有新文件
- 没有 billing，执行 `canon rule domain billing/refunds` → 退出码 3，没有新文件
- `code_root: src`，执行 `canon rule domain billing` → 建出 README，提示代码目录是 `src/billing`；加 `--code src/billing` → 退出码 2
- 执行 `canon rule domain Billing/x` → 退出码 2
- 任何一次成功的 `canon rule domain` → 第一行以 `domains that already exist` 开头，之后是现有领域的清单，再之后才是新 README 的路径；这一行和清单里没有任何 `BR-` 或 `D-` 开头的编号
- 已经有 billing 和它的业务「退款」，执行 `canon rule domain shipping --code src/shipping` → 清单里有 `billing` 那一行和它下面的 `- 退款`
- 在受守卫的 main 上执行 `canon rule domain billing --code src/billing` → 什么也不列，按 BR-2409 拒绝
- 执行 `canon rule domain Billing/x`（名字不合法）或 `canon rule domain nowhere/sub`（外层不存在） → 清单已经列出来了，然后分别以退出码 2、3 拒绝，什么文件也没建
- billing 已存在，再执行 `canon rule domain billing --code src/billing` → 退出码 5，README 不变
