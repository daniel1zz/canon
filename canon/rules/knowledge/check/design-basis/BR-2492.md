## 规则

在一个变更或杂务的 worktree 里，这次工作新加的决策（相对它的 base 是新文件）如果用 `amends` 或 `supersedes` 修改或取代了别的决策，前置信息就必须有 `revised_because`，值是下面之一：

- `premise`：原来的选择在它自己的前提下就选错了；
- `requirement`：出现了新需求；
- `external`：外部的东西变了（依赖升级、服务改行为）；
- `experience`：负责人对体验的反馈；
- `implementation`：是实现的缺陷，不是方案的问题；
- `undetermined`：原因现在判断不了，或几个原因混在一起分不出主次；决策正文要写明为什么定不了。

没写或写了别的值时，`canon check` 报 `decision-revision-reason`，算 finding，信息列出这六个值和各自的含义。这次工作之前已经在的决策不检查。`amends` 或 `supersedes` 只指向自己、不存在的编号或不是决策的文档时，它没有修改任何决策，已经由 BR-2139、BR-2230 报出，这里不再要求原因。这个原因让 `canon stats` 能分开“一开始就选错”和“需求变了”（D-124）。它是作者申报的：canon 只核对写没写、值是不是这六个之一，不核对真假，也不核对 `undetermined` 的正文写没写理由；几个原因混在一起但分得出主次时写主要的那个，并在决策正文里说明，分不出时写 `undetermined`。

## 例子

- 这次工作新加 `D-2`，`amends: [D-1]`，没有 `revised_because` → `decision-revision-reason`，信息含 `names no \`revised_because\``
- 新加 `D-3`，`supersedes: D-1`，`revised_because: typo` → `decision-revision-reason`，信息含 `(typo)`
- 新加 `D-4`，`amends: [D-1]`，`revised_because: premise` → 没有这条
- 新加 `D-6`，`supersedes: D-1`，`revised_because: undetermined` → 没有这条
- `D-2` 在这次工作之前就已经在了 → 不检查
- 新加 `D-5`，`amends: [D-5, D-99]` → 没有 `decision-revision-reason`（这两个引用各自另有 finding）
