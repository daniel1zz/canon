# knowledge/check/design-basis

管一个改动碰到“单向门”（持久数据、外部边界、依赖）时，canon 怎样提示它写方案依据、怎样记下决策被修改的原因，以及怎样统计这两件事（D-124）。不管方案依据写得好不好，那由规则评审给提示（BR-2493）；也不管体验手感类的选择。

## 术语

- **单向门**：选错以后要付出数据、对外契约或返工代价才能改回来的选择，按改动的路径分三类：持久数据 `persistent`、外部边界 `boundary`、依赖 `dependency`。
- **方案依据**：变更文件里 `## 方案依据` 一节，写沿用了哪个决策的哪一部分、新做了什么选择、最坏的失败、证据和能证伪这个选择的结果。

## 业务

- **方案依据提示**：改到单向门路径时提示写方案依据。
- **决策修改原因**：修改或取代已有决策的新决策写明原因。
- **方案依据统计**：合入时记下、`canon stats` 统计。
