id: BR-2035
title: "残留的模板占位行会被报出来"
status: active
---
## 规则

规则、决策、变更、声明类型的文档和领域 README 里，只要有一整行是模板占位，`canon check` 就报 `template-unfilled`。判定标准：去掉行首的列表符号（`-`、`*`、`+`、`1.`、`1)`，以及跟在后面的复选框 `[ ]`）、加粗符号 `**` 和分隔符（`→`、`：`、`:`）之后，整行只剩一个或多个 `<...>` 片段。写在反引号或代码块里的不算（代码块包括 `~~~` 围起来的，认法同 BR-2004）；一行里除了 `<...>` 还有别的正文时也不算。

## 例子

- 规则的例子里还有 `- <边界上的具体输入或状态> → <必须出现的结果>` → 报 `template-unfilled`
- 变更的“为什么”下面还是 `<要解决什么问题。>` → 报 `template-unfilled`，说明没写就不能合入
- 变更的任务还是 `- [ ] <任务>` → 报 `template-unfilled`
- 决策的方案还是 `1. <方案一>：<采用或否决，以及理由>` → 报 `template-unfilled`
- 领域 README 里还有 `- **<术语>**：<在这个领域里的含义>` → 报 `template-unfilled`
- 正文写 `金额 <100 元时免运费` → 不报（这一行还有别的正文）
- 例子写 `` `canon work start <C-n>` `` → 不报（在反引号里）
- 三个反引号或 `~~~` 围起来的代码块里单独一行 `<占位>` → 不报
