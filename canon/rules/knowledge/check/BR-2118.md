status: active

## 规则

配置了 `code_root` 时，`canon check` 对下列情况报 `code-layout`：某个领域或子领域没有它的目录 `<code_root>/<领域路径>`（报在它的 README 上）；`shared` 的某一项不存在（报在 `canon/config.yaml` 上）；`code_root` 下直接放着一个文件；一个目录既不是领域的目录，也不在 `shared` 的某一项之下，也不是某一项的上级目录。目录只在领域分叉的层级检查：`code_root` 的直接子目录，以及有子领域的领域目录的直接子目录；没有子领域的领域，目录里面怎么组织由它自己定；有子领域的领域目录里直接放的文件属于这个领域。只放测试或测试数据的目录没有例外，按同样的方式检查：测试放在它测的代码旁边，否则把目录列进 `shared`。名字以点开头的文件和目录不检查。没有配置 `code_root` 时不做这些检查。

## 例子

- `code_root: src`，有领域 work，没有 `src/work` → 在 work 的 README 上报 `code-layout`
- 有目录 `src/billing`，没有 billing 领域，`shared` 里也没有它 → 报 `src/billing`
- `shared: [src/kernel]`，有 `src/kernel/git.ts` → 不报
- `shared: [src/lib/kernel]`，有目录 `src/lib` → 不报，它是 `shared` 一项的上级目录
- work 有子领域 work/land，有文件 `src/work/db.ts` → 不报，属于 work
- work 有子领域 work/land，有目录 `src/work/helpers` → 报，work 没有子领域 helpers
- work/land 没有子领域，有目录 `src/work/land/steps` → 不报
- 有文件 `src/index.ts` → 报
- `shared: [src/index.ts]`，有文件 `src/index.ts` → 不报
- 有只放测试的目录 `src/__tests__` → 报
- 没有 `code_root` → 以上都不报
