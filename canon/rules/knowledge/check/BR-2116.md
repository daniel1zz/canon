## 规则

`canon/config.yaml` 可以写 `code_root`（相对仓库根目录的目录，如 `src`）和 `shared`（列表，每项是 `code_root` 下的目录或文件，如 `src/kernel`）。写了 `code_root` 时，每个领域和子领域的代码就是 `<code_root>/<领域路径>`，不在任何地方声明；`shared` 列出不属于任何业务领域的代码（共享内核）。下列情况所有命令都以退出码 2 失败（BR-2045）：`code_root` 不是字符串，是绝对路径，含 `.` 或 `..` 段，或以 `/` 结尾；写了 `shared` 却没有 `code_root`（`code_root: null` 算没有）；`shared` 不是列表，或某一项不在 `code_root` 之内（等于 `code_root` 本身也不行）。`shared: null` 和 `code_root: null` 都等于没写，所以只写 `shared: null` 不是错误。两个都不写时，顶层领域用 README 的 `code:` 列出代码目录（BR-2006），子领域不写代码位置。

## 例子

- `code_root: src`，子领域 work/land → 它的代码是 `src/work/land`
- `code_root: src`、`shared: [src/kernel]` → 命令照常执行
- `shared: [src/kernel]`，没有 `code_root` → 退出码 2
- `code_root: src`、`shared: [lib/x]` → 退出码 2，`lib/x` 不在 `src` 下
- `code_root: src`、`shared: [src]` → 退出码 2，`shared` 的一项不能是整个代码目录
- `code_root: /abs/src` 或 `code_root: ../src` → 退出码 2
- 两个都不写 → 照常执行，代码位置由顶层领域 README 的 `code:` 决定
- 只写 `shared: null`，没有 `code_root` → 照常执行，`shared` 是空列表
- `code_root: null`、`shared: [src/kernel]` → 退出码 2
