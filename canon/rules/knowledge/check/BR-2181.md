title: 测试读仓库自己 floor_skip_paths 下的文件时报 test-reads-skip-path
status: retired
---

## 规则

`canon/config.yaml` 配了 `floor_skip_paths` 时，`canon check` 在测试文件（`tests` 找到的文件）里找读仓库自己文件的路径；路径等于某一项或在某一项下，报 `test-reads-skip-path`，写明测试文件、行号、路径和是哪一项。只改这些路径的合入不跑 floor（BR-2164），这样的测试也就不跑，写错的东西要到下一次跑 floor 的、无关的合入才被发现，被拒的是那一次。合入时用的是 rebase 后那棵树上的 `floor_skip_paths`。

只看 JS/TS 测试文件（`.js`、`.ts`、`.jsx`、`.tsx`，含 `.mjs`、`.cjs`、`.mts`、`.cts`），认得这几种写法：

- 从测试文件所在目录出发：`import.meta.dir`、`import.meta.dirname`、`__dirname`、`new URL("<字面量>", import.meta.url)`；从仓库根目录出发：`process.cwd()`（floor 在仓库根目录运行）；
- 用 `join(...)`、`resolve(...)`（可带 `path.`、`posix.` 前缀）或 `` `${...}/...` `` 接上字符串字面量；起点也可以是同一个文件里先用这些写法赋值的变量（如 `const ROOT = join(import.meta.dir, "..", "..")`）；
- 字面量后面还接着不是字面量的部分（如 `join(ROOT, "canon", name)`）时，已经拼出的目录里含有某一项，也报；
- 文件读取调用（`readFileSync`、`existsSync`、`readdirSync`、`statSync`、`Bun.file` 等）的第一个参数直接是相对路径字面量；
- `cwd:` 设成上面这样拼出的路径，按“在这个目录里运行命令”报，规则同上。

拼出的路径跑到仓库外面的不算。局限：在别的文件里的帮助函数拼出的路径、由变量计算的字符串、子进程自己去读的文件（`cwd:` 不在这些项里时）、其他语言的测试，都查不出来；查不出来的仍靠项目自己保证不在 `floor_skip_paths` 里列测试会读的路径。

## 例子

- `floor_skip_paths: [canon/rules]`，`src/a/a.test.ts` 写 `const ROOT = join(import.meta.dir, "..", "..");` 和 `readFileSync(join(ROOT, "canon/rules/x/BR-1.md"))` → 报 `test-reads-skip-path`，指出 `src/a/a.test.ts` 那一行和 `canon/rules/x/BR-1.md`
- 同一个测试，`floor_skip_paths` 没配 → 不报
- `join(import.meta.dir, "..", "cli", "main.ts")`，`floor_skip_paths: [canon/rules]` → 不报
- `join(root, "canon/rules/x/BR-1.md")`，`root` 是 `mkdtempSync(...)` 建的临时目录 → 不报
- `join(ROOT, "canon", name)`，`floor_skip_paths: [canon/rules]` → 报（`canon` 里含 `canon/rules`）
- `` `${ROOT}/canon/notes/N-1.md` ``、`new URL("../../canon/rules/x.md", import.meta.url)`、`readFileSync("canon/rules/x.md")`、`join(process.cwd(), "canon/rules")` → 都报
- `spawnSync([...], { cwd: ROOT })`，`ROOT` 是仓库根目录 → 报
- `join(import.meta.dir, "..", "..", "..", "..", "x")` 跑到仓库外面 → 不报
- `tests/a.py` 里用 `Path(__file__).parent` 读 `canon/rules` → 不报（局限）
