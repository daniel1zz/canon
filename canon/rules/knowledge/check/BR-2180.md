## 规则

规则不抄写代码里的列表、只举其中几项时，在 front matter 写 `lists`：每项是 `file`（仓库内的相对路径）、`name`（这个文件里的常量名）和 `items`（规则文字里用到的列表项，至少一个）。`lists` 不是这样的非空列表、某项缺字段或多字段、`file` 以 `/` 开头或含 `..` 段 → 这条规则读成 `file-invalid`。

`canon check` 对每条生效规则的每一项核对，任何一处不符报 `list-mismatch`，写明规则、文件和常量：

- `file`、`name` 和每个 `items` 都在规则正文（含 `## 例子`）的反引号里出现；
- `file` 是仓库里的文件，里面有 `name = ...` 的赋值（中间可以有类型标注）；
- 每个 `items` 都是这个赋值右边的字符串字面量（`"x"`、`'x'` 或不带插值的反引号字符串）。右边从 `=` 之后读到括号和字符串之外的第一个换行或 `;`。

`canon check` 每次合入都跑，跳过 floor 的合入也一样（BR-2164），所以只改规则文字也会被核对。

局限：规则正文里新写了一项、却没加进 `items`，查不出来；常量的值不是字面量写成的（由函数算出、从别的常量展开）时，展开来的项不算在里面，要把 `name` 指向写着这些字面量的那个常量。

## 例子

- `lists: [{file: src/stats.ts, name: STAGES, items: [floor]}]`，正文写着 `` `src/stats.ts` ``、`` `STAGES` ``、`` `floor` ``，`src/stats.ts` 有 `export const STAGES: readonly string[] = ["floor", "check"];` → 不报
- 同样的配置，正文把 `` `floor` `` 写成 `` `flor` `` → 报 `list-mismatch`：正文没写 `floor`
- `items: [flor]`，正文也写 `` `flor` `` → 报：`flor` 不在 `STAGES` 里
- `src/stats.ts` 里只有 `STAGES2 = [...]` → 报：没有 `STAGES` 的赋值
- `file: src/gone.ts` 不存在 → 报
- Python 文件 `STAGES = ["floor"]`、Go 文件 `var STAGES = []string{"floor"}` → 按同样方式读，不报
- `ALL = [...STAGES, "claim"]`，`items: [floor]` 指向 `ALL` → 报（`floor` 不是 `ALL` 右边的字面量），改成指向 `STAGES` 后不报
- `lists: []` 或 `lists: [{file: src/stats.ts, name: STAGES}]` → `file-invalid`
- 退役的规则写着对不上的 `lists` → 不报
