id: BR-2344
title: 合入前，本变更碰过的测试文件必须有当前内容的报告，否则 canon check 报 test-report-missing
status: active
---

## 规则

`canon check` 在协调数据库的记账（BR-2337）里，对每个匹配 `tests`、在当前树里存在、没有当前内容（git blob 哈希）记账的测试文件，判断它和本变更是否相关：它是本变更改动的文件（对 main 的合并基点比较，含已提交的、未提交的和未跟踪的，删掉的不算），或者它最近一行记账里有会运行的测试的名字点名了本变更碰过的规则（碰过的规则同 BR-2157：规则文件被改过的，加上变更文件 `rules:` 里列的）。有相关的文件时报一条 `test-report-missing`（一个项目一条，退出码 1，合入也被拒），信息写明文件数、前 5 个文件，和“运行 `canon work test <这些文件>`”；不退回“整文件计”，也不当作“没有测试”。在 main 分支的检出里（不在任何变更里）检查时，没有相关的文件，不报这一项。

## 例子

- 变更改了 `b.test.ts`，没有运行过 `canon work test` → 报 `test-report-missing`，信息含 `b.test.ts` 和 `run canon work test b.test.ts`
- 变更改了 `b.test.ts`，`canon work test` 跑过它 → 不报
- 别人合入改了 `a.test.ts`，本变更没改它、没碰它点名的规则，记账里它只有旧行 → 不报（提示见 BR-2345）
- 别人改了 `a.test.ts`，它的旧行点名 `BR-5`，本变更改了 `BR-5` → 报 `test-report-missing`，因为 `BR-5` 的证据要读它当前的内容
- 本变更什么测试都没碰，`c.test.ts` 是别人新加的、没有任何记账 → 不报 `test-report-missing`；只有它点名的规则报 `rule-untested`（BR-2005）
- 7 个相关的文件没有当前内容的报告 → 一条 `test-report-missing`，信息写 7、前 5 个文件和“and 2 more”
- 在 main 的检出里，`a.test.ts` 没有记账 → 不报 `test-report-missing`
