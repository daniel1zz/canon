title: "任何地方提到的编号都必须存在"
status: active
business: 编号和引用
---
## 规则

文档正文、领域 README 的正文、变更的 `rules` 列表、决策的 `supersedes` 和 `amends`（BR-2139），以及测试名里的规则编号（测试和它们的名字按 BR-2005 认定，包括不会运行的测试；注释、字符串等没有进报告的编号不检查），都必须对应文档库里的一个文档，否则 `canon check` 在提到它的文件上报 `ref-dangling`；写在反引号或代码块里的编号算举例，不检查：代码段以一个或多个反引号开头，到同一行里个数相同的反引号结束（代码本身含反引号时用两个反引号开头）；代码块是三个以上反引号或 `~~~` 围起来的行，到同一字符、至少一样长的围栏行结束，没有结束行时到文件末尾。

## 例子

- 变更正文直接写了一个不存在的决策编号（没有加反引号） → 在该变更文件上报 `ref-dangling`
- 决策正文写“例如 `BR-77`” → 不报
- 领域 README 正文直接写了一个不存在的规则编号（没有加反引号） → 在该 README 上报 `ref-dangling`
- 报告里的测试名是 `BR-7: ...`，而 `BR-7` 不存在 → 在该测试文件上报 `ref-dangling`；这个测试是被跳过的 → 照样报
- 测试文件的注释里写着不存在的 `BR-8`，报告里没有 testcase 带它 → 不报
- 正文写 ``` `` tag`x`(BR-77) `` ```（两个反引号开头的代码段里有反引号），`BR-77` 不存在 → 不报
- 正文里 `~~~` 围起来的代码块中有一行 `BR-77`，`BR-77` 不存在 → 不报；同一行写在代码块外面、不加反引号 → 报 `ref-dangling`
