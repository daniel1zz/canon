id: BR-2004
title: "任何地方提到的编号都必须存在"
status: active
---
## 规则

文档正文、领域 README 的正文、变更的 `rules` 列表、决策的 `supersedes` 和 `amends`（BR-2139），以及测试标题里的规则编号（标题按 BR-2005 认定，包括不会运行的测试的标题；JS/TS 测试文件里标题以外的编号不检查，其他测试文件全文都检查），都必须对应文档库里的一个文档，否则 `canon check` 在提到它的文件上报 `ref-dangling`；写在反引号或代码块里的编号算举例，不检查。

## 例子

- 变更正文直接写了一个不存在的决策编号（没有加反引号） → 在该变更文件上报 `ref-dangling`
- 决策正文写“例如 `BR-77`” → 不报
- 领域 README 正文直接写了一个不存在的规则编号（没有加反引号） → 在该 README 上报 `ref-dangling`
- 测试名写 `BR-7: ...`，而 `BR-7` 不存在 → 在该测试文件上报 `ref-dangling`
- JS/TS 测试文件的注释里写着不存在的 `BR-8`，没有测试标题提到它 → 不报
