## 规则

`canon check`、`canon work test` 和合入时的检查找测试文件时，只扫描 `canon/config.yaml` 里 `tests`（glob 列表）匹配的文件，跳过任何深度上名叫 `node_modules` 的目录，不跟随符号链接（BR-2186），不认任何语言：扩展名、文件名都不是依据。没有写 `tests` 时 canon 不猜哪些是测试文件：`canon check`、`canon work test` 以退出码 2 失败，信息写明没有 `tests` 并给出写法（例如 `tests: ["src/**/*.test.ts"]`）；合入时的检查被拒，原因 `check`，信息相同（BR-2022）。

## 例子

- `tests: ["src/**/*.test.ts"]`，只有 `e2e/a.spec.ts` 的报告里有测试点名 `BR-1` → `BR-1` 报 `rule-untested`
- `tests: ["src/**/*.test.ts", "tools/*.py", "**/*.spec.ts"]` → `src/a.test.ts`、`src/deep/b.test.ts`、`tools/a.py`、`e2e/a.spec.ts` 都是测试文件，`tools/b.rb`、`docs/a.test.ts` 不是
- `tests` 的 glob 匹配到 `node_modules/x/a.test.js` → 不算测试文件
- `src/l.test.ts` 是指向 `src/r.test.ts` 的符号链接 → 只有 `src/r.test.ts` 是测试文件
- 没写 `tests` → `canon check` 退出码 2，信息含 `canon/config.yaml has no \`tests\``
