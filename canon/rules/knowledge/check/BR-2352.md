## 规则

项目的 `canon/architecture.md` 除标题外有内容、并且配了 `code_root` 时，每个领域目录 `canon/rules/<领域路径>`（任意深度，含 `work/land/batch` 这样的子领域）对应的代码目录 `<code_root>/<领域路径>`，以及 `shared` 的每一项，都要在总览里有一个反引号片段，整段等于这个目录（结尾的 `/` 不算）；写了 `src/work/land/batch` 不算写了 `src/work/land`，围起来的代码块里的不算。

没有写出来的，分两种，都不拒绝合入、不改变退出码：

- 领域目录（或 `shared` 项）在这次工作开始前就有的（main 最新提交和这个 checkout 的起点上都已有）：`canon check` 在标准错误上写一行 `hint architecture: ...`，列出前五个目录；
- 这次工作新增的：`canon check` 在标准错误上、`canon work test` 和合入在它们的输出里，为每个这样的目录写一行以 `note: canon/architecture.md: ` 开头的提醒，末尾写 `(BR-2352)`，写明这个目录。

总览不存在、或除标题外没有内容、或没有 `code_root` 时什么都不提醒也不提示。只用领域名和目录名，不读源码。

依据：D-139（提醒代替拒绝）。

## 例子

- 配了 `code_root: src`，总览写了 `` `src/billing` ``，这次工作新增领域 `billing/refunds`，总览没有 `` `src/billing/refunds` `` → 标准错误有 `note: canon/architecture.md: domain billing/refunds is new, but canon/architecture.md names no \`src/billing/refunds\` … (BR-2352)`，退出码 0
- 同上，总览也写了 `` `src/billing/refunds` `` → 没有提醒
- 总览写的是 `` `src/billing/refunds/` ``（结尾有 `/`）→ 算写了
- 总览只在围起来的代码块里写了 `src/billing/refunds` → 算没写，有提醒
- 总览写了 `` `src/billing/refunds/x.ts` `` 而没有目录本身 → 算没写，有提醒
- `shared` 新加了 `src/kernel`，总览没有 `` `src/kernel` `` → 有提醒 `shared path src/kernel is new`
- 领域 `billing/refunds` 早就在 main 上，总览没写它，这次工作没碰领域 → `canon check` 退出码 0，标准错误有一行 `hint architecture:` 点名 `` `src/billing/refunds` ``；合入照常
- 总览除标题外是空的，这次工作新增了一个领域 → 没有提醒
- 项目没有 `canon/architecture.md`，或没有配 `code_root` → 没有提醒，也没有提示
- `canon work test` 在新增了领域目录而总览没写的 worktree 里 → 输出一行 `note: `，退出码仍是测试和 `canon check` 的结果
- 合入一个新增了领域目录而总览没写的变更 → 输出一行 `note: `，合入照常排队
