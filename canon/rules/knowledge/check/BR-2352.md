id: BR-2352
title: 新增领域的代码目录必须写进架构总览，否则拒绝合入
status: active
---

## 规则

项目的 `canon/architecture.md` 除标题外有内容、并且配了 `code_root` 时，每个领域目录 `canon/rules/<领域路径>`（任意深度，含 `work/land/batch` 这样的子领域）对应的代码目录 `<code_root>/<领域路径>`，以及 `shared` 的每一项，都要在总览里有一个反引号片段，整段等于这个目录（结尾的 `/` 不算）；写了 `src/work/land/batch` 不算写了 `src/work/land`，围起来的代码块里的不算。没有写出来的，分两种：领域目录（或 `shared` 项）在这次工作开始前就有的（main 最新提交和这个 checkout 的起点上都已有），只是提示：`canon check` 在标准错误上写一行 `hint architecture: ...`，列出前五个目录，不算发现、不改变退出码、合入和 `canon work test` 不拦；这次工作新增的，`canon check`、`canon work test` 和合入报告一条 `architecture-unlisted`（位置 `canon/architecture.md`），拦截合入，原因 `check`。总览不存在、或除标题外没有内容、或没有 `code_root` 时什么都不报也不提示。只用领域名和目录名，不读源码。

## 例子

- 配了 `code_root: src`，总览写了 `` `src/billing` ``，这次工作新增领域 `billing/refunds`，总览没有 `` `src/billing/refunds` `` → `canon check` 报 `architecture-unlisted`，退出码 1；合入被拒，原因 `check`
- 同上，总览也写了 `` `src/billing/refunds` `` → 不报
- 总览写的是 `` `src/billing/refunds/` ``（结尾有 `/`）→ 算写了
- 总览只在围起来的代码块里写了 `src/billing/refunds` → 算没写，报
- 总览写了 `` `src/billing/refunds/x.ts` `` 而没有目录本身 → 算没写，报
- `shared` 新加了 `src/kernel`，总览没有 `` `src/kernel` `` → 报
- 领域 `billing/refunds` 早就在 main 上，总览没写它，这次工作没碰领域 → `canon check` 退出码 0，标准错误有一行 `hint architecture:` 点名 `` `src/billing/refunds` ``；合入照常
- 总览除标题外是空的，这次工作新增了一个领域 → 不报
- 项目没有 `canon/architecture.md`，或没有配 `code_root` → 不报，也没有提示
- `canon work test` 在新增了领域目录而总览没写的 worktree 里 → 输出 `architecture-unlisted`，退出码 1
