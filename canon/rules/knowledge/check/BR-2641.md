## 规则

`policies.checks`（BR-2638）按检查名设 `canon check` 对这一类发现怎么做（D-164）：`refuse` 是发现（`canon check` 退出 1，合入被拒），`remind` 是提醒（只输出 note），`off` 两样都不出。能设的只有说文档不完整、或者还能写得更好的检查，括号里是默认：

- 默认 `refuse`：`doc-missing-section`、`template-unfilled`、`rule-no-example`、`example-before-change`；
- 默认 `remind`：`decision-options`、`rule-business-unmapped`、`decision-rule-unlinked`、`decision-revision-reason`、`domain-no-decision`。
- 合入的检查 `lessons`（默认 `refuse`）：`--finish` 关闭变更时 `## 教训` 没填（BR-2161）。设 `remind` 时合入照常往下走，输出一行 `note:` 写明没填和配置是 `remind`；设 `off` 时什么都不说。`## 教训` 写了两次（BR-2596）不在此列，照样拒绝。

说文档是错的检查（编号重复、引用不存在、路径不存在、成环等）不在这张表里，写进去是配置错误（BR-2638）：它们保证文档说的是真的（D-139、P5），不能由项目关掉。

`canon check`、`canon work test` 和 `canon accept` 按当前 checkout 的设置判断；合入时（排队之后的检查和入队前的重复拒绝，BR-2388）按 main 上已经合入的 `canon/config.yaml` 判断，不按变更自己的树，所以一个变更改这张表放宽的检查，对它自己不生效，合入之后才对后来的变更生效（同 BR-2074 对评审设置的做法）。

## 例子

- `policies: {checks: {rule-no-example: remind}}`，一条规则没有例子 → `canon check` 输出 note，退出 0
- `decision-options: refuse`，一个决策的方案没有否决项 → `canon check` 报发现，退出 1
- `template-unfilled: off` → 留着模板占位行既不报发现也不出 note
- `ref-dangling: remind` → 配置错误，退出码 2，未知的项
- 变更的分支把 `rule-no-example` 改成 `remind`，同时加了一条没有例子的规则 → 合入按 main 上的默认 `refuse`，被拒
- main 上 `lessons: remind`，`--finish` 关闭一个没填 `## 教训` 的变更 → 合入成功，输出 `note: … policies.checks.lessons is remind …`
- 变更自己的分支把 `lessons` 改成 `off` → 合入仍按 main 上的 `refuse` 拒绝
- 不写 `policies.checks` → 和以前一样
