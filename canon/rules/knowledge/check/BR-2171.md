## 规则

`canon check` 读当前文档里反引号写的片段（围起来的代码块不算，用三个以上反引号或 `~~~` 围起来的都是代码块；代码块里以 `## ` 开头的行也不算段落标题）：生效的规则（不含 `## 例子`，那里是假想项目的输入）、领域 README、已接受的决策（不含 `## 背景` 和 `## 方案`，那里写的是做决定时的情况）、open 的变更，仓库根目录的 `CLAUDE.md` 和 `README.md`，以及 `canon/architecture.md`（整篇，它没有“只写历史”的段落）；已完成或放弃的变更、被取代的决策和笔记是历史，不读。一个片段算仓库路径，当它不含空白和占位符号（`<`、`>`、`*`、`?`、`{`、`}`、`$`、`|`、省略号、编号占位如 `C-n`、`://`），并且满足其一：含 `/` 且第一段是仓库根目录下现有的目录（结尾的 `/` 和 `:行号` 去掉后再看）；或者不含 `/`、是带常见扩展名（`.ts`、`.md`、`.yaml`、`.json`、`.sh` 等）的文件名。这样的路径现在不存在（文件名：仓库里没有同名文件），而 HEAD 的 git 历史里有过它（被移走或删除了），报 `path-missing`，写明文档和路径。历史里从没有过的路径（假想的例子、计划新建的文件）不报。只有现在不存在的候选路径才需要读历史：有这样的路径、但目录不是 git 仓库时，只报一条 `path-missing`，报在第一个写了这种路径的文档上，写明读不到历史；仓库还没有任何提交时什么都不报，因为没有历史就没有被移走的路径。

## 例子

- `CLAUDE.md` 写着 `src/coord`，代码已挪到 `src/work`，历史里有 `src/coord/db.ts` → 报 `path-missing`，指出 `src/coord`
- `README.md` 写着 `state.ts`，这个文件已删除、仓库里没有同名文件 → 报
- open 的变更写着计划新建的 `src/work/remote/`，历史里没有 → 不报
- 规则正文写着 `src/billing`，历史里从没有过 → 不报
- 规则的 `## 例子` 里写着已删除的 `src/old.ts` → 不报；同一路径写在 `## 规则` 里 → 报
- 已接受的决策在 `## 背景` 里写已删除的 `src/old.ts` → 不报；写在 `## 决定` 里 → 报
- `canon/architecture.md` 写着已删除的 `src/old.ts`（在正文里，不在代码块里）→ 报，位置 `canon/architecture.md`
- done 或 dropped 的变更、被取代的决策、笔记里写已删除的 `src/old.ts` → 不报
- `src/<领域>/x.ts`、`src/**/*.test.ts`、单独的 `.ts`、`https://x.dev/a.md` → 不算路径
- `src/kernel/git.ts:12` → 按 `src/kernel/git.ts` 检查，存在就不报
- 已删除的路径写在代码块里（反引号或 `~~~` 围起来的），或者不加反引号 → 不报
- 规则的 `## 规则` 里有一个代码块，块里有一行 `## 例子`，代码块后面写着已删除的 `src/old.ts` → 报
- 目录不是 git 仓库，`CLAUDE.md` 和 `README.md` 都写着不存在的 `src/old.ts` → 只报一条，写明读不到历史
- 目录不是 git 仓库，候选路径都存在 → 不报
- 仓库还没有任何提交，`CLAUDE.md` 写着不存在的 `src/old.ts` → 不报
