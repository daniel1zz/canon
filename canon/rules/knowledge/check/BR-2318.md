## 规则

已有领域的名字最后一段是技术层的词（词表见 BR-2317）时，`canon check` 在标准错误上为它写一行 `note: <README 路径>: domain <名字> is named after a technical layer (`<词>`); name domains by business capability ...`，点名这个词；它不是发现：不进 `--json` 的数组，不进 `<条数> finding(s)` 汇总，不改变退出码，也不拦截合入（BR-2189）。`canon rule domains` 在这样的领域那一行末尾写 `(named after a technical layer: `<词>`; name domains by business capability)`，直到领域改名。

领域 README 必须有非空的 `## 术语` 这一条仍按 BR-2091 报 `doc-missing-section`，拦截合入：术语表是共同语言的最低要求，当前每个领域的 README 都已经有。

## 例子

- 只有 `billing` 领域 → `canon check` 标准错误没有 `note:`，`canon rule domains` 的 billing 行没有 `named after a technical layer`
- 有 `config` 领域，README 有术语 → `canon check` 退出码 0，标准输出 `ok: ...`，标准错误有点名 `config` 的 `note:`；`canon rule domains` 的 config 那一行末尾有 `named after a technical layer`
- 有 `config` 领域，`canon check --json` → 输出 `[]`
- 有 `billing/api` 子领域 → 标准错误有点名 `api` 的 `note:`，退出码仍是 0
- 领域 `billing` 的 README 完全没有 `## 术语` → `canon check` 报 `doc-missing-section`，退出码 1；README 有非空的 `## 术语` → 不报
