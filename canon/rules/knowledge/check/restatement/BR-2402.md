status: active

## 规则

`canon restatements --hook` 从标准输入读 Claude Code 的 PostToolUse 输入，取 `tool_input.file_path`。这个文件在一个 git 仓库的 `canon/rules/` 或 `canon/decisions/` 下、以 `.md` 结尾、仓库有 `canon/config.yaml`、并且读出来是一条规则或一个决策时，只检查它的新行：这项工作开始处（HEAD 和配置的 main 分支的 merge base；在 main 上就是 main 的头）的同一个文件里没有的行，内容相同的行一一抵消；文件那时还不存在时每一行都是新的。新行里按 BR-2401 判定为复述的句子（句子只要有一行是新行就算）有一处以上时，标准输出写一行 JSON：`{"hookSpecificOutput":{"hookEventName":"PostToolUse","additionalContext":"<说明>"}}`，说明写明这些句子复述了别的规则、合入后的规则评审会把新行里的复述记成拦截意见（BR-2405），并按 BR-2401 的格式每处一行。没有复述时不写复述的说明（被写的规则或决策的相关文档按 BR-2421 写进同一行 JSON）；文件不是规则或决策、不在用 canon 的仓库里、输入不是 JSON 或没有 `file_path` 时什么也不输出。有输出和没有输出都以退出码 0 结束。另一种情形是报错：仓库的 `canon/config.yaml` 读不了或 main 分支读不到时按 canon 的退出码报错，由 hook 命令里的 `echo` 提示用户（BR-2404）。它只提示、不拦截：文件已经写下了。

## 例子

- 变更的 worktree 里，`BR-2` 新加了一句照抄 `BR-1` 并点名它的话，hook 输入的 `file_path` 是它 → 输出的 `additionalContext` 含 `BR-2 restates BR-1`，退出码 0
- 同一句在 main 上的 `BR-2` 里就有，这次只改了 `## 例子` → 输出里没有 `restates`
- 新建的决策 `D-5` 里有这样一句 → 每一行都是新的，输出含 `D-5 restates BR-1`
- `file_path` 是 `src/a.ts` → 没有输出，退出码 0
- 标准输入不是 JSON → 没有输出，退出码 0
