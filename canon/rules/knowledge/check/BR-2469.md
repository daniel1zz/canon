## 规则

在变更的 worktree 里（不是主 checkout），`canon check` 对这项工作新增或改动的决策（没有被取代的；和 BR-2431 一样，从工作开始处到现在的差异加上还没跟踪的文件）只看 `## 决定` 段里这次新写的行（和工作开始处的同一个文件比，内容相同的行一一抵消；新文件每一行都是新的）：这些行里点名的每个规则编号（反引号和代码块里的不算），要指向一条 `active` 或 `planned` 的规则，而且这条规则的正文点名了这个决策。不满足的每对报一条发现 `decision-rule-unlinked`，写明决策、规则和原因（没有点名这个决策，或规则的状态），并说明：还没做的行为写一条 `status: planned` 的规则，只当背景引用的规则挪到 `## 背景`。编号指向不存在的文档时只按 `ref-dangling` 报，不另报。这项工作没写的行、主 checkout 里都不报，所以已有的决策不用迁移，只在改到它的 `决定` 时才要补（D-112）。

## 例子

- 变更新建 `D-2`，`决定` 写“退款立即到账，按 `BR-9`”，`BR-9` 正文没提 `D-2` → `decision-rule-unlinked`：``D-2's 决定 names BR-9 in a line this work wrote, but BR-9 does not name D-2``，退出码 1
- `BR-9` 的正文改成提到 `D-2` → 不报
- `决定` 点名的 `BR-11` 是 `planned`，正文提到 `D-2` → 不报；`BR-11` 改成 `retired` → 报，原因写 ``BR-11 is retired``
- `决定` 里写在反引号中的 `BR-12` → 不算点名，不报
- 主 checkout 上已有 `D-3`，`决定` 写“按 `BR-9`”，`BR-9` 没提 `D-3`；变更只改 `D-3` 的 `后果` → 不报；改了 `决定` 那一行 → 报
- 在主 checkout 里运行 `canon check`，新加的 `D-2` 点名没链回的 `BR-9` → 不报
