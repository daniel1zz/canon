## 规则

生效的规则必须至少被一个会运行的测试在标题里写出编号，或者在 front matter 里带 `untested: <原因>`，否则 `canon check` 报 `rule-untested`。JS/TS 测试文件（BR-2046 的 12 种扩展名）里，标题是 `test`、`it`、`describe`、`xtest`、`xit`、`xdescribe` 调用的第一个参数，而且必须是字符串或模板字符串字面量；写在注释、其他字符串、作为夹具的字符串里的编号不算。调用本身或任何一层外层的 `describe` 带 `.skip`、`.todo`、`.failing`、`.if(…)`、`.skipIf(…)` 或其他不认识的修饰，或名字以 `x` 开头（`xdescribe` 也算外层）时，不算会运行；`.only`、`.each(…)` 和后面跟带标签模板表格的 `.each`、`.concurrent`、`.serial`、`.sequential` 不影响。其他扩展名的测试文件（只能通过 `tests` 配置扫到）整个文件里出现的编号都算。

## 例子

- `BR-1` 生效，没有测试提到它，也没有 `untested` → 报 `rule-untested`
- `BR-3` 带 `untested: 由支付服务商的合同保证` → 不报
- 测试文件里有 `test("BR-1: refunds day 30", …)` → `BR-1` 不报
- `test.each([1, 2])("BR-1 case %d", …)` 或 `describe("BR-1", …)` → `BR-1` 不报
- `test.each` 后面跟一个带标签模板写的表格，再跟 `("BR-1 $a", …)` → `BR-1` 不报
- `BR-1` 只出现在注释 `// BR-1` 或字符串 `const s = "BR-1"` 里 → 报 `rule-untested`
- `BR-1` 只出现在夹具字符串 `` `it("BR-1", () => {})` `` 里 → 报 `rule-untested`
- 只有 `test.skip("BR-1: …")`、`test.todo("BR-1")`、`xit("BR-1")`，或 `describe.skip("x", () => { test("BR-1", …) })`，或 `xdescribe("x", () => { test("BR-1", …) })` → 报 `rule-untested`
- 配置 `tests: ["tools/*.py"]`，`tools/a.py` 的注释里写着 `BR-1` → 不报
