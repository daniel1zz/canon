## 规则

生效的规则必须至少被一个会运行的测试的名字点名，或者在 front matter 里带 `untested: <原因>`，否则 `canon check` 报 `rule-untested`。canon 不读测试源码：测试有哪些、会不会运行，以项目的测试框架写的 JUnit 报告为准，按 BR-2337、BR-2339 记在协调数据库里，读法见 BR-2338。一个测试的名字是它外层每一层 `testsuite` 的 `name`、`classname` 和 `name`；规则编号出现在其中任何一个里，就算这个测试点名了它。没有 `skipped` 子元素的测试才算会运行，失败的也算。每个测试文件（`tests` 找到的，BR-2046）读哪一行：当前内容有记账就读它；没有，而且本变更和这个文件无关（BR-2344），读它最近的旧行（并按 BR-2345 提示）；有关，不读旧行。一个测试文件没有任何记账时，它不点名任何规则；`rule-untested` 的信息里写明有几个测试文件没有报告并给出 `canon work test --all`，也列出报告里没有 `testcase` 的测试文件（框架没收集到测试和文件真的没有测试，从报告分不出来，canon 不猜）。规划中的规则（`status: planned`，BR-2235）不要求测试，没有测试也不报；测试点名它也不报。

## 例子

- `BR-1` 生效，没有测试提到它，也没有 `untested` → 报 `rule-untested`
- `BR-3` 带 `untested: 由支付服务商的合同保证` → 不报
- 报告里有测试 `BR-1: refunds day 30` → `BR-1` 不报
- 报告里是 `describe("BR-1")` 下的测试 `first`（外层 `testsuite` 名是 `BR-1`，bun 的 `classname` 也是 `BR-1`）→ `BR-1` 不报
- pytest 的参数化测试，报告里 `name` 是 `test_param[BR-1-one]` → `BR-1` 不报；函数名只能写 `test_BR_1` 的框架，写出的是 `BR_1` → 不算点名 `BR-1`
- `BR-1` 只出现在测试文件的注释或字符串里，报告里没有 testcase 带它 → 报 `rule-untested`
- 报告里只有 `test.skip` 或 `test.todo` 的 `BR-1`（带 `skipped` 子元素）→ 报 `rule-untested`；带 `failure` 的 `BR-1` 测试 → 不报
- `BR-1` 只有 `a.test.ts` 点名，它的内容变了，当前内容没有记账、本变更没碰它也没碰 `BR-1` → 不报，按旧行算，提示 `test-report-stale`
- 同上，但本变更改了 `a.test.ts` → 报 `test-report-missing`，`BR-1` 也报 `rule-untested`
- `BR-1` 只有从没记过账的 `a.test.ts` 点名 → 报 `rule-untested`，信息写“1 test file(s) have no report: run canon work test --all”
- `a.test.ts` 的报告是空的（没有 testcase），`BR-1` 只有它能点名 → 报 `rule-untested`，信息列出 `a.test.ts`
- `BR-4` 是 `status: planned`，没有测试提到它，也没有 `untested` → 不报
