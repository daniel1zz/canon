## 规则

项目的 `canon/architecture.md` 除标题外有内容时，一次工作新增了决策、或给决策加了 `supersedes` 或 `amends`，而新加的这条指向的决策是总览引用着的（编号写在总览正文里，反引号和代码块里的不算），同一次工作要满足其一：总览相对这次工作的起点（`git merge-base HEAD main`，合入时是它下面的提交）有改动；或者这次工作新增或改动的变更文件里、或这次工作从起点以来的某个提交说明里，有一行以 `总览不受影响：` 开头、后面写了原因的话（原因不能还是 `<原因>` 占位）；杂务没有变更文件，只能写在提交说明里。

都不满足时，`canon check` 和 `canon work test` 在指向别的决策的那条决策的文件上写一行以 `note: ` 开头的提醒，末尾写 `(BR-2354)`；合入时在它的输出里同样写一行。退出码不变，不拒绝合入，`canon work test` 也不因此失败。只提醒新加进来的指向：起点上那条决策已经指向它的，不提醒。取代它的决策还是 `proposed` 也算（`amends` 不改被指向决策的状态，`architecture-superseded` 看不见）。总览不存在或除标题外没有内容时不提醒。

依据：D-139（提醒代替拒绝）。

## 例子

- 总览写着 D-5；新决策 D-9 `amends: [D-5]`，这次工作没动总览，变更文件也没有声明 → 标准错误有 `note: canon/decisions/D-9.md: D-9 amends D-5, which canon/architecture.md names; … (BR-2354)`，退出码 0；合入照常排队
- 同上，这次工作改了总览一行 → 没有这行提醒
- 同上，变更文件里写了 `总览不受影响：只改了评审的措辞` → 没有提醒
- 变更文件里写的是 `总览不受影响：<原因>` → 有提醒
- 杂务的一个提交说明里写了 `总览不受影响：总览点名的那句没变` → 没有提醒；提交说明里写的是 `总览不受影响：<原因>` → 有提醒
- D-9 `supersedes: D-5` 且 D-9 还是 `proposed` → 有提醒
- D-9 `amends: [D-7]`，总览没引用 D-7 → 没有提醒
- D-9 早在这次工作的起点就 `amends: [D-5]`，这次工作只改了别的 → 没有提醒
- 总览只在反引号里写了 `D-5`，D-9 修订了 D-5 → 没有提醒
- 总览除标题外是空的 → 没有提醒
- 有提醒时合入照常排队 → 退出码 0
