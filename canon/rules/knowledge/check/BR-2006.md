id: BR-2006
title: "每个规则领域都有 README；没有 code_root 时顶层领域写明它管哪些代码"
status: active
---
## 规则

`canon/rules/` 下的每个目录（包括子领域的目录）都必须有 `README.md`，否则报 `file-invalid`。没有配置 `code_root`（BR-2116）时，顶层领域的 README 必须在 front matter 里用 `code:` 列出至少一个代码路径（目录或文件，路径必须存在，BR-2079），缺少或为空列表时报 `file-invalid`，这样 `canon context <路径>` 不会悄悄漏掉某个领域；子领域的 README 不写 `code:`（BR-2117）。配置了 `code_root` 时，代码位置由约定给出，README 不需要 `code:`。

## 例子

- `canon/rules/auth/` 下只有规则文件、没有 README → 报 `file-invalid`
- 没有 `code_root`，顶层 README 的 front matter 没有 `code:` → 报 `file-invalid`
- 没有 `code_root`，顶层 README 写 `code: []` → 报 `file-invalid`
- 没有 `code_root`，顶层 README 写 `code: [src/auth]` → 不报
- 没有 `code_root`，子领域 `canon/rules/auth/tokens/README.md` 没有 `code:` → 不报 `file-invalid`
- 子领域目录 `canon/rules/auth/tokens/` 没有 README → 报 `file-invalid`
- `code_root: src`，顶层 README 没有 front matter → 不报
