## 规则

一个领域连同它的子领域至少有一条规则，而且全部是 `retired` 时，它管的业务已经离开了这个仓库，代码可以一起删掉。这时 `canon check` 对这个领域不再要求代码：

- 没有配置 `code_root` 时，顶层领域的 README 可以不写 `code:` 或写空列表，不报 `file-invalid`（BR-2006 的例外）；`code:` 里写的路径不存在也不报 `domain-code-missing`（BR-2079 的例外）。
- 配置了 `code_root` 时，这个领域或子领域没有目录 `<code_root>/<领域路径>`、或目录里没有文件，不报 `code-layout`（BR-2118 的例外）。

领域里还有一条 `active` 或 `planned` 的规则，或者一条规则都没有，照旧按 BR-2006、BR-2079、BR-2118 检查。别的检查照旧，比如 README 的 `## 术语`、`## 业务`。

## 例子

- 领域 devlog 的 `code: [tools/devlog]`，规则 `BR-1` 是 retired，`tools/devlog` 已删除 → 不报 `domain-code-missing`
- 同一个领域，README 去掉 `code:` → 不报 `file-invalid`
- devlog 还有一条 active 的规则，`code:` 为空 → 照旧报 `file-invalid`
- 新建的领域还没有规则，`code:` 为空 → 照旧报 `file-invalid`
- 配置了 `code_root: src`，领域 devlog 的规则全部 retired，`src/devlog` 不存在 → 不报 `code-layout`
