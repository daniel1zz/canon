## 规则

功能模块存为 `canon/features/F-n.md`（D-130），状态只能是 `active` 或 `dropped`，没写时是 `active`，其他值报 `file-invalid`。

`canon feature new --title "<标题>"` 分配编号、建文件，状态 `active`，正文是四节模板：目标、范围、不做、成功标准；输出文件路径，退出码 0。和 `canon release new` 一样，在 main 受保护的主 checkout 里拒绝。

`canon feature list` 列出状态是 `active` 的模块，按编号的数值排序，每行：编号、状态、标题，以及哪个版本的 `features` 列出了它（BR-2509），没有版本列出它时写 `(no release)`，被几个版本列出时用逗号分隔；`--all` 连 `dropped` 的一起列；`--json` 输出同样的内容，每项含 `id`、`status`、`title`、`releases`（编号数组）；一个也没有时输出 `(no features)`，退出码 0。

## 例子

- `canon feature new --title 基因体系` → 新建 `canon/features/F-1.md`，状态 active，有目标、范围、不做、成功标准四节
- `R-5` 的 `features: [F-1]` → `canon feature list` 输出 `F-1  active  基因体系  R-5`
- `F-2` 没有版本列出 → 那一行末尾 `(no release)`
- `F-3` 是 dropped → 不带 `--all` 不出现，带 `--all` 出现
- `status: done` → `file-invalid`
- 没有任何模块 → `(no features)`，退出码 0
