## 规则

`canon feature status` 不带编号时，每个 `active` 的模块一行，按编号的数值排序（D-151）：

`<编号>  <状态>  <标题>  <规则各执行状态的条数>  成功标准 已满足 <a>/<总数>  变更 已合入 <a>  进行中 <b>  在等 <c>  可开始 <d>  <完成|未完成>`

规则按 `canon release status` 同样的四种执行状态计数（BR-2328）；规则和成功标准的范围、完成与否按 BR-2568；变更是按 BR-2570 属于这个模块的变更，按 BR-2570 的四种状态计数，只是工作量。没有模块时输出 `(no features)`，退出码 0。

`canon feature status F-n`（`dropped` 的也行）输出这一行，然后规则编号和成功标准按 BR-2329 的写法列出。编号不存在或不是模块，退出码 3，标准输出没有内容。

`--json`：不带编号时是数组，每个模块一个对象，字段同 `canon release status --json`（BR-2328），没有 `shipped_at` 和 `changed_after_ship`；带编号时一个对象，再加 `rules` 和 `criteria_list`（按 BR-2329）。

## 例子

- `F-1`（active）挂着 `BR-3` 已通过、`BR-4` 规划中，成功标准 `S1` 已满足、`S2` 未证明，`C-5` 写着 `feature: F-1` 已合入 → `F-1  active  …  规划中 1  已通过 1 …  成功标准 已满足 1/2  变更 已合入 1  进行中 0  在等 0  可开始 0  未完成`
- 同上，`BR-4` 通过、`S2` 改成已满足 → 末尾 `完成`
- `F-2` 是 dropped → 不带编号时不出现；`canon feature status F-2` 照常输出
- `canon feature status F-1` → 汇总行之后 `规划中: BR-4`、`已通过: BR-3 (…)`，然后 `  F-1/S1 已满足 …`、`  F-1/S2 未证明 …`
- `canon feature status F-9`，没有这个模块 → 退出码 3
- `canon feature status R-1` → 退出码 3
- 没有任何模块 → `(no features)`
- `canon feature status --json` → `F-1` 的 `done` 是 `false`，`criteria.met` 是 1，`changes.landed` 是 1
