## 规则

`canon release migrate-criteria [<R-n 或 F-n>]` 把旧写法的成功标准迁到 BR-2504 的写法（D-151）：只看这一个文档，不给编号时看当前 checkout 里的每个版本和模块文档（按编号的数值，版本在前）。一份文档 `## 成功标准` 一节里不缩进、没有编号的列表项，按它在这一节所有不缩进列表项里的位置（从 1 起）叫 `<文档编号>#<位置>`。

- 不加 `--write`：只输出，不写文件。每份有这样列表项的文档一行 `<文档编号>: <条数> list item(s) without an id`，然后每项一行 `  <文档编号>#<位置> → S<k>  <第一行去掉列表符号>`；最后一行说明没写任何东西、`--write` 会写、`--note` 怎样把说明移出列表。
- `--write`：每个这样的列表项在列表符号后面加上 `S<k> `，`k` 从这份文档已有的最大编号加 1 起，按文档里的先后连续分配；其余内容（标记、子项、续行）不变。在主 checkout 里且 main 受保护时拒绝，和 `canon release new` 一样。
- `--note <文档编号>#<位置>,…`：这些列表项不编号，移出列表：去掉列表符号，作为一段文字放到这一节末尾（原来缩进的子项和续行跟着它），和前面隔一个空行。和 `--write` 一起才写，不加 `--write` 时输出里这一项写 `→ note`。

`--write` 之后每份改了的文档一行 `<文档编号>: numbered S<a>, S<b>…; moved <n> item(s) out of the list (<路径>; commit it with your change)`，没有可编号的或移出的部分省掉。没有任何这样的列表项时输出 `nothing to migrate`。退出码 0；给的编号不是版本或模块，退出码 3；`--note` 写错格式、或指的不是一个没编号的列表项，退出码 2，什么都不写。已经带编号的列表项、缩进的子项和这一节以外的内容不动；再运行一次输出 `nothing to migrate`。

## 例子

- `R-2` 已有 `- S1 甲`，还有 `- 乙（未满足）`、`- 验收方式：自己验收。`；`canon release migrate-criteria` → 输出 `R-2: 2 list item(s) without an id`、`  R-2#2 → S2  乙（未满足）`、`  R-2#3 → S3  验收方式：自己验收。`，文件不变
- 同上加 `--write --note R-2#3` → `R-2` 变成 `- S1 甲`、`- S2 乙（未满足）`，这一节末尾一段 `验收方式：自己验收。`；输出 `R-2: numbered S2; moved 1 item(s) out of the list (canon/releases/R-2.md; commit it with your change)`
- `--write` 后再运行 → `nothing to migrate`
- `canon release migrate-criteria F-3 --write`，`F-3` 有 `1. 丙` → 变成 `1. S1 丙`
- `--note R-2#1`，而 `R-2#1` 已带编号 → 退出码 2，不写
- `--note R-2-3` → 退出码 2
- `canon release migrate-criteria BR-3` → 退出码 3
- 一条下面有缩进的子项 `  - 细节` → 子项不编号，跟着它
