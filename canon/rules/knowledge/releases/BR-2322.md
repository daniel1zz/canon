title: 规则的 release 和 changed_in 标签格式或先后不对时报 file-invalid
status: active
business: 规则属于哪个版本

## 规则

规则 front matter 里的 `release` 必须是一个版本编号（如 `R-1`）；`changed_in` 必须是非空的版本编号列表，并且只能和 `release` 一起出现；`changed_in` 里的每个版本编号（数值）都必须大于 `release` 的：版本只能被之后的版本改，不能被自己或更早的版本改。格式不对的规则文件报 `file-invalid`，它不算存在。两个键都可以不写：没写 `release` 的规则不属于任何版本。

## 例子

- `release: R-1` → 正常
- `release: R-1`、`changed_in: [R-2, R-3]` → 正常
- 两个键都没有 → 正常，规则不属于任何版本
- `release: [R-1, R-2]`（一条规则两个版本）→ `file-invalid`
- `release: v1` → `file-invalid`
- `changed_in: [R-2]`，没有 `release` → `file-invalid`，说 `changed_in` 要和 `release` 一起写
- `release: R-1`、`changed_in: []` → `file-invalid`
- `release: R-1`、`changed_in: [R-1]` → `file-invalid`，说 `changed_in` 要晚于 `release`
- `release: R-2`、`changed_in: [R-1]` → `file-invalid`
- `release: R-2`、`changed_in: [R-3, R-1]` → `file-invalid`（有一个不晚于 `release`）
- `release: R-2`、`changed_in: [R-10]` → 正常（按数值比，不按字符串）
