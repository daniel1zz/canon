## 规则

规则的 front matter 可以写 `feature: F-n`，表示这条行为属于那个功能模块（D-130）。`feature` 必须是一个模块编号，同一条规则不能同时写 `release` 和 `feature`，否则报 `file-invalid`；指向的模块不存在时 `canon check` 报 `ref-dangling`。写了 `feature` 的规则可以写 `changed_in`，它的版本按下一段算。

版本文档 front matter 的 `features` 是模块编号的列表，列出组成这个版本的模块；没写时版本没有模块。“标着某版本 `R-n` 的规则”是写了 `release: R-n` 的规则，加上写了 `feature: F-m` 且 `F-m` 在 `R-n` 的 `features` 里的规则。凡是按“标着某版本的规则”算的地方都用这个范围：`canon release status`（BR-2328、BR-2329）、`canon release ship` 要求全部已通过（BR-2333）、发布后冻结（BR-2326）、`canon show` 和 `canon context` 标出规则的版本（BR-2330；挂在模块上的规则标成 `[feature F-m]`，有 `changed_in` 时同样接在后面）。

## 例子

- `BR-7` 写 `feature: F-1`，`R-5` 的 `features: [F-1]` → `canon release status R-5` 把 `BR-7` 算进去
- 同一个仓库 `F-1` 不在任何版本的 `features` 里 → `BR-7` 不属于任何版本
- `BR-8` 同时写 `release: R-5` 和 `feature: F-1` → `file-invalid`
- `feature: F-99`，没有这个模块 → `ref-dangling`
- `feature: R-5` → `file-invalid`
- `canon show BR-7` → 第一行有 `[feature F-1]`
- `R-5` 的 `features: [F-1]`，`F-1` 的一条规则规划中 → `canon release ship R-5` 退出码 1，列出这条规则
