title: canon release ship 要求标着版本的规则全部已通过
status: active

## 规则

`canon release ship R-n` 只在标着 `R-n` 的规则（作废的不算）全部是“已通过”时继续；有规划中、待 main 测试、待重新执行的规则，或者根本没有规则标着它，退出码 1，信息逐条列出规则编号、标题和状态（没有规则时说明没有可发布的行为），不开变更。标着 `R-n` 的计划（BR-2386）也必须所有步骤已完成（D-79）：有没完成的步骤时同样退出码 1，每个这样的计划一行，写计划变更编号、已完成几步，和没完成的步骤名。版本不存在或不是版本退出码 3，已经发布退出码 5。状态用 `canon release status` 同一套算法。检查顺序：版本是否存在、是否已发布，然后规则状态和计划步骤（两者一起检查，都不满足时先列规则、再列计划），最后才是负责人的确认（BR-2331）；前面的不过，退出码按前面的，不管有没有 yes。

## 例子

- `R-1` 标着 3 条规则，都已通过，负责人已确认 → 继续
- 其中 1 条规划中 → 退出码 1，信息含这条规则的编号和“规划中”
- 其中 1 条待重新执行、1 条待 main 测试 → 两条都列出
- 标着 `R-1` 的规则有一条作废了，其余都已通过 → 继续
- 没有规则标着 `R-1` → 退出码 1，信息说没有可发布的行为
- 规则都已通过，标着 `R-1` 的计划 `C-5` 有 4 步、步骤 `3`、`4` 还没完成 → 退出码 1，信息含 `plan C-5` 和 `not done: 3, 4`
- 标着 `R-1` 的计划所有步骤已完成，规则都已通过，负责人已确认 → 继续
- 有一条规则规划中、计划 `C-5` 也没完成，也没有 yes → 退出码 1，信息先列这条规则、再列 `plan C-5`，不提负责人的确认
- `canon release ship R-9`，没有这个版本 → 退出码 3
- `canon release ship R-1`，`R-1` 已经是 `shipped` → 退出码 5
- `R-1` 已经是 `shipped`，也没有 `ship R-1` 的 yes → 仍是退出码 5
- `R-1` 有规划中的规则、也没有 yes → 退出码 1，信息列出规则，没有说缺 yes
