## 规则

一个 `dropped` 且写了 `merged_into` 的版本，它最终并入的版本是：顺着 `merged_into` 走，跳过途中同样 `dropped` 的版本，走到第一个没取消的版本；走不到（指向不存在的版本、循环、或途中某个取消的版本没写 `merged_into`）就没有（D-133）。

对一个没取消的版本 `R-n`，凡是最终并入 `R-n` 的版本，都当作 `R-n` 的一部分：

- 标着它们的规则（`release`）算“标着 `R-n` 的规则”（BR-2509 的范围），`canon release status`、`canon release ship` 的条件（BR-2333）和发布后冻结（BR-2326）都按这个范围算；冻结时，`shipped_at` 那个提交里标着 `R-n` 或这些版本的规则都不许改标。
- 标着它们的计划变更（`release`）算 `R-n` 的计划（BR-2386）。
- 它们 `features` 里的模块算 `R-n` 的模块，挂在这些模块上的规则也算进来；组合检查（BR-2512）按合起来的模块算。
- 它们自己的成功标准在 `canon overview` 和目标模式里算 `R-n` 的成功标准（BR-2505、BR-2519）。

规则和计划的标签不用改；只有取消后没有地方可去的版本，还标着它的规则和计划才由 BR-2512 拦下。

## 例子

- `R-3` dropped、`merged_into: R-5`，`BR-7` 标着 `R-3` 并已通过 → `canon release status R-5` 把 `BR-7` 算在已通过里，`canon check` 不报 `BR-7`
- `R-2` dropped 并入 `R-3`，`R-3` dropped 并入 `R-5` → `R-2` 的规则也算进 `R-5`
- `R-3` dropped、没写 `merged_into`，`BR-7` 还标着它 → `release-dropped`
- `R-3` 并入 `R-5`，`R-3` 列着 `F-2` → `F-2` 算 `R-5` 的模块；`R-6` 也列着 `F-2` → `release-composition`
- `R-3` 并入 `R-5`，`R-3` 有一条待负责人的成功标准 → `canon overview` 的 `## 等负责人` 里有它
- `R-5` 发布后，把 `BR-7` 的 `release: R-3` 改成 `R-6` → `release-frozen`
