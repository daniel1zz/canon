## 规则

`canon release status` 不带编号时，每个版本（含已发布的）输出一行，按编号的数值排序：编号、状态、标题，以及标着它的规则（作废的不算）按执行状态（规划中、已通过、待 main 测试、待重新执行，状态的算法同 `canon progress`）各有几条；已发布的版本再写“发布后又改了”的条数；然后成功标准一段、关联变更的工作量一段（各按 BR-2569 的写法，范围按 BR-2568），最后 `完成` 或 `未完成`（BR-2568，D-151）。计划的步骤不再显示（D-148）。没有版本时输出 `(no releases)`，退出码 0。`--json` 输出同样的内容：每个版本一个对象，含 `id`、`title`、`status`、`shipped_at`（没发布时 `null`）、`counts`（键 `planned`、`passed`、`waiting`、`rerun`）、`changed_after_ship`（条数）、`criteria`（键 `met`、`unmet`、`owner`、`unproven`）、`changes`（键 `landed`、`in_progress`、`waiting`、`ready`）和 `done`（布尔）。没标版本的规则不出现在任何一行。

## 例子

- `R-1`（shipped）标着 3 条规则，都已通过，其中 1 条写了 `changed_in: [R-2]`；`R-2`（active）标着 1 条规划中、1 条待重新执行 → 两行：`R-1  shipped … 已通过 3 … 发布后又改了 1 …` 和 `R-2  active … 规划中 1 … 待重新执行 1 …`
- 同一个仓库加 `--json` → 数组两项，`R-1` 的 `counts.passed` 是 3、`shipped_at` 是提交号，`R-2` 的 `shipped_at` 是 `null`、`counts.planned` 是 1
- `R-10` 和 `R-2` 都有 → `R-2` 在前
- 标着 `R-1` 的一条规则作废了 → 不计入 `R-1` 的任何数量
- 没有任何版本 → `(no releases)`，退出码 0
- 一条规则没有 `release` → 哪一行也不计它
- `R-2` 有成功标准 `S1` 已满足、`S2` 未证明，`C-5` 写着 `release: R-2` 已合入，`C-6` 写着 `release: R-2` 还 open → 那一行有 `成功标准 已满足 1/2`、`变更 已合入 1  进行中 0  在等 0  可开始 1`、`未完成`；`--json` 里 `criteria.met` 是 1、`changes.ready` 是 1、`done` 是 `false`
- `C-5` 是有计划的变更，写着 `release: R-2` → 那一行没有计划的步骤数，`--json` 没有 `plans`
