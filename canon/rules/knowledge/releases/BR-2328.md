## 规则

`canon release status` 不带编号时，每个版本（含已发布的）输出一行，按编号的数值排序：编号、状态、标题，以及标着它的规则（作废的不算）按执行状态（规划中、已通过、待 main 测试、待重新执行，状态的算法同 `canon progress`）各有几条；已发布的版本再写“发布后又改了”的条数；之后，每个标着这个版本的计划（BR-2386）按编号写 `计划 C-n 已完成 <n>/<总数> (<百分比>%)`，已完成按 D-77 的算法只算 main 上 `done` 的变更（D-79）。没有版本时输出 `(no releases)`，退出码 0。`--json` 输出同样的内容：每个版本一个对象，含 `id`、`title`、`status`、`shipped_at`（没发布时 `null`）、`counts`（键 `planned`、`passed`、`waiting`、`rerun`）和 `changed_after_ship`（条数）；有计划标着这个版本时再加 `plans`，每项含 `id`、`title`、`total`、`done`、`percent`，没有时没有这个字段，输出和以前完全一样。没标版本的规则不出现在任何一行。

## 例子

- `R-1`（shipped）标着 3 条规则，都已通过，其中 1 条写了 `changed_in: [R-2]`；`R-2`（active）标着 1 条规划中、1 条待重新执行 → 两行：`R-1  shipped … 已通过 3 … 发布后又改了 1` 和 `R-2  active … 规划中 1 … 待重新执行 1`
- 同一个仓库加 `--json` → 数组两项，`R-1` 的 `counts.passed` 是 3、`shipped_at` 是提交号，`R-2` 的 `shipped_at` 是 `null`、`counts.planned` 是 1
- `R-10` 和 `R-2` 都有 → `R-2` 在前
- 标着 `R-1` 的一条规则作废了 → 不计入 `R-1` 的任何数量
- 没有任何版本 → `(no releases)`，退出码 0
- 一条规则没有 `release` → 哪一行也不计它
- `C-5` 的计划 4 步、1 步已完成，写了 `release: R-2` → `R-2` 那一行的末尾有 `计划 C-5 已完成 1/4 (25%)`；`--json` 里 `R-2` 有 `plans: [{"id":"C-5",…,"total":4,"done":1,"percent":25}]`，`R-1` 没有 `plans`
- 计划 3 步、1 步已完成 → `计划 C-5 已完成 1/3 (33%)`（百分比向下取整，同 BR-2373）
- 没有任何计划标着版本 → 输出和以前完全一样
