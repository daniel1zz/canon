## 规则

版本文档 `## 成功标准` 一节里，每个不缩进的列表项（行首是 `- `、`* ` 或 `数字. `）是一条成功标准，它下面缩进的子项和续行都属于它。一条成功标准的状态只看它第一行末尾的标记（括号全角半角都算，冒号全角半角都算）：

- `（已满足：<证据>）`：证据里至少写了一个文档编号（写在反引号里的是举例，不算，同 `canon check` 的引用规则）→ 已满足，证据就是这些编号；一个编号也没有 → 未证明。
- `（未满足）` 或 `（未满足：<说明>）` → 未满足。
- `（待负责人）` 或 `（待负责人：<说明>）` → 待负责人。
- 没有标记，或括号里是别的内容 → 未证明。

这条成功标准的文字是第一行去掉列表符号和末尾标记。版本标着的规则全部已通过，不会让任何一条成功标准变成已满足（D-129）。证据编号不存在时由 `canon check` 照常报 `ref-dangling`。成功标准的状态在 `canon overview`（BR-2505）和 `canon brief`（BR-2506）里看得到。

## 例子

- `- 标着 R-5 的规则全部通过。（已满足：BR-584、C-497）` → 已满足，证据 `BR-584`、`C-497`
- `- 负责人玩通主线。(已满足: C-12)`（半角括号和冒号）→ 已满足，证据 `C-12`
- `- 负责人玩通主线。（已满足：负责人说可以了）` → 未证明（没有编号）
- `` - 负责人玩通主线。（已满足：`C-12`） `` → 未证明（反引号里的编号是举例）
- `- 五个体系各有构筑通关。（未满足：还差两个）` → 未满足
- `- 负责人完整玩通主线前半部分。（待负责人）` → 待负责人
- `- 不需要人在旁边解释。` → 未证明
- `- 不需要人在旁边解释。（见 N-4）` → 未证明（不是三种标记之一）
- 一条下面有缩进的子项，子项末尾写了 `（已满足：C-3）` → 不影响这一条，只看第一行
- 版本文档没有 `## 成功标准` 一节，或这一节没有列表项 → 0 条成功标准
- 版本的规则全部已通过，成功标准都没有标记 → 每条都是未证明
