## 规则

`canon feature drop <模块编号>` 把模块的 `status` 改成 `dropped`，写在运行它的工作树里，随所在的变更合入（D-130）；输出 `<模块编号> → dropped (<文件路径>; commit it with your change)`，退出码 0。合入时这项改动按 BR-2510 列出，还挂在它上面的规则和还列着它的版本由 `canon check` 拦下（BR-2512）。

- 已经是 `dropped` → 输出 `<模块编号> is already dropped`，不写文件，退出码 0。
- 列着它的版本里有已发布的 → 退出码 1，提示已发布版本的模块不能取消（BR-2515），文件不变。
- 编号不是一个模块 → 退出码 3。
- 在 main 受保护的主 checkout 里 → 和 `canon release new` 一样拒绝。

## 例子

- `F-2` active，没有已发布的版本列着它 → 文件里变成 `status: dropped`，退出码 0
- 再运行一次 → `F-2 is already dropped`，退出码 0
- `F-1` 在已发布的 `R-1` 的 `features` 里 → 退出码 1
- `canon feature drop R-1` → 退出码 3
