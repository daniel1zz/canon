## 规则

`canon release drop <版本编号> [--into <版本编号>]` 把版本的 `status` 改成 `dropped`；给了 `--into` 时再写 `merged_into: <版本编号>`，表示它并进了那个版本；写在运行它的工作树里，随所在的变更合入（D-130）。输出 `<版本编号> → dropped (<文件路径>; commit it with your change)`，退出码 0。有 `--into` 时，它的规则、计划、模块和成功标准按 BR-2521 算进最终并入的版本，不用改标签或那个版本的 `features`；没有 `--into` 时，还标着它的规则和计划由 `canon check` 拦下（BR-2512）。两种情况合入时这项改动都按 BR-2510 列出。

- 已经是 `dropped` → 输出 `<版本编号> is already dropped`，不写文件，退出码 0。
- 版本是 `shipped` → 退出码 1，提示已发布的版本不能取消（BR-2332）。
- `--into` 指向自己、不存在的版本、已发布或已取消的版本 → 退出码 1，文件不变。
- 编号不是一个版本 → 退出码 3。
- 在 main 受保护的主 checkout 里 → 和 `canon release new` 一样拒绝。

## 例子

- `R-3` planned → `status: dropped`，没有 `merged_into`
- `canon release drop R-3 --into R-4`，`R-4` active → `status: dropped`、`merged_into: R-4`
- `--into R-3`（自己）→ 退出码 1
- `--into R-1`，`R-1` 已发布 → 退出码 1
- `R-1` 已发布 → 退出码 1
- 再取消一次 → `R-3 is already dropped`，退出码 0
