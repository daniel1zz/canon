## 规则

`canon links confirm <引用方> <被引方>` 复核一条引用：引用方读过被引方现在的文字、需要时改好了自己之后运行。引用可疑时，把被引方现在的指纹（BR-2423）记到引用方 front matter 的 `links` 映射里，键是被引方的编号，同时去掉 `links` 里正文已经不再点名的编号，键按编号排序，正文不动；输出 `confirmed <引用方> -> <被引方> (<指纹>)`，退出码 0。引用不可疑时什么都不写，输出 `<引用方> -> <被引方> is not suspect; nothing written`，退出码 0。

有记录的引用只看记录：被引方现在的指纹等于 `links` 里记的值就不可疑，不等就可疑，起点提交（BR-2424）和引用方自己的改动都不参与。所以按“先改好引用方、再复核”的顺序，复核时引用仍然可疑，记录照常写下。`links` 在 front matter 里，不改变规则的行为哈希，复核不会让引用方变成待重新执行。

起点提交读不出来时按 BR-2427 报读失败，什么都不写，这一项先于下面的检查，引用已有记录时也一样。引用方或被引方不存在、引用方的正文没有点名被引方时，退出码 3，什么都不写；引用方不是没作废的规则或没被取代的决策时，退出码 2；在签出受守卫的 main 的 checkout 里运行时，退出码 1，提示到变更的 worktree 里运行（同 BR-2409 的理由）。`links` 的键是规则或决策的编号，值是 16 个十六进制小写字符的指纹；不是这个格式时，`canon check` 对这个文件报 `file-invalid`，信息含 `links`。

## 例子

- `BR-1` 到 `BR-2` 可疑，运行 `canon links confirm BR-1 BR-2` → `BR-1` 的 front matter 多出 `links:` 下的 `BR-2: <BR-2 现在的指纹>`，输出 `confirmed BR-1 -> BR-2 (…)`，退出码 0；之后 `canon links list` 不再列它
- 复核之后 `BR-2` 的规则段又改了 → 又可疑
- 在变更的分支上复核了（记下 `BR-2` 的旧指纹）并改了 `BR-1` 的规则段，同时 main 上 `BR-2` 又改了并先合入，rebase 之后 → 仍然可疑（只看记录）
- `BR-2` 改了以后，先改了 `BR-1` 的例子、没复核 → 仍然可疑；这时运行 `canon links confirm BR-1 BR-2` → 写下记录，输出 `confirmed BR-1 -> BR-2 (…)`
- `BR-1` 到 `BR-2` 不可疑时运行 → 输出 `BR-1 -> BR-2 is not suspect; nothing written`，文件不变，退出码 0
- `BR-1` 的 `links` 里还有正文已经删掉的 `BR-3`，复核 `BR-2` → `BR-3` 被去掉
- `canon links confirm BR-1 BR-9`，`BR-1` 的正文没点名 `BR-9` → 退出码 3
- `canon links confirm BR-1 BR-2`，`BR-1` 已作废 → 退出码 2
- 在受守卫的 main 上运行 → 退出码 1，文件不变
- `links:` 写成 `BR-2: abc` → `canon check` 报 `file-invalid`，信息含 `links`
- 没设 `links_since`，`BR-1` 的 `links` 里已有 `BR-2` 的记录 → `canon links confirm BR-1 BR-2` 照样按读失败退出，文件不变
