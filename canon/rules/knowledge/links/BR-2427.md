## 规则

`canon links list` 列出整个项目现在全部可疑的引用（BR-2423），按引用方编号再按被引方编号排序（编号按前缀和数字），每条一行 `<引用方> -> <被引方>: <原因>`，原因按基准写：有记录时 `<被引方> changed since it was confirmed`（BR-2425）；按起点提交比较时 `<被引方> changed since <起点的 7 位短编号>`；起点之后写的、没有记录时 `<被引方> named after <起点的 7 位短编号> and never confirmed`（BR-2424）；最后一行是 `<n> suspect reference(s) in <m> document(s); re-read the named document, fix the referring one if needed, then: canon links confirm <referring> <named>`，没有时是 `no suspect references`。`--json` 只输出数组，每项 `{ "from", "to", "basis", "since" }`，`basis` 是 `confirmed`、`start` 或 `new`（对应上面三种原因），`since` 总是起点的完整提交编号（三种都写，仓库还没有提交时是 `null`）。有可疑引用也是退出码 0。

起点提交读不出来（BR-2424 说的那几种，以及不是 git 仓库、git 出错）时退出码 4，错误信息写明原因；仓库还没有提交不算失败。

## 例子

- 起点提交 `1a2b3c4…`，`BR-1` 到 `BR-2` 按起点可疑，`D-1` 到 `BR-2` 有记录、`BR-2` 之后又改了 → 两行 `BR-1 -> BR-2: BR-2 changed since 1a2b3c4` 和 `D-1 -> BR-2: BR-2 changed since it was confirmed`，最后一行 `2 suspect reference(s) in 2 document(s); …`，退出码 0；`--json` 第一项 `{"from":"BR-1","to":"BR-2","basis":"start","since":"1a2b3c4…"}`
- 起点之后新写的 `BR-3` 点名 `D-1`，没有记录 → `BR-3 -> D-1: D-1 named after 1a2b3c4 and never confirmed`
- `BR-10` 和 `BR-9` 都有可疑引用 → `BR-9` 那行在前
- 没有可疑引用 → 输出 `no suspect references`，退出码 0；`--json` 输出 `[]`
- 有可疑引用时 → 退出码仍是 0
- 起点提交的某个文件在对象库里缺失、`git cat-file` 出错 → 退出码 4
