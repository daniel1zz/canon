## 规则

`canon work land --finish` 把变更 rebase 到 main 之后、记下要检查的提交（BR-2106）之前，如果最上面仍是这个变更的关闭提交（BR-2018），就给这个变更新加的每条引用写下复核记录（BR-2425 的 `links`），并把这些文件改进关闭提交里。之后检查、floor、评审和移动 main 认的都是改过的这个提交，BR-2018 撤回时认的也是它，所以改写本身不算 `moved-during-land`。

- 新加的引用：引用方在 rebase 前的分支上点名了被引方，在分支离开 main 的那个提交里没有点名（新建的引用方也算）。
- 记录的值：被引方在 rebase 前的分支上的指纹（BR-2423），就是作者读到的版本。所以被引方在 main 上同时改过时，合入后这条引用可疑（`changed since it was confirmed`）；没改过就不可疑。
- 已经有记录的引用保留原记录；rebase 前的分支上没有被引方（它是从 main 来的）时不写，这条引用保持可疑。同时去掉 `links` 里正文已不再点名的编号，和 `canon links confirm` 一样。
- 只改这个变更自己新加了引用的文档。写在 rebase 之后，所以不会让 rebase 冲突；写在关闭提交里，所以这次合入没让 main 移动时，记录随关闭提交一起撤回（BR-2018），合入进程被杀后下一次运行时的撤回（BR-2309）也一样。
- 写了记录时输出一行 `confirmed <n> reference(s) this change added, in <C-n>'s close commit: <引用方> -> <被引方>, …; …`。写文件或改提交失败时合入被拒，原因 `environment`。

不带 `--finish` 的合入、关闭提交上面又有了别的提交时，以及和别人的合入一起测的批次成员（BR-2172），都不写记录，它们新加的引用保持可疑，直到 `canon links confirm`。

## 例子

- 变更新建 `BR-3`，正文点名 `BR-2` 和 `BR-9`；排队期间 main 改了 `BR-2` 的规则段 → 合入后 main 最上面的关闭提交含 `BR-3` 的文件，`links` 里 `BR-2` 是旧指纹、`BR-9` 是当前指纹；`BR-3 -> BR-2` 可疑，`BR-3 -> BR-9` 不可疑；输出 `confirmed 2 reference(s) this change added, in C-1's close commit: BR-3 -> BR-2, BR-9`
- 同一个变更还改了 `BR-1` 的规则段，`BR-1` 在分支离开 main 时就点名了 `BR-2` → `BR-1` 不写记录，按起点提交判断（BR-2424）
- 同样的变更，floor 失败、合入被拒 → 关闭提交撤回，`BR-3` 的文件里没有 `links:`，worktree 干净
- 变更里已经用 `canon links confirm` 复核过 `BR-3 -> BR-2` → 保留那条记录，不重写
- 不带 `--finish` 合入 → 不写记录，`BR-3 -> BR-2` 在 main 上是 `named after … and never confirmed`
