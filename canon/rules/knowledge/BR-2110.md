id: BR-2110
title: 方案里的来源要写明出处和原文摘录
status: active
---

## 规则

决策 `## 方案` 段里写到“来源：”的行，必须是 `来源：<网址或仓库里的文件路径> “<原文摘录>”`：网址以 `http://` 或 `https://` 开头；文件路径是仓库里的相对路径，不能是绝对路径，也不能含 `..`，可以带 `:行号`，去掉 `:行号` 后必须是仓库里现有的文件（不是目录），或者是 HEAD 的 git 历史里有过的文件（后来被挪走或删除了，来源写的是做决定时的原文）；摘录放在中文引号里，去掉多余空白后至少 8 个字符。格式不对，或者路径现在不是文件、历史里也从没有过这个文件时，`canon check` 报 `source-malformed`；只有现在不是文件的路径才读历史，读不到历史（目录不是 git 仓库）时照样报并写明读不到历史，仓库还没有提交时历史为空、照样报。只在历史里有过的文件，放行的是 main 上已有的来源：本次新增的来源合入时仍要指向将成为 main 的树里的文件、且文件包含摘录（BR-2111），不去历史版本里找。仓库文件现在还在时，摘录是否仍在文件里由 `canon check` 核对（BR-2252）；网址的摘录只在合入时核对（BR-2111）。模板留下的占位行不算。

## 例子

- `- 来源：https://arxiv.org/abs/2310.01798 “struggle to self-correct their responses”` → 不报
- `- 来源：src/knowledge/check/check.ts “export function check(”` → 不报
- `- 来源：arXiv 上那篇论文` → 报 `source-malformed`，没有摘录
- `- 来源：/Users/a/x.ts “some long quote”` → 报，绝对路径
- `- 来源：https://example.com “太短”` → 报，摘录不到 8 个字符
- `- 来源：arXiv “struggle to self-correct”`，仓库里现在和历史里都没有叫 `arXiv` 的文件 → 报，不是仓库里的文件
- `- 来源：src/knowledge/check/check.ts:12 “export function check(”`，文件存在 → 不报
- `- 来源：src/knowledge “export function check(”`，`src/knowledge` 是目录，历史里只有它下面的文件 → 报
- `- 来源：src/old/refund.ts “export function refund(”`，文件已挪到别处，HEAD 的历史里有过 `src/old/refund.ts` → 不报
- `- 来源：src/biling/refund.ts “export function refund(”`，错别字，历史里从没有过这个文件 → 报
- 目录不是 git 仓库，`- 来源：src/old/refund.ts “export function refund(”` 现在不存在 → 报，写明读不到 git 历史
- `- 来源：../x.ts “some long quote”` → 报，路径含 `..`
- 仓库已初始化但还没有任何提交，`- 来源：src/old/refund.ts “export function refund(”` 现在不存在 → 报 `source-malformed`
