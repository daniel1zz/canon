# 计划（knowledge/plans）

一项大工作拆成有先后依赖的步骤、由多个变更分头做时，进度怎么看：变更文件里的计划表、变更对步骤的引用、每一步的状态，以及 `canon plan status`（D-77）。

不管：版本（`knowledge/releases`）怎么按标着它的规则和计划算进度、能不能发布（D-79），这里只提供计划步骤的状态；待办顺序是负责人排的变更先后（`canon/backlog.md`），不带依赖；怎么把一个大需求拆成步骤是 `canon-triage` 的事。

分类：支撑领域。步骤和依赖写在变更文件里，状态每次从变更的状态算出，不另存。

依赖：`knowledge/documents`（读变更文件和它的 front matter）、`work/session`（还没合入、只在自己分支上的变更）。

## 术语

- **计划**：变更文件里 `## 计划` 一节写的步骤表。放计划的变更叫计划变更；计划变更自己做不做某一步、关没关，都不影响计划。
- **步骤**：计划表的一行：步骤名（如 `1`、`2a`、`3.1`）、内容、依赖的步骤。
- **步骤的变更**：front matter 写了 `plan: C-n` 和 `steps: [步骤名]` 的变更，`C-n` 是计划变更；这是步骤和变更唯一的联系，不按标题猜。
- **已完成 / 进行中 / 可开始 / 被挡住**：步骤的四种状态，每次从变更的状态算出来。已完成要合入 main（变更在 main 上是 `done`）才算。
