## 规则

一个步骤的状态每次从变更算出，不另存。做这一步的变更是 front matter 的 `plan` 和 `steps` 指向它的那些（BR-2371），不算状态是 `dropped` 的。按下面的顺序，先符合的先算：

1. **已完成**：至少有一个变更，且每一个都已合入 main 并且状态是 `done`。
2. **进行中**：有一个变更还没有这样完成：状态是 `open`，或者只存在于自己的变更分支上、还没合入 main（`canon change list` 看到的那种），不管它在分支上写的是不是 `done`。
3. **可开始**：依赖的步骤全部已完成（没有依赖也算）。
4. **被挡住**：其余，也就是有依赖还没完成，而且没有变更在做。

百分比是已完成的步数除以总步数，向下取整。

## 例子

- 步骤 `1` 没有依赖，没有变更做它 → 可开始
- 步骤 `1` 有一个 `done` 的变更 → 已完成
- 步骤 `1` 有两个变更，一个 `done`，一个 `open` → 进行中
- 步骤 `1` 的变更只在自己的分支上，没合入 main → 进行中
- 步骤 `1` 的变更只在自己的分支上，分支上写着 `done` → 进行中（没合入 main 就还没完成）
- 步骤 `1` 唯一的变更是 `dropped` → 当作没有变更：没有依赖就是可开始
- 步骤 `2` 依赖 `1`，`1` 是进行中 → 被挡住
- 步骤 `2` 依赖 `1`，`1` 已完成，没有变更做 `2` → 可开始
- 步骤 `2` 依赖 `1`，`1` 还没完成，但已经有 `open` 的变更做 `2` → 进行中
- 步骤 `3` 依赖 `1` 和 `2`，只有 `1` 已完成 → 被挡住，在等 `2`
- 四步里完成了一步 → 25%；三步里完成了一步 → 33%；三步里完成两步 → 66%
