id: BR-2389
title: canon plan link 给已经开工的变更写上它做的计划和步骤
status: active
business: 变更做哪几步
---

## 规则

`canon plan link <C-n> --plan <C-m> --step <步骤名>[,<步骤名>…]` 在当前 checkout（变更自己的 worktree）里，给变更 `C-n` 的文件写上 front matter `plan: C-m` 和 `steps`（BR-2371），输出 `<C-n> → plan <C-m> step(s) …`，提示随变更一起提交；记一条 `plan.link` 事件。之后 `canon plan status` 把这些步骤算作进行中（BR-2372）。检查按这个顺序，任何一项不过都不改文件、退出码见括号：`--plan` 为空或 `--step` 没有步骤名（2）；当前 checkout 里没有 `C-n` 这个变更（3，提示到变更的 worktree 里运行）；`C-n` 不是 `open`（2）；`C-n` 已经有 `plan`（5，要换得手改）；`C-m` 不是 main 上有合格计划的变更、或者某个步骤不在它的计划里（3，和 `canon work start --plan --step` 同一个检查，BR-2376）。不会按标题或内容猜该链接哪一步（D-77）。

## 例子

- 在 `C-9` 的 worktree 里，`canon plan link C-9 --plan C-1 --step 2` → 退出码 0，`C-9` 的 front matter 有 `plan: C-1`、`steps` 是 `2`，`canon plan status C-1` 的步骤 `2` 是进行中
- `--step 2,3.1` → `steps` 有两项，`3.1` 带引号写成 `"3.1"`（BR-2371），`canon check` 不报 `file-invalid`
- `canon plan link C-9 --plan C-1 --step 9`，计划里没有步骤 `9` → 退出码 3，文件不变
- `--plan C-7`，`C-7` 没有计划 → 退出码 3
- `C-9` 已经有 `plan: C-1` → 退出码 5，信息说要手改
- `C-9` 是 `done` → 退出码 2
- 在主 checkout 里运行，`C-9` 只在它自己的分支上 → 退出码 3，信息说到变更的 worktree 里运行
