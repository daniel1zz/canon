id: BR-2315
title: 代码评审成功后才推进 refs/canon/code-reviewed，失败时不动，第一次从本次合入的 base 开始，只改 canon/ 的范围不调评审命令就推进
status: active
---

## 规则

评审整个范围（BR-2314）并且发现都提交到 GitHub（issue 新建或评论成功，或没有发现）之后，`refs/canon/code-reviewed` 才用比较并交换（`git update-ref <ref> <新> <旧>`）移到 `CANON_HEAD`；评审命令失败、返回内容解析不出、`gh` 失败（BR-2211）时引用不动，输出 `code-review: <原因>`、退出码 1，下一次运行重新评审同一个范围。引用不存在时（第一次）先建在这次合入的 `CANON_BASE` 上，不评审更早的历史。范围内 `canon/` 以外没有任何改动时，不看阈值也不调评审命令，输出 `code-review: no code changed; nothing to review` 并推进引用（BR-2070）；`CANON_HEAD` 已被引用包含时输出 `code-review: already reviewed in a batch; nothing to review`。

## 例子

- 评审命令以 1 结束 → 退出码 1，引用还在原来的提交；再运行一次（评审命令正常）→ 评审同一个范围，引用到 `CANON_HEAD`
- 没有引用，这次合入 base 是 X、head 是 Y → 引用先是 X，范围 X..Y 按 BR-2314 处理；X 之前的提交不进评审
- 这次合入只改 `canon/rules/x.md` → 输出 `no code changed; nothing to review`，没有调评审命令，引用到 `CANON_HEAD`
