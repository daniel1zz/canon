## 规则

合入的树里，正在关闭的变更有带 `wording` 的通过记录（BR-2243）时，合入在关闭提交进 main 之前调用一次措辞判断（即使没有规则或决策文件改动）：用合入前 main 上的 `review` 命令（BR-2074），在 main 提交的临时 worktree 里运行（BR-2216），提示只有一段 `# Wording judgements`，不是规则评审（规则评审在合入之后运行，BR-2441）：对每条这样的规则给出编号、上一次通过时的 `## 规则` 段、现在的 `## 规则` 段和没有变的 `## 例子` 段，要求判断这次修改有没有改变产品必须怎样，回答 `{"findings":[],"wording":{"<编号>": "wording" | {"verdict":"behaviour","quote":"<现在 ## 规则 段里的原句>","requires":"<这句要求了什么以前没要求的>"}}}`；提示写明只写清已有范围、换说法、加引用的答 `wording`。答 `behaviour` 必须带引用（#256）：`quote` 在现在的 `## 规则` 段里（两边都把连续空白合并成一个空格再比）才算答了 `behaviour`；没有 `quote`、`quote` 为空、不在原文里，或者只答了字符串 `"behaviour"`，这条按 `wording` 算，输出一行 `wording judgement: <编号>: behaviour without a quote from the rule: treated as wording`。这样判断能被核对：引用在不在原文里由 canon 比较，`requires` 写进拒绝信息，合入的会话据此改测试，合入后的规则评审看得到它改的测试。每条都必须答 `wording`（含按上面算成 `wording` 的）；带引用答 `behaviour`、没有答、答了别的值，或者没有评审命令（没有配置 `review`，或配置成 `review: none`，BR-2074）时，合入被拒，原因 `review`，信息点名这条规则，带引用的 `behaviour` 写出 `“<quote>” requires <requires>`，说明它要按行为修改执行：改一个标题点名它的测试，带 `untested:` 的写一行验收（BR-2241），再合入。命令运行失败或超时时同样拒绝，原因 `review`。回答读不了（不是 JSON、JSON 解析不了，或意见的格式不对）时，不立刻拒绝：先输出一行 `wording judgement: the answer could not be read (<原因>); asking the review command once more`，再用同一段提示加上一段 `# Your previous answer could not be read`（写明原因，要求按上面的格式只答 JSON）问一次；第二次的回答能读，就照它判断；还是读不了才拒绝，原因 `review`。第二次的回答里有评审写的文字时（JSON 的意见数组里每条字符串、或每个对象的 `text`；没有这些时是标准输出里 JSON 之外的文字；没有 JSON 或 JSON 解析不了时是整个标准输出，都去掉首尾空白、不为空，每段最多 2000 个字符），拒绝信息在 `what the reviewer wrote:` 下面一段一行完整写出这些文字，并记一条 `review.unparsed` 事件（`docs`、`texts`、`commit`）；不记成评审意见，只挡这次合入，再合入时重新判断（#252）；没有任何文字时，信息末尾写 `(asked twice; neither answer could be read)`（#227）。判断记在一条 `review.wording` 事件里（`docs`、`wording`（按上面算过之后的）、评审给的 `why`（每条的 `quote`、`requires`）、按措辞算的 `unquoted`、`hash`、`commit`）；同一份提示、同一条命令最近一次的判断对每条都答了 `wording` 时沿用它，不再调用命令，输出写明沿用的事件号。`canon work review` 事先问同样的判断，只报告、不代替合入时的这次判断（BR-2358）。

## 例子

- `BR-1` 的记录是 `… test wording`，命令答 `{"findings":[],"wording":{"BR-1":"wording"}}` → 合入继续，`review.wording` 事件的 `wording` 是 `{"BR-1":"wording"}`
- 同上，命令答 `"wording":{"BR-1":{"verdict":"behaviour","quote":"Statement one, reworded.","requires":"a changed statement"}}`，现在的 `## 规则` 段里有这句 → 拒绝，原因 `review`，信息含 `BR-1: the review answered behaviour: “Statement one, reworded.” requires a changed statement`
- 同上，`quote` 是规则里没有的句子、为空，或者命令只答 `"wording":{"BR-1":"behaviour"}` → 合入继续，输出 `wording judgement: BR-1: behaviour without a quote from the rule: treated as wording`，`review.wording` 事件的 `wording` 是 `{"BR-1":"wording"}`、`unquoted` 是 `["BR-1"]`
- 规则原文把那句折成两行、多了空格，`quote` 是单行的同一句 → 引用成立，拒绝
- 同上，命令的 JSON 没有 `wording` 字段 → 拒绝，原因 `review`
- 同上，没有配置 `review` → 拒绝，原因 `review`，信息说明没有评审命令来判断
- 同上，配置是 `review: none` → 拒绝，原因 `review`
- 这次合入只改了变更文件，没改规则文件，但有带 `wording` 的记录 → 照样调用命令，提示里有 `# Wording judgements` 和 `BR-1`，没有规则评审的说明和领域全文
- 第一次合入在判断之后被 `before_land` 拒绝，改了和规则无关的代码再合入 → 命令没有再运行，输出写明沿用
- 没有带 `wording` 的记录 → 不调用措辞判断
- 第一次回答 `{"findings":["BR-1 changes when the line shows"]}`（意见没有标准），第二次回答 `{"findings":[],"wording":{"BR-1":"wording"}}` → 合入成功，评审命令运行了两次，第二次的提示是第一次的提示加上 `# Your previous answer could not be read` 和原因
- 两次都答 `{"findings":[{"criterion":"note"}]}`（读不了，也没有文字）→ 拒绝，原因 `review`，信息含 `asked twice; neither answer could be read`，不记意见
- 两次都答 `{"findings":["BR-1 changes when the line shows"]}` → 拒绝，原因 `review`，信息在 `what the reviewer wrote:` 下面有 `  - BR-1 changes when the line shows`；有一条 `review.unparsed` 事件，没有新的评审意见
- 两次都只输出一句话、没有 JSON → 拒绝，信息完整写出这句话
- 评审命令退出码 3 → 只运行一次就拒绝，信息里没有 `asked twice`
