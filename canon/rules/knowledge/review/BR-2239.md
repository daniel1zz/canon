## 规则

合入的树里，正在关闭的变更有带 `wording` 的通过记录（BR-2243）时，合入在关闭提交进 main 之前调用一次措辞判断（即使没有规则或决策文件改动）：用合入前 main 上的 `review` 命令（BR-2074），在 main 提交的临时 worktree 里运行（BR-2216），提示只有一段 `# Wording judgements`，不是规则评审（规则评审在合入之后运行，BR-2441）：对每条这样的规则给出编号、上一次通过时的 `## 规则` 段、现在的 `## 规则` 段和没有变的 `## 例子` 段，要求判断这次修改有没有改变产品必须怎样，回答 `{"findings":[],"wording":{"<编号>": "wording" | "behaviour"}}`。每条都必须答 `wording`；答 `behaviour`、没有答、答了别的值，或者没有评审命令（没有配置 `review`，或配置成 `review: none`，BR-2074）时，合入被拒，原因 `review`，信息点名这条规则，说明它要按行为修改执行：改一个标题点名它的测试，带 `untested:` 的写一行验收（BR-2241），再合入。命令运行失败、超时或结论无效时同样拒绝，原因 `review`。判断记在一条 `review.wording` 事件里（`docs`、`wording`、`hash`、`commit`）；同一份提示、同一条命令最近一次的判断对每条都答了 `wording` 时沿用它，不再调用命令，输出写明沿用的事件号。`canon work review` 事先问同样的判断，只报告、不代替合入时的这次判断（BR-2358）。

## 例子

- `BR-1` 的记录是 `… test wording`，命令答 `{"findings":[],"wording":{"BR-1":"wording"}}` → 合入继续，`review.wording` 事件的 `wording` 是 `{"BR-1":"wording"}`
- 同上，命令答 `"wording":{"BR-1":"behaviour"}` → 拒绝，原因 `review`，信息含 `BR-1`
- 同上，命令的 JSON 没有 `wording` 字段 → 拒绝，原因 `review`
- 同上，没有配置 `review` → 拒绝，原因 `review`，信息说明没有评审命令来判断
- 同上，配置是 `review: none` → 拒绝，原因 `review`
- 这次合入只改了变更文件，没改规则文件，但有带 `wording` 的记录 → 照样调用命令，提示里有 `# Wording judgements` 和 `BR-1`，没有规则评审的说明和领域全文
- 第一次合入在判断之后被 `before_land` 拒绝，改了和规则无关的代码再合入 → 命令没有再运行，输出写明沿用
- 没有带 `wording` 的记录 → 不调用措辞判断
