## 规则

合入不调用措辞判断，也不因它拒绝（D-141）。一次合入关闭了一个变更（合入的树里它是 `done`，合入前的 main 上不是），而这个变更有带 `wording` 的通过记录（BR-2243）时，合入为它排一次合入后的评审（BR-2441，即使没有规则或决策文件改动，BR-2010）；合入后的评审在规则评审之前调用一次措辞判断：用合入后评审的 `review` 命令和临时 worktree（BR-2074、BR-2216），提示只有一段 `# Wording judgements`，不是规则评审：对每条这样的规则给出编号、上一次通过时的 `## 规则` 段、现在的 `## 规则` 段和没有变的 `## 例子` 段，要求判断这次修改有没有改变产品必须怎样，回答 `{"findings":[],"wording":{"<编号>": "wording" | {"verdict":"behaviour","quote":"<现在 ## 规则 段里的原句>","requires":"<这句要求了什么以前没要求的>"}}}`；提示写明只写清已有范围、换说法、加引用的答 `wording`。答 `behaviour` 必须带引用（#256）：`quote` 在现在的 `## 规则` 段里（两边都把连续空白合并成一个空格再比）才算答了 `behaviour`；没有 `quote`、`quote` 为空、不在原文里，或者只答了字符串 `"behaviour"`，这条按 `wording` 算，输出一行 `wording judgement: <编号>: behaviour without a quote from the rule: treated as wording`。评审命令的回答就是判断：canon 只核对回答的格式和 `behaviour` 的引用是不是原文，每次判断连同引用和 `requires` 记在 `review.wording` 事件里（`docs`、`wording`（按上面算过之后的）、评审给的 `why`、按措辞算的 `unquoted`、`hash`、`commit`）；同一份提示、同一条命令最近一次的判断对每条都答了 `wording` 时沿用它，不再调用命令，输出写明沿用的事件号。

答 `wording`（含按上面算成 `wording` 的）的规则输出 `wording judgement: <编号>: wording; its earlier pass carries over`。带引用答 `behaviour`、没有答或答了别的值的规则，各记成一条挂在这条规则上的未处理评审意见（BR-2433，标准 `wording`，变更是这个变更），意见写明变更把它记成只改措辞、评审怎么答的（带引用的 `behaviour` 写出 `“<quote>” requires <requires>`），以及要按行为修改执行它：在 `rules:` 列出它的变更里改一个标题点名它的测试，带 `untested:` 的写一行验收（BR-2241）；它和别的意见一样由主 agent 定档、处理和关闭（knowledge/review/findings），出现在 `canon context`、`canon brief` 和 `canon work due` 里。合入已经完成，判断的结果不改变合入、不撤回关闭提交。

命令运行失败或超时、回答两次都读不了时，这次合入后的评审记为失败（BR-2441 的 `review.fail`），按 BR-2449 重排：回答读不了（不是 JSON、JSON 解析不了，或意见的格式不对）时先输出一行 `wording judgement: the answer could not be read (<原因>); asking the review command once more`，再用同一段提示加上一段 `# Your previous answer could not be read`（写明原因，要求按上面的格式只答 JSON）问一次；第二次的回答能读，就照它判断；还是读不了时，回答里有评审写的文字（JSON 的意见数组里每条字符串、或每个对象的 `text`；没有这些时是标准输出里 JSON 之外的文字；没有 JSON 或 JSON 解析不了时是整个标准输出，都去掉首尾空白、不为空，每段最多 2000 个字符）就在失败信息的 `what the reviewer wrote:` 下面一段一行完整写出，并记一条 `review.unparsed` 事件（`docs`、`texts`、`commit`），不记成评审意见；没有任何文字时，信息末尾写 `(asked twice; neither answer could be read)`（#227、#252）。合入前 main 上没有评审命令（没有配置 `review`，或 `review: none`，BR-2074）时不判断，按 BR-2441 记 `review.skip`，输出写明这些规则的只改措辞记录没有人判断。`canon work review` 事先问同样的判断，只报告（BR-2358）。

## 例子

- `C-1` 的关闭提交有 `BR-1: "… test wording"`，合入后的评审命令答 `{"findings":[],"wording":{"BR-1":"wording"}}` → 合入早已成功；`review.wording` 事件的 `wording` 是 `{"BR-1":"wording"}`，输出 `wording judgement: BR-1: wording; its earlier pass carries over`，没有新的评审意见
- 同上，命令答 `"wording":{"BR-1":{"verdict":"behaviour","quote":"Statement one, reworded.","requires":"a changed statement"}}`，现在的 `## 规则` 段里有这句 → 合入照常成功，main 上有 `C-1` 的关闭提交；`BR-1` 上多一条未处理的评审意见，标准 `wording`，变更 `C-1`，文字含 `the review answered behaviour: “Statement one, reworded.” requires a changed statement`
- 同上，`quote` 是规则里没有的句子、为空，或者命令只答 `"wording":{"BR-1":"behaviour"}` → 输出 `wording judgement: BR-1: behaviour without a quote from the rule: treated as wording`，`review.wording` 事件的 `wording` 是 `{"BR-1":"wording"}`、`unquoted` 是 `["BR-1"]`，没有新的意见
- 规则原文把那句折成两行、多了空格，`quote` 是单行的同一句 → 引用成立，记一条意见
- 同上，命令的 JSON 没有 `wording` 字段 → `BR-1` 上记一条意见，文字含 `the review answered nothing`
- 合入时 → 合入的输出里没有 `wording judgement`，合入不调用评审命令
- 这次合入只改了变更文件，没改规则文件，但关闭提交有带 `wording` 的记录 → 合入后排一次评审，只调用措辞判断，提示里有 `# Wording judgements` 和 `BR-1`，没有规则评审的说明
- 没有带 `wording` 的记录 → 不调用措辞判断
- 第一次回答 `{"findings":["BR-1 changes when the line shows"]}`（意见没有标准），第二次回答 `{"findings":[],"wording":{"BR-1":"wording"}}` → 评审命令运行了两次，第二次的提示是第一次的提示加上 `# Your previous answer could not be read` 和原因，判断是 `wording`
- 两次都答 `{"findings":["BR-1 changes when the line shows"]}` → 合入后的评审失败，信息在 `what the reviewer wrote:` 下面有 `  - BR-1 changes when the line shows`；有一条 `review.unparsed` 事件，没有新的评审意见；合入不受影响
- 评审命令退出码 3 → 只运行一次，合入后的评审失败，有一条 `review.fail`
- 合入前的 main 上 `review: none` → 不调用命令，有一条 `review.skip`，输出写明 `BR-1` 的只改措辞记录没有人判断
