## 规则

`canon work review` 的一次预览或一次合入后评审（含 BR-2449 的重新排队）开始调用评审命令之前，先按 BR-2361、BR-2396 决定哪些规则提示可沿用、哪些需要完整或增量评审，再把实际需要调用的全部规则提示和常驻说明重复评审提示合计。每份实际提示算一次调用，总 KB 按全部提示的 UTF-8 字节合计，1 KB 为 1024 字节，不逐份取整；沿用而不调用的规则提示不计。调用数大于 `review_max_calls`（正整数，默认 16），或字节总数大于 `review_max_total_prompt_kb` 乘 1024（正的有限数，默认 4096）时，本次两种评审的命令都不运行；等于两项阈值仍可运行。配置取自 BR-2074 的可信提交；预览取当前 main，工作树自行调高它们不放行当前预览。0、负数、错误类型和非整数调用数按 BR-2045 退出码 2。

超限时在 `canon human` 里记录一个负责人问题，展示评审种类、工作项、调用次数、总字节及向上取整的 KB、两项阈值和计划指纹，选项为“同意本次评审”“不运行本次评审”。计划由评审种类、工作项、评审命令及它运行的提交、两项阈值和有序的全部实际提示确定，不绑定队列号。相同计划的待答问题重复使用，已答“不运行本次评审”或任何其他未明确同意的回答持续阻止。只有回答精确为“同意本次评审”才放行该计划的一次执行：核对回答和记下消费在同一个写事务里完成，两个并发重试最多一个消费同一次同意。消费后再次执行须问新的问题，运行失败或被杀也不返还同意；计划、种类或评审命令运行的提交变化时不能沿用旧同意。未超限的计划不需要同意。问题及消费记在既有问题和事件记录里，批准不算已评审。

未获放行的预览退出码 1，输出问题号、计划和两项阈值，不写成功预览、不运行相关文档挑选命令。合入后未获放行时，已成功的合入不回退，该次评审记为失败，`canon work after-land` 输出问题号和原因；不自动重试，同意后用 BR-2449 的原命令重排，预览则用原命令重试。首次 `--again` 按 BR-2449 从原 base 切到当前 main 的 reviewer 提交时，属于上述计划变化，先取得新计划的同意；之后 main 未变的重排可消费该同意。新问题或消费写入失败时以环境错误停下，不调用评审命令。本规则不改变提示范围、单份提示装箱、缓存命中条件、并发名额或评审命令的原有失败行为（D-123）。发布、reconcile 和合入时独立措辞判断不属于此处的一次预览或合入后评审。

## 例子

- 计划 16 次、合计 4096 KB，使用默认配置 → 直接运行；17 次或 4096 KB 加 1 字节 → reviewer 零次调用，出现负责人问题
- 规则 1 次、重复评审 1 次，阈值调用数为 1 → 合计超限，两种命令都不运行
- 非 ASCII 提示字节数恰等于总量阈值 → 运行；多一个 UTF-8 字节 → 不运行，不按字符数误判
- 相同计划连续重试两次、问题未答 → 同一个问题号，零调用；答“不运行本次评审”再重试 → 仍零调用
- 明确同意后原命令重试 → 一次执行获准，记消费；两个进程同时重试 → 只有一个获准
- 获准的 reviewer 自己失败 → 该次同意已消费，再试需新问题；失败不重复自动付费
- 同意预览 A 后修改提示、切换 reviewer 的可信提交，或改为合入后评审 → 旧同意无效，超限仍零调用
- 合入后超限 → 合入保留、评审失败、after-land 点名问题；同意后 --again 新建队列记录 → 相同计划可以消费一次同意
- 全部规则提示命中缓存、没有重复评审 → 实际 0 次，不因原始完整提示超限而询问；增量评审只计增量提示
- 工作树把两项阈值提高，main 上仍更低 → 当前预览按 main 的阈值拒绝
