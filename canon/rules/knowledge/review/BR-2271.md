## 规则

已退役：负责人 2026-11-04 选择“整个删掉 (推荐)”，合入后一致性抽查连脚本和代码一起删除（D-43、C-299）。以下是退役前的内容。

`scripts/consistency-review.ts` 作为 `after_land` hook 运行（D-43），环境变量 `CANON_BASE`、`CANON_HEAD` 必填，缺少时退出码 2；参数写错（不认识的参数、`--max-domains` 或 `--max-bytes` 不是大于 0 的整数）时退出码 2。它从 `CANON_HEAD` 的代码树读出规则领域和配置，按 `CANON_BASE..CANON_HEAD` 改动（新增、修改、删除、改名）的文件找出改到的领域：`canon/rules/<领域>/` 下的文件算那个领域；其他文件算代码目录覆盖它、而且覆盖得最具体（代码目录最长）的那个领域；不属于任何领域的文件不算。没有改到任何领域时不调用评审命令，输出 `code-review: consistency: no domain's rules or code changed; nothing to check`。改到的领域先按改到的规则文件数（`canon/rules/` 下的文件）从多到少、再按改动文件数从多到少、相同时按名字排序（规则改动最可能带来不一致），只查前 `--max-domains` 个（默认 1），其余的输出一行 `code-review: consistency: not checked (--max-domains <n>): <领域>, ...`。查一个领域就调用一次评审命令（`CANON_CONSISTENCY_AI`，默认 `claude -p --output-format text`，在 `CANON_HEAD` 导出的代码树目录里运行，不在主 checkout 里：合入之后 main 可能已经前移，它读到的必须是被查的那个提交），从标准输入交给它：这个领域直接包含的、没有作废的规则全文；会运行的测试里标题点名其中某条规则的每个测试（BR-2005 的测试标题），从它的第一行到最后一行；这个领域代码目录下、不属于更具体的领域、不是测试文件的每个文件全文（跳过二进制文件和超过 100 KB 的文件）；带 `canon-consistency` 标签、未关闭的 issue 列表。提示要求只回答两件事：测试有没有覆盖每条规则例子的两侧，代码和规则写的是否一致；提示写明它只看到这个领域自己的代码和点名这些规则的测试，共享内核和 `scripts/` 没给它，所以只有展示出来的代码明确做了别的事才算 `code-mismatch`，不能因为规则要的行为不在这些文件里就报。领域里没有规则时不调用，输出 `code-review: consistency: <领域>: no rules; skipped`。提示超过 `--max-bytes` 字节（默认 150000）时不调用，输出 `code-review: consistency: <领域>: <字节数> bytes is over --max-bytes <n>; not checked`。调用前输出 `code-review: consistency: checking <领域>: <规则数> rules, <测试数> tests, <代码文件数> code files, <字节数> bytes`。评审命令失败或返回的内容解析不出发现列表时，输出 `code-review: consistency: <原因>`，退出码 1。它不在 `hooks.after_land` 里就不运行。

## 例子

- 合入改了 `src/work/land/queue/x.ts`，`code_root: src`，有 `work/land` 和 `work/land/queue` 两个领域 → 只查 `work/land/queue`，提示里有它的规则、点名这些规则的测试段落和 `src/work/land/queue/x.ts` 的全文，没有 `src/work/land/` 下直接的文件
- 合入只改了 `canon/rules/billing/BR-1.md` → 查 `billing`
- 合入改了 `orders` 的一条规则文件、`billing` 的 2 个代码文件，默认 `--max-domains 1` → 查 `orders`，输出 `code-review: consistency: not checked (--max-domains 1): billing`（规则改动排在前面）
- 评审命令的工作目录是导出的代码树（里面没有 `.git`），不是运行脚本的目录
- 合入只改了 `README.md`（不属于任何领域）→ 不调用评审命令，输出 `code-review: consistency: no domain's rules or code changed; nothing to check`
- 合入改了 `billing` 的 2 个文件和 `orders` 的 1 个文件，默认 `--max-domains 1` → 只查 `billing`，输出 `code-review: consistency: not checked (--max-domains 1): orders`
- 同一个合入带 `--max-domains 2` → 两个领域各调用一次评审命令
- 一个测试 `it.skip("BR-1: ...")` 点名了规则 → 它不在提示里；`it("BR-1: ...")` 在
- `--max-bytes 10`，提示有 5000 字节 → 不调用，输出 `... 5000 bytes is over --max-bytes 10; not checked`，退出码 0
- 没有 `CANON_HEAD` → 退出码 2；`--max-domains 0` → 退出码 2
- 评审命令以退出码 1 结束 → 输出 `code-review: consistency: <原因>`，退出码 1
