## 规则

常驻说明的重复评审（BR-2143）在提示里逐个列出 `.claude/skills/<名字>/SKILL.md` 的 `description`，按目录名排序。一个 skill 的 front matter 里没有字符串类型的 `description`，或文件没有 front matter 时，这一项写成 `(no description)`；front matter 不是合法的 YAML 时，写成 `(front matter does not parse: <解析错误的第一行>)`。这两种情况都不让评审失败，评审照常运行。`instructions` 列出的说明文件整篇放进提示。

## 例子

- `good/SKILL.md` 的 description 是 `Use when testing.` → 提示里有 `- .claude/skills/good/SKILL.md: Use when testing.`
- `bare/SKILL.md` 的 front matter 没有 `description`，或者 `none/SKILL.md` 没有 front matter → `- .claude/skills/bare/SKILL.md: (no description)`
- `broken/SKILL.md` 的 front matter 是 `description: [unclosed` → `- .claude/skills/broken/SKILL.md: (front matter does not parse: …)`，提示照常生成
- `CLAUDE.md` 的内容是 `# Project` → 提示里有 `# CLAUDE.md (instruction file, loaded whole)` 和它的全文
