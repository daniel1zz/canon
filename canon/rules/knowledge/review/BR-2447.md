## 规则

规则评审（BR-2009）的提示里有一条拦截标准 `business-overlap`（BR-2367）：这次合入往某个领域 README 的 `## 业务` 段里新加了一个业务，而它管的事和这个领域里已经列着的某个业务是同一件，或者只是把它的一部分换了个名字，就以这个标准拦截，意见里点名两个业务名和这个领域。这次合入没有新加业务时，这条标准不拦任何东西；已经存在的业务之间重叠，只能作为 `note`。

提示里还写明：业务是几条规则共同划出的一块边界，不是一条规则的标题；新业务该有它自己的几条规则，拿不出和已有业务分得开的边界时就是重叠。

## 例子

- 这次合入在 billing 的 `## 业务` 里新加 `- **退货**：钱怎么退回去`，而这个领域已经列着 `- **退款**：钱怎么退回去` → 以 `business-overlap` 拦截，意见点名「退货」「退款」和 billing
- 这次合入新加 `- **对账**：每天和银行对一次账`，领域里已有的业务都和它分得开 → 不拦
- billing 已经列着的 `退款` 和 `退货` 本来就重叠，这次合入没有动 `## 业务` → 只能给 `note`，不拦
- 这次合入只给规则加 `business:`，没有往 `## 业务` 里加新行 → 这条标准不拦任何东西
