status: active

## 规则

规则评审和常驻说明的重复评审的提示里，每条拦截标准有一个短名字（规则评审：`contradiction`、`untestable`、`no-rejected-options`、`release`、`amends`、`overview`；重复评审：`duplication`），并要求评审这样答：`{"findings":[{"criterion":"<标准名>"|"note","text":"<一句话>"}]}`，不要自己给结论。canon 在评审的回答里这样推出结论：每条意见都是带 `criterion` 和非空 `text` 的对象，`criterion` 是上面某个标准名或 `note`；有任何一条的 `criterion` 不是 `note`，结论就是 `block`，否则是 `ok`。这条规则下 `verdict` 字段如果有，也被忽略。拦截时，点名了标准的意见在输出和事件里写成 `[<标准名>] <text>`，`note` 的意见只写 `text`；`ok` 时只有 `note` 意见，照常作为建议处理（BR-2145）。回答里混着对象和字符串、`criterion` 缺失、不是字符串、不是已知的标准名也不是 `note`，或 `text` 为空，是无效结论，合入被拒（BR-2216），错误里写出是第几条意见和可用的标准名。

旧格式（这条规则之前写的评审命令）：回答里没有对象意见（意见没有、是空列表或全是字符串）且 `verdict` 是 `ok` 或 `block` 时，按旧格式处理：结论就是 `verdict`，字符串意见原样当作意见；`verdict` 是别的值、或没有 `verdict` 而意见是字符串（`{"findings":[]}` 除外，它是新格式的 `ok`），是无效结论。旧格式不经过标准名推导，所以结论仍由评审自己决定。多次调用的评审（BR-2359）每次调用的回答各自按这条处理。

## 例子

- `{"findings":[{"criterion":"amends","text":"D-66 changes part of D-21 without amends"}]}` → `block`，意见是 `[amends] D-66 changes part of D-21 without amends`
- `{"findings":[{"criterion":"note","text":"BR-3 could be shorter"}]}` → `ok`，意见 `BR-3 could be shorter`
- `{"verdict":"ok","findings":[{"criterion":"contradiction","text":"BR-1 contradicts BR-2"}]}` → `block`（有 `verdict` 也忽略；点名了标准的意见不能以 ok 通过）
- `{"verdict":"block","findings":[{"criterion":"note","text":"style"}]}` → `ok`
- `{"findings":[]}` → `ok`，没有意见
- `{"findings":[{"criterion":"vague","text":"x"}]}`、`{"findings":[{"text":"x"}]}`、`{"findings":[{"criterion":"note","text":""}]}` 或 `{"findings":[{"criterion":"note","text":"a"},"b"]}` → 无效结论，合入被拒
- 旧格式 `{"verdict":"block","findings":["BR-1 is vague"]}` → `block`，意见 `BR-1 is vague`；`{"verdict":"ok","findings":["BR-1 is vague"]}` → `ok`；`{"verdict":"block"}` → `block`，没有意见
- `{"findings":["BR-1 is vague"]}`（字符串意见、没有 `verdict`）或 `{}`（既没有 `verdict` 也没有 `findings`）→ 无效结论
- 规则评审的提示里有每个标准名，且要求的回答格式是上面这种；重复评审的提示里有 `duplication`
