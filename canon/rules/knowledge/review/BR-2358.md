## 规则

在变更的 worktree 里运行 `canon work review` 时，canon 对这个变更相对 main 合并基点的改动（含已提交、未提交和未跟踪的文件，被 git 忽略的文件不算）运行合入时的两种评审：改动了规则、决策、版本或领域 README 时的规则评审，改动了常驻说明（BR-2143）时的重复评审；提示的生成、`review` 命令、时限和常驻说明清单都和合入时用同一份代码、同一份 main 上的配置，命令在 main 提交的临时 worktree 里运行（BR-2216）。它输出评审的每条意见和结论（之后是 BR-2387 的相关文档段），记一条 `review.preview` 事件（带结论和意见数，规则评审的键、结论和意见（BR-2361），不是合入的评审结果，不挂到任何文档上，D-21），合入时照常再评审一次（预览通过不算合入通过，BR-2361）。退出码：结论 `ok` 为 0，`block` 为 1，评审命令失败或结论无效为 4，没有配置 `review` 为 2。没有规则、决策、版本、领域 README 或常驻说明的改动时不运行评审，退出码 0；`review: none` 时不运行评审，说明已配置为不评审，退出码 0。不在变更的 worktree 里（主 checkout，或没有认领的 worktree）运行时退出码 2，什么都不运行。变更的分支落后 main 时，仍评审 worktree 当前的文字，另打印一行：main 在合并基点之后又有多少个提交，合入时评审的是 rebase 之后的文字，结果可能不同，先 `git rebase main` 更准；退出码不受影响。规则评审要对照的“记录为只改了措辞的规则”（BR-2239）只在合入时问，这里不问。

## 例子

- 改了一条规则，评审命令输出 `{"verdict":"ok","findings":["BR-1 note"]}` → 输出 `review note` 加意见和 `review: ok`，退出码 0，记 `review.preview`，没有 `review.ok` 事件
- 评审命令输出 `{"verdict":"block","findings":["BR-1 contradicts BR-2"]}` → 输出意见和 `review: block`，退出码 1
- 同一变更既改了规则又改了 `CLAUDE.md` 的一行，两次评审都 `ok` → 评审命令运行两次（规则评审、重复评审），退出码 0；其中一次 `block` → 退出码 1
- 评审命令以退出码 3 结束，或没有输出 JSON → 退出码 4，信息里有 `the rule review could not run`
- 规则只是改了没提交的文字，或是还没 `git add` 的新文件 → 评审提示里是这份当前的文字
- 变更只改了代码 → 说明没有规则、决策或常驻说明的改动，评审命令没有被运行，退出码 0
- main 上 `review: none` → 说明已配置为不评审，退出码 0，评审命令没有被运行
- main 上没有 `review`，变更改了规则 → 退出码 2，信息说要配置 `review`；变更只改了代码时没有配置也是退出码 0
- 变更自己改了 `review` 命令 → 运行的是 main 上的那个
- 在主 checkout 里运行，或在没有认领的 worktree 里运行 → 退出码 2，评审命令没有被运行
- main 在合并基点之后有 2 个新提交 → 照样评审当前的文字，多一行写着 2 个提交和先 `git rebase main`，退出码仍由结论决定
- 分支就在 main 的最新提交上 → 没有这一行
- 运行结束后 → `git worktree list` 里没有评审用的临时 worktree，worktree 里的文件和暂存区没有变化
