## 规则

常驻说明是每个会话开始时都会读到的文字：main 上的配置（同 BR-2074，不取自被合入的树）`instructions` 列出的文件（仓库里的相对路径；没配置时是 `CLAUDE.md`）、`.claude/skills/<名字>/SKILL.md` 的 `description`，以及 `canon brief` 输出的工作说明。一次合入新增或修改了 `instructions` 列出的文件或任何 `.claude/skills/<名字>/SKILL.md`（例外见 BR-2410）时，合入之后的评审（BR-2441）在规则评审之后调用配置的评审命令，提示里有改动过的文件名和所有常驻说明的当前文字；改动过的 `.claude/skills/<名字>/SKILL.md` 还附上被合入的树里的全文（评审在 main 提交的临时 worktree 里运行，BR-2216，那里只有旧文字）。提示里还附上每个改动过的常驻说明文件在这次合入里的 unified diff（base 到 head），让评审分得出新旧。只判断这次合入带进来的重复：同一条要求（指令、条件、限定）已经写在另一份常驻说明里，或者在同一份里写了两遍，并且这两处至少有一处在这次合入新增或改动的行里（diff 的 `+` 行）时，评审拦截（结论 `block`，意见按 BR-2442 记账），结论写明重复的两处；被删掉的行造不成重复，移动的行（一处删、另一处加）算新增；两处都在没改动的文字里的重复是原来就有的，不拦截，评审最多把它写成结论为 `ok` 的发现，作为不拦截的提示输出（同 BR-2145）；一句指向别处的引用、在通用要求上加的本项目限定不算重复。只删除这些文件、或没有改动它们时，不做这次评审。评审命令以非 0 退出，或者没有输出有效的结论时，这次评审记为失败（BR-2441），合入不受影响。main 上没有配置 `review` 或配置成 `review: none` 时按 BR-2074 处理（被合入的树自己设了 `review` 也一样）。`instructions` 的格式见 BR-2151。

## 例子

- 只改了 `CLAUDE.md`，评审结论 `block` → 合入成功，合入后的评审事件是 `review.block`（`review` 为 `duplicate`），提示里有 `CLAUDE.md` 的新文字和工作说明
- 改了 `.claude/skills/x/SKILL.md`，评审结论 `ok` → 提示里有每个 skill 的 description，以及 `.claude/skills/x/SKILL.md` 改动后的全文
- `instructions: [docs/agent.md]`，只改了 `CLAUDE.md` → 不做这次评审；改了 `docs/agent.md` → 评审
- `CLAUDE.md` 里原来就有两句重复的要求，这次合入只改了不相关的一行 → 提示里的 diff 只有那一行带 `+`，评审结论 `ok`，重复作为 `review note` 输出
- 这次合入在 `CLAUDE.md` 里新加了一行，重复了别处已写的要求 → 提示里的 diff 里这一行带 `+`，评审回答 `duplication` 时这条意见按 BR-2442 记账
- 只改了代码和变更文件 → 不做这次评审
- 改了 `CLAUDE.md`，没有配置 `review` → 合入成功，输出含 `CLAUDE.md` 和 `landed without a review`，`review.skip` 的 `reason` 是 `unconfigured`
- 改了 `CLAUDE.md`，main 上已经是 `review: none` → 输出 `review: none — CLAUDE.md landed without a review`，事件表多一条 `review.skip`，合入成功
- 改了 `CLAUDE.md`，评审命令以退出码 3 结束 → 合入成功，这次评审记为失败（`review.fail`）
- main 上 `instructions` 是默认的 `CLAUDE.md`，变更改了 `CLAUDE.md`，同时把 `instructions` 改成 `[docs/other.md]` → 仍按 main 上的清单评审 `CLAUDE.md`
- main 上没有 `review`，变更设了 `review` 又改了 `CLAUDE.md` → 合入成功，`CLAUDE.md` 没有评审，变更自己的评审命令没有被调用
