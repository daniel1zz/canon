## 规则

评审收到的提示里，每个在这次合入里改动的版本，和每条在这次合入里改动的、带 `release` 标签的规则所属的版本，各有一段：版本编号、标题、状态，没有在改动文档里出现过的版本还有它的全文，以及标着这个版本的规则（不含作废的）一行一条，写编号、领域、标题，规划中的规则注明；提示的要求里写明：标着某版本的规则做了该版本“不做”里排除的事或超出它的“范围”，该版本的“不做”和它自己的“范围”或标着它的规则矛盾，评审都可以拦。规则索引里带标签的规则写着它的版本。规则评审拆成几次调用时（BR-2359），版本段只在第一次调用里，那里有全部改动文档；之后的调用只列版本的编号、标题和状态。没有版本改动、也没有带标签的规则改动时，提示里没有版本段。

功能模块（D-130）照同样的方式有自己的一段（#249）：每个在这次合入里改动的模块，和每条在这次合入里改动的、带 `feature` 标签的规则所挂的模块，一段 `# Feature <编号> <标题> (<状态>)`：没有在改动文档里出现过的模块还有它的全文；挂在它上面的规则（不含作废的）一行一条，写法同上；列着这个模块的每个版本（版本的 `features` 里有它）一行编号、标题、状态，后面是那个版本的 `## 范围` 和 `## 不做`。提示的要求里写明：挂在模块上的规则做了模块“不做”里排除的事或超出它的“范围”，模块的“不做”和它自己的“范围”或挂着的规则矛盾，模块的“范围”做了列着它的版本“不做”里的事或超出那个版本的“范围”，评审都可以按 `release` 标准拦。拆成几次调用时，模块段和版本段一样只在第一次调用里，之后的调用在 `# Features of this landing` 下只列编号、标题和状态。

## 例子

- 合入只改了 `R-1` 的 `## 不做` → 提示里有 `# Release R-1` 一段，列出标着 `R-1` 的每条规则
- 合入只改了标着 `R-1` 的 `BR-3` → 提示里有 `# Release R-1` 一段，含 `R-1` 的全文（因为它不在改动的文档里），其中 `## 不做` 可见
- 同一次合入既改了 `R-1` 又改了标着它的规则 → `R-1` 只有一段，不重复它的全文
- `BR-4` 没标版本，只改了它 → 提示里没有版本段
- 提示的规则索引里 `BR-3` 一行写着 `[R-1]`，没标版本的规则没有
- 改动了挂着 `feature: F-1` 的规则 `BR-6`，`R-3` 的 `features` 有 `F-1` → 提示有 `# Feature F-1 …` 一段：`F-1` 全文、`Rules tagged F-1:` 下有 `BR-6`（作废的不列）、`Releases listing F-1:` 下有 `R-3` 和它的 `## 范围`、`## 不做`
- 改动的是 `F-1` 本身 → 那一段标题后写 `(new text shown above)`，不重复全文；改动的规则没挂模块 → 没有模块段
