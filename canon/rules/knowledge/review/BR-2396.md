## 规则

合入后的规则评审（BR-2441）按 BR-2361 不能沿用时，先算改动文档的键（`docs_hash`）：对 `review` 命令的文字、`review_max_prompt_kb` 换成的字节数、这次评审的每份改动或新增的规则、决策、版本文档和改动的领域 README（路径和全文）、删除的文档和 README（路径和它们在合入前 main 上的文字），按路径排序，加上这次对架构总览的 diff，取 SHA-256；它不随 main 上别的文档变化。每次合入后的规则评审的 `review.ok` 和 `review.block` 都记 `docs_hash` 和这次合入前 main 的提交 `base`。同一变更最近一条同 `docs_hash` 的规则评审是 `review.ok`、记了 `base` 时：取那次的 `base` 到这次的 `base` 之间 main 上新增或改过的、不是改动文档本身的生效或规划中规则和已接受决策——一份都没有 → 不调用评审命令，沿用那次的结论和意见，日志写明沿用的事件号、之后没有规则或决策合入 main、评审命令没有运行，记 `review.reused`（`review: land`、`by: docs`、`docs`、`docs_hash`、`from`、`commit`，以及 BR-2145 的 `landed`、`reviewed`、`notes`）；有 → 小评审：提示里的改动文档照旧，另有一节 `# Incremental review` 说明改动文档已通过哪次完整评审、只对照下面这些新文档，列出新文档全文，并按 BR-2405 附改动文档这次新增或改动的行，领域正文和索引只含改动文档和新文档，不是整个领域；日志写明对照的新文档编号；小评审的提示超过预算时照 BR-2359 拆成几次调用，每次都通过才算通过；记 `review.ok` 或 `review.block`（带 `docs_hash`、`base`、`incremental`（`from` 和新文档编号），不带 `hash`，所以 BR-2361 不会把它当成完整评审沿用），意见是那次的意见加这次的意见。其余情况（没有同 `docs_hash` 的评审、最近一条是 `block`、没记 `base`、`base` 在仓库里找不到）照常完整评审。合入后每次评审只看那次合入改动的文档，所以同一变更同样文字的改动文档再被评审，只在这个变更后来又合入了同样文字的文档时发生（例如别的变更改过它，这个变更又改回来）。预览评审（`canon work review`）和常驻说明的重复评审不适用这条（D-81）。

## 例子

- `C-1` 合入了 `BR-1`，合入后的评审通过；`C-2` 改了 `BR-1`，又合入了 `BR-2`；`C-1` 再次合入，把 `BR-1` 改回它第一次合入时的文字 → 评审命令运行一次，提示里有 `# Incremental review` 和 `BR-2` 的全文；`review.ok` 带 `incremental`（`from` 是第一次的事件号，`added` 是 `BR-2`），不带 `hash`；日志里仍有第一次的意见
- 同上，但两次合入之间 main 上没有别的规则或决策合入（只改了一个领域 README）→ 评审命令不运行，记 `review.reused`（`by: docs`），日志写明评审命令没有运行
- 改回时差了一个字 → 完整评审，提示里没有 `# Incremental review`
- main 上改了 `review` 命令的文字或 `review_max_prompt_kb` → 键不同，完整评审
- 同一文字的评审最近一次是 `block` → 完整评审
- 那次评审没有记 `base`（旧版本 canon 记的）→ 完整评审
