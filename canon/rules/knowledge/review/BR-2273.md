## 规则

已退役：负责人 2026-11-04 选择“整个删掉 (推荐)”，合入后一致性抽查连脚本和代码一起删除（D-43、C-299）。以下是退役前的内容。

一致性抽查（BR-2271）的准确率是：带 `canon-consistency` 标签、已关闭的 issue 里，结案原因是 `completed` 的个数除以已关闭的总数（`not planned` 和其他原因都算没说对；分拣只在评审说错了时才把这个标签的 issue 关成 `not planned`，已经在 main 上修好、重复、已知限制、被决策否决的都关成 `completed`，写在 canon-triage 里）。`bun scripts/consistency-review.ts --precision` 不需要 `CANON_BASE`、`CANON_HEAD`，不调用评审命令，只输出一行 `code-review: consistency: precision <completed 数>/<已关闭数>, <未关闭数> open`，退出码 0。作为 `after_land` 运行时，脚本在读改动之前先看两件事。一，未关闭的 issue 不少于 `--max-open`（默认 10）：没人在处理发现，已关闭数永远到不了停用线，不调用评审命令，输出 `code-review: consistency: off: <未关闭数> findings are still open (--max-open <n>); triage them, then it runs again`，退出码 0；处理到少于这个数后再运行就恢复。二，算准确率：已关闭数不少于 `--min-closed`（默认 10）、而且准确率低于 `--min-precision`（默认 0.5）时，不调用评审命令，输出 `code-review: consistency: off: precision <completed 数>/<已关闭数> is below <min-precision>; remove it from hooks.after_land`，退出码 0（D-43）。已关闭数少于 `--min-closed` 时照常运行。列出 issue 时 `gh` 以非 0 退出，输出 `code-review: consistency: <原因>`，退出码 1，不调用评审命令。`--min-closed`、`--max-open` 不是大于 0 的整数、`--min-precision` 不是 0 到 1 之间的数时退出码 2。

## 例子

- 已关闭 10 个，4 个 `completed`、6 个 `not planned`，默认停用线 → 不调用评审命令，输出 `code-review: consistency: off: precision 4/10 is below 0.5; remove it from hooks.after_land`，退出码 0
- 已关闭 10 个，5 个 `completed` → 等于 0.5，不低于，照常运行
- 已关闭 9 个，全是 `not planned` → 少于 10 个，照常运行
- 未关闭 10 个、已关闭 0 个 → 不调用评审命令，输出 `code-review: consistency: off: 10 findings are still open (--max-open 10); triage them, then it runs again`，退出码 0；未关闭 9 个 → 照常运行
- `--precision`，已关闭 3 个其中 2 个 `completed`，未关闭 4 个 → 输出 `code-review: consistency: precision 2/3, 4 open`，退出码 0
- 列出已关闭 issue 的 `gh` 以退出码 1 结束 → 退出码 1，评审命令没有被调用
- `--min-precision 2` → 退出码 2；`0` 和 `1` 是合法的（`0` 永远不因准确率停用，`1` 要求已关闭的全部是 `completed`）
- 已关闭 10 个全是 `not planned`、同时缺 `CANON_HEAD` → 退出码 2：参数和环境变量先于准确率检查（BR-2271）
