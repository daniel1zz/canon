## 规则

一致性抽查（BR-2271）的准确率是：带 `canon-consistency` 标签、已关闭的 issue 里，结案原因是 `completed` 的个数除以已关闭的总数（`not planned` 和其他原因都算没说对）。`bun scripts/consistency-review.ts --precision` 不需要 `CANON_BASE`、`CANON_HEAD`，不调用评审命令，只输出一行 `code-review: consistency: precision <completed 数>/<已关闭数>, <未关闭数> open`，退出码 0。作为 `after_land` 运行时，脚本在读改动之前先算准确率：已关闭数不少于 `--min-closed`（默认 10）、而且准确率低于 `--min-precision`（默认 0.5）时，不调用评审命令，输出 `code-review: consistency: off: precision <completed 数>/<已关闭数> is below <min-precision>; remove it from hooks.after_land`，退出码 0（D-43）。已关闭数少于 `--min-closed` 时照常运行。列出 issue 时 `gh` 以非 0 退出，输出 `code-review: consistency: <原因>`，退出码 1，不调用评审命令。`--min-closed` 不是大于 0 的整数、`--min-precision` 不是 0 到 1 之间的数时退出码 2。

## 例子

- 已关闭 10 个，4 个 `completed`、6 个 `not planned`，默认停用线 → 不调用评审命令，输出 `code-review: consistency: off: precision 4/10 is below 0.5; remove it from hooks.after_land`，退出码 0
- 已关闭 10 个，5 个 `completed` → 等于 0.5，不低于，照常运行
- 已关闭 9 个，全是 `not planned` → 少于 10 个，照常运行
- `--precision`，已关闭 3 个其中 2 个 `completed`，未关闭 4 个 → 输出 `code-review: consistency: precision 2/3, 4 open`，退出码 0
- 列出已关闭 issue 的 `gh` 以退出码 1 结束 → 退出码 1，评审命令没有被调用
- `--min-precision 2` → 退出码 2
