# 评审（knowledge/review）

合入时，改动过的规则和决策文字交给一个 AI 评审，对照它所在的整个顶层领域和所有规则的索引找矛盾；改动过的常驻说明（每个会话开始时都会读到的文字：`CLAUDE.md` 这类说明文件、skill 的 description、`canon brief` 的工作说明）也交给评审，找写在多处的同一条要求。拦截时合入被拒；合入后在后台运行代码评审脚本，只找安全和并发问题，发现的问题提成 GitHub issue。

## 业务

- **规则评审**：规则和决策的文字改动合入前要过的评审：什么时候评、评审看到什么、拦哪些事、给的建议去哪儿。
- **评审的提示和复用**：一次评审的提示有多大、超了怎么拆成几次调用、什么时候同样的文字不用再调一次评审命令。
- **常驻说明的重复评审**：每个会话都会读到的文字（配置的 instructions 和 canon-* skill）里同一条要求有没有写在两处，发布前也做一次。
- **合入后的代码评审**：main 前移之后在后台看代码：评哪些合入、只找什么问题、什么时候攒够了才评、评到哪里记在哪。
- **代码评审提的 issue**：代码评审的发现怎么落到 GitHub：一个根因一个 issue、正文写什么、gh 失败怎么办。
- **评审命令的约定**：canon 和评审命令之间怎么打交道：在哪跑、怎么传提示和读结论、超时怎么办、结论由谁说了算、没配置评审时合入怎么处理。
- **合入前的预览评审**：在变更的工作树里先用 main 的评审命令看一遍当前的文字，只报告，不影响合入。

## 术语

- **拦截（block）**：评审认为改动和已有规则或决策冲突、在新写的行里复述了别的规则的行为（BR-2405），或者常驻说明里同一条要求写在了多处，合入被拒。
- **常驻说明**：每个会话开始时都会读到的文字，见 BR-2143。
- **建议（note）**：不拦截的评审意见。不单独开变更，记在合入事件里，等下次有人改它点名的文档时处理（D-21）。
- **未处理的建议**：一份文档最近一次被评审并成功合入时得到的建议；再次评审这份文档时被替换。
