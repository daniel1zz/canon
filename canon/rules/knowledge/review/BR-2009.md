## 规则

一次合入新增、修改或删除了 `canon/rules`、`canon/decisions` 或 `canon/releases` 下的任何文件（包括领域 README），且配置了评审命令时，评审收到规则、版本和决策的新文字、被删除文件在 main 上的原文，以及每个受影响领域的完整上下文；受影响的领域是：改动的规则所在的领域、改动的决策提到的规则所在的领域、README 被改的领域、被删除的规则原来所在的领域，以及被删除的决策在 main 上的原文提到的规则所在的领域；受影响的是子领域时，给的是它所在的整个顶层领域（含全部子领域），这样跨子领域的矛盾也能被发现；一个顶层领域只给一次；被删除的规则所在的整个顶层领域也被删掉时，没有当前内容可给，只给原文；被删除的领域 README 也给 main 上的原文；只是换了路径、内容完全相同的文件（新旧两边是同一个 git 对象）不算新增、修改或删除，不交给评审；项目的 `canon/architecture.md` 除标题外有内容时，它也作为上下文交给评审（写明这次合入有没有改它，改了的给出差异），但不算“改动的文件”，也不让评审的触发条件变宽：只改了总览、没有改上面三个目录下的文件的合入不评审；评审被告知总览只是读者的入口，和规则、已接受的决策矛盾时以后者为准：只有这次合入改过的那部分总览和生效的规则或已接受的决策矛盾时才 `block`，这次合入改的规则或决策让总览里的某句话不对时只给建议（不拦）；结论为 `block`、评审命令运行失败或没有输出有效结论时都拒绝合入，main 不动。

## 例子

- 总览有内容，这次合入改了一条规则、没改总览 → 评审收到总览全文，标明这次合入没有改它
- 这次合入同时改了规则和总览 → 评审还收到总览的差异；评审返回 `block` → 合入被拒绝
- 总览除标题外没有内容，或者项目没有总览 → 评审的输入里没有总览一节
- 这次合入只改了 `canon/architecture.md` → 不调用评审
- 新规则写“退款大概会在某个时间后处理”，评审返回 `block` → 合入被拒绝，退出码 1，main 不变
- 评审命令退出码非 0 → 合入被拒绝，提示评审无法运行
- 只改了 billing 领域的 README，评审返回 `block` → 合入被拒绝
- 只改了 `canon/releases/` 下一个版本文档的 `## 不做`，评审返回 `block` → 合入被拒绝；评审返回 `ok` → 合入继续，评审收到这个版本文档的新文字
- 改了 work/land 里的一条规则 → 评审收到整个 work 领域（含 work/claims 等子领域）的全文
- 把 `canon/rules/work/BR-1.md` 原样挪到 `canon/rules/work/land/BR-1.md`，没有别的规则改动 → 不调用评审
- 挪动的同时改了一个字 → 按删除旧文件、新增新文件评审
- 用 `git rm` 删掉一条规则文件 → 评审收到这条规则删除前的原文；返回 `block` 时合入被拒绝
- 只用 `git rm` 删掉 work/land 里的一条规则 → 评审还收到整个 work 领域现在的全文（含 work/land 剩下的规则和 work/drop 等子领域）
- 删掉的决策在 main 上写着“因为 `BR-4`”，`BR-4` 在 billing → 评审收到 billing 的全文
- 删掉整个 gone 领域（README 和全部规则）→ 评审收到这些规则和 README 在 main 上的原文，没有 gone 的当前内容
