## 规则

一次合入新增、修改或删除了 `canon/rules`、`canon/decisions`、`canon/releases`、`canon/features` 或 `canon/quality` 下的任何文件（包括领域 README；方面清单 `canon/quality/README.md` 除外，见 BR-2559），且合入前的 main 上配置了评审命令（D-51）时，合入之后的评审（BR-2441）收到规则、版本和决策的新文字、功能模块和质量标准的新文字、被删除文件在 main 上的原文，以及每个受影响领域里和改动直接相关的文档（领域区，提示超过 `review_max_prompt_kb` 时按 BR-2359 分次调用；改动文档本身放不进一次调用时按 BR-2448 分部分）；受影响的领域是：改动的规则所在的领域、改动的决策、版本或功能模块提到的规则所在的领域（main 上已有的决策、版本或功能模块只算这次合入新写或改动的那些行里提到的，没改的行不算；新建的算它全文提到的，#237）、README 被改的领域、被删除的规则原来所在的领域，以及被删除的决策在 main 上的原文提到的规则所在的领域；领域区不给整个顶层领域，只给这些文档的全文（D-137、D-138）：改动的规则所在的那个领域（顶层或子领域，不含它的子领域）的全部规则、点名任何一份改动或被删除文档的生效规则和已接受决策、改动文档点名的文档、被删除文档在 main 上的原文点名的文档、按 BR-2387 和每份改动的规则或决策最相关的前 10 份，以及它们所在领域和上层领域的 README；README 被改的领域给出它全部的规则；领域里其余的规则只在规则索引里列出编号和标题，不在同一领域、彼此不点名又不相关的两份文档之间的矛盾，这次评审因此看不到、不会报出，要等之后某次评审把两份文档放进同一份提示（例如改到其中一份时它们已互相点名或进了最相关的前 10 份）才会报出；这样晚报出的矛盾怎么记录、超过多少要放宽范围见 D-138；一个顶层领域只给一次；每条改动的规则还附上点名它、在运行的测试的标题（取自 canon 记下的测试报告，BR-2005；每条最多 10 个并写明总数，没有就写明没有），评审被告知列出了测试的规则由这些测试判定，不能以“没有测试”为由判为不可测（#265）；被删除的规则所在的整个顶层领域也被删掉时，没有当前内容可给，只给原文；被删除的领域 README 也给 main 上的原文；只是换了路径、内容完全相同的文件（新旧两边是同一个 git 对象）不算新增、修改或删除，不交给评审；只有 frontmatter 的 `links` 复核记录（BR-2425）变了、正文和其余 frontmatter 完全相同的文件同样不算改动、不交给评审，因为复核记录由命令写入、由 `canon check` 核对，不是评审能判断的文字；决策只改了 `- 来源：` 行（例如引用的代码搬到了别的文件），其余正文和 frontmatter 完全相同的，也不算改动、不交给评审，因为来源由合入按 BR-2111 核对摘录，不是设计内容（#240），合入输出写明有几份这样的决策；项目的 `canon/architecture.md` 除标题外有内容时，它也作为上下文交给评审（写明这次合入有没有改它，改了的给出差异），但不算“改动的文件”，也不让评审的触发条件变宽：只改了总览、没有改上面三个目录下的文件的合入不评审；评审被告知总览只是读者的入口，和规则、已接受的决策矛盾时以后者为准：只有这次合入改过的那部分总览和生效的规则或已接受的决策矛盾时才 `block`，这次合入改的规则或决策让总览里的某句话不对时只给建议（不拦）；评审说明要求列出发现的每一个拦截问题，不只第一个，因为漏报的问题会在同一份文字之后的合入里再拦一次；拦截问题必须涉及至少一份改动文档（新增、修改或删除的规则、决策、版本，#173），只在没改动的文档之间的问题只能是建议（`note`）。评审的结论不影响合入：拦截问题按 BR-2442 记账；评审命令运行失败或没有输出有效结论时，这次评审记为失败（BR-2441）。同一变更的改动文档已经通过过完整评审的，按 BR-2396 只做小评审或沿用，不按这条给完整上下文。

领域区中，已在同一次提示的 `# Changed documents` 里给出全文的规则只列一行编号和标题（保留规划中、版本和业务标记），正文从该节读取；其他规则仍给全文。预览评审、分次调用和小评审都这样显示；按 BR-2448 分部分时，只看当前部分的 `# Changed documents`，其他部分的改动规则不因此省略领域正文。仅在被点名文档一节给了全文的规则不在此省略范围内。

评审的说明还要求：这次合入新加或改动的规则、决策让命令拒绝、等待或停下工作，而这个拒绝不属于 D-139 的四类（保证 main 正确和文档不说谎、防止丢数据和安全问题、保护机器容量、负责人明确要求），或者会挡住和它要处理的问题无关的工作时，提一条 `note`（不拦），点名这个拒绝，建议改成标准加提醒。

## 例子

- 决策只把 `- 来源：a.gd “x”` 改成 `- 来源：b.gd “x”` → 不交给评审，合入输出 `review: 1 decision(s) only changed their 来源 lines, which the landing checks; not reviewed`；同一次还改了它的一句背景 → 照常评审
- main 上的版本 `R-5` 点名了 116 条分布在多数顶层领域的规则，这次合入只给它加了一行，点名的都是 `power` 领域的规则 → 评审的领域上下文只有 `power`；新建的版本点名两个领域的规则 → 两个领域都给
- billing 领域有 `BR-1`、`BR-2`，只改 `BR-1` → `# Changed documents` 给 `BR-1` 全文，领域区只列 `BR-1` 的编号和标题，`BR-2` 仍给全文；换成只改 `BR-2` 时，省略正文的也换成 `BR-2`
- `BR-1`、`BR-2` 的改动按文档分在两个部分 → 第一部分领域区的 `BR-1` 只列编号和标题、`BR-2` 给全文；第二部分反过来
- 改动的 `BR-1` 点名未改动的 `BR-2`，拆分提示的被点名文档一节给 `BR-2` 全文 → `BR-2` 在领域区仍给全文
- 小评审对照改动的 `BR-1` 和新合入 main 的 `BR-2` → 改动文档仍完整，领域区若列 `BR-1` 则只列编号和标题，新文档正文仍完整

- 总览有内容，这次合入改了一条规则、没改总览 → 评审收到总览全文，标明这次合入没有改它
- 这次合入同时改了规则和总览 → 评审还收到总览的差异；评审返回 `block` → 合入照常成功，评审事件是 `review.block`
- 总览除标题外没有内容，或者项目没有总览 → 评审的输入里没有总览一节
- 这次合入只改了 `canon/architecture.md` → 不调用评审
- 新规则写“退款大概会在某个时间后处理”，评审返回 `block` → 合入成功，main 前移；之后的评审记一条 `review.block`，意见按 BR-2442 记账
- 评审的提示 → 说明里要求列出每一个拦截问题，并写明只在没改动的文档之间的问题只能是 `note`
- 评审的提示 → 说明里要求：新加的拒绝不属于四类、或挡住无关工作时，给一条 `note` 并建议改成提醒（D-139）
- 评审命令退出码非 0 → 合入照常成功，这次评审记为失败，日志里写明评审无法运行
- 只改了 billing 领域的 README，评审返回 `block` → 评审事件是 `review.block`
- 只改了 `canon/releases/` 下一个版本文档的 `## 不做` → 评审收到这个版本文档的新文字；返回 `block` 时评审事件是 `review.block`，返回 `ok` 时是 `review.ok`
- 只新建了 `canon/features/F-1.md` → 评审收到 `F-1` 的新文字（#249）
- 只新建了 `canon/quality/Q-1.md` → 评审收到 `Q-1` 的新文字（BR-2559）
- 改了 work/land 里的一条规则 `BR-7`，work/claims 的 `BR-8` 点名 `BR-7`，work/drop 的 `BR-9` 和它既不互相点名、也不在它最相关的前 10 份里 → 领域区给 work/land 里全部规则的全文、`BR-8` 全文和 work、work/land、work/claims 的 README，`BR-9` 只在规则索引里有编号和标题；提示超过预算时，这些全文分在几次调用里，每次都带这条改动的规则（BR-2359）
- 改了 billing 的 README → 领域区给 billing 全部规则的全文
- 改了 work 下的一条规则，work/land 的 `BR-11` 和它不互相点名、也不相关 → `BR-11` 只在规则索引里；改的是 work/land 下的规则时 `BR-11` 给全文
- 只改了一份决策 → 没有改动的规则，不因此多给哪个领域的全部规则
- 改动的 `BR-7` 有 3 个标题点名它的测试 → 提示的测试一节在 `BR-7` 下列出这 3 个标题；改动的 `BR-10` 没有 → 写明没有在运行的测试点名它
- 一次合入只用 `canon links confirm` 更新了几十份文档 frontmatter 里的 `links` 记录，正文一字未动 → 不调用评审
- 更新一份文档的 `links` 记录的同时改了它正文的一个字，或它 frontmatter 的 `title` → 这份文档照常评审
- 把 `canon/rules/work/BR-1.md` 原样挪到 `canon/rules/work/land/BR-1.md`，没有别的规则改动 → 不调用评审
- 挪动的同时改了一个字 → 按删除旧文件、新增新文件评审
- 用 `git rm` 删掉一条规则文件 → 评审收到这条规则删除前的原文
- 只用 `git rm` 删掉 work/land 里的一条规则 → 评审还收到 work 领域里仍然点名它的规则和决策的全文，以及 work 和 work/land 的 README
- 删掉的决策在 main 上写着“因为 `BR-4`”，`BR-4` 在 billing → 评审的领域区有 billing 的 README 和 `BR-4` 的全文，billing 里和它无关的规则只在规则索引里
- 删掉整个 gone 领域（README 和全部规则）→ 评审收到这些规则和 README 在 main 上的原文，没有 gone 的当前内容
