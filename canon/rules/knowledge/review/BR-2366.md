## 规则

规则评审和常驻说明的重复评审（BR-2216）运行 `review` 命令时，命令的环境里都有 `CANON_REVIEW_KIND`：合入后的评审（`canon work review-landed`，BR-2441）和合入里的措辞判断（`canon work land`，BR-2239）运行的是 `land`，`canon work review`（BR-2358）运行的是 `preview`，canon 仓库发布前的发布评审（BR-2411）运行的是 `release`，`canon finding reconcile`（BR-2461）运行的是 `reconcile`；同一个命令里规则评审和重复评审、拆成几次的调用（BR-2359）都带同一个值。环境里的其他变量照旧传给命令；调用 canon 的进程环境里本来就有 `CANON_REVIEW_KIND` 时，以 canon 设的为准。这个变量只用来让命令自己选模型之类的做法，不改变提示、结论的格式、超时，也不改变评审通不通过的判断。沿用已通过的评审（BR-2361；发布评审按 BR-2411 沿用）时不运行命令，也就没有这个变量。配置参考里 `review` 的说明写明这个变量和它的四个取值。

## 例子

- `canon work land` 改了一条规则，评审命令是 `printenv CANON_REVIEW_KIND > f; …` → `f` 里是 `land`
- 同一个变更运行 `canon work review` → 评审命令里是 `preview`
- 变更同时改了规则和 `CLAUDE.md` 的一行，运行 `canon work review` → 规则评审和重复评审两次运行里都是 `preview`
- 合入后的评审的提示被拆成两次调用 → 两次里都是 `land`
- 运行 `CANON_REVIEW_KIND=land canon work review` → 评审命令里仍是 `preview`
- canon 仓库的发布评审（BR-2411）→ 评审命令里是 `release`
- 评审命令不读这个变量 → 评审照常，结论的处理没有变化
- 同一份提示在预览里通过过，再合入 → 合入后的评审运行评审命令，里面是 `land`（BR-2361）
