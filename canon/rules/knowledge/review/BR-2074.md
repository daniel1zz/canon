title: 有规则或决策改动但没有配置评审命令时拒绝合入，review 写成 none 才明确跳过评审
status: active

## 规则

要不要评审，看这次合入改了什么（下面和 BR-2143 列出的文件）。怎么评审：评审命令 `review`、时限 `review_timeout_minutes`（BR-2296）、每次调用提示的预算 `review_max_prompt_kb`（BR-2359）和常驻说明清单 `instructions`（BR-2143），都取自 main 上（合入开始时 main 的提交，一起测时是整批的 base，同 BR-2248）的 `canon/config.yaml`，也就是已经合入、可信的配置；不取自被合入的树，也不取自运行 `canon work land` 的 worktree 合入开始时读到的配置。理由：取自变更自己的树时，变更可以在同一次合入里把评审命令换成总是回答 ok 的命令，给自己的文字放行（#115）。所以在一次合入里改 `review`，只对之后的合入生效。

一次合入新增、修改或删除了 `canon/rules`、`canon/decisions` 或 `canon/releases` 下的文件，main 上却没有配置 `review`（没有这个键，或者值为 `null`、空字符串、只有空白）时，合入被拒，退出码 1，原因 `review`，main 不动，即使这次合入自己设了 `review`；信息列出要评审的文档，说明要先单独合入一个只设 `review` 的变更、再合入这些改动，并给出评审命令的写法：把 `review` 设成从标准输入读提示、在标准输出给出结论 JSON 的命令（BR-2216），例如 `review: "claude -p --model sonnet --output-format text"`；再建议 `review: none` 先用 `canon human ask` 问负责人，得到同意后单独合入；canon 不核对写 `none` 的是谁、问没问过（BR-2295）。

`review: none` 表示项目明确不评审：main 上已经是这个值时，这样的合入照常进行，输出 `review: none` 和被跳过的文档，并写一条 `review.skip` 事件。`none` 不是命令，不按 BR-2197 检查。在同一次合入里把 `review` 改成 `none` 见 BR-2295；写成 `None`、`"none "` 这类去掉空白、不分大小写后是 `none` 的值是配置错误（BR-2045）。例外：正在关闭的变更带审查判定为措辞修改的通过记录时，没有评审来判断，没有配置和 `review: none` 都拒绝合入（原因 `review`，BR-2239）。

## 例子

- 改了一条规则，main 上没有 `review` → 退出码 1，原因 `review`，信息含这条规则的编号，`claude -p --model sonnet --output-format text` 出现在 `review: none` 之前，信息含 `canon human ask`，事件表没有 `review.skip`，main 不变
- 只新增了一个版本文档，main 上没有 `review` → 同样被拒，原因 `review`，信息含这个版本的编号
- 只删了一条决策，main 上 `review: ""` 或 `review: "  "` → 同样被拒，原因 `review`
- main 上是 `review: none`，改了一条规则 → 输出含 `review: none`，事件表多一条 `review.skip`，合入成功
- 只改了代码和变更文件，main 上没有 `review` → 不评审，合入成功
- main 上的评审命令回答 `block`，变更把 `review` 换成总是回答 `ok` 的命令，又改了一条规则 → 用 main 上的命令评审，合入被拒，原因 `review`，变更里那条命令没有运行
- main 上没有 `review`，变更同时设了评审命令、又改了一条规则 → 拒绝，原因 `review`，信息说先单独合入 `review`；只设 `review` 的变更合入后，再改规则的合入用这条命令评审
- worktree 建立时 main 上还是 `review: none`，之后 main 上改成了评审命令，这个 worktree 没动 `review`、改了一条规则再合入 → 用 main 上现在的评审命令，这条规则被评审
- main 上配好了评审命令，worktree 从更早、还没有 `review` 的 main 建立，没动 `review`、改了一条规则 → 不因“没有配置”被拒，规则被评审
- `review: none`，关闭的变更带一条 `… wording` 的通过记录 → 拒绝，原因 `review`
