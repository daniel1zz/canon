status: active

## 规则

一次合入新增、修改或删除了 `canon/rules` 或 `canon/decisions` 下的文件，配置里却没有 `review`（没有这个键，或者值为空、`null`）时，合入被拒，退出码 1，原因 `review`，main 不动；信息列出要评审的文档，并说明两种做法：把 `review` 设成评审命令（从标准输入读提示、在标准输出给出结论 JSON，BR-2216），例如 `claude -p --output-format text`；或者写 `review: none` 明确不评审。

`review: none` 表示项目明确不评审：这样的合入照常进行，输出 `review: none` 和被跳过的文档，并写一条 `review.skip` 事件。`none` 不是命令，不按 BR-2197 检查。例外：正在关闭的变更带审查判定为措辞修改的通过记录时，没有评审来判断，没有配置和 `review: none` 都拒绝合入（原因 `review`，BR-2239）。

## 例子

- 改了一条规则，配置里没有 `review` → 退出码 1，原因 `review`，信息含这条规则的编号、`review: none` 和怎么配置评审命令，事件表没有 `review.skip`，main 不变
- 只删了一条决策，配置里 `review: ""` → 同样被拒，原因 `review`
- 改了一条规则，配置是 `review: none` → 输出含 `review: none`，事件表多一条 `review.skip`，合入成功
- 只改了代码和变更文件，配置里没有 `review` → 不评审，合入成功
- `review: none`，关闭的变更带一条 `… wording` 的通过记录 → 拒绝，原因 `review`
