id: BR-2359
title: 规则评审的提示超过预算时按子领域拆成几次调用，意见合并
status: active
---

## 规则

规则评审（BR-2009）的提示按 UTF-8 字节算，超过 `review_max_prompt_kb`（千字节，默认 250）时，评审分成几次调用，依次运行：每次调用都带评审说明、全部改动文档的全文、被删除文档的原文、总览、规则标题索引和已接受决策的标题（合起来是固定部分），再加受影响领域全文的一部分；全文按子领域装箱：每个子领域连同它各层上级领域的说明（README）一起装，一个子领域放得进当前这次调用的剩余空间就装进去，放不进就开下一次调用，一个子领域连空的一次调用都放不下时，按规则逐条装；每次调用的提示都不超过预算。一次就装得下时只调用一次，提示和没有预算时完全相同。各次的意见合并，按原文去重；任何一次 `block` 合并后就是 `block`，任何一次运行失败或结论无效，合入按 BR-2216 被拒绝（不再运行后面的调用）；`review_timeout_minutes` 对每次调用分别计时；措辞判断（BR-2239）只在第一次调用里问，后面的调用不带。固定部分本身（或其中带着一条规则的最小一次）超过预算时，不调用评审命令，合入以原因 `review` 被拒绝，信息写明需要多少 KB、预算多少 KB，和最小一次的三个部分各多少 KB（改动文档；评审说明加规则索引加已接受决策的标题；领域的那一块，固定部分本身超过预算时是 0）。补救办法按哪一部分大来说：改动文档是三部分里最大的一块（不小于另两块），并且去掉改动文档后剩下的两块加起来还放得进预算时，说明把改动拆成几次合入；否则说明拆变更没有用（改动文档不是让它超过预算的部分），并写明能用的办法：把 `review_max_prompt_kb` 调到至少需要的 KB，领域的那一块（某个领域的 README 或某一条规则带着它上层的说明）是原因时，再加一条：把这个领域用 `canon rule domain <领域>/<名字>` 拆成子领域。分成几次调用时，合入的输出写明调用次数和每次的 KB；每次调用的提示里也写明这是第几次、共几次，只看到部分领域，不能因为没看到某条规则而 `block`。

## 例子

- 提示 200 KB，预算 250 → 一次调用，提示和没有预算时逐字相同，输出里没有“分成几次”的说明
- 提示 400 KB，预算 250，固定部分 100 KB，受影响的顶层领域有两个子领域各 150 KB 的规则 → 两次调用，每次都带全部改动文档，每次提示不超过 250 KB，输出写明 2 次和每次的 KB
- 改一条大领域的规则，该领域的各子领域放不进一次 → 分成几次，每次调用里都有这条改动规则的全文
- 一个子领域的规则合计 300 KB、每条 10 KB → 按规则逐条装，每次不超过预算
- 两次调用，第二次返回 `block`、意见 `X` → 合入被拒绝，信息里有 `X`；第一次返回 `block` 同样被拒绝
- 两次调用都返回意见 `same note` → 合并后只有一条
- 第一次调用评审命令以退出码 1 失败 → 合入被拒绝（BR-2216），第二次调用没有运行
- 有措辞判断的规则 → 只有第一次调用的提示里有 `# Wording judgements`
- 固定部分 300 KB（其中改动文档 280 KB），预算 250 → 评审命令一次也没运行，合入被拒绝，原因 `review`，信息里有 300 和 250、三部分的 KB 和“拆成几次合入”
- 最小一次共 34 KB（改动文档 1 KB，规则索引等 3 KB，某个子领域的一条规则带着上层说明 30 KB），预算 25 → 拒绝，信息里有三部分的 KB、最小一次需要 34 KB（`review_max_prompt_kb` 至少要 34 KB）和 `canon rule domain <领域>/<名字>`，说拆变更没有用，没有“拆成几次合入”
- 某个领域的 README 本身 40 KB，预算 20，改动文档很小 → 拒绝，信息点名这个 README 的领域，说拆变更没有用，给出调大预算和拆子领域两个办法
- 规则索引加决策标题加评审说明 30 KB，预算 20，改动文档 1 KB → 拒绝，信息说拆变更没有用，只说调大 `review_max_prompt_kb`，没有拆子领域的办法
- 改动文档 40 KB，其余两块各 3 KB，预算 20 → 拒绝，信息说拆成几次合入
- `review_max_prompt_kb: 0` → 配置错误，退出码 2（BR-2045）
