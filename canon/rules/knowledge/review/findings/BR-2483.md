## 规则

`canon finding amend <意见编号> (--fixed <提交> | --spurious "<原文>") --reason "<原来的结案为什么错了>"` 更正一条已关闭意见的结案（#221）：结案方式记错了（真问题被记成不成立，或者修复提交记错了）。它和 `canon finding close` 走同样的检查，顺序和退出码按 BR-2453，之后按意见的档位核对凭据，按 BR-2478（`--owner`、`--covers` 也一样，按 BR-2480）；不同的只有：

- 意见还开着 → 冲突（退出码 5），提示用 `canon finding close`。
- 更正后的结案和现在的结案一样（同样的方式，同一个修复提交或同一段原文）→ 冲突，什么都不写。
- 理由为空 → 用法错误，提示写明原来的结案为什么错了。

通过时在同一个写事务里写一条 `finding.amend` 事件，详情和 `finding.close` 的一样，另带 `from`：原来结案的方式、提交或原文、事件编号和理由；意见的结案方式改成新的，结案事件改成这条事件，关闭时间不变。原来的结案事件留在事件表里，不改。输出 `amended review finding #<编号>: now fixed by <提交前 9 位>|now spurious, quoted from <文档>; was <原来的方式> (event <原来的事件编号>)`。

为了能更正，已关闭的意见也能用 `canon finding tier`、`canon finding advise` 和 `canon finding ask`（BR-2477、BR-2479、BR-2480）。

## 例子

- 意见 #1 是 B 档，按不成立关闭（事件 e1），顾问支持修复 X 后，`canon finding amend 1 --fixed X --reason "顾问查明是真问题"` → 输出 `amended review finding #1: now fixed by <X 前 9 位>; was spurious (event e1)`；#1 的结案方式是 `fixed`，结案事件是新的 `finding.amend`，它的 `from` 是 `spurious`、那段原文和 e1；e1 仍是 `finding.close`
- 再执行一次同样的更正 → 冲突，输出含 `is already closed as fixed by`
- 没有顾问支持 X 时更正成 `--fixed X` → 拒绝，输出含 `another session must support`
- `--reason " "` → 用法错误
- #2 还开着，`canon finding amend 2 --fixed X` → 冲突，输出含 `is still open`
- #2 已关闭但还没定档，agent 会话更正 → 拒绝，输出含 `has no tier yet`；定为 A 档后按修复更正 → 成功，按不成立更正 → 拒绝
- 负责人在 agent 会话之外执行，不论档位 → 只按 BR-2453 核对
