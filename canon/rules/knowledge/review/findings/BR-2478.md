## 规则

`canon finding close` 先按 BR-2453 核对修复提交或原文，再按意见的档位（BR-2477）核对谁能结案（D-118）。结案的人是谁，只从宿主环境判断，不看 `--as` 和 `CANON_ACTOR`：不在 agent 会话里的人就是负责人，任何档位都只要 BR-2453 的凭据。agent 会话：

- 还没定档 → 拒绝，提示先 `canon finding tier`。
- 带了 `--owner <问题编号>` → 按 BR-2480 核对负责人的批准，通过就能结案，不论档位。
- C 档没带 `--owner` → 拒绝，提示用 `canon finding ask` 问负责人。
- A 档按修复（`--fixed`）结案 → 可以；按不成立（`--spurious`）结案 → 拒绝，提示升到 B。
- B 档 → 要有另一个会话按 BR-2479 支持的就是这一种结案（同一个修复提交，或同一段原文）；结案的会话自己的意见不算；任何一个会话对这种结案最新的意见是反对 → 拒绝；没有支持 → 拒绝，提示去找另一个会话，没有别的会话可找时改问负责人（`canon finding ask`，再 `--owner`）。

`finding.close` 事件另外记下档位，以及凭据：负责人结案的写 `by: owner`，B 档写支持它的会话，用了负责人回答的写问题编号（和引用的原文）。

## 例子

- agent 会话关还没定档的 #1 → 拒绝，输出含 `has no tier yet`
- #1 是 A 档，`--fixed` 一个修复提交 → 关闭；`--spurious "untested: fixture"` → 拒绝，输出含 `a spurious close needs another session's support`
- #1 是 B 档，只有结案的会话自己记了支持 → 拒绝
- #1 是 B 档，另一个会话支持修复提交 X，结案用的是更新的提交 Y → 拒绝；那个会话后来又反对 X → 用 X 结案被拒绝，输出含 `opposes`；它再支持 Y → 用 Y 结案成功，事件里有 `tier: B` 和那个会话
- #1 是 B 档，没有别的会话支持 → 拒绝，输出含 `ask the owner instead (canon finding ask 1, then --owner <question>)`；负责人批准后带 `--owner` 结案 → 关闭
- #1 是 C 档，不带 `--owner` → 拒绝，输出含 `the owner decides`
- 不在 agent 会话里的人关还没定档的 #1 → 关闭，事件里有 `by: owner`
