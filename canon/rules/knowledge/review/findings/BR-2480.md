## 规则

`canon finding ask <n> --fixed <提交>|--spurious "<原文>" --reason "<这样结案做了什么>"` 记一个待答问题（BR-2021）：问题文字是 `Close review finding #<n> ([<标准>] <编号>: <意见文字>) as <fixed by <提交前 9 位>|spurious, quoting "<原文>">? <理由>`，选项是 `approve: close it this way` 和 `reject: do not close it this way`，问题绑定这条意见和这一种结案，并记进意见的 `question`，所以等回答期间它不算欠账（BR-2464），回答之后重新算。这条意见已经在等一个没回答的问题时拒绝（冲突）。

结案带 `--owner <问题编号>` 时（BR-2478）：问题必须存在并且已经回答；转述的回答被提问工具的记录否定（`differs`）或记录里没有这个问题（`unasked`）时拒绝（BR-2276）。问题是 `canon finding ask` 记的 → 必须是问这条意见、这一种结案的，回答必须是 `approve: close it this way`。别的问题 → 要加 `--covers "<它的问题或回答里至少 8 个字符的原文>"`，原文必须在那里，事件里记下这段原文，这样负责人以前已经定了的事不用再问一遍（D-118）。

## 例子

- #1 是 C 档，`canon finding ask 1 --fixed X --reason "..."` → 记下问题 #q，文字以 `Close review finding #1 ([contradiction] BR-1, BR-2: ` 开头，#1 的 `question` 是 #q；再问一次 → 冲突，输出含 `already waits on owner question`
- #q 还没回答，`--owner q` → 拒绝，输出含 `not answered yet`
- #q 的回答是 `reject: do not close it this way` → 拒绝，输出含 `did not approve`
- 新问题 #r 回答了 approve，但提问工具的记录是 `differs` → 拒绝，输出含 `not backed`
- #r 批准的是用 X 结案，结案用的是 Y → 拒绝，输出含 `ask again for this close`；用 X → 关闭
- 一个早先回答了的问题 `Should domestic orders keep the three-day refund window?`，不带 `--covers` → 拒绝，输出含 `add --covers`；`--covers "overseas orders only"` → 拒绝；`--covers "keep the three-day refund window"` → 关闭，事件里记下问题编号和这段原文
- 一个 `canon finding ask` 为别的意见记的问题 → 拒绝，输出含 `asked about finding #`
