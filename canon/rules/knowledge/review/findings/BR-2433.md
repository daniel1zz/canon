status: active

## 规则

评审意见的身份由三部分组成：标准、点名的编号、被指出原文的哈希。标准是意见点名的拦截标准名：事件里存成 `[标准名] 文字` 的取方括号里的名字，其余的是 `note`。点名的编号是意见文字里出现的规则、决策和发布编号（`BR-n`、`D-n`、`R-n`，按完整编号匹配，写在引号里的也算），去重后按字符串排序。被指出的原文取意见里写在 `「」`、`“”` 或一对不跨行的反引号里的每一段：空白压成一个空格、去掉首尾空白，去掉空的段和只由编号、逗号、顿号、空白组成的段，剩下的去重、排序后用换行连起来；一段也不剩时，被指出的原文是整条意见文字，空白压成一个空格、去掉首尾空白。哈希是它的 SHA-256 十六进制的前 16 位。三部分都相同的两条意见是同一条意见，措辞不同也一样（D-89）。

## 例子

- `[contradiction] BR-1 的「退款三天内到账」和 BR-2 的「退款七天内到账」矛盾` 与 `[contradiction] BR-2 写「退款七天内到账」，与 BR-1 的「退款三天内到账」冲突` → 同一身份
- 把第一条的标准换成 `[restatement]` → 不同身份
- 第二条引的是「退款五天内到账」 → 不同身份
- `[contradiction] BR-1 和 BR-2 的“三天”矛盾` 与 `[contradiction] BR-2、BR-1 互相矛盾：「三天」` → 同一身份（引号种类和编号顺序不影响）
- 反引号里只有编号：`` [contradiction] `BR-1` 和 `BR-2` 矛盾 `` 与 `[contradiction] BR-1 与 BR-2 矛盾` → 两条都没有原文段，按整条文字算，文字不同，身份不同
- `[untestable]  BR-1 写得   太含糊` 与 `[untestable] BR-1 写得 太含糊` → 只差空白，同一身份
- 意见点名 `BR-201` → 点名的编号是 `BR-201`，不含 `BR-20`
- 存成 `措辞可以更短` 的意见 → 标准是 `note`
