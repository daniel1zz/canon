## 规则

`canon finding reconcile <编号> <编号>` 把两条评审意见（开着或已关闭的都行，编号可带 `#`）连同它们挂的每份文档在 main 上的全文交给合入前 main 配置的 `review` 命令（运行方式、时限同 BR-2216），要它判断两条意见是不是把同一处文字往相反方向拉，是就给出一个两边都满足的写法。按这个顺序检查，先成立的决定退出码：两个编号缺一个、相同或不是正整数 → 退出码 2；有一个编号不存在 → 退出码 3；两条意见没有共同挂着的文档 → 退出码 2；这两条意见已有未回答的裁决问题 → 退出码 5，信息写明问题编号；`review` 没配置或评审命令运行失败、超时、没给出有效结论 → 退出码 4，什么都不记。

评审的回答是一个 JSON 对象：`opposed`（布尔）、`wording`（两边都满足的写法，`opposed` 为真且给得出时）、`reason`。提示不按 BR-2359 拆分：评审命令因提示过大或别的原因失败就是上面的退出码 4。评审给出有效回答的每次运行写一条 `finding.reconcile` 事件（详情有 `findings`、`opposed`、`wording` 或 `question`、`reason`）；被前面的检查拒绝时没有事件。结果三种：

- 不相反（`opposed` 为假）→ 输出理由，退出码 0，意见不变；
- 相反且给出写法 → 输出写法和理由，退出码 0；写法不关闭意见，主会话把它落进一次合入后照常 `canon finding close --fixed`；
- 相反且给不出写法 → 在同一个写事务里先重查两条意见（评审运行期间被关闭、或已有未回答的裁决问题 → 退出码 5，什么都不记），再自动记一条留给人的问题（`canon human ask` 同一张表）：正文含两条意见的编号和原文、评审的理由；问题编号写进两条意见的 `question` 列；输出问题编号，退出码 0。负责人回答后由主会话按答案处理两条意见。

合入后评审记录新拦截意见时，它的文档组和某条未处理意见的文档组完全相同的，日志多一行提示可以运行 `canon finding reconcile <旧编号> <新编号>`；提示是机械对比，不调用模型，不改变评审结论。

## 例子

- #5（要求 `BR-8` 指向 `BR-37`）已 `--fixed` 关闭，#7 拦 `BR-8` 指向后的写法，`canon finding reconcile 5 7` → 评审答 `opposed: true` 并给出写法 → 输出写法，`finding.reconcile` 事件记两个编号和写法，#5、#7 不变
- 同样的两条，评审答 `opposed: true` 但给不出写法 → 新问题出现在 `canon human pending`，正文含 `#5`、`#7` 和两条原文；两条意见的 `question` 列是它的编号
- 评审答 `opposed: false`（两条意见说的是两处不同的文字）→ 退出码 0，输出理由，没有新问题
- 再运行一次 `canon finding reconcile 5 7`，上次的裁决问题还没人回答 → 退出码 5，信息含问题编号
- 两个会话同时 reconcile 同一对，评审都答给不出写法 → 只有一个写进问题，另一个退出码 5，不留第二个重复问题
- `canon finding reconcile 5 5` → 退出码 2；`canon finding reconcile 5 999`（没有 #999）→ 退出码 3
- #5 挂在 `BR-8`、`BR-37` 上，#9 挂在 `BR-2` 上，`canon finding reconcile 5 9` → 退出码 2，信息写明没有共同文档
- `review` 没配置 → 退出码 4，没有事件、没有问题
- 两条意见挂的文档很多、提示超出评审命令能接受的大小，命令失败 → 退出码 4，没有事件
- 新拦截意见 #7 的文档组和未处理的 #5 完全相同 → 记录日志多一行 `review: #5 and #7 name the same documents; if they pull opposite ways, run canon finding reconcile 5 7`
