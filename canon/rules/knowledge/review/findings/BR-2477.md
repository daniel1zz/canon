## 规则

未处理意见记账时还没定档（`untriaged`）。`canon finding tier <n> <A|B|C> --reason "<理由>"` 给它定档或改档：A 是会话自己就能结案的，B 是要另一个会话支持才能结案的，C 是负责人才能定的（D-118）。档位大小写都认；别的写法、空理由是用法错误。一个 agent 会话（宿主环境里有 Claude Code 或 Codex 的会话，按 BR-2478 的判断）只能把档位定高或维持，往低改被拒绝；不在 agent 会话里的人可以往低改。每次定档记一条 `finding.tier` 事件，带意见编号、原来的档位、新档位和理由。已关闭或不存在的意见按 BR-2453 的退出码拒绝。`canon context` 和 `canon brief` 列意见时写出档位，按 BR-2436、BR-2437。

## 例子

- 刚记账的意见 #1 → 档位是 `untriaged`
- 会话执行 `canon finding tier 1 a --reason "代码已经定了"` → #1 是 A 档
- 会话再把 #1 改成 C → 成功；再改成 B → 被拒绝，输出含 `a session only raises a tier`
- 不在 agent 会话里的人把 #1 从 C 改成 B → 成功
- `canon finding tier 1 D --reason x`，或者 `--reason " "` → 用法错误
- 三次定档成功 → 有三条 `finding.tier` 事件
