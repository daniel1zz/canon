## 规则

`canon finding advise <n> --support|--oppose --fixed <提交>|--spurious "<原文>" --reason "<理由>"` 给未处理意见 #n 的某一种结案记一条意见：`--support` 和 `--oppose` 恰好给一个，`--fixed` 和 `--spurious` 恰好给一个，理由不能为空。意见绑定在完整的提交号或去掉多余空白的原文上，换了修复就不再适用。记下的会话从宿主环境读，按 BR-2478：子 agent（Codex 的子线程）、标了 `CLAUDE_DELEGATE_CHILD=1` 的 worker、没有会话编号的 Claude Code 会话都拒绝，因为它们不是独立的第二意见。每条记一条 `finding.advise` 事件（D-118）。同一个会话可以记多次，按 BR-2478 只看它对这种结案最新的一条。

## 例子

- Codex 子线程（`CODEX_SESSION_ID` 和 `CODEX_THREAD_ID` 不同）给 #1 记支持 → 拒绝，输出含 `a subagent`
- 带 `CLAUDE_DELEGATE_CHILD=1` 的会话 → 拒绝，输出含 `a delegated worker`
- Claude Code 会话没有 `CLAUDE_CODE_SESSION_ID` → 拒绝，输出含 `cannot name`
- 会话的环境里 `CLAUDE_CODE_SESSION_ID=abc`、`CANON_ACTOR=agent:someone` → 记成会话 `claude:abc`
- 不在 agent 会话里的人 → 记成 `human:<用户名>`
