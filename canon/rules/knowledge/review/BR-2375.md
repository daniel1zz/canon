title: canon check 在某个顶层领域的评审提示接近 review_max_prompt_kb 时提示一行，不算发现
status: active

## 规则

`review` 不是 `none` 时，`canon check`（带不带 `--json` 都一样）对每个顶层领域按 BR-2359 的同一套大小算出规则评审的最小一次提示的三部分：改动文档、评审说明加规则索引加已接受决策标题（固定部分）、领域的那一块（这个顶层领域里每个子领域连同它各层上级领域的说明，加上它最大的一条规则，没有规则就只是说明，取其中最大的）；三部分之和（按字节）达到 `review_max_prompt_kb` 的 70% 时，对这个领域在标准错误输出一行 `hint review-size: <领域>: ...`，写明领域名、三部分各多少 KB（KB 向上取整，和 BR-2359 拒绝时的写法一样）、合计多少 KB 和占预算的百分比、预算多少 KB，以及补救办法；每个这样的领域一行。用 70% 而不是更高：#145 实测固定部分加领域那一块是 65 + 130 = 195 KB，占 250 KB 预算的 78%，下一个变更带来 56 KB 的改动文档就被拒；70% 在默认预算下留 75 KB，盖得住这 56 KB（D-76）。

改动文档怎么算，取决于在哪里运行。在变更的 worktree 里（分支相对 main 有评审要看的文档改动），按这项工作真实改动的文档算，量法和合入时的评审完全一样（BR-2358：main 的合并基点和 worktree 现在全部内容之间的差异，同一份代码），提示写明 `this work's`；此时三部分之和超过预算（超过 100%）时，提示说这项工作合入后的评审会失败，补救办法按 BR-2359 拒绝时的选法。在 main 的检出里，或这项工作没有评审要看的文档改动时，改动文档按 0 KB 算，提示写明 `not known without a change`，只是下限。预算和 `review` 取合入时用的那份：在 worktree 里读 main 上的 `canon/config.yaml`（和 BR-2074 对评审设置的做法一样，用同一个读取函数，不取自 worktree 里被改过的配置）；在 main 的检出里读本地配置。这是提示，不是发现（D-76）：不算进发现条数，不改变标准输出和退出码，合入时的 `canon check` 也不因此拒绝。三部分之和不到 70%，或 `review` 是 `none`（不评审）时不提示。

## 例子

- main 的检出里，预算 60 KB，顶层领域 `dungeon` 的 README 约 79 KB、有一条很短的规则 → 标准错误有一行以 `hint review-size: dungeon:` 开头，写明 `changed documents 0 KB`、固定部分 3 KB、`domain text 80 KB`、合计约 82 KB 占约 137%、预算 60 KB；README 占那一块的一半以上，所以补救办法写缩短 README，并说拆子领域缩不小它，没有 `canon rule domain`；标准输出是 `ok: ...` 一行，退出码 0
- 同一个项目带 `--json` → 标准输出是 `[]`，提示在标准错误里，退出码 0
- 预算 100 KB，领域各子领域的规则每条 30 KB、README 很短，固定部分 3 KB（合计约 33 KB）→ 不提示；预算改成 40 KB（合计约 83%）→ 提示，补救办法写调大预算和 `canon rule domain <子领域>/<名字>`
- 合计按字节恰好是预算的 70% → 提示；预算再大 1 字节（合计不到 70%）→ 不提示；合计是预算的 69% → 不提示，71% → 提示
- #145 的数：预算 250 KB，固定部分加领域那一块 195 KB（78%）→ 提示（80% 的线不会提示）
- 一个领域的 README 只有 1 KB、最大的一条规则 70 KB，预算 60 KB → 提示，补救办法写拆子领域（README 不是那一块的大头）
- 两个顶层领域都到了 70% → 两行，各写自己的领域名
- `review: none`，README 79 KB，预算 60 KB → 不提示
- 同一个领域有一个子领域的 README 70 KB，顶层 README 很短，预算 60 KB → 提示的补救办法写拆子领域，没有“缩短这份 README”
- worktree 里，这项工作新增了一份 56 KB 的决策，固定部分加领域那一块约 195 KB，预算 250 KB → 提示写 `changed documents 56 KB` 和 `this work's`，合计超过预算，说合入后的评审会失败；同一个检出的 main 上（没有这份改动）按 0 KB 算，只有 78% 的下限提示
- worktree 里，改动文档 10 KB，固定部分加领域那一块约 150 KB，预算 250 KB（合计约 64%）→ 不提示；改动文档 30 KB（合计约 72%）→ 提示，写 `this work's`，没有说会被拒绝
- worktree 里这项工作只改了代码、没有评审要看的文档 → 改动文档按 0 KB 算，写 `not known without a change`
- worktree 里本地配置把 `review_max_prompt_kb` 改得更小，main 上没改 → 按 main 上的预算，不因本地的改动提示
