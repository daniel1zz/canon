---
id: BR-2375
title: canon check 在某个顶层领域的评审提示接近 review_max_prompt_kb 时提示一行，不算发现
status: active
---

## 规则

`review` 不是 `none` 时，`canon check`（带不带 `--json` 都一样）对每个顶层领域按 BR-2359 的同一套大小算出规则评审的最小一次提示的三部分：改动文档（还没有改动，按 0 KB 算）、评审说明加规则索引加已接受决策标题（固定部分）、领域的那一块（这个顶层领域里每个子领域连同它各层上级领域的说明，加上它最大的一条规则，没有规则就只是说明，取其中最大的）；三部分之和（按字节）达到 `review_max_prompt_kb` 的 80% 时，对这个领域在标准错误输出一行 `hint review-size: <领域>: ...`，写明领域名、三部分各多少 KB（KB 向上取整，和 BR-2359 拒绝时的写法一样）、合计多少 KB 和占预算的百分比、预算多少 KB，以及补救办法；每个这样的领域一行。补救办法的选法和 BR-2359 拒绝时一样：顶层领域自己的 README 连同它后面的列表（点名它的规则的决策、变更等文档）占领域那一块的一半以上时，说缩短这份 README 或调大 `review_max_prompt_kb`，并说拆成子领域缩不小它；否则说调大 `review_max_prompt_kb` 或把领域拆成子领域。这是提示，不是发现（D-76）：不算进发现条数，不改变标准输出和退出码，合入时的 `canon check` 也不因此拒绝。改动文档的大小取决于将来的改动，所以不估它，提示只是下限：真正的改动超过 0 KB 的部分，拒绝时才算进去。三部分之和不到 80%，或 `review` 是 `none`（不评审）时不提示。

## 例子

- 预算 60 KB，顶层领域 `dungeon` 的 README 约 79 KB、有一条很短的规则 → 标准错误有一行以 `hint review-size: dungeon:` 开头，写明 `changed documents 0 KB`、固定部分 3 KB、`domain text 80 KB`、合计约 82 KB 占约 137%、预算 60 KB；README 占那一块的一半以上，所以补救办法写缩短 README，并说拆子领域缩不小它，没有 `canon rule domain`；标准输出是 `ok: ...` 一行，退出码 0
- 同一个项目带 `--json` → 标准输出是 `[]`，提示在标准错误里，退出码 0
- 预算 100 KB，领域各子领域的规则每条 30 KB、README 很短，固定部分 3 KB（合计约 33 KB）→ 不提示；预算改成 40 KB（合计约 83%）→ 提示，补救办法写调大预算和 `canon rule domain <子领域>/<名字>`
- 合计按字节恰好是预算的 80% → 提示；预算再大 1 字节（合计不到 80%）→ 不提示
- 一个领域的 README 只有 1 KB、最大的一条规则 70 KB，预算 60 KB → 提示，补救办法写拆子领域（README 不是那一块的大头）
- 两个顶层领域都到了 80% → 两行，各写自己的领域名
- `review: none`，README 79 KB，预算 60 KB → 不提示
- 同一个领域有一个子领域的 README 70 KB，顶层 README 很短，预算 60 KB → 提示的补救办法写拆子领域，没有“缩短这份 README”
