title: 合入后的代码评审看完整 diff 和改动文件的全文，只找安全和并发问题
status: active
---

## 规则

`scripts/code-review.ts`（作为 `after_land` hook 运行，环境变量 `CANON_BASE`、`CANON_HEAD` 必填，缺少时退出码 2）把三样东西交给评审命令（默认 `claude -p`）：`CANON_BASE..CANON_HEAD` 中 `canon/` 以外的完整 diff；这次改动、新增或改名的每个 `canon/` 以外文件在 `CANON_HEAD` 上的全文（跳过二进制文件和超过 100 KB 的文件；删掉的文件只出现在 diff 里）；带 `canon-review` 标签、未关闭的 issue 列表。提示只要求找安全问题和并发问题。这次合入没有改动（新增、修改、删除或改名）`canon/` 以外的任何文件时不调用评审命令，输出 `no code changed; nothing to review`。评审命令正常返回、之后没有提交或评论任何 issue 时，输出 `no findings`；评审命令失败或返回的内容解析不出发现列表时，输出 `code-review: <原因>`、退出码 1，不输出 `no findings`，让合入后的日志能分清“评审过、没发现”和“评审没有跑”。

## 例子

- 合入改了 `src/queue.ts` 的一行 → 评审收到这行的 diff，以及 `src/queue.ts` 的全文（包括没改的行）
- 没有 `CANON_BASE` 时运行 `bun scripts/code-review.ts` → 退出码 2
- 合入新增了一个二进制文件 `logo.png` → 它不作为全文给评审
- 合入删掉了 `src/old.ts` → 它只出现在 diff 里
- 合入只删掉了 `src/old.ts`，或者只改了二进制文件、超过 100 KB 的文件 → 照样调用评审命令，评审只收到这些文件的 diff，不输出 `no code changed`
- 合入新增了一个 120 KB 的 `src/big.ts` → 它不作为全文给评审，只出现在 diff 里
- 评审返回空的发现列表，或者发现全部因缺少文件、行或场景被丢弃 → 输出 `code-review: no findings`
- 评审命令以退出码 1 结束 → 输出 `code-review: <原因>`，退出码 1，没有 `no findings`
- 合入只改了 `canon/rules/` 下的文件 → 不调用评审命令，输出 `no code changed; nothing to review`
