---
id: BR-2070
title: 合入后的代码评审看完整 diff 和改动文件的全文，只找安全和并发问题
status: active
---

## 规则

`scripts/code-review.ts`（作为 `after_land` hook 运行，环境变量 `CANON_BASE`、`CANON_HEAD` 必填，缺少时退出码 2；设了 `CANON_CODE_REVIEW_FORCE=1` 时可以不设，BR-2314）按 BR-2314 到点时把三样东西交给评审命令（默认 `claude -p`）：评审范围（`refs/canon/code-reviewed` 到 `CANON_HEAD`，一次合入也是一个范围，没有引用时从 `CANON_BASE` 开始，BR-2315）中 `canon/` 以外的完整 diff；这个范围里改动、新增或改名的每个 `canon/` 以外文件在 `CANON_HEAD` 上的全文（跳过二进制文件和超过 100 KB 的文件；删掉的文件只出现在 diff 里）；带 `canon-review` 标签、未关闭的 issue 列表。提示只要求找安全问题和并发问题，而且只报正常操作会引出的：每条的出错情形写明谁在哪个正常操作里会遇到。判据只有一条，就是正常操作会不会引出它，测试怎么重现它（屏障、预置状态、假程序）不算判据：两次正常操作之间的竞态，即使测试要用屏障才能做出来，也照报。需要不正常的配置或动作才会出现的情形（用户给系统命令套的包装脚本、没人用的非默认后端、在某一步中间杀掉某个特定进程、不越过安全边界的恶意输入）不报，除非会丢数据、是安全问题，或破坏项目的承诺；canon 自己的仓库里项目的承诺就是 `canon/product.md` 的 P1 到 P7（D-54）。这个范围没有改动（新增、修改、删除或改名）`canon/` 以外的任何文件时不调用评审命令，输出 `code-review: no code changed; nothing to review`。评审命令正常返回、而且没有要提交或评论的发现（列表为空，或者全部按 BR-2071 被丢弃）时，输出 `code-review: no findings`；有要提交的发现、但 `gh` 新建或评论失败时按 BR-2211 处理，不输出 `no findings`；评审命令失败或返回的内容解析不出发现列表时，输出 `code-review: <原因>`、退出码 1，不输出 `code-review: no findings`，让合入后的日志能分清“评审过、没发现”和“评审没有跑”。

## 例子

- 合入改了 `src/queue.ts` 的一行，到点评审（`CANON_CODE_REVIEW_FORCE=1`，或者 `review_max_unreviewed: 1`）→ 评审收到这行的 diff，以及 `src/queue.ts` 的全文（包括没改的行）
- 评审收到的提示 → 要求只报正常操作会引出的问题、出错情形写明谁在哪个正常操作里遇到；写明测试怎么重现不算判据，需要不正常的配置或动作的情形不报，丢数据、安全问题和破坏项目承诺的除外
- 两个会话同时合入，少见的交错让一个没测过的提交被标成已通过，测试要用屏障才能做出这个交错 → 评审照报（正常操作引出，破坏 P4）
- 用户给 `ps` 套了包装脚本，输出格式不同，后台测试的进程判断出错 → 评审不报（需要不正常的配置）
- 没有 `CANON_BASE` 时运行 `bun scripts/code-review.ts` → 退出码 2
- 合入新增了一个二进制文件 `logo.png` → 它不作为全文给评审
- 合入删掉了 `src/old.ts` → 它只出现在 diff 里
- 合入只删掉了 `src/old.ts`，或者只改了二进制文件、超过 100 KB 的文件 → 照样调用评审命令，评审只收到这些文件的 diff，不输出 `code-review: no code changed; nothing to review`
- 合入新增了一个 120 KB 的 `src/big.ts` → 它不作为全文给评审，只出现在 diff 里
- 评审返回空的发现列表，或者发现全部因缺少文件、行或场景被丢弃 → 输出 `code-review: no findings`
- 评审命令以退出码 1 结束 → 输出 `code-review: <原因>`，退出码 1，没有 `code-review: no findings`
- 合入只改了 `canon/rules/` 下的文件 → 不调用评审命令，输出 `code-review: no code changed; nothing to review`
