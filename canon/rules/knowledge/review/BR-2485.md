## 规则

规则评审（BR-2009）的提示要求拦截意见至少牵涉一份这次合入改动或删除的文档。canon 在合入后的评审和 `canon work review` 的预览里按此核对回答：一条点名了标准的意见，文字里点名了文档编号（按 BR-2433 认编号），却没有一个是这次合入改动或删除的规则、决策或发布时，不当拦截意见，而是当成提示，文字后面加上 `(canon: given as [<标准>] but names no document this landing changed or deleted, so taken as a note)`；它不让结论变成 `block`，也不记成未处理意见（BR-2434）。

下面几种照旧，不按这条降级：

- 意见没点名任何编号。
- 标准是 `overview` 或 `business-overlap`，它们说的是总览的改动和领域 README，不靠编号。
- 这次合入没改动或删除任何带编号的文档（只改了领域 README 或常驻说明）。
- 旧格式的回答（BR-2367）。

拆成几次调用时，按整次合入改动的文档核对，不只看这次调用完整给出的那几份。

## 例子

- 合入改了 `BR-5`，意见 `[contradiction] D-89 「核实」 vs D-99 「不另跑核实」` → 提示，末尾有 `(canon: given as [contradiction] but names no document this landing changed or deleted, so taken as a note)`；没有别的拦截意见时结论是 `ok`
- 合入改了 `BR-5`，意见 `[contradiction] BR-5 「三天」 vs BR-4 「五天」` → 拦截
- 合入删除了 `BR-6`，意见 `[contradiction] BR-6 「x」 vs BR-4 「y」` → 拦截
- 合入改了 `BR-5`，意见 `[untestable] the rule is vague`（没点名编号）→ 拦截
- 合入改了 `BR-5`，意见 `[overview] BR-4 「x」 vs the overview` → 拦截
- 合入只改了领域 README → 意见照旧，不降级
