## 规则

规则评审（BR-2009）调用评审命令之前，先算一个键：对评审的种类（合入时的评审是 `land`，`canon work review` 的评审是 `preview`）、`review` 命令的文字、`review_max_prompt_kb` 换成的字节数和这次评审的每一份提示（按顺序）取 SHA-256。事件表里同种类、同键的最新一条评审记录（合入时看 `review.ok` 和 `review.block`，预览看 `review.preview`）的结论为 `ok` 时，不调用评审命令：沿用那次的意见和措辞判断（BR-2239），输出一行写明沿用了哪条事件，记一条 `review.reused` 事件（合入时的字段是 `review`（`land`）、`docs`、`hash`、被沿用的事件号 `from` 和 `commit`；预览的是 `review`（`preview`）、`docs`、`hash`、`from` 和 `tree`），然后照常继续：意见照常输出，合入照常记下它们（BR-2145）。合入时的评审只认 `review.ok` 事件（规则评审写的，带 `hash`）；预览只认 `review.preview` 事件里规则评审结论为 `ok` 的（带 `hash`）；两种互不沿用，预览通过不算合入通过。`block` 的评审不沿用，不管哪一种；同一份提示后来的 `block` 盖过更早的通过（下一次评审看到的是最新的结论，不会靠重试绕过一次拦截）。提示里有任何一个字节不同（改动的文字、领域全文、索引、总览、措辞判断的问题）、`review` 命令或预算不同，键就不同，不按这条沿用；合入时接着按 BR-2396 看改动文档是否已经通过（可能沿用或只做小评审），否则评审照常调用。合入要判断措辞（BR-2239）而那次通过的评审没有对每条都答 `wording` 时不沿用，评审照常调用。键只由上面几项算出，不含评审命令运行时的环境变量（例如用 `ANTHROPIC_MODEL` 选的模型）、工作目录和命令所调用的脚本的内容：这些变了，已通过的评审仍被沿用；要让它重新评审，就改 `review` 命令的文字（例如加一个版本参数）。重复评审（BR-2143）不在这条里，每次都调用。

## 例子

- 合入的规则评审通过后，合入因别的原因（例如 `before_land` 失败）被拒，改了和评审无关的代码再合入 → 评审命令没有再运行，输出写明沿用，记 `review.reused`（`review: land`，带 `hash`），合入成功
- 同上，但改了被评审的规则文字的一个字 → 键不同，评审命令再运行一次，不记 `review.reused`
- 上一次的评审结论是 `block` → 提示不变再合入，评审命令再运行
- `review` 命令的文字不同，或 `review_max_prompt_kb` 不同，其余都相同 → 键不同
- 同一份提示在 `canon work review` 里通过过，合入时再评审 → 合入的键和预览的不同，评审命令运行；合入通过之后再运行 `canon work review`，预览同样要自己调用一次
- 同一份提示的预览通过过，再运行 `canon work review` → 评审命令没有运行，输出沿用的事件号和上次的意见，仍然记 `review.preview`，退出码 0
- 措辞判断的评审那次答了 `behaviour`，被拒绝；提示相同再合入 → 评审命令再运行
- 合入的提示被拆成两次调用（BR-2359）时，键由两份提示一起算；两次都通过后才沿用，只有第一次通过、第二次 `block` 的不沿用
- 同一份提示先通过、后来又 `block` 过一次（例如换了评审命令的行为后重新评审），再合入 → 看到的最新结论是 `block`，评审命令再运行，不沿用更早的通过
- 评审命令文字没变，只是它读的环境变量 `ANTHROPIC_MODEL` 换了，或它调用的脚本改了 → 键相同，沿用，输出写明沿用；在命令文字里加一个版本参数 → 键不同，评审命令运行
- 沿用时的输出里有 `reused the passing review`、被沿用的事件号和哈希的前 12 个字符，并写明评审命令没有运行
