status: active

## 规则

一致性抽查（BR-2271）的评审返回的每条发现必须有类别（`untested-side`：规则的某个例子的一侧没有测试验证；`code-mismatch`：代码和规则写的不一致）、标题、根因、这次查的领域里的一条规则编号、文件、大于 0 的行号，以及出错情形；缺任何一项、类别不是这两种、或者规则编号不是这个领域的规则时，这条发现被丢弃，输出一行 `code-review: consistency: dropped ...`，不提 issue。保留的发现和代码评审一样提交（BR-2072、BR-2210、BR-2211），只是标签换成 `canon-consistency`：先在带 `canon-consistency` 标签的未关闭 issue 里找同一根因的（评审指出的编号，或标题相同的），找到就评论，否则新建带这个标签的 issue；同一次里根因相同的发现合成一个；正文第一行写 ``**<类别>**, found by the post-land consistency check of <变更编号或 a landing> (`<CANON_HEAD 前 9 位>`).``，每处一行 `` - `<文件>:<行>`: <规则编号>: <出错情形> ``，其余和 BR-2210 相同。`gh` 失败时按 BR-2211 处理，输出行以 `code-review: consistency: ` 开头。一个领域查完没有要提交的发现时输出 `code-review: consistency: <领域>: no findings`。

## 例子

- 一条 `code-mismatch` 发现，规则 `BR-1`（这个领域的），`src/billing/refund.ts:3`，情形“退款超过原价 → 返回 0，规则写退出码 1” → 新建带 `canon-consistency` 标签的 issue，正文有 `` - `src/billing/refund.ts:3`: BR-1: 退款超过原价 → 返回 0，规则写退出码 1 ``
- 一条发现的规则是另一个领域的 `BR-9` → 丢弃，不提 issue
- 一条发现的类别是 `security` → 丢弃
- 一条发现没有行号 → 丢弃
- 评审指出 `#12`，`#12` 带 `canon-consistency` 标签且未关闭 → 在 `#12` 下评论
- 评审指出 `#12`，但 `#12` 只带 `canon-review` 标签 → 不算，按标题在 `canon-consistency` 的 issue 里找，找不到就新建
- 评审返回空列表 → 输出 `code-review: consistency: billing: no findings`，退出码 0
- `gh issue create` 以退出码 1 结束 → 退出码 1，没有 `no findings`
