## 规则

规则评审和常驻说明的重复评审都用配置里的 `review` 命令：canon 在一个临时 worktree 里用 `sh -c` 运行它：这个 worktree 在 main 的提交上（分离 HEAD，不检出分支），建在 git 公共目录下的 `canon/review/<进程号>-<序号>`（和协调数据库同一个目录，BR-2208），不在项目的受控目录里；规则评审和重复评审共用同一个，只在真有评审要跑时才建，评审结束后（通过、拦下、超时、非 0 退出、无效结论、被信号终止，都一样）删掉；批量合入也用 main 的提交，不用批量链上的提交。这样变更改不了评审用的脚本，也改不了 `claude -p` 读的 `CLAUDE.md`、`.claude/settings.json` 和 `.claude/skills`（D-51）。临时 worktree 删不掉时，合入以环境错误被拒绝，不会把结论当作通过。评审提示本身带着评审要读的全部新文字（改动过的 skill 附全文，BR-2143），所以不用变更的目录；评审自己去读文件时，读到的是 main 上的旧文字。把评审提示从标准输入交给它，从标准输出里取第一个 `{` 到最后一个 `}` 之间的文字当作 JSON 结论，前后可以有别的文字。结论的格式和结论怎么得出见 BR-2367（意见点名拦截标准，结论由 canon 推出；旧格式用 `verdict` 字段，`verdict` 必须是 `ok` 或 `block`，`findings` 是字符串列表，没有或不是列表时当作没有意见）。命令以非 0 退出时，错误里写出原因：标准错误（去掉首尾空白）不为空时是 `review command exited <退出码>: <标准错误的前 500 个字符>`；标准错误为空、标准输出不为空时，取标准输出的最后 500 个字符（出错的工具通常把原因写在最后），写成 `review command exited <退出码> (stdout): <文字>`；两个都不为空时两段都写，各自标明来源：`review command exited <退出码> (stderr): <标准错误的前 500 个字符>; (stdout): <标准输出的最后 500 个字符>`；两个都为空时是 `review command exited <退出码>: no output`；输出里没有 JSON、JSON 解析不了、或 BR-2367 说是无效结论的情形（例如旧格式的 `verdict` 是别的值）时，是无效结论；这两种情况合入都被拒绝（BR-2009、BR-2143），拒绝信息另起一行说明评审是在 main 提交的哪个临时 worktree 里运行的、那里只有提交进 git 的文件，被 git 忽略的文件（如 `node_modules`、`.env`、`*.local.json`）不在，评审命令不能依赖它们。

## 例子

- 命令输出 `Here is my answer: {"verdict":"block","findings":["BR-1 is vague"]} done` → 结论 `block`，意见 `BR-1 is vague`
- 命令输出 `{"verdict":"ok"}` → 结论 `ok`，没有意见
- 命令先读完标准输入再回答 → 读到的就是完整的评审提示
- 命令输出 `looks fine to me`（没有 JSON）、`{"verdict":"ok",}`（解析不了）或 `{"verdict":"maybe"}` → 无效结论
- 命令向标准错误输出 `boom` 并以退出码 3 结束 → `review command exited 3: boom`，下一行写明 main 的提交和 `git-ignored files such as node_modules`
- 命令只向标准输出写 `Prompt is too long` 并以退出码 1 结束 → `review command exited 1 (stdout): Prompt is too long`
- 命令向标准错误写 `err text`、向标准输出写 `out text`，退出码 2 → `review command exited 2 (stderr): err text; (stdout): out text`
- 命令标准输出和标准错误都为空（或只有空白），退出码 4 → `review command exited 4: no output`
- 命令向标准输出写 600 个字符后以 1 退出 → 信息里是这 600 个字符的最后 500 个
- 变更改了评审脚本（例如 `scripts/review-claude.sh`）→ 运行的是 main 上的那一版
- 变更加了 `CLAUDE.md` 的一行、改了 `.claude/settings.json` 或新增一个 skill → 评审命令的工作目录里是 main 上的版本，没有变更的改动；main 上已有的这些文件都还在
- 评审通过、被拦下、超时或被信号终止之后 → `git worktree list` 里没有这个临时 worktree
- 主 checkout 在别的分支上或有未提交的改动 → 评审照样在 main 的提交上运行
- 临时 worktree 删不掉（例如被锁住）→ 合入被拒绝，原因 `environment`，不算评审通过
- 评审命令读 `.env`（被 git 忽略，只在 worktree 里有）→ 读不到，命令失败，合入被拒，信息里有 main 的提交和被忽略文件不在的说明
- 评审通过或拦下 → 信息里没有这句说明
