# Canon

## 目的

为一个几乎全部由 AI 开发的项目提供共享记忆和协作协调。这个项目由多个 AI 会话同时开发，开局之后无人值守。人只负责定方向，只回答留给人的问题。

## 使用者

- 在项目里干活的 AI 会话（Claude Code 等），经常好几个同时在跑。
- 负责项目方向的 3 到 5 个人。

## 承诺

Canon 里的每样东西，都是为了让下面某一条承诺成立。一个机制如果不支撑任何一条，就删掉。

- **P1 当前真相**：任何时候，AI 都能从一个地方（`canon/rules`）读到产品必须怎么工作，并分清每条规则是规划中、已通过执行，还是改过之后待重新执行（D-32）。
- **P2 为什么**：每个重要决策当初为什么这么定，事后都能查到（`canon/decisions`）。
- **P3 连续性**：新会话不需要人重新交代，就能接着做没完成的工作（变更、handoff、`canon brief`）。
- **P4 并发安全**：多个会话同时工作，不丢工作、不互相覆盖、不弄坏 main（认领、合入队列、floor、main 的比较并交换）。
- **P5 文档不说谎**：main 上的文档和代码一致，没有断掉的引用，每条生效的规则都能追到判定它的测试或验收记录（`canon check`）；规划中的规则标明还没做，不冒充已实现。
- **P6 可追溯、能自我改进**：谁改了什么、为什么改都有记录（git、协调事件表）；发现的问题会变成 GitHub issue；每个检查都记录拒绝的原因，所以能算出它准不准。
- **P7 人只做留给人的决定**：方向和明确留给人的问题走 `canon human`，其余都不等人。

## 不做的事

- 多台电脑同时开发同一个项目（协调状态只存在本机这个 checkout 里）。
- 网页 dashboard 或 HTTP API：人直接看仓库里或 GitHub 上的文件。
- 检查 agent 怎么干活。Canon 只在两个边界检查结果：协调状态写入时，和合入 main 时。

## 语言

`canon/` 下的文档（产品说明、规则、决策、变更、笔记）一律用中文。代码、注释和测试名用英文；编号（`BR-n`、`D-n`、`C-n`、`N-n`）和命令保持原样。
