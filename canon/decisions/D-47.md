## 背景

D-45 让 `canon human answer --relayed` 对照提问工具（AskUserQuestion）的 PostToolUse 记录，标出“一致 / 没有对应记录”。一次独立评审（2026-11-04）找出几处问题，负责人 2026-11-04 选了“D-45 回答佐证 (推荐)”，要求按评审修订 D-45。逐条核对后的事实：

- 对照只看“这个操作者最近一条记录里有没有同样的回答”，不看记录里的问题是不是第 n 个问题（`src/work/humans/questions.ts` 的 `witnessFor`）。agent 用提问工具问“继续吗？”，人选了 `Yes`，agent 把 `Yes` 当成另一个从没给人看过的方向问题的回答转述，也会标“一致”。选项通常很短，碰巧对上并不少见，这违背了 D-45 自己说的“宁可漏标一致，不能碰巧标成一致”。
- 对照按操作者，不按会话。几个会话共用一个导出的 `CANON_ACTOR` 时会对上别人的记录；反过来，只在转述命令前临时设 `CANON_ACTOR=` 会把同一会话拆成两个操作者，标成“没有对应记录”。记录里本来就存了完整的 `session_id`，但没用上。
- D-45 引的“Maps question text to the selected option label”出自 hooks 文档里提问工具的 `tool_input` 表，同一行写着 Claude 不填这个字段，要程序化回答时用 `updatedInput` 填。canon 读的是 `tool_response.answers`，它的出处是 Agent SDK 文档里的 `AskUserQuestionOutput`。这一行还说明：PreToolUse hook 返回 `updatedInput` 就能替人填好回答，工具不再弹出提问。Agent SDK 的应用也是用 `updatedInput` 把回答交回去的，回答可能来自它界面上的人，也可能来自代码。所以记录里是“工具返回了什么”，不一定是“人选了什么”。
- `AskUserQuestionOutput` 还有一个 `afkTimeoutMs` 字段，文档没有解释它的含义。
- Agent SDK 文档允许多选的回答以选项数组交回，而 canon 现在遇到不是字符串的回答就以退出码 2 失败，什么也不记。这句文档说的是交回给工具的 `updatedInput`（工具的输入）；PostToolUse 的 `tool_response` 里会不会原样出现数组，文档没说（`AskUserQuestionOutput` 写的是 `answers: Record<string, string>`），所以“会失败”是从输入推到输出的推测。
- “没有对应记录”混了几种完全不同的情况：根本没有记录；有这个问题的记录但回答不同；hook 没有运行（工作区没被信任、`disableAllHooks`、没装 hook）；hook 运行了但 `canon human record` 失败了（hook 只给用户一条提示）。D-45 后果里“数出没有对应记录的比例”分不清这是 agent 的行为还是环境坏了。
- `CLAUDE_CODE_SESSION_ID` 在 Bash 工具的子进程里和 hook 数据里的 `session_id` 相同，`/clear` 之后会变。
- 评审还提出：对话记录文件异步写只影响 hook 运行的那一刻，事后转述时它已经写完了，可以拿记录里的 `tool_use_id` 去对话记录里核对。

C-253 按本决策实现之后，第二次独立评审（2026-11-04）又找出几处，逐条对着代码核对过：

- `response` 被算作每个问题的回答。Agent SDK 文档写明 `response` 是人关掉问题卡片、不回答任何具体问题时打的笼统回复；一次问 4 个问题，人回一句“好”，转述其中任何一个都标 `match`。人在 Other 里打的字放在这个问题的 `answers` 里，不在 `response` 里；本机 348 次真实的提问工具结果里没有一次带 `response`，它只会出现在 Agent SDK 应用里。
- 对照只看 `--relayed` 的原话，不看存下、给后续工作用的回答：`canon human answer 1 no --relayed "yes"` 在人选了 `yes` 时标 `match`，显示成 `→ no (… "yes") [matches Claude Code's record]`。
- 会话里只要有一条 `human.asked.refuse`，凡是没找到这个问题的转述都标 `record-failed`，包括 agent 手动往 `canon human record` 喂一条别的工具的数据。
- 配置读不出来（BR-2045）和 Claude Code 里 `CANON_ACTOR` 不是 `agent:` 开头（BR-2023）时，`canon human record` 什么都不写，最后标 `no-record`，本决策没有列出这两种。
- 对照不看时间：同一会话里两个文字相同的 canon 问题共用对方的记录；问题创建之前问过的同样文字也算数。
- 多选的转述换了顺序或只说了一部分时标 `differs`，本决策没有写明。

## 方案

1. 按“同一会话、同一问题”对照，没对上时分清原因，不拦截：采用。
   - 会话：转述命令从环境里的 `CLAUDE_CODE_SESSION_ID` 得到会话，只看 `session` 相同的记录，不再看操作者。
   - 问题：第 n 个问题的文字（`canon human ask` 记下的那段）去掉首尾空白后，要和记录里某个问题的文字（去掉首尾空白）完全相同；取这个会话里有这个问题的最近一条记录。原话和这个问题的回答、这个问题的备注，或者这次提问只问了这一个问题时人自己打的回答（`response`）完全相同才算一致；一次问了几个问题时 `response` 不属于其中任何一个，不用。有了问题文字这层约束，不再需要“只看最近一条”来压低碰巧对上的机会。canon 的工作说明相应写明：用提问工具问第 n 个问题时，问题文字照抄 `canon human ask` 的原文。
   - 比较的是原话：标记说明人的原话和记录对不对得上，不说明存下的回答；`pending --all` 的说明写明是“人的原话”，回答和原话本来就在同一行并排显示。
   - 分清的几种标记，canon 都能凭自己手上的数据判断：`match`（对上）、`differs`（有这个问题的记录，回答不同）、`record-failed`（这个会话里 `canon human record` 失败过，没找到这个问题的记录）、`unasked`（这个会话的提问工具有记录，但都不是这个问题）、`no-hook`（项目的 `.claude/settings.json` 里没有记录用的 hook）、`no-record`（这个会话没有任何记录）、`no-session`（转述命令的环境里没有会话 id）。
   - 记录失败也要留痕：`canon human record` 拒绝时写一条带原因的 `human.asked.refuse` 事件（BR-2026），数据里有 `session_id` 就记下它，这样才能标 `record-failed`。
   - 来源：https://code.claude.com/docs/en/agent-sdk/user-input.md “Set `response` only when your UI lets the user dismiss the question card and type a general reply that isn't an answer to any specific question”
   - 多选的回答是字符串数组时，用 `, ` 连起来记录，和文档写的“多选时用逗号连起来”一致，不再让这种记录失败。
   - 来源：https://code.claude.com/docs/en/env-vars.md “this matches the `session_id` field in the hook JSON input and is updated on `/clear`”
   - 来源：https://code.claude.com/docs/en/agent-sdk/typescript.md “Returns the questions asked and the user's answers.”
   - 来源：https://code.claude.com/docs/en/agent-sdk/user-input.md “For multi-select questions, pass an array of labels”
   - 来源：https://code.claude.com/docs/en/hooks.md “hooks fire after a tool has already executed successfully”
   - 来源：https://code.claude.com/docs/en/hooks.md “To temporarily disable all hooks without removing them”
2. 用问题编号而不是问题文字对应（要求提问工具的 `header` 或问题里写上 `#n`）：否决。编号是 agent 自己写上去的，写在一个无关问题上和照抄问题文字一样容易；而照抄文字时，人看到的就是第 n 个问题本身，佐证的正是“人回答的是这个问题”。
3. 文字相似就算同一个问题（模糊匹配）：否决。相似到什么程度算同一个问题没有可核对的标准，又回到了碰巧对上。agent 改写了问题时标 `unasked`，宁可漏标。
4. 想办法认出“回答是 hook 或程序填的，不是人选的”：否决，写成限制。PreToolUse hook 的 `updatedInput` 和 Agent SDK 交回人的回答走的是同一个字段，PostToolUse 拿到的数据里分不出两者；文档也没有说明 `afkTimeoutMs` 的含义。canon 把 `afkTimeoutMs` 原样存进记录，不做解释，以后文档写清楚了可以再用。
   - 来源：https://code.claude.com/docs/en/hooks.md “Claude doesn't set this field; supply it via `updatedInput` to answer programmatically”
   - 来源：https://code.claude.com/docs/en/hooks.md “together with `updatedInput` that holds the answer, so the tool runs without prompting”
   - 来源：https://code.claude.com/docs/en/agent-sdk/user-input.md “Build the `answers` object as a record where each key is the `question` text”
   - 来源：https://code.claude.com/docs/en/agent-sdk/typescript.md “afkTimeoutMs?: number;”
5. 转述时拿记录里的 `tool_use_id` 去对话记录文件（`transcript_path`）核对：否决。评审说得对，事后核对时文件已经写完，异步写不是理由，D-45 这条理由作废。否决的理由是另外三条：只核对 `tool_use_id` 在不在，伪造的人可以借一个真实提问的 id、配上编造的回答；要核对回答本身，就得解析工具结果在对话记录里的文字，而对话记录的格式是 Claude Code 内部的，文档只说它是对话的 JSON，格式一变，canon 就会成片地给出错误的标记；对话记录也在本机、agent 能改。它防的是存心伪造，而 D-6 本来就不声称防得住。canon 把 `transcript_path` 存进记录，需要时人可以自己去对照。
   - 来源：https://code.claude.com/docs/en/hooks.md “Path to conversation JSON.”
   - 来源：canon/decisions/D-6.md “canon 不声称能阻止冒充”
6. 保持 D-45 的对照方式，只改引用：否决。碰巧对上和按操作者对照都是真实的错误标记，不是措辞问题。
7. 完全不用 `response`：否决。一次只问一个问题时，人的笼统回复只可能是对这个问题说的，而且在 Agent SDK 应用里它可能是人留下的唯一一句话；只在多个问题时不用，就消除了“一句话对上任何一个问题”。
8. 要求存下的回答也和记录相同，或者回答和原话不同时另标一种：否决。回答本来就可以和原话不同：canon 问题的选项和提问工具里的选项标签常常写法不一样（例如标签后面加了 `(推荐)`），agent 记回答时用 canon 的选项、或者写个简称都是正常的。要求相同会把这些正常的转述成片标成 `differs`，`--relayed` 也就没有单独存在的意义。canon 判断不了两种写法是不是同一个意思，所以改成写明标记只针对原话，并把回答和原话并排显示，由看的人判断。
9. 第二次评审的其余几处（失败不分问题、写不进事件表的两种失败、同文字问题和问题创建前的记录、多选顺序、在记录时就把记录挂到问题上）现在就处理：否决。负责人 2026-11-04 定了“不要设想不存在的问题”：只修正常转述时真会碰到的，以及规则和代码直接矛盾的。这几处在正常转述里不会碰到，各自为什么不太可能写在后果里。

## 决定

- `canon human record` 记下每个问题的文字、它的回答（多选数组用 `, ` 连起来）和它的备注，以及这次提问人自己打的回答、`tool_use_id`、`transcript_path`、`afkTimeoutMs`（BR-2275）。拒绝时写 `human.asked.refuse`，原因和数据里的 `session_id` 都记下。
- `canon human answer --relayed` 按方案 1 对照，标记按这个顺序取第一个成立的：`no-session`、`match` 或 `differs`、`record-failed`、`unasked`、`no-hook`、`no-record`（BR-2276）；人自己打的笼统回复只在一次提问只有一个问题时算这个问题的回答；对照的是原话，不是存下的回答。`canon human pending --all` 给每种标记显示自己的说明，`match` 和 `differs` 的说明写明说的是“人的原话”，D-45 之前的 `none` 仍显示原来的说明（BR-2289）。
- canon 分不清、也不假装分得清的：
  - `match` 里：人在提问工具里选的、PreToolUse hook 或 Agent SDK 程序填的、agent 自己运行 `canon human record` 编的。
  - `no-record` 里：agent 没用提问工具；人在对话里直接回答；hook 没运行（工作区没被信任、`disableAllHooks`、用户或托管设置）；hook 里找不到 canon（只有一条给用户的提示，什么也写不进事件表）；数据完全不是 JSON、连会话都认不出的失败。
  - `unasked` 里：agent 没问这个问题，还是改写了问题文字。
  - `no-hook` 只看项目主 checkout 的 `.claude/settings.json`，看不到用户设置和托管设置里的 hook。
- 不变：只标记、不拦截（D-45 方案 2）；这是佐证不是证明，D-6 的“canon 不声称能阻止冒充”仍然成立。

## 后果

- 部分修改 D-45：对照的范围从“同一操作者最近一条记录的任何回答”改成“同一会话里同一问题的回答”，“没有对应记录”拆成几种标记，D-45 里对话记录“异步写”的否决理由作废，换成方案 5 的理由。D-45 其余决定不变。
- 转述必须在提问的那个会话里、`/clear` 之前做；`/clear` 之后会话 id 变了，会标 `no-record` 或 `unasked`。
- agent 改写问题文字时标 `unasked`，所以工作说明要写明照抄问题文字。
- 以后从事件表数比例时，`record-failed`、`no-hook`、`no-session` 是环境的问题，`differs`、`unasked`、`no-record` 才可能是 agent 的行为。
- 记录里多了 `questions`（每个问题和它的回答、备注）、`transcript_path` 和 `afk_timeout_ms`；D-45 之前的记录没有按问题分开的备注，对照时只用它们的回答。
- 已知、不处理：会话里任何一次 `human.asked.refuse` 都会把没找到这个问题的转述标成 `record-failed`，盖住 `unasked`。不太可能：hook 只在提问工具上运行，Claude Code 给的数据格式固定，正常使用时不会失败，本机事件表里有 11 条 `human.asked`，一条 `human.asked.refuse` 都没有。
- 已知、不处理：配置读不出来（BR-2045）或 `CANON_ACTOR` 不合法（BR-2023）时 `canon human record` 什么都不写，标成 `no-record`。不太可能：这两种情况下这个会话的所有 canon 命令都会失败，agent 会先修好它们。
- 已知、不处理：同一会话里两个文字相同的待答问题会共用记录，问题创建之前问过的同样文字也算数。不太可能：工作说明规定先 `canon human ask` 再照抄文字去问，留给人的方向问题写的是具体的选择，很少逐字重复（本机至今 2 个问题，文字不同）。
- 已知、不处理：多选的转述换了顺序或只说一部分标 `differs`。不太可能：工作说明要求照抄人的原话，agent 照抄的就是提问工具交回的整串。
