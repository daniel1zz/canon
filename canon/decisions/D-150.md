## 背景

D-148 把杂务改成只要标题的轻变更：占 C 号，文件在合入时随改动写进关闭提交，main 上不多出开工提交，失败或放弃时不留在待办里，`canon update`、`canon release ship` 这类自动入口照样能用，工作身份仍和文档分开。落到规则时有三件事没定：

- C 号什么时候分配：开工时还是合入时。
- 在途的工作用什么身份：`chore-<UUID>` 还是 `C-n`。认领、事件、合入队列、hook 的环境变量、`canon work` 的各命令（test、review、stop、status、after-land、clean、drop、take、unstall）都按身份找工作；现在区分变更和杂务只看身份的样子。
- 已经在做的旧杂务（`chore-<UUID>` 的 worktree 和分支）怎么收尾。

## 方案

1. **身份仍是 `chore-<UUID>`，C 号在合入做关闭提交时分配，同一份工作重试时沿用；关闭提交新建变更文件，front matter 的 `chore` 写回工作身份**：采用。
   - 所有按身份工作的命令和记录不用改，在途的旧杂务用新版本合入时一样写出变更文件，不需要迁移，也就没有迁移丢工作的风险。
   - 编号和文件同时出现：有编号就有文件，`canon show`、`canon human ask --change` 不会指向一个还不存在的变更；失败或放弃的工作不占编号，main 上什么都没留下，自然不在待办里。
   - 代价：开工时还不知道 C 号，提交说明里只能写杂务身份；变更文件里的 `chore` 把编号和身份连起来，事件表照旧按身份记。
   - 来源：canon/decisions/D-148.md “工作身份仍和文档分开”
   - 来源：src/work/session/subject.ts “Resolve an existing chore from git even after its claim was released”
2. **开工就分配 C 号并用它当身份（分支 `change/C-n-<slug>`，合入前分支上没有变更文件）**：否决。开工、接回和列表从分支上读变更文件来认一个变更，轻变更在合入前没有文件，就分不清是轻变更还是坏掉的变更；所有用身份区分杂务的地方都要改成去读分支；在途的旧杂务要改分支名和 worktree 才能接上，改名中途失败会丢工作。
   - 来源：src/work/session/session.ts “A change that is not on main but on its own branch”
3. **开工就分配 C 号，身份仍是 `chore-<UUID>`，两个都输出**：否决。编号在文件出现前就给出去，`canon show C-n` 找不到，`canon human ask --change C-n` 问的是不存在的变更；放弃的工作白占编号。换来的只是提交说明里能早点写上编号。
   - 来源：canon/product.md “main 上的文档和代码一致，没有断掉的引用”
4. **开工时像 `--title` 一样把变更文件提交到分支上，合入时把开工提交并进关闭提交**：否决。文件在分支上，`canon change list` 就会把在途和被放弃但没删分支的轻变更列出来（它也读只在分支上的变更），不符合“失败或放弃时不留在待办里”；合入时改写分支历史，和关闭提交只靠比较并交换撤回（BR-2018）的做法冲突。
   - 来源：canon/decisions/D-148.md “失败或放弃时不留在待办里”

## 决定

采用方案 1：开工按 BR-2457，合入写变更文件按 BR-2458，`chore` 键的写法和校验也在 BR-2458，轻变更不要求段落按 BR-2091。D-100 里“不占知识编号，不建知识文档或开工/关闭文档提交”改为：不建开工提交，合入时在关闭提交里建变更文件、占 C 号；分支、身份和恢复方式不变。BR-2510 不再按通道区分目标的改动，按改动的内容判断（D-139）。

## 后果

- main 上每个轻变更多一个 `canon: close chore-<UUID>` 关闭提交，正文写着它的 C 号和标题。
- 轻变更的变更文件正文是空的，`rules` 为空、没有 `passes`：它不计算执行证据，和原来的杂务一样（BR-2458）。
- 开工和合入之间重装或清空了协调数据库时，标题取不回来，变更文件用分支 slug 当标题，合入输出说明这一点（BR-2457 的已知情形）。
- 什么结果说明选错了：迁移完成后两周内，会话为了在提交说明或 `canon human ask --change` 里写编号，反复把轻变更改成完整变更，说明开工时就要有编号。
