---
id: D-28
title: 配置的查看和编辑提示：命令列出全部配置项，schema 由 canon 生成、不提交
status: accepted
---

## 背景

负责人想方便地看到 `canon/config.yaml` 能设置的全部项并进行设置，问要不要做网页配置页。`canon/product.md` 把网页 dashboard 列为不做的事；而且配置决定 floor、评审和 hook 怎么跑，修改必须走合入（BR-2165 特意不让 `floor_skip_paths` 盖住它），网页直接写文件会绕过合入。负责人同意改成：一个列出全部配置项的命令，加上给编辑器用的 JSON Schema。

C-135 之后，每个配置项由用它的领域在 `config-keys.ts` 里声明（名字、说明、默认值、校验），这是命令和 schema 的共同来源。两个要定的问题：每个配置项的 schema 从哪里来；项目怎样拿到 schema 并在 canon 升级后保持一致。给出推荐前请一个看不到推荐的子 agent 反驳过一次，下面的否决理由有两条来自它。

## 方案

1. 网页配置页：否决。违反产品的“不做的事”，并且绕过合入。
2. schema 从哪来——每个配置项多声明一个 schema 片段，测试用 ajv 拿同一批正例、反例分别问 schema 和 canon 的读取，要求结论一致，schema 表达不了的检查列为例外且只许 schema 更宽：采用。和校验写在同一处，新键不写 schema 编译不过；测试比的是行为，不只是默认值。
3. schema 从哪来——改用 zod 一类的库写校验，再从它导出 JSON Schema：否决。跨键约束（`shared` 依赖 `code_root`）、单位换算、`types` 的相互约束要写成 refine 或 transform，导出时会丢掉，校验仍然分两处，还多一个运行时依赖。
4. schema 从哪来——手写一份独立的 schema 文件，测试只比较键名：否决。`types` 这类嵌套结构最容易不一致，而比较键名发现不了。
5. 分发——把 schema 提交进仓库，由 `canon check` 判断过期：否决。合入时运行检查的是 main 上构建的旧版 canon，新增配置项的变更重新生成 schema 后，会被旧版判成过期而合不进去；不同机器上版本不同的 canon 还会互相把对方的文件判成过期。
6. 分发——modeline 指向 canon 仓库在网上的 schema 地址：否决。canon 没有发布版本，地址只能指向 main，和本机装的 canon 对不上；离线或私有仓库时编辑器拿不到。
7. 分发——像自带 skill 一样由 `canon install`、`canon update` 写进项目并提交：否决。要走一次合入才能更新，并和正在进行的配置修改冲突；schema 是从当前 canon 算出来的东西，没有需要保留的项目改动。
8. 分发——`canon brief`（每个会话开始时运行）和 `canon config` 把 schema 写进被 git 忽略的 `.canon/config.schema.json`，`canon/config.yaml` 第一行用相对路径的 modeline 指向它：采用。始终和本机运行的 canon 一致，不进合入，worktree、离线、私有仓库都能用。代价是从没运行过 canon 的新 clone 里编辑器找不到 schema，运行一次 `canon brief` 即可。
   - 来源：https://raw.githubusercontent.com/redhat-developer/yaml-language-server/main/README.md “Relative paths in modelines are resolved from the YAML file's location, not the workspace root.”

## 决定

采用方案 2 和方案 8：

- `ConfigKey` 增加必填的 `schema` 片段（默认值用文件里的写法和单位），以及可选的 `needs`（必须同时设置的键，生成 `dependencies`）。
- `canon config` 列出全部配置项（BR-2174），`canon config --schema` 输出 schema（BR-2175），`canon brief` 和 `canon config` 写 `.canon/config.schema.json` 并把 `/.canon/` 加进 git 公共目录的 `info/exclude`（BR-2176）。
- `canon init` 写的 `canon/config.yaml` 第一行是 modeline（BR-2032）。
- modeline 只能写成注释；`$schema:` 写成键会被当作未知键，配置读取失败。

## 后果

- 新增配置项时多写一个 schema 片段，并在测试里补正例、反例。
- 编辑器没标红不等于配置有效：表达不了的检查只在 `canon config` 等命令读配置时报出。
- `canon brief` 多一次写文件；内容不变时不写。
