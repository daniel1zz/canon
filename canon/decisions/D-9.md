---
id: D-9
title: canon 的 skill 装在项目级别，只在用 canon 的项目里出现
status: accepted
---

## 背景

D-7、D-8 把 canon 的 skill 链接到 `~/.claude/skills/`，这样它们会出现在这台电脑上的每一个项目里，包括没用 canon 的项目。负责人要求（2026-11-03）：所有 skill 都应该是项目级别的，项目安装了 canon 才安装，不污染用户的全局配置。

## 方案

1. 继续放在用户全局。否决：负责人明确不要；没用 canon 的项目也会加载这些 skill 的描述。
2. 在项目的 `.claude/skills/` 里放指向 canon 仓库的链接。否决：链接是这台电脑上的绝对路径，提交进项目后换台电脑、换个位置就失效；不提交又会让每个 worktree 都缺 skill。
3. 做成 Claude Code 插件，在项目的 `.claude/settings.json` 里启用。否决：要有一个所有协作者都能访问的插件市场，canon 仓库是私有的；而且插件更新的时机不受项目控制。
4. 把 skill 复制进项目的 `.claude/skills/canon-*` 并和项目一起提交，`canon init` 时安装，`canon skills install` 更新；用一份清单记录 canon 写下的每个文件的哈希，项目里改过的文件不会被悄悄覆盖。采用。

## 决定

- canon 仓库里 skill 的源头放在 `.claude/skills/canon-*`（原来的 `skills/` 搬过去），canon 自己也就只在项目级别使用它们。
- `canon init` 安装（BR-2080）；`canon skills install [--force]` 更新，不覆盖项目里改过的文件（BR-2081）；找不到源头时以环境错误失败（BR-2082）。
- 移除这台电脑上 `~/.claude/skills/canon-*` 的 9 个链接；用户自己的 `user-*` skill 不受影响。
- D-8 里“链接到 `~/.claude/skills/`”这一点由本决策取代；D-8 的移植清单不变。

## 后果

- 每个用 canon 的项目都提交一份 skill 副本；canon 更新 skill 后，各项目要运行一次 `canon skills install` 并提交。
- skill 要改就在 canon 仓库里改，再装进各项目；在项目里直接改会在下次安装时被拦下。
