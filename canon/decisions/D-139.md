## 背景

D-136 把防止忘事的检查改成了提醒，并在它的方案 1 里写了一句分类：以后新加的检查，只是防止忘事的做成提醒，保证 main 正确的才拒绝。这句话只在一个决策的一个方案里，`canon/product.md` 和设计用的 skill 都没有，新设计读不到它。

2026-11-20 设计质量标准（C-609）时，主会话接连提出了一串硬拦截：判定过期就不许开新功能、判定不合格就挡住、写代码的会话不能当判定人、没证明就不能发布、调研结论没写去向就让 `canon check` 报错、每个方面都必须有标准。负责人逐条纠正，原话是：「判定过期时不开新功能我觉得也太绝对」「如果新功能完全和当前的不相关呢」「我发现你很多判定都太绝对了」「如果两个之间没有相关性为什么要阻塞呢」「我们应该要给主agent足够的自由度，他有自己的判断能力」「我们应该给引导给标准，不要动不动就强制拦截」「我们应该重提醒，轻拦截，这个应该固化到canon中」。

推出硬拦截的思路每次都一样：提醒被忽略过（D-126 的理由、zhushenkongjian 的体验验收一再推迟），于是直接改成拒绝，没有再看两件事：被挡住的工作和问题相不相关，以及主 agent 自己能不能判断。canon 已经有让提醒真正送到会话的办法：待办清单（BR-2527）、长期运行的 `canon work watch`（BR-2528）、`canon brief` 和 `canon overview`；主 agent 写在变更文件里的理由，负责人在总览里看得到。

## 方案

1. **写成 canon 的总原则：给标准、在相关的时候提醒、由主 agent 判断并写下理由；只有下面几类检查才拒绝**：采用。
   - 保证 main 正确、文档不说谎的完整性检查（P4、P5；按 D-137，只在关键节点加重）；
   - 防止丢数据和安全问题（D-54 的例外类）；
   - 保护机器容量（D-136）；
   - 负责人明确要求拦的（有记录的回答或转述的原话）。

   其余检查（防忘事、流程是否走全、质量是否达标、该不该先做别的）都给出标准，并在和当前工作相关时提醒。主 agent 判断相关性和处理办法，写下理由；负责人事后在总览里纠正。即使属于上面几类，拒绝也只挡和问题相关的工作，不挡无关的工作。原则写进 `canon/product.md`，每个会话都会读到；设计用的 canon-design 在横切检查里加一行；规则评审看到新加的拒绝不属于这几类时提一条意见（`note`，不拦）。
   - 来源：canon/decisions/D-136.md “以后新加的检查也按这条分类”
   - 来源：https://github.com/daniel1zz/canon/issues/260 “所有类似的情况都可以通过monitor处理”
2. **维持现状，每个检查个案决定**：否决。分类已经写在 D-136 里，这次设计照样推出六个硬拦截，靠负责人逐条纠正；原则不在每次都读的地方，就挡不住同一种推理。
   - 来源：canon/product.md “检查 agent 怎么干活”
3. **用 `canon check` 拒绝没写类别的新拒绝**：否决。它本身就是一条防忘事的硬拦截，违反要立的原则；而且一条规则是不是在拒绝、拒绝的是什么，要读懂文字才知道，机器判断不准。改由规则评审提意见，评审本来就在读这些文字。
   - 来源：canon/rules/work/session/BR-2530.md “不因为未处理的评审意见拒绝开工”
4. **所有检查都改成提醒，完整性检查也不拦**：否决。P4、P5 要求 main 上每个提交都可信；只靠文字让模型自己决定省哪些步骤，模型会把它当成省步骤的许可。D-137 已经把完整性检查减到关键节点，剩下的保留拒绝。
   - 来源：canon/product.md “这一点对 main 的每个提交都成立”
   - 来源：canon/decisions/D-137.md “permission to skip steps”

## 决定

采用方案 1。D-136 方案 1 的两类分类由这里的四类取代；D-136 的其他内容不变。

- 原则写进 `canon/product.md` 的「检查的分寸」一节。
- canon-design 的横切检查加一行「拒绝」：设计让命令拒绝、等待或停下时，写明属于哪一类、只挡哪些工作；不属于的改成标准加提醒。
- 规则评审对新加的、不属于这几类的拒绝提意见：BR-2009。

## 后果

- 新设计默认做成提醒；要拒绝就得说明属于哪一类、挡的范围，评审会提意见，但不拦合入。
- 现有的拒绝不在这次逐个复查：下次改到哪条，就按这里重新判断，评审会提醒。
- 提醒被忽略的风险还在。应对办法不是改回拒绝，而是让提醒只列相关的事、主动送到会话（watch），并要求主 agent 写下处理理由，让负责人看得到。
- C-609（质量标准）按这条原则设计：标准和提醒为主，主 agent 判断相关性。
