## 背景

D-99 让主 agent 用 `canon finding close` 当场结案每条拦截意见，凭据只有修复提交或一段原文（BR-2453），不管这条意见该由谁来定。#216 记了一个项目同一天的情况：措辞矛盾（会话自己就能定）、两条都说得通的规则谁让步（需要第二意见）、发布范围（只有负责人能定，而且负责人已经回答过）混在一起，会话可以凭自己的判断用 `--fixed` 关掉负责人才能定的意见，也可以不经任何人用 `--spurious` 说评审错了。D-115 已经要求修意见不能删除、收窄或放宽负责人定的目标，但没有东西核对。

负责人 2026-11-14 在对话里选了“全部做”（canon question #44，问题原文写明会修改 D-99 的“主 agent 自己结案”）；之前说过“心智负担不在考虑范围内，只要真的有效有作用有意义”。顾问会话（Codex，codex:0294b0da）对方案提了七条修改和一组反例，全部采纳。之后负责人又说：“没有顾问在线就直接问我”。

## 方案

1. 每条意见先“待分拣”，会话定档并写理由；按档要凭据：A 会话自己，B 另一个会话亲自记下的支持，C 负责人批准这一种结案；`--spurious` 至少 B；只有正在等负责人回答的意见不算欠账：采用。凭据都绑定在这条意见和这一种结案（同一个提交或同一段原文）上，换了修法就要重新来，这是顾问指出“回答过不等于批准当前处理方式”之后定的。
   - 来源：src/knowledge/review/findings/tier.ts “BR-2478: whether this caller may close finding”
2. 按 #216 原文：默认 B，C 档引用一个比意见新的 accepted 决策即可：否决。D-109 之后合入就自动 accepted，accepted 不再说明负责人点过头；而早于意见、但已经定了这件事的负责人回答，又不该因为早而要求再问一遍。改成引用负责人的回答，旧回答要引出定了这件事的原文。默认 B 也否决：首次定档若能直接定 A，默认值形同虚设；若不能，又要为每条措辞问题找顾问。
3. B 档凭据用会话自己填的顾问消息编号（例如 Concord 的 message id）：否决。canon 核对不了编号背后是谁、说了什么；改为顾问会话亲自运行 `canon finding advise`，会话身份从宿主环境读。
4. 维持 D-99，只在工作说明里写分档的做法：否决。#216 的两种情况都是会话按说明之外的判断结案，说明拦不住。

## 决定

采用方案 1：定档按 BR-2477，按档结案按 BR-2478，另一个会话的意见按 BR-2479，问负责人和引用旧回答按 BR-2480；BR-2453 的凭据照旧，档位检查在它之后。没有别的会话可以给意见时，B 档改问负责人（BR-2478、BR-2480）。

D-99 仍然成立的部分：拦截意见记账交给主 agent，不自动复问；结案由主会话执行 `canon finding close`；子 agent 被拒三次交给主 agent。

## 后果

- 会话结案之前多一步定档；B 档要另一个会话在线，没有时问负责人，等回答期间这条意见不算欠账（BR-2464）。
- canon 从宿主环境（`CLAUDE_CODE_SESSION_ID`、`CODEX_SESSION_ID`、`CODEX_THREAD_ID`、`CLAUDE_DELEGATE_CHILD`）判断会话，不看 `--as` 和 `CANON_ACTOR`，所以不能靠参数冒充顾问；一个改写自己环境变量的 agent 拦不住，和转述回答一样（BR-2021），canon 只保证记下的是哪种凭据。
- 定档本身由会话决定：把 C 定成 A 这种越权，canon 只记下理由（`finding.tier` 事件）供事后核对，拦不住。
- 合入之前已经开着的意见都是“待分拣”，agent 会话要先定档才能结案。
