id: D-19
title: 常驻说明的重复在合入时由 AI 评审拦截
status: accepted
---

## 背景

每个会话开始时都会收到几份常驻说明：项目的 `CLAUDE.md`、`canon brief` 的工作说明、每个项目 skill 的 description。C-104 发现 canon 仓库里 `CLAUDE.md` 和工作说明有约 11 条要求意思相同，“问人”在 `CLAUDE.md` 里还写了三遍；两份要同步修改，写法一旦不一致，agent 不知道以哪份为准。这些重复是一次次分别添加时积累起来的，没有任何检查会发现。

负责人在对话里选了“合入时 AI 评审 (推荐)”（2026-11-03，问题 #1）。

## 方案

1. 合入时 AI 评审：改动常驻说明时，用已配置的评审命令，把改动的文字和所有常驻说明的当前文字交给评审，重复就拦截。采用：重复常常是中英文写法不同、意思相同，只有读懂意思才能发现；只在改动常驻说明时多一次评审调用。
   - 来源：canon/changes/C-104.md “两边约 11 条规则意思相同”
2. `canon check` 机械比对：`CLAUDE.md` 里出现的 canon 命令已在工作说明里出现就报错。否决：只认命令字面，抓不到意思相同的句子；现在 `CLAUDE.md` 里“停下前用 `canon search` 查重”这种合理引用也会被误报。
3. 只靠文字约定：`CLAUDE.md` 开头写“通用流程以 `canon brief` 为准，这里不重复”。否决：完全依赖 agent 自觉，这次的重复正是在没有检查的情况下积累的。约定这句话照样保留，作为评审的依据之一。
4. 并入 C-34 的定期审计，只出报告。否决作为唯一机制：事后报告不拦截，重复还是会进 main；它能覆盖仓库外的全局规则（`~/.claude/rules/`），可以以后另做。

## 决定

改动常驻说明的合入，在规则评审之后再做一次重复评审（BR-2143）。常驻说明是配置 `instructions` 列出的文件（默认 `CLAUDE.md`）、项目 skill 的 description 和 canon 程序里的工作说明。仓库外的全局配置不在评审范围内：它因机器而异，合入的结果不能依赖它。

## 后果

- 改 `CLAUDE.md`、`instructions` 列出的文件或项目 skill 的合入多一次评审调用；没有配置评审命令时照常合入并记 `review.skip`。
- canon 仓库自己在 `instructions` 里加上 `src/cli/guide.ts`，改工作说明的合入也会被评审。
- 评审是 AI 判断，可能误拦；被拒时结论写明重复的两处，改掉其中一处或说明为什么不算重复后重新合入。
