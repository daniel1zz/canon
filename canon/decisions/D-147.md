## 背景

D-107 以上一次发布的文字为基线，只拦落在改动行里的重复，缩小了 #191 里同一段文字时拦时不拦的范围。但落在改动行里的重复仍然拦发布：拦的时候 `dist/canon` 和 `dist/skills` 都停在旧版本，PATH 上的 canon 和下游拿到的 skill 落后 main，直到有人改掉那段文字。D-107 的后果里写着这一点，也写着“落在改动行里的边界段落仍可能时拦时不拦”。

D-139 把 canon 的检查分成四类：只有保证 main 正确和文档不说谎的完整性检查、防止丢数据和安全问题、保护机器容量、负责人明确要求拦的检查才拒绝；其余给出标准并提醒，由主 agent 判断。发布的 skill 文字里同一条要求写了两处，是文字质量的提示，不是文档说错，也不让 main 或下游的行为出错，不在这四类里。D-91 的“通过才发布”和 D-107 的“只拦落在改动行里的重复”因此要改。

## 方案

1. **保留基线和 `(already released) ` 的判定，每条 `duplication` 发现都只作提示，发布照常进行**：采用。提示仍然送到发布输出，早已发出的重复和落在改动行里的重复都看得到；评审命令跑不了（没有配置、命令失败、提示超出预算）仍然是错误，退出码 4、不发布，所以不会悄悄跳过评审。
   - 来源：canon/decisions/D-139.md “只有下面几类检查才拒绝”
   - 来源：canon/decisions/D-107.md “只拦落在改动行里的重复”
2. **维持 D-107 的拦截，落在改动行里的重复仍拦发布**：否决。D-139 的四类不包括文字重复；D-107 自己记下了这类边界段落时拦时不拦，一次拦下就让二进制和 skill 停在旧版本，#191 的问题只是缩小、没有消失。
   - 来源：canon/decisions/D-107.md “落在改动行里的边界段落仍可能时拦时不拦”
3. **取消发布评审**：否决。重复的提示和基线信息还有价值；取消后连提示也没有；评审跑不了时的不发布是防止没评审过的文字进入下游（#159、#182），要保留。
   - 来源：canon/decisions/D-139.md “给标准、在相关的时候提醒”

## 决定

采用方案 1。行为见 BR-2411：发布评审的重复发现只作提示，发布照常进行。沿用旧记录时只读发现、不读当时记的结论，所以早先记为拦截的那次现在也是提示。D-107 里“只拦落在改动行里的重复”这一段由这一条取代，D-107 的其他内容不变；BR-2412 随这一条一并改写（见 BR-2412）。D-91 里“通过才发布”由 D-107 和本条取代，D-91 其他内容不变。

## 后果

- 发布不再因为重复停下：`dist/canon` 和 `dist/skills` 总是前进到最新的测过的提交，重复只在发布输出里以 `note: ` 出现。
- 重复清理由人判断：要清理的文字，开变更改 skill，改到的行重新进入提示；不改也不拦。
- 评审设置问题仍会挡住发布：没有 `review`、`review: none`、评审命令失败、最大的 skill 超过单次预算的一半，都退出码 4、什么也不发布。
- 提示可能被忽略：发布评审的输出只在 `after_green` 的日志里，看它的人比合入时的评审少。D-139 的应对办法是让提醒只列相关的事并送到会话；发布输出目前只写到日志，如果重复长期没人处理，可以把它们也列进 `canon work due` 或 `canon brief`，但这次不做。
- 发布评审的调用次数不变：同样的文字和基线仍只评审一次，沿用记录的发现。
