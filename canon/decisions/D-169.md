## 背景

C-708 把 5 条常驻规则算进每个会话固定加载的文字后，canon 自己的会话要加载 17673 字节，session_text_budget 是 12000（D-37、BR-2256）。C-724 逐句压缩后还有 15823 字节：工作说明 5775、规则 5174、skill 描述 3034、CLAUDE.md 1840。原文本来就紧凑，再压就得删要求。

负责人 2026-11-28：「12000的话看看有哪些可以动态加载的，而不是全部直接注入」，接着说「不一定要CLAUDECODE的按需注入啊，你直接在一级注入中用一个引用，让AI自己判断需不需要注入就行啊」。

查了 Claude Code 的文档：没写 `paths` 的规则文件在会话开头整篇加载，canon 的规则都是通用行为，没有对应的文件可写 `paths`；CLAUDE.md 的 `@import` 照样在开头加载；SessionStart hook 的输出（`canon brief` 走这条路）超过 10000 个字符就只给模型看前 2000 字的预览。

工作说明有一半只在特定时刻才用得上：合入要等多久、合入后怎么跟进、优先级、合入后评审的定档、问人之后怎么记录回答、挑任务的顺序和派 worker。规则里证据分级、教训怎么固化、提 issue 的步骤也是这样。

## 方案

1. 调高 session_text_budget：否决。只是承认体量，每个会话照样加载全部文字，而且 `canon brief` 越长越接近 SessionStart 输出的上限。
   - 来源：https://code.claude.com/docs/en/hooks “capped at 10,000 characters”
2. 用宿主的按需加载（规则的 `paths`、CLAUDE.md 的 `@import`）：否决。没写 `paths` 的规则照样在开头加载，canon 的规则没有对应的文件；`@import` 也在开头加载；而且只有 Claude Code 有，Codex 用不上。
   - 来源：https://code.claude.com/docs/en/memory “loaded at launch with the same priority”
3. 把细节做成 skill：否决。skill 的描述照样每个会话都加载，而且触发靠描述匹配，不能在工作说明的某一句后面直接点名。
   - 来源：https://code.claude.com/docs/en/skills “full skill content only loads when invoked”
4. 常驻文字只留索引，细节按主题由 `canon guide <主题>` 输出：采用。这是负责人说的做法。细节写在 canon 程序里，和工作说明一样跟着正在运行的 canon 走（D-10），Codex 也能用，不用改安装逻辑。每个主题在常驻文字里留一句，写明什么时候读、读哪个主题；安全约束（比如 subagent 要加 `--as`、什么时候才问人、`canon work drop`）留在常驻文字里。

## 决定

采用方案 4：BR-2654；BR-2090 列出的工作说明内容相应缩短。canon 的常驻规则 canon-behavior 里的证据分级、教训和提 issue 的步骤也挪进主题，规则里只留一句什么时候读。

## 后果

- canon 自己的会话固定加载的文字降到 11977 字节，回到 12000 以内。
- 风险是 agent 到了那一步却没去读主题。所以每个引用都写明时机，命令的输出和拒绝信息照旧提示下一步（BR-2648）；会让 main 出错或丢数据的约束不挪。要是发现某个主题常被跳过、因此出错，就把那一句挪回常驻文字。
- 以后新加的说明先问：它是每次都要守的，还是只在某个时刻才用得上？后者写成主题。
