id: D-30
title: Bash 调用前给未提交的工作留快照，而不是拦截会丢工作的命令
status: accepted
---

## 背景

2026-11-03 一个 agent 在 bypassPermissions 模式下用 Bash 里的 python 改了 `src/cli/strict.ts`（没提交、没暂存），随后为了撤销一次临时实验运行 `git checkout -q src/cli/strict.ts`，把新函数一起清掉了。git 找不回（从没暂存过），Claude Code 的 `/rewind` 也找不回：只被 Bash 改过的文件不在检查点里。这次能恢复，只是因为内容还在 agent 的上下文里。负责人要求由 canon 在项目级别安装防护，不放进个人的全局配置。

实测：PreToolUse hook 返回 deny 在 bypassPermissions 模式下仍然拦得住 Bash 调用，改了配置不用重启会话就生效。给出推荐前请一个看不到推荐的子 agent 反驳过一次，下面的否决理由有几条来自它。

D-18 撤掉旧的 PreToolUse hook 时，把“每个 Bash 调用多约 36 ms”列为理由之一。这条理由不成立：本会话约 2 小时调用 Bash 152 次，每次多 60 ms 合计约 9 秒，约占 0.1%，而且不花 token、不占上下文、不增加出错概率。D-18 的其余理由（放行规则太宽导致 #26，分开同一 worktree 里两个 agent 的能力 canon 本来就不允许）不受影响，D-18 撤掉的那个 hook 也不恢复。

## 方案

1. 拦截：PreToolUse hook 解析命令文字，认出 `git checkout -- <路径>`、`git restore`、`git reset --hard`、`git clean -f` 等，涉及的文件有未提交改动时拒绝：否决。它拦的正是 agent 想做的事（这次的 `git checkout` 本意就是撤销实验），被拒后 agent 会换成直接写文件绕过去；`bash -c`、git 别名、`git -C`、脚本里调用 git 都解析不到；`rm`、重定向、`sed -i` 覆盖文件完全管不到；而且这是判断 agent 怎么干活，属于产品不做的事。
2. 快照：Bash 调用前，worktree 有未提交的工作就存成一个 git 提交（从 worktree 自己索引的副本起步，`add -A`、`write-tree`、`commit-tree`），放在 `refs/canon/snapshots/` 下，加列出和找回的命令；不拦截任何命令：采用。不管工作是怎么丢的都能找回，符合 P4“不丢工作”；canon 只记录结果，不判断 agent 怎么干活。
   - 来源：https://code.claude.com/docs/en/checkpointing “A file that only Bash commands changed isn’t tracked and stays as it is.”
3. 拦截加快照：否决。拦截的缺点全部保留，快照已经让丢失可以找回。
4. 什么都不装，靠 agent 养成先提交或先备份的习惯：否决。同一个会话里，agent 在知道这条教训之后又在主 checkout 里用 `git checkout` 还原了一次改动，习惯靠不住。
5. 快照和 `canon work drop` 的存档共用一个函数：否决。存档要包含不能重建的被忽略文件，并在删除前读回校验；快照要快、不碰被忽略的文件。合在一起会让快照变慢，或者削弱存档的校验。
6. worktree 被清理或放弃时删掉它的快照：否决。没发现就弄丢、随后又合入并清理的工作会跟着永久丢失。
7. 每个 worktree 只留最近 20 个快照：否决。几乎每次 Bash 调用前都有新改动，本会话的节奏下 20 个只覆盖约 15 分钟，过一会儿才发现的丢失就找不回了（负责人转来的提醒指出）。改为按时间：24 小时内全留，之后每小时留一个，14 天后删除。

## 决定

采用方案 2：

- `canon snapshot take [--hook]` 做快照（BR-2182）：只在 canon 项目、工作区不干净、内容和最近一个快照或 HEAD 不同时新建；大于 5 MB 的文件不放进去并写明；不改 worktree 的文件和索引。
- 24 小时内的快照全留，之后每个 worktree 每小时留最新的一个，超过 14 天的删除，不随 worktree 清理而删除（BR-2183）。
- `canon snapshot list` 列出快照和找回的命令（BR-2184）。
- `canon init`、`install`、`update` 把 PreToolUse（`Bash`）hook 合并进 `.claude/settings.json`，`update --check` 报告缺失；hook 失败时用 `systemMessage` 告诉用户，不拦截 Bash（BR-2185）。

## 后果

- 每次 Bash 调用多一次 canon 启动和一次 `git status`；工作区不干净时再多一次快照，本仓库实测约 0.1 秒以内。
- 快照只在本机：没被忽略的 `.env` 之类会进对象库，默认的 `git push` 不推 `refs/canon/*`，`git push --mirror` 会推。
- 漏洞：同一次 Bash 调用里先改后丢，快照只有调用前的状态；用 `git -C` 或 `cd` 去操作别的 worktree 时只快照 hook 的 `cwd` 所在的那个。
- 合入后、`after_land` 重新构建 `dist/canon` 之前，PATH 上的旧 canon 没有 `snapshot` 命令，hook 会提示失败一次，属于预期。
