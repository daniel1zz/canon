---
id: D-40
title: 注入内容的使用统计是单独的命令，可用清单取自窗口内各个会话记录里实际注入的内容
status: accepted
---

## 背景

C-34 要一个报告：读本项目的 Claude Code 会话记录，统计 skill、MCP 工具、子 agent 类型用了几次、最近一次是什么时候，再对照可用的清单，列出很久没用过的项和它们的注入量。N-2 是 2026-11-03 手工做的一次同样的审计。

2026-11-04 对真实记录（只用 `head` 和按关键字截取）核对过的事实：

- 会话记录在 `~/.claude/projects/<路径编码>/` 下，路径编码是把路径里每个字母和数字以外的字符换成 `-`。canon 的会话不只在主 checkout 的目录里：在变更 worktree 里启动的会话在 `-Users-apple-Projects-zz-canon-worktrees-C-n` 下（172 个），一起测的 worktree 在 `-Users-apple-Projects-zz-canon--git-canon-batch-n` 下（11 个）；子 agent 的记录在 `<会话>/subagents/agent-*.jsonl`。这些目录合计 516 个 `.jsonl` 文件、约 400MB，最大的一个 20MB；全部读一遍实测约 1.3 秒。
- 调用记在 `type: "assistant"` 记录的 `message.content` 里 `type: "tool_use"` 的块：skill 是 `name: "Skill"`、`input.skill`；MCP 工具的 `name` 是 `mcp__<服务>__<工具>`；子 agent 是 `name: "Agent"`、`input.subagent_type`。同一个 `tool_use` 的 `id` 会在记录里出现不止一次。用户输入的斜杠命令记成 `<command-name>/名字</command-name>`，其中多数是 `/model`、`/login` 这类内置命令。
- 会话里注入了什么也记在里面：`attachment.type` 为 `skill_listing`（每个 skill 一行描述，`isInitial` 为 true 时是完整清单，之后的是新增）、`mcp_instructions_delta`（每个 MCP 服务的说明）、`deferred_tools_delta`（延迟加载的工具名，包括 MCP 工具）、`agent_listing_delta`（子 agent 类型和描述）。
- 这些格式不是公开文档写明的接口，Claude Code 升级时可能改。

## 方案

1. 在 `canon stats` 里加一节。否决：`canon stats` 读的是事件表，几十毫秒；会话记录有约 400MB，每次看检查统计都要读一遍不划算；`canon stats` 的文字输出顺序和 `--json` 字段都有规则固定（BR-2202）。
   - 来源：src/work/stats/commands.ts “Check precision: runs, refusals and what happened after each refusal”
2. 单独的命令 `canon usage`，放在 `work/stats` 领域。采用：只在要审计时才读会话记录；和 `canon stats` 一样是“从记录里算出来的数字”，属于同一个领域。
3. 可用清单读配置文件（`~/.claude/settings.json`、`~/.claude.json`、插件目录、各级 skill 目录）。否决：配置分散在多处，还有插件、账号连接器、被组织策略关掉的服务，自己拼出来的清单和会话里真正注入的会不一样；注入量也只能估。
4. 可用清单只取最近一个会话最后注入的内容。否决：2026-11-04 实测，最新的会话（一个很短的会话）结束时只连上了 context7 和 mcp-deepwiki 两个 MCP 服务，serena、claude-in-chrome 等都还没连上，按它算会漏掉大半的 MCP 注入。
5. 可用清单是统计窗口（最近 N 天）里各个会话最后注入的内容的并集，每项附上最后注入它的会话的时间。采用：这就是模型真正看到的东西，注入量按实际注入的字符数算，不用估；一个已经从配置里去掉的项，看最后注入时间就能认出来，过了 N 天自然不再列出。代价是要靠没有公开文档的格式；格式变了时报告会显示没找到清单，而不是悄悄给出错的数字。
6. 会话记录目录按 `CLAUDE_CONFIG_DIR` 定位，没有设置时用 `~/.claude`。采用：Claude Code 自己就是这样存放会话记录的；测试也可以用它指向伪造的目录，不碰真实记录。
   - 来源：https://code.claude.com/docs/en/settings “Claude Code then stores your settings, session history, and plugins there instead”
7. 只统计主 checkout 编码出来的那一个目录。否决：canon 的会话多数在变更 worktree 和一起测的 worktree 里启动，只看主 checkout 会漏掉一大半。

## 决定

采用方案 2、5、6：`canon usage [--days N] [--json]` 读 `<CLAUDE_CONFIG_DIR 或 ~/.claude>/projects` 下属于本项目的目录（主 checkout、变更 worktree 目录下的、git 公共目录 `canon/` 下的），只读不写，统计 skill、MCP 服务、子 agent 类型的使用次数和最近一次时间（BR-2265）；可用清单是窗口内各个会话实际注入的内容的并集，列出可用但 N 天（默认 30）没用过的项和它们注入的字符数（BR-2266）。只报告，不改任何配置：去掉哪一项要人决定（C-34）。

## 后果

- 注入量用字符数报，不换算成 token：字符数能核对，token 数要看分词器。
- 规则文件（`CLAUDE.md`、`~/.claude/rules`）的注入一直生效，会话记录里没有“用过一次”这种事，这个命令不统计它们；它们的大小也不在这个命令里报告。
- 会话记录的格式变了时，统计会变成 0、清单会找不到；报告写明没找到清单和跳过了多少行读不懂的记录，看到这种输出要先核对格式。
- 用户的斜杠命令只有名字是可用 skill 的才算 skill 调用，`/model` 这类内置命令不算。
