---
id: D-17
title: 子 agent 的执行者身份由 PreToolUse hook 注入
status: accepted
---

## 背景

执行者（BR-2023）在 Claude Code 里是 `agent:<会话 id 前 8 个字符>`。一个会话的子 agent 和主会话环境完全相同（同一个 `CLAUDE_CODE_SESSION_ID`、同一个 `CLAUDE_PID`，每个 Bash 调用是新的 shell），所以 canon 分不开它们（D-11）。C-87 让有效的认领挡住所有 start 和 drop，同一个执行者也一样；但 issue #23 指出：被拒绝的兄弟子 agent 会被提示进入持有者的 worktree，那里只比较执行者，它就能续期、合入或放开兄弟的认领，半成品被合入 main，或者两个会话写同一个 worktree。

2026-11-03 在 Claude Code 2.1.316 上实测：

- 子 agent 里发起的 Bash 调用，PreToolUse hook 的输入带 `agent_id` 和 `agent_type`，主会话的没有。
- PreToolUse hook 只返回 `hookSpecificOutput.updatedInput`（不带 `permissionDecision`）时，命令确实被改写：在命令前加 `export CANON_PROBE='agent:<8>[:<agent_id>]'` 一行后，主会话读到 `agent:3d606482`，子 agent 读到 `agent:3d606482:add88b47cf722ff32`。
- `canon hook pre-bash` 每次调用增加的耗时见 C-91。

负责人在 2026-11-03 选了“子 agent 身份（推荐）”这个方向。

## 方案

1. 执行者只到会话一级，靠 C-87 的“有效认领挡住所有人”（现状）：否决。#23 仍然成立：同一个执行者在持有者的 worktree 里就是持有者，挡不住兄弟子 agent。
   - 来源：src/work/claims/claims.ts “a live claim refuses every start, the same actor included”
2. PreToolUse hook 在子 agent 的每个 Bash 调用前加一行 `export CANON_ACTOR='agent:<会话>:<agent_id>'`，只返回 `updatedInput`：采用。`agent_id` 是 Claude Code 文档里写明的字段，改写后的命令仍按权限规则逐行核对，只需为这一行加一条放行规则；旧系统 lore 用同样的做法给每次调用注入运行身份。
   - 来源：https://code.claude.com/docs/en/hooks.md “Unique identifier for the subagent or in-process teammate the hook fires in.”
   - 来源：https://code.claude.com/docs/en/hooks.md “Claude Code evaluates permission rules and a Bash command”
   - 来源：https://code.claude.com/docs/en/permissions.md “Every subcommand must be allowed for a compound command to run without a prompt”
   - 来源：https://raw.githubusercontent.com/daniel1zz/lore/main/docs/requirements/spec/SPEC-245-a-lore-call-s-run-identity-is-injected-per-bash-ca.md “The hook stays a blind pipe that never gives a permission decision”
3. 照 lore 的做法再加运行登记表，并沿进程祖先链核对身份，防止冒充别的会话：否决。canon 面对的是互相配合的 agent，不防恶意冒充；登记表和每次调用的进程链遍历是额外的状态和开销。只做一个便宜的一致性检查：`agent:<x>:<y>` 的 `<x>` 必须是本会话（BR-2023）。
   - 来源：https://raw.githubusercontent.com/daniel1zz/lore/main/docs/requirements/spec/SPEC-245-a-lore-call-s-run-identity-is-injected-per-bash-ca.md “Walk from the lore process itself”
4. hook 返回 `updatedInput` 的同时返回 `permissionDecision: "allow"`：否决。allow 会跳过整条命令的权限提示，用户自己的那部分命令也被放行。
   - 来源：https://code.claude.com/docs/en/hooks.md “skips the permission prompt, except for”

## 决定

- `canon hook pre-bash`（BR-2127）读 PreToolUse 输入，有 `agent_id` 时返回改写后的命令，否则什么都不输出；任何情况都以 0 结束，不做权限决定。
- `canon install`、`canon init`、`canon update` 把这个 hook（canon 不在 PATH 上时什么都不做的形式）和只匹配那一行的放行规则合并进 `.claude/settings.json`（BR-2128）。
- 子 agent 是单独的执行者 `agent:<会话>:<agent_id>`，主会话仍是 `agent:<会话>`（BR-2023）。认领只由持有者续期、停下、放开和合入（BR-2104）对每个子 agent 分别成立，修好 #23。
- 子 agent 结束后它的认领放不开（进程还是会话的进程，BR-2100 不起作用），所以主会话可以用 `canon work stop --release --takeover` 显式放开自己子 agent 的认领（BR-2129）；不允许主会话替子 agent 合入，兄弟子 agent 和别的会话也不能接手。

## 后果

- 事件表、认领和 `canon work status` 里的执行者能分开子 agent，`canon stats` 和 C-43 的实测能按子 agent 统计。
- 没装这个 hook 的项目（或 PATH 上没有 canon）里子 agent 仍共用执行者，#23 在那里仍然存在；`canon update --check` 和 `canon brief` 会把缺少的 hook 报为过期。
- 主会话启动认领、再派子 agent 去合入的做法不再可行：子 agent 会被拒绝，要由主会话先放开（`canon work stop --release`），子 agent 再 `canon work start`。
- 每个子 agent 的 Bash 调用多一行命令和一次 `canon` 进程启动。主会话的调用也会启动一次 `canon`，只是什么都不改。
- 放行规则 `Bash(export CANON_ACTOR='agent:*')` 依赖 Claude Code 把命令按行拆开逐行核对；Claude 自己写出形如这一行、里面含命令替换的命令时，是否被放行取决于 Claude Code 对替换的处理（假设见 C-91）。
