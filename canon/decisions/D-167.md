## 背景

N-1（2026-11-03）从旧 lore 改写出的 user-* 规则一直放在负责人笔记本的 `~/.claude/rules/`，canon 不管。2026-11-27 迁到 Mac Studio 时它们一个都没跟过来，canon 和 zhushenkongjian 的会话因此读不到派 worker、如实报告、上下文收尾这些规则。负责人 2026-11-27 定了方向：「放到项目级别」「然后CANON管理」；2026-11-28 回答了两个设计问题（问题 #76、#77）：文件名改为 `canon-*`；装进项目前压缩但不丢任何一条要求，并算进预算。同日按“只在具体场景才读的做成 skill、一直要守的写成规则、别处已有的不重复”删掉了全部 user-* skill，user-15 并进 canon-parallel（C-708 的记录）。

## 方案

1. 继续放在用户主目录，换机器时手工拷。否决：负责人明确要求项目级、由 canon 管理；这次迁移就是因为手工拷漏了。
   - 来源：canon/decisions/D-9.md “所有 skill 都应该是项目级别的，项目安装了 canon 才安装，不污染用户的全局配置”
2. 规则跟 canon-* skill 走同一套安装：源头在 canon 仓库的 `.claude/rules/canon-*.md`，`canon init`、`install`、`update` 复制进项目的 `.claude/rules/`，单独一份清单记哈希，项目里改过的不覆盖，`uninstall` 一并移除；发布时放进 `dist/skills` 指向的目录里（`.rules/`），和 skill 同一次切换：采用。复用已有的“只覆盖没改过的文件”逻辑，不用新机制。
   - 来源：canon/rules/install/BR-2080.md “把 canon 自带的每个 `canon-*` skill 复制到当前项目的 `.claude/skills/` 下”
3. 把规则文字并进 `canon brief` 的工作说明。否决：工作说明是 canon 流程的唯一来源，这些规则多数和 canon 流程无关（如实报告工具调用、输出风格、证据分级）；而且 Codex 等别的宿主读 brief，规则是 Claude Code 的 `.claude/rules` 机制。
   - 来源：CLAUDE.md “`canon brief` 输出的工作说明是通用流程的唯一来源”
4. 保留 `user-*` 文件名。否决：负责人选了 `canon-*`（问题 #76），和 canon-* skill 一样一眼看出是 canon 装的。
   - 来源：canon/decisions/D-9.md “用户自己的 `user-*` skill 不受影响”

## 决定

采用方案 2：BR-2651；BR-2080 写明安装也包括规则；每个会话的文字预算（BR-2256、BR-2257）把 `.claude/rules/*.md` 全文算进去，因为 Claude Code 在每个会话开头整篇加载它们。

## 后果

- 压缩的结果：逐句核对、不丢要求之后，5 条规则从 5213 字节降到 5174 字节（去掉强调符号、把箭头改写成句子；原文本来就紧凑，没有可删的要求）。
- 规则算进预算后，canon 自己每个会话固定加载 17673 字节，`session_text_budget` 是 12000，`canon check` 一直提示超出：要么压缩 canon-* skill 的 description，要么调预算，留给负责人定。
- 只装进 Claude Code 目标；Codex 没有 `.claude/rules` 这种机制，不装。
- 没装 canon 的项目不再有这些规则，这是负责人要的结果。
- zhushenkongjian 手工放的 user-* 规则和 `.claude/skills/.user-skills.json`，在它运行 `canon update` 装上 canon-* 规则后删掉。
