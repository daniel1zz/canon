---
id: D-37
title: 每个会话固定加载的文字：按字节量，在 canon check 里提示，不拒绝合入
status: proposed
---

## 背景

C-59：lore 的 CLAUDE.md 涨到 164.6KB，压缩后 4 天又涨到 52.8KB，只靠写规范拦不住；按内容做的检查误报很多。每个会话开始时固定加载三样文字：仓库根目录的 `CLAUDE.md`、`canon brief` 最先输出的工作说明、每个项目 skill 的描述。canon 仓库在 C-59 之前合计 12505 字节（`CLAUDE.md` 3342、工作说明 3543、10 个 skill 描述 5620）。负责人要求只看大小、不看内容，超过配置的预算时提示。要定的是：在哪里报、怎么量、量哪些文件、超了是提示还是拒绝。

支撑的承诺是 P3（连续性）：新会话不需要人重新交代就能接着做，前提是每个会话一开始固定加载的文字不会涨到占满上下文（C-59 里 lore 涨到 164.6KB）。

## 方案

1. 放进 `canon brief` 的输出：否决。`canon brief` 的输出本身每个会话都加载，多出的行自己就占预算，而且每个会话都看一遍，大多数会话不改这些文字。
2. 放进 `canon stats`：否决。`canon stats` 报协调数据库里历次合入和检查的统计，是回头看的；文字大小是当前树的状态，改这些文字的会话在合入前跑的是 `canon check` 和 `canon work test`，不看 `canon stats`。
3. 作为 `canon check` 的发现，超过预算就拒绝合入：否决。一旦超了，之后每个合入都被拒，哪怕它根本没碰这些文字，等于把别人的工作挡在门外，要等有人先压缩；预算是项目自己估的数，不值得当成门槛。
4. `canon check --sizes` 报每一部分的大小；配置了预算且超过时，`canon check` 和 `canon work test` 在标准错误输出一行提示，不算发现：采用。改这些文字的会话按工作说明合入前会跑 `canon work test`，能看到；标准输出和退出码不变，现有的输出格式（BR-2189）和合入都不受影响。
   - 来源：canon/rules/knowledge/check/BR-2189.md “有任何一条发现时退出码 1”
5. 按 token 量：否决。token 数取决于模型的分词器，要联网或者带分词表，结果还随模型变；字节数确定、离线、和 lore 的教训用的单位一致。中文一个字 3 字节，比英文显得大，但预算是每个项目按自己的文字定的，只比较同一个项目自己的变化。
6. 量 `instructions` 配置列出的文件，而不是固定的 `CLAUDE.md`：否决。canon 仓库为了让重复评审（BR-2143）看到工作说明，把工作说明的源码 `src/**/guide.ts` 列进了 `instructions`；这些文件不会被加载，量它们会把工作说明算两遍。Claude Code 每个会话加载的是根目录的 `CLAUDE.md`。
   - 来源：canon/config.yaml “工作说明的源码也算”

## 决定

采用方案 4：按 UTF-8 字节量根目录的 `CLAUDE.md`、当前 canon 自带的工作说明、`.claude/skills/*/SKILL.md` 的 `description`（BR-2256）；预算是配置项 `session_text_budget`（字节，不配置就不提示），超过时 `canon check` 和 `canon work test` 提示一行，不拒绝合入（BR-2257）。

## 后果

- 只量项目里的文字：用户自己的全局 `~/.claude` 说明、插件的 skill、嵌套目录里的 `CLAUDE.md` 都不算。用 `AGENTS.md` 而不是 `CLAUDE.md` 的项目量不到，以后需要时再加。
- 提示不拦合入，所以超了也可能一直没人管；它的作用是让改这些文字的会话在合入前看到数字。
- 提示只出现在 `canon check` 和 `canon work test`，`canon work land` 不输出：合入不要求先跑过它们，只改 `CLAUDE.md` 或 skill 描述的变更直接合入就看不到。这里选择写明这个限制，不让合入也输出提示：合入输出加提示要改合入路径、BR-2257 和测试，而提示本身只是提醒，超预算不丢数据、不弄坏 main，漏看一次的代价小；预算一直超着也会在下一次有人跑 `canon check` 时看到。真的出现“超了很久没人看见”时再把提示放进合入输出。
- 提示不写进协调事件表，提示出现过几次、有没有人因此压缩，之后查不出来；这是一个不计量的辅助提示，不算 P6 里的“检查”。
- 合计里 canon 自带的部分占大头：当前 canon 仓库 11560 字节中，工作说明 3877 加 10 个 canon 自带 skill 的描述 5620，共 9497 字节（82%）是 canon 发布的文字，用 canon 的项目自己改不了，只能随 `canon update` 变；项目自己写的只有 `CLAUDE.md`（2063 字节）。别的项目配预算时要把这 9.5KB 算进去，预算余量（canon 自己 12000 对 11560，余 440 字节）也主要被 canon 的升级吃掉。
- 先合后测（D-31）下 main 红的时候，PATH 上的 canon 是旧构建，量到的工作说明可能和 main 上的不一致；记成已知限制（D-54）。
- 新增配置键 `session_text_budget` 和使用它要分两次合入（BR-2248）。
