---
id: D-6
title: agent 可以转述负责人的回答，canon 如实记录而不假装能阻止冒充
status: accepted
---

## 背景

C-19 为了修 issue #4（agent 套伪终端替人回答），规定 `canon human answer` 只接受 `human:` 操作者。之后发现两件事：

- 负责人平时在 Claude Code 里工作：在对话里告诉 agent 怎么回答，或者用 `!` 运行命令。这两种情况的环境里都有 `CLAUDECODE=1`，操作者都会被认成 agent，于是负责人只能另开一个终端去回答。
- C-2 的代码评审试跑指出：agent 去掉 `CLAUDECODE` 再设 `CANON_ACTOR=human:x`，就能冒充人。操作者身份来自 agent 自己能改的环境变量，所以“必须是 `human:`”拦不住存心冒充的 agent，只挡住了负责人正常的用法。

负责人选择允许转述、如实记录（2026-11-03，在 Claude Code 里回答）。

## 方案

1. 保持只认 `human:`。否决：负责人在 Claude Code 里没法回答，而它防不住真正的冒充。
2. 允许转述，但删除带未合入工作的变更（`canon work drop`）时仍要人亲自回答。否决：负责人选了更简单的一种；而且“亲自回答”同样建立在可以伪造的身份上，并不更安全。
3. 允许 agent 用 `--relayed "<人的原话>"` 转述，记录为转述，所有地方和人直接回答的区分开；`canon work drop` 也接受转述。采用。

## 决定

- `canon human answer` 接受两种回答：`human:` 在终端里直接回答；agent 带 `--relayed` 转述人的原话。其他情况退出码 2（BR-2021）。
- 转述的回答保存原话，`canon human pending --all`、事件和 `canon work drop` 的输出都写明是哪个 agent 转述的。
- canon 不声称能阻止冒充：P7 靠 agent 遵守规则（CLAUDE.md 写明只转述人真实说过的话，并先用提问工具问人），以及事后能查出每个回答是怎么来的。
- 回答的写入改成原子的，两个同时到达的回答只有一个成功（BR-2040；这是代码评审试跑发现的另一个问题）。

## 后果

- 提问时 agent 应该用 Claude Code 的提问工具问负责人，再把原话用 `--relayed` 记下来；CLAUDE.md 写明这一点。
- C-19 的“只认 `human:`”被这个决策取代；`human.answer.refuse` 事件仍然记录不带转述的 agent 回答。
- 关于 `canon work drop` 的部分（方案 2、`canon work drop` 接受转述的同意）已被 D-13 取代：`canon work drop` 不再问人，改为存档后删除。转述人的回答、如实记录的其余决定不变。
