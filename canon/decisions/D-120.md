## 背景

2026-11-14 canon 自己的规则评审两次没跑成，都是 `review command printed no JSON`：评审命令 `claude -p` 的输出只有一句“已提交 1 条阻塞性发现……”“我报告了 1 条阻断问题……”。`claude -p` 默认带着 Claude Code 的全部工具，其中有一个专门报告评审意见的工具，模型把意见交给了它，只在 stdout 留下一句总结，canon 读不到 JSON，评审按 BR-2216 失败。评审需要读的规则、决策、总览和改动都在提示里（BR-2009），代码评审的提示也带着 diff 和改动文件全文（BR-2070），两者都用不着工具。`canon init` 写进项目的默认命令（BR-2032）和 canon 自己的评审脚本都是这样调用的。

## 方案

1. 默认命令加 `--tools ''`，关掉全部工具：采用。模型只剩打印文字一条路，提示要求的 JSON 只能出现在 stdout；同一提示加上它后正常输出 `{"findings":[]}`。
   - 来源：src/knowledge/review/config-keys.ts “--tools '' --output-format text”
2. 只用 `--disallowedTools` 关掉那一个报告工具：否决。别的工具（读文件、跑命令）同样用不着，还会让评审去读提示之外、合入前不该看的文件；工具清单换了名字还得跟着改。
3. canon 收到不是 JSON 的输出时重跑一次：否决。按根因修，重跑只是碰运气，还要多花一次调用。

## 决定

采用方案 1：`canon init` 写的默认评审命令按 BR-2032；没配评审时提示里给的是同一条命令。canon 自己当时的 scripts/review-claude.sh（2026-11-15 起换成 Codex，scripts/review-codex.sh）和代码评审 `scripts/code-review.ts` 的默认命令也一样关掉工具。

## 后果

- 已经用默认命令的项目不会自动改：`canon/config.yaml` 是项目自己的，要自己加 `--tools ''`；这次会通知用 canon 的项目。
- 以后评审要是真需要读提示之外的东西，得先改提示，而不是给评审开工具。
