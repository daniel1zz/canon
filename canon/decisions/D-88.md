## 背景

D-85、D-86 按“项目的环境变量管理”做了一套：canon-secrets skill，快照跳过密钥文件（BR-2406），合入时用 varlock 扫描提交的密钥（BR-2407、BR-2408）。负责人随后说明（2026-11-11）这不是负责人要的：负责人要的是全局的隐私管理，在使用 AI agent 时脱敏，主要场景是 agent 跑命令要用 key，不分项目，不需要跨机器；并要求把 canon 里的这几个变更全部撤掉；之后选定的做法是 Claude Code hook 在命令执行时把 `{{名字}}` 换成真实值、输出里再换回去，作为 canon 的功能默认装进每个项目。

2026-11-12，负责人在当前会话补充：“密钥管理功能不何如”，随后澄清“不需要”。因此这次撤销继续执行，但不再用 hook 替换代号、输出打码或其他密钥管理功能补回来；C-466 取消并归档。

## 方案

1. 保留 canon 里的实现，再另外做全局方案：否决。负责人明确要求全部撤掉；项目级的开启条件和合入扫描服务的是负责人不需要的场景，留着只会多一套要维护的检查。
   - 来源：canon/decisions/D-85.md “开启的判断用 `.env.schema` 是否存在”
2. 只保留快照跳过密钥文件，其余撤掉：否决。负责人在三个选项（全部保留、只留快照、全部撤掉）里选了全部撤掉。
3. 全部撤掉，全局脱敏改用 hook 替换代号，另开变更做进 canon：2026-11-11 采用；2026-11-12 因负责人明确不需要密钥管理而取消替代方案。
4. 全部撤掉，不再实现密钥管理替代方案：采用。符合负责人在当前会话的最新要求。

## 决定

撤掉 C-449、C-450、C-451、C-458 的全部功能：删除 canon-secrets skill，快照和合入恢复原来的行为，BR-2406、BR-2407、BR-2408 下线，D-85、D-86 作废。不再实现给 agent 用的密钥代号替换或输出打码，C-466 的未合入工作归档，不进入 main。

## 后果

- 已装了 canon-secrets skill 的项目，下次 `canon update` 时会删掉它；项目里改过的文件保留（BR-2083、BR-2089）。
- #185、#186 针对的合入扫描已不存在，随本变更关闭。
- 快照又会收进没被 git 忽略的明文密钥文件；保存在本地的 `refs/canon/snapshots/*` 里；canon 的常规 main 推送不推这些 ref。
