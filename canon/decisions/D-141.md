## 背景

这是 C-603 计划的 E 步。D-137 定的方向是过程交给模型、合入只做完整性检查和机械检查，E 步要去掉过程中的两个强制步骤，并接上关键程度：关键改动合入前跑全量测试、由独立 agent 验收，普通改动抽查。

本仓库 2026-11-02 到 11-19 的合入拒绝里（D-137 背景），合入时的措辞判断拒了 137 次，证据检查拒了 27 次，是拒绝最多的两个来源。两者都是 D-139 说的「流程是否走全」的检查，不属于四类可以拒绝的检查：

- 证据检查（BR-2241）：要执行的规则没有点名它的测试改动、也没有验收行时拒绝。规则没有证据时，它的执行状态本来就由通过记录算成「待重新执行」（BR-2246），`canon progress` 看得到；拒绝只是逼会话在合入前补上。D-32 当初担心的是「规则悄悄变成待重新执行」，要防的是悄悄，不是变成待重新执行本身。
- 措辞判断（BR-2239）：合入时调用一次模型，判断只改了 `## 规则` 段的修改是措辞还是行为，不确认就拒绝。这是合入里唯一的模型调用，和「合入只做机械检查」相反；D-32 否决了由改规则的变更自己声明「行为不变」（agent 自己证明自己），所以独立的判断要留下，只是不必在合入里、也不必拒绝。

另外，`canon check` 的 `test-report-missing`（BR-2344）在合入时拒绝改了测试文件、却没跑过 `canon work test` 的变更。它要的东西（改动的测试和点名碰过的规则的测试的当前报告）合入自己就能跑出来。

2026-11-20 负责人改了 D-137 里关键程度的做法：在「合入前验收，只缩小关键的范围」「改成合入后验收，不拦」「去掉关键程度」「维持 D-137」四个选项里选了「改成合入后验收，不拦」。主会话转述的要求是：关键改动照常合入，合入后在后台由独立 agent 从真实入口按改动的规则验收，结果记下；失败走已有的路（测试失败时自动撤回弄坏 main 的那次合入，BR-2534 到 BR-2536；或在 `canon work due`、`canon brief` 里点名变更和作者提醒修）；保留「关键改动比普通改动验得多，普通改动抽查」，去掉「等验收完才合入」。

按 D-137 的关键程度定义，改规则或决策就算关键。本仓库 2026-11-06 以后合入的 186 个变更里，169 个改了 `canon/rules` 或 `canon/decisions`（`git log main --since=2026-11-06` 按变更前缀统计），照 D-137 做，九成以上的合入都要等全量测试和独立验收，比现在更重。

## 方案

1. **两个检查改成记下状态加提醒，措辞判断挪到合入之后；合入自己跑相关测试；关键程度改成合入后验收、不拦合入**：采用。
   - 证据：缺证据的规则不写通过记录，合入照常进行，输出一行说明它以「待重新执行」合入、怎样补证据；`canon work due`（也就在 `canon brief` 的 Due now 里）点名这次合入的变更和这些规则，直到它们有了当前文字的通过记录。
   - 措辞：关闭提交照旧按 BR-2243 写 `… wording` 记录；合入不调用模型。合入之后在后台评审里问同样的措辞判断，没确认的规则记成挂在它上面的未处理评审意见，点名变更，由主 agent 按意见的流程处理。
   - 测试：合入在关闭提交和排队之前，自己跑改动的测试文件和点名碰过的规则、还没有当前内容报告的测试文件；`canon work test` 已经跑过的不重跑；rebase 之后内容变了的再跑一次（BR-2381）。失败就不排队：这是保证 main 正确的检查，只挡这一个变更。
   - 关键程度：canon 按事实算，会话只能调高；关键改动合入后由独立 agent 验收，普通改动按比例抽查；都不拦合入。
   - 来源：canon/product.md “重提醒，轻拦截（D-139）”
   - 来源：canon/decisions/D-139.md “即使属于上面几类，拒绝也只挡和问题相关的工作”
   - 来源：canon/decisions/D-32.md “规则悄悄变成待重新执行”
2. **保留合入前验收，只缩小「关键」的范围**：否决。要缩到真正少数的合入才不变重，就得把「改规则或决策」拿掉，而关键程度要抓的恰恰是看起来小、实际有破坏性的改动；范围怎么缩都是在猜，而等验收的代价每次都实打实地付。
   - 来源：canon/decisions/D-137.md “真正有破坏性的改动常常看起来很小”
3. **去掉关键程度，所有改动一样对待**：否决。负责人要的是关键节点更重；去掉以后，改持久化数据、跨领域、近期被撤回过的那片代码和改一行文案一样只靠抽查，丢掉了 D-137 要的分级。
   - 来源：canon/decisions/D-137.md “关键节点才重、轻量节点就轻”
4. **维持 D-137：关键改动合入前跑全量测试、等独立验收**：否决。九成以上的合入改规则或决策，都会被判成关键，合入比现在更慢，和 D-137 要的「合入变快」相反；而合入后验收失败时已经有撤回和提醒两条路把问题送回作者。
   - 来源：canon/decisions/D-137.md “合入变快：普通改动不再等 8 到 20 分钟的合入前测试和措辞判断”
5. **措辞判断留在合入里，只是不拒绝**：否决。判断的结果改不了已经做好的关闭提交（合入的必须是检查过的那个提交，BR-2106），不拒绝时它能做的只有记一条意见，这件事合入后做也一样，却让每次合入多等一次模型调用、多建一个临时 worktree。
   - 来源：canon/decisions/D-32.md “合入的必须是检查过的那个提交”
6. **措辞由会话自己声明，不再有独立判断**：否决。D-32 已经否决过：这是 agent 自己证明自己；D-137 也提醒过，只靠文字让模型自己决定省哪些步骤，会被当成省步骤的许可。
   - 来源：canon/decisions/D-32.md “这是 agent 自己证明自己”

## 决定

采用方案 1。

- 证据检查不拒绝：BR-2241；`canon work test` 只提示、不因此失败：BR-2456；提醒：BR-2527。
- 措辞判断在合入之后：BR-2239、BR-2243，合入后为它排评审：BR-2010、BR-2441。
- 合入自己跑相关测试：BR-2542；rebase 之后：BR-2381；`canon check` 的报告检查：BR-2344。
- 关键程度和合入后验收先写成规划中的规则：BR-2543、BR-2544。它们要有一个能从真实入口驱动产品的验收 agent 和它的配置，本变更不实现，由后续变更做。

D-137 里「关键改动合入前跑全量测试，并由独立的 agent 从真实入口验收」改为合入后验收、不拦合入；D-137 的其他内容不变。D-32 里「缺一条就拒绝」和「审查判为行为……这次合入被拒」改为上面的记录加提醒；执行状态、通过记录和行为哈希的定义不变。

## 后果

- 合入少了两个最大的拒绝来源和唯一的模型调用；代价是没有证据的规则会以「待重新执行」进 main，措辞判断判成行为的规则在意见处理之前显示为已通过（记录带 `wording`，意见挂在规则上，`canon context` 和 `canon work due` 看得到）。
- 提醒被忽略的风险还在：`canon work due` 的项一直列着，直到规则有了当前文字的通过记录；评审意见按意见的流程定档和关闭。
- 合入前跑测试的时间从「会话记得跑 `canon work test`」变成「合入一定跑相关的那几个文件」；跑过的不重跑，所以照常先跑 `canon work test` 的会话不多花时间。
- 关键程度和合入后验收要等 BR-2543、BR-2544 实现；在那之前，关键改动和普通改动一样合入，靠后台测试和撤回（BR-2534 到 BR-2536）兜底。C-603 的 E 步因此只完成前三项。
- 如果出现「待重新执行」的规则长期没人补、`unverified:` 项在 `canon work due` 里停留超过一周的情况变多，就说明提醒不够，应该让它们进入验收（knowledge/accept）挡住那几条规则，而不是改回拒绝合入。
