## 背景

2026-11-20 负责人在 delegate 项目的会话里提出：“我希望canon后面是可以配置可装配的，我们现在是否能提供一个可视化的配置和装配管理，把流程列出来，然后流程对应的配置，然后我可以对某个节点取消或者改他的配置”，目的是“这样所有项目就可以有一个更适合自己的canon”。

当时的事实：

- `canon config` 列出 51 个配置项（BR-2174），按 `listed` 平铺，看不出每一项在流程的哪一步起作用、哪一步在这个项目里没开。能关的步骤其实不少（`review: none`、不写 `remote`、`floor_timing: after` 把 floor 挪到合入后、各个 `hooks` 事件），但只能从每项的英文说明里逐条读出来。
- D-28 否决过网页配置页，理由有两条：违反 product.md 的“不做的事”；配置决定 floor、评审和 hook 怎么跑，修改必须走合入，网页直接写文件会绕过合入。
- 并不是每一步都能关：认领、合入排队、移动 main 的比较并交换支撑 P4，`canon check` 支撑 P5；`floor`、`tests` 缺了合入就被拒绝（`src/work/land/land.ts` 的 `no-floor`，`tests` 的说明 “Required”）。

会话先给了只在终端按流程分组列出的方案，负责人先选了它，随后改口：“我要ui可视化的，更清晰的看清楚流程”。会话在 delegate 上用 `canon config --json` 的数据手写了一份只读页面作为原型，负责人看过后，在“只当参考图用”和“做进 canon”之间选了后者（回答 “2”）。

## 方案

1. 网页配置页，能开关步骤、直接改配置：否决。D-28 的理由仍然成立：改配置不走合入，floor、评审和 hook 的改动就没有经过测试和评审。
   - 来源：canon/decisions/D-28.md “网页直接写文件会绕过合入”
2. 只在终端按流程分组列出：否决作为唯一形式。负责人要的是看得清流程的图形界面；文字形式保留，作为同一份数据给 agent 读。
3. 本地 HTTP 服务实时显示：否决。canon 没有常驻进程，product.md 不做 HTTP API；静态文件就能显示同样的内容。
   - 来源：canon/product.md “网页 dashboard 或 HTTP API：人直接看仓库里或 GitHub 上的文件”
4. `canon config --flow` 生成一个不连网、只读的 HTML 文件，放进被 git 忽略的 `.canon/`：采用。位置和理由同 D-28 方案 8 的 schema 文件：由当前运行的 canon 生成，不进合入，worktree 和离线都能用。页面不能改配置，只给出可以复制的 YAML 写法，改配置仍走合入。
5. 在 `src/invocation` 里集中写一张“配置项 → 步骤、类别”的表：否决。invocation 的约定是配置项不集中登记，由用它的领域声明；集中的表在新加配置项时容易漏，只能靠测试发现。
   - 来源：canon/rules/invocation/README.md “配置项不集中登记：每一项（名字、类型、默认值、校验、说明）由用它的领域在自己代码目录的 `config-keys.ts` 里声明”
6. 每个配置项在自己的声明里写 `flow`：配置哪些步骤、属于哪一类、哪个值让某一步不运行：采用。字段必填，新配置项不写就编译不过；步骤 id 是类型，写错也编译不过。流程的骨架（阶段、步骤、内置步骤支撑的承诺）不是配置项，集中写在 `src/invocation/flow.ts`。

## 决定

采用方案 4 和方案 6：

- `canon config --flow` 按流程列出配置：BR-2540。
- 它把只读页面写进 `.canon/flow.html`：BR-2541。
- `canon/product.md` 的“不做的事”里，网页 dashboard 加一个例外：这个本地、只读、不连网的流程图。可编辑的网页和 HTTP 服务仍然不做。

## 后果

- 新加配置项时多写一个 `flow` 字段；新加流程步骤时改 `src/invocation/flow.ts`。
- 类别和归属是人判断的，写错了不会被类型检查发现，要靠合入后的代码评审和使用时发现。
- 页面是运行那一刻的快照，配置改了要重新运行。
- 流程视图（`--flow` 的文字输出、JSON 里的标题和说明、页面）用中文：负责人看过原型后要求“用中文”。canon 其他命令的输出仍是英文；每个配置项自带的说明（`doc`，schema 和 `canon config` 也用它）仍是英文原文，页面上写明了这一点。
