## 背景

D-6 允许 agent 用 `--relayed "<人的原话>"` 转述负责人的回答，并且明说 canon 防不住冒充：原话是 agent 自己写的，canon 分不出转述和编造。D-6 的备选方案只比较了“谁能回答”，没有考虑从 Claude Code 那边拿一份 agent 不经手的记录来对照。

lore 的 SPEC-234 在提问工具（AskUserQuestion）返回之后挂了一个只记录的 hook，直接从 Claude Code 交给 hook 的数据里记下人的选择。C-58 把这种做法搬进 canon。

查过的事实（Claude Code 官方文档，2026-11-04）：

- PostToolUse hook 在工具成功执行之后触发，拿到工具的输入和结构化输出。
- AskUserQuestion 的输出里有每个问题和人选的选项（多选时用逗号连起来），人自己打字回答时有 `response`，备注在 `annotations` 的 `notes` 里。
- hook 的数据里有 `session_id`；canon 在 Claude Code 里没有设置 `CANON_ACTOR` 时，操作者是 `agent:` 加会话 id 的前 8 位，设置了就用 `CANON_ACTOR`（BR-2023）；子 agent 和主会话共用会话 id（D-18）。
- 对话记录文件（`transcript_path`）是异步写的，hook 触发时可能还没写到这一轮。

## 方案

1. PostToolUse hook 只记录提问工具的问题和回答（`human.asked` 事件），`canon human answer --relayed` 对照同一操作者最近的一条，标出“一致 / 没有对应记录”，不一致也照样记下：采用。记录来自 Claude Code 交给 hook 的数据，agent 不经手；只标记、不拦截，符合 D-1（没有 hook 检查 agent 怎么干活）。
   - 来源：https://code.claude.com/docs/en/hooks.md “hooks fire after a tool has already executed successfully”
   - 来源：https://code.claude.com/docs/en/agent-sdk/typescript.md “Returns the questions asked and the user's answers.”
   - 来源：https://code.claude.com/docs/en/hooks.md “Maps question text to the selected option label.”
   - 来源：canon/decisions/D-1.md “没有任何 hook 检查 agent 怎么干活”
2. 同样的记录，但对不上时 `canon human answer` 拒绝：否决。人常常在对话里直接回答，不经过提问工具，这时根本没有记录，拒绝会挡住负责人正常的用法，正是 D-6 要避免的；而且 agent 自己运行记录命令就能造出一条记录，拦也拦不住存心伪造。
   - 来源：canon/decisions/D-6.md “canon 不声称能阻止冒充”
3. 回答时去读对话记录文件（`transcript_path`）找人的回答：否决。文件是异步写的，可能还没写到；格式是 Claude Code 内部的、文档没有承诺；文件在本机、agent 能改，并不比 hook 的记录更可信。
   - 来源：https://code.claude.com/docs/en/hooks.md “The transcript file is written asynchronously and may lag the in-memory conversation”
4. 保持 D-6 不变，不加佐证：否决。转述的原话完全没有旁证，事后查一个回答是怎么来的，只能相信 agent 的转述。

## 决定

- canon 往项目的 `.claude/settings.json` 合并一条 `matcher` 为 `AskUserQuestion` 的 PostToolUse hook，运行 `canon human record`，把问题和人的回答写成 `human.asked` 事件（BR-2274、BR-2275）。只写项目的设置，不碰 `~/.claude`。
- `canon human answer --relayed` 对照同一操作者最近的一条 `human.asked`：原话和其中某个回答、自由回答或备注完全相同算一致。结果存进问题和 `human.answer` 事件，`canon human pending --all` 显示（BR-2276）。
- 这是佐证，不是证明：agent 也能自己运行 `canon human record` 喂编造的数据。D-6 的“canon 不声称能阻止冒充”仍然成立；这里加的是，人确实通过提问工具回答过时，记录能对上，事后能看出哪些回答有旁证。

## 后果

- 部分修改 D-6：转述的回答多了一个“是否和 Claude Code 的记录一致”的标记，D-6 其余决定不变。
- 每次提问工具返回都多一条事件；事件表本来就只增不减。
- 只认完全相同的原话和“最近一条”：人用自己的话回答、或先后答了两个问题再转述前一个时，会标“没有对应记录”。宁可漏标一致，不能碰巧标成一致。
- 以后可以从事件表数出“没有对应记录”的比例，看 agent 是不是真的先用提问工具问人；lore 的 90 个问题只有 22 个用上记录，原因还没核实。
