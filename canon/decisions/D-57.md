## 背景

D-40 定了 `canon usage`：读本项目的 Claude Code 会话记录，列出可用但 N 天没用过的 skill、MCP 服务和子 agent 类型及注入量。2026-11-04 的独立评审指出了五处问题，负责人当天选择按评审重做（选项“D-35、D-43、D-40 一并重做”）。按 D-54（只修正常操作会引出的问题）逐条判断：

1. **未用清单里有删不掉的和别的项目在用的项（修）。** 评审在本仓库实跑得到 149 个未用项，其中有内置 skill（`code-review`、`update-config`）、账号连接器（`claude_ai_Vercel`，12804 字符，排第一）、用户全局 skill（`claude-api`）。命令只看本项目的记录，“本项目没用过”会被读成“可以删”。人看这份报告就是正常使用，所以要修。
2. **注入量少算了一部分（已知限制）。** MCP 的注入量是服务说明加延迟加载的工具名，一开始就加载的完整工具定义、之后经 ToolSearch 取回的定义不在会话记录的这几类附件里；只靠 `Skill` 调用统计也看不到直接读 `SKILL.md` 的情形。记录里没有这些数据，补不出来，写成已知限制。
3. **内存随记录总量增长（已知限制）。** 评审实测 482MB 记录用时 1.88 秒、峰值 854MB，D-40 写的是约 400MB、1.3 秒。这是个人偶尔审计时运行的只读命令，没丢数据也不是安全问题，也不影响 P1 到 P7；不为它改成流式读取。
4. **Claude Code 清理过的旧记录会让项显示成“从没用过”（已知限制）。** 超过它保留期的记录已被删掉，`--days` 取得比保留期大就会这样；保留期的默认值评审没有从文档里确认。
5. **路径编码有损（已知限制）。** `…/canon/worktrees/x` 和同级另一个叫 `…/canon-worktrees-x` 的项目会编码成同一个名字，前缀匹配可能多读到别的项目的记录。要两个目录名这样撞上才会发生。

## 方案

1. 每个未用项标明范围，靠读用户的配置文件、插件目录和账号设置判断它来自哪一层。否决：D-40 方案 3 已经否决过读配置自己拼清单，配置分散在多处，还有组织策略；要为一个提示再加一整套读配置的代码。
   - 来源：canon/decisions/D-40.md “配置分散在多处，还有插件、账号连接器、被组织策略关掉的服务”
2. 只在输出末尾加一句说明，不分范围。否决：人仍要自己逐项判断 149 项里哪些是本项目的，最有用的区分（本项目自己定义的项，删了只影响这个项目）没有给出。
3. 两档范围：`project`（本项目自己的文件定义了它：`.claude/skills/<名字>`、`.claude/agents/<名字>.md`、`.mcp.json` 的 `mcpServers`）和 `other`（其余：用户、插件、账号连接器、内置，canon 不去分），加固定的一行说明 `other` 只在本项目的会话里判断过，别的项目可能在用，内置的删不掉。采用：判断只要查本项目目录里文件是否存在，不读用户配置；真正能当场决定“删这个只影响本项目”的就是 `project` 这一档，其余一律提醒人先去别处核对。
4. 把 2 到 5 项也做成机制（流式读取、按修改时间跳过、读保留期配置、更精确的路径编码）。否决：按 D-54，这些都需要不正常的使用（对很大的历史反复运行、两个目录名碰巧相同）才出现，也没有一项丢数据或破坏承诺，修它们要加的代码比问题本身大。
   - 来源：canon/decisions/D-54.md “记成已知限制，写在相关决策的“后果”或规则里一行，不为它加机制”

## 决定

采用方案 3 并记下 2 到 5 项已知限制。D-40 的决定整体沿用并由本决定取代：`canon usage [--days N] [--json]` 读 `<CLAUDE_CONFIG_DIR 或 ~/.claude>/projects` 下属于本项目的目录（主 checkout、变更 worktree 目录下的、git 公共目录 `canon/` 下的），只读不写，统计 skill、MCP 服务、子 agent 类型的使用次数和最近一次时间（BR-2265）；可用清单是窗口内各个会话实际注入的内容的并集，列出可用但 N 天（默认 30）没用过的项、它们的 `scope`（`project` 或 `other`）和注入的字符数，输出末尾固定写一行说明 `other` 只在本项目的会话里判断过；`--json` 的每个未用项也有 `scope`（BR-2266）。只报告，不改任何配置：去掉哪一项要人决定（C-34）。D-40 的后果（字符数不换算成 token、规则文件不在统计里、会话记录格式变了时报告写明没找到清单、内置斜杠命令不算 skill 调用）继续有效。

## 后果

- `other` 不等于能删，也不等于不能删：它只说明本项目的文件没有定义这一项，要不要去掉仍要人先去用户配置、插件和账号设置里核对。
- 已知限制：注入量只算会话记录里附件注入的部分，少算一部分（评审项 2）；内存随记录总量增长，评审实测 482MB 记录峰值 854MB（项 3）；`--days` 超过 Claude Code 的记录保留期时，被清理掉的使用会让项显示成从没用过（项 4）；两个项目的路径编码相同时会混读（项 5）。这些情形出现了真实的复现再重新打开。
- 项目自己定义的 skill 如果装在 `.claude/skills` 之外（例如 `.claude/commands`），会被归成 `other`，只是多一句提醒，不会漏报。
