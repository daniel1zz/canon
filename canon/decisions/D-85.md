title: 密钥防泄漏用开源第三方工具，canon 只出一个 skill
status: accepted
---

## 背景

负责人要一个通用的密钥管理办法（私钥、API key、账号密码），让 AI agent 用到这些东西时不泄漏，并作为 canon 的功能装进每个项目（2026-11-11）。负责人定了三条：有好用的第三方工具就直接用，canon 只出一个 prompt 或 skill；第三方工具必须开源免费；外部工具是可选的，项目开启了但没装要报错。

AI 读到的一切（文件、命令输出）都可能进日志、发给模型服务商，或者被网页、README 里藏的指令骗着发出去；在 canon 里还多三条路：快照会收进没被忽略的未跟踪文件，规则评审和代码评审把 diff 发给 `claude -p`，代码评审会把发现提成 GitHub issue。所以办法的核心是值不进 AI 的上下文。

在本机实测了 sops 3.13.3、age、varlock 1.24.0（2026-11-11）：
- sops 用 age 加密 dotenv 文件，私钥来自 `SOPS_AGE_KEY_FILE` 或 `SOPS_AGE_KEY`，两种都能解密；`sops decrypt --extract` 能只取一个键。
- varlock 的 `.env.schema` 用 `exec()` 从 sops 取值；`varlock load --agent` 输出里敏感值打了码；`varlock run` 给子进程的 stdout 和 stderr 打码，接管道也打码；取不到私钥时以退出码 1 失败并写明哪个变量；`varlock scan --staged` 在暂存文件里出现真实值时退出码 1。
- 打码只认原样的值：在 `varlock run` 里把值反转后输出，没有被打码。
- 许可证：varlock MIT、sops MPL-2.0、age BSD-3-Clause，都不需要服务器或付费服务。

## 方案

1. canon 自带密钥命令（`canon secret run`、`canon secret set`），包装 sops 和 varlock：否决。canon 会变成密钥管理的入口，重复成熟工具已有的功能；七条承诺里没有一条需要 canon 自己管密钥，按产品说明不支撑承诺的机制不做。
   - 来源：canon/product.md “一个机制如果不支撑任何一条，就删掉”
2. canon 装一个 PreToolUse hook，拦下 `printenv`、`cat .env` 这类读密钥的命令：否决。产品说明把“检查 agent 怎么干活”列为不做的事；而且按命令文字拦截挡不住变形后的读取，上面的反转实验说明换一种写法就能绕过，拦截给的是假的安全感。
   - 来源：canon/product.md “检查 agent 怎么干活。Canon 只在两个边界检查结果”
3. 用 Infisical（开源，可自己部署）做默认方案：否决。要部署和维护一个服务器，和“不依赖本地环境、不要服务器”的要求不符；它给 agent 用的代理已经废弃，换成了另一个产品。
   - 来源：https://infisical.com/docs/cli/commands/agent-proxy “Agent Proxy is deprecated, and Agent Vault replaces it”
4. sops + age 存储，varlock 注入、打码、扫描，canon 出 `canon-secrets` skill 教 agent 怎么用：采用。全部开源免费，不要服务器；加密文件进 git，换机器、CI、云端 agent 只需要一个 age 私钥；agent 读 `.env.schema` 就知道有哪些配置，读不到值。
   - 来源：https://varlock.dev/guides/ai-tools/ “never leave your machine or touch AI servers”
   - 来源：https://github.com/getsops/sops “Mozilla Public License Version 2.0”
   - 来源：src/work/snapshots/snapshot.ts “untracked files git does not ignore”

1Password CLI 在第一轮建议里出现过，它不开源，按负责人的要求不考虑。

## 决定

新增 skill `.claude/skills/canon-secrets/SKILL.md`，随 `canon init` 和 `canon update` 装进项目（BR-2080）。项目根目录有提交进 git 的 `.env.schema` 就算开启：这时 sops、age、varlock 是必需的，缺哪个 agent 就停下并写明缺哪个，不退回明文 `.env`。canon 的代码和检查不变。

## 后果

- 每个会话的上下文多一个 skill 的描述。
- 防护靠 agent 遵守 skill，canon 不强制：值一旦被注入进程，变形后输出或发出去都挡不住，skill 里写明了这条局限，并要求高价值密钥不交给 agent。
- 开启的判断用 `.env.schema` 是否存在，不在 `canon/config.yaml` 加配置项，因为 canon 的代码不读它。
- 快照收进没被忽略的明文密钥文件的问题，靠 skill 要求的 `.gitignore` 条目避免，canon 的快照逻辑不改。
