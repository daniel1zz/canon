id: D-111
title: worker 会话按进程树认出：自己的 claude 进程上面还有 claude 进程
status: accepted
---

## 背景

负责人的 `delegate` 工具从主会话的 Bash 里用 `claude -p` 启动 worker，每个 worker 是一个独立的 Claude Code 会话。它的 hook 输入里没有 `agent_id`，所以 `canon work check-as --hook` 把它当主会话：带 `--as` 被拒，不带 `--as` 就按 BR-2023 记成 `agent:<它自己的会话>`（#205）。2026-11-14 实测：这种 worker 有自己的 `CLAUDE_CODE_SESSION_ID`（主会话 335cc8af，`claude -p` 里是 a69bb94c）；zhushenkongjian 里 C-607 记在 `agent:d7dee66a`，C-608 记在 `agent:09d7d405`，分得开。缺的是角色：canon 把 worker 当主会话，BR-2454（子 agent 连续被拒三次交给主 agent）和 BR-2455 对它从不生效。zhushenkongjian 运行中的 worker，进程链是主会话 `claude` → `zsh` → `delegate run` → worker 的 `claude -p`，没有脱离父进程。主会话和 `claude -p` 会话里看得到的环境变量对比：`CLAUDE_CODE_CHILD_SESSION=1` 两边都有，分不出；只有 `CLAUDE_CODE_SESSION_ATTENDED` 不同（0 和 1），它说的是有没有人看着，不是谁启动的。

## 方案

1. 按进程树认：hook 进程往上，在会话自己的 `claude` 进程之上还有 `claude` 进程，就是 worker，按子 agent 处理，名字由它自己用 `--as` 给：采用。不要启动 worker 的工具配合，canon 已经靠进程表认会话进程；代价是每次没有 `agent_id` 的认领命令多读一次进程表，读不出来时放行并记下（BR-2341），worker 若被启动工具脱离父进程就认不出，照旧当主会话。
   - 来源：src/work/claims/liveness.ts “Every agent of one Claude Code session, subagents included, runs under the same process”
2. 由启动 worker 的工具设一个环境变量（例如 `CANON_AGENT=<名字>`），canon 认它：否决。要每个启动工具配合，canon 核对不了值是谁设的；负责人的 `delegate` 是编译好的程序，现在不设它。
3. 没有 `agent_id` 的调用一律允许 `--as`：否决。主会话也能给自己起名字，BR-2340 防的“主会话冒充子 agent、绕过 BR-2455”就没了。
   - 来源：src/work/claims/as-check.ts “a subagent must not let its own stopped change land again”
4. 认 `CLAUDE_CODE_SESSION_ATTENDED=0`：否决。它只说明没人看着，主会话用 `claude -p` 跑自动化时也是 0。

## 决定

采用方案 1，按 BR-2468；BR-2340、BR-2341、BR-2023 随之改。

## 后果

- 已经不带 `--as` 认领的 worker，下一次认领命令会被拒，按提示补上 `--as <名字>` 即可；之后它的认领和合入记成 `agent:<会话>:<名字>`。
- 在一个 worker 会话里跑 canon 自己的 hook 测试时，主会话那几个用例会被当成 worker；canon 仓库目前不用 worker 跑测试。
