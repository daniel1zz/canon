## 规则

主会话用下面的命令记下对议程项（BR-2527、BR-2581）的处理结论，三种结论必须且只能给一种：

- `canon work handled <键>[,<键>…] --to <C-n>`：交给变更 `C-n` 处理；
- `canon work handled <键>[,<键>…] --defer "<原因>" --for <时长>`：推迟，`<时长>` 写成 `30m`、`4h`、`2d`；
- `canon work handled <键>[,<键>…] --not-doing "<原因>"`：不处理。

每个键在协调事件表里写一条 `reminder.handled`，对象是这个键，详情含 `outcome`（`handed`、`deferred`、`not-doing`）、`to`（交给的变更）、`reason`、`until`（推迟到的时间，ISO 8601）、`since`（这一项当时的开始时间，没有时为 `null`）、`via`（`handled` 或 `settles`）。每个键输出一行 `handled <键>: handed to <C-n>`、`deferred until <时间>: <原因>` 或 `not doing: <原因>`，退出码 0。

**之后议程里不再出现它**，直到：

- 交给的变更关闭（BR-2571 的主状态 `landed` 或 `dropped`）后这一项还在；
- 推迟的时间到了；
- 这一项消失后又出现，新的开始时间晚于记下结论时的开始时间（例如同一个变更再次停滞）。

同一个键再记一次，以最新的一条为准。

**`canon work start --settles <n>[,<n>]`**（BR-2530）开工成功后，为每个编号写一条 `reminder.handled`：对象 `finding:<n>`，`outcome` 为 `handed`，`to` 是开的变更，`via` 为 `settles`；和用本命令交给这个变更一样算。

**拒绝和错误**（拒绝都写 `reminder.handled.refuse` 事件，带原因）：

- 一个键现在不在调用者的议程里（拼错、已经没了）：退出码 3，信息列出这些键并提示 `canon work due`，一个都不记；
- `--to` 的变更不存在或已关闭：退出码 3，一个都不记；
- 三种结论没给或给了多种、`--defer` 没有 `--for`、`--for` 不是 `<正整数><m|h|d>`、`--for` 和别的结论一起给、原因为空：用法错误，退出码 2；
- worker 运行：用法错误，退出码 2，信息说明处理结论由主会话记；
- 键里有 `red-main` 而结论是 `--defer` 或 `--not-doing`：退出码 1，一个都不记，原因 `red-main`，信息说明 main 没通过不能推后，只能修（BR-2601）；`--to` 照常。

依据：D-151 第三部分第 6 条；D-139「由主 agent 判断怎么处理并写下理由」。

## 例子

- `canon work handled finding:1016,finding:1017 --to C-1053` → 两行 `handled finding:1016: handed to C-1053` 等，两条 `reminder.handled`；之后 `canon work due` 里没有这两项
- `C-1053` 合入后意见 #1016 还开着 → `finding:1016` 又出现
- `C-1053` 被放弃 → `finding:1016` 又出现
- `canon work handled stalled:C-5 --defer "等负责人回来再定" --for 4h` → 4 小时内不出现，4 小时后又出现
- `canon work handled awaiting-close:C-343 --not-doing "上传要负责人本人操作"` → 一直不出现；`C-343` 关闭后这一项本来也没了
- 对 `stalled:C-5` 写了不处理，之后 `C-5` 被重新派发、又停滞 → 新的 `stalled:C-5` 开始时间更晚，又出现
- `canon work handled finding:99`，#99 不在议程里 → 退出码 3，没有写 `reminder.handled`
- `canon work handled finding:12 --to C-9 --not-doing "x"` → 退出码 2
- `canon work handled finding:12 --defer "x"` → 退出码 2，提示要 `--for`
- `canon work handled red-main --not-doing "x"` → 退出码 1，`reminder.handled.refuse` 原因 `red-main`，没有写 `reminder.handled`
- `canon work start --title "补测试" --settles 12` → 开出 `C-20`，事件表有 `reminder.handled`、对象 `finding:12`、`to` 为 `C-20`、`via` 为 `settles`
