## 调度：按成本和效率选执行者
谁来做不按角色固定。每次比较三项再选：token（subagent 要从零读上下文，通常几万 token）、耗时（能不能并行、派发和汇报的往返）、主 agent 上下文压力（原始输出之后还用不用得上）。
- **主 agent 自己做**：需要的上下文已在手上，改动集中（约 5 个文件以内或单个模块），或下一步直接依赖它的结果。
- **派子 agent 写代码**（`isolation: "worktree"`）：有 2 个以上互不依赖、可以并行的任务；或任务要读大量主 agent 之后用不上的内容（预计原始输出超过约 30k token）；或主 agent 上下文已经很重，需要隔离。
- **派只读子 agent**：跨两个以上区域（源码 / 测试 / 文档）的盘点，或预计原始输出超过约 10k token 且之后不需要原文；或需要一份不受主 agent 结论影响的独立评审。已知路径、计数、一两条命令的定点查询主 agent 自己跑。
- 混合任务拆开：适合派的派出去，其余主 agent 做；同一项不两边都做。派出去的结论，关键点要抽查。
- **并发上限按机器资源定，不只看 CPU**：派新 worker 前查负载（`uptime`）和内存（`sysctl vm.swapusage`）。交换区剩余不到约 0.5 GB、或负载持续高于核数的 2 倍，就不再派，必要时让最新开工的 worker 提交后暂停（之后 `--resume`）。参考：8 核 16 GB 的机器同时约 10 个 worker（每个 `claude -p` 约 300 MB，加上它跑的 Godot/测试进程），超过后内存换页会让落地测试整组超时。
- 不管谁写代码，都在自己的 worktree 里改，合入走项目自己的流程（见项目 CLAUDE.md）；共享 checkout 不改文件。这是为了并发安全，不是角色限制。
